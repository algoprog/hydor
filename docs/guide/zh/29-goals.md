# 目标

目标会让智能体一轮接一轮地持续工作，直到你们商定的检查项全部成立。你和智能体先把“完成”的含义商定成一份简短的检查项清单。之后，应用本身会在每一轮结束后运行这些检查项，并判断这一轮是否让事情更接近目标，所以智能体说“完成了”并不算数：只有检查项才能结束目标。它适用于所有智能体（Claude Code、Codex、Custom，以及你添加的其他智能体），因为驱动它的是应用自己的循环。

## 设定目标

要设定目标，请打开会话的菜单（⋯）→ **设定目标**，写下工作完成时应当成立的事情（“npm test 通过，并且上传页面能处理 2 GB 的文件”），选择 **向你询问的频率**，然后点击 **起草检查项**（或按 Ctrl+Enter）。你也可以在开始会话时就设定：在起始页打开 **选项** → **目标** → **直到完成**，你的第一条消息就是目标。以下情况无法设定目标：由另一个会话启动的会话（Hydor 子智能体：它的菜单里没有 **设定目标**）；在 VS Code 或终端中运行的会话（请先在应用中继续该会话）；处于计划模式的会话，因为智能体不会改动任何内容；领导战役、深度研究或竞技场对战的会话（“这个会话带领着一场战役：目标可以与集群配合使用，暂不支持战役。”，其他情况类似）；以及已经有其所用程序自带 `/goal` 的会话（请先用 `/goal clear` 清除）。如果你用 **目标** 启动的会话无法设定目标，它会作为普通会话继续，并有一条通知说明原因（“未能设定目标：…”）。一个会话同一时间只能有一个目标，而且目标会消耗很多轮对话：你在下面商定的限制可以对其加以控制。当会话被归档，或被 **从这里编辑** 替换时，目标会自行停止。

侧边栏中的靶心标记会显示哪些会话有目标；将鼠标指向它，可以看到当前是第几轮以及有多少检查项成立，会话自己的选项标签上会写着“目标模式”。你第一次从起始页开启目标时，会出现一段简短的说明，告诉你它的作用和代价。

## 商定“完成”的含义

智能体会阅读项目，并提出检查项、不得更改的路径和限制。你会在消息框上方的一张卡片上看到它们，卡片标题是 **“完成”是这个意思吗？**。**完成条件** 列出各项检查；每一项都有一个标签表示它的类型：

- **命令**：必须通过的命令（“npm test”）。
- **已测量**：打印出一个数字的命令，并带有目标：至少或至多（“搜索 p95 低于 200 ms”）。某一轮可以略低于目前的最佳值（相差十分之一以内）而仍然算数。
- **得分**：[实验](/experiments)中该项目的评测以它自己的封存方式给工作打分，得分必须比评测的基线至少高出你们商定的幅度（“比基线至少高 0.02”；0 表示只要提升超过各随机种子的噪声即可）。该评测必须能够给会话的文件夹打分（评测自己的文件夹、其中的子文件夹，或同一仓库的工作树），并且已经有基线。基线只能由你在评测页面上测量。点击 **开始** 时，目标值按当时的基线固定下来，评测所保护的文件也会加入智能体不得改动的路径。无论会话的权限如何，在你点击 **开始** 之前都不会运行打分（打分可能占用 GPU）：在此之前，卡片显示 “开始后评分 · 基线 0.412”；点击 **开始** 后立即进行的第一次打分就是起点。它的值是得分的平均数；当两边都有三个或更多随机种子时，落在噪声范围内的提升不算成立（"0.431 against 0.412: within the noise of 3 seeds"）。因评测文件被改动而遭拒绝的打分，或运行失败的打分，都不算成立。如果在目标运行期间评测被重新封存或换了基线，它的得分就无法再与商定的值比较：目标会就此停下并询问你，**按它现在的样子继续** 会按评测当时的状态重新固定该检查项。**修改…** 以及 **添加检查** → **得分** 会列出该文件夹的评测，尚未测量基线的评测会附上链接。目标从不运行评测的最终测试：达成目标时，报告会说明该评测有最终测试，并链接到它的页面，你可以在那里运行。
- **审稿人**：一句必须由审稿人认定为真的话。审稿人是一个没有参与任何工作的模型：它会阅读改动的内容、检查项所指的文件或输出（所指的若是文件夹，则展示其中的文件），并说明这句话是否成立及其理由。它用于命令无法证明的内容，例如“设置页面有深色模式”。如果不看某个文件就无法判断，它会说明是哪个文件，应用会把该文件展示给它并再问一次；git 忽略的文件绝不会以这种方式展示。
- **你**：只有你能确认的事情。当其他一切都成立时，它会等你确认。

**已妥善保存** 显示智能体不能更改的路径（测试、测试数据、检查项自己的脚本）以及它的工作位置。**限制** 是它最多可以使用的轮数、费用（按 API 价格计算）和时间；轮数来自 [目标最多可运行的轮数](/settings?s=goals&find=Rounds%20a%20goal%20may%20run)（除非你修改，否则为 30），费用和时间在你设置之前不设限。在 **向你询问的频率** 下，你仍然可以修改它询问的频率。如果会话的花费没有价格（使用的模型没有定价），卡片会说明费用限制无法让它停下，但轮数和时间仍然可以。

应用会在任何一轮开始之前先测量当前进度，所以卡片上会显示“3 分钟前测量 · 5 项中有 3 项成立”。只有当会话的权限已经允许智能体无需询问就运行命令（Claude Code 的 **绕过**，Codex 和 Custom 的 **完全访问**），并且会话不是保密会话时，它才会在提出检查项之后立刻测量。否则不会运行任何东西，卡片会显示“尚未测量”和“你点击“开始”时，检查项会首次运行”：这些命令是智能体提出的方案，需要你先同意。无法运行的检查项视为不成立；卡片会说明这一点，按钮会变成 **仍然开始**。

检查项的运行方式与会话自己的命令相同，绝不会更宽松，并使用智能体获得的环境。在保密会话中，它们总是在应用的沙盒内、无网络地运行，在没有沙盒的电脑上则根本无法运行（检查项会显示“这台电脑上没有可供运行的沙盒”）。在自动模式且开启沙盒的 Custom 会话中，它们同样在沙盒中运行，并限制在该文件夹内；在低于 **完全访问** 的 Codex 会话中，它们在沙盒中运行，限制在该文件夹内，并且除非 Codex 自己的沙盒策略允许，否则没有网络；其他情况下则直接运行。

- **开始**：同意这些检查项。如果它们已经全部成立，目标会立即达成；否则第 1 轮开始。
- **修改…**：把各行变成可编辑的字段。你可以删除检查项，编辑它的标签、命令、目标或句子，**添加检查** 某一类型的检查项，编辑受保护的路径（每行一个）和限制，然后点击 **开始**。**取消更改** 会让卡片恢复原样。
- **暂不**：停止该目标。

如果智能体被要求两次后仍没有提出任何检查项，应用会替它提出一项：由审稿人对照你的目标阅读改动。

## 各轮：保留或撤销

在每一轮中，智能体会得到要处理的内容：每项检查目前的情况、上一轮做了什么、你对它提出的要求，以及哪些内容不能更改。它的工作方式与处理任何消息时一样，使用会话已有的权限，并在告知应用它做了什么、还剩下什么之后结束这一轮。你自己的消息仍然优先：它们是这一轮之内的普通对话轮次。

当回合结束（并且智能体启动的任何东西，例如 Hydor 子智能体，都已不在工作）时，应用会运行所有检查项。对于仍在运行的命令（例如开发服务器），应用会在回合结束后等待 10 分钟，然后照常运行检查项。它的某个 Hydor 子智能体遗留的运行中命令，也按同样方式等待。打分排在命令和数值之后，通过实验队列运行，可能需要等待 GPU，耗时数小时：状态栏会显示出来（“正在评分：排队等待中”、“正在评分：已完成 2/3 次运行”）。除非检查项另有规定，打分最多等待 6 小时（上限 48 小时），并且绝不超过目标的时间限制：如果在等待打分时时间用完，目标就停在限制处。如果应用中途重启，它会继续等待同一次打分，而不会另起一次。你在两轮之间对文件所做的改动，绝不会算作某一轮的成果来评判，也不会随该轮一起撤销。当事情更接近目标且没有任何东西被破坏时，该轮标记为 **已保留**。出现以下情况时，该轮标记为 **已撤销**：

- 它更改了不允许更改的路径；
- 它违反了你的某条规则（见 [随时掌控方向](#steer-it-whenever-you-want)）；
- 一项原本成立的检查不再成立；
- 某个测量的数值远远落后于它的最佳值；或者
- 没有任何进展。

被撤销的一轮会让文件回到该轮开始时的样子（即目前最好的一轮，列表中标记为 **目前最佳**，除非你在两轮之间改动过什么）。这需要会话在工作树中工作（起始页的 **新建工作树**）；卡片会告诉你属于哪种情况：“它在自己的分支上工作”或“它在你的文件夹中工作，其中无法撤销某一轮”。在你自己的文件夹中，较差的一轮会被标记为 **保持原样**，并且会告知下一轮哪里变差了，让它加以纠正。

只有当自这一轮开始以来没有其他人在该文件夹中工作过（同一文件夹中的另一个会话，例如一个分叉），并且本会话自这一轮结束后一直处于安静状态时，应用才会自行把文件恢复原状。在此之前，它会把文件夹中的所有内容，包括检查项自己的输出和你所做的任何编辑，作为这一轮自己的文件保存下来，所以对该轮点击 **仍然保留…** 就能把一切都找回来。如果另一个会话在该文件夹中工作过，或者已经有过一次提交，这一轮就 **不会被撤销**：它会保留下来，标记为 **保持原样** 并附上原因（“未撤销：另一个会话（“…”）正在该文件夹中工作”），目标继续进行，并告知下一轮文件没有被恢复。如果是你自己的消息在检查项运行期间到达，这一轮会在会话安静下来时再检查一次（三次之后目标会暂停：“第 4 轮无法检查：检查项运行期间会话仍在文件夹中工作。请继续以再次检查。”）。应用绝不会尝试第二次：如果恢复文件没有完成（失败，或应用在中途重启），目标会暂停一次，并显示“恢复第 4 轮的文件未完成，因此文件可能只恢复了一部分。文件夹中的所有内容都已保存：对第 4 轮点击 **仍然保留…** 即可找回。继续会从文件现在的状态接着进行。”已保留的某一轮所删除的文件，在之后的撤销中仍然保持删除状态。

消息框上方的一个栏会显示目标、它正在做什么（“第 7 轮，共 12 轮 · 工作中”“正在运行检查项”“正在询问你”“已暂停”）、每项检查对应的一个标记（成立时是对勾，数值类的是“0.73 / 0.80”并带一个小进度条，尚未成立的是空心圆点，无法运行的是琥珀色标记）、费用和时间相对于各自限制的用量，以及 **各轮 · 3 已保留 · 2 已撤销**。点击它会打开各轮列表：每一轮做了什么、什么发生了变化（“相关性 0.61 → 0.68”）、是 **已保留** 还是 **已撤销**、花了多少钱以及用了多长时间。打开某一轮，可以看到智能体报告了什么、每项检查的结果，以及这一轮为何如此收场。循环发给智能体的消息在对话中显示为安静的一行，“目标 · 第 5 轮，共 12 轮”；点击它即可阅读该消息。

一项原本成立、现在却无法运行的检查（审稿人不可用、超时、缺少工具）并不算不再成立：它会再运行一次，如果仍然无法运行，目标就会暂停（“‘测试通过’无法运行：…请继续以再次检查这一轮”），这一轮既不保留也不撤销。如果审稿人无法读取你的规则，这一轮会继续进行，它的那一行会显示“这一轮无法检查你的规则”。

当所有检查项都成立时，应用并不会立即采信：它会把命令和数值再运行一遍（得分不重跑：它的随机种子已经反映了噪声，所以沿用对相同文件的打分），并由一个审查者阅读全部改动（以及检查项指定的或其审查者要求查看的文件），确认没有测试被削弱或跳过、没有答案被直接写进代码，并且目标确实达成。只有这样，目标才算达成。如果这一步没通过，下一轮会被告知最终检查发现了什么；从此以后，只要没有东西被破坏且文件有改动，该轮就保留；文件没有改动则按“没有变化”撤销。之后，类型为 **你** 的检查项会来询问你：**成立** 或 **还没有**（可附备注），选择“还没有”时的处理方式与上述相同。

## 向你询问的频率

**向你询问的频率** 有三个选项，位于起始页、**设定目标** 对话框、卡片和栏上的标签中：

- **自行进行**（标签显示“自行工作”）：只有在没有你就无法继续时才询问（需要只有你能提供的内容，或只有你能确认的检查项）。
- **在转折点**（默认；标签显示“在转折点询问”）：当它即将改变做法时询问，这发生在连续两轮没有进展之后。
- **每一轮**（“每轮询问”）：每一轮结束后，它会展示自己的发现以及对下一轮的选择。

当它询问时，一张提问卡片会给出两到四种继续的方式，每种都附有理由、应带来什么、代价是什么，并且在智能体自己倾向的那一种上标有 **它的选择**。勾选一种或几种方式，它们会按你勾选的顺序依次执行。**其他：请说明哪种方式** 可以填入你自己的方式，**给智能体的备注（可选）** 会进入下一轮。主按钮显示为 **走这条路**，或“按此顺序执行这 2 项”；**仅限它的选择** 采用智能体的选择。按键 1 到 4 可勾选对应的方式。

如果没有回答，它会在 10 分钟后按它的选择继续（分钟数为整数，0 到 1,440，其中 0 表示一直等待），或者等你：**如果你不回答** 中有这两个选项。卡片会倒计时（“9 分钟后按它的选择继续”），**等我** 会让计时停止。只有你能确认的检查项，或只有你能提供的内容，总是会等你。

新目标的起始设置（轮数、向你询问的频率，以及按它自己的选择继续之前的分钟数）在 [设置 → 功能 → 目标](/settings?s=goals) 中为每个新目标设定；在这里你只为一个目标更改它。

## 随时掌控方向

你可以随时掌控目标的方向。

- 像往常一样 **给智能体发消息**：你的消息优先，这一轮从那里继续。
- 栏上的**暂停**和**继续**。正在运行的一轮会像其他轮一样先完成并接受检查（栏上显示“本轮结束后暂停”，此时在那里按**继续**可以撤回暂停）；之后目标进入等待，在你继续之前不会再发送任何内容。如果正在等待评分，**暂停**不会等评分完成：评分的运行会立即停止，目标暂停，这一轮保持未检查状态，按**继续**会重新评分。**停止**同样会停止评分的运行。这时正是对某一轮发表意见的时机（见下文）。如果想让智能体立即停下，请在会话中停止它：目标会暂停，这一轮未经检查，按**继续**会检查它已经做的工作。它启动的 Hydor 子智能体会一起停止；如果某个子智能体还有报告尚未送达，该报告会在会话的队列中等待，在你继续目标时交给智能体。**停止**会结束目标（见下文）。
- 栏上 ⋯ 菜单中的 **添加规则…** 会把某件事固定下来，对此后的每一轮都有效（“不新增依赖”）。审稿人会对照你的规则检查每一轮；违反规则的一轮会被撤销。规则显示在 **来自你** 下，每条都有一个 × 可以移除。
- 同一菜单中的 **更改检查项…** 可以在目标运行期间编辑检查项、路径和限制；你添加或更改的检查项会被重新测量。只更改了目标值（或单位、容差、时限、名称）的检查项会保留它的值：它会按新的目标值重新判定，而不会重新测量。对限制的更改立即生效。在一轮进行期间对检查项或路径所做的更改，要等到这一轮按它开始时的检查项判定完毕后才生效（栏上会显示“你对检查项的更改将在这一轮之后生效。”），否则从下一轮起生效。
- 对某一轮的 **你的意见**，前提是会话在工作树中工作，并且目标不在某一轮的进行当中（请暂停它，或等待）。以下情况会被拒绝，并附一句说明阻碍所在的话：本会话的智能体正在工作时（“本会话的智能体正在工作：请等它这一轮结束，然后再试。”）；另一个会话正在该文件夹中工作时；自目标上次处理文件以来，文件夹中有过提交时（请先把它移到自己的分支上）；以及自目标上次处理文件以来，文件在目标之外被更改时：消息会列出这些文件（最多五个），并给出在工作树顶层文件夹中运行的命令，把你对这些文件的更改暂存到 stash 中，并恢复目标自己的版本（`git stash push --include-untracked -- <files>`，然后 `git restore --source=<checkpoint> --worktree -- <files>`；超过十个文件时，对整个文件夹执行同样的操作），这样你自己的更改绝不会丢失。在某一轮运行期间暂停的目标，会在文件夹中保留该轮尚未检查的工作：此时消息会这样说明，并且 **继续** 会让应用先检查那一轮：
  - 对被撤销或保持原样的一轮点击 **仍然保留…**，会保留它的文件并把它设为最佳。对于每一项未达成的已测量检查项，你可以保留原目标，或把它改为这一轮达到的数值，并给出理由。
  - 对已保留的一轮点击 **撤销**，会把文件恢复到它之前所保留的那一轮，并且它尝试过的做法不会再被尝试。
  - **从这里换一种方式** 会保留这一轮的文件，并让下一轮从那里起换一种做法；如果你愿意，可以说明改为尝试什么。

## 为集群设定目标

带领 [集群](/guide/research#set-a-swarm-on-a-hard-problem) 的会话也可以有目标：在开始页的 **选项** 中同时打开 **目标** 和 **集群**，在已经带领集群的会话中设定目标，或者在目标运行期间打开它的集群。战役、深度研究和竞技场不能与目标同时使用。

- **一轮就是整个集群的工作。** 应用把这一轮的消息发给主导智能体，由它让成员去处理尚未成立的部分：每人一个角度或一个检查项。它们都在主导智能体的文件夹中工作。
- **所有成员都完成时，这一轮才结束**：主导智能体的回合已经结束，没有成员还在工作，它们之间也没有任何内容在传递途中。在此之前，栏上会显示“正在等待 2 名成员”。之后应用会像对单个智能体一样，对主导智能体的文件夹运行检查项，这一轮或被保留，或被撤销。被撤销的一轮会连同成员所做的更改一起撤销。
- **成员在各轮之间会保留**，并记得自己的工作：主导智能体给它们下一步，为新的角度启动新的成员，并停止角度已经用尽的成员。每一轮的那一行会说明有多少成员在这一轮中工作过。
- **限制针对整个团队。** 费用统计主导智能体和每个成员花掉的钱，时间是团队在工作的时间，在一轮中途达到限制时，成员和主导智能体都会被停止。成员在停止之后报告的内容会在主导智能体的队列中等待，而不会唤醒它，并在目标继续时交给它。
- **暂停** 照常等待这一轮结束，在这里意味着等待每一个成员。集群看板上的 **全部停止** 会同时停止主导智能体和它的成员，目标随之暂停（“你已停止集群。点击‘继续’以检查它做了什么。”）。
- 只有主导智能体会向你提问；有问题要问的成员会把它发布到看板上。

集群的一轮要花掉它所有成员花费的总和：是单个智能体一轮的好几倍。请给目标设一个合适的费用限制。

## 何时停止，以及给它更多

目标会在达成时、你点击 **停止** 时，或在某个限制处（轮数、费用或时间）自行停止。它也会暂停并告诉你原因，这些情况包括：你停止了智能体、某一轮失败、应用无法保存文件，或恢复某一轮的文件未完成（如上所述）、某项检查无法运行、因会话持续工作而无法检查某一轮、它的消息无法发送、应用重启第二次打断了智能体的一轮（第一次时，应用会重新发送这一轮的消息，并加以说明），或应用恰好在循环的某条消息发出时重启（两分钟内没有任何东西启动后，它会再发送一次消息，然后暂停并加以说明），或智能体在其套餐的用量上限处停止而应用不会自行让它继续。当会话的队列处于搁置状态时，目标会请你在那里点击 **继续**。应用重启之后，目标会立刻查看自己的进度，无需等待。随后会有一张卡片显示报告：**达成目标**、**在上限处停止** 或 **由你停止**，附有轮数、费用和时间、一份摘要、一张表格（列出每项检查在开始时、现在以及所需的情况；在目标运行期间添加或更改的检查项，在开始列显示“—”，并以首次测量它之后的那一轮作为标题），以及最终审查的理由。**查看改动** 会打开会话的改动。**关闭** 会移除报告，这样你就可以设定新的目标。

在上限处停止的目标会显示 **给它更多…**：提高用完的那一项（轮数、费用或时间），然后点击 **继续**；它会从文件当前的状态接着进行，就像在任何一轮之后一样。在限制处等待期间，你仍然可以添加或删除规则，并更改向你询问的频率：它们会在它继续时生效。如果仍然触及某个限制，对话框会说明目标已经用了多少（“它已运行 4 轮：请给它比这更多的轮数。”，费用和时间同理），并且不会有任何改变。触及限制后不会恢复任何文件：被费用或时间限制中途停下的一轮，会保持智能体离开时的样子留在文件夹中。 智能体启动的 Hydor 子智能体会随它一起停止；在这一轮的文件保存时仍在工作的子智能体会在报告中被点名（“子智能体‘Cache’在第 4 轮的文件保存时仍在工作：它之后写入的内容在文件夹中，但不在这一轮里。”）；它们在停止之后报告的内容会在会话的队列中等待，直到你给目标更多。它会被记录为独立的一轮（**保持原样**，“在上限处中途停止”）并附上它的文件，报告会写道“第 4 轮被中途停止，它的工作仍在文件夹中。对第 3 轮点击 **仍然保留…** 会把文件恢复到最佳的一轮。” **给它更多…** 会从文件现在的状态接着进行。已达成或被你停止的目标则就此结束。

通知：目标工作期间，你会在检查项已就绪等你查看时、某项检查无法运行时、它向你提问或需要你时、它暂停时、它在上限处停止时，以及目标达成时（“达成目标：…”）收到通知，而不是每一轮都收到一条“已完成”；在它等你的时候，“已完成”通知不会被压下。参见 [各条通知的含义](/guide/inbox#what-each-notification-says)。

## 在 Claude Code 或 Codex 中输入 /goal

在 Claude Code 或 Codex 的聊天中输入 `/goal` 并跟上一个条件，是该程序自带的、较简单的目标：程序会一直进行，直到它判断目标已达成（Claude Code 在每一轮之后检查；Codex 自行决定）。它没有商定的检查项、轮次或撤销，并显示在消息框上方较旧的小栏中，带有 **暂停** 和 **继续**（Codex）以及 **清除**。会话菜单中的 **设定目标** 是应用自己的目标，适用于所有智能体。在 Custom 会话或其他智能体的会话中，`/goal` 只是普通文本。一个会话不能同时拥有两者：当程序自带的目标已设定时，**设定目标** 会被拒绝；在应用的目标运行期间输入的 `/goal` 会像任何消息一样交给程序，并且没有任何东西会注意到它。

- “设定一个目标：在我的评测上把 nDCG@10 比基线提高 1 个点，最多 10 轮。”
