# 手机、其他机器和分享

Naget Agent 在任何浏览器里都能用：在你的手机上、在另一台电脑上，也可以横跨几台各自运行它的机器。本主题介绍：在手机上使用它，从别处安全地访问它，在一个应用里使用其他机器，用只读链接分享会话，让别处的智能体在这里启动和引导会话，以及添加用来创建拉取请求的 GitHub 或 Gitea 账户。

## 在手机上使用应用

手机上的应用和电脑上的是同一个应用，只是为小屏幕重新排布了（电脑上的窄窗口也会用这种布局）。不同之处在于：

- **侧边栏是一个抽屉**。轻点页面或会话左上角的**菜单**（≡）即可打开它。它占满整个屏幕，里面有你的会话、收件箱和各种工具；轻点一个会话或工具即可前往，或轻点**关闭菜单**（✕）返回。
- **选择器以底部面板的形式打开**。在开始页上，智能体、模型、文件夹、助手和**选项**的菜单会从屏幕底部升起，避开键盘，背后的页面会变暗；**选项**下的某项设置会在它的面板上方打开。在会话中，消息框里的模型标签（以及它的思考强度和权限）也会以同样的方式打开一个面板。对话框同样从底部升起。
- **一次只显示一样东西**。设置是一个列表，每个部分各占一页。文件页一次显示一个文件夹，名称显示在顶部（轻点名称可以打开位置，**‹** 回到上一级文件夹），再在单独的页面上显示文件，带有**返回**。Git 页面先列出你的仓库，再打开其中一个，带有返回箭头。
- **用触摸代替鼠标**。在文件页中，一行的 ⋯ 会打开它的菜单，长按一行则会选中它，以便一次处理多项。编辑器会把长行自动换行。终端页面会多出一排手机上没有的按键（Ctrl、Alt、Esc、Tab、方向键等）。

要在手机上访问应用，首先它必须能从这台电脑之外访问到：见[从其他设备访问应用](/guide/devices#reach-the-app-from-another-device)。

### 把它添加到主屏幕

安装到主屏幕后，应用会像其他应用一样，带着自己的图标全屏打开。这需要应用通过 HTTPS 提供（见[从其他设备访问应用](/guide/devices#reach-the-app-from-another-device)）。

- **iPhone 或 iPad**：在浏览器中打开应用，轻点**分享**，然后轻点**添加到主屏幕**。此后就从新图标打开 Naget Agent。
- **Android**：在浏览器中打开应用，用浏览器菜单中的选项安装应用，或把它添加到主屏幕。

### 在手机上接收通知

会话完成、失败或需要你答复时，即使应用已关闭，通知也能送到你的手机上。

1. 在手机上打开[设置 → 应用 → 通知](/settings?s=notifications&find=Notify%20this%20device)。
2. 开启**通知此设备**，并在浏览器询问时允许通知。每台设备各自开启这一项。
3. **发送测试**可以检查它是否正常（通知只在应用不在眼前时显示）。

在 iPhone 或 iPad 上，先把应用添加到主屏幕并从那里打开：否则浏览器收不到通知。如果这个网站的通知被屏蔽了，请先在浏览器设置中允许。对于简单的“是或否”批准，只要手机能显示按钮，通知上就会直接带有**批准**和**拒绝**。更多内容见[收件箱和通知](/guide/inbox)。

## 从其他设备访问应用

默认情况下，应用只在它运行的那台电脑上响应（`127.0.0.1` 的 8790 端口）。任何能访问到它并知道密码的人，都能以你的用户身份在那台电脑上运行任何命令，所以要像对待这台电脑的 SSH 访问一样对待它。要从手机或另一台电脑使用它，请在它前面加一层 HTTPS，而不要把端口直接开放到网络上：

- **Tailscale**：在这台电脑上运行 `tailscale serve --bg 8790`，应用就会在 `https://<machine>.<tailnet>.ts.net` 上提供，只有你自己的设备能访问。
- **Cloudflare Tunnel**：把一条隧道指向 `http://localhost:8790`。Cloudflare Access 还可以在前面再加一道登录。
- **你自己的反向代理**，例如 Caddy，把你的某个主机名转发到 `127.0.0.1:8790`。

如果代理会改动 `Host` 请求头，就要告诉应用大家用来打开它的地址：`ALLOWED_ORIGINS=https://agents.example.com`。这类设置，作为服务安装的应用写在 `~/.config/naget-agent.env` 里（每行一个 `NAME=value`），用 Docker Compose 运行的则写在 `.env` 里；之后重启应用。

手机要安装应用和接收推送通知，也需要 HTTPS。开发服务器的预览使用单独的端口（8791）；见[用预览查看开发服务器](/guide/files-git#look-at-a-dev-server-with-preview)。

密码守护着一切。登录后，浏览器会保持登录 30 天。输错的密码按它们来自的地址计数，只算最近一小时：

- 输错三次后，登录页还会显示一张有五个字符的图片，要把这些字符输入到**图片中的字符**里，这样程序就没法一直猜下去。字符输错不算次数，**换一张图片**（旁边的圆形箭头）会换来另一张。
- 输错十次后，这个地址一小时内无法登录，即使密码正确也不行。页面会说明还要等多久。
- 所有地址加起来输错十次后，每个人都会看到图片；加起来六十次后，在这一小时结束前谁都无法登录。

在上面任一种代理后面，计数用的是访问者自己的地址，由代理转告给应用。如果把自己锁在了外面，可以换个网络登录（比如用手机的移动数据）、等一等，或者在那台电脑上设置新密码，这会解除所有暂停。见[修改密码](/guide/app#change-your-password)。

## 在一个应用里使用其他机器

如果 Naget Agent 运行在不止一台机器上（一台台式机、一台 GPU 服务器、一台云电脑），你可以从其中一台使用所有机器。每台机器都保留自己的会话、文件、终端、登录和设置；你打开的应用一次显示一台机器，用侧边栏在它们之间切换。

这在[设置 → 应用 → 机器](/settings?s=machines)里设置。其中的**机器**列表以这台机器开头（“此服务器”，附带它的版本），后面是你添加的机器，每台都有：

- 一个圆点：有响应时为绿色，正在连接时为灰色，没有响应时为红色；
- 它的连接方式（`ssh gpu-box` 或它的地址）和它的状况：“在线”、“2 个需要你 · 1 个在工作”、“正在连接…”或“无法连接”（附带原因）；
- **打开**（它的页面）、**编辑**和**移除**。没有响应的机器还有**立即重试**。

### 添加机器

1. **在另一台机器上**，安装 Naget Agent，并为这台机器创建一个访问令牌：在那台机器自己的[设置 → 应用 → 机器](/settings?s=machines&find=Access%20from%20other%20machines) → **新建令牌**，或者在它的 Naget Agent 文件夹里运行 `node dist/server/cli.js access-token "my laptop"`。复制这个令牌（它以 `acm_` 开头）。
2. **在这台机器上**，打开[设置 → 应用 → 机器](/settings?s=machines&find=Add%20a%20machine)，点击**添加机器**。
3. 给它起个**名称**（“GPU 主机”）。
4. 在**连接方式**下，选择这台机器如何到达那里：
   - **通过 SSH**，最简单：填写 **SSH 主机**（你的 `~/.ssh/config` 里的一个名称，或 `user@host`）和**它的端口**，即 Naget Agent 在那边监听的端口（8790）。这台机器用它自己的 SSH 密钥建立连接，这些密钥必须无需输入口令就能使用。另一台机器仍然只在它自己的 `127.0.0.1` 上监听：那边什么都不用开放。
   - **通过地址**，适用于私有网络、Tailscale 或 WireGuard 之类的 VPN，或者在 HTTPS 后面：例如 `http://100.64.0.5:8790`。那边的应用必须在这台机器能到达的地方监听（它的 `HOST` 设置）。
5. 粘贴**访问令牌**，然后点击**连接**。

应用会先确认这台机器有响应，然后才保存它。如果没有响应，对话框会说明原因（“无法使用 GPU 主机：…”），什么也不会添加。

### 在机器之间切换

添加了机器之后，侧边栏顶部、**新建会话**上方会出现一行，显示当前机器的名称。点击它可以看到每台机器及其状态，当前显示的那台带有勾号；选一台即可转到它的页面。**添加或更改机器**会打开设置 → 机器。

在另一台机器的页面上，这一行会高亮显示，让你知道自己在哪里；行上的圆点表示其他机器上有会话在等你。如果那台机器没有响应，页面会显示“无法连接到 …”，并带有**重试**、一个返回你自己机器的按钮，以及**设置 → 机器**。

### 跨机器时什么能用

- **一台机器页面上的一切都属于那台机器**：它的会话、文件夹和文件、Git、终端、智能体的登录、模型和设置。
- **有些东西总是来自你打开应用的那台机器**：你的密码和登录、机器列表、通知、你制作的主题，以及欢迎导览和它之后的小贴士。
- **每台机器的提醒都会送到你这里**。来自另一台机器的提醒会注明是哪台，推送通知经由你自己的机器发出，[收件箱](/guide/inbox)会列出每台机器上等你处理的事项。侧边栏收件箱上的计数也包含它们。
- **只读链接**对其他机器上的会话同样有效（见[用只读链接分享会话](/guide/devices#share-a-session-with-a-read-only-link)）。
- **其他机器上没有的**：预览，它只打开你打开应用的那台机器上的开发服务器；还有连接其他智能体，因为每台机器自己的服务器要通过它自己的地址访问。
- 你的浏览器会为每台机器分别记住文件页的文件夹、打开的文件，以及你上次用过的终端。

### 更改或移除机器

- **编辑**可以更改名称、连接方式或访问令牌。令牌留空即保留原有的令牌。连接方式有改动时，会先重新检查，然后才保存。
- **移除**会先询问。那台机器的会话仍留在那台机器上；这个应用只是不再显示它们。

### 让其他机器使用这台机器

在**从其他机器访问**下（在另一台机器的页面上则显示为**对 … 的访问**，… 即那台机器），你可以创建其他机器用来访问这台机器的令牌。持有这种令牌的另一个 Naget Agent 能做你在这里能做的一切，包括运行命令，所以要为每台连接过来的机器各创建一个。

1. 点击**新建令牌**。
2. 回答 **哪台机器会使用它？**（“我的笔记本电脑”），然后点击**创建令牌**。
3. 复制令牌，粘贴到另一台机器的设置 → 机器中。它只在此时显示这一次。

每个令牌都会显示创建时间和最近使用时间。**撤销**（确认之后）会立即切断那台机器。

## 用只读链接分享会话

只读链接能让没有你密码的人实时关注一个会话。打开会话的菜单（⋯）→ **分享只读链接**。

1. 在**有效期**下，选择**一天**、**一周**、**一个月**或**直到关闭**。
2. 点击**创建链接**。
3. 复制链接并发送出去。它只显示一次；你随时可以再创建一个。

**当前有效的链接**列出这个会话正在生效的链接，每条都显示创建时间、结束时间（一直有效到关闭的显示为“无期限”）、被打开过几次以及最近一次是什么时候。**关闭**（垃圾桶图标）会立即停用一条链接。

### 对方看到什么

链接只打开这个会话本身，没有侧边栏，也没有可以输入的地方。它显示会话的标题、在其中工作的是哪个智能体、“只读，分享自 Naget Agent”，以及智能体工作时的“正在工作”。下面是对话：你的消息、智能体的回复、它的各个步骤名称（附带每处文件修改增删的行数，修改本身点一下就能看到），以及智能体展示过的页面。智能体工作时，它会每隔几秒自己跟着更新。

对方看不到命令输出、智能体的思考过程、你附加的图片（只能看到附过图片）或应用里的其他任何内容，也不能输入或更改任何东西。已到期或被关闭的链接会显示“此链接已过期或已被关闭”。

## 把其他智能体连接到这个应用

在别处运行的智能体（你笔记本电脑上的 Claude Code、Codex、Cursor，或任何支持 MCP 的客户端；MCP 是智能体调用工具所用的协议）可以通过应用自带的 MCP 服务器，列出、读取、启动和引导这台机器上的会话。每个智能体都需要一个令牌，在[设置 → 应用 → 连接其他智能体](/settings?s=connect)中创建。持有令牌的智能体可以像你一样在这里启动和引导会话。

1. 点击[**新建令牌**](/settings?s=connect&find=New%20token)。
2. 在**按它要用在哪里来命名**下，输入类似“我笔记本电脑上的 Claude Code”的名字，然后点击**创建令牌**。
3. 现在就复制你需要的内容（之后不会再显示）：
   - **令牌**，即令牌本身。
   - **Claude Code**：一条添加该服务器的命令，`claude mcp add --transport http naget-agent <address>/mcp --header "Authorization: Bearer <token>"`。
   - **Codex**：写入 `~/.codex/config.toml` 的几行配置，令牌放在环境变量 `NAGET_AGENT_TOKEN` 中。
   - **其他客户端（JSON）**：常见的 MCP 服务器条目。

这个地址就是你浏览器当前打开的地址，所以另一台机器上的智能体必须以和你的浏览器相同的方式访问应用（见[从其他设备访问应用](/guide/devices#reach-the-app-from-another-device)）。

**Token** 列表显示每个令牌的名称、创建时间和最近使用时间。为每个智能体或每台机器各创建一个，这样你就可以逐个**撤销**；撤销会立即切断那个智能体。

### 它们能做什么

[**它们能做什么**](/settings?s=connect&find=What%20they%20can%20do)列出了持有令牌的智能体能用的工具：

- **list_sessions** 和 **read_session**：找到一个会话并了解它的进展（它的消息，以及各个步骤的名称）。
- **start_session**：在任意文件夹中新建一个带首条消息的 Claude Code 或 Codex 会话，还可以让它在自己的工作树中运行。它会返回一个你可以打开的链接。
- **send_message**：引导一个会话。如果它的智能体正忙，消息会在会话的队列里等到这一轮结束。
- **list_models**：新会话可以使用的模型。

你提供给其他智能体的应用（应用的**提供给其他智能体**开关，见[应用](/guide/apps)）也会作为工具出现，用应用表单里的字段来运行应用。

在这个应用里启动的会话不需要这些。这一部分只在你打开应用的那台机器上显示，在其他机器的页面上不会出现。

## 添加 GitHub 或 Gitea 账户

拉取请求要用[设置 → 应用 → 源代码管理](/settings?s=scm)中的账户来创建。每个账户负责它所在服务器上的仓库：GitHub、GitHub Enterprise 服务器或 Gitea 服务器。推送本身用的是这台电脑自己的 git 设置（它的 SSH 密钥或保存的凭据）；账户用于创建拉取请求和跟踪它的检查。

1. 点击[**添加账户**](/settings?s=scm&find=Add%20an%20account)。
2. 选择 **GitHub** 或 **Gitea**。
3. 对于 GitHub：如果这台电脑上的 GitHub CLI 已登录，**使用它的登录**只需点一下就能添加账户，这样就完成了。否则，粘贴一个**访问令牌**：一个细粒度令牌，对你的仓库拥有 Pull requests（读写）、Contents（读取）和 Commit statuses（读取）权限（**创建一个**会打开 GitHub 上的相应页面）。只有 GitHub Enterprise 才需要填写**服务器地址**。
4. 对于 Gitea：填写**服务器地址**（`https://gitea.example.com`），以及一个在 Gitea 的 Settings → Applications → Generate token 中创建、带有仓库读写权限的**访问令牌**。
5. 点击**添加**。应用会向服务器询问令牌属于谁，以此检查令牌，然后把账户列在那个用户名下。

同一服务器的第二个账户会取代第一个。每个账户都显示它的用户名、服务器，适用时还会显示“通过 GitHub CLI”，并附有打开该服务器的链接。**移除**会先询问：已经关联到会话的拉取请求会保持关联，但它们的状态不再更新。

拉取请求如何创建和跟踪：[从会话创建拉取请求](/guide/files-git#open-a-pull-request-from-a-session)。

## 问问智能体

- “为这个会话创建一个有效期一周的只读链接。”
- “关闭这个会话的所有分享链接。”
- “我的哪些机器离线了？试着重新连接它们。”
- “把名为 gpu-box 的机器重命名为‘工作室 GPU’。”
- “列出其他智能体用来访问这个应用的令牌，并撤销名为‘旧笔记本电脑’的那个。”
- “用 GitHub CLI 的登录添加我的 GitHub 账户。”
