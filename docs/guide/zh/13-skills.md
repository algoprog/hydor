# 技能

技能是写成文字的方法，智能体在任务需要时加载它们：怎样研究一个问题、追查一个故障、制作 Word 文档，或在任务结束后清理。本主题介绍应用自带的技能库、智能体经你批准后学会的技能、空间自己的技能、为 Custom 引入技能的关键词，以及 Claude Code 和 Codex 自己的技能。

![设置 → 技能库：智能体经你批准学会的技能，以及应用自带的技能](images/skills.webp)

## 什么是技能

技能是一份简短的指南，智能体在做某一类工作时照着它来做。每个技能是一个文件夹，里面有一个名为 SKILL.md 的文件：一个名称，一行说明何时使用，然后是步骤、检查项和要避免的错误。有些技能还带有自己的文件：步骤中用到的示例、模板或小脚本。

智能体并不会一直读取所有技能。会话开始时，智能体只看到每个技能的名称和那一行“何时使用”。当某个任务适合某个技能时，它才加载并遵循那个技能。打个招呼、问个简单问题或做一处小而明确的修改，都用不着技能。

在应用中，技能来自三个地方：

- **技能库**，位于[设置 → 技能库](/settings?s=skillpack)：应用自带的技能，以及智能体经你批准后学会的技能。从应用启动的 Claude Code、Codex 和 Custom 会话都能获得它。
- **空间自己的技能**，位于空间的**技能**标签页：只有在这个空间里启动的会话才会获得它们，和技能库一起使用。参见[给空间添加它自己的技能](/guide/spaces#give-a-space-skills-of-its-own)。
- **Claude Code 和 Codex 自己的技能**，位于[设置 → 技能](/settings?s=skills)：你自己的文件夹和项目文件夹中的技能，这两个智能体无论在哪里运行都会读取。

助手也可以指定它偏好的技能：当其中某个技能适合当前任务时，智能体会在开始前加载它。参见[助手](/guide/assistants)。

## 哪些智能体获得哪些技能

应用启动的每个 Claude Code、Codex 和 Custom 会话都会获得技能库：

- **Claude Code** 以一个名为“naget”的插件获得它，所以其中的技能名称前面会带上这个名字：naget:research、naget:writing 等等。
- **Codex** 以一个额外的技能文件夹获得它。
- **Custom**（应用自带的智能体）在它的技能列表中获得它。参见 [Custom](/guide/custom)。

在应用之外（终端或 VS Code 中）启动的会话看不到技能库。技能库不会往你的 Claude Code 或 Codex 设置里写入任何东西。

空间里的会话会在同一个插件、文件夹或列表中获得空间自己的技能，和技能库的技能一起。空间里与技能库中某个技能同名的技能，会在这个空间的会话中替代它。

你自己的技能和项目的技能优先。如果其中某个技能与技能库中的技能同名，智能体会使用你的。

Custom 按以下顺序从多个文件夹读取技能：项目自己的技能（在项目的 `.claude/skills` 和 `.agents/skills` 文件夹中），你为 Claude Code（`~/.claude/skills`）和 Codex（`~/.agents/skills` 和 `~/.codex/skills`）准备的个人技能，最后是技能库。两个技能同名时，先找到的那个生效。所以你在设置 → 技能中为 Claude Code 或 Codex 写的技能，Custom 也能用上。

## 查看智能体何时使用技能

当智能体加载一个技能时，对话中会出现一个小标签：**正在使用技能 research**，智能体读取它时还会显示一个转圈图标。Claude Code、Codex 和 Custom 都是如此。

点击这个小标签即可阅读技能：它的内容、适用场景和历史（参见[阅读技能及其历史](#read-a-skill-and-its-history)）。如果这个技能不属于应用的技能库，窗口会注明：它来自你自己的或项目的技能文件夹。在空间里，如果智能体使用的是空间自己的技能，小标签会打开空间的那个技能：窗口的标记显示空间的名称，**空间的技能**会打开它的技能标签页。

如果是你自己的话把某个技能引入了 Custom 会话，小标签会注明是哪些词引入的：“因你消息中的‘research’而引入”。参见[按关键词引入技能](#bring-skills-in-by-keywords)。

智能体每加载一次技能，就算使用一次。技能库会显示每个技能被使用的次数，以及最近一次使用的时间。

## 打开技能库

前往**设置 → 功能 → 技能库**（[打开](/settings?s=skillpack)）。在手机上，先打开设置，再轻点“功能”下的**技能库**。

这个页面最多有四个部分：

- **等你处理**：智能体提议、需要你答复的技能。只有存在这类技能时才会显示。
- **已习得**：你批准过的技能。
- **内置**：应用自带的技能。
- **智能体如何获得它们**：**按关键词引入技能**开关，以及每个智能体如何获得技能库。

你也可以在搜索框（Ctrl+K，Mac 上是 ⌘K）中查找技能：输入它的名称或用途。技能显示在**技能**下，选中一个就会在技能库中打开到那个技能。

## 内置技能

**内置**（[打开](/settings?s=skillpack&find=Built%20in)）下是应用自带的技能。它们随应用一起更新，智能体在任务需要时加载相应的技能。每一行显示技能的名称、何时使用、智能体使用它的次数（“已使用 3 次，最近一次是 2 天前”，或“尚未使用”），以及它供 Custom 使用的关键词（如果有）。点击名称即可阅读整个技能。

应用自带以下技能：

- **app-builder**：用于制作或修改你的应用。智能体先弄清楚输入什么、输出什么，为每个部分选最省的步骤，给应用配上带检查的示例，并在交给你之前试运行，说明一次运行要花多少钱。
- **clarify-first**：用于规模大或开放式的请求（一个网站、一次旅行、一次装修、一场演讲、一份商业计划）。智能体先阅读已有的内容，一次只问一个问题并说明为什么问，复述它的理解，给出两三种做法，并在动手之前写一份简短的说明供你批准。
- **clean-up**：在任务结束时使用。智能体列出它在过程中创建的东西，删除不再需要的（草稿文件、测试数据、临时文件夹、已合并或已放弃的分支、工作树、它启动的进程），从不删除不是它创建的东西，涉及大的或共享的东西时会先问你，最后用一句话说明删了什么、留下了什么。只要[设置 → 助手](/settings?s=assistants&find=Clean%20up%20after%20a%20task)中的**任务完成后清理**是开启的（除非你关闭，否则默认开启），每个智能体都会被要求在任务结束时这样做。
- **decisions-log**：用于你不在场时的工作（一个目标、一个定时任务、“不用等我”）。智能体自己解决一般的问题，把每个决定连同理由以及万一错了的代价记下来，然后继续工作。它只在以下情况前停下：无法撤销的步骤（发送、付款、删除、发布）、任何涉及密码或访问权限的事，或者任何超出工作范围的事；它的最后一条消息会列出它做的每个决定。
- **evidence-before-done**：在智能体说某件事已完成、已修好、已保存、已发送或属实之前使用。它会指出能证明这一点的检查，运行检查，读取结果，然后连同证据一起报告；或者坦白说明哪些它无法核实。
- **pdf**：制作 PDF（报告、发票、证书、传单、表格），合并、拆分、旋转、填写 PDF 或给它们加盖印章，把 Office 文件转成 PDF，以及阅读 PDF（包括扫描页）。
- **presentations**：制作或修改幻灯片（.pptx），保持整体风格统一，包含图表、表格和演讲者备注，交付前先把它们当作图片看一遍，还能阅读 .pptx、.ppt 和 .odp 文件。
- **research**：规划一个问题需要的搜索，先广泛搜索再逐步聚焦（论文、专利、新闻、公开申报文件），用两个独立来源或一个原始来源核对每个关键说法，最后附上引用作答，并说明哪些无法证实。
- **spreadsheets**：制作或修改带公式、数字格式和图表的工作簿（.xlsx），检查公式是否有错，还能阅读 .xlsx、.xls、.ods 和 .csv 文件。
- **troubleshooting**：用于任何没有正常工作的东西（一个错误、一台设备、家庭网络、一个公式、一份食谱）。智能体会有意让问题重现，收集事实，一次只验证一个想法，修复根本原因，并证明它已修好。
- **word-documents**：制作或修改 Word 文档（.docx），使用真正的标题、列表和表格，交付前先查看页面效果，还能阅读 .docx、.doc 和 .odt 文件。
- **writing**：用于任何要给人读的东西（报告、文章、信件、演讲稿、故事）。智能体先确定谁来读、为什么读，先列提纲再起草，并分几遍分别修改。

文档类技能（pdf、presentations、spreadsheets、word-documents）用小型 Python 脚本生成文件。它们需要这台电脑上有 Python 3。第一次需要时，它们用到的库会被下载到应用数据文件夹中的一个私有文件夹里（约 30 MB，只下载一次）；不会为整个系统安装任何东西。如果缺少 Python，智能体会告诉你安装它的命令。为了在交付文件前把页面当作图片查看，如果这台电脑上有 LibreOffice 和 Poppler，它们就会用上这两者。参见[文档、图片和语音](/guide/documents-voice)。

内置技能没有“移除”按钮。你不能删除它们，但智能体可以提议改进某个内置技能，改进后的版本会保存为你自己的版本（参见[你自己版本的内置技能](#your-version-of-a-built-in-skill)）。

## 阅读技能及其历史

在技能库中点击技能的名称，或点击对话中的**正在使用技能**小标签。会打开一个窗口，其中有：

- 技能的名称和一个标记：**内置**、**已习得**，或空间自己的技能显示空间的名称；
- 何时使用；
- 它的关键词（如果有）：“当你说出以下内容时，Custom 会引入它”，后面是这些词；
- 两个标签页：**技能**，即智能体读到的完整指南；以及**历史**，并显示更改次数；
- 底部是它的文件在这台电脑上的位置。

**历史**列出这个技能的每一次更改，最新的在前：**已保存**、**已修改**、**已移除**或**已恢复**，距今多久，以及新增和删除了多少行。点击某次更改可以逐行查看；最新的一次已经展开。没人改过的内置技能会注明它是随应用提供的原始版本。

在手机上，这个窗口会以从屏幕底部弹出的面板打开。**关闭**可以关掉它。

## 智能体学会的技能

**已习得**（[打开](/settings?s=skillpack&find=Learned)）下是你批准过的技能，供每个智能体使用。每一行显示：

- 名称；如果它取代了某个内置技能，会带有**你自己版本的内置技能**标记；
- 何时使用；
- 智能体使用它的次数、保存于多久以前，以及它供 Custom 使用的关键词（如果有）；
- **历史**（时钟图标），会打开该技能的“历史”标签页；
- **移除**（垃圾桶图标）。

还没有已习得的技能时，页面会说明它们从何而来：完成一项真正费力的任务后，智能体可以提议把它的做法保存为技能，或改进它所遵循的某个技能，而你可以逐一批准、编辑或忽略。

### 移除已习得的技能

1. 点击它所在行的**移除**（垃圾桶图标）。
2. 再点**移除**确认。

智能体将不再看到这个技能。如果它是你自己版本的内置技能，智能体会改回使用内置版本。技能的文本会保留在它的历史中，所以你可以把它找回来。

### 找回已移除的技能

已移除的已习得技能列在**已习得**下面的“**已移除：**”之后。点击那里的名称（鼠标悬停可以看到它是何时移除的）。技能的文本会恢复成你移除它时的样子，智能体也会重新获得它。

### 把你自己的技能加入技能库

页面底部会显示已习得技能所在的文件夹（在应用的数据文件夹中，除非你的安装把数据放在别处，否则是 `~/.naget-agent/skills`）。你自己放进去的技能也会加入技能库，供每个智能体使用：每个技能一个文件夹，用小写字母、数字和短横线命名，里面放它的 SKILL.md。它们会显示在**已习得**下。

## 批准、编辑或忽略提议的技能

完成一项真正费力的任务后，智能体可能会提议把它的做法保存为技能：试了好几次才找到的修复方法、你不得不解释的工作流程、步骤容易出错的过程。当它发现所遵循的某个技能缺了一步、有错误或不够清楚时，也可能提议改进那个技能。智能体被告知不要提议一次性的事实、你的个人信息或任何机密内容。

在你批准之前，什么都不会保存。在此期间智能体会继续它的工作，你的答复会作为一条消息送达它。

### 卡片上显示什么

提议会以卡片的形式出现在对话中，位于折叠的步骤之外，智能体则继续工作。卡片顶部会问：**把这个保存为技能？**、**改进这个技能？**，或**改进这个内置技能？**，并附上技能名称和一个标记：**等你处理**、**已保存**、**已忽略**或**已替换**。

下面是：

- **原因**：用智能体自己的话说明，这次任务中发生了什么让它值得保留。
- **适用场景**：智能体据以判断何时使用它的那一行。如果改进提议修改了这一行，旧的那行会显示为删除线。
- 它供 Custom 使用的关键词（如果有）：“当你说出以下内容时，Custom 会引入它”，后面是这些词。
- 警告（如果有，参见[卡片上的警告](#warnings-on-the-card)）。
- 正文，可以在**文本**（新技能）或**更改**（改进，逐行显示）与**技能**（指南读起来的样子）之间切换，并显示它新增和删除了多少行。
- 在空间里，**保存给**：**所有会话**或空间的名称（参见[智能体在空间里提议的技能](/guide/spaces#skills-agents-propose-in-a-space)）。

### 批准

点击**批准**。技能会保存到你的技能库中，卡片会显示它已在你的技能库中：每个智能体都能使用。点**技能库**链接可以前往那里。

如果在**保存给**下选了空间的名称，它会改为保存到空间的技能中：卡片会说明它已在其中，**空间的技能**会带你前往那里。

Custom 从下一轮起就能使用这个技能；Claude Code 和 Codex 则从下一个会话起。

### 先编辑

1. 点击**编辑…**。会打开一个窗口，以文本形式显示整个技能。
2. 随意修改。顶部那几行（两个 `---` 行之间）是它的名称（必须保留）和说明何时使用的那一行。它们下面的全部内容就是智能体遵循的指南。
3. 点击**保存并批准**。

卡片随后会注明你在保存前编辑过它，并显示保存后的版本。应用检查你编辑的文本，和检查智能体写的文本一样：需要有一行说明何时使用、有实际的步骤，并且不能含有机密。

### 忽略

1. 点击**忽略…**。
2. 你也可以在打开的输入框中告诉智能体原因（可选）。
3. 点击**关闭**（或点**取消**返回）。

什么都不会保存。智能体会得知你忽略了它，连同你的说明，并被告知除非你要求，否则不要再提议它。

### 卡片上的警告

技能是每个智能体都会读取的文件，所以应用会在你看到每份提议之前先检查它：

- **含有机密的提议会被拦下**。如果提议中有看起来像密码、密钥或令牌的东西（API 密钥、私钥、直接写出的密码或藏在网址里的密码），它根本不会以卡片的形式到达你这里。智能体会被要求把它删掉，改为说明机密存放在哪里。
- **试图操纵智能体的文字会被指出**。当提议新增的某一行有以下情况时，卡片会显示**批准前请先看看这几行**，并列出行号和文字：要求智能体忽略它们的指令、试图替换智能体的身份、要求智能体对你隐瞒某些事、试图绕过批准、把密钥或私人文件发送到别处、直接运行来自互联网的脚本、修改智能体设置或启动文件、在项目之外很远的地方删除或覆盖内容、把指令藏在 HTML 注释里，或者含有你看不见的字符。

批准带有警告的提议时，会再问一次：“**有这些警告，仍要保存吗？**”只有当被标出的那几行确实是你希望智能体遵循的内容时，才点**保存**。

### 在设置或收件箱中答复

一份提议会在三个地方等你，在其中任何一处答复，都会在所有地方、所有设备上显示出来：

- 它所在对话中的卡片；
- 技能库顶部的**等你处理**（“智能体在完成困难任务后提出的技能。你批准之前，什么都不会保存。”）。每一行显示**新建技能**或**修改**加上名称、距今多久、来自哪个对话（点击可打开），有警告时还会显示“有警告”。**审查**会在一个窗口中打开同样的卡片；
- [收件箱](/inbox)，显示为“建议新增技能：…”或“建议修改 … 技能”。**打开**会带你到它所在的对话，卡片就在那里。参见[收件箱和通知](/guide/inbox)。

### 限制

- 一份提议最多 20,000 个字符。更长的指南会被拒绝，智能体会被要求只保留主要步骤。
- 新技能需要一个未被使用的名称。名称由简短的小写单词和短横线组成，例如 release-notes。
- 同一个对话中，最多同时有五份提议等你处理。
- 如果智能体在你答复之前再次提议同一个技能，新的提议会取代旧的，旧的会显示**已替换**。
- 如果在提议提出之后，又保存了一个同名技能，或者该技能被修改过，批准会失败并显示一条消息。请忽略它，再问一次智能体。
- 智能体只能改进应用技能库中的技能和空间自己的技能。你自己文件夹或项目文件夹中的技能不会以这种方式修改：请在[设置 → 技能](/settings?s=skills)中编辑它们。
- 已答复的提议会在旧对话的卡片上保留半年。

## 你自己版本的内置技能

当你批准对某个内置技能的改进时，卡片上已经提示过：“内置技能：批准后会保存你自己的版本来替代它。原版仍保留在应用中。”你的版本一开始是该内置技能整个文件夹的副本（包括其中的示例和脚本），并已做出相应修改。

从那以后，智能体会使用你的版本而不是内置版本，即使应用之后更新了内置技能也是如此。它显示在**已习得**下，带有**你自己版本的内置技能**标记。要改回内置技能，移除你的版本即可：参见[移除已习得的技能](#remove-a-learned-skill)。

## 按关键词引入技能

有些模型很少自己去加载技能。对于这些模型，当你的消息用到某个技能的关键词时，Custom 可以把这个技能引入：技能的文本会随你的消息一起送达，智能体在合适的地方遵循它。

这个开关位于**设置 → 功能 → 技能库 → 智能体如何获得它们 → 按关键词引入技能**（[打开](/settings?s=skillpack&find=Bring%20skills%20in%20by%20keywords)）。除非你关闭，否则它是开启的。它只影响 Custom；Claude Code 和 Codex 会自己加载技能。关闭后，Custom 仍能看到它的技能列表，并在任务适合时加载某个技能。

当关键词引入了某个技能时，对话中你的消息下方会出现一个小标签：**正在使用技能 research**，“因你消息中的‘research’而引入”。点击它即可阅读这个技能。

### 关键词如何匹配

- 关键词按整词匹配，不区分大小写：“research”不会匹配“researchers”。
- 以 * 结尾的关键词也会匹配更长的词：“renovat*”能匹配 renovate 和 renovation；“debug*”能匹配 debugging。
- 少于四个词的消息不会引入任何技能，所以“好的，继续”永远不会加载技能。
- 一次最多引入两个技能：在你的消息中出现关键词最多的技能优先。
- 引入的技能会在那条消息和接下来的两条消息中保持有效，这样像“先问清楚”或“做研究”这样的过程就能跨越几轮进行。较新消息引入的技能会取代较旧的。
- 较长的技能会被截短，以适应模型能接收的长度；智能体会被告知自己去加载其余部分。

带有关键词的内置技能有：app-builder（“make a template”、“make an app”、“automate”…）、clarify-first（“plan a trip”、“business plan”、“renovat*”…）、clean-up（“clean up after”、“leftover files”…）、decisions-log（“while I'm away”、“overnight”…）、evidence-before-done（“double-check”、“verify”…）、research（“research”、“find sources”、“fact-check”…）、troubleshooting（“not working”、“keeps crashing”、“debug*”…）和 writing（“draft a”、“proofread”、“cover letter”…）。文档类技能没有关键词：Custom 会在任务适合时加载它们。你可以在每个技能所在的行和它的页面上看到它的关键词。

### 给技能设置关键词

技能的关键词是写在其 SKILL.md 顶部几行中的一个列表，例如 `triggers: [weekly report, status update, standup]`。智能体在提议新技能时最多可以附带 12 个关键词，每个 3 到 40 个字符。Custom 也会匹配你自己文件夹和项目文件夹中技能的关键词，因为它也会读取这些技能。

## Claude Code 和 Codex 自己的技能

Claude Code 和 Codex 还会从它们自己的文件夹中读取技能：你的个人技能文件夹，它们在任何文件夹中都会读取；以及项目的技能文件夹，它们只在该项目中读取。前往**设置 → 智能体 → 技能**（[打开](/settings?s=skills)）查看和管理它们。

### 选择文件夹

项目的技能取决于文件夹，所以这个页面一次只显示一个文件夹的技能。**文件夹**按钮位于这一部分的标题旁边（在手机上，位于描述这一部分的那行文字下方）。它一开始指向在[文件](/files)中打开的文件夹，否则就是你的默认文件夹。点击它可以选择另一个文件夹。

### 列表显示什么

顶部有：**全部**、**Claude Code** 或 **Codex**，可以只显示某一个智能体的技能；一个**筛选技能**输入框（它会匹配名称、描述和插件名称）；以及**新建技能**。

接下来每个智能体各有一个部分，并显示它有多少个技能。每一行显示技能的名称（关闭时显示为灰色）、一个表示来源的标记、插件技能所属插件的名称，以及它的描述：

- **此文件夹**：该文件夹自己的技能。
- **此仓库**：随仓库一起提供的 Codex 技能。
- **所有文件夹**：你自己的技能，适用于每个文件夹。
- **插件**：随插件提供的技能。插件在[设置 → 插件](/settings?s=plugins)中管理。
- **内置**：Codex 自带的技能。
- **管理员**：管理员为 Codex 设置的技能。

对于 Claude Code，页面会列出你的技能（在 `~/.claude/skills` 中）和该文件夹的技能（在它的 `.claude/skills` 中；如果该文件夹就是你的主文件夹，则没有）。对于 Codex，页面会列出 Codex 自己为该文件夹报告的技能。读取技能时出现的问题，例如 Codex 没有响应，或有它读不了的技能文件，会在列表上方的提示中显示。

应用自己的技能库不在这个列表中：它有自己的页面，[设置 → 技能库](/settings?s=skillpack)。

### 开启或关闭技能

使用行末的开关。关闭的技能仍保留在磁盘上，但智能体不会再获得它。Claude Code 把这个选择按技能名称保存在它自己的设置中；Codex 则保存在它自己的配置中。用同一个开关可以重新开启。

### 编写新技能

1. 点击**新建技能**（[打开](/settings?s=skills&find=New%20skill)）。
2. 在**适用于**下，选择 **Claude Code** 或 **Codex**。
3. 输入**名称**。它会成为文件夹的名称：小写，用短横线连接（“Release notes”会变成 release-notes）。
4. 在**何时使用**下写一行，例如“在根据已合并的拉取请求撰写发布说明时使用”。智能体在每个会话中都会看到这一行，只有在适用时才会读取技能的其余部分。
5. 对于 Claude Code，选择**位置**：**所有文件夹**（你自己的技能）或**此文件夹**（顶部选中的文件夹）。窗口会显示技能将保存在哪里。Codex 技能放在 `~/.agents/skills` 中，Codex 在每个文件夹中都会读取它。
6. 点击**创建和编辑**。

应用会创建技能的文件夹和它的 SKILL.md，其中包含名称、你写的那一行以及步骤的占位内容，并在编辑器中打开它。写好步骤后，点击**保存**，再点**完成**。如果已经有同名的技能，应用会提示你，并且不会创建任何东西。

### 编辑或删除技能

- **编辑**（铅笔图标；对于你不能删除的技能，它的标签是**打开**）会在编辑器中打开技能的 SKILL.md。修改后点击**保存**，再点**完成**。**在“文件”中打开文件夹**会显示技能的文件夹，以及其中的其他文件。如果你在有未保存更改时关闭编辑器，它会在丢弃这些更改前先询问你。
- **删除**（垃圾桶图标）在你确认后，会把技能的文件夹连同其中的所有文件从磁盘上删除。你自己的技能有这个按钮，Claude Code 的文件夹技能也有。内置、管理员和插件技能没有垃圾桶按钮：请改为关闭它们。删除的技能无法在应用中找回。

- “技能库里哪些技能被智能体用过？各用了多少次？”
- “给我看看等我处理的技能提议，以及每份提议会改动什么。”
- “给我看看 research 技能自从我批准以来改了什么。”
- “移除已习得的技能 release-notes”，或者“把我昨天移除的技能找回来。”
- “为 Custom 关闭按关键词引入技能。”
- “我的‘毕业论文’空间有哪些自己的技能？各用了多少次？”
- “列出 Claude Code 在 ~/projects/shop 中的技能，并关闭名为 deploy 的那个。”
