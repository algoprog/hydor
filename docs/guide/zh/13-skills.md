# 技能

技能是写成文字的方法，智能体在任务需要时加载它们：怎样研究一个问题、追查一个程序缺陷、规划一个项目、制作 Word 文档，或在任务结束后清理。智能体能用的所有技能都在一个页面上，即[设置 → 技能](/settings?s=skills)：应用自带的、你的、你的插件带来的、Claude Code 和 Codex 自己的，以及你的项目的。本主题介绍所有这些技能、智能体经你批准后学会的技能，以及为 Custom 引入技能的关键词。

![设置 → 技能：智能体能用的所有技能，按用途分组](images/skills.webp)

## 什么是技能

技能是一份简短的指南，智能体在做某一类工作时照着它来做。每个技能是一个文件夹，里面有一个名为 SKILL.md 的文件：一个名称，一行说明何时使用，然后是步骤、检查项和要避免的错误。有些技能还带有自己的文件：步骤中用到的示例、模板或小脚本。

智能体并不会一直读取所有技能。会话开始时，智能体只看到每个技能的名称和那一行“何时使用”。当某个任务适合某个技能时，它才加载并遵循那个技能。打个招呼、问个简单问题或做一处小而明确的修改，都用不着技能。

## 技能从哪里来

技能页面显示来自五个地方的技能，每一行都标明了来源：

- **内置**：应用自带的技能（六十多个）。它们随应用一起更新。
- **你的**：你在这个页面上编写的技能、智能体建议后你批准的技能，或你自己放进技能文件夹的技能。
- **来自插件**：你开启的[插件](/guide/plugins)的技能。它们随插件一起出现和消失。
- **Claude Code 和 Codex**：这两个智能体自己的技能，放在它们自己的文件夹中。只有对应的那个智能体会获得它们。
- **项目中**：项目自己的技能，只有这个项目的会话会获得。你在项目的**技能**标签页上修改它们：参见[给项目添加它自己的技能](/guide/spaces#give-a-project-skills-of-its-own)。

前三类组成技能库，应用启动的每个智能体都会获得它。助手也可以指定它偏好的技能：当其中某个技能适合当前任务时，智能体会在开始前加载它。参见[助手](/guide/assistants)。

## 哪些智能体获得哪些技能

应用启动的每个会话都会获得技能库：

- **Claude Code** 以一个名为“hydor”的插件获得它，所以其中的技能名称前面会带上这个名字：hydor:research、hydor:writing 等等。
- **Codex** 以一个额外的技能文件夹获得它。
- **Custom**（应用自带的智能体）在它的技能列表中获得它。参见 [Custom](/guide/custom)。
- **其他智能体**（Gemini CLI、OpenCode 等）获得技能列表，每个技能都附有适用时要读取的文件。

在应用之外（终端或 VS Code 中）启动的会话看不到技能库。技能库不会往你的 Claude Code 或 Codex 设置里写入任何东西。

项目里的会话会获得项目自己的技能，和技能库的技能一起。项目里与技能库中某个技能同名的技能，会在这个项目的会话中替代它。

你自己的技能优先于内置技能：你的技能如果与某个内置技能同名，就会替代它。插件中与技能库已有技能同名的技能会被略去，插件的页面会说明智能体改用哪个技能。

Custom 按以下顺序从多个文件夹读取技能：项目自己的技能（在项目的 `.claude/skills` 和 `.agents/skills` 文件夹中），你主文件夹中 Claude Code 和 Codex 自己的技能，最后是技能库。两个技能同名时，先找到的那个生效。所以你为 Claude Code 或 Codex 写的技能，Custom 也能用上。

## 查看智能体何时使用技能

当智能体加载一个技能时，对话中会出现一个小标签：**正在使用技能 research**，智能体读取它时还会显示一个转圈图标。Claude Code、Codex 和 Custom 都是如此。

点击这个小标签即可阅读技能：它的内容、适用场景和历史。如果这个技能不属于应用的技能库，窗口会注明：它来自智能体自己的技能文件夹，或项目的技能文件夹。在项目里，如果智能体使用的是项目自己的技能，小标签会打开项目的那个技能：窗口的标记显示项目的名称，**项目的技能**会打开它的技能标签页。

如果是你自己的话把某个技能引入了 Custom 会话，小标签会注明是哪些词引入的：“因你消息中的‘research’而引入”。参见[按关键词引入技能](#bring-skills-in-by-keywords)。

智能体每加载一次技能，就算使用一次。技能库中的技能所在的行会显示它被使用的次数，以及最近一次使用的时间。

## 打开技能页面

前往**设置 → 智能体 → 技能**（[打开](/settings?s=skills)）。在手机上，先打开设置，再轻点“智能体”下的**技能**。

页面从上到下依次是：

- 有智能体建议的技能时，一个列出这些技能的框（参见[批准、编辑或忽略提议的技能](#approve-edit-or-dismiss-a-proposed-skill)）；
- 一个搜索框、**新建技能**，以及 **⋯** 菜单：**推荐合适的技能**、**按关键词引入技能**、**你的技能文件夹**（在“文件”中打开它）、**用插件获取更多技能**（打开[设置 → 插件](/settings?s=plugins)）和**智能体如何获得技能**；
- 一排筛选：**全部**、**内置**、**你的**、**来自插件**、**Claude Code 和 Codex** 以及**项目中**，每个都显示它包含多少个技能。只显示有技能的筛选；
- 按用途分组的技能：**工作方法**、**写作**、**文档**、**研究和网络**、**规划和决策**、**数据和数字**、**设计和图片**、**编程**、**AI 模型**和**这个应用**；然后是 **Claude Code 自己的技能**、**Codex 自己的技能**，以及每个有自己技能的项目各一组；
- 页面底部是你移除的技能，可以把它们找回来。

项目的技能（项目文件夹中 Claude Code 和 Codex 的技能）取决于文件夹，所以这个页面一次只显示一个文件夹的技能。**文件夹**按钮位于这一部分的标题旁边（在手机上，位于描述这一部分的那行文字下方）。它一开始指向在[文件](/files)中打开的文件夹，否则就是你的默认文件夹。点击它可以选择另一个文件夹。

## 查找技能

在搜索框中输入：它会匹配技能的名称、用途，以及它所属插件或项目的名称。按 Esc 或点叉号可以清除。选择一个筛选，就只看某一类技能。

你也可以在应用的搜索框（Ctrl+K，Mac 上是 ⌘K）中查找技能：输入它的名称或用途。技能显示在**技能**下，选中一个就会在这个页面上打开到那个技能。

## 开启或关闭技能

技能库以及 Claude Code 和 Codex 的每个技能，在所在行的末尾都有一个开关。关闭的技能仍留在原处，但智能体不再获得它；它所在的行会变灰，并显示**关闭**。用同一个开关可以重新开启。你也可以在它的窗口中切换。

- 技能库中的技能（内置的、你的或插件的）关闭后，所有项目里的所有智能体都不会再获得它。
- Claude Code 把这个选择按技能名称保存在它自己的设置中；Codex 则保存在它自己的配置中。

项目的技能在这里没有开关：请在项目的**技能**标签页上修改它们。

## 阅读技能及其历史

点击技能所在的行，或对话中的**正在使用技能**小标签。会打开一个窗口，其中有：

- 它的来源、所属分组，以及智能体使用它的次数；
- 它的开关：**智能体会获得它**，或**已关闭：智能体不会获得它**；
- 何时使用它，以及它的关键词（如果有）：“当你说出以下内容时，Custom 会引入它”，后面是这些词；
- 智能体读到的指令；
- **历史**（有更改时显示）：每一次更改，最新的在前：**已保存**、**已修改**、**已移除**或**已恢复**，距今多久，以及新增和删除了多少行。点击某次更改可以逐行查看；
- 底部是它的文件所在的位置：点击即可在“文件”中显示它。

窗口底部的按钮取决于技能：

- 内置技能：**制作我自己的版本**（参见[修改内置技能](#change-a-built-in-skill)）。
- 你的技能：**修改**和**移除**。
- 插件的技能：**所属插件**（打开该插件）和**制作我自己的版本**。
- Claude Code 或 Codex 的技能：**修改**（对于你不能删除的技能，它是**打开**），它会在编辑器中打开技能的 SKILL.md；以及**删除**。
- 项目的技能：**项目的技能**。

在手机上，这个窗口会以从屏幕底部弹出的面板打开。**关闭**可以关掉它。

## 内置技能

应用自带以下技能，按页面上显示的分组排列。打开任何一个都可以阅读全文。

**工作方法**

- **clarify-first**：用于规模大或开放式的请求（一个网站、一次旅行、一次装修、一场演讲、一份商业计划）。智能体先阅读已有的内容，一次只问一个问题并说明为什么问，复述它的理解，给出两三种做法，并在动手之前写一份简短的说明供你批准。
- **clean-up**：在任务结束时使用。智能体列出它在过程中创建的东西，删除不再需要的（草稿文件、测试数据、临时文件夹、已合并或已放弃的分支、工作树、它启动的进程），从不删除不是它创建的东西，涉及大的或共享的东西时会先问你，最后用一句话说明删了什么、留下了什么。只要[设置 → 助手](/settings?s=assistants&find=Clean%20up%20after%20a%20task)中的**任务完成后清理**是开启的（除非你关闭，否则默认开启），每个智能体都会被要求在任务结束时这样做。
- **decisions-log**：用于你不在场时的工作（一个目标、一个定时任务、“不用等我”）。智能体自己解决一般的问题，把每个决定连同理由以及万一错了的代价记下来，然后继续工作。它只在以下情况前停下：无法撤销的步骤（发送、付款、删除、发布）、任何涉及密码或访问权限的事，或者任何超出工作范围的事；它的最后一条消息会列出它做的每个决定。
- **evidence-before-done**：在智能体说某件事已完成、已修好、已保存、已发送或属实之前使用。它会指出能证明这一点的检查，运行检查，读取结果，然后连同证据一起报告；或者坦白说明哪些它无法核实。
- **troubleshooting**：用于任何没有正常工作的东西（一个错误、一台设备、家庭网络、一个公式、一份食谱）。智能体会有意让问题重现，收集事实，一次只验证一个想法，修复根本原因，并证明它已修好。

**写作**

- **writing**：用于任何要给人读的东西（报告、文章、信件、演讲稿）。智能体先确定谁来读、为什么读，先列提纲再起草，并分几遍分别修改。
- **creative-writing**：故事、小说、回忆录、诗歌和剧本：找到故事、规划、顺畅地起草、走出写作瓶颈、按顺序修改、获取反馈，以及出版（投稿信、故事梗概、文学经纪人、自出版和要避开的陷阱），始终保留作者自己的声音。
- **email**：整理收件箱（哪些需要回复、哪些可以等、哪些要归档），并撰写需要用心的邮件：回复、催办、道歉、婉拒或说不，长度和语气都恰到好处。
- **plain-language**：把现有的文字改写得清楚、有人情味，去掉行话、废话以及生硬或像 AI 写的措辞，调整到合适的阅读难度，同时保留原意。
- **translation**：忠实、自然地翻译文档、消息、网页、应用文字和字幕，为术语和名称建立词汇表，按目标地区的习惯写数字和日期，并检查译文。
- **social-media**：为每个平台（LinkedIn、X、Instagram、Mastodon、Bluesky…）策划和撰写帖子，把一条信息改写成适合多个平台的版本，并维护内容日历。
- **seo**：让网站、网店或博客在搜索引擎和 AI 回答中被找到：检查它的页面、标题和描述、收录、结构化数据和 AI 爬虫，并如实衡量效果，不承诺排名。
- **release-notes**：根据提交和拉取请求，为读者撰写发布说明和变更日志条目，并选择下一个版本号。

**文档**

- **pdf**：制作 PDF（报告、发票、证书、传单、表格），合并、拆分、旋转、填写 PDF 或给它们加盖印章，把 Office 文件转成 PDF，以及阅读 PDF（包括扫描页）。
- **presentations**：制作或修改幻灯片（.pptx），保持整体风格统一，包含图表、表格和演讲者备注，交付前先把它们当作图片看一遍，还能阅读 .pptx、.ppt 和 .odp 文件。
- **spreadsheets**：制作或修改带公式、数字格式和图表的工作簿（.xlsx），检查公式是否有错，还能阅读 .xlsx、.xls、.ods 和 .csv 文件。
- **word-documents**：制作或修改 Word 文档（.docx），使用真正的标题、列表和表格，交付前先查看页面效果，还能阅读 .docx、.doc 和 .odt 文件。

**研究和网络**

- **research**：规划一个问题需要的搜索，先广泛搜索再逐步聚焦（论文、专利、新闻、公开申报文件），用两个独立来源或一个原始来源核对每个关键说法，最后附上引用作答，并说明哪些无法证实。
- **spin-check**：判断一则广告、一条热传帖子、一次推销或一个说法是真的、误导的还是骗局：逐条拆开，每条都对照能下定论的来源核查，点出其中的说服手法，并给出各自的结论。
- **papers**：深入处理学术论文：谁引用了某篇论文、合法获取全文、阅读和总结、比较各项研究的表格、判断研究质量，以及规范地引用。
- **blocked-pages**：当某个网页无法加载或读取时（报错、付费墙、Cookie 墙或机器人检查、需要 JavaScript 的页面），按顺序尝试获取其内容的其他途径，绝不绕过你无权访问的内容。
- **web-scraping**：有礼貌且可靠地从网站收集结构化数据（列表、表格、价格、商品目录），整理成 CSV 或 JSON，并加以检查。
- **maps-and-places**：不用付费地图服务处理地点：地址的坐标、附近有什么、距离、路线和行程时间、时区、营业时间，以及页面中的地图。
- **watch-and-alert**：用定时任务在几天或几周内持续关注某件事（价格、商品重新到货、某家公司的新闻、页面变化、新版本发布），只在重要时通知你。

**规划和决策**

- **decision-brief**：帮你做选择：各个选项（如果什么都不做确实可行，它也是其中之一）、什么重要以及有多重要、取舍和风险，以及明确的建议，都写在一页上。
- **project-plan**：规划任何类型的项目（活动、搬家、产品发布、装修）：里程碑、带负责人和日期的任务、事项之间的依赖关系、风险，以及一份需要保持更新的时间线。
- **meetings**：到底要不要开会、用问题写成的议程、邀请谁、怎样主持、一对一谈话和会后跟进，以及为别人主持的会议做准备。
- **weekly-review**：每周重新整理：哪些事还没完成、答应了别人什么、哪些停滞了，以及下周的优先事项和时间安排。
- **brainstorming**：用有名字的方法（反转、限制条件、类比、最糟的点子…）想出很多点子，然后加以整理，挑出几个来尝试。
- **study-coach**：学习一门学科或一项技能：你已经知道什么、一份计划、适合你水平的讲解、练习题，以及可以反复复习的抽认卡。
- **job-interviews**：为求职面试做准备：这个职位需要什么、一组真实的经历例子、一次只问一个问题并给出坦诚反馈的模拟面试、难题的应对，以及复盘一次面试；也适用于面试官。
- **solo-business**：属于你自己的一门生意（自由职业、一项服务、一款产品、一份副业）：你需要它带来什么，先用付费客户检验方案、再大量投入，定出能覆盖你时间成本的价格，以及何时该调整方向或停下。

**数据和数字**

- **data-analysis**：根据数据（CSV、Excel 表格、导出的数据）回答问题：检查并清理数据，用可以核对的方式算出结果，并说明答案依据的是什么。
- **dashboards**：为问题选择合适的图表，并把仪表板做成资料库中可以反复查看的页面，数据可以保存下来，也可以实时获取。
- **financial-model**：用电子表格整理企业的数字（收入、成本、现金流、盈亏平衡、情景分析），把假设放在单独的工作表上，公式清晰可循。
- **sql-and-databases**：正确、安全的 SQL，对线上数据也安全的结构修改和迁移，索引，以及在做任何有风险的操作之前先备份。

**设计和图片**

- **image-prompts**：用应用的图像模型制作图片（和短视频）：要描述什么、尺寸、图片中的文字、让角色或风格在多张图片中保持一致，以及编辑图片。
- **diagrams**：人们能看懂的流程图、时间线、组织结构图、思维导图和架构图，显示在对话中或保存为页面。
- **infographics**：一页纸的图解说明（信息图、比较各种选择的海报、流程图或时间线图）：先定信息和有出处的事实，再选合适的结构和风格，最后按读者实际看到的尺寸检查导出的成品。
- **ui-mockups**：在构建界面或页面之前，在对话中展示两三个快速、风格明显不同的草图，供比较和挑选。
- **brand-kit**：为小企业、俱乐部或项目打造品牌：面向谁、语气、检查过对比度的颜色、免费字体、标志构想，以及品牌卡和品牌手册，并用到个人资料和名片上。
- **youtube-thumbnails**：缩略图和标题一起做出一个诚实的承诺：三个不同的构思，缩得很小也看得清，放在其他视频旁边预览，并用 YouTube 的 Test & Compare 测试。

**编程**

- **debugging-code**：找出缺陷的根本原因：先写一个失败的测试，看堆栈跟踪，逐步缩小范围（日志、调试器、git bisect），修复，并用一个测试确保它不再出现。
- **test-first**：先写测试再写代码，用于新功能和缺陷修复，在合适的层面测试，并说明哪些该模拟、哪些不该。
- **code-review**：审查一项改动，或智能体在交付前审查自己的工作：先看正确性，再看安全、测试和清晰度，每个发现都写明位置、原因和修复办法。
- **refactoring**：在不改变代码行为的前提下调整它的结构，小步进行，并保持测试通过。
- **codebase-tour**：在陌生的代码库中找到方向：如何构建、运行和测试它，它由哪些部分组成、东西放在哪里，并附一份简短的概览和一张图。
- **git-rescue**：安全地摆脱 Git 麻烦：撤销提交、找回丢失的工作、解决冲突、处理误提交的机密，而且总是先备份。
- **github**：用 gh 命令或 GitHub 的 API 处理 GitHub 上的拉取请求、审查、检查及其日志、议题和发布版本。
- **api-requests**：调用和调试网络 API：用你保存的密钥登录、错误响应、分页的结果、速率限制和重试。
- **frontend-polish**：让网页看起来、用起来都更完善：布局、间距、字体、颜色和对比度、每一种状态、手机、键盘操作，并在真实截图上检查。
- **web-accessibility**：人人都能用的网站和网页应用（键盘、读屏软件、缩放、对比度、字幕、表单和对话框），用工具和手动两种方式检查，并如实报告。
- **web-app-qa**：像挑剔的用户一样在浏览器中测试网页应用，并写下发现的缺陷，附上步骤和证据。
- **docker**：Dockerfile 和 compose 文件，构建和调试容器，以及小心地清理。
- **servers**：通过 SSH 维护一台服务器或另一台电脑（更新、出故障的服务、磁盘已满、用户和密钥、防火墙、备份），改动访问设置之前总先留好退路，先在一台机器上做，每次改动后都检查。
- **security-check**：实用的安全审查：机密、注入、谁能做什么、过时的软件包，每个问题都按严重程度报告。
- **performance**：先测量，找出最大的开销，修复后再测量，从而让软件更快。
- **mcp-servers**：构建 MCP 服务器，让智能体获得新工具：设计好它的工具、测试它，并把它添加到智能体中。

**AI 模型**

- **hugging-face**：在 Hugging Face Hub 上发布和使用模型和数据集：上传、模型卡和数据集卡、受限仓库，以及检查上传结果。
- **fine-tuning**：是否值得微调语言模型，以及怎样微调：训练数据、LoRA 和 QLoRA、参数设置、所需的显存，以及诚实的评估。
- **model-evaluation**：公平地评估模型：合适的测试集和指标、基准测试、谨慎地让模型充当评判，以及结果有多可靠。
- **local-models**：在你自己的电脑上运行开放模型：哪个模型和规模合适、需要多少内存、量化，以及 Ollama、llama.cpp 或 vLLM。

**这个应用**

- **everyday-help**：用于“你能为我做什么？”：围绕你的日常简短聊几句，一次只问一个问题，然后给出一两个与应用实际功能相匹配的建议，你同意后再设置好一件小事。
- **app-builder**：用于制作或修改你的应用。智能体先弄清楚输入什么、输出什么，为每个部分选最省的步骤，给应用配上带检查的示例，并在交给你之前试运行，说明一次运行要花多少钱。
- **skill-authoring**：写好一个技能：什么时候值得写、说明何时使用的那一行、它的结构和检查，以及用过之后怎样改进。
- **plugin-authoring**：制作、打包和分享插件（参见[插件](/guide/plugins)）：里面放什么、它的格式、检查它以及添加它。

文档类技能（pdf、presentations、spreadsheets、word-documents）用小型 Python 脚本生成文件。它们需要这台电脑上有 Python 3。第一次需要时，它们用到的库会被下载到应用数据文件夹中的一个私有文件夹里（约 30 MB，只下载一次）；不会为整个系统安装任何东西。如果缺少 Python，智能体会告诉你安装它的命令。为了在交付文件前把页面当作图片查看，如果这台电脑上有 LibreOffice 和 Poppler，它们就会用上这两者。参见[文档、图片、视频和语音](/guide/documents-voice)。

内置技能不能移除，但你可以关闭其中任何一个，或修改它：你的版本会替代它。

## 编写你自己的技能

1. 点击**新建技能**（[打开](/settings?s=skills&find=New%20skill)）。
2. 输入**名称**：简短，用短横线连接（只保留英文字母、数字和短横线）。“Invoice checks”会保存为 invoice-checks。
3. 在**何时使用**下写一行，例如“在付款前核对供应商的发票时使用”。智能体在每个会话中都会看到这一行，只有用得上时才会读取其余部分。
4. 在**指令**下写出方法：按顺序的步骤、检查项、要避免的错误。可以使用 Markdown。
5. 你还可以选择它的**组合**，以及**引入它的关键词**：请求中出现这些词时，会自动把这个技能带进 Custom 的这一轮，词与词之间用逗号分隔（参见[按关键词引入技能](#bring-skills-in-by-keywords)）。
6. 在**谁会获得它**下，保留**所有智能体**，或选择 **Claude Code** 或 **Codex**，让只有那个智能体获得这个技能。对于 Claude Code，再选择**所有文件夹**或**此文件夹**（顶部选中的文件夹）。
7. 点击**添加技能**。

为所有智能体编写的技能保存在你的技能文件夹中（在应用的数据文件夹中，除非你的安装把数据放在别处，否则是 `~/.hydor/skills`），并显示在**你的**下。Claude Code 技能放在 `~/.claude/skills`（或该文件夹的 `.claude/skills`）中，Codex 技能放在 `~/.agents/skills` 中，Codex 在每个文件夹中都会读取它。如果那里已有同名的技能，应用会提示你，并且什么都不保存。

要修改你的某个技能，打开它并点击**修改**：还是同样的字段，用**保存**保存。每次修改都会记录在它的历史中。你也可以自己把技能放进你的技能文件夹：每个技能一个文件夹，用小写字母、数字和短横线命名，里面放它的 SKILL.md。它们会显示在**你的**下。

## 修改内置技能

打开技能，点击**制作我自己的版本**。会打开同样的字段，里面是它的文本；随意修改，然后点击**保存**。你的版本一开始是该内置技能整个文件夹的副本（包括其中的示例和脚本），并已做出你的修改。

从那以后，智能体会使用你的版本而不是内置版本，即使应用之后更新了内置技能也是如此。它显示在**你的**下，标为“你自己版本的内置技能”。要改回内置技能，移除你的版本即可（参见[移除技能并把它找回来](#remove-a-skill-and-bring-it-back)）。

当你批准智能体对某个内置技能的改进时，它也会以同样的方式保存为你的版本：卡片会在你批准之前说明这一点。

## 移除技能并把它找回来

1. 打开你的某个技能，点击**移除**。
2. 再点**移除**确认。

智能体将不再获得它。如果它是你自己版本的内置技能，智能体会改回使用内置版本。它的文本会保留在技能的历史中，所以你可以把它找回来：你移除的技能列在页面底部的“**已移除：**”之后。点击那里的名称（鼠标悬停可以看到它是何时移除的），技能就会恢复成原来的样子。

Claude Code 和 Codex 自己的技能：在它们的窗口中点**删除**，确认后会把技能的文件夹连同其中的所有文件从磁盘上删除。你自己的技能有这个按钮，Claude Code 的文件夹技能也有。这些智能体的内置、管理员和插件技能不能删除：请改为关闭它们。删除的技能无法在应用中找回。

## 批准、编辑或忽略提议的技能

完成一项真正费力的任务后，智能体可能会提议把它的做法保存为技能：试了好几次才找到的修复方法、你不得不解释的工作流程、步骤容易出错的过程。当它发现所遵循的某个技能缺了一步、有错误或不够清楚时，也可能提议改进那个技能。智能体被告知不要提议一次性的事实、你的个人信息或任何机密内容。

在你批准之前，什么都不会保存。在此期间智能体会继续它的工作，你的答复会作为一条消息送达它。

### 卡片上显示什么

提议会以卡片的形式出现在对话中，位于折叠的步骤之外，智能体则继续工作。卡片顶部会问：**把这个保存为技能？**、**改进这个技能？**，或**改进这个内置技能？**，并附上技能名称和一个标记：**等你处理**、**已保存**、**已忽略**或**已替换**。

下面是：

- **原因**：用智能体自己的话说明，这次任务中发生了什么让它值得保留。
- **适用场景**：智能体据以判断何时使用它的那一行。如果改进提议修改了这一行，旧的那行会显示为删除线。
- 它供 Custom 使用的关键词（如果有）：“当你说出以下内容时，Custom 会引入它”，后面是这些词。
- 警告（如果有，参见[卡片上的警告](#warnings-on-the-card)）。
- 正文，可以在**文本**（新技能）或**更改**（改进，逐行显示）与**技能**（指南读起来的样子）之间切换，并显示它新增和删除了多少行。
- 在项目里，**保存给**：**所有会话**或项目的名称（参见[智能体在项目里提议的技能](/guide/spaces#skills-agents-propose-in-a-project)）。

### 批准

点击**批准**。技能会保存到你的技能库中，卡片会显示它已在你的技能库中：每个智能体都能使用。**你的技能**链接会带你前往[设置 → 技能](/settings?s=skills)。

如果在**保存给**下选了项目的名称，它会改为保存到项目的技能中：卡片会说明它已在其中，**项目的技能**会带你前往那里。

Custom 从下一轮起就能使用这个技能；Claude Code 和 Codex 则从下一个会话起。

### 先编辑

1. 点击**编辑…**。会打开一个窗口，以文本形式显示整个技能。
2. 随意修改。顶部那几行（两个 `---` 行之间）是它的名称（必须保留）和说明何时使用的那一行。它们下面的全部内容就是智能体遵循的指南。
3. 点击**保存并批准**。

卡片随后会注明你在保存前编辑过它，并显示保存后的版本。应用检查你编辑的文本，和检查智能体写的文本一样：需要有一行说明何时使用、有实际的步骤，并且不能含有机密。

### 忽略

1. 点击**忽略…**。
2. 你也可以在打开的输入框中告诉智能体原因（可选）。
3. 点击**关闭**（或点**取消**返回）。

什么都不会保存。智能体会得知你忽略了它，连同你的说明，并被告知除非你要求，否则不要再提议它。

### 卡片上的警告

技能是每个智能体都会读取的文件，所以应用会在你看到每份提议之前先检查它：

- **含有机密的提议会被拦下**。如果提议中有看起来像密码、密钥或令牌的东西（API 密钥、私钥、直接写出的密码或藏在网址里的密码），它根本不会以卡片的形式到达你这里。智能体会被要求把它删掉，改为说明机密存放在哪里。
- **试图操纵智能体的文字会被指出**。当提议新增的某一行有以下情况时，卡片会显示**批准前请先看看这几行**，并列出行号和文字：要求智能体忽略它们的指令、试图替换智能体的身份、要求智能体对你隐瞒某些事、试图绕过批准、把密钥或私人文件发送到别处、直接运行来自互联网的脚本、修改智能体设置或启动文件、在项目之外很远的地方删除或覆盖内容、把指令藏在 HTML 注释里，或者含有你看不见的字符。

批准带有警告的提议时，会再问一次：“**有这些警告，仍要保存吗？**”只有当被标出的那几行确实是你希望智能体遵循的内容时，才点**保存**。

### 在设置或收件箱中答复

一份提议会在三个地方等你，在其中任何一处答复，都会在所有地方、所有设备上显示出来：

- 它所在对话中的卡片；
- [设置 → 技能](/settings?s=skills)顶部的框：“智能体建议了一个技能”（或建议了几个）。每一行显示**新技能**或**修改**加上名称、距今多久、来自哪个对话（点击可打开），有警告时还会显示“有警告”。**审查**会在一个窗口中打开同样的卡片；
- [收件箱](/inbox)，显示为“建议新增技能：…”或“建议修改 … 技能”。**打开**会带你到它所在的对话，卡片就在那里。参见[收件箱和通知](/guide/inbox)。

### 限制

- 一份提议最多 20,000 个字符。更长的指南会被拒绝，智能体会被要求只保留主要步骤。
- 新技能需要一个未被使用的名称。名称由简短的小写单词和短横线组成，例如 release-notes。
- 同一个对话中，最多同时有五份提议等你处理。
- 如果智能体在你答复之前再次提议同一个技能，新的提议会取代旧的，旧的会显示**已替换**。
- 如果在提议提出之后，又保存了一个同名技能，或者该技能被修改过，批准会失败并显示一条消息。请忽略它，再问一次智能体。
- 智能体只能改进应用技能库中的技能和项目自己的技能。Claude Code 和 Codex 自己的技能不会以这种方式修改：请在[设置 → 技能](/settings?s=skills)中修改它们。
- 已答复的提议会在旧对话的卡片上保留半年。

## 适合新会话的技能

会话以一条消息开始时，如果有技能明显适合这条消息，它的智能体还会得知是哪些：最多三个，每个都附上它的用途，以及这个智能体怎样加载它（Claude Code 用它的 Skill 工具，Codex 和其他智能体读取它的 SKILL.md，Custom 用它的 skill 工具）。智能体会在开始之前加载合适的那个，没有合适的就照常进行。它只在开始时的指令中得知一次，而不是每条消息都提一遍。

这些技能的查找方式和记忆查找笔记一样（见[智能体开始时带着什么](/guide/memory#what-an-agent-starts-with)）：按字词，技能的名称分量最重，其次是它的关键词和用途；在[设置 → 记忆](/settings?s=memory&find=Search%20by%20meaning)中开启按含义搜索后，还会按含义查找，所以换个说法或换一种语言提出的请求，也能找到对应的技能。只有明确的匹配才算：按字词，至少要有你的两个词，并且远远领先其他技能；按含义，只取最接近的那一个技能，而且要足够接近。请求中的常用词，比如“帮忙”“需要”或“之后”，不计入匹配。闲聊、简短的回复以及没有技能适合的请求，都不会得到推荐。

它位于[设置 → 技能](/settings?s=skills&find=Suggest%20skills%20that%20fit)的 **⋯** 菜单中：**推荐合适的技能**，开启时它的前面会打勾。除非你关掉，它一直开启。继续进行的会话和应用的运行不会得到推荐。

## 按关键词引入技能

有些模型很少自己去加载技能。对于这些模型，当你的消息用到某个技能的关键词时，Custom 可以把这个技能引入：技能的文本会随你的消息一起送达，智能体在合适的地方遵循它。

它位于[设置 → 技能](/settings?s=skills&find=Bring%20skills%20in%20by%20keywords)的 **⋯** 菜单中：**按关键词引入技能**，开启时它的前面会打勾。除非你关闭，否则它是开启的。它只影响 Custom；Claude Code 和 Codex 会自己加载技能。关闭后，Custom 仍能看到它的技能列表，并在任务适合时加载某个技能。

当关键词引入了某个技能时，对话中你的消息下方会出现一个小标签：**正在使用技能 research**，“因你消息中的‘research’而引入”。点击它即可阅读这个技能。

### 关键词如何匹配

- 关键词按整词匹配，不区分大小写：“research”不会匹配“researchers”。
- 以 * 结尾的关键词也会匹配更长的词：“renovat*”能匹配 renovate 和 renovation；“debug*”能匹配 debugging。
- 少于四个词的消息不会引入任何技能，所以“好的，继续”永远不会加载技能。
- 一次最多引入两个技能：在你的消息中出现关键词最多的技能优先。
- 引入的技能会在那条消息和接下来的两条消息中保持有效，这样像“先问清楚”或“做研究”这样的过程就能跨越几轮进行。较新消息引入的技能会取代较旧的。
- 较长的技能会被截短，以适应模型能接收的长度；智能体会被告知自己去加载其余部分。

带有关键词的内置技能有：app-builder（“make a template”、“make an app”、“automate”…）、clarify-first（“plan a trip”、“business plan”、“renovat*”…）、clean-up（“clean up after”、“leftover files”…）、decisions-log（“while I'm away”、“overnight”…）、evidence-before-done（“double-check”、“verify”…）、research（“research”、“find sources”、“literature review”…）、troubleshooting（“not working”、“keeps crashing”、“debug*”…）和 writing（“draft a”、“proofread”、“cover letter”…）。其他大多数技能也有几个关键词，文档类技能则没有：Custom 会在任务适合时加载它们。打开技能就能看到它的关键词。

### 给技能设置关键词

技能的关键词是写在其 SKILL.md 顶部几行中的一个列表，例如 `triggers: [weekly report, status update, standup]`。智能体在提议新技能时最多可以附带 12 个关键词，每个 3 到 40 个字符。Custom 也会匹配你自己文件夹和项目文件夹中技能的关键词，因为它也会读取这些技能。

## Claude Code 和 Codex 自己的技能

Claude Code 和 Codex 还会从它们自己的文件夹中读取技能：你的技能，它们在任何文件夹中都会读取；以及项目的技能，它们只在该项目中读取。这些技能显示在技能页面上的 **Claude Code 自己的技能**和 **Codex 自己的技能**下（筛选 **Claude Code 和 Codex** 只显示它们）。每一行都注明技能的来源：

- **此文件夹**：该文件夹自己的技能。
- **此仓库**：随仓库一起提供的 Codex 技能。
- **所有文件夹**：你自己的技能，适用于每个文件夹。
- **插件**：随该智能体自己的某个插件提供的技能（参见[Claude Code 和 Codex 自己的插件](/guide/plugins#claude-codes-and-codexs-own-plugins)）。
- **它自带的**：Codex 自带的技能。
- **管理员设置的**：管理员为 Codex 设置的技能。

对于 Claude Code，页面会列出你的技能（在 `~/.claude/skills` 中）和该文件夹的技能（在它的 `.claude/skills` 中；如果该文件夹就是你的主文件夹，则没有）。对于 Codex，页面会列出 Codex 自己为该文件夹报告的技能。如果有些技能无法读取（Codex 没有响应，或有它读不了的技能文件），列表下方会有一行说明。

用**新建技能**编写一个，在**谁会获得它**下选择 **Claude Code** 或 **Codex**（参见[编写你自己的技能](#write-a-skill-of-your-own)）。打开一个技能即可阅读它；**修改**会在编辑器中打开它的 SKILL.md：修改后点击**保存**，再点**完成**。**在“文件”中打开文件夹**会显示技能的文件夹，以及其中的其他文件。
