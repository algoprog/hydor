# Custom，应用自己的智能体

Custom 是 Naget Agent 自己的智能体：它可以运行你添加的任何模型，无论来自 OpenRouter、Ollama、vLLM 还是其他兼容 OpenAI 的服务器，并且拥有和 Claude Code、Codex 相同的工具、技能和连接。本主题介绍它能做什么、它的权限模式以及它如何检查命令、自动模式、命令沙盒、目标、它如何应对长时间的工作和能力较弱的模型，以及它的设置。

## Custom 是什么，什么时候用它

Claude Code 只能运行 Anthropic 的模型，Codex 只能运行 OpenAI 的。Custom 可以运行你在[设置 → 智能体 → 模型](/settings?s=models)中设置的任何模型：你自己电脑上的开放模型、通过 OpenRouter 使用的便宜或免费模型，或者你自己的服务器。关于如何添加模型，请看[智能体、账户和模型](/guide/agents-models)。

在以下情况下使用 Custom：

- 你想要一个完全不离开你电脑的模型（Ollama 或 vLLM）；
- 你想用某个特定的模型，比如 DeepSeek、Qwen、GLM 或 Kimi；
- 你想控制成本，或者在 Claude 或 ChatGPT 套餐用完后继续工作。

它什么都能帮忙：研究、写作、文档和日常事务。在代码项目中（带有 `package.json`、`Cargo.toml`、git 仓库之类的文件夹），它像一个细心的工程师那样工作：先读再改，遵循项目自己的说明，并在说完成之前运行项目的测试和检查。

和其他智能体一样，Custom 会读取项目的 `AGENTS.md` 或 `CLAUDE.md` 文件，并遵循你的[智能体准则](/guide/guidelines)。

## 开始一个 Custom 会话

1. 在开始页上点击**智能体**，选择 **Custom**（“任意模型：OpenRouter、Ollama、vLLM”）。
2. 点击**模型**，选择你的一个模型。如果列表是空的，请先添加一个模型：**智能体** → **Custom 的模型**。
3. 在**选项**下选择**权限**（见[选择 Custom 不问你就可以做什么](#choose-what-custom-may-do-without-asking)）。Custom 没有思考强度设置。
4. 输入任务，然后按 Enter。

由 vLLM 提供的本机模型，会在会话第一次用到它时启动；会话里会显示“正在用 vLLM 启动 …（第一次需要一两分钟）…”。

Custom 一次只接收一条消息。它工作时你发的消息会在消息框上方的队列里等着，等这一轮结束再发出。

你可以在会话中途，从消息框下方的菜单切换模型。Custom 会从下一步开始使用新模型，即使正处在一轮的中间。

## Custom 能做什么

- **文件**：读取文件（带行号的文本、长文件一次读一部分、文件夹的内容），创建、重写和编辑文件，列出文件夹，以及按名称或内容查找文件。在重写本会话中还没读过的整个文件之前，它会被要求先读一遍。
- **文档**：PDF、Word、Excel、PowerPoint、OpenDocument、RTF 和 EPUB 文件会被当作文本读取。
- **图片**：你附加的图片、它打开的图片文件，以及来自网页或工具的图片。能看图片的模型会直接拿到图片；看不了的，则由辅助模型来描述（见[为看不了图片的模型处理图片](#images-for-models-that-dont-see)）。
- **命令**：在会话文件夹中运行 shell 命令，默认最长两分钟，最多十分钟。服务器、监视程序和其他持续运行的命令会放到后台：Custom 在需要时读取它们的输出，也可以停止它们。Custom 退出时它们也会停止，而它的下一轮会被告知哪些还在运行。
- **网页**：把网页抓取为干净的文本，保留标题、链接、列表和表格；网上的 PDF 和 Office 文件会被当作文本读取。它只能访问公开地址；要访问这台电脑或其所在网络，它会使用 `curl` 之类的命令。
- **计划**：对于有好几个步骤的工作，它会维护一份清单，显示在会话中，并逐项打勾。
- **技能**：它会加载适合任务的技能：项目的、你的（Claude Code 和 Codex 的技能文件夹），以及应用的[技能库](/guide/skills)。
- **MCP 服务器**：你为 Claude Code 设置的工具服务器（适用于所有文件夹的和适用于这个文件夹的）、项目的 `.mcp.json`，以及 Codex 的。
- **应用自带的工具**：网页搜索、浏览器、记忆、页面、你的[连接](/guide/connections)等等，和这里的每个智能体一样。

每一步都会以简明的名称显示在会话中（“读取 index.ts”“编辑 README.md”“获取 https://…”），点一下就能看到它的差异或输出。

## 选择 Custom 不问你就可以做什么

**权限**设置（在开始页的**选项**下，或会话消息框下方的菜单里）决定 Custom 可以自行做什么。在消息框中按 Shift+Tab 会切换到下一个模式。

- **询问**（默认）：编辑文件和运行命令之前都会先问你。只是查看情况的命令（`ls`、`cat`、`git status` 之类）可以随意运行。
- **接受编辑**：可以随意编辑会话文件夹中的文件；运行命令（只查看情况的除外）以及涉及文件夹之外的任何操作之前，会先问你。
- **自动**：常规步骤直接进行；快速检查发现有风险的步骤，会来问你。见[自动模式](#auto-mode)。
- **完全访问**：只在有风险的命令（以管理员身份运行、删除文件夹之外的东西、运行下载的文件……）之前问你。沙盒开启时，命令会在[沙盒](#the-sandbox-for-commands)中运行。
- **计划**：只读和规划。Custom 不能编辑文件或运行命令，只使用读取类的工具。它最后会给出一份编号的计划。要执行这份计划，请切换到另一个模式，并告诉它开始做。

在每个模式下，都有一些命令总是会问你：见[总是会询问的命令](#commands-that-always-ask)。

## 批准或拒绝 Custom 想做的事

当 Custom 需要你同意时，会话中（以及[收件箱](/guide/inbox)里）会出现一张卡片。它的标题会说明这一步要做什么、为什么要问你，例如“编辑 /home/you/notes/plan.md——它会更改会话文件夹之外的文件”。如果是命令，卡片会显示完整的命令。

- **允许**让这一步运行。
- **始终允许…** 会让它运行，并且从现在起，这个会话中类似的步骤都不再问你。按钮上会写明它涵盖的范围：“始终允许 npm run build …”“允许所有编辑”“始终允许读取 ~/data 中的内容”“始终允许更改 ~/site 中的内容”。
- **拒绝**会阻止这一步。Custom 会被告知你拒绝了，并且不要再试。

**始终允许**对命令的作用方式：Custom 会把一条命令拆成几个部分（在 `&&`、`;`、`|` 等处拆开），逐一检查。一条规则只涵盖它所针对的命令，按开头的几个词来匹配（`git status`、`npm run build`、`docker compose up`），所以没有什么能跟在 `&&` 后面蒙混过关。只是查看情况的命令从来不需要规则。

在无法保证安全时，不会提供**始终允许**：

- 直接写在命令里的代码（比如 `python -c "…"`）；
- 事先无法知道名字的文件；
- 无法有把握读懂的命令；
- 有风险的命令，它们每次都会问你。

## 总是会询问的命令

有些步骤每次都会问你，在每个模式下都是如此，包括完全访问和自动，无论你之前允许过什么：

- 以管理员身份运行（`sudo` 之类）；
- 删除会话文件夹之外的文件、删除会话文件夹本身，或者删除事先无法说出名字的文件；
- 把下载的内容直接通过管道交给 shell 执行，或者下载后直接运行；
- 向磁盘写入原始数据、格式化磁盘或重新分区；
- 关闭或重启电脑；
- 更改计划作业（`crontab`）；
- 更改整个文件夹树的权限或所有者；
- 更改 SSH 密钥，或者你主文件夹中的设置文件和启动文件（比如 `.bashrc` 或 `~/.config`），除非会话就在那个文件夹中工作。

## 文件夹之外的文件和存有密钥的文件

在询问、接受编辑和计划模式下，Custom 在读取或更改会话文件夹之外的文件之前会先问你（临时文件夹不算）。这时**始终允许**会涵盖那个文件夹，用于读取或用于更改。

存有密钥或密码的文件，即使在文件夹之内，读取或更改之前也会先问你：`.env` 文件（示例文件除外）、SSH 及其他私钥、`.netrc`、`.npmrc`、凭据文件、你的云服务和密码库文件夹、各智能体自己的登录信息，以及应用自己的数据。更改 git 自身的设置和钩子也会问你。这时**始终允许**只涵盖那一个文件。

在自动模式下，改由自动模式的规则和它的快速检查来决定这些。在完全访问模式下，它们不会问你。

## 自动模式

自动模式让常规工作直接进行、不打扰你，其余的才来问你。在**权限**下选择**自动**。

每个本来需要询问的步骤，都会依次经过以下检查：

1. 不需要模型的**固定规则**：
   - 直接进行：在会话文件夹内的编辑；在临时文件夹中新建的草稿文件；只在文件夹内读取的命令；项目自己的测试、构建、代码检查和类型检查。
   - 问你：覆盖文件夹之外的文件；[总是询问清单](#commands-that-always-ask)上的任何操作；用 git 强制推送；在文件夹之外写入、移动或删除文件；调用支付服务的命令；已连接的应用或 MCP 服务器中会发送或发布内容、或者会花钱的工具。
2. 其余的一切都交给**快速检查**，由[辅助模型](/guide/agents-models#choose-the-helper-model)来做。它给出三种回答之一：
   - **允许**：它明显是在完成你要求的事，不出你的文件夹（或者只是读取），而且很容易撤销；
   - **询问**：它可能造成持久的损害，或者影响范围更大（删除数据、为整个系统安装软件、更改设置、使用密码或密钥、发送或发布任何东西、花钱，或者做你没要求的事）；
   - **禁止**：它显然有害，或者违背你的意愿。这一步不会运行；Custom 会被告知原因，并且必须另找办法。

快速检查只看得到你自己在会话中发的消息（第一条和最近十条）、你设定的目标（如果有）、文件夹和这一步本身（如果是编辑，则是新文本的开头）。它从来看不到 Custom 读过的内容，所以网页或文件都没法说动它做任何事。如果检查失败或超过 45 秒，就由你来决定。在同一轮中，同样的步骤会得到同样的回答。

在会话中，自动模式放行的步骤会带一个小小的**自动**标签；把鼠标悬停在上面可以看到原因。被自动模式拦下的步骤，标签会显示为红色；悬停在上面会看到“自动模式拦下了这一步：…”和原因。自动模式发给你的卡片会以“自动：”和原因开头。

[设置 → 功能 → Custom](/settings?s=custom&find=Auto%20mode) 中用同样的话介绍了自动模式；那里没有什么需要开关的。

## 命令沙盒

在自动和完全访问模式下，Custom 的命令可以在沙盒中运行：它们只能更改会话文件夹和临时文件夹（`/tmp`）中的文件，电脑上的其他一切都是只读的。它们仍然可以使用网络。当会话在 git 工作树或仓库的子文件夹中工作时，仓库自己的文件夹也保持可写，这样 git 就能提交。包管理器的缓存会移到临时文件夹。

当命令碰到沙盒的边界时，Custom 会被告知它是在沙盒中运行的，然后要么在沙盒范围内完成工作，要么告诉你需要在别处做些什么。

要打开或关闭它，请打开[设置 → 功能 → Custom](/settings?s=custom&find=Sandbox%20for%20commands)，使用**命令沙盒**旁边的开关。它默认是打开的。如果某个工具必须写到别处，比如要为整个系统安装某样东西，就把它关掉。更改会在大约 15 秒内对正在运行的会话生效。

沙盒使用的是 Linux 工具 bubblewrap。如果它没有安装，或者无法运行（某些容器中就是这样），开关会变成灰色，这个部分也会注明；这时命令会在没有沙盒的情况下运行。在询问和接受编辑模式下，命令不使用沙盒：在这两种模式下，凡是不只是查看情况的命令，都要等你同意，或者等你用**始终允许**保存的规则。

## 给 Custom 设定目标

目标会让 Custom 一轮接一轮地持续工作，直到某个条件成立：“npm test 通过，并且上传页面能处理 2 GB 的文件”。

1. 打开会话的菜单（⋯）→ **设定目标**。
2. 描述“完成”是什么样子，写成一个工作完成时就会成立的条件。
3. 点击**开始处理**（或按 Ctrl+Enter，Mac 上是 ⌘Enter）。

Custom 会立刻开始处理；如果有一轮正在运行，目标会在那一轮结束时检查。

每轮结束后，辅助模型会对照证据检查目标：各个步骤做了什么、显示了什么（命令输出、测试结果、文件、读过的网页）。光是 Custom 自己说完成了并不算数。然后：

- **完成**：目标被清除，你会收到一条通知：“目标已达成”。
- **尚未完成**：检查会写出下一步，并把它作为下一条消息发出（“目标检查 3：还没达到…”）。
- **需要你处理**：目标会显示“卡住了：智能体需要你”以及要问的问题，你会收到一条通知。在会话中回答即可。
- **等待中**（在等外部的事情，比如一次部署、一次下载）：三分钟后再看一次。

你自己的消息优先：检查会等到队列清空后再进行。

在以下情况下，目标会暂停，并告诉你原因：

- 它发出的下一步已经达到设置中**目标**允许的数量（除非你更改，否则为 30）；
- 连续三轮都没有进展；
- 你停止了智能体、某一轮失败了、智能体没在运行，或者检查本身失败了。

消息框上方的目标横条会显示目标、目前的状态（“正在处理”“已暂停”“卡住了：智能体需要你”）、检查了多少次、持续了多长时间，以及最近一次检查给出的理由。**暂停**会停止发出新的下一步（已经在运行的一轮会跑完），**继续**会从最后一个下一步接着做（轮数重新计算），**清除**则不再朝这个目标努力。目标运行期间，你只会在它达成时收到一条通知，而不是每轮结束都收到一条。

要更改一个目标最多可以运行多少轮，请打开[设置 → 功能 → Custom](/settings?s=custom&find=Goals)，在**目标**旁边选择 **10**、**30** 或 **100**。

## 很长的对话和很长的输出

每个模型一次能读的内容都有限（它的上下文）。Custom 会自己让每个对话保持在这个范围内，所以 Custom 会话没有“压缩”按钮：

1. 当对话接近上限时（会给回复留出空间），Custom 会先清除旧的工具输出。会话里会注明：“已清除旧的工具输出，以保持在模型的上下文范围内。”
2. 如果这还不够，模型会把之前的部分总结成笔记，工作就从这些笔记接着进行（“正在总结之前的对话，以保持在模型的上下文范围内…”）。下一次，它会更新这些笔记，而不是从头再来。无论哪种方式，你的计划和正在使用的技能都会保留。

如果模型的服务器说对话太长，Custom 会记下那个模型真实的上限，并立刻进行压缩。每次请求只会带上最近的几张图片。

很长的输出也不会塞满对话。当一个命令、一个网页或一个工具返回的内容超过模型上下文的一定份额时，Custom 会把全部内容存到会话自己文件夹里的一个文件中。模型会拿到开头和结尾（如果是命令，主要是结尾，因为错误会出现在那里）以及文件的位置，然后分段读取其余部分，或者在里面搜索。这些文件一周后会被删除。

## Custom 如何应对能力较弱的模型

不是每个模型使用工具都像 Claude 或 GPT 那样熟练。Custom 会发现常见的失误，把模型拉回正轨：

- **重复**：同样的步骤，如果其间什么都没变，不会运行第三次（模型会被告知使用之前的结果）；到第五次就会停止这一轮。
- **失败的步骤**：连续失败四步后，模型会被告知停下来重新思考；连续失败八步，这一轮就会停止。
- **兜圈子**：陷入循环的步骤会收到一条提示，让它换个办法试试。
- **没做完的工作**：模型说了“让我来…”却没有去做，或者计划里还有未完成的项目就停下了，这两种情况各会被打回去继续干一次。如果改了代码却没运行项目的检查，它会被要求在结束前运行这些检查。
- **长度**：一轮最多 200 步；到第 150 步时，模型会被告知先完成最重要的部分。因模型长度限制而被截断的回复，会分成更短的几步继续。
- **出错的工具调用**：以文本形式写出的调用会被读出并运行，参数差一点就对的调用会被修好，拼错的工具名会被对应到正确的工具，或者得到一份工具列表作为回答。
- **不支持工具调用的模型**：当模型的服务器不接受工具时，Custom 会在指令中描述这些工具，并从模型写出的文字中读出它的调用。
- **小故障**：当连接在回复中途断开，或者服务器正忙时，Custom 会等一等，再重试几次。
- **工具很多**：当工具很多时（来自 MCP 服务器和连接），模型会看到一份简短的列表，再去查它需要的那些工具的完整说明。上下文较短的模型（大约 32,000 个 token 或更少，且不是通过 OpenRouter 使用的）会拿到较少的工具，并被要求小步前进。
- **每个模型家族**都会用上它的厂商推荐的设置、它训练时使用的编辑格式，以及（如果有的话）一个推理强度。只读的步骤会同时运行，以减少等待。

当 Custom 因为以上某个原因停止一轮时，回复会以“（已停止：…）”结尾。

## 为看不了图片的模型处理图片

能看图片的模型会直接拿到你的图片。如果这台电脑上有 ffmpeg 或 ImageMagick，图片会先被缩小。

对于看不了图片的模型，辅助模型会用文字描述每张图片：图上有什么、东西在什么位置，以及图中的所有文字（一字不差地照抄）。这需要一个能看图片的辅助模型：打开[设置 → 智能体 → 模型](/settings?s=models&find=Helper%20model)，在**辅助模型**下选一个标有“能看图片”的模型。“自动”做不到。没有这样的辅助模型时，Custom 会告诉模型这里有一张它看不到的图片。

## 分叉和“从这里编辑”

Custom 会话可以像 Claude Code 和 Codex 会话一样分叉：会话的菜单（⋯）→ **分叉**。你也可以用**从这里编辑**修改你之前发的某条消息：对话会在一个副本中从那条消息之前继续，而当前这个会话会被归档。勾选**把文件恢复到这条消息之前的样子**，可以撤销从那以后对文件的更改。对 Custom 来说，这涵盖它自己的编辑改动过的文件；命令改动的内容则保持原样。

Custom 会把每个对话保存在磁盘上，所以应用重启后它还能接着进行。

## Custom 的花费

- 通过 OpenRouter 使用的模型：OpenRouter 会报告每次调用花了多少钱，会话的花费就以此为准。
- 这台电脑上的模型（Ollama、vLLM）：不花钱。
- 其他端点：token 的计价方式和其他智能体的一样（见[用量、限额和费用](/guide/usage)）。

[花费上限](/guide/usage#cap-what-a-session-spends)对 Custom 会话同样有效。

## 设置 → 功能 → Custom

[设置 → 功能 → Custom](/settings?s=custom)（“自动模式、命令沙盒，以及目标的运行时长”）有三个部分：

- **自动模式**（“Custom 的模式之一，另外还有‘询问’‘接受编辑’‘完全访问’和‘计划’。”）：自动模式会放行什么、什么总是要问，以及由辅助模型来做检查。没有什么需要开关的：你在每个会话的**权限**下选择自动。
- **命令沙盒**（“在‘自动’和‘完全访问’模式下，命令只能修改会话文件夹和 /tmp 中的文件，但仍然可以使用网络。”）：一个开关，默认打开。当 bubblewrap 无法在这里运行时会变成灰色。
- **目标**（“使用 /goal 时，Custom 会一轮接一轮地持续工作，直到目标达成。达到这么多轮后，它会暂停等你。”）：**10**、**30**（默认）或 **100** 轮。连续三轮没有进展时，它也会暂停。

Custom 的模型在[设置 → 智能体 → 模型](/settings?s=models)中，负责检查的模型就是那里的**辅助模型**。
