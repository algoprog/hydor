# Custom，Hydor 自带的智能体

Custom 是 Hydor 自带的智能体：它可以运行你的 Claude 和 ChatGPT 订阅计划中的模型，也可以运行你自己添加的任何模型（来自 OpenRouter、Ollama、vLLM 或其他兼容 OpenAI 的服务器），并且拥有与 Claude Code 和 Codex 相同的工具、技能和连接。本主题介绍它能做什么、它的权限模式以及它如何检查命令、自动模式、命令沙盒、目标、它如何应对长时间的工作和较弱的模型，以及它的设置。

![设置 → 模型：辅助模型，以及这台电脑上的模型](images/custom.webp)

## Custom 是什么，什么时候用

Claude Code 只能运行 Anthropic 的模型，Codex 只能运行 OpenAI 的模型。Custom 也能通过这台电脑上 Claude Code 和 Codex 的登录状态，运行你的 Claude 和 ChatGPT 订阅计划中的模型；还能运行你在[设置 → 智能体 → 模型](/settings?s=models)中配置的任何模型：你自己电脑上的开源模型、通过 OpenRouter 使用的低价或免费模型，或是你自己的服务器。订阅计划中的模型无需任何设置：只要 Claude Code 已登录，Custom 的**模型**菜单就会列出 Claude Opus、Fable、Sonnet 和 Haiku；只要 Codex 已用 ChatGPT 登录，菜单里还会列出你的 ChatGPT 订阅计划提供的模型，它们都在**你的订阅**下。这些模型使用的是你订阅计划的用量，而不是 API 密钥。关于 Custom 的模型从哪里来以及如何添加更多模型，请参阅[智能体、账户和模型](/guide/agents-models#where-customs-models-come-from)。

在以下情况下使用 Custom：

- 你想用一个不离开你电脑的模型（Ollama 或 vLLM），或者让整个会话都不离开电脑：[保密会话](/guide/sessions#keep-a-session-confidential)始终在 Custom 上运行，并且只使用这台电脑或你自己网络上的模型（绝不使用你订阅计划中的模型，因为它们运行在 Anthropic 或 OpenAI 的服务器上）；
- 你想用某个特定的模型，例如 DeepSeek、Qwen、GLM 或 Kimi；
- 你想让 Custom 自己的工具和规则搭配你的 Claude 或 ChatGPT 订阅模型使用，或者想节省费用，或者在你的 Claude 或 ChatGPT 额度用完时继续工作（使用其他来源的模型）。

它什么都能帮上忙：研究、写作、文档和日常事务。在代码项目中（包含 `package.json`、`Cargo.toml`、git 仓库等的文件夹），它像一位细心的工程师那样工作：先阅读再修改，遵循项目自己的说明，并在宣布完成之前运行项目的测试和检查。

和其他智能体一样，Custom 会读取项目的 `AGENTS.md` 或 `CLAUDE.md` 文件，并遵循你的[智能体准则](/guide/guidelines)。

## 开始一个 Custom 会话

1. 在起始页上，点击**智能体**并选择 **Custom**（“任意模型：OpenRouter、Ollama、vLLM”）。
2. 点击**模型**并选择你的某个模型；菜单里有**自动**时也可以选它：Custom 的档位会根据它拥有的模型自动填充（先是你的 Claude 订阅计划的，然后是 ChatGPT 订阅计划的，再然后是你添加的、不在这台电脑上的模型）；一旦它的“最佳”档位指定了模型，选择**自动**的会话就会从该模型启动，并由它领导子智能体（参阅[档位：为每类工作选择模型](/guide/agents-models#tiers-a-model-for-each-kind-of-job)）。如果列表为空，请先添加模型：**智能体** → **Custom 的模型**。
3. 在**选项**下选择**权限**（参阅[选择 Custom 无需询问就能做什么](#choose-what-custom-may-do-without-asking)）。Custom 没有思考强度设置。
4. 输入任务并按 Enter。

由 vLLM 提供服务的、位于这台电脑上的模型，会在会话第一次使用它时启动；会话中会显示“正在用 vLLM 启动……（第一次需要一两分钟）…”。

Custom 一次处理一条消息。你在它工作时发送的消息会在消息框上方排队，并在当前这一轮结束后发出。

你可以在会话进行中通过消息框下方的菜单切换模型。Custom 从下一步起就会使用新模型，即使是在一轮的中途也一样。

## Custom 能做什么

- **文件**：读取（带行号的文本、长文件的某一部分、文件夹的内容）、创建、重写和编辑文件，列出文件夹，并按名称或内容查找文件。在重写一个它在本会话中还没读过的整个文件之前，它会被要求先读取该文件。
- **文档**：PDF、Word、Excel、PowerPoint、OpenDocument、RTF 和 EPUB 文件会被当作文本读取。
- **图片**：你附加的图片、它打开的图片文件，以及来自网页或工具的图片。能看图的模型会直接得到图片；对于不能看图的模型，则由辅助模型来描述图片（参阅[为看不了图的模型处理图片](#images-for-models-that-dont-see)）。
- **命令**：在会话的文件夹中运行 shell 命令，默认最长两分钟，最多十分钟。服务器、监视程序和其他持续运行的命令会在后台运行：Custom 在需要时读取它们的输出，也可以停止它们。Custom 退出时它们也会停止，而它的下一轮会被告知哪些命令仍在运行。
- **网页**：把网页抓取为干净的文本，保留标题、链接、列表和表格；在线的 PDF 和 Office 文件会被当作文本读取。它只能访问公开地址；要访问这台电脑或其所在网络，它会使用 `curl` 之类的命令。
- **计划**：对于有多个步骤的工作，它会维护一份清单，显示在会话中，并逐项打勾。
- **技能**：它会加载适合任务的技能：项目自带的、你自己的（Claude Code 和 Codex 的技能文件夹），以及应用的[技能库](/guide/skills)。它按分组和名称来认识这些技能，也可以用几个词描述工作内容来查找技能。
- **MCP 服务器**：你为 Claude Code 设置的工具服务器（针对所有文件夹和针对当前文件夹的）、项目的 `.mcp.json`，以及 Codex 的。
- **应用自带的工具**：网页搜索、浏览器、记忆、网页、你的[连接](/guide/connections)等等，这里的每个智能体都能使用这些工具。

每一步都会在会话中以一个通俗的名称显示（“Read index.ts”“Edit README.md”“Fetch https://…”），点击一下即可查看其差异或输出。

## 选择 Custom 无需询问就能做什么

**权限**设置（在起始页的**选项**下，或在会话消息框下方的菜单中）决定 Custom 可以自行做什么。在消息框中按 Shift+Tab 会切换到下一个模式。

- **询问**（默认）：编辑文件之前和运行命令之前都会询问。只是查看情况的命令（`ls`、`cat`、`git status` 等）可以直接运行。
- **接受编辑**：可以随意编辑会话文件夹中的文件；运行命令（只是查看情况的除外）之前以及做任何文件夹之外的操作之前会询问。
- **自动**：常规步骤直接进行；对有风险的步骤，会先做一次快速检查再询问你。参阅[自动模式](#auto-mode)。
- **完全访问**：工具和命令在运行时没有批准提示，也没有命令[沙盒](#the-sandbox-for-commands)，包括管理员命令和文件夹之外的更改。它们使用你电脑账户的权限：这不会授予你的账户所没有的管理员权限。保密会话仍会保留其网络限制。
- **计划**：只读取和制定计划。Custom 不能编辑文件或运行命令，只使用读取类的工具。它最后会给出一份带编号的计划。要执行计划，请切换到其他模式并告诉它开始。

在完全访问之外，有些命令始终会询问：参阅[始终会询问的命令](#commands-that-always-ask)。

## 批准或拒绝 Custom 想做的事

当 Custom 需要你的同意时，会话中（以及[收件箱](/guide/inbox)里）会出现一张卡片。卡片标题会说明这一步做什么以及为什么要询问，例如“Edit /home/you/notes/plan.md — it changes files outside the session folder”。对于命令，卡片会显示完整的命令。

- **允许**让这一步运行一次。
- **始终允许 …** 让这一步以及本会话中今后类似的步骤无需询问就能运行。按钮上会写明它涵盖的范围：“Always allow npm run build …”“Allow all edits”“Always allow reading in ~/data”“Always allow changes in ~/site”。
- **拒绝**停止这一步。Custom 会被告知你拒绝了，并且不要再试。

对于命令，**始终允许**的工作方式是：Custom 会把命令拆成几个部分（按 `&&`、`;`、`|` 等拆分）并逐一检查。规则只涵盖它所针对的命令，按开头的几个词来判断（`git status`、`npm run build`、`docker compose up`），所以不会有东西跟在 `&&` 后面夹带通过。只是查看情况的命令从不需要规则。

在无法确保安全时，不会提供**始终允许**：

- 直接写在命令里的代码（例如 `python -c "…"`）；
- 事先无法知道文件名的文件；
- 无法有把握地读懂的命令；
- 有风险的命令，每次都会询问。

## 始终会询问的命令

在完全访问之外，以下步骤每次都会询问你，包括自动模式下，无论你之前允许过什么：

- 以管理员身份运行（`sudo` 之类）；
- 删除会话文件夹之外的文件、删除会话文件夹本身，或删除事先无法指明名称的文件；
- 把下载内容直接通过管道传给 shell，或下载后立即运行；
- 向磁盘写入原始数据、格式化或重新分区磁盘；
- 关闭或重启电脑；
- 更改计划任务（`crontab`）；
- 更改整个文件夹树的权限或所有者；
- 更改 SSH 密钥，或你主文件夹中的设置和启动文件（如 `.bashrc` 或 `~/.config`），除非会话就在该文件夹中工作。

## 文件夹之外的文件和含密钥的文件

在询问、接受编辑和计划模式下，Custom 在读取或更改会话文件夹之外的文件之前会询问（临时文件夹不算）。这时**始终允许**会涵盖该文件夹，用于读取或更改。

含有密钥或密码的文件在读取或更改之前会询问，即使在文件夹内也是如此：`.env` 文件（示例文件除外）、SSH 和其他私钥、`.netrc`、`.npmrc`、凭据文件、你的云服务和密码存储文件夹、各智能体自己的登录信息，以及应用自己的数据。对 git 自身设置和钩子的更改也会询问。这时**始终允许**只涵盖那一个文件。

在自动模式下，这些情况由自动模式的规则和它的快速检查来决定。在完全访问下，它们不会询问。

## 自动模式

自动模式让常规工作无需打断你就能进行，并就其余情况询问你。在**权限**下选择**自动**。

每个本来要询问的步骤都会依次经过这些检查：

1. **固定规则**，不需要模型：
   - 直接进行：会话文件夹内的编辑；临时文件夹中新建的临时文件；只读取文件夹内容的命令；项目自己的测试、构建、代码检查和类型检查。
   - 询问你：覆盖文件夹之外的文件；[始终询问清单](#commands-that-always-ask)上的任何内容；用 git 强制推送；写入、移动或删除文件夹之外的文件；调用支付服务的命令；已连接账户或 MCP 服务器中会发送、发布内容或花钱的工具。
2. **快速检查**，用于其余所有情况，由[辅助模型](/guide/agents-models#choose-the-helper-model)完成。它有三种回答：
   - **允许**：这一步明显是在完成你要求的事，只在你的文件夹内进行（或只是读取），而且容易撤销；
   - **询问**：这一步可能造成持久的伤害或影响范围更广（删除数据、为整个系统安装软件、更改设置、使用密码或密钥、发送或发布任何内容、花钱，或是你没有要求的事）；
   - **拒绝**：这一步明显有害或违背你的意愿。该步骤不会运行；Custom 会被告知原因，并且必须另想办法。

快速检查只能看到你自己在会话中的消息（第一条和最近十条）、你设置的目标（如果有）、文件夹，以及这一步本身（对于编辑，则是新文本的开头）。它永远看不到 Custom 读取的内容，所以网页或文件无法诱使它做任何事。如果检查失败或耗时超过 45 秒，就由你来决定。在同一轮之内，同一步骤会得到相同的答案。在[保密会话](/guide/sessions#keep-a-session-confidential)中，检查会留在这台电脑上：如果辅助模型在本机运行，就由它来做，否则由会话自己的模型来做。

在会话中，被自动模式放行的步骤会带有一个小的**自动**标签；把鼠标悬停在上面可以看到原因。被自动模式拦下的步骤会以红色显示该标签；悬停时会看到“Auto stopped this: …”以及原因。自动模式发给你的卡片，开头会是“Auto:”和原因。

[设置 → 功能 → Custom](/settings?s=custom&find=Auto%20mode)中有一行**自动模式**，其中的 (i) 用同样的话描述了自动模式；那里没有需要切换的开关。

## 命令沙盒

在自动模式下，Custom 的命令可以在沙盒中运行：命令只能修改会话所在文件夹和临时文件夹中的文件，电脑上的其他一切都是只读的。命令仍然可以使用网络。当会话在 git 工作树或仓库的子文件夹中工作时，仓库本身的文件夹也保持可写，这样 git 才能提交。包管理器的缓存会移到一个临时文件夹。沙盒如何实现，取决于你的电脑：

- **Linux**：使用 bubblewrap。命令可以修改会话文件夹、临时文件夹（`/tmp`）和仓库本身文件夹中的文件。
- **Mac**：使用 Seatbelt，这是 macOS 自带的沙盒。规则相同：会话文件夹、临时文件夹和仓库本身的文件夹。
- **Windows**：命令以低完整性级别运行，这是 Windows 自带的一种保护机制：命令可以读取所有内容，但只能修改已被标记的文件夹中的文件。首次运行时，Hydor 会标记会话文件夹（以及仓库本身的文件夹），这个标记会一直保留。命令会得到一个专属的临时文件夹，位于 `AppData\LocalLow\Hydor`，用于存放临时文件和包缓存。你的主文件夹、整个磁盘、Windows、Program Files 以及应用数据文件夹永远不会被标记：在这类文件夹中，命令不使用沙盒运行。Git 的 bash 在低完整性级别下无法与你平时的 bash 窗口共享其运行数据，所以首次运行时，Hydor 还会为沙盒中的命令复制一份 Git 的程序，放在 `AppData\Local\Hydor\sandbox`（由指向相同文件的链接组成，因此当 Git 在同一个磁盘上时不占用空间）。

当命令碰到沙盒的限制时，Custom 会被告知它是在沙盒中运行的，然后要么在限制范围内完成工作，要么告诉你需要在别处做什么。

要开启或关闭沙盒，请打开 [设置 → 功能 → Custom](/settings?s=custom&find=Sandbox%20for%20commands)，使用 **命令沙盒** 旁边的开关。它默认是开启的。如果某个工具必须写入其他位置（例如为整个系统安装软件），请关闭它。更改会在大约 15 秒内应用到正在运行的会话。

如果沙盒无法运行，开关会变灰，并且该行会说明原因；此时命令不使用沙盒运行。在 Linux 上，这意味着未安装 bubblewrap 或它无法运行（如在某些容器中）。在 Mac 上，这意味着 Seatbelt 无法启动。在 Windows 上，Hydor 首次运行时会用 Windows 自带的 .NET Framework 构建一个小型辅助程序，同时还需要 Git for Windows（命令本来就需要它）：当其中任何一个缺失或辅助程序无法启动时，该行会告诉你。在询问和接受编辑模式下，命令不使用沙盒：在这两种模式下，每个不只是查看环境的命令都会等待你的确认，或等待你用 **始终允许** 保存的规则。

在[保密会话](/guide/sessions#keep-a-session-confidential)中，无论处于哪种模式、无论这个开关如何设置，每个命令运行时都没有网络，因此它无法访问互联网、你的其他电脑或这台电脑的服务器。它的文件权限仍按所处模式的规定。这在 Linux（bubblewrap）和 Mac（Seatbelt）上可行。Windows 无法用这种方式切断网络，因此在 Windows 上以及沙盒无法运行的任何情况下，每个命令在任何模式下都会先询问你，且没有 **始终允许** 选项。Custom 会被告知这一点，尝试访问网络的命令也会得知失败的原因。

## 给 Custom 设定目标

目标会让 Custom 一轮接一轮地持续工作，直到某个条件成立，例如：“npm test 通过，并且上传页面能处理 2 GB 的文件”。

1. 打开会话的菜单（⋯）→ **设定目标**。
2. 描述“完成”是什么样子，写成工作完成时为真的条件。
3. 点击 **开始处理**（或按 Ctrl+Enter，Mac 上按 ⌘Enter）。

Custom 会立即开始处理；如果有一轮正在运行，则会在这一轮结束时检查目标。

每一轮之后，辅助模型会根据证据检查目标：各个步骤做了什么、显示了什么（命令输出、测试结果、文件、读取过的网页）。仅仅 Custom 说完成了并不算数。然后：

- **完成**：目标被清除，你会收到“目标已达成”的通知。
- **还没有**：检查会写出下一步，并作为下一条消息发送（“目标检查 3：还没有达成……”）。
- **需要你处理**：目标会显示“卡住了：智能体需要你”，并附上问题，同时你会收到通知。请在会话中回答。
- **等待中**，在等待外部的事情（部署、下载）时：它会在三分钟后再次查看。

你自己的消息优先：检查会等到队列清空后才进行。

出现以下情况时，目标会暂停，并告诉你原因：

- 它已发送的下一步数量达到了设置中 **目标暂停前的轮数** 所允许的上限（除非你更改，否则为 30）；
- 连续三轮没有进展；
- 你停止了智能体、某一轮失败、智能体没有在运行，或检查本身失败。

消息框上方的目标栏会显示目标、它当前的状态（“正在处理”“已暂停”“卡住了：智能体需要你”）、已检查的次数和持续时间，以及最近一次检查的原因。**暂停** 不再发送下一步（已在运行的一轮会完成），**继续** 从最近一次的下一步接着进行（轮数会重新计算），**清除** 则停止朝该目标努力。目标运行期间，目标达成时你只会收到一次通知，而不是每一轮之后都收到。

要更改目标可以运行的轮数，请打开 [设置 → 功能 → Custom](/settings?s=custom&find=Rounds%20before%20a%20goal%20pauses)，在 **目标** 组的 **目标暂停前的轮数** 一行中选择 **10**、**30** 或 **100**。

## 长对话与长输出

每个模型一次只能读取有限的内容（即它的上下文）。Custom 会自行让每段对话保持在这个范围之内，所以 Custom 会话没有“压缩”按钮：

1. 当对话接近上限时（会为回复留出空间），Custom 首先清除旧的工具输出。会话中会注明“已清除旧的工具输出，以保持在模型的上下文范围内。”
2. 如果这样还不够，模型会把前面的部分总结成备注，工作从这些备注继续进行（“正在总结前面的对话，以保持在模型的上下文范围内……”）。下一次它会更新这些备注，而不是从头开始。无论哪种方式，你的计划和正在使用的技能都会保留。

如果模型的服务器提示对话太长，Custom 会了解该模型的真实上限并立即压缩。每次请求只会附带最近的几张图片。

记忆在开始时提供给 Custom 的内容在工作期间保持不变，这样模型的服务器就可以复用它保存的对话内容，既更快，费用也更低。每次压缩时，它会针对你最新的消息重新读取记忆（见[智能体一开始拥有什么](/guide/memory#what-an-agent-starts-with)）。

消息框旁边的圆环以百分比显示模型上下文的占用程度；把指针移上去可以看到词元数以及它们的去向。在 **选项**（消息框下方的标签）下，**上下文** 一行显示“已使用 42%”，旁边有一个小箭头：点击它可以显示（或隐藏）明细，明细起初是折叠的：**指令**、**项目指令**、**记忆**、**应用功能**、**技能**、**工具** 和 **对话**，每一项都附有词元数和一条表示占比的细条。没有内容的部分会被省略。这些数字是根据文本估算的，并按模型服务器的计数进行了换算。在 Custom 会话中点击圆环没有任何作用，因为 Custom 会自行压缩；Claude Code 和 Codex 会话则保留圆环和 **压缩**（见[查看仪表：上下文、缓存和速度](/guide/sessions#read-the-meters-context-cache-and-speed)）。

长输出也不会塞满对话。当命令、网页或工具返回的内容超过模型上下文的一定比例时，Custom 会把全部内容保存在会话自己文件夹中的一个文件里。模型会得到开头和结尾（对于命令，主要是结尾，因为错误通常出现在那里）以及该文件的位置，并分段读取其余部分或在其中搜索。这些文件会在一周后删除。

## 模型会读取什么

在你的消息之前，模型会按以下顺序得到：

- Custom 自己的规则（如何工作、模式、文件夹）、智能体的指令和你的智能体准则：明细中的 **指令**；
- 项目的指令，即它的 `AGENTS.md` 或 `CLAUDE.md`：**项目指令**；
- [记忆](/guide/memory#what-an-agent-starts-with)中与你的请求相关的内容：**记忆**；
- 应用功能所说明的内容：回复的样式、不让密钥和密码出现在聊天中、清理工作，以及如何完整使用它拥有的工具（图片、应用、浏览器、文档等）：**应用功能**；
- 它的技能（**技能**），按组命名：项目自己的、你的，然后是资料库中的各组，例如编程或文档。Custom 可以按名称加载某个技能，也可以按工作内容查找技能。Custom 最多接受 200 个技能，其中项目自己的和你的合计最多 40 个。与你第一条消息相符的技能会连同各自的用途一起提供；
- 它的工具，包括完整提供的工具和其余工具的简短列表：**工具**。

某个功能中关于它自己工具的说明会随这些工具一起提供。当某个工具还在 Custom 的简短工具列表中等待时，它的说明也在等待；当模型查找该工具或使用它时才会加入。无论使用哪些工具都始终适用的规则一直保留。Claude Code 和 Codex 则像以前一样，在一开始就得到应用的全部指令。

因此，发给小上下文模型的第一条消息比以前更短，每个部分占用多少可以在 **选项** 下的明细中看到：见[长对话与长输出](#long-conversations-and-long-output)。

**记忆的大小会根据模型的上下文调整。** 如果记忆占用固定的量，小上下文的模型就无法完成工作，所以记忆的份额会随窗口缩小（明细中的 **记忆** 一行显示它占用多少）：

- **低于 12,000 个词元**：一个小块，最多占上下文的 6%，包含你个人资料的前 120 个词（并说明这只是开头部分）、最多三条备注，没有索引。记忆不会随你的消息添加任何内容，也不会在模型读取或修改文件时添加内容，并且不提供 Wiki 文章条目或计划。模型会被告知可以用记忆工具查找备注。
- **最多约 33,000 个词元**（不通过 OpenRouter）：一个最多占上下文 6% 的块，包含你个人资料的前 400 个词、最多五条备注、一个简短索引、一条 Wiki 文章条目和一条计划条目，随消息最多附带一条备注（600 个字符），读取或修改文件时最多附带一条（350 个字符）。
- **更大的模型**：[记忆提供给智能体](/guide/memory#what-an-agent-starts-with)的全部内容，这只占它们上下文的一小部分。

作为参考，记忆的块对于 8,000 个词元的模型约为 1,700 个字符，32,000 个词元约为 3,800 个，200,000 个词元约为 7,300 个。只得到你个人资料开头部分的会话无法改写它：模型会告诉你要补充什么，或者你可以在[设置 → 记忆](/settings?s=memory&find=Your%20profile)中编辑。Wiki 的指令也被缩短了：Custom 始终只得到一小段关于 Wiki 记忆的说明，而如何保存来源、检查 Wiki 和采用计划的说明只有在提供相应工具时才会出现。Custom 压缩对话之后，会话的检查点（见[检查点](/guide/wiki-memory#checkpoints)）会被裁剪到上下文的 8%，最多 16,000 个字符，并附上读取其余内容的位置。

## Custom 如何应对较弱的模型

并非每个模型都像 Claude 或 GPT 那样熟练地使用工具。Custom 会捕捉常见的失误，让模型回到正轨：

- **重复**：自上次以来没有任何变化的同一步骤不会运行第三次（模型会被告知使用之前的结果）；第五次时会终止本轮。
- **失败的步骤**：连续四次步骤失败后，模型会被告知停下来重新思考；连续八次后，本轮终止。
- **绕圈**：步骤陷入循环时，会收到一条提示，让模型尝试不同的做法。
- **未完成的工作**：模型说了“让我……”却没有动手，或者在计划里还有未完成的事项时就停下，会被送回去继续工作，每种情况各一次。修改了代码却没有运行项目的检查，会被要求在结束前先运行这些检查。
- **长度**：一轮最多 200 个步骤；到 150 个步骤时，模型会被告知去完成最重要的部分。回复被模型的长度上限截断时，会用更短的步骤接着写完。
- **损坏的工具调用**：以文本形式写出的调用会被读取并运行，参数几乎正确的调用会被修复，拼错的工具名会被匹配到正确的工具，或者得到一份工具列表作为回应。以文本形式写出调用的回复，到调用结束处就结束：模型在调用之后写的内容（它想象出来的结果、叠加在其上的更多调用、重复的同一个调用）既不会运行也不会保留，一条回复最多运行六个调用。
- **不支持工具调用的模型**：当模型的服务器不接受工具时，Custom 会在指令中描述这些工具，并从模型写出的内容中读取它的调用。
- **通过 Claude Code 使用 Claude**：Anthropic 只允许自家的程序使用套餐的登录信息，因此你套餐中的 Claude 模型会通过 Claude Code 本身一步一步地作答。Custom 的工具在指令中被描述，Claude 把工具调用写成文本，就像不支持工具调用的模型那样，而且每一步都会复用上一步的缓存。Claude Code 无法在工具调用处结束回复，所以 Custom 会自己在那里结束，并停止该程序，赶在 Claude 写出它想象出来的结果之前。Codex 的模型则不同：它们直接在你的 ChatGPT 套餐上被调用，Custom 的工具是真正的工具。
- **小故障**：当连接在回复中途断开，或服务器繁忙时，Custom 会等待并重试几次。当应用重启（更新）时，如果有一个步骤正在等待你套餐中的模型，应用恢复后会重新请求该步骤；因重启而结束的一轮会说明这一点，发一条消息即可继续。
- **工具很多**：当工具很多时（来自 MCP 服务器和连接），模型看到的是一份简短的列表，需要哪个就去查哪个的完整说明；某个功能关于某个工具的指令，会在模型查阅或使用该工具时一并提供（参见[模型会读到什么](#what-the-model-reads)）。上下文较短的模型（约 32,000 个 token 或更少，且不通过 OpenRouter）会得到一套更精简的配置：没有关于回答卡片的指引，工具列表只有名称，完整呈现的工具也更少（显示 HTML 页面的那个工具也排在列表中等待）。同时它还会被要求小步前进。
- **每个模型系列**都会使用其厂商推荐的设置、它所训练的编辑格式，以及在有此选项时的思考强度。只读取的步骤会同时运行，以节省等待时间。

当 Custom 因上述某个原因终止一轮时，回复末尾会显示“(Stopped: …)”。

## 为看不见图片的模型处理图片

能看图片的模型会直接收到你的图片。当这台电脑装有 ffmpeg 或 ImageMagick 时，图片会先被缩小。

对于看不见图片的模型，辅助模型会用文字描述每张图片：图中显示了什么、各物体的位置，以及图中的文字（原样照抄）。这需要一个能看图片的辅助模型：打开[设置 → 智能体 → 模型](/settings?s=models&find=Helper%20model)，在**辅助模型**组的**模型**菜单中选择一个标有“sees images”的模型。“自动”不行。没有这样的模型时，Custom 会告诉模型有一张它看不到的图片。在保密会话中，只有这台电脑上的辅助模型才会描述图片（你套餐中的模型绝不会）。

## 分叉与从这里编辑

Custom 会话可以像 Claude Code 和 Codex 会话一样分叉：会话菜单 (⋯) → **分叉**。你也可以用**从这里编辑**修改你之前发的某条消息：对话会在一个副本中从那条消息之前继续，而当前这个会被归档。勾选**把文件恢复到这条消息之前的样子**可以撤销此后的文件改动。对 Custom 来说，这涵盖它自己的编辑所改动的文件；命令所做的改动则保持原样。

Custom 会把每段对话保存在磁盘上，所以应用重启后可以接着继续。

## Custom 的花费

- 通过 OpenRouter 使用的模型：OpenRouter 会报告每次调用的花费，会话的花费以此为准。那里的 Claude 模型会被要求把对话保留在缓存中（其他模型会自行这样做），因此每一步读回它的价格约为十分之一；而且提供给 Custom 的工具在一个会话中最多改变一次（一旦运行过后台命令的工具，这些工具就会一直保留），这样缓存才能保持有效。
- 你的 Claude 或 ChatGPT 套餐中的模型（在**你的订阅**下）：消耗的是套餐的用量，而不是按 token 计费的金额，所以会话中这些步骤显示为 $0。账户达到用量上限或已退出登录时，该步骤会交给该程序的下一个账户（需开启**达到限额时切换账户**）。
- 这台电脑上的模型（Ollama、vLLM）：不花钱。
- 其他端点：token 的定价与其他智能体相同（参见[用量、限额与费用](/guide/usage)）。

即使没有设置花费上限，会话也会在消息框上方显示 API 费用以及输入、缓存和输出的 token 数。费用取自 OpenRouter 的响应；如果流式返回的费用缺失，则取自它的生成记录；再不行就用它自己的目录价格作为后备。无需手动填写价格。

[花费上限](/guide/usage#cap-what-a-session-spends)同样适用于 Custom 会话。

## 设置 → 功能 → Custom

[设置 → 功能 → Custom](/settings?s=custom)（“自动模式、命令沙盒，以及目标运行多久”）有三行：

- **自动模式**（Custom 的模式之一，与询问、接受编辑、完全访问和计划并列）：它的 (i) 会说明自动模式放行什么、哪些始终要询问，以及检查由辅助模型完成。无需开关：你在**权限**下为每个会话选择自动模式。
- **命令沙盒**（在自动模式下，命令只能修改会话所在文件夹、Linux 上的 /tmp、Mac 上的临时文件夹，或 Windows 上它自己的临时文件夹中的文件；完全访问则不使用此沙盒，也没有批准提示）：一个开关，默认开启。当沙盒在这里无法运行时会变灰（Linux 上需要 bubblewrap，Mac 上需要 Seatbelt，Windows 上需要 Git for Windows 和 .NET Framework），该行会说明原因。
- **目标暂停前的轮数**，位于**目标**组中（使用 /goal 时，Custom 会一轮接一轮地工作，直到目标达成；达到这个轮数后会暂停，等你处理）：**10**、**30**（默认）或 **100** 轮。连续三轮没有进展时也会暂停。

Custom 的模型在[设置 → 智能体 → 模型](/settings?s=models)中，负责检查的模型就是那里的**辅助模型**。
