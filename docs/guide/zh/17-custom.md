# Custom，Hydor 自带的智能体

Custom 是 Hydor 自带的智能体：它可以运行你的 Claude 和 ChatGPT 套餐中的模型，以及你自行添加的任何模型（来自 OpenRouter、Ollama、vLLM 或其他兼容 OpenAI 的服务器），并且拥有与 Claude Code 和 Codex 相同的工具、技能和连接。本主题介绍它能做什么、它的权限模式以及它如何检查命令、自动模式、命令的沙盒、目标、它如何应对长时间的工作和较弱的模型，以及它的设置。

![设置 → 模型：辅助模型，以及这台电脑上的模型](images/custom.webp)

## Custom 是什么，什么时候用

Claude Code 只能运行 Anthropic 的模型，Codex 只能运行 OpenAI 的模型。Custom 也能通过这台电脑上 Claude Code 和 Codex 的登录状态来运行你的 Claude 和 ChatGPT 套餐中的模型，还能运行你在[设置 → 智能体 → 模型](/settings?s=models)中配置的任何模型：你自己电脑上的开源模型、通过 OpenRouter 使用的低价或免费模型，或者你自己的服务器。你套餐中的模型无需任何设置：Claude Code 登录后，Custom 的**模型**菜单会提供 Claude Opus、Fable、Sonnet 和 Haiku；Codex 用 ChatGPT 登录后，则会提供你的 ChatGPT 套餐所列出的模型，它们都在**你的订阅**下。这些模型使用的是你套餐的用量，而不是 API 密钥。关于 Custom 的模型从哪里来以及如何添加更多模型，请参阅[智能体、账户和模型](/guide/agents-models#where-customs-models-come-from)。

在以下情况下使用 Custom：

- 你想要一个不会离开你电脑的模型（Ollama 或 vLLM），或者让整个会话都不离开电脑：[保密会话](/guide/sessions#keep-a-session-confidential)总是在 Custom 上运行，并且只使用这台电脑或你自己网络中的模型（绝不会使用你套餐中的模型，因为它们运行在 Anthropic 或 OpenAI 的服务器上）；
- 你想要某个特定的模型，例如 DeepSeek、Qwen、GLM 或 Kimi；
- 你想在你的 Claude 或 ChatGPT 套餐的模型上使用 Custom 自己的工具和规则，或者想降低成本，又或者在你的 Claude 或 ChatGPT 套餐额度用完时继续工作（使用其他来源的模型）。

它什么都能帮上忙：研究、写作、文档和日常任务。在代码项目中（包含 `package.json`、`Cargo.toml`、git 仓库等的文件夹），它像一位细心的工程师那样工作：先阅读再修改，遵循项目自己的说明，并在说完成之前运行项目的测试和检查。

Custom 会读取项目的 `AGENTS.md` 或 `CLAUDE.md` 文件，并像其他智能体一样遵循你的[智能体准则](/guide/guidelines)。

## 开始 Custom 会话

1. 在起始页上，点击**智能体**并选择 **Custom**（“任意模型：OpenRouter、Ollama、vLLM”）。
2. 点击**模型**并选择你的某个模型；菜单提供**自动**时也可以选它：Custom 的档位会根据它拥有的模型自动填充（先是你的 Claude 套餐的模型，然后是你的 ChatGPT 套餐的模型，再然后是你添加的、不在这台电脑上的模型），一旦它的“最佳”档位指定了模型，处于**自动**的会话就会从该模型开始，并由它带领子智能体（参见[档位：为每类工作选择模型](/guide/agents-models#tiers-a-model-for-each-kind-of-job)）。如果列表是空的，请先添加模型：**智能体** → **Custom 的模型**。
3. 在**选项**下选择**权限**（参阅[选择 Custom 无需询问就能做什么](#choose-what-custom-may-do-without-asking)）。能进行推理的模型会提供**思考强度**设置：Claude 或 ChatGPT 套餐中的模型，可选其程序为它列出的强度（选中**默认**时，用程序自己的默认值）；[OpenRouter 模型](/guide/agents-models#effort-for-openrouter-models)，可选 OpenRouter 为它列出的强度（选中**默认**时为中等）；或[端点](/guide/agents-models#other-openai-compatible-endpoints)的模型（端点表明它能推理，或你将它的**推理强度**设为**是**），可选它的**思考强度级别**。对于其他模型，Custom 没有思考强度设置。
4. 输入任务并按 Enter。

由 vLLM 提供服务的这台电脑上的模型会在会话第一次使用它时启动；会话会显示“Starting … with vLLM (the first time takes a minute or two)…”。

Custom 一次处理一条消息。你在它工作时发送的消息会在消息框上方的队列中等待，并在这一轮结束后发出。

你可以在会话中通过消息框下方的菜单切换模型。Custom 会从下一步开始使用新模型，即使是在一轮的中途。

## Custom 能做什么

- **文件**：读取文件（带行号的文本、一次读取长文件的一部分、文件夹的内容），创建、重写和编辑文件，列出文件夹，并按名称或内容查找文件。在重写一个本次会话中还没读过的完整文件之前，它会被要求先读一遍。
- **文档**：PDF、Word、Excel、PowerPoint、OpenDocument、RTF 和 EPUB 文件会被作为文本读取。
- **图片**：你附加的图片、它打开的图片文件，以及来自网页或工具的图片。能看图片的模型会直接得到图片（对于端点的模型，要端点声明支持，或者你把 **能看图片** 设为 **是**）；对于看不了图片的模型，则由辅助模型来描述图片（参阅[为看不了图片的模型处理图片](#images-for-models-that-dont-see)）。
- **命令**：在会话的文件夹中运行 shell 命令，默认最长两分钟，最多十分钟。服务器、监视器和其他持续运行的命令会放到后台：Custom 在需要时读取它们的输出，也可以停止它们。Custom 退出时它们也会停止，并且它的下一轮会被告知哪些仍在运行。
- **网页**：把一个网页抓取为干净的文本，保留其标题、链接、列表和表格；在线的 PDF 和 Office 文件会被作为文本读取。它只能访问公开地址；对于这台电脑或它所在的网络，它会使用 `curl` 之类的命令。
- **计划**：对于有多个步骤的工作，它会维护一份清单，显示在会话中，并逐项打勾。
- **技能**：它会加载适合任务的技能：项目的技能、你自己的技能（Claude Code 和 Codex 的技能文件夹）以及应用的[技能库](/guide/skills)。它按分组和名称了解这些技能，也可以用几个词描述工作内容来查找某个技能。
- **MCP 服务器**：Custom 自己的服务器（在 [设置 → MCP 服务器](/settings?s=mcp) 中添加，见[添加服务器](/guide/connections#add-a-server)），以及为 Claude Code（适用于所有文件夹和当前文件夹）、项目的 `.mcp.json` 和 Codex 设置的服务器；重名时以 Custom 的为准。对于要求在浏览器中登录的服务器，在那里登录（见[登录服务器](/guide/connections#sign-in-to-a-server)）。
- **应用自带的工具**：网页搜索、浏览器、记忆、页面、你的[连接](/guide/connections)等，每个智能体在这里都能用到。

每一步都以通俗易懂的名称显示在会话中（“Read index.ts”“Edit README.md”“Fetch https://…”），点一下即可查看它的差异或输出。

## 选择 Custom 无需询问就能做什么

**权限**设置（在起始页的**选项**下，或在会话消息框下方的菜单中）决定 Custom 自己可以做什么。在消息框中按 Shift+Tab 可切换到下一个模式。

- **询问**（默认）：在编辑文件和运行命令之前先询问。只是查看情况的命令（`ls`、`cat`、`git status` 等）可以直接运行。
- **接受编辑**：可以随意编辑会话文件夹中的文件；运行命令（只是查看情况的除外）以及文件夹之外的任何操作之前会先询问。
- **自动**：常规步骤直接进行；对有风险的步骤，会通过快速检查来询问你。参见[自动模式](#auto-mode)。
- **完全访问**：工具和命令在运行时没有批准提示，也不受命令[沙盒](#the-sandbox-for-commands)限制，包括管理员命令和文件夹之外的更改。它们使用你电脑账户的权限：这并不会授予你的账户所没有的管理员权限。保密会话仍会保留其网络限制。
- **计划**：只读取和制定计划。Custom 不能编辑文件或运行命令，只使用读取类的工具。它最后会给出一份带编号的计划。要执行计划，请切换到另一种模式并告诉它继续。

在完全访问之外，有些命令总是会询问：参见[总是会询问的命令](#commands-that-always-ask)。

## 批准或拒绝 Custom 想做的事

当 Custom 需要你同意时，会话中（以及[收件箱](/guide/inbox)里）会出现一张卡片。卡片标题会说明这一步做什么以及为什么要询问，例如“Edit /home/you/notes/plan.md — it changes files outside the session folder”。对于命令，卡片会显示完整的命令。

- **允许**让这一步运行一次。
- **Always allow …** 让这一步运行，并且本次会话中此后类似的步骤也不再询问。按钮会说明它涵盖的范围：“Always allow npm run build …”“Allow all edits”“Always allow reading in ~/data”“Always allow changes in ~/site”。
- **拒绝**停止这一步。Custom 会被告知你拒绝了，并且不要再尝试。

命令的 **Always allow** 是这样工作的：Custom 会把命令拆分成几个部分（按 `&&`、`;`、`|` 等拆分）并逐一检查。规则按命令开头的几个词（`git status`、`npm run build`、`docker compose up`）覆盖它所针对的那条命令，因此不会有东西能借着 `&&` 之后夹带运行。只是查看情况的命令永远不需要规则。

在无法确保安全时，不会提供 **Always allow**：

- 对于直接写在命令里的代码（例如 `python -c "…"`）；
- 对于名称无法事先知道的文件；
- 对于无法可靠读懂的命令；
- 对于有风险的命令，它们每次都会询问。

## 总是会询问的命令

在完全访问之外，以下这些步骤每次都会询问你，包括自动模式，无论你之前允许过什么：

- 以管理员身份运行（`sudo` 之类）；
- 删除会话文件夹之外的文件、删除会话文件夹本身，或删除无法事先指明名称的文件；
- 把下载内容直接通过管道交给 shell，或下载后立即运行；
- 向磁盘写入原始数据、格式化或重新分区磁盘；
- 关闭或重启电脑；
- 更改计划任务（`crontab`）；
- 更改整个文件夹树的权限或所有者；
- 更改 SSH 密钥，或你主文件夹中的设置和启动文件（例如 `.bashrc` 或 `~/.config`），除非会话就在该文件夹中工作。

## 文件夹之外的文件和含有密钥的文件

在**询问**、**接受编辑**和**计划**模式下，Custom 在读取或更改会话文件夹之外的文件之前会先询问（临时文件夹不算）。此时 **Always allow** 会涵盖该文件夹，用于读取或更改。

含有密钥或密码的文件在读取或更改之前会询问，即使在文件夹内也一样：`.env` 文件（示例文件除外）、SSH 和其他私钥、`.netrc`、`.npmrc`、凭据文件、你的云服务和密码库文件夹、各智能体自己的登录信息，以及应用自己的数据。你附加到消息里的文件是例外：应用把它们和自己的数据存放在一起，但 Custom 会直接读取，不会询问。在其他对话中附加的文件仍会询问。对 git 自身设置和钩子的更改也会询问。此时 **Always allow** 只涵盖那一个文件。

在自动模式下，这些情况由自动模式的规则及其快速检查来决定。在完全访问下则不会询问。

## 自动模式

自动模式让常规工作不打断你地进行，并对其余的事情询问你。在**权限**下选择**自动**。

每个本来会询问的步骤都会按顺序经过以下检查：

1. 不需要模型的**固定规则**：
   - 直接进行：在会话文件夹内的编辑；在临时文件夹中新建的临时文件；在文件夹内只读取的命令；项目自己的测试、构建、代码检查和类型检查。
   - 询问你：覆盖文件夹之外的文件；[总是询问清单](#commands-that-always-ask)上的任何内容；用 git 强制推送；在文件夹之外写入、移动或删除文件；调用支付服务的命令；已连接账户或 MCP 服务器中会发送或发布内容、或花钱的工具。
2. 对其他所有情况，由[辅助模型](/guide/agents-models#choose-the-helper-model)进行**快速检查**。它有三种回答：
   - **允许**：它明显是在做你要求的事，没有离开你的文件夹（或只是读取），并且容易撤销；
   - **询问**：它可能造成持久的损害或影响范围更广（删除数据、为整个系统安装软件、更改设置、使用密码或密钥、发送或发布任何内容、花钱，或者你没有要求的事）；
   - **拒绝**：它显然有害或违背你的意愿。这一步不会运行；Custom 会被告知原因，并且必须另找办法。

快速检查只会看到你在会话中自己的消息（第一条和最近十条）、你设置的目标（如果有）、文件夹，以及这一步本身（对于编辑，是新文本的开头）。它永远看不到 Custom 读取的内容，所以网页或文件无法诱使它做任何事。如果检查失败或超过 45 秒，则由你来决定。在同一轮中，同一步会得到相同的答案。在[保密会话](/guide/sessions#keep-a-session-confidential)中，检查会留在这台电脑上：辅助模型在这里运行时由它来检查，否则由会话自己的模型来检查。

在会话中，自动模式放行的步骤带有一个小小的**自动**标签；把鼠标悬停在上面可查看原因。自动模式拦下的步骤，其标签显示为红色；悬停在上面可看到“Auto stopped this: …”及原因。自动模式发给你的卡片以“Auto:”和原因开头。

[设置 → 功能 → Custom](/settings?s=custom&find=Auto%20mode) 中有一行**自动模式**，其 (i) 以相同的措辞介绍自动模式；那里没有什么可以切换的。

## 命令沙盒

在自动模式下，Custom 的命令可以在沙盒中运行：它们只能修改会话文件夹和临时文件夹中的文件，电脑上的其他内容都是只读的。它们仍然可以使用网络。当会话在 git 工作树或仓库的子文件夹中工作时，仓库自身的文件夹也保持可写，这样 git 才能提交。包管理器的缓存会移到一个临时文件夹。沙盒如何实现，取决于你的电脑：

- **Linux**：使用 bubblewrap。命令可以修改会话文件夹、临时文件夹（`/tmp`）和仓库自身文件夹中的文件。
- **Mac**：使用 Seatbelt，即 macOS 自带的沙盒。规则相同：会话文件夹、临时文件夹和仓库自身的文件夹。
- **Windows**：命令以低完整性级别运行，这是 Windows 自带的一种保护机制：命令可以读取所有内容，但只能修改已被标记的文件夹中的文件。第一次运行时，Hydor 会标记会话文件夹（以及仓库自身的文件夹），这个标记会一直保留。命令会得到一个专属的临时文件夹，位于 `AppData\LocalLow\Hydor`，用来存放临时文件和包缓存。你的主文件夹、整个磁盘、Windows、Program Files 以及应用数据文件夹永远不会被标记：在这类文件夹中，命令不使用沙盒运行。Git 的 bash 在低完整性级别下无法与你平时打开的 bash 窗口共用它的工作文件，所以第一次运行时，Hydor 还会为沙盒中的命令复制一份 Git 的程序，放在 `AppData\Local\Hydor\sandbox`（由指向相同文件的链接组成，因此当 Git 位于同一个磁盘时不占用空间）。

当命令碰到沙盒的边界时，Custom 会被告知它是在沙盒中运行的，然后要么在沙盒范围内继续工作，要么告诉你还需要在别处做什么。

要开启或关闭沙盒，请打开 [设置 → 功能 → Custom](/settings?s=custom&find=Sandbox%20for%20commands)，使用 **命令沙盒** 旁边的开关。它默认是开启的。如果某个工具必须写入其他位置，例如为整个系统安装软件，请把它关闭。更改会在大约 15 秒内应用到正在运行的会话。

如果沙盒无法运行，开关会变灰，该行会说明原因；此时命令会在没有沙盒的情况下运行。在 Linux 上，这意味着没有安装 bubblewrap，或者它无法运行（例如在某些容器中）。在 Mac 上，这意味着 Seatbelt 无法启动。在 Windows 上，Hydor 第一次会用 Windows 自带的 .NET Framework 构建一个小型辅助程序，同时还需要 Git for Windows（命令本来就需要它）：当其中任何一个缺失或辅助程序无法启动时，该行会告诉你。在询问和接受编辑模式下，命令不使用沙盒：在这两种模式中，每一条不只是查看的命令都会等待你的确认，或者等待你用 **始终允许** 保存的规则。

在[保密会话](/guide/sessions#keep-a-session-confidential)中，无论处于哪种模式、无论这个开关如何设置，每条命令都在没有网络的情况下运行，因此它无法访问互联网、你的其他电脑或这台电脑的服务器。它的文件访问范围仍按当前模式而定。这在 Linux（bubblewrap）和 Mac（Seatbelt）上有效。Windows 无法用这种方式切断网络，所以在 Windows 上，以及在沙盒无法运行的任何地方，每条命令在每种模式下都会先询问你，并且没有 **始终允许** 选项。Custom 会被告知这一点，尝试访问网络的命令也会知道失败的原因。

## 给 Custom 设定目标

Custom 与其他智能体拥有相同的目标功能：应用自己的循环会一轮接一轮地驱动它，直到你认可的检查全部通过。打开会话的菜单（⋯）→ **设定目标**，或者在起始页开启 **选项** → **目标**，智能体就会提出检查项供你确认。每一轮，应用都会自己运行这些检查，保留这一轮的成果或撤销它（在工作树中），在转折点询问你该往哪个方向走，并在所有检查都通过、你叫停，或达到上限时停止。包含各个界面的完整说明见[目标](/guide/goals)。

现在对所有智能体都一样的有：确认卡片、检查项、轮次列表、提问、你的规则和 **你的意见**，以及报告。在 Custom 会话中输入 `/goal` 不再有任何特殊作用：它只是普通文本。有两点是 Custom 特有的：

- **审查者** 检查和最终检查由一个没有参与任何工作的模型来判断。在[保密会话](/guide/sessions#keep-a-session-confidential)中，这个模型是这台电脑上的模型；如果没有这样的模型，检查就无法运行。
- 检查命令按 Custom 自己命令的运行方式来运行：在自动模式下，若 **命令沙盒** 已开启，就在沙盒内运行，限制在会话文件夹中；在其他模式下，按它自己命令的运行方式；在保密会话中，始终在没有网络的沙盒内运行。
- 新目标获得的轮数来自 [设置 → 功能 → 目标](/settings?s=goals) 中的 **目标最多可运行的轮数**。它对所有智能体的目标都有效，而不只是 Custom 的。

在此版本之前 Custom 正在运行的目标不会被保留：请设定一个新的目标。

要更改新目标获得的轮数，请打开 [设置 → 功能 → 目标](/settings?s=goals&find=Rounds%20a%20goal%20may%20run)，在 **目标最多可运行的轮数** 一行中选择 **10**、**30** 或 **100**。你可以在确认卡片上设置其他数字，智能体也可能会提出一个数字。

## 长对话与长输出

每个模型一次只能读取有限的内容（它的上下文）。Custom 会自行让每段对话保持在这个范围之内，所以 Custom 会话没有 **压缩** 按钮：

1. 当对话接近上限时（会为回复留出空间），Custom 首先清除旧的工具输出。会话中会注明“已清除旧的工具输出，以保持在模型的上下文范围内。”
2. 如果这样还不够，模型会把前面的部分总结成备注，工作就从这些备注继续（“正在总结前面的对话，以保持在模型的上下文范围内……”）。下一次，它会更新这些备注，而不是从头开始。无论哪种方式，你的计划和正在使用的技能都会保留。

如果模型的服务器提示对话太长，Custom 会了解该模型真实的上限并立即压缩。每次请求只会附带最近的几张图片。

记忆在开始时给 Custom 的内容在它工作期间保持不变，这样模型的服务器就能复用它已保留的对话内容，速度更快，费用也更低。每次压缩时，它会针对你最新的消息重新读取记忆（见[智能体一开始有什么](/guide/memory#what-an-agent-starts-with)）。

消息框旁边的圆环以百分比显示模型上下文的占用程度；把鼠标指向它，可以看到词元数量以及它们的去向。在 **选项**（消息框下方的小标签）下，**上下文** 一行会显示“已使用 42%”，旁边有一个小箭头：点击它可以展开（或收起）明细，明细默认是折叠的：**指令**、**项目指令**、**记忆**、**应用功能**、**技能**、**工具** 和 **对话**，每一项都带有词元数量和一条表示占比的细条。内容为空的部分会被省略。这些数字是根据文本估算的，并按模型服务器统计的数值进行了换算。在 Custom 会话中点击圆环没有任何作用，因为 Custom 会自行压缩；Claude Code 和 Codex 会话保留它们的圆环和 **压缩**（见[读懂各项指标：上下文、缓存和速度](/guide/sessions#read-the-meters-context-cache-and-speed)）。

长输出同样不会占满对话。当命令、网页或工具返回的内容超过模型上下文的某个比例时，Custom 会把全部内容保存在会话自己文件夹中的一个文件里。模型会得到开头和结尾（对于命令，主要是结尾，因为错误通常出现在那里）以及文件的位置，然后分段读取其余部分或在其中搜索。这些文件会在一周后删除。

## 模型会读到什么

在你的消息之前，模型会按以下顺序得到这些内容：

- Custom 自己的规则（如何工作、模式、文件夹）、智能体的指令以及你的智能体准则：明细中的 **指令**；
- 项目的指令，即它的 `AGENTS.md` 或 `CLAUDE.md`：**项目指令**；
- [记忆](/guide/memory#what-an-agent-starts-with)针对你的请求提供的内容：**记忆**；
- 应用各项功能所说明的内容：回复的呈现方式、不让密钥和密码出现在聊天中、清理工作，以及如何使用它完整拥有的工具（图片、应用、浏览器、文档等）：**应用功能**；
- 它的技能（**技能**），按分组列出：项目自己的技能、你的技能，然后是资料库中的各个分组，例如编程或文档。Custom 可以按名称加载某个技能，也可以根据工作内容查找技能。Custom 最多接收 200 个技能，其中项目自己的和你的技能最多 40 个。与你第一条消息相符的技能会连同各自的用途一起提供；
- 它的工具，包括完整提供的工具和其余工具的简短列表：**工具**。

某项功能中关于其自身工具的说明会随这些工具一起提供。当某个工具还在 Custom 的简短工具列表中等待时，它的说明也在等待；当模型查找或使用该工具时，说明才会被加入。无论使用哪些工具都始终有效的规则则一直保留。Claude Code 和 Codex 与以前一样，在开始时就得到应用的全部说明。

因此，发给小上下文模型的第一条消息比以前更短，各部分占用的大小可以在 **选项** 下的明细中看到：参见[长对话与长输出](#long-conversations-and-long-output)。

**记忆的大小会根据模型的上下文来调整。** 如果记忆占用固定的大小，小上下文的模型就无法完成工作，所以记忆的占比会随窗口缩小而缩小（明细中的 **记忆** 一行会显示它占用多少）：

- **低于 12,000 个词元**：一个小块，最多占上下文的 6%，包含你个人资料的前 120 个词（并说明这只是开头部分）、最多三条备注，没有索引。记忆不会随你的消息、也不会在模型读取或修改文件时添加任何内容，也不提供 Wiki 文章条目或计划。模型会被告知可以用记忆工具查找备注。
- **最多约 33,000 个词元**（不含通过 OpenRouter 的情况）：一个最多占上下文 6% 的块，包含你个人资料的前 400 个词、最多五条备注、一个简短的索引、一条 Wiki 文章条目和一条计划条目；随消息最多附带一条备注（600 个字符），读取或修改文件时最多附带一条（350 个字符）。
- **更大的模型**：[记忆给智能体的](/guide/memory#what-an-agent-starts-with)全部内容，这只占它们上下文的一小部分。

作为参考，对于 8,000 个词元的模型，记忆块约为 1,700 个字符；32,000 个词元约为 3,800 个字符；200,000 个词元约为 7,300 个字符。只获得了你个人资料开头部分的会话无法重写它：模型会告诉你需要补充什么，或者你也可以在[设置 → 记忆](/settings?s=memory&find=Your%20profile)中编辑。Wiki 的指令也会缩短：Custom 始终只会得到一小段关于 Wiki 记忆的说明，而关于如何保存来源、检查 Wiki 和采用计划的说明，只有在提供相应工具时才会出现。Custom 压缩对话之后，会话的检查点（见[检查点](/guide/wiki-memory#checkpoints)）会被裁剪到上下文的 8%，最多 16,000 个字符，并附上在哪里可以读到其余内容。

## Custom 如何应对较弱的模型

并不是每个模型都像 Claude 或 GPT 那样擅长使用工具。Custom 会捕捉常见的失误，并让模型回到正轨：

- **重复**：同一步骤如果自上次以来没有任何变化，就不会运行第三次（模型会被告知使用之前的结果）；第五次则会终止这一轮。
- **失败的步骤**：连续四次步骤失败后，模型会被告知停下来重新思考；连续八次后，这一轮会终止。
- **兜圈子**：步骤陷入循环时，会收到一条提示，让它尝试别的做法。
- **未完成的工作**：如果模型说了“让我……”却没有去做，或者在计划中还有未完成的事项时就停下来，会被送回去继续工作，每种情况各一次。修改代码后如果没有运行项目的检查，会被要求在结束前先运行它们。
- **长度**：一轮最多 200 步；到 150 步时，模型会被告知完成最重要的部分。因模型的长度限制而被截断的回复，会以更短的步骤继续。
- **损坏的工具调用**：以文本形式写出的调用会被读取并运行，参数几乎正确的调用会被修复，拼错的工具名会被匹配到正确的工具，或者以工具列表作为回应。以文本形式写出调用的回复会在其调用结束处结束：模型在这些调用之后写的内容（它想象出来的结果、叠加在其上的更多调用、重复的同一调用）既不会运行也不会保留，并且一条回复最多运行六个调用。
- **不支持工具调用的模型**：当模型的服务器不接受工具时，Custom 会在指令中描述这些工具，并从模型所写的内容中读取它的调用。
- **通过 Claude Code 使用 Claude**：Anthropic 只允许它自己的程序使用套餐的登录凭据，所以你套餐中的 Claude 模型会通过 Claude Code 本身一步一步地作答。Custom 的工具在它的指令中被描述，Claude 把工具调用写成文本，就像不支持工具调用的模型一样，而且每一步都会复用上一步的缓存。Claude Code 无法在工具调用处结束一条回复，所以由 Custom 自己在那里结束它并停止该程序，以免 Claude 写出它想象出来的结果。Codex 的模型则不同：它们直接通过你的 ChatGPT 套餐来请求，Custom 的工具是真正的工具。
- **小故障**：当回复中途连接中断，或服务器繁忙时，Custom 会等待并重试几次。当应用重启（更新）而某一步正在等待你套餐中的模型时，应用恢复后会再次请求这一步；因重启而结束的一轮会注明这一点，发送一条消息即可继续。
- **工具很多时**：当工具很多（来自 MCP 服务器和连接）时，模型会看到一个简短的列表，并查找它需要的那些工具的完整说明；某项功能中关于工具的说明会在模型查找或使用该工具时一并提供（见[模型会读到什么](#what-the-model-reads)）。上下文较短的模型（约 32,000 个词元或更少，不含通过 OpenRouter 的情况）会得到一套更精简的配置：没有关于回答卡片的指引，工具列表只列出名称，完整提供的工具更少（用于显示 HTML 网页的那个工具也留在列表中等待）。同时它也会被要求小步前进。
- **每个模型系列**都会得到其厂商推荐的设置、它训练时使用的编辑格式，以及（若有）思考强度。只读取的步骤会同时运行，以节省等待时间。

当 Custom 因上述某个原因终止一轮时，回复会以“（已停止：……）”结尾。

## 为不能看图的模型准备图片

能看图片的模型会直接收到你的图片。端点的模型默认被视为不能看图片，除非端点声明它能看图片，或者你在它的[这一行](/guide/agents-models#other-openai-compatible-endpoints)中把 **能看图片** 设为 **是**。如果这台电脑上装有 ffmpeg 或 ImageMagick，图片会先被缩小。

对于不能看图的模型，辅助模型会用文字描述每张图片：图片里有什么、各个内容在什么位置，以及图片中的文字（原样照抄）。这需要一个能看图的辅助模型：打开 [设置 → 智能体 → 模型](/settings?s=models&find=Helper%20model)，在 **辅助模型** 组的 **模型** 菜单中选择一个标有“能看图”的模型。“自动”做不到这一点。如果没有这样的模型，Custom 会告诉模型这里有一张它看不到的图片。在保密会话中，只有这台电脑上的辅助模型才会描述图片（你的套餐中的模型则永远不会）。

## 分叉与从这里编辑

Custom 会话可以像 Claude Code 和 Codex 会话一样进行分叉：会话的菜单（⋯）→ **分叉**。你也可以用 **从这里编辑** 修改你之前发过的某条消息：对话会从那条消息之前的位置在一个副本中继续，而当前这个会话会被归档。勾选 **把文件恢复到这条消息之前的样子**，可以撤销从那时起对文件所做的修改。对于 Custom，这只涵盖它自己的编辑所改动的文件；命令所做的改动会保持原样。

Custom 会把每段对话保存在磁盘上，因此应用重启后也能接着进行。

## Custom 的费用

- 通过 OpenRouter 使用的模型：OpenRouter 会报告每次调用的费用，会话的花费就以此为准。那里的 Claude 模型会被要求把对话保留在缓存中（其他模型会自行这样做），因此每一步读回缓存的价格约为十分之一；而且 Custom 获得的工具在一个会话中最多只变化一次（在后台运行命令的工具，一旦运行过就会保留），这样缓存才能一直有效。
- 你的 Claude 或 ChatGPT 套餐中的模型（在 **你的订阅** 下）：消耗的是套餐的用量，而不是按 token 计费的金额，所以这些步骤在会话中显示为 $0。如果某个账户达到用量限额或已退出登录，这一步会交给该程序的下一个账户（需开启 **达到限额时切换账户**）。
- 这台电脑上的模型（Ollama、vLLM）：不收费。
- 其他端点：token 的定价与其他智能体相同（参见[用量、限额与费用](/guide/usage)）。

即使没有设置花费上限，会话也会在消息框上方显示 API 费用，以及输入、缓存和输出的 token 数。费用来自 OpenRouter 的响应；如果流式返回的费用缺失，则来自它的生成记录；再不行就以它自己的目录价格作为后备。无需手动填写价格。

[花费上限](/guide/usage#cap-what-a-session-spends)同样适用于 Custom 会话。

## 设置 → 功能 → Custom

[设置 → 功能 → Custom](/settings?s=custom)（“自动模式和命令沙盒”）有两项：

- **自动模式**（Custom 的模式之一，与询问、接受编辑、完全访问和计划并列）：它的 (i) 会说明自动模式放行哪些操作、哪些操作始终会询问，以及检查由辅助模型完成。无需开关：你在 **权限** 下为每个会话选择自动模式。
- **命令沙盒**（在自动模式下，命令只能修改会话文件夹中的文件，以及 Linux 上的 /tmp、Mac 上的临时文件夹，或 Windows 上它自己的临时文件夹；完全访问则在没有此沙盒和批准提示的情况下运行）：一个开关，默认开启。如果这里无法运行沙盒（Linux 上的 bubblewrap、Mac 上的 Seatbelt、Windows 上的 Git for Windows 和 .NET Framework），该项会变灰，并说明原因。

Custom 的模型位于[设置 → 智能体 → 模型](/settings?s=models)，负责检查的模型就是那里的 **辅助模型**。
