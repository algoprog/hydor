# 定时任务

定时任务是自己启动的智能体工作：可以在一天中的某个时间启动，每隔几分钟或几小时启动，只运行一次，在其他服务调用它的 Webhook 时启动，在你监测的内容发生变化时启动，在收到新邮件或已连接的应用中出现新记录时启动，也可以在日历中每个日程开始前的设定时间启动。你可以用它来做早间简报、提醒、盯着某个价格或某个网页、每周报告、处理每封通过邮件送达的新发票、首次回复每个新线索、在每次客户通话前准备简报、审阅每个新的拉取请求，或排查每次失败的 CI 运行，而结果会直接送到你面前，不需要你自己开启会话。

## 什么是定时任务

定时任务就是带有触发条件的提示词。每次触发条件满足时，应用会开始一次运行：使用该任务的智能体、模型和文件夹新建一个会话，第一条消息就是任务的提示词（如果你愿意，也可以把提示词发到你已有的某个会话中）。智能体的工作方式与在任何会话中一样。结束时它会用一行话说明进展如何，任务的历史会保存这一行、花费以及指向该会话的链接。

任务可以通过以下方式启动：

- **定时**：在你选定的星期几的某个时间点启动，或使用 cron 表达式。
- **重复**：每隔若干分钟（至少 5 分钟）或若干小时。
- **一次**：在某个日期和时间。
- **监测**：当监测器发现订阅源、网页、JSON 中的某个值、某个文件夹或某条命令的输出发生变化，你的某个邮箱账户收到新邮件，已连接的应用中出现新内容（交易、文件、工单、付款），或在已连接日历中每个日程开始前的设定时间。监测器查看时不使用模型，所以检查不消耗 token；只有内容发生变化时，智能体才会被唤醒。
- **Webhook**：当其他服务（GitHub、Gitea、表单，或你自己的脚本）调用该任务专属的地址时。

任务也可以不运行提示词，而是运行你的某个应用：每次触发条件满足时，应用会按你设定的答案运行，任务的历史会链接到那次运行（参见[自动运行应用](/guide/apps#run-an-app-by-itself)）。

时间采用你所在的时区，应用会从你的浏览器中获取。如果某次运行因为电脑关机、休眠或应用没有运行而没能按时启动，它会在下一次有机会时运行。

你的任务在[设置 → 定时任务](/settings?s=tasks)中（**设置 → 智能体 → 定时任务**）。搜索框（Ctrl+K，Mac 上为 ⌘K）也可以按名称找到任务并在那里打开。创建任务有五种方式：

- 在“设置”中点击 **新建任务**，由你自己设定每个部分。
- **从示例开始**：针对常见任务的简短表单。
- 在任意对话中让智能体来设置（“提醒我周五 9 点……”）：它会显示一张卡片供你确认。
- 在会话菜单中选择 **把它设为自动化**：根据一次运行良好的会话起草任务。
- 在某个应用的 **运行记录** 中点击 **添加定时运行**：创建一个运行该应用的任务。

当套餐的用量限制重置后自动继续会话，是一个单独的开关：[设置 → 通用 → 用量限制后继续](/settings?s=general&find=Resume%20after%20usage%20limits)（参见[用量、限制和费用](/guide/usage)）。

## 查看你的定时任务

[设置 → 定时任务](/settings?s=tasks)中有一个分组 **你的任务**，它的说明行会写明你的时区（旁边的 (i) 还会补充说明：因电脑关机而没能启动的运行，会在下一次有机会时运行），并按创建时间从早到晚列出你的任务。列表会随着运行的开始和结束自动更新。**新建任务**旁边的 **周视图** 会把所有任务显示在一个日历上（参见[查看这一周：已运行的和接下来要运行的](#see-the-week-what-ran-and-what-runs-next)）。每一行显示：

- 触发方式的图标（日历、监测器的眼睛、Webhook 标志）、任务名称和它的智能体的图标。
- 何时运行以及在哪里运行，例如“工作日 09:00 · 在 reports 中新建会话 · 14 小时 20 分钟后”，或“发到某个会话中”。
- 对于监测器，显示它最近一次查看：“5 分钟前查看：12 项，2 项新内容”（查看失败时为琥珀色）。
- 任务自行暂停时，显示原因，以及“打开开关以重试。”
- 最近几次运行的圆点（最多六个，从旧到新：绿色表示完成，琥珀色表示部分完成或受阻，红色表示失败或出错，灰色表示没有新内容），旁边是 **历史**；**上次运行 3 小时前**（如果上次运行未能启动，则显示为红色并附原因）；以及 **打开**，用来打开上次运行的会话。
- 对于 Webhook 任务，显示它的地址和复制按钮；如果任务由示例创建，还会说明要把地址粘贴到调用它的服务的哪个位置。

每一行的右侧有一个用于暂停或开启任务的开关，以及任务菜单（⋯）：**立即运行**、**测试但不发送**、**编辑**、**历史**、**创建副本**、**新地址**（仅限 Webhook 任务）和 **删除**。

能自行保持更新的看板卡片也会列出，归在该看板名下：“Shop · Sales by day: refresh”。它的那一行有开关、**立即刷新** 和 **打开看板**，后者会在看板上打开该卡片的设置：在那里修改它的问题、定时和档位，在那里点击 **停止刷新**（或把卡片移除，或删除看板）就会把它从这个列表中移除（[让卡片保持更新](/guide/library#keep-cards-up-to-date)）。

还没有任务时，列表会显示“还没有定时任务：从下面的示例开始，或让智能体帮你设置一个”。

## 查看这一周：已运行的和接下来要运行的

所有自己运行的工作都集中在一处：[智能体 → 定时运行](/agents/schedules)，即智能体页面栏中的 **定时运行**（在手机上是顶部的一个标签页）。设置 → 定时任务中的 **周视图** 也会打开它，搜索框同样可以。它汇集了你的定时任务、智能体的定时运行、应用的定时运行（包括 **自动更新**）、能自行保持更新的看板卡片、监测器和 Webhook，这样你可以看到明天要运行什么、为什么有好几项都在 08:00 启动，以及上周的情况如何。

- **这一周**：七天并排显示，从周一到周日，左侧是小时，今天会被标出，并有一条表示当前时间的线。每次已发生的运行是其时间点上的一个色块，颜色表示结果：绿色为 **完成**，灰色为 **没有新内容**，琥珀色为 **需要你处理**（部分完成或受阻），红色为 **失败**（或出错）。尚未到来的运行以淡色绘制，带虚线边缘和名称。当同一时间启动的超过三项时，会显示两项，再加一个 **+2**（或更多）的色块列出其余的。
- **每天的栏**会说明当天的运行花费了多少，以及有多少次失败。
- **每隔几分钟运行的任务、监测器和 Webhook**：每天运行超过八次的监测器和 Webhook，会在小时栏上方为每个任务显示为一条带状条，而不是每次运行一个色块。每天有一条表示运行结果的条形、已运行的次数，以及尚未到来的次数，例如 **+48**。点击该行可将它们收起。
- **点击一个方块**会弹出它的卡片：结果如何、什么时候、用了多久、花费多少、是什么启动了它（不是按它的定时运行时才显示）、智能体的一行摘要、**打开它的会话**（应用则是**打开它的运行**）、**编辑**、**暂停**（或**开启**）和**删除**。尚未到来的运行会说明它何时运行，并带有同样的这三个按钮。点击某条横带上的某一天，会按结果统计当天的运行次数，如果有会话则带有**打开最近一次**，以及同样的这三个按钮。看板卡片的刷新没有**删除**：请在看板上停止它。
- **右键点击一个条目**（方块、尚未到来的运行或横带的某一天）或列表中的一行，会弹出菜单：**编辑**、**暂停**（或**开启**）和**删除…**，后者会先询问“要删除 *名称* 吗？”。对于看板卡片的刷新，菜单里显示的是**在看板上停止**，并会带你过去。使用键盘时，在获得焦点的条目上按菜单键或 Shift+F10 可以打开菜单，按 Esc 关闭。在没有右键的设备（手机或平板）上，直接点按该条目：它的卡片上有同样的按钮。
- **‹** 和 **›** 可前往上一周或下一周，**今天** 可回到本周。右上角的 **周** 和 **月份** 可切换到月视图：每一天都有一条表示运行结果的条形、已运行和失败的次数、尚未到来的次数（每隔几分钟运行的任务则显示 **+48 次重复**），以及它的花费。点击某一天会打开它所在的那一周。
- 日历上方的一行汇总了所显示的内容：运行了多少次、失败了多少次、花费多少、尚未到来的有多少，然后是各种颜色的含义和你的时区。
- 顶部的 **筛选标签**（**全部**、**任务**、**智能体**、**应用**、**看板**、**监测器**、**Webhook**、**已暂停**，每个都带有数量）只显示对应的内容：在日历上、在汇总中和在列表中都是如此。

日历下方，**所有自己运行的工作**逐项列出：先是接下来要运行的，然后是监测器和 webhook，最后是已暂停的。每一行显示它的名称和归属（**智能体 ·** 加智能体名称、**应用 ·** 加应用名称、**看板 ·** 加看板名称，或者**任务**）、运行的时间和下一次运行的时间、自行暂停的原因、最近几次运行的圆点，以及**上次运行 3 小时前：**和结果、智能体的摘要和**打开**。开关用来暂停或开启它，垃圾桶图标在询问确认后将其删除（看板卡片的刷新没有此项）。铅笔图标会打开可以修改它的地方：智能体的定时运行在该智能体的页面上，应用的在应用的**运行记录**下（对于**自动更新**，则在它页面的**设置**中），看板卡片的刷新在它的看板上（它的**保持更新…**：[让卡片保持更新](/guide/library#keep-cards-up-to-date)），其他任何任务则在设置 → 定时任务中，并打开它的表单。

时间采用你所在的时区。在手机上，“定时运行”一次只显示一天：**‹** 和 **›**，或左右滑动，可前往前一天或后一天。

## 新建任务

1. 打开 [设置 → 定时任务](/settings?s=tasks)，选择 [**新建任务**](/settings?s=tasks&find=New%20task)，它是页面标题旁边的按钮。**新建定时任务**表单随即打开。
2. 输入名称，选择智能体和文件夹，然后写下提示词。
3. 在 **时间** 下，选择任务何时运行。
4. 在 **每次运行** 下，选择每次运行的去向和限制。
5. 如果需要，可以选择 **试运行**，不保存直接试跑一次（参见[用试运行试一试任务](/guide/tasks#try-a-task-with-a-test-run)）。
6. 选择 **创建任务**。

任务有了名称和提示词之后，**创建任务**和**试运行**才可以使用。新任务默认设为工作日 09:00 运行，使用你上次在开始页面选择的智能体，工作文件夹为应用的默认文件夹（通常是你的主文件夹）。

### 名称、智能体和文件夹

- **名称**（显示“名称，例如 Morning CI summary”的输入框）：任务在列表、通知以及各次运行所属会话标题中的显示方式（例如“Morning brief · 3 Nov, 07:30”）。最多 120 个字符。
- 智能体标签：由谁来运行任务。可以是 Claude Code、Codex、Custom，或你添加的其他智能体（参见[智能体、账户和模型](/guide/agents-models)）。换成另一个智能体会清除模型和思考强度，并设为该智能体的常用权限。
- 文件夹标签：每次运行所在的文件夹。输入路径或从列表中选取，然后选择 **使用此文件夹**。该文件夹必须已经存在。

### 模型、思考强度、权限和其他选项

下面一行提供与开始页面相同的选择器：

- **模型**和**思考强度**：使用的模型，以及它思考的深入程度。与开始页面一样，**自动**排在**模型**菜单的第一项：任务的会话从“最佳”档开始，遇到问题实在太难时，主智能体可能会自行切换到“最大值”档（参见[档位：为不同的工作选用不同的模型](/guide/agents-models#tiers-a-model-for-each-kind-of-job)）。当 [**主智能体带领子智能体**](/settings?s=models&find=Lead%20with%20subagents)已开启、且该程序有档位时（对 Custom 来说，要等它的“最佳”档指定了模型），才会提供这个选项；保密任务不提供。凡是提供的地方，新任务都从**自动**开始；你之前保存的任务保留原来的模型，你可以随时在这里更改。在终端中，`hydor tasks new … --model auto` 可以达到同样的效果（参见[在终端中使用 Hydor](/guide/terminal)）。按名称选定的模型会照名称使用。其他情况下不做更改，则使用智能体的默认设置。
- **权限**：智能体无需询问你就可以做的事。新任务的起始设置是：Claude Code 为**询问**，Codex 为**自动**，Custom 为**自动**（常规步骤直接进行，有风险的步骤会先询问）。运行时可能没有人在场：需要你批准的运行会一直等待，等待的位置是它的会话和[收件箱](/guide/inbox)。
- **智能体**、**记忆**（记忆开启时）、**花费上限**、**集群**和**研究**：每次运行的新会话都以这些设置开始，与从开始页面发起的会话相同（参见[会话](/guide/sessions)、[智能体](/guide/agents)和[记忆](/guide/memory)）。作为你的某个智能体来运行的任务，属于该智能体的日程之一：它会显示在该智能体的页面上，其运行采用该智能体的档位，并计入它的每月预算。如果某次运行在该智能体的档位上失败或因错误而停止，会在高一档的档位上重新运行，最高到“最佳”，除非该智能体的**检查未通过时升档**已关闭。用某个档位思考的智能体仍然在它的档位上运行，不论任务的模型是什么。如果该智能体有自己的对话，每次运行就会发送到那个对话中，而不是开始新会话。

### 提示词

智能体每次要做的事。请把它写成完整的指示：每次运行都是从头开始的，看不到你产生这个想法时的那段对话。最多可以有 50,000 个字符。

每次运行的第一条消息包含的不只是你的提示词：还有一行说明任务名称、运行频率、本次运行为何启动以及当前时间；一个让智能体汇报进展如何的请求；以及该任务在之前运行中留下的备注。在运行的会话中，这些内容显示为一行，例如“Scheduled task Morning brief · Weekdays at 07:30”。选择它即可阅读提示词，以及在“Added by the app for this run”下查看其余内容。

### 运行时间

**时间**有五个选项：**定时**、**重复**、**一次**、**监测**和 **Webhook**。前三个选项下面有一行（“Next: …”），按你所在的时区列出接下来的运行时间，最多三次。

- **定时**：一天中的某个时间，加上一周中的哪几天（日 一 二 三 四 五 六）。选择某一天可以开启或关闭它；七天全开表示每天，且至少会保留一天。
- **Cron 表达式…**（在**定时**下面）会把时间和日期转换成 cron 表达式（一种书写日程的标准方式），之后你可以再修改；**改用一天中的某个时间**则会切换回去。它有五个字段：分钟、小时、每月的第几天、月份和星期几（0 或 7 表示星期日），按你所在的时区计算。`*/15 9-17 * * 1-5` 表示工作日 09:00 到 17:45 之间每 15 分钟运行一次。月份和星期的名称（`jan`、`mon`）以及快捷写法 `@hourly`、`@daily`、`@weekly`、`@monthly` 和 `@yearly` 也可以使用。无效的表达式会在保存时被拒绝，并说明原因。
- **重复**：“每 [数字] 分钟”或“小时”。最短间隔为 5 分钟；新建的重复任务默认每小时运行一次。第一次运行在你保存之后过一个间隔时间才会进行。
- **一次**：一个日期和时间（默认是一小时之后）。运行顺利（**完成**或**没有新内容**）之后，任务会被删除，因为它已经无事可做。如果运行失败或需要你处理，任务会自动关闭并保留在列表中，这样你可以查看原因，并用**立即运行**再次运行。
- **监测**：参见[监测变化](/guide/tasks#watch-for-a-change)。
- **Webhook**：参见[用 Webhook 从其他服务启动运行](/guide/tasks#start-runs-from-another-service-with-a-webhook)。

在桌面应用中，从运行前几分钟起直到它开始，以及运行期间，电脑都不会自行进入睡眠（参见[让电脑保持唤醒](/guide/app#keep-the-computer-awake)）；监测器的检查不会让电脑保持唤醒。合上笔记本电脑的盖子仍会让它进入睡眠，到点时处于睡眠状态的电脑会在唤醒后运行一次该任务。对于必须在任何时刻都运行的任务，请使用一直开机的电脑。

### 每次运行

- **开始新会话**（默认），或**发送到：**你最近的某个使用同一智能体的会话（最近的 40 个未归档会话）。发送到某个会话中，可以让每次运行都在同一段对话里，该对话使用它自己的模型和设置。如果那里的智能体正忙，运行的消息会在它的队列中等待，直到当前一轮结束，并且这次运行的费用只计算它自己的那部分。
- **花费上限 $**：每次运行的花费上限，按 API 价格计算。会话花费达到这个数额后就会停止（每次模型调用后检查）。留空表示没有上限。它与上面的**花费上限**标签是同一个上限，也和它一样，只适用于新会话。
- **连续失败 [3] 次后暂停**：任务在连续失败这么多次后会自行暂停，并告诉你原因。0 表示失败永远不会让它暂停；最大为 50。

下面的一行做了总结：“运行结束后会告诉你进展如何；没有可汇报内容的运行保持安静，失败则一定会通知。”

## 监测变化

监测器是一种低成本的检查，每隔几分钟运行一次，不使用模型，只有在发生变化时才唤醒智能体。在**时间**下选择**监测**，然后选择要查看的对象：

- **订阅源**：RSS 或 Atom 订阅源（许多网站、博客和代码托管平台发布的新帖列表）的**地址**。每个新条目都会唤醒智能体，并附上它的标题、链接、日期和摘要（一次最多 25 条）。
- **网页**：网页的**地址**，以及**哪一部分**要关注：
  - **整个页面**：可读文字有任何变化。
  - **某段文字附近**：只看包含这段文字的行，以及每行的前一行和后一行（例如价格可以填“价格”）。
  - **选择器**：由一个简单的 CSS 选择器选出的部分（网页给自己各个部分起的名字）：标签、`#id`、`.class` 或 `[attribute=value]`，可以组合或嵌套，例如 `main .price`。

  运行时会得到新出现的行和消失的行。监测器读取的是服务器收到的页面，不会运行页面的脚本，所以请用**测试**检查它看到的是否与你看到的一致。
- **JSON**：JSON 响应（许多服务的 API 提供的数据格式）的**地址**，**值的位置**填写路径，例如 `data.price` 或 `data.items[0].price`，以及**唤醒条件**：变化、等于、不等于、大于、小于或包含某个**值**。数字按数值比较。条件在开始成立时唤醒智能体，而不是在成立期间的每次检查都唤醒。
- **文件夹**：这台电脑上的一个**文件夹**，如果需要，还可以填写**仅限这类文件**的模式，例如 `*.pdf`（`*` 代表任意文字，`?` 代表一个字符）。新文件会唤醒智能体，并附上它们的名称、大小和日期。隐藏文件和子文件夹不包括在内。
- **命令**：一条**命令**，每次检查时用你的 shell 在任务的文件夹中运行，最长一分钟，并选择在**当它的输出变化时**还是**当它的退出码变化时**唤醒（退出码是命令结束时给出的数字：0 通常表示成功）。运行时会得到输出以及其中发生的变化。
- **电子邮件**：你已连接的邮件账户中的新邮件（参见[连接你的电子邮件](/guide/connections#connect-your-email)）。选择**账户**和**文件夹**（不选其他则为收件箱），如果需要，还可以只看**发件人包含**或**主题包含**某段文字的邮件，或者**只看仍未读的邮件**。每封新邮件都会单独启动一次运行，每次检查最多 10 封：包括发件人和收件人、日期、主题和正文（作为外部数据），其附件会保存在任务文件夹的 email-attachments 下。如果两次检查之间到达的邮件超过 10 封，最新的 10 封会各自得到一次运行，第一次运行会用一行列出较早的邮件。同一封邮件不会启动两次运行，即使应用重启也一样。
- **已连接的应用**：你所连接的某个应用中出现的新内容（参见[已连接的应用](/guide/connections)），例如 CRM 中的新交易或新联系人、云端硬盘中的新文件、新工单或新付款。选择**账户**，然后选择每次检查时调用的**工具**：只提供它用于查看（列出或搜索）的工具，绝不会提供发送、更改、删除或付款的工具，而且只提供已为它开启的工具。在应用中存有这类内容的地方，**从模板开始**提供现成的起点（**新文件**、**新联系人**、**新交易**、**新工单**、**新付款**等）：每个起点会选定该账户自己的一个工具并填好它的字段。工具的字段可以按需填写；在字段中，`{{now}}` 代表每次检查的时间，`{{now+2d}}` 代表两天之后（`{{today}}` 和 `{{tomorrow}}` 也可以用）。**试一试**会调用该工具一次并显示返回的内容：条目在它的回答中的位置（**条目所在位置**）、用于区分条目的字段（**用于区分的字段**，例如 id 或地址）、最前面的几个条目，以及完整的**它的回答**。如果它找到的列表或字段不对，可以在这里另选一个。之后每个新条目都会单独启动一次运行，每次检查最多 10 个，条目作为外部数据提供；如果一次来了更多，第一次运行会用一行列出其余的条目。同一个条目不会启动两次运行，即使应用重启也一样。在字段允许的情况下，请让工具把最新的排在最前面，并且返回足够多的条目。
  - **每个日程开始前**：针对已连接的日历，在每个日程之前的某个固定时间启动一次运行，而不是为每个新条目各启动一次。**启动一次运行**的时间可选日程开始前 **15 分钟**、**30 分钟**或 **1 小时**，也可以选 **前一天晚上**的某个**时间**，如果需要，还可以只看**标题包含**某段文字的日程，或**只看有其他人参加的日程**。请使用列出你日程的工具，字段取从 `{{now}}` 到 `{{now+2d}}` 左右，并在**试一试**之后，在**开始时间所在字段**下选择包含每个日程开始时间的字段。监测器在每次检查时读取即将到来的日程，并在每个日程的时刻再读取一次。日程如果改期，会在它的新时间之前得到运行；已取消的日程则不会运行。

然后：

- **每 [数字] 分钟检查一次**：查看的频率，从 1 分钟到一周。新建的监测器每 15 分钟查看一次。
- **允许本机或其所在网络上的地址**（订阅源、网页和 JSON）：除非你勾选，否则默认关闭，所以监测器只能访问公共网站。只有你可以在这里的表单中允许这一点；由智能体提议的监测器永远无法访问你自己的网络。
- **测试**：显示监测器现在看到的内容，附带类似“12 items (first look)”的一行和它所读取内容的样本，或者出了什么问题。

监测器的行为方式：

- 你保存后它的第一次查看只做记录；之后的变化才会唤醒智能体。更改任务监测的对象会让它从头开始。
- 它读取的内容会作为外部数据交给智能体，供其处理，绝不会当作指示来执行。
- 如果上一次变化对应的运行仍在进行时又出现了变化，这次变化要等到下一次查看。新邮件、已连接的应用的新条目和日历日程是例外：它们各自启动自己的运行。
- 如果某次查看失败（网站无法访问、文字不再出现在页面上、已连接的应用已退出登录，或它的回答发生了变化），该行会显示原因，并且不会基于它没能读取的内容启动运行。连续失败的查看达到**连续失败 … 次后暂停**允许的次数后，任务就会暂停：“Paused after its check failed 3 times in a row: …”。
- 对监测器任务选择**立即运行**，会用监测器现在看到的内容来运行智能体，而不是用某次变化。

## 使用 Webhook 从其他服务启动运行

Webhook 是另一个服务在某件事发生时调用的地址：比如 GitHub 在拉取请求创建时、表单在有人提交时，或者你自己的脚本。在 **时间** 下选择 **Webhook** 并保存任务，即可获得它的地址（“保存任务即可获得它的地址；每次调用都会启动一次运行”）。地址会显示在任务所在的行中，旁边有一个复制按钮。这个地址无需登录应用就能使用，因为地址中的密钥部分就是权限：请妥善保密，并优先选择会在更改前询问的权限模式。服务必须能通过该地址访问到本应用。

调用的各个部分都可以放进提示词：

- `{{body.path.to.field}}`：服务发送内容中的某个值（JSON、表单或纯文本），例如 `{{body.pull_request.html_url}}`。
- `{{headers.name}}`：调用的某个请求头。携带凭据的请求头（Authorization、cookie、签名、令牌）不会被填入。
- `{{query.name}}`：地址查询部分（`?` 之后的部分）中的某个值。
- `{{body}}` 表示整个正文，`{{request}}` 表示正文、请求头和查询合在一起。

它们会作为外部数据被标记后交给智能体。对 Webhook 任务选择 **立即运行**，会按原样发送它的提示词，不会有调用来填充其中的内容。

地址下方的选项：

- **签名密钥（可选）**：自己输入一个，或选择 **生成**，然后把同一个密钥交给该服务。此后，调用必须附带用该密钥对正文生成的 HMAC-SHA256 签名（只有知道密钥的人才能生成的代码），GitHub、Gitea 等都会这样发送；GitLab 的令牌请求头同样可用。不带签名的调用会被拒绝。
- **签名请求头**：设置了密钥后才会显示。常见的请求头（X-Hub-Signature-256、X-Gitea-Signature、X-Signature-256 等）可以留空，或者填写你的服务所使用的那一个。
- **筛选（可选）**：**仅在以下情况运行** 或 **在以下情况跳过**，条件是调用中的某个路径 **等于** 某个值：`body.action` 等于 `opened`，`headers.x-github-event` 等于 `push`，`query.kind` 等于 `daily`。不带 `body.`、`headers.` 或 `query.` 的路径会读取正文。被筛选排除的调用会得到响应，但不会启动任何运行。

该地址对调用的处理方式：

- 使用相同的 Idempotency-Key 或投递 ID 重复发送的投递（GitHub、Gitea 和 GitLab 会为每次投递提供一个）只会运行一次。这些 ID 会被记住一周。
- 距任务上次运行不到五秒的调用会被拒绝，因此一连串的调用只会启动一次运行。
- 已暂停的任务会拒绝调用。单次调用最大可达 2 MB。
- 调用会立即得到响应，其中附有指向该次运行会话的链接。在地址后添加 `?wait=60`，可在响应中等待最多 60 秒以获取智能体的回复（最长 300 秒）；到时仍在进行的运行，则会响应一个指向它的链接。

## 为 Webhook 任务更换新地址

如果地址泄露了，或者某个服务不应再调用它：打开任务的菜单（⋯）→ **新地址**，然后确认 **新地址**（“当前地址将失效。请更新调用它的服务。”）。编辑 Webhook 任务不会改变它的地址；创建副本则会得到一个独立的地址。

## 从示例开始

在列表下方，[**从示例开始**](/settings?s=tasks&find=Start%20from%20an%20example)（“每个示例一份简短表单；之后随时可以更改”）以行的形式列出现成的任务，先显示前四个，其余的收在 **显示全部示例** 后面（**收起示例** 会再次将它们折叠）。它们分为三组：**日常**、**监测** 和 **工程**。选择其中一个即可打开它的简短表单，填写后在 **执行者** 下选择由谁来运行，再选择 **创建任务**。**更多选项…** 则会打开填好全部内容的完整任务表单。标有（可选）的字段可以留空，其余字段则必须填写。开关（例如 **创建拉取请求**）决定智能体可以做什么：开或关，随你决定。

**日常**

- [**晨间简报**](/settings?s=tasks&find=Morning%20brief)：每天早晨送上天气、你关注的新闻和你这一天的安排。你需要给出时间（起始为 07:30）、日期、查询天气的城市和新闻的话题；连接了日历或邮箱账户后，它还会加上今天的日程和紧急邮件。
- [**某个话题的新闻**](/settings?s=tasks&find=News%20on%20a%20topic)：按你选定的时间和日期（起始为每天 09:00），带来某个主题上真正的新动态并附上来源；没有新动态时保持安静。
- [**基于文件夹的每周报告**](/settings?s=tasks&find=Weekly%20report%20from%20a%20folder)：在每周的某一天（起始为周五 16:00），汇报文件夹或仓库在过去七天里有哪些变化、哪些看起来还没做完，并给出下周的三条建议。它不会更改任何文件。
- [**收件箱摘要**](/settings?s=tasks&find=Inbox%20digest)：自上次运行以来收到的邮件，需要你处理的邮件排在最前。它只读取，并且需要已连接的邮箱账户（参见[已连接的应用、密钥和工具](/guide/connections)）。
- [**习惯打卡**](/settings?s=tasks&find=Habit%20check-in)：在你选定的时间（起始为每天 20:00）友好地询问某个习惯的情况，并把你的连续记录保存在任务的备注中。
- [**提醒**](/settings?s=tasks&find=Reminder)：在你选定的日期的固定时间提醒你一下（起始为工作日 09:00）。如果只需要一次性提醒，参见[提醒](/guide/tasks#reminders)。

**监测**

- [**价格监控**](/settings?s=tasks&find=Price%20watch)：每 60 分钟查看一次商品页面（如果你给出了“价格”之类的文字，则只看该文字附近），并在价格变化或达到、低于你设定的目标价时通知你。
- [**网页变化提醒**](/settings?s=tasks&find=Page%20change%20alert)：每 30 分钟查看一个网页，或某段文字附近的部分，说明有什么变化以及是否重要；无关紧要的变化不会打扰你。
- [**新版本发布**](/settings?s=tasks&find=New%20releases)：每 6 小时查看一次某个 GitHub 仓库（owner/name）的发布，并总结有哪些新内容、哪些地方可能出问题。
- [**网站在线检查**](/settings?s=tasks&find=Site%20up%20check)：每 10 分钟检查一个地址。网站宕机时，智能体会查明原因（DNS、证书、HTTP 状态、超时）；恢复后，它会用一句话告诉你。
- [**磁盘空间提醒**](/settings?s=tasks&find=Disk%20space%20alert)：每 30 分钟检查一个磁盘（起始为 `/`）。当占用超过某个阈值（90%）时，智能体会找出占用空间的内容并建议清理哪些，但不会删除任何东西。
- [**文件夹中的新文件**](/settings?s=tasks&find=New%20files%20in%20a%20folder)：每 15 分钟查看一个文件夹（如果你指定，则只看 `*.pdf` 之类的文件），对每个新文件执行你在 **然后** 下写的操作，或者用一句话告诉你每个文件是什么。

**工程**（更多内容参见[工程](/guide/engineering)）

- [**审查新的拉取请求**](/settings?s=tasks&find=Review%20new%20pull%20requests)：在某个仓库文件夹中的 Webhook 任务，GitHub 或 Gitea 会为每个新的拉取请求调用它（仅当调用中为 `opened` 时才运行）。智能体会审查更改并提出修改建议，但不会推送或合并。保存后，按它所在行的说明，把它的地址复制到仓库的 Webhook 设置中（在单个事件里只勾选 **拉取请求**）。
- [**CI 医生**](/settings?s=tasks&find=CI%20doctor)：GitHub Actions、GitLab CI、Buildkite 或 CircleCI 上的一次失败运行会唤醒一个智能体，它会阅读日志，分辨是偶发失败还是真正的问题，并按你的许可重新运行，或创建带修复的草稿拉取请求，最后做出总结。参见 [CI 医生](/guide/engineering#ci-doctor)。
- [**议题分诊**](/settings?s=tasks&find=Issue%20triage)：每个新议题都会被打上标签、检查是否重复，并友好地请提出者补充缺少的信息；如果修复很小，还会尝试以草稿拉取请求的形式给出。参见[议题分诊](/guide/engineering#issue-triage)。
- [**依赖园丁**](/settings?s=tasks&find=Dependency%20gardener)：每周一次（起始为周一 09:00），在工作树中升级依赖并运行测试，优先处理安全修复，每个风险等级一个拉取请求，或者给出一份报告。参见[依赖园丁](/guide/engineering#dependency-gardener)。
- [**故障第一响应人**](/settings?s=tasks&find=Incident%20first%20responder)：来自 Sentry、Grafana、Datadog、Better Stack 或其他服务的告警会唤醒一个智能体，它会立刻通知你，找出可能的原因，并在任何回滚之前先询问你。参见[故障第一响应人](/guide/engineering#incident-first-responder)。

Webhook 示例的表单会在字段下方说明它的地址将用在哪里；任务创建后，任务所在行会在地址下方给出同样的说明。

## 用试运行来试一试任务

表单页脚中的 **试运行** 会按表单当前的内容立即运行一次任务，而不保存它。它和真正的运行一样，在一个独立的会话中进行，会话标题为“Test: <名称> · <时间>”，运行结束后，表单中的一条提示栏会显示 **试运行** 以及运行结果，还有 **打开它的会话**。试运行永远不会计入导致任务暂停的失败次数。对正在编辑的任务进行测试时，会读取它的备注，并在它的历史中显示为 **试运行**；新任务还没有备注。

如果要试一个会发送、发布或删除内容的任务，又不想真的有任何东西发出去，请打开 **试运行** 旁边的菜单（**更多测试方式**）并选择 **测试但不发送**，或在已保存任务的菜单（⋯）中选择 **测试但不发送**。它的运行方式相同，但每一次对已连接账户中会对外产生作用的工具的调用（发送、发布、公开、回复、邀请、分享、删除或付款），以及每一次对设为“先询问”的工具的调用，都会被记为“本会发送”，并且不会真正执行。智能体会被告知这一点，并像已经执行了一样继续进行。它的提示栏、它在 **历史** 中的运行记录以及它的会话，都会列出它 **本会发送** 的内容，之后发件箱中不会有任何东西在等待。读取操作照常进行。参见[已连接的应用、密钥和工具](/guide/connections#ask-first-calls-that-wait-for-your-ok)。

## 立即运行任务

任务的菜单（⋯）→ **立即运行** 会马上开始一次运行，不论任务是开启还是暂停状态，并打开它的会话。

## 查看运行情况

任务的菜单（⋯）→ **历史**，或圆点旁边的 **历史**，会打开该任务的运行记录，最新的在前（显示最近 50 条；应用为每个任务保留 100 条）。每条运行记录显示：

- 运行结果：**正在运行**、**完成**、**部分完成**、**受阻**（智能体需要你：访问权限或某个决定）、**失败**、**没有新内容** 或 **错误**（无法启动，或它的这一轮因错误而停止）。
- 开始时间、由什么触发（**按计划**、**Webhook**、**监测器**、**立即运行**、**重新运行**、**试运行** 或 **测试但不发送**）、耗时和花费。
- 对于不发送的测试，显示它 **本会发送** 的内容：每次调用，以及账户、工具和会发给谁。
- 智能体的一句话总结。选择较长的总结可以阅读智能体最后一次回复的全文。
- **打开它的会话**，以及 **用相同的输入再运行一次**，它会用那次运行得到的内容再次运行任务：同样的 Webhook 调用，或监测器看到的同一处变化。

结果就是智能体在最后报告的内容。如果它什么也没报告，则由应用判定：如果这一轮因错误而停止，就是 **错误**；如果回复以 [SILENT] 开头，或只是说没有可报告的内容，就是 **没有新内容**；其他情况是 **完成**。在该次运行的会话中，智能体的报告会显示为一个步骤：“Reported done: …”。

## 任务在各次运行之间保留的备注

历史下方是任务的记事本，即 **各次运行记下的笔记**：下一次运行应该知道的内容，比如已经报告过什么、累计总数或进行到哪里。每次运行开始时都会读取它，智能体会在其中追加内容或重写它。选择 **编辑** 可以自己修改，然后选择 **保存**（或 **取消**）。它最多容纳 8,000 个字符；超出后，最旧的行会被删除。

## 任务的通知

一次运行会通过其会话常规的通知告诉你运行情况，通知标题是会话的名称，内容是智能体的一句话总结。它遵循你的通知设置（参见[收件箱和通知](/guide/inbox)）。

- 没有内容可报告的运行不会发送任何通知。
- 失败的运行，或以错误结束的运行，一定会发送失败通知。
- 受阻的运行会发送一条需要你处理的通知，以“Blocked:”开头。
- 无法启动的运行（它的文件夹已不存在，或它要发布到的会话已被删除）会发送失败通知，“Could not start: …”。
- 自行暂停的任务会发送一条说明原因的通知。
- 结束了自己任务的运行会如此说明：“Its job is done, so its schedule was deleted.”
- 发布到你的某个对话中的运行，不会改变该对话原有的通知。

智能体在工作时也可以给你发送通知（它的 notify_user 工具），用于等不到运行结束的事情；任何智能体以及应用的某个步骤同样可以这样做。

## 暂停、开启、编辑、创建副本或删除任务

- **暂停或开启**：任务所在行的开关。已暂停的任务不会运行，也不会监测，它的 Webhook 会拒绝调用。重新开启任务会清除它的失败次数和暂停原因。
- **自行暂停**：连续失败达到设定的次数后，任务会暂停，它所在的行会说明原因（“Paused after 3 failed runs in a row. The last: …”）。
- **编辑**：任务的菜单（⋯）→ **编辑** 会以 **编辑任务** 的形式打开表单；选择 **保存**。已保存任务的表单页脚中也有 **删除**，同样会先询问。
- **创建副本**：打开一个新任务表单，其中是名为“<名称> (copy)”的副本，可修改后保存。
- **删除**：会先询问：“It stops running, and its history goes. Sessions it started stay.”
- **自动删除**：不再需要的任务会在最后一次运行结束约一分钟后自行删除：一次性任务在一次顺利的运行之后；以及运行时发现任务已完成的任务，因为它等待或监测的事情已经发生，并且它的提示词说过到那时就停止（运行的通知会说明这一点）。智能体的定时任务会随智能体一起删除。

## 让智能体设置任务

在任何对话中，都可以用你自己的话来提出：“周五早上 9 点提醒我给牙医打电话”“每周一早上，总结上周的问题”“这个网页有变化时告诉我”。智能体会提出任务方案，并在对话中用一张卡片展示。在你回应之前，不会保存任何内容。

卡片会询问 **要安排这个任务吗？**，并显示任务名称和 **等你处理**，同时展示：

- **时间**：用文字描述的计划，以及按你所在时区显示的接下来几次运行时间。对于监视任务，则显示监视的对象和频率，以及网址、命令或已连接的应用的工具，还有这句话：“确认后会检查一次是否正常，之后只有内容发生变化时才会唤醒智能体。”
- **执行内容**：提示词（较长的提示词可点击 **显示全部** 展开）。
- **运行记录**：使用的智能体、它的模型（当对话使用 **自动** 时，这里也显示 **自动**），以及运行位置：某个文件夹中的新会话，或当前对话。

然后选择：

- **安排**：保存任务并开启。
- **编辑…**：打开任务表单，所有内容都已填好，可以先修改任何部分；表单上的按钮同样是 **安排**。
- **暂不**：拒绝这个方案。

智能体会把你的回应当作一条消息收到，包括你修改过的部分，所以你不必再告诉它。卡片会连同结果一起保留在对话中（“已安排”“下次运行……”，以及指向 **定时任务** 的链接），并且在你的其他设备上显示相同的内容。

除非你另有要求，任务会使用对话中的智能体、模型、权限和文件夹来运行（处于 **自动** 的对话会生成同样从 **自动** 开始的任务），并且每次运行的会话都以对话的设置开始：它的智能体、记忆、花费上限、已连接的账户和项目。如果你要求把运行结果发到这里，每次运行都会发到当前对话中，而不是新建会话。

智能体也可以修改、暂停、重新开启或删除你的任务，并且总是先出示一张卡片：**修改这个任务？**（显示将要改动的部分，旧值带删除线，显示在新值上方）、**暂停此任务？**、**要重新开启此任务吗？** 或 **删除这个任务？**，每张卡片都有各自的肯定和否定选项（**确认修改** 或 **保持原样**，**暂停** 或 **继续运行**，**开启** 或 **保持暂停**，**删除** 或 **保留**）。它们还可以列出你的任务，包括每个任务下次运行的时间以及上次运行的情况。

对于不再需要的任务，智能体会直接删除，而不是暂停。对于应在某件事发生时停止的任务（“直到新版本发布”“等我的包裹送到后”），智能体会在任务的提示词中写明，并由发现该事件发生的那次运行结束这个任务。

一些限制让这一切保持在可控范围内：

- 一个对话中最多可以有五个方案在等你回应。
- 当你已有 100 个任务时，智能体无法再提出新任务。
- 定时运行不能安排或修改任务；它会被告知在摘要中提出建议。它只能在工作完成后结束自己的任务。
- 智能体提出的监视任务绝不会访问你自己电脑或网络上的地址。

## 把会话变成任务

如果某个会话做的事情你想再做一次：点击会话的菜单（⋯）→ **更多** → **把它设为自动化**。[辅助模型](/settings?s=models&find=Helper%20model)会阅读这段对话并起草一个任务：一条可以自行再次运行的提示词（去掉了这一次的一次性细节，并融入了你的修正），以及一个合适的触发条件。智能体、模型、思考强度、权限、文件夹和会话的设置都来自该会话（处于 **自动** 的会话会生成从 **自动** 开始的任务）；在工作树中的会话会在它所源自的仓库中运行。

表单会以 **从此会话新建自动化** 为标题打开，并附有一行说明，解释为什么选择了这个触发条件。你可以修改任何内容，试运行一次，然后保存；之后该任务就会出现在[设置 → 定时任务](/settings?s=tasks)中。没有你发送过消息的会话无法变成任务。

## 提醒

提醒是一种任务，它在设定的时间运行，并通过通知和它的会话告诉你一件事。设置提醒有三种方式：

- 让智能体来做：“明天早上 8 点提醒我把垃圾拿出去”。它会提出一个只运行一次的任务，你在卡片上确认即可。
- 使用[**提醒**](/settings?s=tasks&find=Reminder)示例，设置在你选定的日子重复的提醒。
- 新建一个任务（**新建任务**），在 **时间** 下选择 **一次**，并写下这样的提示词：“用一句友好的话提醒我给牙医打电话。”

## 在手机上

[设置 → 定时任务](/settings?s=tasks)在手机上的用法相同，而[日程](/agents/schedules)一次显示一天。任务表单、示例的表单以及各种确认（在 **删除** 或 **新地址** 之前）都会以面板形式从屏幕底部弹出。**时间** 下的各个选项和监视任务的类型在放不下时可以左右滑动，示例则排成一列。要在应用关闭时也收到任务的通知，请为手机开启通知（参见[收件箱与通知](/guide/inbox)）。

## 询问智能体

- “工作日每天 7:30，告诉我雅典的天气和昨天以来的 AI 新闻。”
- “周五早上 9 点提醒我给牙医打电话。”
- “让我的晨间简报在自动模式下运行。”
- “盯着这个商品页面，价格降到 €99 以下时告诉我。”
- “每当会计发来带发票的邮件，就把 PDF 保存到 ~/Invoices，并在我的支出表格里添加一行。”
- “HubSpot 里有新交易时启动一个任务：查一下这家公司，并起草给对方联系人的第一封回复。”
- “在我的 Google 日历中每次客户电话会议前 30 分钟，向我简要介绍我要见的人以及我们上次讨论的内容。”
- “我的定时任务中，本周哪些失败了，为什么？”
- “我的看板上有什么会在明天早上刷新，这些刷新每月要花多少钱？”
- “明天有什么会自动运行，几点运行？”
- “为什么我有这么多任务都在周一 08:00 启动？把它们错开。”
- “暂停我的晨间简报”，或者“现在运行每周报告。”
- “删除我误加到研究员上的每周计划。”
- “每 30 分钟检查一次我的包裹是否已送达，送到后告诉我，然后停止。”
- “我的定时任务里有哪些已经不需要了？把它们删除。”
- “测试我的发票提醒，但不要发送任何内容，并给我看它本来会发出的邮件。”
- “把这个对话变成每周一早上 9 点运行的任务。”
- “每当这个订阅源有新帖子时，就运行我的阅读列表应用，并附上帖子的链接。”
- “为 ~/code/shop 设置一个 GitHub Actions 的 CI 医生，允许它重新运行不稳定的作业。”
