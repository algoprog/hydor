# 定时任务

定时任务是会自己开始的智能体工作：在每天的某个时间、每隔几分钟或几小时、只运行一次、在其他服务调用它的 webhook 时，或在你关注的东西发生变化时开始。你可以用它来做晨间简报、提醒、盯住某个价格或网页、每周报告，或审查每个新的拉取请求，结果会自动送到你面前，不用你自己开会话。

![设置 → 定时任务：自己开始的工作](images/tasks.webp)

## 什么是定时任务

定时任务就是带有触发条件的提示词。每次触发时，应用都会启动一次运行：用任务的智能体、模型和文件夹开一个新会话，第一条消息就是任务的提示词（如果你愿意，也可以把提示词发到你已有的某个会话里）。智能体会像在任何会话中一样工作。结束时，它会用一句话说明情况如何，任务的历史会记下这句话、花费，以及指向该会话的链接。

任务可以在以下情况开始：

- **定时**：在你选的一周中某几天的某个时间，或按 cron 表达式。
- **重复**：每隔若干分钟（至少 5 分钟）或若干小时。
- **一次**：在某个日期和时间。
- **监测**：当监测器发现订阅源、网页、JSON 中的某个值、某个文件夹或某个命令的输出有变化时。监测器查看时不用模型，所以检查不消耗 token；只有发生变化时才会唤醒智能体。
- **Webhook**：当其他服务（GitHub、Gitea、某个表单、你自己的脚本）调用任务专属的地址时。

任务也可以不用提示，而是运行你的某个应用：每次触发时，应用会用你设定的回答运行，任务的历史会链接到那次运行（见[让应用自行运行](/guide/apps#run-an-app-by-itself)）。

时间按你的时区计算，应用从你的浏览器获取时区。如果因为电脑关机或应用没有运行，某次运行没能按时开始，它会在下一次有机会时运行。

你的任务在[设置 → 定时任务](/settings?s=tasks)中（**设置 → 智能体 → 定时任务**）。搜索框（Ctrl+K，Mac 上是 ⌘K）也能按名称找到任务，并在那里打开它。创建任务有五种方式：

- 设置中的**新建任务**，每一项都由你自己设置。
- **从示例开始**：为常见任务准备的简短表单。
- 在任何对话中让智能体来做（“周五 9 点提醒我”）：它会显示一张卡片，由你确认。
- 会话菜单中的**把它设为自动化**：根据一个做得好的会话起草一个任务。
- 应用**运行记录**中的**添加定时运行**：一个运行这个应用的任务。

套餐的用量限额重置后让会话自己继续，是另一个单独的开关：[设置 → 通用 → 用量限制解除后继续](/settings?s=general&find=Resume%20after%20usage%20limits)（见[用量、限额和费用](/guide/usage)）。

## 查看你的定时任务

[设置 → 定时任务](/settings?s=tasks)开头有一行写明你的时区，然后列出你的任务，最早创建的在前。运行开始和结束时，列表会自动更新。每一行显示：

- 表示触发方式的图标（日历；监测器是一只眼睛；webhook 标志）、任务名称，以及它的智能体图标。
- 它什么时候运行、在哪里运行，比如“工作日 09:00 · 在 reports 中新建会话 · 下次在 14 小时 20 分钟后”，或“发送到某个会话”。
- 对于监测器，显示它最近一次查看的情况：“5 分钟前查看过：12 个条目，2 个新条目”（查看失败时显示为琥珀色）。
- 如果任务自己暂停了，会说明原因，并附上“开启它即可重试。”
- 表示最近几次运行的圆点（最多六个，最早的在前：绿色表示完成，琥珀色表示部分完成或受阻，红色表示失败或出错，灰色表示没有新内容），旁边是**历史**；**上次运行于 3 小时前**（如果上次运行没能开始，会用红色显示并附上原因）；以及**打开**，用来打开上次运行的会话。
- 对于 webhook 任务，显示它的地址和一个复制按钮。

每一行右边有一个用来暂停或开启任务的开关，以及任务的菜单（⋯）：**立即运行**、**编辑**、**历史**、**创建副本**、**新地址**（仅限 webhook 任务）和**删除**。

还没有任务时，列表会显示“还没有定时任务”，并引导你去看它下面的示例。

## 新建任务

1. 打开[设置 → 定时任务](/settings?s=tasks)，选择右上角的[**新建任务**](/settings?s=tasks&find=New%20task)。会打开**新建定时任务**表单。
2. 输入名称，选择智能体和文件夹，然后写下提示词。
3. 在**时间**下，选择它什么时候运行。
4. 在**每次运行**下，选择每次运行在哪里进行，以及它的限制。
5. 如果你愿意，可以选择**试运行**，不保存就先试一次（见[用试运行试试任务](/guide/tasks#try-a-task-with-a-test-run)）。
6. 选择**创建任务**。

任务有了名称和提示词之后，**创建任务**和**试运行**才能使用。新任务默认在工作日 09:00 运行，使用你上次在开始页上选的智能体，在应用的默认文件夹（通常是你的主文件夹）中运行。

### 名称、智能体和文件夹

- **名称**（写着“名称，例如‘早间 CI 摘要’”的输入框）：任务在列表中、通知中，以及它各次运行的会话标题中显示的名字（“晨间简报 · 11月3日 07:30”）。最多 120 个字符。
- 智能体按钮：由谁来运行它。Claude Code、Codex、Custom，或你添加的其他智能体（见[智能体、账户和模型](/guide/agents-models)）。换一个智能体会清除模型和思考强度，并设为那个智能体通常的权限。
- 文件夹按钮：每次运行工作的文件夹。输入路径或选择一个，然后选择**使用此文件夹**。这个文件夹必须已经存在。

### 模型、思考强度、权限和其他选项

它们下面的一行，有开始页上的那些选择器：

- **模型**和**思考强度**：用哪个模型，以及它思考得多深入。不动的话，就用智能体的默认设置。
- **权限**：智能体不问你就可以做什么。新任务对 Claude Code 默认是**询问**，对 Codex 是**自动**，对 Custom 也是**自动**（常规步骤直接进行，有风险的步骤会询问）。运行时可能没有人在看：需要你批准的运行会在它的会话里和[收件箱](/guide/inbox)中等你批准。
- **助手**、**记忆**（开启记忆时）、**花费上限**、**集群**和**研究**：每次运行的新会话都会带着这些设置开始，就像从开始页启动的会话一样（见[会话](/guide/sessions)、[助手](/guide/assistants)和[记忆](/guide/memory)）。

### 提示词

智能体每次要做的事。把它写成完整的指示：每次运行都是从头开始的，看不到你产生这个想法时的那段对话。最多可以写 50,000 个字符。

每次运行的第一条消息不只有你的提示词：还有一行写明任务名称、运行频率、这次运行开始的原因和当前时间；一个让它报告进展的请求；以及任务在之前各次运行中记下的笔记。在运行的会话中，这些内容显示为一行，比如“定时任务 晨间简报 · 工作日 07:30”。选中它，就能看到提示词，以及“应用为本次运行添加的内容”下面的其余部分。

### 运行时间

**时间**有五个选项：**定时**、**重复**、**一次**、**监测**和 **Webhook**。对于前三个，下面会有一行（“接下来：…”）按你的时区列出接下来的运行时间，最多三个。

- **定时**：一天中的某个时间，以及一周中的哪几天（S M T W T F S，即周日到周六）。选中某一天可以开启或关闭它；七天全选表示每天，并且至少总有一天是开启的。
- **Cron 表达式…**（在**定时**下）会把时间和日期转换成 cron 表达式（一种书写日程的标准方式），之后你可以修改它；**改用一天中的某个时间**可以切换回去。它有五个字段：分钟、小时、日期（月中的第几天）、月份和星期几（0 或 7 表示周日），按你的时区计算。`*/15 9-17 * * 1-5` 表示工作日 09:00 到 17:45 之间每 15 分钟运行一次。月份和星期的名称（`jan`、`mon`）以及快捷写法 `@hourly`、`@daily`、`@weekly`、`@monthly` 和 `@yearly` 也可以用。无效的表达式会在你保存时被拒绝，并说明原因。
- **重复**：“每 [数字] 分钟”或“小时”。最短间隔是 5 分钟；新的重复任务默认每小时运行一次。第一次运行在你保存后过一个间隔时进行。
- **一次**：一个日期和时间（默认是一小时后）。运行之后，任务会自己关闭，但仍留在列表中：你可以用**立即运行**再运行一次，或者删除它。
- **监测**：见[监测变化](/guide/tasks#watch-for-a-change)。
- **Webhook**：见[用 webhook 让其他服务启动运行](/guide/tasks#start-runs-from-another-service-with-a-webhook)。

### 每次运行

- **开始新会话**（默认），或 **发送到：** 你最近使用同一智能体的某个会话（最近 40 个未归档的会话）。发送到同一个会话，会让每次运行都留在一段对话里，并使用那个会话自己的模型和设置。如果那里的智能体正忙，运行的消息会在队列中等到这一轮结束，而这次运行的花费只计算它自己那部分。
- **花费上限 $**：每次运行的花费上限，按 API 价格计算。运行的会话一旦花到这个数就会停止（每次调用模型后检查）。留空表示没有上限。它和上面的**花费上限**按钮是同一个上限，也一样只对新会话有效。
- **暂停于 [3] 次连续失败**：连续失败这么多次后，任务会自己暂停，并告诉你原因。0 表示失败永远不会让它暂停；最多可以设为 50。

它们下面的一行做了总结：“每次运行都会告诉你进展如何；没什么可报告的运行会保持安静，而失败总会通知你。”

## 监测变化

监测器是一种低成本的检查，每隔几分钟运行一次，不用模型，只在有变化时才唤醒智能体。在**时间**下选择**监测**，然后选择要看什么：

- **订阅源**：RSS 或 Atom 订阅源的**地址**（许多网站、博客和代码托管平台发布的新文章列表）。每个新条目都会唤醒智能体，并附上它的标题、链接、日期和摘要（每次最多 25 个）。
- **网页**：网页的**地址**，以及**哪一部分**算数：
  - **整个页面**：可读文字的任何变化。
  - **某段文字附近**：只看含有这段文字的行，以及每一行的前一行和后一行（比如要看价格，就填“价格”）。
  - **选择器**：一个简单的 CSS 选择器（网页给它各部分起的名字）选中的部分：标签、`#id`、`.class` 或 `[attribute=value]`，可以组合或嵌套，比如 `main .price`。

  运行会得到新出现的行和消失的行。监测器读取的是服务器收到的网页原样，不会运行网页的脚本，所以请用**测试**检查它看到的是否和你看到的一样。
- **JSON**：一个 JSON 响应（许多服务的 API 给出的数据格式）的**地址**、**值的位置**（一个路径，比如 `data.price` 或 `data.items[0].price`），以及**唤醒条件**：它变化、等于、不是、高于、低于或包含某个**值**时。数字按数字来比较。条件在开始成立时唤醒智能体，而不是在成立期间的每次检查都唤醒。
- **文件夹**：这台电脑上的一个**文件夹**，如果你愿意，还可以用**仅限这类文件**指定一个模式，比如 `*.pdf`（`*` 代表任意文字，`?` 代表一个字符）。新文件会唤醒智能体，并附上它们的名称、大小和日期。隐藏文件和子文件夹不算在内。
- **命令**：一条**命令**，每次检查时在任务的文件夹中用你的 shell 运行，最多运行一分钟；以及选择**当它的输出变化时**还是**当它的退出码变化时**唤醒（退出码是命令结束时给出的数字：0 通常表示成功）。运行会得到输出以及其中变化的部分。

然后：

- **检查频率：每 [数字] 分钟**：多久查看一次，从 1 分钟到一周。新的监测器默认每 15 分钟查看一次。
- **允许本机或其所在网络上的地址**（适用于订阅源、网页和 JSON）：除非你勾选，否则是关闭的，所以监测器只能访问公开网站。只有你能在这个表单里允许这一项；智能体提议的监测器永远不会访问你自己的网络。
- **测试**：显示监测器现在看到的内容，带有一行类似“12 个条目（第一次查看）”的说明和它读到内容的样本，或者出了什么问题。

监测器的行为方式：

- 保存后的第一次查看只做记录；之后的变化才会唤醒智能体。修改任务监测的对象会让它重新开始。
- 它读到的内容交给智能体时会被标为外部数据，供它处理，而绝不会被当作指令来执行。
- 如果上一次变化引发的运行还在进行，这期间出现的变化会等到下一次查看。
- 查看失败时（网站宕机、那段文字已经不在页面上了），这一行会说明。连续失败的次数达到**暂停于 … 次连续失败**所允许的数目后，任务会暂停：“检查连续失败 3 次后已暂停：…”。
- 对监测任务使用**立即运行**，会让智能体处理监测器现在看到的内容，而不是某个变化。

## 用 webhook 让其他服务启动运行

webhook 是其他服务在发生某件事时调用的地址：GitHub 在有拉取请求创建时、表单在有人提交时、你自己的脚本。在**时间**下选择 **Webhook**，然后保存任务以获取它的地址（“保存任务后即可获得它的地址；每次调用都会启动一次运行”）。地址显示在任务那一行中，带有一个复制按钮。这个地址不用登录应用就能使用，因为地址中保密的那部分本身就是许可：请保管好它，并尽量选择在做出更改前会询问的权限模式。那个服务必须能通过这个地址访问到本应用。

调用中的部分内容可以放进提示词：

- `{{body.path.to.field}}`：服务发来的内容（JSON、表单或纯文本）中的某个值，比如 `{{body.pull_request.html_url}}`。
- `{{headers.name}}`：调用的某个请求头。带有凭据的请求头（Authorization、cookie、签名、令牌）永远不会被填入。
- `{{query.name}}`：地址查询部分（`?` 后面的部分）中的某个值。
- `{{body}}` 表示整个请求体，`{{request}}` 表示请求体、请求头和查询部分的全部内容。

它们交给智能体时会被标为外部数据。对 webhook 任务使用**立即运行**，会按原样发送提示词，因为没有调用来填充它。

地址下面的选项：

- **签名密钥（可选）**：输入一个，或选择**生成**，然后把同一个密钥交给那个服务。之后，调用必须带有用它对请求体做出的 HMAC-SHA256 签名（只有知道密钥的人才能生成的代码），GitHub、Gitea 等服务都会发送这种签名；GitLab 的令牌请求头也可以。没有签名的调用会被拒绝。
- **签名请求头**：有了密钥后才会显示。使用常见的请求头（X-Hub-Signature-256、X-Gitea-Signature、X-Signature-256…）时留空即可，否则填写你的服务所用的那个。
- **筛选（可选）**：**仅在以下情况运行**或**在以下情况跳过**：调用中的某个路径**是**某个值，比如 `body.action` 是 `opened`、`headers.x-github-event` 是 `push`、`query.kind` 是 `daily`。不以 `body.`、`headers.` 或 `query.` 开头的路径读取的是请求体。被筛选排除的调用会得到回应，但不会启动任何东西。

这个地址如何处理调用：

- 带有相同 Idempotency-Key 或投递 ID 的重复投递（GitHub、Gitea 和 GitLab 会给每次投递一个 ID）只运行一次。这些 ID 会被记住一周。
- 在任务上次运行后五秒内到来的调用会被拒绝，所以一连串的调用只会启动一次运行。
- 已暂停的任务会拒绝调用。一次调用最多可以携带 2 MB。
- 调用会立即得到回应，附带指向这次运行会话的链接。在地址后加上 `?wait=60`，就可以最多等 60 秒，让回应中带上智能体的回复（最多可设为 300）；到那时仍在进行的运行，会回应一个指向它的链接。

## 给 webhook 任务换一个新地址

如果地址泄露了，或者某个服务不应再调用它：任务的菜单（⋯）→ **新地址**，然后确认**新地址**（“当前地址将失效。请更新调用它的服务。”）。编辑 webhook 任务会保留它的地址；创建的副本会有自己的地址。

## 从示例开始

列表下方的[**从示例开始**](/settings?s=tasks&find=Start%20from%20an%20example)（“每个只需填一张简短的表单；之后随时可以修改。”）里有现成的任务。选择一个打开它的简短表单，填写好，在**执行者**下选择由谁运行，然后选择**创建任务**。**更多选项…** 则会打开完整的任务表单，所有内容都已填好。标有（可选）的字段可以留空；其他字段必须填写。

- [**晨间简报**](/settings?s=tasks&find=Morning%20brief)：每天早上告诉你天气、你关注的新闻，以及你这一天的安排。你填写时间（默认 07:30）、哪几天、看天气的城市和新闻的话题；连接了日历或邮件账户时，它还会加上今天的日程和紧急邮件。
- [**某个话题的新闻**](/settings?s=tasks&find=News%20on%20a%20topic)：在你选的时间和日子（默认每天 09:00），告诉你某个主题真正的新动态，并附上来源；没有新动态时就保持安静。
- [**价格监控**](/settings?s=tasks&find=Price%20watch)：每 60 分钟查看一次商品页面（如果你给了一段文字，比如“价格”，就只看它附近），在价格变化时，或在价格达到或低于你给的目标价时告诉你。
- [**网页变化提醒**](/settings?s=tasks&find=Page%20change%20alert)：每 30 分钟查看一次某个网页或其中某段文字附近的部分，告诉你变了什么、是否重要；无关紧要的变化不会打扰你。
- [**基于文件夹的每周报告**](/settings?s=tasks&find=Weekly%20report%20from%20a%20folder)：在每周的某一天（默认周五 16:00），总结某个文件夹或代码仓库在过去七天里的变化，以及哪些看起来还没完成，并为下周提三条建议。它不会修改任何文件。
- [**收件箱摘要**](/settings?s=tasks&find=Inbox%20digest)：自上次运行以来你收到的邮件，需要你处理的排在前面。它只读不写，并且需要连接一个邮件账户（见[已连接的应用、密钥和工具](/guide/connections)）。
- [**习惯打卡**](/settings?s=tasks&find=Habit%20check-in)：在你选的时间（默认每天 20:00）友好地问问你某个习惯的情况，并在任务的笔记里记下你连续坚持的天数。
- [**新版本发布**](/settings?s=tasks&find=New%20releases)：每 6 小时查看一次某个 GitHub 仓库（owner/name）的发布，总结有哪些新内容、哪些可能导致问题。
- [**网站在线检查**](/settings?s=tasks&find=Site%20up%20check)：每 10 分钟检查一次某个地址。网站宕机时，智能体会查出原因（DNS、证书、HTTP 状态、超时）；恢复时，它会用一句话告诉你。
- [**磁盘空间提醒**](/settings?s=tasks&find=Disk%20space%20alert)：每 30 分钟检查一次某个磁盘（默认是 `/`）。当占用超过某个水位（90%）时，智能体会找出是什么占了空间，并建议清理哪些，但不会删除任何东西。
- [**审查新的拉取请求**](/settings?s=tasks&find=Review%20new%20pull%20requests)：代码仓库文件夹中的一个 webhook 任务，GitHub 或 Gitea 会为每个新的拉取请求调用它（只有调用中写着 `opened` 时才运行）。智能体会审查这些更改并提出修改建议，但不会推送或合并。保存后，把它的地址复制到代码仓库的 webhook 设置中。
- [**文件夹中的新文件**](/settings?s=tasks&find=New%20files%20in%20a%20folder)：每 15 分钟查看一次某个文件夹（如果你指定了，就只看 `*.pdf` 这类文件），对每个新文件执行你在**然后**下面写的操作，或用一句话告诉你每个文件是什么。
- [**提醒**](/settings?s=tasks&find=Reminder)：在你选的日子的固定时间提醒你一下（默认工作日 09:00）。只提醒一次的，见[提醒](/guide/tasks#reminders)。

## 用试运行试试任务

表单底部的**试运行**会按表单当前的内容立即运行一次任务，而不保存它。它像真正的运行一样，在一个标题为“测试：<名称> · <时间>”的独立会话中运行；结束后，表单中会出现一条横栏，显示**试运行**和运行结果，以及**打开它的会话**。试运行永远不会计入让任务暂停的失败次数。对正在编辑的任务做试运行，会读取它的笔记，并在它的历史中显示为**试运行**；新任务还没有笔记。

## 立即运行任务

任务的菜单（⋯）→ **立即运行**会立刻启动一次运行，无论任务是开启还是暂停状态，并打开它的会话。

## 查看运行情况

任务的菜单（⋯）→ **历史**，或圆点旁边的**历史**，会打开任务的各次运行，最新的在前（显示最近 50 次；应用为每个任务保留 100 次）。每次运行显示：

- 运行结果：**正在运行**、**完成**、**部分完成**、**受阻**（智能体需要你：给予访问权限，或做个决定）、**失败**、**没有新内容**或**错误**（它没能启动，或它的这一轮因出错而停止）。
- 它什么时候开始、由什么启动（**按计划**、**Webhook**、**监测器**、**立即运行**、**重新运行**或**试运行**）、用了多长时间、花了多少钱。
- 智能体的一句话总结。选中较长的总结，可以阅读智能体最后一条回复的全文。
- **打开它的会话**，以及**用相同的输入再运行一次**：用那次运行得到的内容再运行一次任务，也就是同一个 webhook 调用，或监测器看到的同一个变化。

结果就是智能体在最后报告的内容。如果它什么都没报告，就由应用来判断：如果这一轮因出错而停止，就是**错误**；如果回复以 [SILENT] 开头，或者只是说没什么可报告的，就是**没有新内容**；否则就是**完成**。在运行的会话中，智能体的报告显示为一个步骤：“报告完成：…”。

## 任务在各次运行之间保留的笔记

历史下方是任务的记事本，**各次运行记下的笔记**：下一次运行应该知道的事，比如已经报告过什么、累计的数字，或上次停在了哪里。每次运行开始时都会读取它，智能体会往里添加内容或重写它。选择**编辑**可以自己修改，然后选择**保存**（或**取消**）。它最多容纳 8,000 个字符；超出时，最早的几行会被删除。

## 任务的通知

运行会用它会话的常规通知告诉你结果，通知以会话名称为标题，内容是智能体的一句话总结。它遵循你的通知设置（见[收件箱和通知](/guide/inbox)）。

- 没什么可报告的运行不会发送任何通知。
- 失败的运行，或以错误结束的运行，总会发送失败通知。
- 受阻的运行会发送一条需要你处理的通知，以“受阻：”开头。
- 没能启动的运行（它的文件夹不见了、它要发送到的会话已被删除）会发送一条失败通知：“无法启动：…”。
- 自己暂停的任务会发送一条通知说明原因。
- 发送到你某个对话中的运行，不会改变那个对话原本的通知。

智能体在工作时也可以给你发通知（它的 notify_user 工具），用于等不到运行结束的事；任何智能体和应用的步骤也都可以。

## 暂停、开启、编辑、复制或删除任务

- **暂停或开启**：任务那一行上的开关。已暂停的任务不会运行或查看，它的 webhook 也会拒绝调用。重新开启任务会清除它的失败计数和暂停原因。
- **自动暂停**：连续失败达到设定的次数后，任务会暂停，它那一行会说明原因（“连续 3 次运行失败后已暂停。最后一次：…”）。
- **编辑**：任务的菜单（⋯）→ **编辑**会打开标题为**编辑任务**的表单；改好后选择**保存**。
- **创建副本**：打开一个新任务表单，里面是名为“<名称>（副本）”的副本，供你修改并保存。
- **删除**：会先询问：“它会停止运行，历史记录也会删除。它启动的会话会保留。”

## 让智能体设置任务

在任何对话中，用你自己的话提出来：“周五 9 点提醒我给牙医打电话”“每周一早上总结一下上周的 issue”“这个页面有变化时告诉我”。智能体会提议这个任务，对话中会出现一张卡片展示它。在你回答之前，什么都不会保存。

卡片会问 **要安排这个任务吗？** 并附上任务名称和**等你处理**，还会显示：

- **时间**：用文字描述的日程，以及按你的时区列出的接下来几次运行。如果是监测器，会显示它监测什么、多久查看一次，以及地址或命令，并附上“确认后它会立即查看一次，之后只有内容有变化时才会唤醒智能体。”
- **执行内容**：提示词（较长时，**显示全部**可以展开）。
- **运行记录**：智能体、它的模型，以及在哪里运行：在某个文件夹中的新会话，或在这段对话中。

然后选择：

- **安排**：保存任务并开启它。
- **编辑…**：打开已填好所有内容的任务表单，可以先修改任何部分；它的按钮也写着**安排**。
- **暂不**：拒绝。

智能体会以消息的形式收到你的回答，包括你修改过的部分，所以你不必再告诉它。卡片会留在对话中，显示结果（“已安排”“下次运行：…”，以及指向**定时任务**的链接），在你的其他设备上也一样。

除非你另有要求，任务会使用这段对话的智能体、模型、权限和文件夹运行，每次运行的会话也会带着这段对话的设置开始：它的助手、记忆、花费上限、已连接的账户和空间。如果你要求把运行发到这里，每次运行都会发送到这段对话中，而不是开一个新会话。

智能体也可以修改、暂停、重新开启或删除你的任务，但总是先出示一张卡片：**修改这个任务？**（显示要改的部分，旧值划掉放在新值上方）、**暂停此任务？**、**要重新开启此任务吗？** 或 **删除这个任务？**，每张都有各自的“是”和“否”（**确认修改**或**保持原样**、**暂停**或**继续运行**、**开启**或**保持暂停**、**删除**或**保留**）。它们还可以列出你的任务，以及每个任务下次什么时候运行、上次运行得怎么样。

有一些限制让这一切保持可控：

- 一段对话中最多可以有五个等你回答的提议。
- 你有了 100 个任务后，智能体就不能再提议新任务了。
- 定时运行不能安排或修改任务；它会被要求改为在总结中提出建议。
- 智能体提议的监测器永远不会访问你自己电脑或网络上的地址。

## 把会话变成任务

当某个会话做了一件你希望再做一次的事：会话的菜单（⋯）→ **更多** → **把它设为自动化**。[辅助模型](/settings?s=models&find=Helper%20model)会读这段对话并起草一个任务：一个能自己再次运行的提示词（去掉这一次的一次性细节，并融入你做过的纠正），以及一个合适的触发条件。智能体、模型、思考强度、权限、文件夹和会话设置都来自这个会话；在工作树中的会话，会在它所来自的代码仓库中运行。

表单会以**从此会话新建自动化**为标题打开，并有一行说明它为什么选了那个触发条件。你可以修改任何内容、试运行一次，然后保存；任务随后就会出现在[设置 → 定时任务](/settings?s=tasks)中。没有你发过任何消息的会话无法变成任务。

## 提醒

提醒是一种任务，它的运行会在固定的时间告诉你某件事，以通知的形式，也会出现在它的会话中。设置提醒有三种方式：

- 让智能体来做：“明天 8 点提醒我倒垃圾”。它会提议一个只运行一次的任务，你在卡片上确认即可。
- 要在你选的日子里重复提醒，就用[**提醒**](/settings?s=tasks&find=Reminder)示例。
- 用**新建任务**新建一个任务，在**时间**下选择**一次**，再写一个提示词，比如“用一句友好的话提醒我给牙医打电话。”

## 在手机上

[设置 → 定时任务](/settings?s=tasks)在手机上的用法相同。任务表单、示例的表单和确认框（在**删除**或**新地址**之前）会以面板形式从屏幕底部弹出。**时间**下的选项和监测器的类型放不下时可以左右滑动，示例会排成一列。要在应用关闭时也能收到任务的消息，请为手机开启通知（见[收件箱和通知](/guide/inbox)）。

## 问问智能体

- “每个工作日 7:30，告诉我雅典的天气，以及从昨天到现在的 AI 新闻。”
- “周五 9 点提醒我给牙医打电话。”
- “盯着这个商品页面，价格跌破 99 欧元时告诉我。”
- “我的定时任务这周有哪些失败了？原因是什么？”
- “暂停我的晨间简报”，或“现在就运行每周报告。”
- “把这段对话做成一个每周一 9 点运行的任务。”
- “这个订阅源每有新文章，就用文章的链接运行我的‘阅读清单’应用。”
