# 实验

“实验”替你运行训练和评估作业。一个作业会一直等到你的某台机器上有一块空闲显存足够的 GPU 空出来（或者在计算集群的队列里排到它），然后自行运行，并留下一份记录：运行了什么（代码及其改动、设置、随机种子、环境）、运行得怎么样（日志和指标），以及出问题时值班智能体做了什么。勾选几次运行就能比较它们，或者生成一张带显著性检验的结果表，直接用在你的论文里。智能体也会用它：让任何智能体在空闲的 GPU 上训练或评估某个东西，它就会在这里启动一次运行，而不会让自己的对话一直被占着。

![系统 → 实验：按实验分组的运行，上方是队列和 GPU，列表旁边是一次运行的日志和指标](images/experiments.webp)

## 打开实验

点击侧边栏中的**系统**，再点**实验**标签页，或者前往[实验](/system/experiments)。[系统的概览](/system)上的**实验**卡片会列出正在进行的运行；点击其中一个即可打开。

顶部那一行说明队列在做什么（“2 个运行中 · 1 个在等待 GPU”）。旁边是这台电脑的 GPU，显示为几个小仪表：每块 GPU 用了多少显存；被你的某次运行占用时显示为强调色（点击它可以打开那次运行）。

下面是你的运行，按实验分组，最新运行所在的实验排在最前。每一行显示运行的名称、它的关键指标（它输出的前几个指标的最新值）、开始时间，下方是它的状态（一个圆点和几个字）以及它在哪里运行。状态的说法有：

- **排队中**：刚刚加入。**正在等待 GPU**、**等待中**或**在计算集群的队列中**：已经轮到它了，但它需要的资源还没空出来；把鼠标指向这一行可以看到原因。
- **正在启动**、**已运行 2 h 13 min**、**正在停止**。
- **完成**（以退出码 0 结束）、**失败**、**已停止**、**已提前停止**（参数扫描中的提前停止）、**进程不见了**（比如电脑重启过）。

列表上方右侧的**查找**会打开一个搜索框（按名称、实验或命令搜索），并可以按状态和运行位置筛选。有筛选生效时，旁边的 **× 已显示 N 个**可以清除它。

还没有运行时，页面会说明“实验”是什么，并提供**新建运行**，或者“对任意智能体说：‘用空闲的 GPU 训练这个，完成后告诉我’”。

## 启动一次运行

1. 点击右上角的[**新建运行**](/system/experiments?new=1)。
2. 输入**命令**，就像在它的文件夹里输入那样：`python train.py --lr 3e-4`。
3. 选择它运行所在的**文件夹**，以及**运行位置**：**这台电脑**、你的其他某台机器，或者某个计算集群（参见[运行位置](#where-runs-go)）。
4. 设置它需要的 **GPUs** 数量（0 表示不用 GPU）和**每块 GPU 的空闲显存（GB）**。留空时，它会等一块没人在用的 GPU。
5. 愿意的话，给它起个**名称**（否则用它的脚本名），并填写**实验**：同一个实验的运行会放在一起列出和比较。
6. 点击**开始**。

**更多选项**里是其余的设置：

- **设置**：每行一个 name=value，随运行一起保存，并在表格中比较。命令本身里的设置会被自动读出：`--name value`、`--name=value`，以及程序后面 `name=value` 形式的词（Hydra 就是这样接收它们的）。命令中的 `{name}` 会取这个设置的值。
- **随机种子**（命令中的 `{seed}` 会取它的值；命令中的 `--seed` 也会被读出）、**优先级**（高的先运行）和**时间上限（小时）**（超过这个时长就会被停止）。
- **指标文件**：除了输出的内容之外，运行还会以 JSON lines 格式把指标写进这个文件。**逐样本得分**：记录每个样本得分的文件（参见[为论文生成结果表](#results-tables-for-your-paper)）。
- **通知我**：**完成时**和**失败时**（除非你取消勾选，否则两项都开启），以及**某个指标越过设定值时**（“val_acc > 0.9”）。
- **值班智能体**：参见[值班智能体](#the-agent-on-call)。
- 在 SLURM 计算集群上：**处理器**、**分区**和**内存（GB）**。

新的运行会随即打开，你可以看着它启动。

## 队列如何选择

- 作业先按优先级排，再按先来后到。需要 GPU 的作业会用那些空闲显存不少于它要求、且没有被你的其他运行占用的 GPU，最空闲的优先。在空出足够多的 GPU 之前，它会一直等待，并说明原因：“正在等待 1 块有 20 GB 空闲显存的 GPU：目前空闲显存最多的是 GPU 2，有 12 GB；GPU 0 被你的其他运行占用”。排在它后面的较小作业，在它需要的资源空闲时，可能会先启动。
- 不用 GPU 的作业会立即启动，一次几个；具体几个在[运行位置](#where-runs-go)中设置（默认是电脑线程数的四分之一，在 1 到 4 之间）。
- 要求的 GPU 比电脑上的还多，或者在没有 NVIDIA GPU 的电脑上要求 GPU 的作业，会立即失败并说明原因。
- 一次运行只看得到分给它的 GPU（CUDA_VISIBLE_DEVICES）；不用 GPU 的运行一块也看不到。它还会得到 HYDOR_RUN（它的 id）、HYDOR_RUN_DIR（它的文件夹）和 HYDOR_SEED，并且 Python 会立即输出（PYTHONUNBUFFERED），所以日志会随着运行实时更新。
- 应用重启或更新时，运行会在 tmux 中（没有 tmux 的地方则在后台）继续。应用恢复后，会重新找到它们，读取它们在此期间输出的内容，并查看哪些已经结束；如果某次运行的进程不见了，它会被标为**进程不见了**。

## 一次运行会记录什么

- **它的代码**：启动时，它的文件夹所在 Git 仓库的提交和分支，以及是否有未提交的更改；如果有，就保存一份这些更改的补丁（不含二进制文件，最多 2 MB），以及有多少个文件没有被 Git 跟踪。
- **它的环境**：哪台电脑；命令所用的 Python，以及其中 PyTorch、Transformers、JAX、TensorFlow 和 NumPy 的版本（从软件包信息中读出，不会导入任何东西）；用 GPU 时，还有 CUDA 和驱动的版本以及 GPU 的型号。
- **它的设置和随机种子**、它的**日志**、它的**退出码**，以及它在应用数据中自己的文件夹（存放日志、补丁、退出码和指标）。
- **它的指标**，随着输出的增加从中读出：`key=value` 形式的键值对（`loss=0.42`，Lightning 的进度条就是这样输出的）、一行一个 JSON 对象（`{"step": 100, "loss": 0.42}`）、Python 输出的字典（Hugging Face 的 Trainer 就是这样输出的）、Keras 的“loss: 0.41 - accuracy: 0.87”，以及指标文件。步数取自 `step`、`global_step`、`iter` 或 `epoch`。对每个指标，它都保存最新值、最佳值（按名称判断：损失、错误率、困惑度之类越低越好，其他的越高越好），以及一串用来画图的数据。

## 运行的页面

点击一次运行。在宽屏上，它会在列表旁边打开；在窄屏上则取代列表打开，并有一个返回箭头。

- 顶部：它的名称；运行或等待期间有**停止**；**再运行一次**会打开已填好它的设置的“新建运行”，你可以先修改再启动；还有**更多**（⋯）：**复制命令**、**在“文件”中打开它的文件夹**，以及运行结束后的**删除记录**（它的记录、日志、补丁和指标都会删除；作业在它自己的文件夹里生成的文件会保留）。
- 它的状态及原因、在哪里运行，以及何时开始或结束。
- **指标**：每个指标随步数的变化，以及它的最新值和最佳值。指标超过四个时，**全部 N** 会把其余的也显示出来。
- **日志**：它输出的最后部分，最新的在底部。运行期间，**跟随最新**会让最新的内容一直留在视野里；向上滚动阅读时，它就不再跟随。
- **运行内容**：命令、文件夹、代码（提交、分支，以及用来查看补丁的**查看改动**）、它的设置、随机种子和环境、它是哪次运行的重新运行，以及启动它的会话。
- **发生了什么**：它的各个事件及其时间：何时等待、开始和结束，以及值班智能体看到了什么、做了什么，并附有**打开它的会话**。

**停止**会向运行的程序发送 Ctrl-C，如果 10 秒后它们还没结束，就强行停止。还在等待的运行会被立即移出队列。

## 值班智能体

在**更多选项** → **值班智能体**下：

- **关闭**（默认）：出的问题仍会记在运行的页面上。
- **通知我**：出问题时发一条通知。
- **让智能体排查**：一个智能体在运行的文件夹中开一个会话，带上发生了什么、日志的最后部分、运行的记录，以及**智能体可以做什么**，也就是你给它定的规则。它在这些规则范围内行动，然后用几行话告诉你发生了什么、它做了什么。运行的页面会链接到它的会话。

它会留意以下情况（除非你取消勾选其中一些，否则全部留意）：**NaN**（某个指标变成 NaN 或无穷大，或者日志里出现 NaN 损失）、**内存不足**（CUDA 的报错信息、`OutOfMemoryError`，或者程序以退出码 137 被杀掉）、**卡住**（30 分钟或你设定的分钟数内没有新的输出）、**崩溃**（退出码不是 0，或者进程死掉了）以及**发散**（损失连续五次读数都超过其最佳值的两倍）。

规则留空时是：“阅读日志和代码。如果修复方法明确且安全，就用 experiment_run 再运行一次（如果有检查点，就从最后一个检查点继续），改动尽量少。绝不要删除文件或检查点。然后用几句话告诉用户发生了什么、你做了什么。”负责排查的智能体就是启动这次运行的那个（如果是智能体启动的），否则是你上次在开始页上选的智能体和模型。同一次运行同一时间只有一个智能体在排查，而且一小时内最多出动三次：超过之后，改为通知你。

## 通知

运行完成或失败时（除非你取消勾选）、某个指标越过你设定的值时，以及值班智能体有消息时，你都会收到通知。点开通知会打开运行的页面。参数扫描只通知一次：在它的所有运行都结束时，并附上其中最好的一次。关于运行的通知，十分钟内最多八条；超过之后，会用一条通知告诉你还有多少条。

智能体以“结束时告诉我”（report）方式启动的运行，结束时还会给那个会话发一条消息，好让它的智能体接着往下做。

## 比较运行

勾选你想要的每次运行的复选框：底部会出现一个横条，提供**比较**、**生成表格**，以及用来全部取消勾选的 ×。**比较**会为每个指标画一张图，每次运行一条线，并把各次运行的设置并排列出，标出它们之间的不同之处。

每个实验的菜单（它名称旁边的 ⋯）里有**生成表格**（用它已结束的运行）、**比较最近的 6 次运行**和**全选**。

## 为论文生成结果表

**生成表格**（用勾选的运行，或者从实验的菜单里）会按你的选择显示表格：

- **列**：各个指标。点击一个指标可以添加或移除它，点它的箭头可以切换哪个方向更好。
- **行数据**：**按实验**，或者按各次运行之间不同的某个设置（**按 lr**）。
- **基线**：其他各行要与之比较检验的那一行（除非你另选，否则是第一行）。
- **与基线做显著性检验**：**帮我选**（运行保存了逐样本得分时，按样本配对；否则在各行的运行使用相同的种子时，按种子配对；再不然就用跨种子的 Welch t 检验）、**跨种子的 Welch t 检验**、**配对 t 检验（按种子或按样本）**、**按样本的配对 bootstrap 检验**或**不做检验**。
- **说明文字**。

每个单元格是该行各次运行（它的各个种子）的均值 ± 标准差；每列最好的值用粗体；剑号（†）标出在 p < 0.05 时优于基线的单元格，已针对检验多行做了 Holm 校正。把鼠标指向单元格可以看到它的 p 值。表格下方有一行说明做了哪种检验，以及哪些被排除了（还没结束的运行，或者没有这些指标的运行）。

然后：

- **复制 LaTeX**：一个使用 booktabs 横线的 `table`（在导言区加上 `\usepackage{booktabs}`），最好的值用 `\textbf`，带有 `$\pm$` 和剑号，还有一段说明单元格如何解读的标题。
- **复制 Markdown** 和**下载 CSV**（每个指标的均值、标准差、运行次数和 p 值）。
- **放进 LaTeX 文档**：选择[资料库](/library)中的一个 LaTeX 文档，再选其中的一个文件。表格会放在 `\end{document}` 之前（文件里没有它时放在末尾），或者替换掉之前在那里生成的表格，并保留你自己的标题和标签。它会像你自己的编辑一样，保存为文档的一个新版本。

你复制表格或把它放进文档时，表格会被保存下来。它的 LaTeX 在 tabular 的正上方带有一行 `% hydor:table <id>`：请保留这一行，这样提交前的检查才能根据运行重新算出这些数字，并指出哪些变了。页面顶部菜单（⋯）里的**结果表**会列出保存下来的表格：打开一个，可以再次复制或放置它，或者按它的运行现在的样子**重新计算**。

要按样本做配对检验（检索中的查询、翻译中的句子），运行需要写一个逐样本得分的文件，并在**逐样本得分**中给出它：JSON lines 格式，每行有一个 `id`（或 `qid`、`query`、`example`）和每个指标的一个数值，例如 `{"id": "q12", "ndcg@10": 0.53}`；也可以是 trec_eval -q 输出的那些行。和命令一样，它可以带 `{name}` 占位符；运行结束时，这个文件会随运行一起保存。

## 参数扫描

参数扫描是一条为每个设置都留了占位符的命令，对这些设置取值的每种组合各运行一次。点击顶部的**更多**（⋯），再点[**新建参数扫描**](/system/experiments?new=sweep)，或者在“新建运行”中选择**参数扫描**：

1. 输入命令，在每个设置的值应该出现的地方写 `{name}`：`python train.py --lr {lr} --batch {batch}`。
2. 在**设置及其取值**下，给每个设置填上它的取值：`lr` 和 `0.001, 0.0003, 0.0001`。要再加一个设置，点**添加设置**。
3. 选择**所有组合**，或者从中**随机抽样**（**最多** N 次运行）。
4. 要停掉那些不会胜出的运行，就在**提前停止运行的依据**中设一个指标以及哪个方向更好：一旦已有另外三次运行到达某一步，在这一步上该指标比其他运行的中位数差的运行就会被停止（**已提前停止**）。
5. 给它的**实验**起个名字，然后点击**开始 N 次运行**。

它的运行会列在它的实验下，名称旁边有**参数扫描**。点它会打开这次参数扫描：各次运行进行得如何，最好的一次运行（按你选的指标，取每次运行的最佳值或最新值），以及每个设置与该指标的关系图，每次运行一个点（取值跨度很大时用对数刻度，比如学习率），最好的那个点会圈出来。在那里可以**生成表格**或**比较最好的 6 次运行**。

## 运行位置

顶部的**更多**（⋯）→ [**运行位置**](/system/experiments?places=1)：

- **这台电脑**：它的 GPU，以及**不使用 GPU 的作业：最多 N 个同时运行**。
- **其他机器**：[设置 → 机器](/settings?s=machines)中已连接的那些。发到某台机器的运行由那台机器保存和照看：它的值班智能体和通知都来自那台机器（这些通知会像那台机器的所有通知一样来到你这里），这个页面会跟进它。这里的列表也会显示每台已连接机器上的运行，并标明它们在哪里运行；打开一个，就是在那台机器上读取它，停止也是在那里停止它。
- **计算集群**：你通过 SSH 访问的计算机，那边不需要安装任何东西。

### 添加计算集群

点击[**添加计算集群**](/system/experiments?cluster=new)，然后填写：

- **名称**和 **SSH 主机**：就像你在 `ssh` 后面输入的那样，可以是你 `~/.ssh/config` 里的一个条目，或者 `me@login.cluster.edu`。应用的服务器用它自己的 SSH 密钥连接，从不询问密码，所以那边需要有一把不用密码就能用的密钥（`ssh-copy-id`），并且要已知计算集群的主机密钥（在终端里用 `ssh` 连接一次即可）。
- **SLURM** 或**普通 SSH**。
- **那边存放运行日志的文件夹**（默认 `~/hydor-runs`），用 SLURM 时还有它的**分区**和**账户**。
- **准备命令**，在那边每个作业运行之前执行：`module load cuda/12.1`、`source ~/venvs/ml/bin/activate`。

**查看**会先尝试 `ssh host true`，然后对 SLURM 运行 `sinfo`（它会列出分区），对普通 SSH 则检查 `nvidia-smi` 和 tmux。**添加**会保存它；在列表中，每个计算集群都有**查看**和**移除**。

发往计算集群的作业在那边的某个文件夹里运行（代码必须已经在那里：先把它克隆过去）。在 **SLURM** 上，应用会写一个批处理脚本，写明作业的需求（GPU 写作 `--gres=gpu:N`、处理器、内存、以 `--time` 表示的时长、分区和账户）、你的准备命令和命令本身，然后用 sbatch 提交。作业等待期间，它的状态会说明原因，既有 SLURM 自己的说法，也有通俗的说法（“其他作业优先（Priority）”）。应用用 squeue 和 sacct 跟进它，把它的日志随着增长复制到这里，**停止**会用 scancel 取消它。在**普通 SSH** 上，GPU 的选择方式和这里一样，运行会放进那边的 tmux 里。每个计算集群只保持一个打开的 SSH 连接，所以跟进运行的开销很小。

## 在手机上

列表占满屏幕，每次运行的指标单独占一行。运行会取代列表打开，并有一个返回箭头；它的日志按屏幕宽度自动换行，**跟随最新**的用法和在电脑上一样。“新建运行”、“比较”和表格都从屏幕底部弹出。

## 问问智能体

- “用空闲的 GPU 训练这个，完成后告诉我。”
- “在 Unity 计算集群上用 2 块 GPU 运行 eval.py，时长 4 小时。”
- “对学习率 1e-4、3e-4 和 1e-3 做参数扫描，种子用 1、2 和 3，并提前停掉表现差的运行。”
