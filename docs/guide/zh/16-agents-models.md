# 智能体、账户和模型

Hydor 可以运行多种 AI 智能体：Claude Code、Codex、Custom（应用自带的智能体，可搭配任意模型），以及其他支持 ACP 的智能体，例如 Gemini CLI、OpenCode、Qwen Code、Goose、Grok Build 或 Antigravity CLI（Google 为你的 Google AI 套餐提供的智能体）。本主题介绍它们有何不同、它们的程序如何安装并保持最新、如何登录（也可以登录多个账户），以及 Custom 的模型从哪里来：OpenRouter、Ollama、在这台电脑上运行的 Hugging Face 模型，或任何兼容 OpenAI 的端点。

![在开始页面选择智能体：Claude Code、Codex 或 Custom](images/agents-models.webp)

## 我该用哪个智能体？

智能体是在会话中干活的程序：它读取你的消息，使用工具（文件、命令、网络），然后给出回答。模型是它背后的 AI。这里的每个智能体都能从应用获得同样的帮助（网页搜索、浏览器、记忆、技能、你的连接），区别在于它们的模型来自哪里。

- **Claude Code**（Anthropic）。使用你的 Claude 套餐运行，或向 Anthropic API 账户计费。它的模型是 Anthropic 的（Opus、Sonnet、Haiku）。它有自己的用量上限，[用量页面](/usage)会显示。
- **Codex**（OpenAI）。使用你的 ChatGPT 套餐运行。它的模型是 OpenAI 的。它同样有用量上限，在用量页面显示。Codex 随应用提供。
- **Custom**，应用自带的智能体。它可以运行你的 Claude 和 ChatGPT 套餐中的模型（通过 Claude Code 和 Codex 的登录），也可以运行你在[设置 → 智能体 → 模型](/settings?s=models)中添加的任何模型：通过 OpenRouter 的模型、在这台电脑上的模型（使用 Ollama 或 vLLM），或任何兼容 OpenAI 的端点。开放模型、更便宜的模型，或永远不会离开你电脑的模型，都可以用它。参见 [Custom，应用自带的智能体](/guide/custom)。
- **支持 ACP 的智能体**：Gemini CLI、OpenCode、Qwen Code、Goose、Kimi CLI、Auggie、Grok Build（xAI 的编程智能体，搭配 Grok 模型）、Antigravity CLI（Google 的编程智能体，搭配你的 Google AI 套餐）等，或你自己的命令。ACP（Agent Client Protocol）是应用与智能体程序通信的一种通用方式。每个智能体登录一次，并使用各自的模型：大多数在它们自己的程序中登录，Grok Build 和 Antigravity CLI 则在[设置 → 智能体 → 账户](/settings?s=accounts)下登录。自 2026 年 6 月 18 日起，Gemini CLI 不再为 Google AI Pro 和 Ultra（或面向个人的 Gemini Code Assist）提供服务：这些套餐对应的 Google 终端智能体是 Antigravity CLI（参见 [Antigravity CLI](#antigravity-cli)）。Gemini CLI 仍可用于 Gemini API 密钥，或 Gemini Code Assist Standard 或 Enterprise 许可。

各智能体在应用中能做什么：

- 目标（应用让智能体一轮接一轮地持续工作，直到你认可的检查项成立；参见[目标](/guide/goals)）：所有智能体都支持，包括 Claude Code、Codex、Custom 和其他 ACP 智能体。在 Claude Code 或 Codex 聊天中输入的 `/goal` 是该程序自己的、更简单的目标。分叉（从较早的一条回复处复制出的会话）：Claude Code、Codex 和 Custom 支持，其他 ACP 智能体不支持。
- **转到…**（把对话交给另一个智能体）：从 Claude Code 或 Codex 出发，可转到另一个或 Custom。
- 思考强度（模型思考的投入程度）：Claude Code、Codex、Grok Build 和 Antigravity CLI，以及其模型提供该选项的任何其他 ACP 智能体。
- 多个账户，以及在达到上限时切换账户：Claude Code、Codex 和 Grok Build。用量页面显示的套餐用量上限：这三个，外加 Antigravity CLI 的一张卡片，说明在哪里查看它的用量（它只有一个登录，且只在你自己启动的会话中可用：参见 [Antigravity CLI](#antigravity-cli)）。
- 上限重置和达到上限时的 API 额度：仅限 Claude Code 和 Codex。

## 为新会话选择智能体和模型

在开始页面（`/`），消息框下方的一行说明由谁来干活。

1. 点击**运行于**。列表显示 **Claude Code**（“Anthropic · Claude 套餐或 API 密钥”）、**Codex**（“OpenAI · ChatGPT 套餐或 API 密钥”）、**Custom**（“任意模型：OpenRouter、Ollama、vLLM”），以及你在设置 → 更多智能体中添加的每个智能体（“ACP 智能体 · ”加上它的命令）。底部的 **Custom 的模型**会打开设置 → 模型，**添加或管理智能体**会打开设置 → 更多智能体。
2. 点击**模型**并选择一个。位于顶部、起初就被选中的**自动**，让档位来做选择：最佳，如果问题证明太难，则用最大值（参见[档位：为每类工作配一个模型](#tiers-a-model-for-each-kind-of-job)）。它下方的列表只显示该智能体自己的模型。智能体的默认模型标有“默认”。较旧版本的模型收在类似“2 个较旧的模型”的一行后面；点击它即可查看。当模型超过八个时，顶部会出现**搜索模型**框：输入几个字母并按回车，即可选中第一个匹配项。如果智能体没有按应用的要求启动并提供它的模型，菜单会说明这一点，并附上智能体自己给出的原因，点击**重试**会再问一次。
3. 在**选项**下，你会找到**思考强度**（适用于有此功能的智能体和模型：默认、低、中、高等；Grok Build 的情况参见 [Grok Build 的思考强度](#effort-for-grok-build)）和**权限**（智能体无需询问你就可以做的事）。在消息框中按 Shift+Tab 也可以切换权限。

开始页面会记住你在每个工作位置（每个项目、每个文件夹和**新建任务文件夹**）所做的选择，并在所有设备上同步：每个程序的模型、思考强度和权限都会像你离开时那样恢复（参见[开始页面会记住什么](/guide/sessions#what-the-start-page-remembers)）。

除 Custom 之外的 ACP 智能体，只有在它的第一个会话之后才会显示它的**模型**和**权限**选项：它们列出智能体上次运行时提供的内容。Grok Build 是例外：添加后，它的模型以及每个模型支持的思考强度就会立即显示，因为应用会向 Grok 询问这些信息。Antigravity CLI 的模型和思考强度会在它的第一个会话之后显示，即会话打开时应用了解到它们的时候。

开启**选项** → **保密**后，**运行于**为 **Custom**，**模型**只列出这台电脑或你的私人网络上的模型，其中最好的排在最前面并被选中：参见[让会话保密](/guide/sessions#keep-a-session-confidential)。

在手机上，这些菜单都会从屏幕底部以面板的形式打开。

## 在会话中途切换模型

在会话中，模型、思考强度和权限位于消息框下方。它们是一个小标签，内容类似“Opus 5.5 · 最高 · 计划”：点击它即可设置**模型**、**思考强度**和**权限**。

选择另一个模型后，会话就会用它继续：

- Claude Code 立即切换。
- Codex 从下一轮起使用新模型。
- Custom 从下一步起使用它，即使是在一轮的中途。
- 其他 ACP 智能体如果提供模型可选，也会切换。

会话的**思考强度**同样如此。选好之后，正在运行的智能体从下一轮起使用它。如果你切换到的模型不支持你原来的思考强度，选择器会显示该模型的默认值，模型也会按它运行。

模型菜单只列出该会话自己智能体的模型；保密会话则只列出这台电脑或你的私人网络上的模型。要把对话转给另一个智能体，请使用会话的菜单（⋯）→ **转到 Codex**、**转到 Claude Code** 或 **转到 Custom 智能体**（适用于 Claude Code 和 Codex 的会话；Custom 在有了模型之后才会出现）。你的下一条消息会在同一文件夹中启动该智能体的一个新会话，并带上到目前为止的对话。已停止的会话会在它上次使用的模型上继续，除非你在发送前选了另一个。

## Grok Build 的思考强度

Grok 的模型支持推理强度，和 Claude Code、Codex 提供的选择一样：

- Grok 4.6（以及提供同样选项的更新模型）：**xhigh**、**high**、**medium** 或 **low**。默认是 **High**。
- Grok 4.5：**high**、**medium** 或 **low**。

在开始页面的**运行于**下选择 **Grok Build**，然后选择**选项** → **思考强度**：它会列出你所选模型的思考强度，以及**默认**。Grok Build 一添加就会显示，甚至在它的第一个会话之前。正在运行的 Grok Build 会话在它自己的**思考强度**选择器（消息框下方的小标签）中更改思考强度，[应用](/guide/apps)运行时也可以设置。当你把会话切换到不支持你原来思考强度的模型时（例如 Grok 4.5 上的 xhigh），选择器会显示该模型的默认值，模型也会按它运行。

这不只适用于 Grok：任何其他支持 ACP 且模型提供思考强度的智能体，都会得到同样的**思考强度**选择。

## 档位：为每类工作配一个模型

智能体按档位而不是按名称来选择模型：**快速**用于结果可以检查的、小而非常明确的工作，**标准**用于中等规模的明确任务，**最佳**用于会话的主智能体，它负责规划、带领子智能体并检查它们的工作，**最大值**用于最难的问题。一项工作的大部分是明确的部分，较便宜的模型就能做好，所以这样一个会话花费更少，结果也不会变差：房间里最强的模型仍然负责规划工作并检查它。

在开始页面上，**模型**默认停在**自动**：会话从最佳开始（同样的**自动**也用于启动[定时任务](/guide/tasks#model-effort-permissions-and-other-options)的会话，[应用](/guide/apps)也可以用档位而不是按名称指定的模型来思考）。它的主智能体会把明确的部分交给标准和快速档的子智能体，并且在问题证明比最佳档应付得了的更难时（修复失败了两次、找不到原因、一个证明），可能把自己切换到最大值；对话中会有一行说明这一点及原因。请求不会仅凭措辞就被送到最大值：看上去很难的事情，大多数最佳档就能解决，而且花费更少。改为按名称选择一个模型，会话就用那个模型思考；它的子智能体仍然使用档位。你的某个智能体可以改用某一个档位来思考（参见[智能体用什么来思考：档位](/guide/agents#what-an-agent-thinks-with-tiers)）。

[设置 → 智能体 → 模型 → 档位](/settings?s=models&find=Tiers)说明每个档位对每个程序意味着什么：每个档位一行，分组标题旁有一个开关用来选择程序（**Claude Code**、**Codex** 或 **Custom**），每一行中有一个模型，Claude Code 和 Codex 还有一个思考强度。点击档位的 (i) 可以了解更多。起初，对 Claude Code 来说，快速是 Haiku，标准是 Sonnet，最佳是 Opus，最大值是最新的 Fable；对 Codex 来说，快速是 Luna，标准是 Terra，最佳是 Sol，最大值是 Astra（在缺少其中某个的套餐上，则用它提供的最接近的模型，如果两个档位共用一个模型，较高的档位会用更高的思考强度）；Custom 的档位会自动填写：你不去动的档位，会从 Custom 拥有的模型中取同类型的最新模型。来自你的 Claude 套餐的，快速是 Haiku，标准是 Sonnet，最佳是 Opus，最大值是最新的 Fable；否则来自你的 ChatGPT 套餐，即 Luna、Terra、Sol 和 Astra；再否则来自你添加的、不在这台电脑上（OpenRouter、某个端点）且名称属于这些系列之一的模型。这台电脑上的模型绝不会被自动选中，因为它的名称看不出强弱，小模型（Haiku、Luna）也绝不会成为最佳：如果只有小模型或本地模型，档位会一直为空，直到你来选择，而 Custom 会话则保留它所选的模型。一旦最佳指定了模型，开始页面就会为 Custom 提供**自动**，它的会话会带领子智能体（Hydor 子智能体，因为 Custom 没有自己的 Agent 工具）。在 **Custom** 标签页上，你可以为某个档位指定它的任何模型（参见[Custom 的模型从哪里来](#where-customs-models-come-from)）。你不去动的档位，会跟随其程序中同类型的最新模型。标题旁 **⋯** 菜单中的**恢复默认**会把它们恢复，包括 Custom 的选择。

档位下方**会话中的档位**分组里有两个开关，说明会话如何使用档位：

- **主智能体带领子智能体**（起初开启）：会话的主智能体被告知要规划、把明确的部分交给较便宜档位的子智能体并检查它们的工作，而未指定档位而请求的子智能体会得到标准档。关闭后，智能体除非自己另行选择，否则独自工作，开始页面和任务表单中也没有自动。
- **难题用最高档位**（起初开启）：处于自动的主智能体，在问题证明对最佳来说太难时，可以把自己切换到最大值。关闭后，处于自动的会话会一直停在最佳。

## 智能体程序会自行安装和更新

Claude Code、Codex、Gemini CLI、Grok Build 和其他智能体都是这台电脑上的程序。你不必手动安装。例外是 Antigravity CLI：Google 要求用户自己安装它，所以应用不会代装（参见 [Antigravity CLI](#antigravity-cli)）。它会自行更新。

打开[设置 → 智能体 → 账户](/settings?s=accounts&find=Agent%20programs)，查看**智能体程序**分组。它列出 Claude Code、Codex、Gemini CLI、OpenCode、Qwen Code、Auggie、Grok Build（添加之后）以及需要 ACP 适配器的智能体，每一项都附有会话所运行的版本及其来源：

- **你自己安装的**：你自己安装的（对 Grok Build，也可以用 xAI 自己的安装程序，它会把程序放在 `~/.grok/bin`）。
- **由应用安装**：应用把它安装在自己的文件夹中。
- **随应用提供**：Codex 随应用一起提供。
- **这里没有：首次使用时会自行安装**：缺失。点击**安装**即可立即获取。

有更新版本时，该行还会写明“… 已发布”。如果你自己也有一个 Codex，Codex 的那一行还会加上“你在终端中的：…”：会话运行的是应用的那个，终端运行的是你的那个。

缺失的程序也会在第一次需要时自行安装：Claude Code 在你登录它或启动 Claude Code 会话时，ACP 智能体在你于设置 → 智能体 → 更多智能体中添加它或用它启动会话时。应用用 npm 把它们安装到自己的文件夹中，所以你不需要管理员权限。

Goose、Kimi CLI、Antigravity CLI 和其他一些智能体不在这个列表中：请自行安装（设置 → 智能体 → 更多智能体会显示获取地址）。需要 ACP 适配器的智能体分两部分安装，即适配器和智能体本身；列表中两者合用一行。

## 保持智能体程序为最新版本

开启 [**自动更新**](/settings?s=accounts&find=Update%20automatically)（它是 **智能体程序** 的最后一行，默认开启，除非你把它关掉）后，应用会每天一次把每个智能体程序更新到最新版本。第一次运行大约在应用启动十分钟后。

- 应用自行安装的副本通过 npm 在它自己的文件夹中更新。如果有比应用自带版本更新的副本，Codex 会切换到该副本。
- 你自己安装的程序用它们各自的更新器更新：Claude Code 用 `claude update`，Codex 用 `codex update`（即你的终端所运行的那个），OpenCode 用 `opencode upgrade`，Grok Build 用 `grok update`。
- 如果 Gemini CLI、Qwen Code、Auggie、Grok Build，或带有 ACP 适配器的智能体是你用 `npm install -g` 安装的，那么在你的用户有权写入该文件夹时，会通过 npm 更新。以其他方式安装的程序，则留给你按照当初的安装方式自行更新。
- Claude Code 遵循它自己的发布渠道：当它的设置中写有 `"autoUpdatesChannel": "stable"` 时用稳定版，否则用最新版。
- 如果你用 `DISABLE_AUTOUPDATER=1` 关闭了 Claude Code 自带的更新（Docker 镜像就是如此），应用也不会自动更新你的 Claude Code。**立即更新** 仍然可以更新它。

只有当新版本能按会话使用它的方式正常工作时，应用才会保留它。Claude Code 必须在会话启动时作出响应并列出它的模型，Codex 必须启动它的应用服务器并列出它的模型，其他程序则必须能启动并报告自己的版本。这些检查都不需要登录，也不会消耗你的任何套餐额度。每个程序有一分钟的响应时间，并且只计算电脑处于唤醒状态的时间，所以 Mac 在检查过程中进入睡眠，不会把这一分钟用掉。如果某个程序第一次响应很慢（Mac 在新程序第一次运行前会先对它做检查），会再给它两分钟重新启动，如果那时仍然没有响应，才算失败。失败的版本会被撤销：

- 应用自行安装的副本，或你自己的、由应用通过 npm 更新的副本，会回到之前的版本。
- 对于你自己安装的 Claude Code，会话会继续运行之前的版本，该版本由 Claude Code 的安装程序保存在新版本旁边。终端中的 `claude` 命令仍然是新版本。该行会显示“… did not work here”。
- 失败的版本不会自动再次尝试，但下一个版本会被尝试，而 **立即更新** 会再试一次该版本。

在那一行下面会显示应用上次检查的时间，例如“Up to date · checked 2h ago”，旁边有 **立即检查** 可以再次检查。当有更新的版本发布时，它会这样提示，并提供 **立即更新** 一次性安装全部更新（没有针对单个程序的按钮）；更新过程中它会显示正在更新哪个程序。下面的几行会说明上次更新带来了什么变化，例如“Claude Code 2.1.308 → 2.1.316”，或者某个版本为什么无法安装。

正在运行的会话会继续使用它们启动时的版本；新建会话使用新版本。关闭 **自动更新** 后，应用仍然每天检查一次并显示有哪些新版本，但在你点击 **立即更新** 之前不会安装任何东西。

## 登录 Claude Code、Codex 和 Grok Build

Claude Code 和 Codex 需要先登录才能工作，Grok Build 在你添加之后也一样（参见[添加 Gemini CLI、OpenCode 和其他 ACP 智能体](#add-gemini-cli-opencode-and-other-acp-agents)）。打开[设置 → 智能体 → 账户](/settings?s=accounts)（在手机上，设置是一个分区列表：在“智能体”下点按 **账户**；顶部的标题可以带你返回）。**账户** 分组（它的 (i) 说明这里是你的会话所使用的 Claude Code、Codex 和 Grok Build 登录，你可以再添加一个订阅，比如工作和个人各一个，并在开始会话时选择其中一个）会先列出每个智能体自己的登录，然后是你为它添加的账户。Grok Build 自己的登录在这里也有一行，即 **Grok Build**，添加之后才会显示。每一行会显示一个绿色对勾，以及邮箱、套餐和登录方式；或者显示一个红色叉号，以及“未登录”或出错的原因。

登录步骤：

1. 点击智能体旁边的 **登录**。
2. 选择登录方式：
   - Claude Code：**Claude 订阅**（你的 Claude 套餐）或 **Console（API 计费）**（Anthropic API 账户）。
   - Codex：**设备码** 或 **浏览器跳转**。
   - Grok Build：无需选择，它总是通过验证码登录。
3. 点击 **获取登录链接**。
4. 按对话框显示的步骤操作：
   - Claude Code：打开链接（**打开登录页面**），在浏览器中批准访问，然后把页面显示的代码粘贴到 **粘贴页面上的代码** 中，再点击 **完成登录**。
   - Codex，设备码：在任意设备上打开链接，登录 ChatGPT，并输入对话框中显示的一次性代码。完成后，对话框会自动察觉。
   - Codex，浏览器跳转：登录后，你的浏览器会尝试打开一个“localhost”页面，但会失败。复制该页面的地址，粘贴到 **粘贴浏览器中的 localhost 地址** 中，然后点击 **完成登录**。
   - Grok Build：你会得到一个链接和一个一次性验证码。在任意设备上打开链接，用你的 Grok 账户登录并确认验证码（**2. 确认此验证码**）。不需要粘贴任何内容：完成后，对话框会自动察觉。

成功后你会看到“Claude Code 已登录”（或 Codex、Grok Build）。如果失败，对话框会说明原因；点击 **重试**。

Antigravity CLI 是 Google 为你的 Google AI 套餐提供的智能体，添加之后，同一分组中会有它自己的一行 **Antigravity CLI**。它的登录方式略有不同：参见 [Antigravity CLI](#antigravity-cli)。

登录之后，按钮会变为 **切换账户**：它会为另一个账户启动同样的登录流程（对 Grok Build 来说是一个新的验证码）。**退出登录** 在该行的 **⋯** 菜单中：确认之后，它会在这台电脑上让该程序退出登录，所有使用它的终端和编辑器都会受影响。

如果你在 Grok Build 未登录时启动 Grok Build 会话，会话会停止，并提示“Grok Build is not signed in: sign in with your Grok account in Settings → Agents → Accounts, then try again.”请在那里登录，然后重新发送你的消息。放在智能体环境中的 `XAI_API_KEY` 里的 xAI API 密钥，也可以代替订阅用于 Grok Build。

欢迎导览（从侧栏上的 **帮助** 进入）会询问你想使用哪些智能体和模型，并带你完成这些登录。

## 添加第二个账户（工作和个人）

你可以登录多个 Claude Code、Codex 或 Grok Build 账户，例如一个工作套餐和一个个人套餐，并为每个会话选择其中一个。

1. 打开[设置 → 智能体 → 账户](/settings?s=accounts&find=Accounts)。
2. 点击 **账户** 分组标题旁边的 **添加账户**。
3. 选择 **Claude Code**、**Codex** 或 **Grok Build**（Grok Build 在设置好之后才会出现；Antigravity CLI 永远不会出现：它只有一个登录，参见 [Antigravity CLI](#antigravity-cli)），输入一个名称（最多 40 个字符，例如“工作”或“个人”），然后点击 **添加并登录**。
4. 会为新账户打开登录对话框。按上面所述登录。

每个添加的账户各自登录，并保留自己的会话历史。你的设置、指令、技能和插件与该智能体的主登录共享，所以修改会对两者都生效。对于 Claude Code，你在主登录下信任的文件夹，对添加的账户也同样受信任，因此该文件夹自己的权限规则会在它的会话中生效。同一个智能体的两个账户不能同名。

添加的 Grok Build 账户有它自己的文件夹，里面存放它的登录信息和 Grok 自己的会话历史。它与你的主登录共享 Grok CLI 自己的设置：配置、规则（`AGENTS.md`）、技能、插件和 MCP 登录。

每个添加的账户在该智能体自己的登录下面各有一行，带有 **登录** 或 **切换账户**；它的 **⋯** 菜单中有 **退出登录**、**重命名** 和 **移除**：

- **重命名** 会要求你输入新名称。
- **退出登录** 会让以该账户运行的会话无法工作，直到它重新登录。
- **移除** 会把该账户从应用中删除。它的会话会从列表中消失，但它们的历史仍保留在磁盘上，除非你同时勾选 **同时删除它的登录信息和会话历史**。当有会话正以该账户运行时，你不能移除它：请先停止这些会话。

[用量页面](/usage)会为每个添加的 Claude Code、Codex 或 Grok Build 账户显示一张卡片，上面是它自己的限额。

## 选择会话以哪个账户运行

当你选择的智能体有添加的账户时（对 Grok Build 来说，是在你添加了一个之后），起始页的 **选项** 中会出现一行 **账户**。点击它：

- **你的登录** 是该程序自己的账户（即 **账户** 中该智能体的第一个；对 Grok Build 来说，是“The Grok Build CLI's own account”）。
- 每个添加的账户都按名称列出。
- **管理账户** 会打开“设置 → 智能体 → 账户”。

起始页会记住你为该智能体所做的选择，在所有位置都一样。以添加的账户运行的会话，会在会话顶部显示该账户的名称，并带有一个人形图标。如果该账户达到用量限额，消息框上方的限额提示就是针对该账户的。账户在会话启动时确定。只有 **达到限额时切换账户**（见下文）才会让它自动改变。

要自己把会话移到另一个账户，请点击会话自己的 **账户** 标签并选择一个。这对 Claude Code、Codex 和 Grok Build 会话都有效，并从你的下一条消息开始生效。Grok Build 会话的 Grok 历史会随之移动；如果 Grok 无法在另一个账户下重新打开它，它会在那里重新开始，并附有一条说明。

## 用上你所有的账户：达到限额时切换

如果同一个智能体有两个或更多账户，应用可以把它们都用上：当其中一个用完用量时，你的工作会换到另一个账户继续。打开[设置 → 智能体 → 账户](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit)，找到 **账户** 下 **达到用量限额时** 分组中的 **达到限额时切换账户**，只要你添加了任何账户（包括 Grok Build 的），它就会显示（它的 (i) 说明：当会话的账户用完用量时，会话会移到该智能体另一个还有用量的账户并继续，而新会话会跳过已达限额的账户）。它一开始就是开启的（如果你更想自己选择账户，可以在那里关掉），并且在没有打开任何浏览器时也能工作。

- 当某一轮因为会话的账户达到用量限额而停止时，应用会从同一智能体已登录且仍有用量的账户中选出另一个（用量最少的那个），把会话连同全部历史一起移过去，并发送“… reached its usage limit, so this session now runs on …. Continue where you left off.”屏幕底部的一条简短提示会说明移到了哪个账户。
- Claude Code 会话在后台运行的子智能体也会继续。限额触发时仍在工作的那些，会在下一步停止并保留它们的工作，应用会等待它们（最多两分钟），然后再移动会话。随后的消息会点出它们的名字，智能体会让每一个从停下的地方继续。如果只有子智能体达到了限额（比如仅针对它们的模型），会话会在这一轮结束且没有任何子智能体仍在工作时移动。
- Hydor 子智能体（智能体为完成一部分工作而启动的会话）本身就是独立的会话，所以当限额使它们的某一轮停止时，每一个都会自行移动。启动它的智能体会得知它在继续，而不是失败了，并在它完成时收到它的回复。
- 你的主登录和每个添加的账户都算在内。Claude Code 账户由 Claude Code 账户接替，Codex 由 Codex 接替，Grok Build 由 Grok Build 接替。Antigravity CLI 没有其他账户可以移过去，所以这一功能从不适用于它（参见 [Antigravity CLI](#antigravity-cli)）。
- Grok Build 账户在达到每周限额、额度限额或按量付费花费上限时，即为达到限额。此时会话会移到另一个已登录且仍有用量的 Grok 账户（用量最少的那个），并以“… reached its usage limit, so this session now runs on …”继续。短暂的速率限制（一阵密集的请求）不会触发移动：它会自行过去。消息框上方的限额提示对 Grok 会话同样会显示。
- 由应用驱动的目标属于应用，所以它会在新账户上继续进行。在 Codex 中以 `/goal` 输入的目标会随会话一起移动并继续。
- 算数的是会话所用模型剩余的用量。只针对某一个模型的限额（例如 Fable 的每周限额）只会挡住使用该模型的会话：使用 Sonnet 或 Opus 的会话仍会转到只用完了 Fable 份额的账户。套餐不包含会话所用模型的账户会被跳过（Claude Code 会提示该模型“requires usage credits”，比如 Pro 套餐下的 Fable）：会话会转到套餐包含该模型的账户，或者等待其中最先重置的账户，提示会写“… 的套餐不包含 …”。
- 当所有账户都达到限额时，什么也不会移动（除非下面所说的 **达到限额时使用 API 额度** 已开启，对 Claude Code 而言）。开启 **用量限制解除后继续** 后，会话会在第一个账户重置时，在该账户上继续。这对 Grok Build 会话同样适用。更多内容见[用量、限额和费用](/guide/usage#continue-sessions-automatically-after-a-limit)。
- 如果会话无法转移，屏幕底部的一条简短提示会说明原因，会话会留在原来的账户上：开启 **用量限制解除后继续** 后，它会在该账户重置时继续。之前的转移留在另一个账户中的会话历史副本不会阻止转移：转移的历史会替换这个副本，副本中不同的部分会移到“文件”页面的**废纸篓**。
- 在已达限额的账户上新启动的会话，会改为在仍有用量的账户上启动；而你向其账户已达限额的会话发送消息时，会先移动会话，这样你的消息不会被拒之门外。随你的消息一起，智能体会得知它现在运行在一个仍有用量的账户上，所以不会等待旧账户的重置，也会知道它的哪些子智能体可以继续。
- 在 VS Code 或终端中打开的会话会留在它们的账户上。
- 限额重置（Codex 重置额度、Claude 重置授予）和 API 额度仍然只适用于 Claude Code 和 Codex。
- 应用自己向 Claude Code 或 Codex 提出的快速提问（设为 **自动** 的辅助模型、应用的快速模型步骤、拉取请求描述、命令建议），在其中一个达到限额或已退出登录时，会以同样的方式交给你的下一个已登录账户。当 Claude Code 和 Codex 都无法回答时，你的某个 Custom 模型会接手（参见[账户退出登录时](#when-an-account-is-signed-out)）。

## 账户登出时

Claude Code、Codex 或 Grok Build 的账户可能会被登出：它的登录已结束或被撤销，程序会提示 "Not logged in · Please run /login" 或 "401 Unauthorized"。应用会尽可能自行解决，只有在别无他法时，才会请你重新登录。

Antigravity CLI 没有其他账户可以切换。如果你在它登出时新建会话，会话会停止，并提示 "Antigravity CLI is not signed in: sign in with your Google account in Settings → Agents → Accounts, then try again."，同时那里的对应行会显示它已登出。请在那里登录，然后重新发送你的消息。

- **你的会话.** 当某个会话的一轮请求因其账户已登出而被拒绝，并且 [达到限额时切换账户](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit) 已开启（默认开启）时，该会话会连同全部历史记录，转移到同一智能体的另一个仍有用量的已登录账户，并继续运行。屏幕底部会出现一条简短的提示："<session>: <account> is signed out, so it continues on <other account>"，同时智能体会收到这样的告知："… is signed out, so this session now runs on …. Continue where you left off."。如果你向一个不久前被发现账户已登出的会话发送消息，会话会先以同样的方式转移，这样你的消息就不会被拒绝。
- **会话无法转移时。** 如果 **达到限额时切换账户** 已关闭，或者该智能体没有其他账户还有用量，会话就会停止。消息框上方会出现一条横幅，写着 "<account> is signed out" 和 "This session continues once you sign in again."，并带有一个 **登录** 按钮。你重新登录后（无论是在这里还是在终端中），会话会自行继续，智能体会收到这样的告知："Signed in again. Continue where you left off."。
- **后台工作。** 在 [辅助模型](/settings?s=models&find=Helper%20model) 设为 **自动** 时，它负责的小任务（会话标题、记忆备注、精简[你的个人资料](/guide/memory#your-profile)、应用的快速模型步骤、拉取请求描述等）会跳过已登出的账户 15 分钟，之后再重试，因此你在终端中完成的登录会被察觉。接下来由下一个已登录的账户来回答，再之后是 Codex。当 Claude Code 和 Codex 都无法回答（已登出、已达限额或未安装）时，会由你的某个 **Custom** 模型来完成：即 Custom 的 **快速** 档位在 [设置 → 智能体 → 模型 → 档位](/settings?s=models&find=Tiers) 中指定的那个模型（其次是 **标准**，遇到少见的较大任务则依次是 **最佳**、**最大值**），否则就用你添加的最便宜的模型（本机上的模型视为免费）。最多尝试两个。它的花费和其他 Custom 模型的用量一样计算。
- **登录提示。** 只有在没有任何方式能完成工作、且有账户已登出时，每个页面的右下角（手机上则在消息框上方）才会显示一张卡片。标题是 "Sign in to Claude Code again"（或 Codex、Grok Build），下面是 "<account> is signed out."，然后说明原因："Background work needs it (shortening your profile), and no other account or Custom model could do it."，如果是它停止的会话，则是 "… continues once you sign in."。**登录** 会打开与 [设置 → 智能体 → 账户](/settings?s=accounts) 相同的登录对话框。**暂不** 会把这张卡片隐藏一小时；如果有会话因此而停止，卡片会再次显示，而该会话中的横幅会一直保留。同时最多显示两张卡片，多出的部分会显示为 "+N more"，点击后会跳转到 设置 → 智能体 → 账户。账户重新登录后，卡片就会消失，无论是通过卡片、设置还是在终端中登录（应用会在下一次成功的调用时察觉）。当后台工作通过其他方式重新得以完成（其他账户或某个 Custom 模型作答）时，卡片也会消失。当 Claude Code 和 Codex 都已登出时，只会询问最先作答的 Claude Code。

你的个人资料也会显示这一点：如果精简它时因账户已登出而失败，下方的原因会这样说明（"Your Claude Code account “Work” is signed out, and no other account or Custom model could do this: sign in again (Settings → Agents → Accounts)."），并且会出现这张卡片。

## 所有账户都达到限额时使用 API 额度

如果你有 Anthropic API 密钥（来自 [console.anthropic.com](https://console.anthropic.com) → API keys），那么当所有 Claude Code 账户都达到用量限额时，你的 Claude Code 会话可以用它继续运行，而不是停止。这需要花钱：会话以这种方式运行期间，由 Anthropic 按 API 价格计费，不包含在你的订阅内。

1. 打开 [设置 → 智能体 → 账户](/settings?s=accounts&find=Use%20API%20credit%20at%20a%20limit)。在 **账户** 中某个 Claude Code 账户所在的行（你的主登录账户，或你添加的账户）上，点击 **⋯**，然后点击 **添加 API 密钥…**。
2. 将密钥粘贴到 **Anthropic API 密钥** 中，然后点击 **保存密钥**。应用会向 Anthropic 验证该密钥，并将其加密保存在这台电脑上。之后该行会显示一个 **API 额度** 标签。**更改 API 密钥…** 可替换它，**移除 API 密钥** 可删除它。
3. 在 **达到用量限额时** 分组中，打开 **达到限额时使用 API 额度**（它的 (i) 说明：当所有 Claude Code 账户都达到用量限额时，会话会改为计入某个账户的 Anthropic API 密钥继续运行，而不是停止；在你开启之前，它是关闭的）。只有在 Claude Code 已登录，或你已添加了 Claude Code 账户后，它才会显示。

之后会发生这些事：

- 当某个 Claude Code 会话的账户达到用量限额时，应用会先尝试 **达到限额时切换账户** 的做法：换到另一个仍有用量的账户。只有在没有任何账户还有用量、且该设置已开启时，会话才会改为计入 API 密钥继续运行。
- 会话仍留在它自己的账户上，因此它的历史记录不会转移。如果该账户没有密钥，就会使用另一个 Claude Code 账户的密钥。
- 会话顶部其账户旁会显示一个 **API 额度** 标签。把鼠标悬停在上面可以看到原因。
- 当某个套餐重新有了用量，会话会在下一轮结束后切回去：回到它自己的账户，或转到另一个仍有用量的账户。你无需做任何事。
- 如果应用无法读取某个账户的用量，就绝不会把你的工作转到 API 计费上。
- Codex 不受影响：它没有 API 额度。

## 添加 Gemini CLI、OpenCode 和其他 ACP 智能体

打开 [设置 → 智能体 → 更多智能体](/settings?s=agents&find=Agents%20that%20speak%20ACP)。

- **你的智能体**（开始会话时，它们会显示在 Claude Code 和 Codex 旁边）首先列出 Custom，然后是你添加的智能体。如果对应的程序已安装在这里，每一项会显示一个对勾；否则显示叉号和“未安装”。
- **支持 ACP 的智能体**（先安装一个，在它自己的 CLI 中登录一次，再回到这里添加）列出你还没有添加的已知智能体：Gemini CLI、OpenCode、Qwen Code、Goose、Kimi CLI、Auggie、Grok Build、Antigravity CLI 等。已安装的排在前面。显示“未安装”的一行会告诉你如何获取它。列表只显示前几个未安装的智能体；点击 **全部显示** 可以看到其余的。

添加方法：

1. 点击该行末尾的 **添加**。如果程序已经安装，这个按钮会更醒目。
2. 如果应用知道如何安装它（Gemini CLI、OpenCode、Qwen Code、Auggie、Grok Build，以及需要 ACP 适配器的智能体），就会立即在后台安装。Goose、Kimi CLI、Antigravity CLI 和其他智能体需要你自己安装，使用它们所在行里的命令或地址即可。
3. 在该智能体自己的程序中登录一次：打开 [终端](/terminal)，运行它的命令（例如 `gemini`），并按提示登录。如果跳过这一步，会话会提示：“Gemini CLI is not signed in. Run gemini once in a terminal and sign in there, then try again.” Grok Build 和 Antigravity CLI 是例外：它们在 [设置 → 智能体 → 账户](/settings?s=accounts) 下登录。

Gemini CLI 适用于 Gemini API 密钥，或 Gemini Code Assist 标准版或企业版许可；这里的预设会用 `--acp` 启动它。自 2026 年 6 月 18 日起，它不再支持 Google AI Pro 和 Ultra（以及面向个人的 Gemini Code Assist）：这些套餐请使用 Antigravity CLI。

之后，该智能体会显示在开始页面的 **运行于** 列表中。

要修改已添加的智能体，点击 **编辑**。要移除它，打开它的 **⋯** 菜单，选择 **移除** 并确认：它的会话仍会保留在列表中，但要继续这些会话，需要重新设置该智能体。Custom 是内置的：它的那一行写着“内置：模型来自 OpenRouter、Ollama 和 vLLM，在设置 → 模型中配置”，并且有一个 **模型** 按钮，而不是编辑和移除。

### Grok Build

**Grok Build** 是 xAI 的编程智能体（即 `grok` 程序）。点击它那一行的 **添加** 就完成了：应用会在第一次需要时从 npm（`@xai-official/grok`）安装它，或者使用这里已有的版本，包括通过 xAI 自带安装程序装在 `~/.grok/bin` 中的版本。之后它会显示在 **智能体程序** 下，并与其他程序一起保持最新。Hydor 通过 ACP 运行它，使用应用自己的工具、批准卡片以及 Grok 的模型。

它的登录方式与其他 ACP 智能体不同：不在终端中登录，而是在 [设置 → 智能体 → 账户](/settings?s=accounts) 下，添加后那里会立即出现一行 **Grok Build**（参见 [登录 Claude Code、Codex 和 Grok Build](#sign-claude-code-codex-and-grok-build-in)）。你还可以在那里添加更多 Grok 账户。

### Antigravity CLI

**Antigravity CLI** 是 Google 推出的终端编程智能体（即 `agy` 程序），也是适用于你的 Google AI 套餐的那一个。自 2026 年 6 月 18 日起，Gemini CLI 不再支持 Google AI Pro 和 Ultra（以及面向个人的 Gemini Code Assist）。Gemini CLI 仍适用于 Gemini API 密钥，或 Gemini Code Assist 标准版或企业版许可。

**自行安装。** Google 要求用户自己安装，因此应用不会代为安装。它在 [设置 → 智能体 → 更多智能体](/settings?s=agents&find=Agents%20that%20speak%20ACP) 中的那一行（位于 **支持 ACP 的智能体** 下，名为 **Antigravity CLI**，命令为 `agy acp`）会显示 Google 的安装程序。在 macOS 和 Linux 上，在 [终端](/terminal) 中运行下面的命令；它会把 `agy` 放到 `~/.local/bin` 中：

```
curl -fsSL https://antigravity.google/cli/install.sh | bash
```

在 Windows 上，在 PowerShell 中运行：

```
irm https://antigravity.google/cli/install.ps1 | iex
```

它会自动更新，所以不在应用负责保持最新的 **智能体程序** 之列。安装完成后，点击它那一行的 **添加**。

**登录。** 添加之后，[设置 → 智能体 → 账户](/settings?s=accounts) 会显示一行 **Antigravity CLI**，并有它自己的登录流程：

1. 点击 **登录**，然后点击 **获取登录链接**。
2. 点击 **1. 打开此链接**：这是 Google 的登录页面。使用你的 Google 账户登录，需为个人账户，且订阅了 Google AI Pro、Ultra、Plus 或 Antigravity 的免费套餐。随后页面会显示一个代码。
3. 把代码粘贴到 **2. 粘贴页面上的代码**（或者粘贴你跳转到的页面的完整地址），然后点击 **完成登录**。

之后该行会显示邮箱，在打开过一次会话后还会显示套餐（例如 Google AI Pro）。该行 **⋯** 菜单中的 **退出登录** 会在这台电脑上退出 Antigravity CLI，所有使用它的程序都会受影响。在终端应用中，`hydor accounts sign-in antigravity` 可以完成同样的登录。如果在未登录时启动会话，会话会停止并提示：“Antigravity CLI is not signed in: sign in with your Google account in Settings → Agents → Accounts, then try again.”

**模型和思考强度。** 在会话中，**模型** 列出 Antigravity CLI 自己的模型（Gemini 4 系列模型、Gemini 3.8 Flash，以及你的套餐提供的其他模型），**思考强度** 列出它的思考级别（low、medium、high、xhigh 和 max），**权限** 列出它的权限模式。它们会在第一次会话之后显示，因为应用是在会话打开时了解到这些内容的。应用自己的工具和批准卡片的工作方式与其他 ACP 智能体相同。

**Google 的条款在这里意味着什么。** 在这一行下方，应用会说明：“Google 的套餐条款只允许在你亲自发起并操作的会话中使用 Antigravity CLI，因此它只有一种登录方式，也从不在后台工作。” 在 Hydor 中，这意味着：

- **只有一个登录。** 你不能添加更多 Antigravity CLI 账户：**添加账户** 不提供它，**达到限额时切换账户** 也永远不适用于它。
- **只限你自己启动的会话。** 开始页面、终端应用、聊天应用（Telegram 等）和免提语音可以启动它。定时计划、其他智能体启动的子智能体、[应用](/guide/apps) 运行、竞技场，或应用启动的其他任何内容，都会被拒绝：“Antigravity CLI 只能在你亲自发起并操作的会话中运行：Google 的套餐条款不允许由应用或其他智能体发起的工作（定时任务、子智能体、应用）。请为此选择其他智能体。”
- **应用不会自行发送消息。** 应用永远不会自己给它发消息。本来要发送的内容（子智能体的结果、应用的回答、提醒）会作为备注显示在会话中：“未发送给 Antigravity CLI，它只接收你亲自发送的消息（Google 的套餐条款）。如需转达，请亲自发送：”，后面跟着相应的文字。你自己做的操作（回答卡片、保存密钥、你的语音）仍然会送达它。
- **不会自行继续。** 达到限额后，它永远不会自行继续：它没有 **用量限制解除后继续**，也没有 **重置时继续** 按钮。参见 [用量、限额和费用](/guide/usage#what-happens-when-you-hit-a-limit)。

在其他任何程序中使用它的登录，或轮换账户，可能会导致该 Google 账户的 Antigravity 访问权限被暂停（Google 在其常见问题中这样说明），所以请只按这里所述的方式使用。对于无人值守的工作，例如定时计划、子智能体和应用，使用 Gemini CLI 搭配 Gemini API 密钥才是正确的做法。

它的用量会以卡片形式显示在 [用量页面](/usage) 上，有邮箱和套餐，但没有计量条：参见 [查看套餐的限额](/guide/usage#read-a-plans-limits)。

### 添加你自己的智能体

任何支持 ACP 的程序都可以在这里运行。

1. 点击 **你的智能体** 标题旁边的 **添加你自己的**。
2. 填写：
   - **名称**：它在列表中显示的名字，例如“Gemini CLI”。
   - **命令**：要启动的程序，例如 `gemini`，或完整路径。
   - **参数**：以 ACP 模式启动它所需的内容，例如 `--acp`。
   - **环境变量（可选，每行一个 NAME=value）**：程序需要的设置，例如 API 密钥变量。
3. 点击 **保存**。

该命令必须以 ACP 模式启动智能体，并通过它的标准输入和输出进行通信。

### 在智能体自己的程序中设置的智能体

列表中有些智能体是需要你自己设置的程序，与应用替你安装的那些相比，有几点不同：

- 它们在 **更多智能体** 中的那一行会显示安装它们所用的命令或地址。应用不会替你运行来自网络的脚本：请自己安装，在 [终端](/terminal) 中或按那一行说明的方式安装。
- 在智能体自己的程序中登录一次，同样在终端中进行（例如运行它的命令并按提示登录，或在那里选择它的模型）。此后应用就会启动它。它会把自己的会话和记忆保存在它自己的文件夹中，批准卡片也是它自己提供的那些。
- 其中一个会连接到它自己的网关：先用该智能体自己的设置命令把它设置好，并保持网关运行。
- 当智能体本身不支持 ACP 时，它需要一个 ACP 适配器。应用会把适配器和智能体一起安装，二者都通过 npm 装在它自己的文件夹中，并且不运行它们的安装脚本。如果你自己安装的智能体在 PATH 中，就会使用它。
- 不接受 MCP 服务器的智能体只能使用它自己的工具：应用的工具（网页、搜索……）无法送达它，会话开始时会说明这一点。它仍然会在第一条消息中获得应用的准则、记忆备注和技能。

### ACP 智能体在这里能做什么、不能做什么

应用会在你选择的文件夹中打开会话，显示智能体的消息和步骤，并在智能体请求权限时询问你。有些方面与 Claude Code 和 Codex 的工作方式不同：

- 它一次只处理一条消息。你在它工作时发送的消息会在消息框上方的队列中等待，并在这一轮结束时发出。（Custom 也是这样工作的。）
- 无法重新打开早期会话的智能体，在你继续旧会话时会从头开始，没有上面的对话内容。会话会说明这一点。如果智能体以前能重新打开会话、现在不能了，也会这样：它会带着一条备注重新开始，而不是失败。
- 你附加的图片只有在它接受图像时才会送达。
- 不支持分叉和交接（Custom 支持分叉）。目标是支持的：应用自己的循环为每个智能体驱动目标。
- Antigravity CLI 只能在你自己启动并操作的会话中工作，且只有一个登录（参见 [Antigravity CLI](#antigravity-cli)）。
- 应用的工具（网页、搜索、记忆……）以 MCP 服务器的形式送达智能体：如果智能体接受，就通过地址；否则通过应用为它启动的一个小程序。完全不接受这些的智能体只能使用它自己的工具，但仍会获得准则、记忆备注和技能。

## Custom 的模型从哪里来

Custom 可以运行你的 Claude 和 ChatGPT 套餐中的模型、这台电脑上的模型以及云端的模型，使用的工具、技能和 MCP 服务器与其他智能体相同。在开始页面选择 Custom，然后选择模型。它们来自三个地方：

- **你的订阅**：你的 Claude 和 ChatGPT 套餐中的模型，通过这台电脑上 Claude Code 和 Codex 的登录获得。无需任何设置：当 Claude Code 已登录时，Custom 的 **模型** 菜单会提供 Claude Opus、Fable、Sonnet 和 Haiku（始终是各自最新的版本）；当 Codex 以 ChatGPT 登录时，它会提供你的 ChatGPT 套餐列出的模型（例如 GPT-6 Luna）。如果发现某个程序已退出登录，它的模型会从菜单中消失，直到你重新登录；而以 API 密钥而不是 ChatGPT 登录的 Codex 不会提供任何模型。它们使用的是你套餐的用量，而不是 API 密钥，也不按词元计费，所以 Custom 会话在这些步骤上显示 $0。程序的每个账户会依次尝试，与其他一次性工作相同：某个账户达到用量上限或已退出登录时，会把这一步交给你的下一个账户（需开启 **达到限额时切换账户**）。[保密会话](/guide/sessions#keep-a-session-confidential) 永远不会使用它们，因为它们运行在 Anthropic 或 OpenAI 的服务器上。关于它们如何回答，参见 [Custom](/guide/custom#what-custom-is-and-when-to-use-it)。
- **在这台电脑上**：安装在这里的模型（Ollama、vLLM），以及你网络中的端点。
- **在云端**：OpenRouter、其他地方的端点，以及 Ollama 的云端模型。

在任何可以选择 Custom 模型的地方都可以选择它们：开始页面、会话的模型菜单、Custom 的档位、辅助模型，以及智能体或应用的模型。

[设置 → 智能体 → 模型](/settings?s=models) 包含 Custom 的模型所需的一切。该页面从上到下分为七个部分：

- **辅助模型**：用于应用小任务的模型。
- **档位**：为每一类工作指定一个模型（参见 [档位：为每一类工作指定一个模型](#tiers-a-model-for-each-kind-of-job)）。
- **你的订阅**：Claude Code 和 Codex 各占一行，显示它借给 Custom 的模型。某一行会显示“已退出登录：请重新登录以使用这些模型”，并带有指向 **账户** 的链接，或者显示“未安装在这台电脑上”。
- **在本机**：这台电脑所具备的条件，以及安装在这里的模型。
- **从 Hugging Face 添加模型**：搜索、检查并安装开放模型。
- **OpenRouter**：通过一个密钥使用数百个模型，分为三组：你的密钥、你添加的模型，以及用于添加更多模型的搜索。
- **运行时和端点**：Ollama、vLLM、其他兼容 OpenAI 的服务器，以及 Hugging Face 令牌。

在 Custom 的 **模型** 菜单中，模型按 **你的订阅**、**在这台电脑上** 和 **在云端** 分组，每一行都会说明它通过什么提供：“Claude Code”、“Codex”、“OpenRouter”、“Ollama”、“vLLM”或某个端点的名称。将鼠标悬停在模型上，可以看到它在哪里运行以及一次能读取多少内容，例如“OpenRouter · 128K context”或“vLLM, on this machine · 32K context · starts when used”。这些列表每分钟自动刷新一次。

## 选择辅助模型

辅助模型负责在你的会话之外处理一些小任务，不参与任何对话：

- 根据你的请求为每个新会话命名（即它在侧边栏中的标题）；
- 在 Custom 的自动模式下检查步骤，并判断必须由审查者确认成立的目标检查项（审查者是没有参与任何工作的模型，在保密会话中则是这台电脑上的模型）；
- 大约每天整理一次记忆，从此后的对话中学习，并为智能体开场读取的索引给备注拟定标题；
- 回答关于浏览器已打开网页的某个问题；
- 在 Naget Search 搜索之前，读取网络搜索的文字所表达的筛选条件（网站、日期、网页类型、语言）（参见[智能体如何搜索网络](/guide/web#how-agents-search-the-web)）；
- 为看不了图片的 Custom 模型描述图片；
- 概括 Hydor 子智能体的长回复；
- 根据会话起草应用或定时任务；
- 免提语音模式。

打开 [设置 → 智能体 → 模型](/settings?s=models&find=Helper%20model)，点击**辅助模型**组中的**模型**菜单（其中的 (i) 列出了这些小任务）：

- **自动**（默认）：通过 Claude Code 使用 Claude Haiku；Claude Code 无法回答时使用 Codex。如果某个账户已达到用量上限，会先把问题交给你的下一个已登录账户（需开启**达到限额时切换账户**），已退出登录的账户会被跳过。两个程序都无法回答时，由你的某个 Custom 模型来完成（即 Custom 的**快速**档位所指定的模型，否则是你添加的最便宜的模型；你的套餐中的模型在这里会被跳过，因为它们走的是同样的两个程序），只有在没有任何模型能完成时，才会出现一张卡片请你登录（参见[账户已退出登录时](#when-an-account-is-signed-out)）。当没有任何模型回答时，错误信息会逐一说明原因：“You've hit your weekly limit”、你的 Codex 套餐不提供的模型……
- Custom 的任一模型，分组与 Custom 的**模型**菜单相同（**你的订阅**、**在这台电脑上**和**在云端**），并标明它通过什么提供（Claude Code、Codex、OpenRouter、Ollama、vLLM 或某个端点的名称），能看图片的模型会标注“能看图片”。你的 Claude 或 ChatGPT 套餐中的模型也可以做辅助模型：它通过 Claude Code 或 Codex 回答，消耗你套餐的用量。

自动无法查看图片。如果你使用的 Custom 模型看不了图片，请选择一个能看图片的辅助模型，否则 Custom 无法为你的图片生成描述。

## 查看这台电脑能运行什么

[设置 → 智能体 → 模型](/settings?s=models&find=On%20this%20machine)中的**在本机**部分，开头是这台电脑的概况：

- **显卡**：显卡（GPU）及其显存；在搭载 Apple 芯片的 Mac 上，则是它的芯片（“Apple M3 Max”，其图形处理与电脑共用内存）；或者显示“No GPU”（此时模型在处理器上运行）。
- **内存和磁盘**：电脑的内存（总量和可用量），以及磁盘的可用空间和已安装模型占用的空间。
- **运行方式**：**Ollama** 和 **vLLM** 是否已安装及其版本，或者一个安装链接。
- 如果有显卡，还会显示能装下多大的模型：“Fits about 30B parameters at 4-bit on one GPU”（在 Mac 上：“Fits about 40B parameters at 4-bit”）。参数量是衡量模型大小的单位；4-bit 是一种常见的压缩形式，大约只需要四分之一的内存。

下面依次是：

- **正在进行的下载**，每项都有进度条、已完成的量，以及它是用于 Ollama 还是 vLLM。**取消**可以停止其中一项。失败或已取消的下载会显示原因，并带有**关闭**。
- **已安装的模型**（先显示前几个，其余点击**全部显示**），每个模型都显示其运行方式（Ollama 或 vLLM）、大小、详细信息（例如 Ollama 模型的大小和压缩方式）、能看图片的会标注“能看图片”，以及是否正在运行。
  - vLLM 模型带有**开始**和**停止**。会话第一次使用它时，它会自动启动（第一次启动需要一两分钟），运行在空闲显存最多的显卡上（如果原样放不下，则使用 8-bit），或者在没有任何一张显卡放得下时，拆分到 2、4 或 8 张显卡上（“running on GPUs 1, 2”）；在 Mac 上则运行在它的 Apple 芯片上。它会一直运行，即使应用重启也不会停，直到你点击**停止**。如果无法启动，原因会显示在它下方。
  - 模型的 **⋯** 菜单中的**移除**会在你确认后，从这台电脑上删除该模型的文件。之后你可以再次安装。

如果还没有任何模型，会显示：“No models here yet: add one from Hugging Face below.”

## 从 Hugging Face 添加模型

Hugging Face 是开源模型的主要网站。[从 Hugging Face 添加模型](/settings?s=models&find=Add%20a%20model%20from%20Hugging%20Face)这一组（为这台电脑推荐，或搜索全站）会推荐几个模型，提供搜索，并在下载之前告诉你每个模型在这台电脑上会如何运行。

### 为这台电脑推荐

在你搜索之前，这一组会根据这台电脑的配置，列出应用推荐的、能在上面运行的模型：

- **LFM3-VL 2B**（Liquid AI）：小巧快速，能读图片。几乎任何电脑都能运行。
- **Gemma 4 12B**（Google）：能力全面，能读图片，适合配有好显卡的电脑。
- **Flint**（Recursive）：专为编程智能体打造，适合搭载 Apple 芯片、内存 32 GB 及以上的 Mac。
- **GLM-5.3 Flash**（Z.ai）：最强的开源模型之一，适合配有多张大显存显卡的服务器。

每一项都会显示它在这里运行得流畅还是缓慢、会如何运行（“vLLM at 8-bit, on GPU 0”、“vLLM, split across 2 GPUs”、“vLLM, on Apple silicon”）、下载大小，以及**安装**。**本机最佳**标记的是运行流畅的模型中最强的一个。它们默认用 vLLM 运行；既没有 NVIDIA 显卡也没有 Apple 芯片的电脑，则会改为获得小型模型的 Ollama 版本。如果运行它们所需的程序尚未设置好，后面会出现警告（“vLLM is not set up”、“Ollama is not running”）：参见[连接 Ollama、vLLM 或其他端点](#connect-ollama-vllm-or-another-endpoint)。**2 more for bigger computers** 这一行（或其他数量）会显示其余的模型，以及各自的要求。欢迎导览推荐的也是这几个。

### 搜索和筛选

1. 在**搜索 Hugging Face，或粘贴 org/name**中输入：可以是 `qwen3` 这样的名称，也可以是模型的完整名称（`org/name`）或它的 huggingface.co 地址。输入之前，它会给出几个名称建议，或者**查看下载最多的**。
2. 用筛选项缩小列表范围（可以组合使用）：
   - **在这里运行流畅**：只显示在这台电脑上能流畅运行的模型。
   - **GGUF · Ollama**：GGUF 格式的模型，由 Ollama 运行。
   - **vLLM**：safetensors 格式的模型，由 vLLM 在显卡上运行。
   - **能看图片**：同时能读图片的模型。
3. 用右侧的菜单更改排序：**下载最多**、**热门**、**最受喜爱**或**最新**。

最多会得到 40 个模型，起初显示前八个，其余点击**全部显示**。你输入了完整名称的模型会显示在最前面，即使搜索结果里没有它，按回车键会立即检查它。

每一行显示制作方和名称、它的格式（**GGUF** 或 **vLLM**）、如果能看图片则显示**图片**、如果其制作方要求你先接受条款则显示**受限**，以及它的参数量、最近 30 天的下载量、点赞数和最后更新时间。

### 初步判断

每个模型下面有一个彩色标签，仅根据模型大小给出初步判断：

- **Runs well with vLLM** 或 **Runs well with Ollama**，并附有大致速度（“about 40 tokens/s”；token 是词的一小段）：它能装进你的显卡显存。
- **用处理器运行，较慢**或**用处理器运行，非常慢**：它只能装进电脑的内存，所以在处理器上运行。只有 Ollama 能做到这一点。
- **对这台电脑来说太大**：它装不下，或者下载内容放不进磁盘。
- **At 4-bit with Ollama: runs well…**：模型按原样存储时太大，但它压缩后的 4-bit 版本用 Ollama 可以流畅运行。

把鼠标悬停在标签上，可以看到背后的数据。

### 下载前先检查

点击模型上的**检查**，就能确切看到它在这里会如何运行。面板会显示它的大小、一次能读多少内容（即上下文）、它能否看图片，然后是：

- 对于 GGUF 模型：“Runs with Ollama”，以及每个可用的大小（文件越小，会用一点质量换取速度和内存），从最小的开始。每一行给出它的判断、所需内存、大约的运行速度和下载大小，并带有**安装**按钮。Ollama 在这里没有运行时，或者对于太大的版本，安装按钮是灰色的。
- 对于 vLLM 模型：“Runs with vLLM, which starts it on a GPU when a session uses it”，以及同样的数据、关于它会使用哪张显卡的说明，还有一个**下载**按钮。如果没有安装 vLLM，或者你的 vLLM 还不能运行这类模型，页面会如实说明；如果存在 GGUF 版本，则会提供对那个版本的**检查**。
- 对于其他情况：“No weights this app can run (safetensors for vLLM, GGUF for Ollama).”

这些数据假设对话最长约 32,000 个 token，即这台电脑上的模型所获得的长度。**关闭**会收起面板。

### 安装，以及之后会发生什么

点击**安装**（Ollama）或**下载**（vLLM）。下载会连同进度显示在**在本机**中。完成后，模型会出现在 Custom 的**模型**菜单中。中断的 vLLM 下载在你重试时会从中断处继续。对任何一张显卡来说都太大的 vLLM 模型，会在启动时以 8-bit（FP8）存储，这样权重占用的内存减半而损失很小（适用于 NVIDIA RTX 30 系列及 A100 以上的显卡）；如果仍然放不下，且几张显卡加起来有足够空间，它就会被拆分到多张显卡上。

### 受限模型和私有模型

有些制作方要求你先接受他们的条款；它们的模型会显示**受限**。请在该模型位于 huggingface.co 的页面上接受条款，然后添加 Hugging Face 令牌（参见 [Hugging Face 令牌](#hugging-face-token)）。私有模型同样需要令牌。

## 通过 OpenRouter 使用模型

OpenRouter（openrouter.ai）让你用同一个密钥使用来自众多制作方的数百个模型，按使用量付费。

### 添加你的密钥

1. 在 openrouter.ai 获取密钥（本节中有指向那里的链接）。
2. 在[设置 → 智能体 → 模型](/settings?s=models&find=OpenRouter)中，点击**你的 OpenRouter 密钥**这一行里的**添加密钥**，在弹出的对话框中把密钥粘贴到**你的 OpenRouter 密钥：sk-or-…**，然后点击**保存**。

之后这一行会显示**已连接到 OpenRouter**，以及你密钥的开头和结尾。它的 **⋯** 菜单中的**移除密钥**会让应用忘记这个密钥。密钥保存在服务器上，不会再次显示。

你也可以在第一次需要时再添加：智能体要生成图片、绘图、视频或声音而又没有密钥时，会在对话中用一张卡片向你索取（[当智能体需要 OpenRouter 密钥时](/guide/documents-voice#when-an-agent-needs-the-openrouter-key)），编辑器的 AI 工具则会在它们的对话框中询问。无论哪种方式，密钥都保存在这里。

### 推荐模型

在你搜索之前，**添加 OpenRouter 模型**这一组中的**推荐**会列出四个适用于 Custom 的模型，并说明各自的理由：**GPT-6 Luna**（Fast and cheap）、**Grok 4.7**（Good, with fewer refusals）、**GPT-6.1 Sol**（Better）和 **Claude Opus 5.5**（Best overall）。**添加**会把其中一个放进选择器。至于图片、音乐、语音和视频，应用选用的是 Seedream 5.0 Pro（以及更快更便宜的 Flash）、Lyria 3 Pro、Seed Audio 1.0 和 Seedance 2.5：参见[设置 → 功能 → 图片、视频和音频](/settings?s=images)。

### 搜索目录

在同一组中，在**搜索 OpenRouter：deepseek、qwen、claude…**中输入，或者点击某个推荐的名称，或者**查看最新的**。筛选项：

- **工具调用**：原生调用工具的模型，这是 Custom 用起来最好的方式（**最佳匹配**会把这些排在前面）。
- **能看图片**
- **推理**：回答前会先思考的模型。
- **免费**

右侧的菜单用来排序结果：**最佳匹配**（按名称搜索时）、**最新**、**最便宜**或**最长上下文**。最多会得到 50 个模型，起初显示前八个，其余点击**全部显示**。

每个模型显示它的制作方、名称和标签：**最新**（始终是制作方的最新版本）、**新增**（最近三周内上架）、**免费**、**推理**、**图片**，以及**无原生工具**（此时 Custom 会在指令中描述它的工具，并从它的文本中读取它的调用）。下面是：它一次能读多少内容（“128K context”）、它最长的回复（“16K out”）、每百万个 token 的输入和输出价格、上架的月份、一段简短描述和它的 OpenRouter 名称。

### 把模型添加到选择器

点击模型上的**添加**。它所在的行随后会显示**已添加**，该模型会出现在搜索框上方的**你的 OpenRouter 模型**组（“In the model pickers”）中，也会出现在 Custom 的**模型**菜单里。点击其中某个模型上的 × 可以把它从菜单中移除。在你至少添加一个模型之前，OpenRouter 不提供任何模型（“Add at least one model to use OpenRouter.”）。

## 连接 Ollama、vLLM 或其他端点

**运行时和端点**分组用来连接运行模型的程序。你可以在 [设置 → 智能体 → 模型](/settings?s=models&find=Runtimes%20and%20endpoints) 中打开它。

### Ollama

Ollama 是一款免费程序，可以在你的电脑上用显卡或处理器运行模型。它所在的行会显示“运行中”和版本号，或者显示“此地址未运行”，并附有 **安装 Ollama** 链接。除非你修改，否则它的地址是 `http://127.0.0.1:11434`：在输入框中输入另一个地址，旁边就会出现 **保存**。这个 Ollama 中的所有模型都会显示在 Custom 的模型列表里，包括你在应用之外拉取的模型。

### vLLM

vLLM 是一个适用于 NVIDIA 显卡的快速模型服务器，也是来自 Hugging Face 的模型在这里默认的运行方式。对一张显卡来说过大的模型，可以在它上面以 8 位运行，或者拆分到 2 张、4 张或 8 张显卡上。在 Mac 上，vLLM 通过它的 Metal 插件（vllm-metal）在 Apple 芯片上运行。应用会在 PATH 中或 conda、venv 环境里自动找到它，并显示它的版本和所在位置。如果显示“未找到（pip install vllm），或指定它的命令”，请安装它，或者在输入框中输入它的 `vllm` 命令的完整路径，然后点击 **保存**（输入后才会出现）。如果让输入框保持为空，应用就会自行查找。

### 其他兼容 OpenAI 的端点

许多程序和服务的应答方式与 OpenAI 的 API 相同：LM Studio、llama.cpp 的服务器、其他服务商。添加方法如下：

1. 点击分组标题旁边的 **添加端点**。
2. 在对话框中输入 **名称**、它的地址（例如 `http://localhost:1234/v1`）和 **密钥（可选）**。
3. 点击 **添加**。

端点会显示为一行，其中有它的地址和它提供的模型数量。它的模型会以“模型（名称）”的形式出现在 Custom 的列表中。× 可以移除它。添加同名的另一个端点会替换第一个。

点击该行下方的 **设置每个模型的能力**，可以查看它的模型，每个模型有两个选项：**能看图片** 和 **推理强度**。每个选项都可以选 **自动**、**是** 或 **否**。能看图片的模型会以图片的形式收到截图和图片，而不能看图片的模型会收到它们的文字描述（见 [不能看图的模型如何处理图片](/guide/custom#images-for-models-that-dont-see)）；会推理的模型会在 **思考强度** 菜单中提供低、中、高三档，Custom 会把你选的那一档作为 `reasoning_effort` 发送，这是兼容 OpenAI 的服务器所接受的设置（选择 **默认** 时不会发送任何内容）。**自动** 会遵循端点对该模型的说明，菜单中会显示具体是什么：会描述自身模型的服务器（OpenRouter 风格、Mistral 等）会在模型列表中一并说明；对于 LiteLLM 网关，Hydor 还会用同一个密钥查询它的模型信息。没有任何说明的端点按“否”处理：对于你确定能看图片或会推理的模型，请设为 **是**。再次添加该端点时，你的设置会保留。

[保密会话](/guide/sessions#keep-a-session-confidential)可以使用地址为本机或你的私有网络的端点：`localhost`、`127.0.0.1`、`::1`、`10.…`、`192.168.…`、`172.16.…` 到 `172.31.…`，或以 `.local` 结尾的名称。任何其他地址都视为在线，即使它指向你自己的服务器也一样：请改用它的私有地址。Ollama 的地址同样适用这条规则，而 Ollama 的云端模型（名称以“cloud”结尾）始终视为在线。

### Hugging Face 令牌

[Hugging Face 令牌](/settings?s=models&find=Hugging%20Face%20token)可以让应用下载受限或私有的模型（该行会显示“仅用于受限或私有模型”）。请在你的 Hugging Face 账户设置中创建一个令牌，点击 **添加令牌**，把它粘贴到对话框中（它以 `hf_` 开头），然后点击 **保存**。之后该行会显示令牌的开头和结尾，并在它的 **⋯** 菜单中提供 **移除令牌**。
