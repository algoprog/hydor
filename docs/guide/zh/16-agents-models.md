# 智能体、账户和模型

Hydor 可以运行多个 AI 智能体：Claude Code、Codex、Custom（应用自带的智能体，可使用任何模型），以及其他支持 ACP 的智能体，例如 Gemini CLI、OpenCode、Qwen Code、Goose 或 Grok Build。本主题介绍它们有什么不同、它们的程序如何安装并保持最新、如何登录（也包括登录多个账户），以及 Custom 的模型从哪里来：OpenRouter、Ollama、在这台电脑上运行的 Hugging Face 模型，或任何兼容 OpenAI 的端点。

![在起始页选择智能体：Claude Code、Codex 或 Custom](images/agents-models.webp)

## 我该用哪个智能体？

智能体是在会话中干活的程序：它读取你的消息，使用工具（文件、命令、网络），然后给出回答。模型则是它背后的 AI。这里的每个智能体都能从应用获得同样的帮助（网页搜索、浏览器、记忆、技能、你的连接），但它们的模型来源不同。

- **Claude Code**（Anthropic）。使用你的 Claude 套餐运行，或按 Anthropic API 账户计费。它的模型是 Anthropic 的（Opus、Sonnet、Haiku）。它有自己的用量限制，可在[用量页面](/usage)中查看。
- **Codex**（OpenAI）。使用你的 ChatGPT 套餐运行。它的模型是 OpenAI 的。它同样有用量限制，显示在用量页面上。Codex 随应用提供。
- **Custom**，应用自带的智能体。它可以运行你的 Claude 和 ChatGPT 套餐中的模型（通过 Claude Code 和 Codex 的登录），也可以运行你在[设置 → 智能体 → 模型](/settings?s=models)中添加的任何模型：通过 OpenRouter 的模型、这台电脑上的模型（使用 Ollama 或 vLLM），或任何兼容 OpenAI 的端点。想用开源模型、更便宜的模型，或绝不离开你电脑的模型时，就用它。参见 [Custom，应用自带的智能体](/guide/custom)。
- **支持 ACP 的智能体**：Gemini CLI、OpenCode、Qwen Code、Goose、Kimi CLI、Auggie、Grok Build（xAI 的编程智能体，使用 Grok 模型）等，或者你自己的命令。ACP（Agent Client Protocol，智能体客户端协议）是应用与智能体程序通信的一种通用方式。每个智能体在自己的程序中登录一次，并使用自己的模型。

各个智能体在应用中能做什么：

- 目标（智能体持续工作，直到某个条件成立）和分叉（从较早的某条回复处复制出一个会话）：Claude Code、Codex 和 Custom 支持，其他 ACP 智能体不支持。
- **转到…**（把对话交给另一个智能体）：从 Claude Code 或 Codex 出发，可转到另一个，或转到 Custom。
- 思考强度（模型思考的投入程度）：Claude Code、Codex、Grok Build，以及模型提供此选项的其他 ACP 智能体。
- 多个账户、套餐用量限制，以及在达到限制时切换账户：Claude Code、Codex 和 Grok Build。
- 限制重置，以及在达到限制时使用 API 额度：仅限 Claude Code 和 Codex。

## 为新会话选择智能体和模型

在起始页（`/`）上，消息框下方的一行显示由谁来干活。

1. 点击**运行于**。列表中有 **Claude Code**（“Anthropic · Claude 套餐或 API 密钥”）、**Codex**（“OpenAI · ChatGPT 套餐或 API 密钥”）、**Custom**（“任何模型：OpenRouter、Ollama、vLLM”），以及你在“设置 → 更多智能体”中添加的每个智能体（“ACP 智能体 · ”加上它的命令）。底部的 **Custom 的模型**会打开“设置 → 模型”，**添加或管理智能体**会打开“设置 → 更多智能体”。
2. 点击**模型**并选择一个。位于顶部、一开始就被选中的**自动**，会让各档位来选择：最佳，如果问题太难则用最大值（参见[档位：为每类工作选择合适的模型](#tiers-a-model-for-each-kind-of-job)）。它下方的列表只显示该智能体自己的模型。智能体的默认模型标有“默认”。模型的旧版本收在“2 个旧版模型”这样的一行后面，点击它即可查看。模型超过八个时，顶部会出现**搜索模型**框：输入几个字母，按 Enter 选取第一个匹配项。如果智能体没有按应用的要求启动并提供模型，菜单会说明这一点，并附上智能体自己给出的原因，点击**重试**会再次请求。
3. 在**选项**下，你会看到**思考强度**（适用于有此功能的智能体和模型：默认、低、中、高等；Grok Build 的情况参见 [Grok Build 的思考强度](#effort-for-grok-build)）和**权限**（智能体无需询问你就可以做什么）。在消息框中按 Shift+Tab 也可以切换权限。

起始页会记住你在每个工作位置（每个项目、每个文件夹和**新建任务文件夹**）所做的选择，并在所有设备上同步：各个程序的模型、思考强度和权限会按你上次的设置恢复（参见[起始页会记住什么](/guide/sessions#what-the-start-page-remembers)）。

除 Custom 之外的 ACP 智能体，只有在它的第一次会话之后才会显示**模型**和**权限**选项：列出的是智能体上次运行时提供的内容。Grok Build 是例外：添加之后，它的模型以及每个模型支持的思考强度就会立即显示，因为应用会向 Grok 询问这些信息。

打开**选项** → **保密**后，**运行于**为 **Custom**，**模型**只列出这台电脑或你的专用网络上的模型，并优先选中其中最好的一个：参见[让会话保持保密](/guide/sessions#keep-a-session-confidential)。

在手机上，这些菜单都会以从屏幕底部升起的面板形式打开。

## 在会话中途切换模型

在会话中，模型、思考强度和权限位于消息框下方。它们合成一个标签，读起来像“Opus 5.5 · 最高 · 计划”：点击它即可进入**模型**、**思考强度**和**权限**。

选择另一个模型后，会话会用它继续进行：

- Claude Code 立即切换。
- Codex 从下一轮起使用新模型。
- Custom 从下一步起使用，甚至在一轮进行到一半时也可以。
- 其他 ACP 智能体如果提供模型选择，也可以切换。

会话的**思考强度**同样如此。选好之后，正在运行的智能体从下一轮起使用它。如果你切换到的模型不支持当前的思考强度，选择器会显示该模型的默认值，模型也会按这个值运行。

模型菜单只列出该会话自己的智能体的模型；保密会话则只列出这台电脑或你的专用网络上的模型。要把对话转移到另一个智能体，请使用会话的菜单（⋯）→ **转到 Codex**、**转到 Claude Code** 或**转到 Custom 智能体**（适用于 Claude Code 和 Codex 会话；Custom 在有了模型之后才会出现）。你的下一条消息会在同一个文件夹中，带着到目前为止的对话，启动该智能体的一个新会话。已停止的会话会接着用它上次使用的模型继续，除非你在发送前选了别的模型。

## Grok Build 的思考强度

Grok 的模型支持推理强度，和 Claude Code、Codex 提供的选择相同：

- Grok 4.6（以及提供同样选项的更新模型）：**xhigh**、**最高**、**medium** 或**最低**。默认是**最高**。
- Grok 4.5：**最高**、**medium** 或**最低**。

在起始页的**运行于**下选择 **Grok Build**，然后选**选项** → **思考强度**：它会列出你所选模型的各档思考强度，以及**默认**。添加 Grok Build 之后它们就会显示，甚至在它的第一次会话之前。正在运行的 Grok Build 会话可以在它自己的**思考强度**选择器（消息框下方的标签）中更改思考强度，[应用](/guide/apps)的运行也可以设置。当你把会话切换到不支持当前思考强度的模型时（例如在 Grok 4.5 上用 xhigh），选择器会显示该模型的默认值，模型也会按它运行。

这不只适用于 Grok：任何其他支持 ACP、且模型提供思考强度的智能体，都会有同样的**思考强度**选项。

## 档位：为每类工作选择合适的模型

智能体按档位而不是按名称来选择模型：**快速**用于结果可以核对的、小而非常明确的工作，**标准**用于中等规模的明确任务，**最佳**用于会话的主智能体（它负责规划、带领子智能体并检查它们的工作），**最大值**用于最难的问题。一项工作的大部分是明确的部分，更便宜的模型就能做好，所以这样一个会话花费更少，结果也不会变差：房间里最强的模型依然负责规划工作并检查成果。

在起始页上，**模型**默认停在**自动**：会话从最佳开始（同样的**自动**也用于启动[定时任务](/guide/tasks#model-effort-permissions-and-other-options)的会话，[应用](/guide/apps)也可以用档位而不是模型名称来思考）。它的主智能体会把明确的部分交给标准和快速档的子智能体，当问题被证明超出最佳档的能力时（修复已失败两次、找不到原因、需要证明），它可能会自己切换到最大值；对话中会有一行说明这一点及其原因。请求不会仅凭措辞就被送到最大值：看起来很难的问题，大多数最佳档就能解决，而且花费更少。如果改为按名称选择模型，会话就用那个模型思考；它的子智能体仍然使用档位。你自己的智能体可以只用某一个档位思考（参见[智能体用什么思考：档位](/guide/agents#what-an-agent-thinks-with-tiers)）。

[设置 → 智能体 → 模型 → 档位](/settings?s=models&find=Tiers)说明了每个档位对各个程序意味着什么：每个档位一行，分组标题旁有一个开关用来选择程序（**Claude Code**、**Codex** 或 **Custom**），每一行中有一个模型，对于 Claude Code 和 Codex 还有一个思考强度。点击档位旁的 (i) 可以了解更多。起初，对 Claude Code 而言，快速是 Haiku，标准是 Sonnet，最佳是 Opus，最大值是最新的 Fable；对 Codex 而言，快速是 Luna，标准是 Terra，最佳是 Sol，最大值是 Astra（如果你的套餐里没有其中某个，就用它提供的最接近的一个，在两个档位共用同一个模型时，较高的档位使用更高的思考强度）；Custom 的档位会自行填写：你没有改动的档位，会从 Custom 拥有的模型中取同类里最新的模型。如果来自你的 Claude 套餐，那就是快速用 Haiku、标准用 Sonnet、最佳用 Opus、最大值用最新的 Fable；否则来自你的 ChatGPT 套餐，即 Luna、Terra、Sol 和 Astra；再否则来自你添加的、不在这台电脑上（OpenRouter、某个端点）且名称属于上述系列之一的模型。这台电脑上的模型永远不会被自动选中，因为它的名称看不出强弱，而小型模型（Haiku、Luna）也永远不会成为最佳：如果只有小型或本地模型，档位就保持为空，直到你自己选择，此时 Custom 会话会沿用它所选的模型。一旦最佳指定了模型，起始页就会为 Custom 提供**自动**，它的会话会带领子智能体（即 Hydor 子智能体，因为 Custom 自己没有 Agent 工具）。在 **Custom** 标签页上，你可以为某个档位指定它的任何模型（参见[Custom 的模型从哪里来](#where-customs-models-come-from)）。你没有改动的档位，会跟随其程序中同类的最新模型。标题旁 **⋯** 菜单中的**恢复默认**会把它们恢复原状，包括 Custom 的选择。

档位下方的**会话中的档位**分组里有两个开关，决定会话如何使用档位：

- **主智能体带领子智能体**（起初为开）：会话的主智能体会被告知去规划、把明确的部分交给较便宜档位的子智能体，并检查它们的工作；未指定档位而请求的子智能体会得到标准档。关闭后，智能体各自独立工作，除非它们另有选择，并且起始页和任务表单中不再有自动。
- **难题用最高档位**（起初为开）：处于自动的主智能体，在问题被证明对最佳档太难时，可以自己切换到最大值。关闭后，处于自动的会话会停留在最佳档。

## 智能体程序会自行安装和更新

Claude Code、Codex、Gemini CLI、Grok Build 以及其他智能体，都是这台电脑上的程序。你不必手动安装它们。

打开[设置 → 智能体 → 账户](/settings?s=accounts&find=Agent%20programs)，查看**智能体程序**分组。它列出 Claude Code、Codex、Gemini CLI、OpenCode、Qwen Code、Auggie、Grok Build（添加之后）以及需要 ACP 适配器的智能体，每一行都显示会话运行的版本及其来源：

- **你自己安装的**：你自己安装的（对于 Grok Build，也包括用 xAI 自己的安装程序安装，它会装在 `~/.grok/bin`）。
- **由应用安装**：应用把它安装在自己的文件夹中。
- **随应用提供**：Codex 随应用一起提供。
- **这里没有：首次使用时会自行安装**：缺失。点击**安装**即可立即获取。

当有更新的版本发布时，某一行还会显示“… is out”。如果你自己也装了 Codex，Codex 的那一行会加上“yours in the terminal: …”：会话运行的是应用自带的，而终端运行的是你自己的。

缺失的程序在第一次需要时也会自行安装：Claude Code 在你登录它或启动 Claude Code 会话时安装，ACP 智能体在你于“设置 → 智能体 → 更多智能体”中添加它或用它启动会话时安装。应用用 npm 把它们安装到自己的文件夹中，所以不需要管理员权限。

Goose、Kimi CLI 和其他一些智能体不在这个列表中：请自己安装（“设置 → 智能体 → 更多智能体”会告诉你从哪里获取）。需要 ACP 适配器的智能体分两部分安装，即适配器和智能体本身；列表中两者合占一行。

## 让智能体程序保持最新

开启 [**自动更新**](/settings?s=accounts&find=Update%20automatically)（位于 **智能体程序** 的最后一行，默认开启，除非你把它关掉）后，应用每天会把每个智能体程序更新到最新版本。第一次运行在应用启动后约十分钟。

- 应用自己安装的副本通过 npm 在应用自己的文件夹中更新。如果有比应用自带版本更新的副本，Codex 会切换到该副本。
- 你自己安装的程序用各自的更新器更新：Claude Code 用 `claude update`，Codex 用 `codex update`（即你的终端运行的那个），OpenCode 用 `opencode upgrade`，Grok Build 用 `grok update`。
- 用 `npm install -g` 安装的 Gemini CLI、Qwen Code、Auggie、Grok Build 或带 ACP 适配器的智能体，在你的用户有权写入该文件夹时，通过 npm 更新。以其他方式安装的程序不会被处理，需要你按安装时的方式自己更新。
- Claude Code 遵循它自己的发布通道：当它的设置中写有 `"autoUpdatesChannel": "stable"` 时用稳定版，否则用最新版。
- 如果你用 `DISABLE_AUTOUPDATER=1` 关闭了 Claude Code 自己的更新（Docker 镜像就是这样），应用也不会自动更新你的 Claude Code。不过 **立即更新** 仍然可以更新它。

只有当新版本能按会话使用的方式正常工作时，应用才会保留它。Claude Code 必须在会话开始时作出响应并列出它的模型，Codex 必须启动它的应用服务器并列出它的模型，其他程序必须能启动并报告自己的版本。这些检查都不需要登录，也不会消耗你的任何套餐额度。每个程序有一分钟的响应时间，并且只计算电脑处于唤醒状态的时间，所以检查过程中进入睡眠的 Mac 不会把这一分钟用掉。第一次响应很慢的程序（Mac 在新程序首次运行前会先检查一遍）会再给两分钟重新启动，只有那时仍无响应才算失败。失败的版本会被撤销：

- 应用安装的副本，或你的、由应用通过 npm 更新的副本，会回退到之前的版本。
- 对于你自己安装的 Claude Code，会话会继续运行之前的版本，Claude Code 的安装程序把它保存在新版本旁边。终端里的 `claude` 命令则仍使用新版本。该行会显示“… did not work here”。
- 失败的版本不会自动重试，但下一个版本会被尝试，**立即更新** 也会再次尝试它。

在该行下方会显示应用上次检查的时间，例如“Up to date · checked 2h ago”，旁边的 **立即检查** 可以再次检查。有更新的版本发布时，这里会提示，并用 **立即更新** 一次性全部安装（没有针对单个程序的按钮）；更新过程中会显示正在更新哪个程序。下面几行会说明上次更新改变了什么，例如“Claude Code 2.1.308 → 2.1.316”，或者某个版本无法安装的原因。

正在运行的会话继续使用它们启动时的版本，新会话使用新版本。关闭 **自动更新** 后，应用仍会每天检查一次并显示有哪些新版本，但在你点击 **立即更新** 之前不会安装任何东西。

## 登录 Claude Code、Codex 和 Grok Build

Claude Code 和 Codex 需要先登录才能工作，添加之后的 Grok Build 也一样（参见[添加 Gemini CLI、OpenCode 和其他 ACP 智能体](#add-gemini-cli-opencode-and-other-acp-agents)）。打开[设置 → 智能体 → 账户](/settings?s=accounts)（在手机上，设置是一个分区列表：点按“智能体”下的 **账户**；顶部的标题可以带你返回）。**账户** 组（它的 (i) 说明这里是你的会话使用的 Claude Code、Codex 和 Grok Build 登录，你还可以添加另一个订阅，比如工作和个人各一个，并在开始会话时选择其中一个）会先列出每个智能体自己的登录，然后是你为它添加的账户。Grok Build 自己的登录在这里也有一行，即 **Grok Build**，添加后才会显示。每一行会显示绿色对勾以及邮箱、套餐和登录方式，或者显示红色叉号以及“Not signed in”或出错的原因。

登录步骤：

1. 点击智能体旁边的 **登录**。
2. 选择登录方式：
   - Claude Code：**Claude 订阅**（你的 Claude 套餐）或 **Console（API 计费）**（Anthropic API 账户）。
   - Codex：**设备码** 或 **浏览器跳转**。
   - Grok Build：无需选择，它始终使用验证码登录。
3. 点击 **获取登录链接**。
4. 按对话框中显示的步骤操作：
   - Claude Code：打开链接（**打开登录页面**），在浏览器中批准访问，然后把页面显示的代码粘贴到 **粘贴页面上的代码** 中，并点击 **完成登录**。
   - Codex，设备码：在任意设备上打开链接，登录 ChatGPT，并输入对话框中显示的一次性验证码。完成后对话框会自动察觉。
   - Codex，浏览器跳转：登录后，你的浏览器会尝试打开一个“localhost”页面并失败。复制该页面的地址，粘贴到 **粘贴浏览器中的 localhost 地址** 中，并点击 **完成登录**。
   - Grok Build：你会得到一个链接和一个一次性验证码。在任意设备上打开链接，用你的 Grok 账户登录，并确认验证码（**2. 确认此验证码**）。不需要粘贴任何内容：完成后对话框会自动察觉。

成功后你会看到“Claude Code is signed in”（或 Codex、Grok Build）。如果失败，对话框会说明原因；点击 **重试**。

登录之后，按钮会变为 **切换账户**：它会为另一个账户启动同样的登录（Grok Build 则是一个新的验证码）。**退出登录** 在该行的 **⋯** 菜单中：确认后，它会在这台电脑上让该程序退出登录，所有使用它的终端和编辑器都会受影响。

如果你在 Grok Build 未登录时启动 Grok Build 会话，会话会停止，并显示“Grok Build is not signed in: sign in with your Grok account in Settings → Agents → Accounts, then try again.”请在那里登录，然后重新发送你的消息。放在智能体环境中的 `XAI_API_KEY` 里的 xAI API 密钥，也可以代替订阅供 Grok Build 使用。

欢迎导览（在侧边栏的 **帮助** 中）会询问你想使用哪些智能体和模型，并带你完成这些登录。

## 添加第二个账户（工作和个人）

你可以登录多个 Claude Code、Codex 或 Grok Build 账户，例如一个工作套餐和一个个人套餐，并为每个会话选择其中一个。

1. 打开[设置 → 智能体 → 账户](/settings?s=accounts&find=Accounts)。
2. 点击 **账户** 组标题旁边的 **添加账户**。
3. 选择 **Claude Code**、**Codex** 或 **Grok Build**（设置好 Grok Build 之后才会提供），输入名称（最多 40 个字符，如“工作”或“个人”），然后点击 **添加并登录**。
4. 新账户的登录对话框会打开。按上文所述登录。

每个添加的账户各自登录，并保留各自的会话历史。你的设置、指令、技能和插件与该智能体的主登录共享，所以更改会同时作用于两者。对于 Claude Code，你用主登录信任过的文件夹，对添加的账户同样受信任，因此该文件夹自己的权限规则也适用于这个账户的会话。同一个智能体的两个账户不能重名。

添加的 Grok Build 账户有自己的文件夹，存放它的登录信息和 Grok 自己的会话历史。它与你的主登录共享 Grok CLI 自己的设置：配置、规则（`AGENTS.md`）、技能、插件和 MCP 登录。

每个添加的账户在该智能体自己的登录下面都有单独一行，带有 **登录** 或 **切换账户**；它的 **⋯** 菜单中有 **退出登录**、**重命名** 和 **移除**：

- **重命名** 会请你输入新名称。
- **退出登录** 会让以此账户运行的会话无法工作，直到它重新登录。
- **移除** 会把账户从应用中去掉。它的会话会从列表中消失，但历史仍保留在磁盘上，除非你同时勾选 **同时删除它的登录信息和会话历史**。当有会话正在以该账户运行时，你不能移除它：请先停止这些会话。

[用量页面](/usage)会为每个添加的 Claude Code、Codex 或 Grok Build 账户显示一张卡片，上面是它自己的限额。

## 选择会话使用的账户

当你选择的智能体有添加的账户时（对于 Grok Build，则是在你添加了账户之后），开始页面的 **选项** 中会出现 **账户** 一行。点击它：

- **你的登录** 是该程序自己的账户（即 **账户** 中该智能体的第一个；对于 Grok Build 是“The Grok Build CLI's own account”）。
- 每个添加的账户都按名称列出。
- **管理账户** 会打开设置 → 智能体 → 账户。

开始页面会记住你为该智能体所做的选择，在所有位置都一样。以添加的账户运行的会话，会在会话顶部显示该账户的名称，并带有一个人形图标。如果该账户达到了用量限额，消息框上方的限额提示就是针对该账户的。账户在会话开始时确定。只有 **达到限额时切换账户**（见下文）会让它自动改变。

如果你想自己把会话移到另一个账户，请点击会话自己的 **账户** 标签并选择一个。这适用于 Claude Code、Codex 和 Grok Build 会话，并从你的下一条消息开始生效。Grok Build 会话的 Grok 历史会随之移动；如果 Grok 无法在另一个账户下重新打开它，会话会在那里重新开始，并附带一条说明。

## 用上你所有的账户：达到限额时切换

当同一个智能体有两个或更多账户时，应用可以把它们都用起来：一个账户的用量耗尽时，你的工作会换到另一个账户继续。打开[设置 → 智能体 → 账户](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit)，找到 **账户** 下 **达到用量限额时** 组中的 **达到限额时切换账户**，只要你添加了任何账户（包括 Grok Build 的）它就会显示（它的 (i) 说明：当会话的账户用量耗尽时，会话会转到该智能体另一个还有用量的账户并继续，新会话会跳过已达限额的账户）。它一开始就是开启的（如果你更想自己选账户，可以在那里关掉），并且在没有打开任何浏览器时也能工作。

- 当某一轮因会话的账户达到用量限额而停止时，应用会选择同一智能体另一个仍有用量的已登录账户（用得最少的那个），把会话连同全部历史移到那里，并发送“… reached its usage limit, so this session now runs on …. Continue where you left off.”屏幕底部的一条简短提示会说明移到了哪个账户。
- Claude Code 会话在后台运行的子智能体也会继续。限额触发时仍在工作的子智能体会在下一步停止，已完成的工作会保留，应用会等待它们（最多两分钟）之后再移动会话。随后的消息会点名它们，智能体会让每一个从停下的地方继续。如果只有子智能体达到了限额（比如仅针对它们所用模型的限额），会话会在这一轮结束且没有子智能体仍在工作后再移动。
- Hydor 子智能体（智能体为完成部分工作而启动的会话）本身就是独立的会话，所以当限额使某一轮停止时，每一个都会自行移动。启动它的智能体收到的是它会继续，而不是失败的消息，并在它完成时得到它的回复。
- 你的主登录和每个添加的账户都算在内。Claude Code 账户由 Claude Code 账户接替，Codex 由 Codex 接替，Grok Build 由 Grok Build 接替。
- Grok Build 账户在达到每周限额、额度限额或按量付费的花费上限时即算达到限额。此时会话会转到另一个仍有用量的已登录 Grok 账户（用得最少的那个），并以“… reached its usage limit, so this session now runs on …”继续。短暂的速率限制（一阵密集的请求）不会触发任何移动：它会自己过去。消息框上方的限额提示对 Grok 会话同样会显示。
- Codex 目标会随会话一起移动并继续进行。
- 当所有账户都达到限额时，不会有任何移动（除非开启了下面提到的 **达到限额时使用 API 额度**，适用于 Claude Code）。开启 **用量限制解除后继续** 后，会话会在第一个账户重置时，在该账户上继续。这同样适用于 Grok Build 会话。详见[用量、限额和费用](/guide/usage#continue-sessions-automatically-after-a-limit)。
- 在已达限额的账户上新启动的会话，会改在仍有用量的账户上启动；而你发送给其账户已达限额的会话的消息，会先让会话移动，这样消息就不会被拒之门外。随着你的消息，智能体会得知它现在运行在一个仍有用量的账户上，所以不会去等旧账户的重置，也会知道它的哪些子智能体可以继续。
- 在 VS Code 或终端中打开的会话会留在它们的账户上。
- 限额重置（Codex 重置额度、Claude 重置授予）和 API 额度仍然只适用于 Claude Code 和 Codex。
- 应用自己向 Claude Code 或 Codex 提出的快速问题（设为 **自动** 的辅助模型、应用的快速模型步骤、拉取请求描述、命令建议），在其中一个达到限额或已退出登录时，同样会交给你的下一个已登录账户。当 Claude Code 和 Codex 都无法回答时，你的某个 Custom 模型会顶上（参见[账户退出登录时](#when-an-account-is-signed-out)）。

## 账户登出时

Claude Code、Codex 或 Grok Build 的账户可能会被登出：它的登录已结束或被撤销，程序会提示 “Not logged in · Please run /login” 或 “401 Unauthorized”。应用会尽可能自行绕过这个问题，只有在没有其他办法完成工作时，才会请你重新登录。

- **你的会话.** 当某个会话的一轮对话因其账户已登出而被拒绝，且[达到限额时切换账户](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit)已开启（默认即为开启）时，该会话会连同全部历史记录，转移到同一智能体的另一个已登录且仍有用量的账户，并继续运行。屏幕底部会显示一条简短提示：“<session>: <account> is signed out, so it continues on <other account>”，同时智能体会收到这样的通知：“… is signed out, so this session now runs on …. Continue where you left off.” 如果你向一个不久前被发现账户已登出的会话发送消息，它会先以同样的方式转移，这样你的消息就不会被拒绝。
- **会话无法转移时。** 如果 **达到限额时切换账户** 已关闭，或者该智能体没有其他账户还有用量，会话就会停止。其消息框上方会出现一条横幅，写着 “<account> is signed out” 和 “This session continues once you sign in again.”，并带有 **登录** 按钮。一旦你重新登录（无论是在这里还是在终端里），会话会自行继续，智能体会收到通知：“Signed in again. Continue where you left off.”
- **后台工作。** 设为 **自动** 的[辅助模型](/settings?s=models&find=Helper%20model)所做的小任务（会话标题、记忆备注、精简[你的个人资料](/guide/memory#your-profile)、应用的快速模型步骤、拉取请求描述等）会先跳过已登出的账户，15 分钟后再次尝试，因此你在终端里完成的登录会被发现。接下来由下一个已登录的账户回答，然后是 Codex。当 Claude Code 和 Codex 都无法回答（已登出、达到限额或未安装）时，会由你的某个 **Custom** 模型来完成：即 [设置 → 智能体 → 模型 → 档位](/settings?s=models&find=Tiers)中 Custom 的 **快速** 档位所指定的模型（其次是 **标准**，遇到少见的较大任务则先 **最佳**，再 **最大值**），否则就用你添加的最便宜的模型（本机上的模型视为免费）。最多尝试两个。它的花费与其他 Custom 模型的使用一样计算。
- **登录提示。** 只有在没有任何办法完成工作、且有账户已登出时，才会在每个页面的右下角显示一张卡片（手机上位于消息框上方）。卡片标题是 “Sign in to Claude Code again”（或 Codex、Grok Build），下面是 “<account> is signed out.”，以及它要求登录的原因：“Background work needs it (shortening your profile), and no other account or Custom model could do it.”，如果是它停止的会话，则是 “… continues once you sign in.” **登录** 会打开与[设置 → 智能体 → 账户](/settings?s=accounts)相同的登录对话框。**暂不** 会把这张卡片隐藏一小时；因此而停止的会话会再次显示这张卡片，而该会话中的横幅会保留。同时最多显示两张卡片，其余的以 “+N more” 显示，点击后会前往 设置 → 智能体 → 账户。账户重新登录后（无论是通过卡片、设置还是终端，应用会在下一次成功的调用时发现），卡片就会消失。当后台工作通过其他方式重新完成时（由其他账户或 Custom 模型回答），卡片也会消失。当 Claude Code 和 Codex 都已登出时，只会询问先回答的 Claude Code。

你的个人资料也会显示这一情况：当精简它因账户已登出而失败时，其下方的原因会说明这一点（“Your Claude Code account “Work” is signed out, and no other account or Custom model could do this: sign in again (Settings → Agents → Accounts).”），同时卡片会出现。

## 所有账户都达到限额时使用 API 额度

如果你有 Anthropic API 密钥（来自 [console.anthropic.com](https://console.anthropic.com) → API keys），当每个 Claude Code 账户都达到用量限额时，你的 Claude Code 会话可以用它继续运行，而不是停止。这是要花钱的：只要会话以这种方式运行，Anthropic 就会按 API 价格向你计费，不在你的订阅范围内。

1. 打开[设置 → 智能体 → 账户](/settings?s=accounts&find=Use%20API%20credit%20at%20a%20limit)。在 **账户** 中某个 Claude Code 账户所在的行（你的主登录账户，或你添加的账户）上，点击 **⋯**，然后点击 **添加 API 密钥…**。
2. 在 **Anthropic API 密钥** 中粘贴密钥，然后点击 **保存密钥**。应用会向 Anthropic 验证它，并将其加密保存在这台电脑上。该行随后会显示 **API 额度** 标签。**更改 API 密钥…** 可替换密钥，**移除 API 密钥** 可删除密钥。
3. 在 **达到用量限额时** 分组中，打开 **达到限额时使用 API 额度**（它的 (i) 说明：当每个 Claude Code 账户都达到用量限额时，会话会改为按某个账户的 Anthropic API 密钥计费并继续运行，而不是停止；在你打开之前它是关闭的）。登录 Claude Code 或添加 Claude Code 账户后，这个选项才会显示。

接下来会发生的事：

- 当某个 Claude Code 会话的账户达到用量限额时，应用会先尝试 **达到限额时切换账户** 所做的事：换到另一个仍有用量的账户。只有在没有任何账户还有用量、且该设置已开启时，会话才会按 API 密钥计费并继续运行。
- 会话仍然留在它自己的账户上，因此历史记录不会转移。如果该账户没有密钥，就会使用另一个 Claude Code 账户的密钥。
- 会话顶部其账户旁会显示 **API 额度** 标签。把鼠标悬停在上面可以看到原因。
- 当某个套餐重新有用量时，会话会在下一轮结束后回到该套餐：回到它自己的账户，或另一个仍有用量的账户。你不需要做任何事。
- 如果应用无法读取某个账户的用量，就绝不会把你的工作转到 API 计费上。
- Codex 不受影响：它没有 API 额度。

## 添加 Gemini CLI、OpenCode 和其他 ACP 智能体

打开[设置 → 智能体 → 更多智能体](/settings?s=agents&find=Agents%20that%20speak%20ACP)。

- **你的智能体**（开始会话时，它们会显示在 Claude Code 和 Codex 旁边）先列出 Custom，再列出你添加的智能体。如果其程序已安装在这里，每个智能体会显示一个对勾；否则显示叉号和 “not installed”。
- **支持 ACP 的智能体**（先安装一个，在它自己的 CLI 中登录一次，再回到这里添加）列出你尚未添加的已知智能体：Gemini CLI、OpenCode、Qwen Code、Goose、Kimi CLI、Auggie、Grok Build 等。已安装的排在前面。显示 “Not installed” 的行会说明如何获取它。列表会显示前几个未安装的智能体；**全部显示** 可显示其余的。

添加方法：

1. 点击它所在行末尾的 **添加**。如果程序已经安装，这个按钮会更醒目。
2. 如果应用知道如何安装它（Gemini CLI、OpenCode、Qwen Code、Auggie、Grok Build，以及需要 ACP 适配器的智能体），现在就会在后台安装。Goose、Kimi CLI 和其他智能体需要你自己安装，用它们所在行中的命令或地址即可。
3. 在智能体自己的程序中登录一次：打开[终端](/terminal)，运行它的命令（例如 `gemini`），然后按提示登录。如果你跳过这一步，会话会告诉你：“Gemini CLI is not signed in. Run gemini once in a terminal and sign in there, then try again.”

此后该智能体会显示在开始页面的 **运行于** 列表中。

要修改已添加的智能体，点击 **编辑**。要移除它，打开它的 **⋯** 菜单，选择 **移除** 并确认：它的会话仍会保留在列表中，但要继续这些会话，需要重新设置该智能体。Custom 是内置的：它所在的行写着 “Built in: models from OpenRouter, Ollama and vLLM, in Settings → Models”，并且有一个 **模型** 按钮，而不是“编辑”和“移除”。

### Grok Build

**Grok Build** 是 xAI 的编码智能体（即 `grok` 程序）。点击它所在行的 **添加**，这样就完成了：应用会在第一次需要时通过 npm（`@xai-official/grok`）安装它，或者使用这里已有的版本，包括来自 xAI 自带安装程序、位于 `~/.grok/bin` 的版本。之后它会显示在 **智能体程序** 下，并与其他智能体一起保持更新。Hydor 通过 ACP 运行它，使用应用自己的工具、批准卡片和 Grok 的模型。

它的登录方式与其他 ACP 智能体不同：不是在终端里，而是在[设置 → 智能体 → 账户](/settings?s=accounts)中，添加之后那里会立即出现一行 **Grok Build**（参见[登录 Claude Code、Codex 和 Grok Build](#sign-claude-code-codex-and-grok-build-in)）。你也可以在那里添加更多 Grok 账户。

### 添加你自己的智能体

任何支持 ACP 的程序都可以在这里运行。

1. 点击 **Your agents** 标题旁的 **添加你自己的**。
2. 填写：
   - **名称**：它在列表中的显示名称，例如 “Gemini CLI”。
   - **命令**：要启动的程序，例如 `gemini`，或完整路径。
   - **参数**：用于以 ACP 模式启动它的内容，例如 `--experimental-acp`。
   - **环境变量（可选，每行一个 NAME=value）**：程序需要的设置，例如 API 密钥变量。
3. 点击 **保存**。

该命令必须以 ACP 模式启动智能体，并通过其标准输入和输出进行通信。

### 在智能体自己的程序中设置的智能体

列表中有些智能体是需要你自己设置的程序，与应用替你安装的智能体相比有几点不同：

- 它们在 **更多智能体** 中所在的行会显示安装用的命令或地址。应用不会替你运行来自网络的脚本：请自己安装，在[终端](/terminal)中，或按该行所说的方式。
- 在智能体自己的程序中登录一次，同样可以在终端里完成（例如运行它的命令并按提示登录，或在那里选择它的模型）。之后应用就会启动它。它会把自己的会话和记忆保存在自己的文件夹中，批准卡片也是它自己提供的那些。
- 其中一个智能体会连接到它自己的网关：请先用该智能体自己的设置命令把它设置好，并保持网关运行。
- 当某个智能体本身不支持 ACP 时，它需要一个 ACP 适配器。应用会把适配器与智能体一起安装，两者都通过 npm 装在它自己的文件夹中，且不运行它们的安装脚本。你自己安装的智能体，只要在 PATH 中就会被使用。
- 不接受任何 MCP 服务器的智能体只能使用它自己的工具：应用的工具（页面、搜索等）无法到达它，会话启动时会这样提示。它仍会在第一条消息中收到应用的准则、记忆备注和技能。

### ACP 智能体在这里能做什么、不能做什么

应用会在你选择的文件夹中打开会话，显示智能体的消息和步骤，并在智能体请求权限时询问你。有些地方与 Claude Code 和 Codex 不同：

- 它一次只处理一条消息。你在它工作时发送的消息会在消息框上方的队列中等待，并在这一轮结束时发出。（Custom 也是这样。）
- 无法重新打开早先会话的智能体，在你继续旧会话时会重新开始，不带之前的对话内容。会话会说明这一点。如果智能体以前能重新打开会话、现在不能了，也会这样：它会带着一条提示重新开始，而不是失败。
- 你附加的图片只有在它支持图像时才会送达。
- 目标、分叉和交接不可用（Custom 有目标和分叉）。
- 应用的工具（页面、搜索、记忆等）会作为 MCP 服务器送达智能体：智能体接受时通过地址，否则通过应用为它启动的一个小程序。不接受其中任何一种的智能体只能使用它自己的工具，但仍会收到准则、记忆备注和技能。

## Custom 的模型来自哪里

Custom 可以运行你的 Claude 和 ChatGPT 订阅方案中的模型、这台电脑上的模型以及云端的模型，并使用与其他智能体相同的工具、技能和 MCP 服务器。在起始页选择 Custom，然后选择模型。模型来自三个地方：

- **你的订阅**：你的 Claude 和 ChatGPT 订阅方案中的模型，通过这台电脑上 Claude Code 和 Codex 的登录状态使用。无需任何设置：当 Claude Code 已登录时，Custom 的**模型**菜单会提供 Claude Opus、Fable、Sonnet 和 Haiku（始终是各自最新的版本）；当 Codex 以 ChatGPT 登录时，会提供你的 ChatGPT 方案所列出的模型（例如 GPT-6 Luna）。如果发现某个程序处于退出登录状态，它的模型会从菜单中消失，直到你重新登录；如果 Codex 是用 API 密钥而不是 ChatGPT 登录的，则不会提供任何模型。这些模型使用的是你订阅方案的用量，而不是 API 密钥，也不按 token 计费，因此使用它们的 Custom 会话在这些步骤上显示 $0。同一个程序的每个账户会依次尝试，与其他一次性工作相同：某个账户达到用量限额或已退出登录时，会把这一步交给你的下一个账户（需开启**达到限额时切换账户**）。[保密会话](/guide/sessions#keep-a-session-confidential)从不使用这些模型，因为它们运行在 Anthropic 或 OpenAI 的服务器上。关于它们如何回答，请参阅 [Custom](/guide/custom#what-custom-is-and-when-to-use-it)。
- **在这台电脑上**：安装在本机的模型（Ollama、vLLM），以及你网络中的端点。
- **在云端**：OpenRouter、其他位置的端点，以及 Ollama 的云端模型。

你可以在任何可以选择 Custom 模型的地方选择它们：起始页、会话的模型菜单、Custom 的档位、辅助模型，以及智能体或应用的模型。

[设置 → 智能体 → 模型](/settings?s=models)包含 Custom 模型所需的一切。该页面从上到下分为七个部分：

- **辅助模型**：负责应用中各种小任务的模型。
- **档位**：为每一类任务指定一个模型（参见[档位：为每一类任务指定一个模型](#tiers-a-model-for-each-kind-of-job)）。
- **你的订阅**：Claude Code 和 Codex 各占一行，显示它提供给 Custom 的模型。某一行会显示“已退出登录：请重新登录以使用这些模型”，并附带指向**账户**的链接，或者显示“未安装在这台电脑上”。
- **在本机**：这台电脑的配置，以及安装在本机的模型。
- **从 Hugging Face 添加模型**：搜索、检查并安装开放模型。
- **OpenRouter**：通过一个密钥使用数百个模型，分为三组：你的密钥、你添加的模型，以及用于添加更多模型的搜索。
- **运行时和端点**：Ollama、vLLM、其他兼容 OpenAI 的服务器，以及 Hugging Face 令牌。

在 Custom 的**模型**菜单中，模型按**你的订阅**、**在这台电脑上**和**在云端**分组，每一行都会标明它通过什么提供：“Claude Code”“Codex”“OpenRouter”“Ollama”“vLLM”或某个端点的名称。把鼠标悬停在模型上，可以看到它在哪里运行以及一次能读取多少内容，例如“OpenRouter · 128K 上下文”或“vLLM，在本机 · 32K 上下文 · 使用时启动”。这些列表每分钟自动刷新一次。

## 选择辅助模型

辅助模型在你的会话之外处理一些小任务，不属于任何对话：

- 根据你的请求为每个新会话命名（即它在侧边栏中的标题）；
- 在 Custom 的自动模式中检查步骤，并在每一轮之后检查 Custom 的目标；
- 大约每天整理一次记忆，从之后的对话中学习，并为智能体启动时使用的索引给备注拟定标题；
- 回答关于浏览器中已打开网页的某个问题；
- 在 Naget Search 搜索之前，读取网络搜索的措辞所表达的筛选条件（网站、日期、网页类型、语言）（参见[智能体如何搜索网络](/guide/web#how-agents-search-the-web)）；
- 为无法看图的 Custom 模型描述图片；
- 总结 Hydor 子智能体的长篇回复；
- 根据会话起草应用或定时任务；
- 免提语音模式。

打开[设置 → 智能体 → 模型](/settings?s=models&find=Helper%20model)，点击**辅助模型**组中的**模型**菜单（其 (i) 列出了这些小任务）：

- **自动**（默认）：通过 Claude Code 使用 Claude Haiku，当 Claude Code 无法回答时使用 Codex。某个账户达到用量限额时，会先把问题交给你下一个已登录的账户（需开启**达到限额时切换账户**），已退出登录的账户会被跳过。当两个程序都无法回答时，由你的某个 Custom 模型来完成（即 Custom 的**快速**档位所指定的模型，否则是你添加的最便宜的模型；这里会跳过你订阅方案中的模型，因为它们走的是同样的两个程序），只有在没有任何模型能完成时，才会出现一张卡片请你登录（参见[账户退出登录时](#when-an-account-is-signed-out)）。当没有任何模型回答时，错误信息会分别说明原因：“你已达到每周限额”、你的 Codex 方案不提供的模型……
- Custom 的任意模型，分组方式与 Custom 的**模型**菜单相同（**你的订阅**、**在这台电脑上**和**在云端**），并标明它通过什么提供（Claude Code、Codex、OpenRouter、Ollama、vLLM 或某个端点的名称），能看图的模型还会标注“**能看图片**”。你的 Claude 或 ChatGPT 订阅方案中的模型也可以作为辅助模型：它通过 Claude Code 或 Codex，使用你订阅方案的用量来回答。

**自动**无法查看图片。如果你使用的 Custom 模型不能看图，请选择一个能看图的辅助模型，否则 Custom 无法为你的图片生成描述。

## 查看这台电脑能运行什么

[设置 → 智能体 → 模型](/settings?s=models&find=On%20this%20machine)中的**在本机**部分，开头是这台电脑的概览：

- **显卡**：显卡（GPU）及其显存；在搭载 Apple 芯片的 Mac 上，则是它的芯片（“Apple M3 Max”，其图形处理共用电脑的内存）；或者显示“无 GPU”（此时模型在处理器上运行）。
- **内存和磁盘**：电脑的内存（总量和可用量），以及磁盘的可用空间和已安装模型占用的空间。
- **运行方式**：**Ollama** 和 **vLLM** 是否已安装及其版本，或者一个安装它们的链接。
- 如果有显卡，会显示能容纳多大的模型：“在一块 GPU 上大约可容纳 4 位的 30B 参数”（在 Mac 上：“大约可容纳 4 位的 40B 参数”）。参数是衡量模型大小的单位；4 位是一种常见的压缩形式，只需约四分之一的内存。

其下是：

- **进行中的下载**，每项都有进度条、已完成的量，以及它是用于 Ollama 还是 vLLM。**取消**会停止某一项下载。失败或已取消的下载会显示原因，并附有**关闭**。
- **已安装的模型**（先显示前几个，然后是**全部显示**），每个都显示它的运行时（Ollama 或 vLLM）、大小、详细信息（例如 Ollama 模型的大小和压缩方式）、能看图的会标注“能看图片”，以及它是否正在运行。
  - vLLM 模型有**开始**和**停止**。会话第一次使用它时会自动启动（首次启动需要一两分钟），在空闲显存最多的显卡上运行（如果原样放不下，则采用 8 位），当没有任何一块显卡放得下时，则分到 2、4 或 8 块显卡上（“运行在 GPU 1、2 上”）；在 Mac 上则运行在它的 Apple 芯片上。它会一直运行，即使应用重启也不会停止，直到你点击**停止**。如果无法启动，原因会显示在它下方。
  - 模型的 **⋯** 菜单中的**移除**，会在你确认后从这台电脑上删除该模型的文件。你以后可以重新安装。

如果还没有任何模型：“这里还没有模型：请在下方从 Hugging Face 添加。”

## 从 Hugging Face 添加模型

Hugging Face 是开放模型的主要网站。[从 Hugging Face 添加模型](/settings?s=models&find=Add%20a%20model%20from%20Hugging%20Face)这一组会推荐一些适合这台电脑的模型，也可以搜索全部模型，并在下载任何内容之前，告诉你每个模型在这台电脑上会如何运行。

### 为这台电脑推荐

在你搜索之前，这一组会根据这台电脑的配置，列出应用推荐的、可在这台电脑上运行的模型：

- **LFM3-VL 2B**（Liquid AI）：小巧而快速，能读取图片。几乎在任何电脑上都能运行。
- **Gemma 4 12B**（Google）：能力全面、能读取图片，适合配有好显卡的电脑。
- **Flint**（Recursive）：专为编程智能体打造，适合内存 32 GB 或以上、搭载 Apple 芯片的 Mac。
- **GLM-5.3 Flash**（Z.ai）：最强的开放模型之一，适合配有多块大显存显卡的服务器。

每个模型都会显示它在这里运行得流畅还是缓慢、会如何运行（“8 位的 vLLM，在 GPU 0 上”“vLLM，分到 2 块 GPU 上”“vLLM，在 Apple 芯片上”）、下载大小，以及**安装**。**本机最佳**标记的是能流畅运行的模型中最强的一个。它们默认使用 vLLM 运行；既没有 NVIDIA 显卡也没有 Apple 芯片的电脑，则会改为获得小型模型的 Ollama 版本。如果运行它们所需的程序尚未设置，会出现警告（“vLLM 尚未设置”“Ollama 未在运行”）：请参阅[连接 Ollama、vLLM 或其他端点](#connect-ollama-vllm-or-another-endpoint)。“**还有 2 个适合更强大的电脑**”这一行（数字会相应变化）会显示其余的模型，以及各自的要求。欢迎导览推荐的也是这些模型。

### 搜索和筛选

1. 在**搜索 Hugging Face，或粘贴 org/name**中输入：可以是 `qwen3` 这样的名称，也可以是模型的完整名称（`org/name`）或它的 huggingface.co 地址。输入之前，它会推荐几个名称，或者**查看下载最多的**。
2. 用筛选条件缩小列表（可以组合使用）：
   - **在这里运行流畅**：只显示在这台电脑上能流畅运行的模型。
   - **GGUF · Ollama**：GGUF 格式的模型，由 Ollama 运行。
   - **vLLM**：safetensors 格式的模型，由 vLLM 在显卡上运行。
   - **能看图片**：同时能读取图片的模型。
3. 用右侧的菜单更改排序：**下载最多**、**热门**、**最受喜爱**或**最新**。

最多会显示 40 个模型，起初显示前八个，其余的点击**全部显示**。你输入了完整名称的模型会排在最前面，即使搜索没有列出它，直接按回车也会马上检查它。

每一行会显示开发者和名称、它的格式（**GGUF** 或 **vLLM**）、如果能看图则显示**图片**、如果开发者要求你先接受条款则显示**受限**、以参数量表示的大小、最近 30 天的下载量、点赞数，以及最后更新时间。

### 初步判断

每个模型下方有一个彩色标签，仅根据它的大小给出初步判断：

- **用 vLLM 运行流畅**或**用 Ollama 运行流畅**，并附带大致速度（“约 40 tokens/s”；token 是词的一小段）：它放得进你显卡的显存。
- **用处理器运行，较慢**或**用处理器运行，非常慢**：它只放得进电脑的内存，因此在处理器上运行。只有 Ollama 能做到这一点。
- **对这台电脑来说太大**：它放不下，或者下载内容放不进磁盘。
- **用 Ollama 以 4 位运行：运行流畅……**：模型按原样存储时太大，但它压缩后的 4 位版本用 Ollama 可以流畅运行。

把鼠标悬停在标签上，可以看到判断所依据的数字。

### 下载前先检查

点击某个模型上的**检查**，可以确切了解它在这里会如何运行。面板会显示它的大小、一次能读取多少内容（即上下文）、它能否看图，然后是：

- 对于 GGUF 模型：“用 Ollama 运行”，以及每个可用的大小（较小的文件以少许质量换取速度和内存），从最小的开始。每一行会给出它的判断、所需内存、大致运行速度和下载大小，并带有**安装**按钮。当 Ollama 没有在这里运行，或者某个大小太大时，“安装”会呈灰色。
- 对于 vLLM 模型：“用 vLLM 运行，会话使用它时由 vLLM 在 GPU 上启动”，同样的数据，关于会使用哪块显卡的说明，以及一个**下载**按钮。如果未安装 vLLM，或者你的 vLLM 暂时无法运行这类模型，面板会这样说明；如果存在 GGUF 版本，则会提供对该版本的**检查**。
- 对于其他情况：“没有本应用能运行的权重（vLLM 用 safetensors，Ollama 用 GGUF）。”

这些数据假设对话最长约 32,000 个 token，这是这台电脑上的模型所获得的长度。**关闭**会收起面板。

### 安装，以及接下来会发生什么

点击**安装**（Ollama）或**下载**（vLLM）。下载会连同进度显示在**在本机**中。完成后，该模型会出现在 Custom 的**模型**菜单里。中途被中断的 vLLM 下载，在你再次尝试时会从停下的地方继续。对于任何一块显卡都放不下的 vLLM 模型，会在启动时以 8 位（FP8）存储，这样它的权重占用的内存减半而损失很小（适用于 NVIDIA RTX 30 系列及以后的显卡和 A100）；如果仍然放不下，且几块显卡合计有足够空间，就会把它分到多块显卡上。

### 受限模型和私有模型

有些开发者要求你先接受他们的条款；这些模型会显示**受限**。请在 huggingface.co 上该模型的页面接受条款，然后添加 Hugging Face 令牌（参见 [Hugging Face 令牌](#hugging-face-token)）。私有模型同样需要令牌。

## 通过 OpenRouter 使用模型

OpenRouter（openrouter.ai）通过一个密钥为你提供来自众多厂商的数百个模型，按使用量付费。

### 添加你的密钥

1. 在 openrouter.ai 获取一个密钥（该部分有链接指向那里）。
2. 在 [设置 → 智能体 → 模型](/settings?s=models&find=OpenRouter) 中，点击 **你的 OpenRouter 密钥** 一行中的 **添加密钥**，在弹出的对话框里把密钥粘贴到 **你的 OpenRouter 密钥：sk-or-…**，然后点击 **保存**。

随后这一行会显示 **已连接到 OpenRouter**，以及密钥的开头和结尾。其 **⋯** 菜单中的 **移除密钥** 会让应用忘记这个密钥。密钥保存在服务器上，之后不会再显示。

你也可以在第一次需要时再添加：如果智能体要生成图片、绘图、视频或声音，而你还没有密钥，它会在对话中用一张卡片向你索取（[智能体需要 OpenRouter 密钥时](/guide/documents-voice#when-an-agent-needs-the-openrouter-key)），编辑器里的 AI 工具则会在对话框中询问。无论哪种方式，密钥都保存在这里。

### 推荐模型

在你搜索之前，**添加 OpenRouter 模型** 组中的 **推荐** 会为 Custom 列出四个模型，并附上推荐理由：**GPT-6 Luna**（快速且便宜）、**Grok 4.7**（表现不错，拒绝回答的情况更少）、**GPT-6.1 Sol**（更好）和 **Claude Opus 5.5**（综合最佳）。点击 **添加** 即可把其中一个放进模型选择器。对于图片、音乐、语音和视频，应用选用的是 Seedream 5.0 Pro（以及更快更便宜的 Flash）、Lyria 3 Pro、Seed Audio 1.0 和 Seedance 2.5：请参阅 [设置 → 功能 → 图片、视频和音频](/settings?s=images)。

### 搜索目录

在同一组中，在 **搜索 OpenRouter：deepseek、qwen、claude…** 中输入内容，或点击某个推荐的名称，或点击 **查看最新的**。可用的筛选项：

- **工具调用**：原生支持调用工具的模型，这是 Custom 用起来效果最好的方式（**最佳匹配** 会把这些模型排在前面）。
- **能看图片**
- **推理**：先思考再回答的模型。
- **免费**

右侧的菜单用来为结果排序：**最佳匹配**（按名称搜索时）、**最新**、**最便宜** 或 **最长上下文**。最多会得到 50 个模型，起初显示前八个，其余的点击 **全部显示** 查看。

每个模型都会显示其厂商、名称和标签：**最新**（始终是厂商的最新版本）、**新增**（最近三周内上架）、**免费**、**推理**、**图片**，以及 **无原生工具**（此时 Custom 会在指令中描述它的工具，并从它的文本中读取调用）。下方依次是：一次能读取的内容量（“128K context”）、最长回复（“16K out”）、每百万词元的输入和输出价格、上架的月份、简短说明和它在 OpenRouter 上的名称。

### 把模型添加到选择器

点击模型上的 **添加**。该行随后会显示 **已添加**，模型会出现在搜索框上方的 **你的 OpenRouter 模型** 组（“在模型选择器中”）里，也会出现在 Custom 的 **模型** 菜单中。点击其中某个模型上的 × 即可把它从菜单中移除。在你至少添加一个模型之前，OpenRouter 不提供任何模型（“Add at least one model to use OpenRouter.”）。

## 连接 Ollama、vLLM 或其他端点

**运行时和端点** 组用来连接运行模型的程序。你可以在 [设置 → 智能体 → 模型](/settings?s=models&find=Runtimes%20and%20endpoints) 中打开它。

### Ollama

Ollama 是一款免费程序，可以在你的电脑上用显卡或处理器运行模型。它所在的行会显示“running”和版本号，或者显示“not running at this address”，并附带一个 **安装 Ollama** 链接。它的地址默认是 `http://127.0.0.1:11434`，除非你修改：在输入框中输入另一个地址，旁边就会出现 **保存**。该 Ollama 中的每个模型都会显示在 Custom 的模型列表里，包括你在应用之外拉取的模型。

### vLLM

vLLM 是面向 NVIDIA 显卡的高速模型服务器，也是来自 Hugging Face 的模型在这里默认的运行方式。对一张显卡来说太大的模型，可以用 8 位精度在其上运行，或拆分到 2、4 或 8 张显卡上。在 Mac 上，vLLM 借助它的 Metal 插件（vllm-metal）在 Apple 芯片上运行。应用会自动在 PATH 中，或在 conda 或 venv 环境里找到它，并显示它的版本和所在位置。如果显示“not found (pip install vllm), or give its command”，请先安装它，或者在输入框中输入其 `vllm` 命令的完整路径，然后点击 **保存**（输入后才会显示）。把输入框留空，则由应用自行查找。

### 其他与 OpenAI 兼容的端点

许多程序和服务的响应方式与 OpenAI 的 API 相同：LM Studio、llama.cpp 的服务器，以及其他提供商。添加方法如下：

1. 点击该组标题旁边的 **添加端点**。
2. 在对话框中输入 **名称**、它的地址（例如 `http://localhost:1234/v1`）和 **密钥（可选）**。
3. 点击 **添加**。

该端点会显示为一行，包含它的地址和提供的模型数量。它的模型会在 Custom 的列表中显示为“model (name)”。点击 × 可将其移除。再添加一个同名端点，会替换第一个。

[保密会话](/guide/sessions#keep-a-session-confidential)可以使用地址指向这台电脑或你的私有网络的端点：`localhost`、`127.0.0.1`、`::1`、`10.…`、`192.168.…`、`172.16.…` 到 `172.31.…`，或以 `.local` 结尾的名称。任何其他地址都视为在线，即使它指向你自己的服务器：请改用它的私有地址。Ollama 的地址也适用同样的规则，而 Ollama 的云端模型（名称以“cloud”结尾）始终视为在线。

### Hugging Face 令牌

[Hugging Face 令牌](/settings?s=models&find=Hugging%20Face%20token)可让应用下载受限或私有的模型（该行显示“Only for gated or private models”）。在你的 Hugging Face 账户设置中创建一个令牌，点击 **添加令牌**，把它粘贴到对话框中（以 `hf_` 开头），然后点击 **保存**。随后这一行会显示令牌的开头和结尾，其 **⋯** 菜单中有 **移除令牌**。
