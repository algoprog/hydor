# 智能体、账户和模型

Hydor 可以运行多种 AI 智能体：Claude Code、Codex、Custom（应用自带的智能体，可使用任何模型），以及其他支持 ACP 的智能体，例如 Gemini CLI、OpenCode、Qwen Code、Goose 或 Grok Build。本主题会说明它们有何不同，它们的程序如何安装并保持最新，如何登录（也包括登录多个账户），以及 Custom 的模型从哪里来：OpenRouter、Ollama、在这台电脑上运行的 Hugging Face 模型，或任何兼容 OpenAI 的端点。

![在起始页选择智能体：Claude Code、Codex 或 Custom](images/agents-models.webp)

## 我该用哪个智能体？

智能体是在会话中干活的程序：它读取你的消息，使用工具（文件、命令、网络），然后给出回答。模型则是它背后的 AI。这里的每个智能体都能得到应用提供的同样的帮助（网页搜索、浏览器、记忆、技能、你的连接），区别在于它们的模型来自哪里。

- **Claude Code**（Anthropic）。使用你的 Claude 套餐运行，或向 Anthropic API 账户计费。它的模型是 Anthropic 的（Opus、Sonnet、Haiku）。它有自己的用量限制，可在[用量页面](/usage)查看。
- **Codex**（OpenAI）。使用你的 ChatGPT 套餐运行。它的模型是 OpenAI 的。它同样有用量限制，也显示在用量页面。Codex 随应用提供。
- **Custom**，应用自带的智能体。它可以运行你的 Claude 和 ChatGPT 套餐中的模型（通过 Claude Code 和 Codex 的登录），也可以运行你在[设置 → 智能体 → 模型](/settings?s=models)中添加的任何模型：通过 OpenRouter 的模型、在这台电脑上运行的模型（使用 Ollama 或 vLLM），或任何兼容 OpenAI 的端点。想用开源模型、更便宜的模型，或绝不离开你电脑的模型时，就用它。参见 [Custom，应用自带的智能体](/guide/custom)。
- **支持 ACP 的智能体**：Gemini CLI、OpenCode、Qwen Code、Goose、Kimi CLI、Auggie、Grok Build（xAI 的编程智能体，使用 Grok 模型）等，也可以是你自己的命令。ACP（Agent Client Protocol，智能体客户端协议）是应用与智能体程序通信的一种通用方式。每个智能体只需在它自己的程序里登录一次，并使用它自己的模型。

各智能体在应用中能做什么：

- 目标（应用会让智能体一轮接一轮地持续工作，直到你认可的检查全部通过；参见[给会话设定目标](/guide/sessions#give-the-session-a-goal)）：所有智能体都支持，包括 Claude Code、Codex、Custom 和其他 ACP 智能体。在 Claude Code 或 Codex 的对话中输入 `/goal`，用的是该程序自己的、更简单的目标功能。分叉（从较早的某条回复处复制出会话的副本）：Claude Code、Codex 和 Custom 支持，其他 ACP 智能体不支持。
- **转到…**（把对话交给另一个智能体）：从 Claude Code 或 Codex 转到另一个，或转到 Custom。
- 思考强度（模型思考得多用力）：Claude Code、Codex 和 Grok Build 支持，其他模型提供该选项的 ACP 智能体也支持。
- 多账户、套餐用量限制，以及达到限制时切换账户：Claude Code、Codex 和 Grok Build 支持。
- 限制重置，以及达到限制时使用 API 额度：仅限 Claude Code 和 Codex。

## 为新会话选择智能体和模型

在起始页（`/`）上，消息框下方的一行显示由谁来干活。

1. 点击**运行于**。列表中有 **Claude Code**（“Anthropic · Claude 套餐或 API 密钥”）、**Codex**（“OpenAI · ChatGPT 套餐或 API 密钥”）、**Custom**（“任何模型：OpenRouter、Ollama、vLLM”），以及你在设置 → 更多智能体中添加的每个智能体（“ACP 智能体 · ”加上它的命令）。底部的 **Custom 的模型**会打开设置 → 模型，**添加或管理智能体**会打开设置 → 更多智能体。
2. 点击**模型**并选一个。顶部的**自动**一开始就是选中状态，它让档位来选择：最佳，以及在问题被证明太难时用最大值（参见[档位：为每类工作配一个模型](#tiers-a-model-for-each-kind-of-job)）。它下面只列出该智能体自己的模型。智能体的默认模型标有“默认”。模型的旧版本收在“2 个旧模型”之类的一行后面，点击即可展开。模型超过八个时，顶部会出现**搜索模型**框：输入几个字母并按 Enter，即可选中第一个匹配项。如果智能体没有按应用的要求启动并提供模型，菜单会说明这一点，并附上智能体自己给出的原因，点击**重试**会再请求一次。
3. 在**选项**下，你会找到**思考强度**（适用于有此功能的智能体和模型：默认、最低、medium、最高等；Grok Build 请参见 [Grok Build 的思考强度](#effort-for-grok-build)）和**权限**（智能体不必问你就可以做哪些事）。在消息框中按 Shift+Tab 也可以切换权限。

起始页会记住你在每个工作位置（每个项目、每个文件夹和**新建任务文件夹**）所选的内容，并在所有设备上同步：每个程序的模型、思考强度和权限都会按你离开时的样子恢复（参见[起始页会记住什么](/guide/sessions#what-the-start-page-remembers)）。

Custom 之外的 ACP 智能体，要在它的第一个会话之后才会显示**模型**和**权限**选项：它们列出的是智能体上次运行时提供的内容。Grok Build 是个例外：添加后，它的模型以及每个模型支持的思考强度就会立刻显示，因为应用会向 Grok 询问这些信息。

打开**选项** → **保密**后，**运行于**会变成 **Custom**，**模型**只列出这台电脑上或你的私有网络中的模型，其中最好的排在最前面：参见[让会话保持保密](/guide/sessions#keep-a-session-confidential)。

在手机上，这些菜单都会从屏幕底部以面板形式打开。

## 在会话中途切换模型

在会话中，模型、思考强度和权限位于消息框下方。它们合成一个标签，内容类似“Opus 5.5 · 最高 · 计划”：点击它即可设置**模型**、**思考强度**和**权限**。

选择另一个模型后，会话会接着用它继续：

- Claude Code 立即切换。
- Codex 从下一轮起使用新模型。
- Custom 从下一步起使用，甚至在一轮进行到一半时也一样。
- 其他 ACP 智能体如果提供模型选择，也会切换。

会话的**思考强度**也是同样的方式。选好之后，正在运行的智能体从下一轮起使用它。如果你切换到的模型不支持你原来的思考强度，选择器会显示该模型的默认值，模型就按这个值运行。

模型菜单只列出会话自己的智能体的模型；保密会话则只列出这台电脑上或你的私有网络中的模型。要把对话转给另一个智能体，请使用会话的菜单（⋯）→ **转到 Codex**、**转到 Claude Code** 或**转到 Custom 智能体**（适用于 Claude Code 和 Codex 会话；Custom 在有了模型之后才会出现）。你的下一条消息会在同一个文件夹中启动该智能体的一个新会话，并带上目前为止的对话。已停止的会话会用它上次使用的模型继续，除非你在发送前选了别的模型。

## Grok Build 的思考强度

Grok 的模型支持推理强度，与 Claude Code 和 Codex 给你的选择相同：

- Grok 4.6（以及提供同样选项的更新模型）：**xhigh**、**最高**、**medium** 或**最低**。**最高**是默认值。
- Grok 4.5：**最高**、**medium** 或**最低**。

在起始页的**运行于**下选择 **Grok Build**，然后点击**选项** → **思考强度**：它会列出你所选模型的思考强度，并带有**默认**。Grok Build 一添加就会显示，甚至在它的第一个会话之前。正在运行的 Grok Build 会话可以在它自己的**思考强度**选择器（消息框下方的标签）中更改思考强度，[应用](/guide/apps)运行时也可以选择。当你把会话切换到不支持原有思考强度的模型时（例如在 Grok 4.5 上选 xhigh），选择器会显示该模型的默认值，模型就按这个值运行。

这不仅限于 Grok：任何其他支持 ACP、且模型提供思考强度的智能体，也会得到同样的**思考强度**选项。

## 档位：为每类工作配一个模型

智能体按档位而不是按名称来选择模型：**快速**用于小而非常明确、结果可以检查的工作，**标准**用于明确的中等规模任务，**最佳**用于会话的主智能体（它负责制定计划、带领子智能体并检查它们的工作），**最大值**用于最难的问题。一项工作的大部分是明确的部分，用更便宜的模型就能做好，所以会话这样运行成本更低，结果却不会变差：房间里最强的模型仍然负责规划工作并检查成果。

在起始页上，**模型**默认打开的是**自动**：会话从最佳档位开始（同样的**自动**也用于启动[定时任务](/guide/tasks#model-effort-permissions-and-other-options)的会话，[应用](/guide/apps)也可以用某个档位而不是具体名称的模型来思考）。它的主智能体会把明确的部分交给标准和快速档位的子智能体，并且在问题被证明超出最佳档位的能力时（修复失败了两次、找不到原因、需要证明），可能把自己切换到最大值；对话中会有一行说明这一点及原因。请求不会仅凭措辞就被送到最大值：最佳档位能以更低的成本解决大多数看起来很难的问题。改为按名称选择模型的话，会话就用那个模型思考；它的子智能体仍然使用档位。你自己的智能体也可以只用一个档位来思考（参见[智能体用什么思考：档位](/guide/agents#what-an-agent-thinks-with-tiers)）。

[设置 → 智能体 → 模型 → 档位](/settings?s=models&find=Tiers)说明了每个档位对每个程序意味着什么：每个档位一行，分组标题旁有一个开关用于选择程序（**Claude Code**、**Codex** 或 **Custom**），每一行里有一个模型，对于 Claude Code 和 Codex 还有一个思考强度。档位旁的 (i) 会提供更多说明。起初，对 Claude Code 来说，快速是 Haiku，标准是 Sonnet，最佳是 Opus，最大值是最新的 Fable；对 Codex 来说，快速是 Luna，标准是 Terra，最佳是 Sol，最大值是 Astra（如果套餐里没有其中某个模型，就用它提供的最接近的那个；当两个档位共用一个模型时，较高的档位用更高的思考强度）。Custom 的档位会自动填充：你没有动过的档位，会从 Custom 拥有的模型中选取同类里最新的模型。来自你的 Claude 套餐的，快速是 Haiku，标准是 Sonnet，最佳是 Opus，最大值是最新的 Fable；否则来自你的 ChatGPT 套餐，依次是 Luna、Terra、Sol 和 Astra；再否则来自你添加的、不在这台电脑上（OpenRouter、某个端点）且名称属于上述系列之一的模型。这台电脑上的模型绝不会被自动选中，因为它的名称看不出它有多强；小模型（Haiku、Luna）也绝不会成为最佳：如果只有小模型或本地模型，档位会一直为空，直到你自己选择，此时 Custom 会话会沿用它所选的模型。一旦最佳指定了模型，起始页就会为 Custom 提供**自动**，它的会话会带领子智能体（Hydor 子智能体，因为 Custom 自身没有 Agent 工具）。在 **Custom** 标签页上，你可以为某个档位指定它的任何模型（参见[Custom 的模型从哪里来](#where-customs-models-come-from)）。你没有动过的档位，会跟随其程序中同类的最新模型。标题旁 **⋯** 菜单中的**恢复默认**会把它们都恢复，包括 Custom 的选择。

档位下方**会话中的档位**分组里的两个开关，决定会话如何使用档位：

- **主智能体带领子智能体**（起初为开）：会话的主智能体会被告知要制定计划、把明确的部分交给更便宜档位的子智能体，并检查它们的工作；没有指定档位的子智能体会得到标准档位。关闭后，智能体除非自己另有选择，否则独自工作，起始页和任务表单中也不会有自动选项。
- **难题用最高档位**（起初为开）：处于自动模式的主智能体，在问题被证明对最佳档位来说太难时，可以把自己切换到最大值。关闭后，处于自动模式的会话会一直停留在最佳档位。

## 智能体程序会自行安装和更新

Claude Code、Codex、Gemini CLI、Grok Build 等都是这台电脑上的程序。你不必手动安装它们。

打开[设置 → 智能体 → 账户](/settings?s=accounts&find=Agent%20programs)，查看**智能体程序**分组。它列出 Claude Code、Codex、Gemini CLI、OpenCode、Qwen Code、Auggie、Grok Build（添加之后）以及需要 ACP 适配器的智能体，每一项都标明会话所运行的版本及其来源：

- **你自己安装的**：你自己装的（对 Grok Build 来说，也包括用 xAI 自己的安装程序安装，它会装在 `~/.grok/bin`）。
- **由应用安装**：应用把它安装在自己的文件夹里。
- **随应用提供**：Codex 随应用一起发布。
- **这里没有：首次使用时会自行安装**：缺失。点击**安装**可立即获取。

有更新版本发布时，这一行还会写上“… 已发布”。如果你自己也装了 Codex，Codex 那一行还会加上“你在终端里用的：…”：会话运行的是应用自带的那个，终端运行的是你自己的那个。

缺失的程序在第一次需要时也会自行安装：Claude Code 在你登录它或启动 Claude Code 会话时安装，ACP 智能体在你于设置 → 智能体 → 更多智能体中添加它或用它启动会话时安装。应用用 npm 把它们安装到自己的文件夹里，所以你不需要管理员权限。

Goose、Kimi CLI 和其他一些智能体不在这个列表中：请自行安装（设置 → 智能体 → 更多智能体会告诉你去哪里获取）。需要 ACP 适配器的智能体分两部分安装，即适配器和智能体本身；列表中两者合并显示为一行。

## 保持智能体程序为最新版本

开启 [**自动更新**](/settings?s=accounts&find=Update%20automatically)（它位于 **智能体程序** 的最后一行，默认开启，除非你自己关闭）后，应用会每天把每个智能体程序更新到最新版本。第一次运行大约在应用启动十分钟后。

- 由应用安装的副本通过 npm 在它自己的文件夹中更新。Codex 会切换到比应用自带版本更新的副本。
- 你自己安装的程序用它们各自的更新器更新：Claude Code 用 `claude update`，Codex 用 `codex update`（即你的终端运行的那个），OpenCode 用 `opencode upgrade`，Grok Build 用 `grok update`。
- 如果 Gemini CLI、Qwen Code、Auggie、Grok Build 或带有 ACP 适配器的智能体是你用 `npm install -g` 安装的，那么在你的用户有权写入该文件夹时，它们会通过 npm 更新。以其他方式安装的程序，需要你按当初安装的方式自行更新。
- Claude Code 遵循它自己的发布通道：当它的设置中写有 `"autoUpdatesChannel": "stable"` 时使用稳定版，否则使用最新版。
- 如果你用 `DISABLE_AUTOUPDATER=1` 关闭了 Claude Code 自身的更新（Docker 镜像就是如此），应用也不会自动更新你的 Claude Code。不过 **立即更新** 仍然有效。

只有当新版本能按会话使用它的方式正常工作时，应用才会保留它。Claude Code 必须在会话启动时作出响应并列出它的模型，Codex 必须启动它的应用服务器并列出它的模型，其他程序必须能启动并报告自己的版本。这些检查都不需要登录，也不会消耗你的任何套餐额度。每个程序有一分钟的时间作出响应，并且只计算电脑处于唤醒状态的时间，所以检查过程中进入睡眠的 Mac 不会把这一分钟用掉。第一次响应较慢的程序（Mac 在新程序首次运行前会先检查它）会再给两分钟重新启动，如果那时仍未响应才算失败。失败的版本会被撤销：

- 由应用安装的副本，或你自己安装、由应用通过 npm 更新的副本，会回到之前的版本。
- 对于你自己安装的 Claude Code，会话会继续运行之前的版本，Claude Code 的安装程序会把它与新版本放在一起保留。终端里的 `claude` 命令则保持在新版本。该行会显示“… did not work here”。
- 失败的版本不会自动重试，但下一个版本会被尝试，**立即更新** 也会再次尝试它。

在该行下方会显示应用上次检查的时间，例如“Up to date · checked 2h ago”，旁边的 **立即检查** 可以再次检查。当有更新版本发布时，这里会提示，并提供 **立即更新** 一次性安装全部更新（没有针对单个程序的按钮）；更新过程中会显示正在更新哪个程序。下面几行说明上次更新改变了什么，例如“Claude Code 2.1.308 → 2.1.316”，或者某个版本为何无法安装。

正在运行的会话会继续使用它们启动时的版本；新会话使用新版本。关闭 **自动更新** 后，应用仍会每天检查一次并显示有哪些新版本，但在你点击 **立即更新** 之前不会安装任何内容。

## 登录 Claude Code、Codex 和 Grok Build

Claude Code 和 Codex 需要先登录才能工作，添加 Grok Build 之后它也需要登录（参见[添加 Gemini CLI、OpenCode 和其他 ACP 智能体](#add-gemini-cli-opencode-and-other-acp-agents)）。打开[设置 → 智能体 → 账户](/settings?s=accounts)（在手机上，设置是一个分区列表：点按智能体下的 **账户**；顶部的标题可以带你返回）。**账户** 组（它的 (i) 说明这里是你的会话使用的 Claude Code、Codex 和 Grok Build 登录，你可以添加另一个订阅，比如一个工作订阅和一个个人订阅，并在开始会话时选择其中一个）先列出每个智能体自己的登录，然后是你为它添加的账户。Grok Build 自己的登录在这里也有一行，即 **Grok Build**，添加后才会显示。每一行会显示绿色对勾以及邮箱、套餐和登录方式，或者显示红色叉号以及“未登录”或出错的原因。

登录步骤：

1. 点击智能体旁边的 **登录**。
2. 选择方式：
   - Claude Code：**Claude 订阅**（你的 Claude 套餐）或 **Console（API 计费）**（Anthropic API 账户）。
   - Codex：**设备码** 或 **浏览器跳转**。
   - Grok Build：无需选择，它总是使用验证码登录。
3. 点击 **获取登录链接**。
4. 按对话框显示的步骤操作：
   - Claude Code：打开链接（**打开登录页面**），在浏览器中批准访问，然后把页面显示的代码粘贴到 **粘贴页面上的代码**，再点击 **完成登录**。
   - Codex，设备码：在任意设备上打开链接，登录 ChatGPT，并输入对话框中显示的一次性验证码。完成后对话框会自动察觉。
   - Codex，浏览器跳转：登录后，你的浏览器会尝试打开一个“localhost”页面，但会失败。复制该页面的地址，粘贴到 **粘贴浏览器中的 localhost 地址**，然后点击 **完成登录**。
   - Grok Build：你会得到一个链接和一个一次性验证码。在任意设备上打开链接，用你的 Grok 账户登录并确认验证码（**2. 确认此验证码**）。无需粘贴任何内容：完成后对话框会自动察觉。

成功后，你会看到“Claude Code 已登录”（或 Codex、Grok Build）。如果失败，对话框会说明原因；点击 **重试**。

登录之后，按钮会变成 **切换账户**：它会为另一个账户启动同样的登录流程（对于 Grok Build，则是一个新的验证码）。**退出登录** 在该行的 **⋯** 菜单中：确认后，它会在这台电脑上退出该程序的登录，所有使用它的终端和编辑器都会受影响。

如果你在 Grok Build 未登录时启动 Grok Build 会话，会话会停止，并显示“Grok Build 未登录：请在设置 → 智能体 → 账户中用你的 Grok 账户登录，然后重试。”在那里登录后，再次发送你的消息即可。放在智能体环境中的 `XAI_API_KEY` 里的 xAI API 密钥，也可以代替订阅让 Grok Build 工作。

欢迎导览（在导航栏的 **帮助** 中）会询问你想使用哪些智能体和模型，也会带你完成这些登录。

## 添加第二个账户（工作和个人）

你可以登录不止一个 Claude Code、Codex 或 Grok Build 账户，例如一个工作套餐和一个个人套餐，并在每个会话中选择其中一个。

1. 打开[设置 → 智能体 → 账户](/settings?s=accounts&find=Accounts)。
2. 点击 **账户** 组标题旁边的 **添加账户**。
3. 选择 **Claude Code**、**Codex** 或 **Grok Build**（设置好 Grok Build 之后才会提供），输入名称（最多 40 个字符，例如“工作”或“个人”），然后点击 **添加并登录**。
4. 新账户的登录对话框会打开。按上文所述登录。

每个添加的账户各自独立登录，并保留各自的会话历史。你的设置、指令、技能和插件与该智能体的主登录共享，所以更改会同时应用到两者。对于 Claude Code，你在主登录下信任的文件夹，在添加的账户下同样受信任，因此该文件夹自己的权限规则会在其会话中生效。同一个智能体的两个账户不能同名。

添加的 Grok Build 账户有自己的文件夹，其中存放它的登录信息和 Grok 自己的会话历史。它与你的主登录共享 Grok CLI 自己的设置：配置、规则（`AGENTS.md`）、技能、插件和 MCP 登录。

每个添加的账户在该智能体自己的登录下方都有单独的一行，带有 **登录** 或 **切换账户**；它的 **⋯** 菜单中有 **退出登录**、**重命名** 和 **移除**：

- **重命名** 会要求你输入新名称。
- **退出登录** 会让以该账户运行的会话停止工作，直到它重新登录。
- **移除** 会把该账户从应用中删除。它的会话会从列表中消失，但它们的历史仍保留在磁盘上，除非你同时勾选 **同时删除它的登录信息和会话历史**。当有会话正以该账户运行时，你不能移除它：请先停止这些会话。

[用量页面](/usage)会为每个添加的 Claude Code、Codex 或 Grok Build 账户显示一张卡片，上面是它自己的限额。

## 选择会话所用的账户

当你选择的智能体有添加的账户时（对于 Grok Build，则是在你添加了一个之后），起始页的 **选项** 中会显示 **账户** 一行。点击它：

- **你的登录** 是该程序自己的账户（**账户** 中该智能体的第一个；对于 Grok Build，是“Grok Build CLI 自己的账户”）。
- 每个添加的账户都按名称列出。
- **管理账户** 会打开设置 → 智能体 → 账户。

起始页会记住你为该智能体所做的选择，在所有地方都一样。以添加的账户运行的会话，会在会话顶部显示该账户的名称和一个人形图标。如果该账户达到用量限额，消息框上方的限额提示就是针对该账户的。账户在会话启动时确定。只有 **达到限额时切换账户**（见下文）会让它自动改变。

要自己把会话转到另一个账户，请点击会话自己的 **账户** 标签并选择一个。这适用于 Claude Code、Codex 和 Grok Build 会话，并从你的下一条消息开始生效。Grok Build 会话的 Grok 历史会随之转移；如果 Grok 无法在另一个账户下重新打开它，就会在那里重新开始，并附有说明。

## 使用你所有的账户：达到限额时切换

当同一个智能体有两个或更多账户时，应用可以把它们全部用起来：当其中一个用完用量，你的工作会换另一个账户继续。打开[设置 → 智能体 → 账户](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit)，找到 **达到限额时切换账户**，它位于 **账户** 下的 **达到用量限额时** 组中，只要你添加了任何账户（包括 Grok Build 的）就会显示（它的 (i) 说明：当会话的账户用完用量时，会话会转到该智能体另一个仍有用量的账户并继续，新会话会跳过已达限额的账户）。它一开始就是开启的（如果你更想自己选择账户，可以在那里关闭），并且在没有打开浏览器时也能工作。

- 当某一轮因会话的账户达到用量限额而停止时，应用会从同一个智能体中挑选另一个仍有用量的已登录账户（用得最少的那个），把会话连同全部历史转到那里，并发送“… reached its usage limit, so this session now runs on …. Continue where you left off.”。屏幕底部的一条简短提示会说明它转到了哪个账户。
- Claude Code 会话在后台运行的子智能体也会继续。限额触发时仍在工作的子智能体会在下一步停止，并保留它们的工作，应用会等待它们（最多两分钟），然后再转移会话。随后的消息会点名它们，智能体会从每个子智能体停下的地方继续它。如果只有子智能体达到了限额（比如仅针对它们所用的模型），会话会在这一轮结束且没有子智能体仍在工作后转移。
- Hydor 子智能体（智能体为完成部分工作而启动的会话）本身就是独立的会话，所以当限额使它的一轮停止时，每一个都会自行转移。启动它的智能体得知的是它会继续，而不是失败了，并会在它完成时收到它的回复。
- 你的主登录和每个添加的账户都算在内。Claude Code 账户由 Claude Code 账户接替，Codex 由 Codex 接替，Grok Build 由 Grok Build 接替。
- Grok Build 账户在达到每周限额、额度限额或按量付费的花费上限时即为达到限额。此时会话会转到另一个仍有用量的已登录 Grok 账户（用得最少的那个），并以“… reached its usage limit, so this session now runs on …”继续。短时的速率限制（一阵密集请求）不会触发任何转移：它会自行过去。消息框上方的限额提示对 Grok 会话同样会显示。
- 由应用驱动的目标属于应用，所以它会在新账户上继续进行。在 Codex 中以 `/goal` 输入的目标会随会话转移并继续进行。
- 当所有账户都达到限额时，不会发生转移（除非开启了下文提到的 **达到限额时使用 API 额度**，适用于 Claude Code）。开启 **用量限制解除后继续** 后，会话会在第一个账户重置时在该账户上继续。这对 Grok Build 会话同样适用。更多内容见[用量、限额和费用](/guide/usage#continue-sessions-automatically-after-a-limit)。
- 在已达限额的账户上启动的新会话，会改为在仍有用量的账户上启动；而你向账户已达限额的会话发送消息时，会话会先转移，这样你的消息就不会被拒之门外。随着你的消息，智能体会得知它现在运行在一个仍有用量的账户上，因此不会等待旧账户重置，也会知道它的哪些子智能体可以继续。
- 在 VS Code 或终端中打开的会话会留在它们的账户上。
- 限额重置（Codex 重置额度、Claude 重置授权）和 API 额度仍然仅适用于 Claude Code 和 Codex。
- 应用自己向 Claude Code 或 Codex 提出的快速问题（设为 **自动** 的辅助模型、应用的快速模型步骤、拉取请求描述、命令建议），在其中一个达到限额或已退出登录时，同样会交给你的下一个已登录账户。当 Claude Code 和 Codex 都无法回答时，你的某个 Custom 模型会接手（参见[账户退出登录时](#when-an-account-is-signed-out)）。

## 账户登出时

Claude Code、Codex 或 Grok Build 的账户可能会被登出：它的登录已结束或被撤销，程序会提示“Not logged in · Please run /login”或“401 Unauthorized”。应用会尽可能自行解决，只有在没有其他办法完成工作时，才会请你重新登录。

- **你的会话.** 当某个会话的一轮对话因账户已登出而被拒绝，并且 [达到限额时切换账户](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit) 已开启（默认开启）时，该会话会带着全部历史记录转到同一智能体的另一个仍有用量的已登录账户，并继续进行。屏幕底部会出现一条简短提示：“<会话>：<账户> 已登出，因此改用 <其他账户> 继续”，同时智能体会收到：“… is signed out, so this session now runs on …. Continue where you left off.” 如果你向一个不久前被发现已登出账户的会话发送消息，会话会先以同样的方式转移，这样你的消息就不会被拒绝。
- **会话无法转移时。** 如果 **达到限额时切换账户** 已关闭，或者该智能体没有其他账户还有用量，会话就会停止。消息框上方会出现一条横幅，写着“<账户> 已登出”和“你重新登录后，此会话会继续。”，并带有 **登录** 按钮。当你重新登录后（无论是在这里还是在终端中），会话会自动继续，智能体会收到：“Signed in again. Continue where you left off.”
- **后台工作。** 在 **自动** 模式下，[辅助模型](/settings?s=models&find=Helper%20model)执行的小任务（会话标题、记忆备注、精简[你的个人资料](/guide/memory#your-profile)、应用的快速模型步骤、拉取请求描述等）会跳过已登出的账户 15 分钟，然后再次尝试，因此你在终端中完成的登录会被发现。接下来由下一个已登录的账户来回答，然后是 Codex。当 Claude Code 和 Codex 都无法回答（已登出、达到限额或未安装）时，会由你的某个 **Custom** 模型来完成：即 Custom 的 **快速** 档位在 [设置 → 智能体 → 模型 → 档位](/settings?s=models&find=Tiers) 中指定的模型（然后是 **标准**，遇到少见的较大任务时是 **最佳**，再然后是 **最大值**），否则使用你添加的最便宜的模型（本机上的模型视为免费）。最多尝试两个。其费用与其他 Custom 模型的用量一样计算。
- **登录提示。** 只有在没有任何办法完成工作且有账户已登出时，每个页面的右下角（手机上位于消息框上方）才会显示一张卡片。它的标题是“重新登录 Claude Code”（或 Codex、Grok Build），下面写着“<账户> 已登出。”，并说明原因：“后台工作需要它（精简你的个人资料），而且没有其他账户或 Custom 模型可以完成。”或者，对于被它停止的会话，写着“… 登录后即可继续。” **登录** 会打开与[设置 → 智能体 → 账户](/settings?s=accounts)相同的登录对话框。**暂不** 会将这张卡片隐藏一小时；因此而停止的会话会再次显示这张卡片，该会话中的横幅也会保留。同时最多显示两张卡片，之后“+N more”会带你前往设置 → 智能体 → 账户。账户重新登录后（无论是通过卡片、设置还是终端），卡片就会消失（应用会在下一次成功的调用时发现）。当后台工作通过其他方式重新完成（其他账户或 Custom 模型作出了回答）时，卡片也会消失。当 Claude Code 和 Codex 都已登出时，只会询问最先回答的 Claude Code。

你的个人资料也会显示这一点：当精简它因账户已登出而失败时，其下方的原因会这样说明（“你的 Claude Code 账户“Work”已登出，而且没有其他账户或 Custom 模型可以完成此操作：请重新登录（设置 → 智能体 → 账户）。”），同时卡片会出现。

## 所有账户都达到限额时使用 API 额度

如果你有 Anthropic API 密钥（来自 [console.anthropic.com](https://console.anthropic.com) → API keys），那么当每个 Claude Code 账户都达到用量限额时，你的 Claude Code 会话可以用它继续进行，而不是停止。这需要花钱：只要会话以这种方式运行，Anthropic 就会按 API 价格向你计费，不在你的订阅范围内。

1. 打开[设置 → 智能体 → 账户](/settings?s=accounts&find=Use%20API%20credit%20at%20a%20limit)。在 **账户** 中某个 Claude Code 账户所在的行（你的主登录账户或你添加的账户）上，点击 **⋯**，然后点击 **添加 API 密钥…**。
2. 将密钥粘贴到 **Anthropic API 密钥** 中，然后点击 **保存密钥**。应用会通过 Anthropic 验证它，并将其加密保存在这台电脑上。之后该行会显示 **API 额度** 标签。**更改 API 密钥…** 可替换密钥，**移除 API 密钥** 可删除密钥。
3. 在 **达到用量限额时** 分组中打开 **达到限额时使用 API 额度**（它的 (i) 说明：当每个 Claude Code 账户都达到用量限额时，会话会改为计入某个账户的 Anthropic API 密钥来继续进行，而不是停止；在你打开之前它是关闭的）。只有在 Claude Code 已登录或你已添加 Claude Code 账户后，它才会显示。

之后会发生这些事：

- 当某个 Claude Code 会话的账户达到用量限额时，应用会先尝试 **达到限额时切换账户** 所做的事：改用另一个仍有用量的账户。只有在没有任何账户还有用量，并且该设置已开启时，会话才会改为计入 API 密钥继续进行。
- 会话仍留在它自己的账户上，因此它的历史记录不会转移。如果该账户没有密钥，则使用另一个 Claude Code 账户的密钥。
- 会话顶部其账户旁边会显示 **API 额度** 标签。将鼠标悬停在上面即可查看原因。
- 当某个套餐的用量恢复后，会话会在下一轮结束后回到该套餐：回到它自己的账户，或另一个仍有用量的账户。你不需要做任何事。
- 如果应用无法读取某个账户的用量，就绝不会把你的工作转到 API 计费上。
- Codex 不受影响：它没有 API 额度。

## 添加 Gemini CLI、OpenCode 和其他 ACP 智能体

打开[设置 → 智能体 → 更多智能体](/settings?s=agents&find=Agents%20that%20speak%20ACP)。

- **你的智能体**（开始会话时，它们会显示在 Claude Code 和 Codex 旁边）首先列出 Custom，然后是你添加的智能体。如果其程序已安装在这里，每个智能体都会显示一个对勾，否则显示一个叉号和“未安装”。
- **支持 ACP 的智能体**（先安装一个，在它自己的 CLI 中登录一次，然后在这里添加）列出你尚未添加的已知智能体：Gemini CLI、OpenCode、Qwen Code、Goose、Kimi CLI、Auggie、Grok Build 等。已安装的排在最前面。显示“未安装”的行会说明如何获取它。列表只显示前几个未安装的智能体；**全部显示** 会显示其余的。

添加方法：

1. 点击它所在行末尾的 **添加**。如果程序已经安装，这个按钮会更醒目。
2. 如果应用知道如何安装它（Gemini CLI、OpenCode、Qwen Code、Auggie、Grok Build，以及需要 ACP 适配器的智能体），就会立即在后台安装。Goose、Kimi CLI 和其他的需要你自己安装，使用它们所在行中的命令或地址。
3. 在智能体自己的程序中登录一次：打开[终端](/terminal)，运行它的命令（例如 `gemini`），并按提示登录。如果你跳过这一步，会话会提示你：“Gemini CLI 尚未登录。请在终端中运行一次 gemini 并在那里登录，然后重试。”

之后，该智能体就会显示在开始页面的 **运行于** 列表中。

要修改已添加的智能体，点击 **编辑**。要移除它，打开它的 **⋯** 菜单，选择 **移除** 并确认：它的会话仍会保留在列表中，但要继续这些会话，需要重新设置该智能体。Custom 是内置的：它所在的行写着“内置：来自 OpenRouter、Ollama 和 vLLM 的模型，位于设置 → 模型”，并且有一个 **模型** 按钮，而不是编辑和移除。

### Grok Build

**Grok Build** 是 xAI 的编程智能体（即 `grok` 程序）。点击它所在行中的 **添加**，这样就完成了：应用会在第一次需要时从 npm（`@xai-official/grok`）安装它，或者使用这里已有的版本，包括来自 xAI 自己的安装程序、位于 `~/.grok/bin` 的版本。之后它会显示在 **智能体程序** 下，并与其他智能体一起保持更新。Hydor 通过 ACP 运行它，使用应用自己的工具、批准卡片和 Grok 的模型。

它的登录方式与其他 ACP 智能体不同：不是在终端中，而是在[设置 → 智能体 → 账户](/settings?s=accounts)下，添加后那里会立即出现一行 **Grok Build**（参见[登录 Claude Code、Codex 和 Grok Build](#sign-claude-code-codex-and-grok-build-in)）。你也可以在那里添加更多 Grok 账户。

### 添加你自己的智能体

任何支持 ACP 的程序都可以在这里运行。

1. 点击 **Your agents** 标题旁边的 **添加你自己的**。
2. 填写：
   - **名称**：它在列表中显示的名字，例如“Gemini CLI”。
   - **命令**：要启动的程序，例如 `gemini`，或完整路径。
   - **参数**：以 ACP 模式启动它所需的内容，例如 `--experimental-acp`。
   - **环境变量（可选，每行一个 NAME=value）**：程序所需的设置，例如 API 密钥变量。
3. 点击 **保存**。

该命令必须以 ACP 模式启动智能体，并通过它的标准输入和输出进行通信。

### 在智能体自己的程序中设置的智能体

列表中的一些智能体是需要你自己设置的程序，与应用为你安装的智能体相比，有几点不同：

- 它们在 **更多智能体** 中的行会显示用来安装它们的命令或地址。应用不会替你运行来自网络的脚本：请自己安装，在[终端](/terminal)中或按该行所说的方式进行。
- 在智能体自己的程序中登录一次，同样是在终端中（例如运行它的命令并按提示登录，或在那里选择它的模型）。从那以后应用就会启动它。它会把自己的会话和记忆保存在它自己的文件夹中，它的批准卡片也是它自己提供的那些。
- 其中一个会连接到它自己的网关：请先用该智能体自己的设置命令进行设置，并保持网关运行。
- 当某个智能体本身不支持 ACP 时，它需要一个 ACP 适配器。应用会把适配器与智能体一起安装，两者都通过 npm 安装在它自己的文件夹中，不运行它们的安装脚本。你自己安装的智能体，只要在 PATH 中就会被使用。
- 不接受任何 MCP 服务器的智能体只能使用它自己的工具：应用的工具（网页、搜索等）无法到达它，会话开始时会这样告知你。它仍会在第一条消息中收到应用的准则、记忆备注和技能。

### ACP 智能体在这里能做什么、不能做什么

应用会在你选择的文件夹中打开会话，显示智能体的消息和步骤，并在智能体请求权限时询问你。有些地方与 Claude Code 和 Codex 的做法不同：

- 它一次只处理一条消息。你在它工作时发送的消息会在消息框上方的队列中等待，并在这一轮结束后发出。（Custom 也是这样工作的。）
- 无法重新打开早先会话的智能体，在你继续一个旧会话时会重新开始，不带之前的对话。会话会告诉你这一点。如果某个智能体以前能重新打开会话、现在却不能，也会发生同样的事：它会带着一条说明重新开始，而不是失败。
- 你附加的图片只有在它接受图像时才会传给它。
- 不支持分叉和移交（Custom 支持分叉）。目标则支持：应用自己的循环会为每个智能体驱动它们。
- 应用的工具（网页、搜索、记忆等）会作为 MCP 服务器传给智能体：智能体接受时通过地址，否则通过应用为它启动的一个小程序。不接受其中任何一种的智能体只能使用它自己的工具，但仍会收到准则、记忆备注和技能。

## Custom 的模型来自哪里

Custom 可以运行你的 Claude 和 ChatGPT 套餐里的模型、这台电脑上的模型以及云端的模型，使用的工具、技能和 MCP 服务器与其他智能体相同。在起始页选择 Custom，再选择模型。模型来自三个地方：

- **你的订阅**：你的 Claude 和 ChatGPT 套餐里的模型，通过这台电脑上 Claude Code 和 Codex 的登录状态使用。无需任何设置：Claude Code 已登录时，Custom 的**模型**菜单会提供 Claude Opus、Fable、Sonnet 和 Haiku（始终是各系列最新的版本）；Codex 用 ChatGPT 登录时，会提供你的 ChatGPT 套餐列出的模型（例如 GPT-6 Luna）。如果发现某个程序已退出登录，它的模型会从菜单中消失，直到你重新登录；Codex 若用 API 密钥而不是 ChatGPT 登录，则不会提供任何模型。这些模型使用的是你套餐的用量，不是 API 密钥，也不按 token 计费，所以使用它们的 Custom 会话在这些步骤上显示 $0。该程序的每个账户会依次尝试，与其他一次性工作相同：某个账户达到用量限额或已退出登录时，这一步会交给你的下一个账户（需开启**达到限额时切换账户**）。[保密会话](/guide/sessions#keep-a-session-confidential)从不使用这些模型，因为它们运行在 Anthropic 或 OpenAI 的服务器上。关于它们如何回答，请参阅 [Custom](/guide/custom#what-custom-is-and-when-to-use-it)。
- **在这台电脑上**：安装在本机的模型（Ollama、vLLM），以及你网络上的端点。
- **在云端**：OpenRouter、其他地方的端点，以及 Ollama 的云端模型。

凡是可以选择 Custom 模型的地方，你都可以选择它们：起始页、会话的模型菜单、Custom 的档位、辅助模型，以及智能体或应用的模型。

[设置 → 智能体 → 模型](/settings?s=models)包含 Custom 的模型所需的一切。这一页从上到下分为七个部分：

- **辅助模型**：负责应用中各种小任务的模型。
- **档位**：为每一类任务指定一个模型（参阅[档位：为每一类任务指定一个模型](#tiers-a-model-for-each-kind-of-job)）。
- **你的订阅**：Claude Code 和 Codex 各占一行，显示它借给 Custom 的模型。某一行会显示“已退出登录：请重新登录以使用这些模型”，并附带指向**账户**的链接，或显示“未安装在这台电脑上”。
- **在本机**：这台电脑的配置，以及安装在本机的模型。
- **从 Hugging Face 添加模型**：搜索、检查并安装开源模型。
- **OpenRouter**：通过一个密钥使用数百个模型，分为三组：你的密钥、你添加的模型，以及用于添加更多模型的搜索。
- **运行时和端点**：Ollama、vLLM、其他兼容 OpenAI 的服务器，以及 Hugging Face 令牌。

在 Custom 的**模型**菜单中，模型按**你的订阅**、**在这台电脑上**和**在云端**分组，每一行会注明它通过什么使用：“Claude Code”“Codex”“OpenRouter”“Ollama”“vLLM”或某个端点的名称。把鼠标悬停在模型上，可以看到它在哪里运行以及一次能读取多少内容，例如“OpenRouter · 128K 上下文”或“本机 vLLM · 32K 上下文 · 使用时启动”。这些列表每分钟自动刷新一次。

## 选择辅助模型

辅助模型在你的会话之外处理一些小任务，不属于任何对话：

- 根据你的请求为每个新会话命名（即它在侧边栏中的标题）；
- 在 Custom 的自动模式下检查各个步骤，并判断某个目标的检查项是否成立，这类检查必须由审核者确认（审核者是没有参与任何工作的模型，在保密会话中则是这台电脑上的模型）；
- 大约每天整理一次记忆，从此后的对话中学习，并为智能体启动时读取的索引给备注拟定标题；
- 回答关于浏览器中打开的某个网页的一个问题；
- 在 Naget Search 搜索之前，读取网页搜索词语中包含的筛选条件（网站、日期、页面类型、语言）（参阅[智能体如何搜索网页](/guide/web#how-agents-search-the-web)）；
- 为看不了图片的 Custom 模型描述图片；
- 概括 Hydor 子智能体的长回复；
- 根据会话起草应用或定时任务；
- 免提语音模式。

打开[设置 → 智能体 → 模型](/settings?s=models&find=Helper%20model)，点击**辅助模型**组中的**模型**菜单（其中的 (i) 会列出这些小任务）：

- **自动**（默认）：通过 Claude Code 使用 Claude Haiku，Claude Code 无法回答时使用 Codex。某个账户达到用量限额时，会先把问题交给你的下一个已登录账户（需开启**达到限额时切换账户**），已退出登录的账户会被跳过。两个程序都无法回答时，由你的某个 Custom 模型来完成（即 Custom 的**快速**档位指定的模型，否则是你添加的模型中最便宜的；这里会跳过你套餐里的模型，因为它们走的仍是这两个程序），只有在没有任何模型能完成时，才会出现一张卡片请你登录（参阅[账户退出登录时](#when-an-account-is-signed-out)）。当没有任何模型回答时，错误信息会逐一说明原因：“你已达到每周限额”、你的 Codex 套餐不提供的某个模型……
- Custom 的任何模型，分组与 Custom 的**模型**菜单一致（**你的订阅**、**在这台电脑上**和**在云端**），并注明它通过什么使用（Claude Code、Codex、OpenRouter、Ollama、vLLM 或某个端点的名称），能看图片的模型会标注“能看图片”。你的 Claude 或 ChatGPT 套餐里的模型也可以当辅助模型：它通过 Claude Code 或 Codex，使用你套餐的用量来回答。

自动选项无法查看图片。如果你使用的 Custom 模型看不了图片，请选择一个能看图片的辅助模型，否则 Custom 无法让人描述你的图片。

## 查看这台电脑能运行什么

[设置 → 智能体 → 模型](/settings?s=models&find=On%20this%20machine)的**在本机**部分，开头是这台电脑的概况：

- **显卡**：显卡（GPU）及其显存；如果是搭载 Apple 芯片的 Mac，则显示它的芯片（“Apple M3 Max”，其图形处理与电脑共享内存）；或显示“无 GPU”（此时模型在处理器上运行）。
- **内存和磁盘**：电脑内存的总量和可用量，以及磁盘的可用空间和已安装模型占用的空间。
- **运行方式**：**Ollama** 和 **vLLM** 是否已安装及其版本，或指向安装方法的链接。
- 如果有显卡，还会显示能放下多大的模型：“在一块 GPU 上约可容纳 4 位的 30B 参数”（在 Mac 上：“约可容纳 4 位的 40B 参数”）。参数是衡量模型大小的单位；4 位是一种常见的压缩形式，大约只需四分之一的内存。

下方内容：

- **进行中的下载**，每项都有进度条、已完成的数量，以及它是为 Ollama 还是 vLLM 下载的。点击**取消**可以停止某一项。失败或已取消的下载会显示原因，并带有**关闭**。
- **已安装的模型**（先显示前几个，其余点击**全部显示**），每个模型会显示它的运行时（Ollama 或 vLLM）、大小、详情（例如 Ollama 模型的大小和压缩方式）、能看图片的会标注“能看图片”，以及它是否正在运行。
  - vLLM 模型有**开始**和**停止**。会话第一次使用它时，它会自动启动（首次启动需要一两分钟），使用空闲显存最多的那块显卡（放不下时按 8 位运行），或者在没有任何一块显卡放得下时拆分到 2、4 或 8 块显卡上（“运行在 GPU 1、2 上”）；在 Mac 上则使用它的 Apple 芯片。它会一直运行，即使应用重启也不例外，直到你点击**停止**。如果无法启动，原因会显示在它下方。
  - 模型的 **⋯** 菜单中的**移除**，会在你确认后从这台电脑上删除该模型的文件。你以后可以重新安装。

当还没有任何模型时会显示：“这里还没有模型：请在下方从 Hugging Face 添加。”

## 从 Hugging Face 添加模型

Hugging Face 是开源模型的主要网站。[从 Hugging Face 添加模型](/settings?s=models&find=Add%20a%20model%20from%20Hugging%20Face)这一组会推荐几个模型（为这台电脑推荐，或在整个站点中搜索），帮你搜索，并在下载任何内容之前告诉你每个模型在这台电脑上会如何运行。

### 为这台电脑推荐

在你搜索之前，这一组会根据这台电脑的配置，列出应用推荐的、能在这台电脑上运行的模型：

- **LFM3-VL 2B**（Liquid AI）：小巧快速，能读取图片。几乎任何电脑都能运行。
- **Gemma 4 12B**（Google）：能力全面、能读取图片的多面手，适合配有较好显卡的电脑。
- **Flint**（Recursive）：专为编程智能体打造，适合搭载 Apple 芯片且内存在 32 GB 以上的 Mac。
- **GLM-5.3 Flash**（Z.ai）：最强的开源模型之一，适合配有多块大显存显卡的服务器。

每一项都会显示它在这里运行流畅还是较慢、会如何运行（“8 位 vLLM，运行在 GPU 0 上”“vLLM，拆分到 2 块 GPU”“vLLM，运行在 Apple 芯片上”）、下载大小，以及**安装**。**本机最佳**标记的是能流畅运行的模型中最强的一个。它们默认使用 vLLM 运行；既没有 NVIDIA 显卡也没有 Apple 芯片的电脑，则改为获得小型模型的 Ollama 版本。当运行它们所需的程序尚未设置时，会出现警告（“vLLM 尚未设置”“Ollama 未在运行”）：参阅[连接 Ollama、vLLM 或其他端点](#connect-ollama-vllm-or-another-endpoint)。**另外 2 个适合更大的电脑**这一行（数字会随实际数量变化）会显示其余的模型，以及每个模型的要求。欢迎导览推荐的也是这几个。

### 搜索和筛选

1. 在**搜索 Hugging Face，或粘贴 org/name**中输入：可以是 `qwen3` 这样的名称，也可以是模型的完整名称（`org/name`）或它的 huggingface.co 地址。输入之前，它会推荐几个名称，或者点击**查看下载最多的**。
2. 用筛选条件缩小列表范围（可以组合使用）：
   - **在这里运行流畅**：只显示在这台电脑上能流畅运行的模型。
   - **GGUF · Ollama**：GGUF 格式的模型，由 Ollama 运行。
   - **vLLM**：safetensors 格式的模型，由 vLLM 在显卡上运行。
   - **能看图片**：还能读取图片的模型。
3. 用右侧的菜单更改排序：**下载最多**、**热门**、**最受喜爱**或**最新**。

最多会显示 40 个模型，起初显示前八个，其余点击**全部显示**。你输入完整名称的模型会排在最前面，即使搜索结果中没有列出它，按下回车键则会立即检查它。

每一行会显示制作者和名称、它的格式（**GGUF** 或 **vLLM**）、能读取图片的会显示**图片**、制作者要求你先接受条款的会显示**受限**，还有以参数计的大小、最近 30 天的下载量、点赞数，以及上次更新的时间。

### 初步判断

每个模型下方有一个彩色标签，仅根据模型大小给出初步判断：

- **用 vLLM 运行流畅**或**用 Ollama 运行流畅**，并附有大致速度（“约 40 token/秒”；token 是词语的一小段）：它能放进你显卡的显存。
- **用处理器运行，较慢**或**用处理器运行，非常慢**：它只能放进电脑内存，所以在处理器上运行。只有 Ollama 能这样运行。
- **对这台电脑来说太大**：它放不下，或者下载内容放不进磁盘。
- **用 Ollama 以 4 位运行：流畅…**：模型按原样存储时太大，但它压缩后的 4 位版本用 Ollama 可以流畅运行。

把鼠标悬停在标签上，可以看到判断所依据的数字。

### 下载前先检查

点击模型上的**检查**，可以确切了解它在这里会如何运行。面板会显示它的大小、一次能读取多少内容（上下文）、它是否能看图片，然后是：

- GGUF 模型：“使用 Ollama 运行”，以及每个可用的大小（较小的文件以少许质量换取速度和内存），按从小到大排列。每一行都会给出判断、所需内存、大致运行速度和下载大小，并带有**安装**按钮。当 Ollama 没有在本机运行，或者某个大小太大时，安装按钮是灰色的。
- vLLM 模型：“使用 vLLM 运行，会话使用它时由 vLLM 在 GPU 上启动”，附带同样的数据、关于它会使用哪块显卡的说明，以及**下载**按钮。如果没有安装 vLLM，或者你的 vLLM 暂时无法运行这类模型，面板会说明，并且在存在 GGUF 版本时，改为提供对该版本的**检查**。
- 其他情况：“没有本应用能运行的权重（vLLM 用 safetensors，Ollama 用 GGUF）。”

这些数据假定对话最长约 32,000 个 token，这是为这台电脑上的模型设定的长度。点击**关闭**可收起面板。

### 安装，以及接下来会发生什么

点击**安装**（Ollama）或**下载**（vLLM）。下载会连同进度显示在**在本机**中。完成后，模型会出现在 Custom 的**模型**菜单中。被中断的 vLLM 下载在你再次尝试时会从中断处继续。对于任何一块显卡都放不下的 vLLM 模型，它会在启动时以 8 位（FP8）存储，这样权重占用的内存减半，质量损失很小（适用于 NVIDIA RTX 30 系列及以上和 A100 及以上的显卡）；如果仍然放不下，且几块显卡合起来有足够空间，它会被拆分到多块显卡上。

### 受限模型和私有模型

有些制作者要求你先接受他们的条款，这类模型会显示**受限**。请在 huggingface.co 上该模型的页面接受条款，然后添加 Hugging Face 令牌（参阅 [Hugging Face 令牌](#hugging-face-token)）。私有模型同样需要令牌。

## 通过 OpenRouter 使用模型

OpenRouter（openrouter.ai）通过一个密钥为你提供来自众多厂商的数百个模型，按使用量付费。

### 添加你的密钥

1. 在 openrouter.ai 获取一个密钥（该部分有链接指向那里）。
2. 在 [设置 → 智能体 → 模型](/settings?s=models&find=OpenRouter) 中，点击 **你的 OpenRouter 密钥** 一行里的 **添加密钥**，在弹出的对话框中将密钥粘贴到 **你的 OpenRouter 密钥：sk-or-…**，然后点击 **保存**。

之后该行会显示 **已连接到 OpenRouter**，并显示密钥的开头和结尾。**⋯** 菜单中的 **移除密钥** 会让应用忘记这个密钥。密钥保存在服务器上，不会再次显示。

你也可以在第一次需要时再添加：如果智能体要生成图片、绘图、视频或声音，而你还没有添加密钥，它会在对话中用一张卡片向你索取（[智能体需要 OpenRouter 密钥时](/guide/documents-voice#when-an-agent-needs-the-openrouter-key)），编辑器里的 AI 工具则会在各自的对话框中询问。无论哪种方式，密钥都会保存在这里。

### 推荐模型

在你搜索之前，**添加 OpenRouter 模型** 组中的 **推荐** 会列出四个适用于 Custom 的模型，并说明各自的特点：**GPT-6 Luna**（又快又便宜）、**Grok 4.7**（表现不错，拒绝较少）、**GPT-6.1 Sol**（更好）和 **Claude Opus 5.5**（综合最佳）。点击 **添加** 即可把其中一个放进模型选择器。至于图片、音乐、语音和视频，应用选用的是 Seedream 5.0 Pro（以及更快更便宜的 Flash）、Lyria 3 Pro、Seed Audio 1.0 和 Seedance 2.5：请参阅 [设置 → 功能 → 图片、视频和音频](/settings?s=images)。

### 搜索目录

在同一组中，在 **搜索 OpenRouter：deepseek、qwen、claude…** 中输入内容，或者点击某个推荐的名称，也可以点击 **查看最新的**。可用的筛选项：

- **工具调用**：原生支持调用工具的模型，这是 Custom 用起来效果最好的方式（**最佳匹配** 会把这些模型排在前面）。
- **能看图片**
- **推理**：先思考再回答的模型。
- **免费**

右侧的菜单用于对结果排序：**最佳匹配**（按名称搜索时）、**最新**、**最便宜** 或 **最长上下文**。最多会显示 50 个模型，起初显示前八个，其余的点击 **全部显示** 查看。

每个模型会显示其厂商、名称和标签：**最新**（始终是厂商的最新版本）、**新增**（最近三周内上架）、**免费**、**推理**、**图片**，以及 **无原生工具**（此时 Custom 会在指令中描述它的工具，并从模型的文本中读取调用）。下方依次是：一次能读取的量（“128K context”）、最长的回复（“16K out”）、每百万个输入和输出词元的价格、上架的月份、一段简短的说明，以及它在 OpenRouter 上的名称。

### 把模型添加到选择器

点击模型上的 **添加**。该行随后会显示 **已添加**，这个模型会出现在搜索框上方的 **你的 OpenRouter 模型** 组（“在模型选择器中”）里，也会出现在 Custom 的 **模型** 菜单中。点击其中某个模型上的 × 可以把它从菜单中移除。在至少添加一个模型之前，OpenRouter 不会提供任何模型（“Add at least one model to use OpenRouter.”）。

## 连接 Ollama、vLLM 或其他端点

**运行时和端点** 组用于连接运行模型的程序。你可以在 [设置 → 智能体 → 模型](/settings?s=models&find=Runtimes%20and%20endpoints) 中打开它。

### Ollama

Ollama 是一款免费程序，可在你的电脑上用显卡或处理器运行模型。它所在的行会显示“running”和版本号，或者显示“not running at this address”，并附有 **安装 Ollama** 链接。除非你修改，否则它的地址是 `http://127.0.0.1:11434`：在输入框中输入其他地址，旁边就会出现 **保存**。该 Ollama 中的每个模型都会显示在 Custom 的模型列表中，包括你在应用之外拉取的模型。

### vLLM

vLLM 是一种面向 NVIDIA 显卡的高速模型服务器，也是 Hugging Face 上的模型在这里默认的运行方式。对一张显卡来说过大的模型，可以在它上面以 8 位运行，或拆分到 2、4 或 8 张显卡上运行。在 Mac 上，vLLM 借助其 Metal 插件（vllm-metal）在 Apple 芯片上运行。应用会自动在 PATH 中，或在 conda 或 venv 环境里找到它，并显示它的版本和所在位置。如果显示“not found (pip install vllm), or give its command”，请安装它，或者在输入框中输入其 `vllm` 命令的完整路径，然后点击 **保存**（输入后才会出现）。将输入框留空，则由应用自行查找。

### 其他兼容 OpenAI 的端点

许多程序和服务的应答方式与 OpenAI 的 API 相同：LM Studio、llama.cpp 的服务器，以及其他服务商。添加方法：

1. 点击该组标题旁边的 **添加端点**。
2. 在对话框中输入 **名称**、它的地址（如 `http://localhost:1234/v1`）以及 **密钥（可选）**。
3. 点击 **添加**。

该端点会显示为一行，包含它的地址和它提供的模型数量。它的模型会以“model (name)”的形式出现在 Custom 的列表中。点击 × 可将其移除。添加同名的另一个端点会替换第一个。

点击该行下方的 **设置每个模型的能力**，可查看它的模型，每个模型有两个选项：**能看图片** 和 **推理强度**。每项都可选 **自动**、**是** 或 **否**。能看图片的模型会把截图和图片当作图片接收，不能看的模型则会收到它们的文字描述（参见 [为看不了图片的模型处理图片](/guide/custom#images-for-models-that-dont-see)）；会推理的模型会在 **思考强度** 菜单中提供低、中、高，Custom 会把你选的那一项作为 `reasoning_effort` 发送，这是兼容 OpenAI 的服务器所接受的设置（选择 **默认** 时不会发送任何内容）。**自动** 会遵循端点对该模型的说明，菜单会显示具体是什么：会描述自己模型的服务器（OpenRouter 风格的、Mistral 的等）会在模型列表中说明，而对于 LiteLLM 网关，Hydor 还会用同一个密钥查询它的模型信息。什么都不说的端点按“否”处理：对你知道能看图片或会推理的模型，请设为 **是**。你设置的内容在你重新添加该端点时会保留。

[保密会话](/guide/sessions#keep-a-session-confidential)可以使用地址为本机或你的私有网络的端点：`localhost`、`127.0.0.1`、`::1`、`10.…`、`192.168.…`、`172.16.…` 到 `172.31.…`，或以 `.local` 结尾的名称。任何其他地址都算作在线，即使它指向你自己的服务器：请改用它的私有地址。Ollama 的地址同样适用这一规则，而 Ollama 的云端模型（名称以“cloud”结尾）始终算作在线。

### Hugging Face 令牌

[Hugging Face 令牌](/settings?s=models&find=Hugging%20Face%20token)可让应用下载受限或私有的模型（该行显示“Only for gated or private models”）。请在你的 Hugging Face 账户设置中创建一个令牌，点击 **添加令牌**，将其粘贴到对话框中（以 `hf_` 开头），然后点击 **保存**。之后该行会显示令牌的开头和结尾，其 **⋯** 菜单中有 **移除令牌**。
