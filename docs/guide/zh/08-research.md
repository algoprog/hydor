# 深度研究、第二意见和多个智能体

当一个智能体单独干活不够用时，应用可以让好几个智能体一起上：深度研究会派研究员分头攻克问题的每个部分，最后交回一份注明出处的报告；子会话能从智能体手里接过任务的一部分；集群从几个角度同时攻克一个难题；战役则把一项大改动分成许多部分来完成。你还可以让另一家公司的模型检查某一轮的工作，把同一个提示词发给几个模型并留下最好的回答，还可以给会话设一个花费上限，免得这些功能把你的钱花得失控。

![开始页面上的深度研究：同时几个研究员、几轮、总共多少次搜索，以及报告的形式](images/research.webp)

## 运行深度研究

深度研究适合需要很多来源的问题：比较几个选项、核实一个说法、全面了解一个主题、弄清楚关于某件事目前已知的情况。你启动的那个智能体负责主导。它会规划搜索，派研究员分头去查问题的每个部分，深挖他们没解决的地方，让关键说法都经过两个来源的核对，最后交付一份每个来源都注明出处的报告。

### 打开它

1. 在开始页上打开**选项**（消息框下方那一行最右边的按钮），然后选择**研究**。
2. 选择**深度研究**（“广泛搜索，核查来源，并注明出处”）。它的设置会出现在下方。
3. 设置各项数字和你想要的报告类型（见下文）。
4. 在消息框中输入你的问题，然后按**开始**。

这时“研究”一行会显示“深度 · 60 次搜索”（你的搜索预算），选项按钮上也会写明它（“深度研究”）。选择**关闭**（“由一个智能体回答，按需搜索”）即可回到单个智能体。

在手机上，选项会以面板的形式从屏幕底部弹出，研究则在它上面打开。

深度研究和集群（或战役）都是通过一组子会话来工作的，所以只能选其一：打开一个，另一个就会关闭。

定时任务也可以在每次运行时做一次深度研究：它的编辑器里有同样的**研究**设置（[定时任务](/guide/tasks)）。

### 它的设置

- **同时进行的研究员数**（1 到 8；默认为 4）：每一轮有多少个研究员同时搜索，也就是每一轮铺得有多宽。
- **轮数**（1 到 5；默认为 2）：研究进行几轮，每一轮都去追查上一轮留下的空白。这些轮次之后还有一轮核查。
- **总搜索次数**（10 到 500，以 10 为单位增减；默认为 60）：整个研究可以使用的网页搜索次数，主导智能体和研究员的加在一起。
- **报告**：**网页**或 **Word**。

这个浏览器会记住这些数字，供你下次做深度研究时使用。但模式本身不会保留：每个新会话开始时，研究都是关闭的，因为一次深度研究的花费是一次普通回答的好几倍。

### 逐步看它怎么进行

1. **规划**。主导智能体先弄清楚这个问题真正问的是什么，完整的回答应该涵盖哪些内容。它把问题拆成若干子问题，并为每个子问题写几条搜索：措辞各不相同，在有帮助时也用其他语言，并且瞄准能下定论的来源（官方数据、论文、原始文件、可靠的报道）。如果有关键的地方不清楚，它会简短地问你一次；否则它会说明自己的假设，然后继续。
2. **第一轮**。它最多启动你设定数量的研究员，每个子问题一个。每个研究员都是一个子会话，有一份自己的任务说明：整个问题、它负责的部分、从哪些搜索开始、它大约可以用多少次搜索，以及要汇报什么。然后主导智能体等待；每个研究员的报告都会以消息的形式发回给它。
3. **更多轮次**。主导智能体阅读这些报告，再派新的研究员去追查其中的空白、矛盾，以及只靠单一来源支撑的说法。如果没有什么重要的问题悬而未决，它就跳过这一轮。每轮结束后，它会用一句话告诉你发现了什么、接下来做什么。
4. **核查**。它列出回答所依据的各项说法。每一项都需要两个相互独立的来源，否则就标明只有一个来源，或者标明有争议。由一个研究员（或主导智能体自己）打开引用的网页，确认每个关键说法和数字确实在那里；核对不上的会被更正或删掉。
5. **报告**。它撰写报告：一个清楚的标题，开头先用几句话给出答案，然后分节展开，每个说法后面都有编号的引用，末尾列出来源（标题、网站、日期和链接）。它会说明哪些地方不确定或有争议、原因是什么，并在对话中给你一份简短的总结。

研究员用应用自带的网页搜索来搜索，用它的网页阅读器来读网页（[搜索和浏览器](/guide/web)）。为了让每次搜索都计入预算，深度研究中会关闭 Claude Code 和 Codex 内置的网页搜索。预算用完后，搜索会被拒绝，智能体会被告知根据已有的内容撰写报告。同样，一旦你设定的轮次和核查那一轮都完成了，主导智能体就不能再启动更多研究员。

### 在会话中跟进

主导会话的消息框上方有一个横条，显示研究正在做什么：**深度研究** · 先是“规划中”，然后是“第 1 轮，共 2 轮 · 4 位研究员在工作”，两轮之间是“正在阅读报告”，研究员核查关键说法时是“核查来源”，接着是“正在撰写报告”，最后是“报告已完成” · 以及预算用了多少（“已用 12 次搜索，共 60 次”）。报告完成后，横条右侧的**打开报告**会打开它：资料库中的那个网页，或那份 Word 文档。把指针指向横条，可以看到这次研究的设置和报告的形式。

每个研究员都会以标着“研究员”的卡片显示在主导智能体的对话中，并在侧边栏里排在主导会话下面，和任何[子会话](/guide/research#follow-child-sessions)一样。每个研究员发回的内容显示为一行：“回复来自”和它的标题，后面是它所发现内容的开头；点击这一行就能阅读。打开一个研究员就能看它工作：它的横条写着“正在研究”和主导会话的标题，点**主导**可以返回。

### 报告

- **网页**：报告会保存为一个页面，供你留存。它显示在对话中，并保留在你的资料库里（[资料库：页面、图片、视频和网站](/guide/library)）。
- **Word**：报告是会话文件夹里的一个 Word 文档（.docx），由应用的 **word-documents** 技能生成，并显示为一张文件卡片，你可以打开或下载（[文档、图片、视频和语音](/guide/documents-voice#open-or-download-the-files-an-agent-made)）。

深度研究会同时运行很多智能体。开始之前，先在同一个选项菜单里设一个花费上限：它涵盖主导智能体和它的所有研究员（[给会话设花费上限](/guide/research#put-a-spending-cap-on-a-session)）。

## 让智能体把工作交给子会话

任何智能体都可以把工作中自成一体的一部分交给一个新会话，也就是子会话；子会话同时处理这部分工作，并汇报结果。不需要打开什么开关：用平常的话提出来就行（“让三个子会话各调查一家供应商”“你写文档的时候，让 Codex 去写测试”），或者让智能体自己判断什么时候适合拆分工作。

对每个子会话，智能体会选好：

- **智能体和模型**：Custom 及它的任意模型（来自[设置 → 模型](/settings?s=models)）、Claude Code、Codex，或者你添加的其他智能体（Gemini CLI、OpenCode……）。默认情况下，子会话运行的智能体和启动它的会话相同。便宜的模型或本地模型适合大批量的工作；Claude Code 或 Codex 适合难啃的部分。
- **文件夹**：用父会话的文件夹，除非它指定了别的。
- **工作树**（如果需要）：在一个新分支上为文件夹的 git 仓库单独做一份副本，这样子会话的更改就不会和别人的混在一起。
- **一个简短的标题**，也就是你看到的名字。

子会话看不到父会话的任何对话内容，所以智能体会给它写一份任务说明，把它需要的一切都写进去。子会话工作时没人盯着：小问题它自己决定，并说明自己是怎么决定的，只有在无法继续时才会停下来提问。

### 回复怎么传回来

子会话的一轮结束时，它的回复会作为一条消息发回父会话，并唤醒父会话。如果父会话正忙，这条消息会在它的队列里等着，直到它这一轮结束。

在父会话的对话中，回复显示为一行：“回复来自”、子会话的标题，以及它所写内容的开头。点击这一行就能阅读回复（回复很长时是它的摘要），再点**打开它的会话**或**阅读完整回复**就能转到子会话。在完成之前被停止的子会话显示为“… 已被停止”，出错的显示为“… 因出错而停止”。

- 超过约 4,000 个字符的回复，会以辅助模型写的简短摘要送达（[智能体、账户和模型](/guide/agents-models)）；父会话仍然可以读到全文。
- 如果子会话因出错而停止，或者在完成之前被停止，父会话也会得到通知。
- 父会话随时可以查看它的子会话（每个在做什么、用的是哪个智能体和模型、花了多少钱、最新回复的开头），也可以给其中某个再派些工作。
- 在应用停止期间结束的那些轮次，其回复会在应用重新启动时传过去。

你可以打开一个子会话，像和其他会话一样与它对话。它在一轮结束时的回复同样会发回父会话。

### 跟进子会话

- **在父会话的对话中**：每个子会话都有一张卡片，位于启动它的那一轮下面。卡片上有子会话的标题、“子会话”（深度研究中为“研究员”）、它的智能体和模型、它现在在做什么（停下后会显示“未在运行”或“因出错而停止”）、上次活动的时间，以及它花了多少钱。点击它（**打开**）就能转到子会话。子会话工作时，旁边的方形按钮可以停止它的这一轮。
- **在侧边栏中**：子会话排在父会话下面，折叠成一行，比如“3 个子会话 · 1 个需要你 · 2 个在工作”。点击这一行就能展开；当你在其中某个子会话里时，它会保持展开。在手机上，侧边栏是一个抽屉，轻点这一行会展开它，而不会关闭抽屉。
- **在子会话中**：消息框上方的横条写着“子会话，来自”和父会话的标题（“它的回复会发回那里”），旁边有**打开父会话**。

需要你批准或回答的子会话，会像任何会话一样等你处理，并显示在收件箱里（[收件箱和通知](/guide/inbox)）。

### 子会话能做和不能做的事

- **只有一层**。子会话不能再启动自己的子会话：它自己完成那部分工作，并说明还需要做什么。
- **权限绝不会更宽**。子会话得到的权限绝不会比启动它的会话更宽。当它运行的是 Claude Code、Codex 和 Custom 中的另一个时，它会得到那个智能体的权限中不比父会话宽的、最宽的一档；其他智能体（Gemini CLI 之类）则从它们自己的默认权限开始。
- **分到一份上限**。如果父会话有花费上限，每个新的子会话都会从剩余的额度中分到一份，而父会话的上限涵盖它们全部（[子会话的上限](/guide/research#caps-for-child-sessions)）。
- **同一个账户**。运行与父会话相同智能体（Claude Code 或 Codex）的子会话，使用父会话的账户。
- **一次只能几个**。一个会话的子会话同时工作的数量有限；智能体要等一个完成，才会启动下一个。

### 设置同时工作的数量

在[设置 → 功能 → 子会话](/settings?s=children)中，用 − 和 + 设置**每个会话同时工作的数量**（[直接前往](/settings?s=children&find=Working%20at%20once%2C%20per%20session)）：从 1 到 12，默认为 4。它分别计算每个会话的子会话，而不是整个应用的。深度研究改用它自己的**同时进行的研究员数**，集群则用它的**集群规模**。

## 让集群攻克难题

集群让一组智能体共同对付一个问题。由一个主导智能体把问题拆成真正不同的切入角度（不同的方法、假设或看问题的方式），并为每个角度启动一个成员。成员把自己尝试了什么、发现了什么发布到一块共享的看板上，阅读彼此的帖子，互相发消息；主导智能体掌控方向，随着有成员完成而启动更多成员，并在把答案交给你之前先让人核查。

它适合有许多可能路径的难题：一个证明、一个顽固的 bug、一个谁都找不到明确入口的问题。它的花费是单个智能体的好几倍。

### 启动集群

1. 在开始页上打开**选项**，然后选择**集群**。
2. 选择**集群**（“最多同时 5 个智能体，各自从自己的角度出发”；这个数字就是你的集群规模）。
3. 输入任务，然后按**开始**。

“集群”一行会显示“开启 · 同时 5 个”，选项按钮上也会写明它。菜单底部的**集群规模**会带你到它的设置。和深度研究一样，这个模式不会保留到你的下一个会话，而且两者只能开一个。在同一个选项菜单里设的花费上限涵盖主导智能体和每个成员。定时任务的编辑器里也有同样的**集群**设置，可以在每次运行时启动一个集群。

### 集群如何运作

1. 主导智能体先弄清楚任务要求什么、经过核查的答案应该是什么样子，然后选出最多与你的集群规模相同数量的不同角度（比如证明题：直接论证、反证法、归纳法、小情形加计算机搜索、已知结果）。
2. 它为每个角度启动一个成员。每个成员都是一个子会话，带有一份任务说明：整个问题、它的角度、怎样才算完成以及如何核查，标题就是它的角度。除非主导智能体另选，成员会使用和主导智能体相同的模型和思考强度。
3. 成员边做边往看板上发帖：**进展**（尝试了什么、做到哪儿了）、**发现**（其他成员现在就能用的结果）、**问题**（需要有人回答的事）和**备注**。他们每隔几步就看一下看板，在彼此的发现上继续推进，跳过别人已经排除的方向，并回答别人向他们提出的问题。
4. 主导智能体会分批收到看板上的动态：一个发现、一个问题或一条发给主导智能体的消息，大约一分钟内就会送到；只有进展的话，每隔几分钟送一次。它会把有用的发现转告其他成员，把卡住了或在重复别人工作的成员转到新的角度，请一个成员核查另一个成员的结果，并在有成员完成时，为还没人尝试过的思路启动新成员。
5. 在得出结论之前，主导智能体会让答案经过独立核查：由另一个成员核查、通过一次计算核查，或由它自己仔细检查。
6. 当问题解决了或者角度都用完了，它会停止仍在工作的成员，然后给你答案：结果是什么、是怎么找到和核查的，以及哪些角度失败了、为什么失败。

完成自己角度的成员会把报告发给主导智能体。发给一个不在工作的成员的消息会把它唤醒。

### 跟进它：横条和看板

主导智能体的会话在消息框上方有一个横条：**集群** · 起初是“正在选择切入角度”，之后会是“3 个在工作 · 2 个已完成 · 14 条帖子”这样的内容，还有**排行榜**按钮。每个成员的会话也有一个横条：“所属集群”和主导会话的标题（“它的帖子和报告都会发到那里”），以及**排行榜**和**主导**按钮。在侧边栏中，成员排在主导会话下面，折叠成一行，比如“5 个集群成员 · 3 个在工作”。

**排行榜**会打开集群看板（在手机上从屏幕底部弹出）：

- **成员**：有多少个正在工作、最多可以同时工作多少个，然后是每个成员和它现在在做什么，或者“已完成这一轮”“已停止”“因出错而停止”。点击一个成员可以打开它的会话；**打开主智能体**会转到主导会话。在主导智能体选好角度之前，列表会说明还没有成员启动。
- **帖子**：所有发布的内容，最新的在前。每条帖子会显示是谁写的（主导，或成员的标题）、发给谁（如果是发给某个成员或主导智能体的）、它的类型（进展、发现、问题、备注），以及发布了多久。可以在**全部**、**发现**和**问题**之间切换。新帖子一到就会出现。

### 停止成员

看板上的**全部停止**（有成员在工作时才会出现）会停止所有仍在工作的成员。被停止的成员会保留已经做完的工作，新的帖子也不会再唤醒它们。主导智能体会得知你停止了它们，它仍然可以给其中某个再派些工作。问题一旦解决，主导智能体会自己停止成员。

### 设置集群规模

在[设置 → 功能 → 子会话](/settings?s=children)中，**集群规模**（[直接前往](/settings?s=children&find=Swarm%20size)）决定一个集群或战役中同时工作的成员数量：从 1 到 16，默认为 5。每个成员的花费大约相当于一个智能体；随着有成员完成，主导智能体会启动更多成员。

## 用战役完成一项大改动

战役是集群的另一种形式，用于在整个代码库中完成一项大改动，而不是攻克一个难题：一次迁移、一次框架升级、一次到处都要改的重命名。在同一个地方选择它：**选项** → **集群** → **战役**（“把一项大改动拆成几部分，各在一个工作树中完成”），所在文件夹必须是 git 仓库。之后“集群”一行会显示“战役 · 同时 5 个”。

主导智能体把改动拆成几部分（包、模块、文件夹），并把它们作为计划发出来。每个部分由一个成员在新工作树中、在自己的分支上完成，同时工作的成员最多不超过你的集群规模；成员运行检查后，发帖把这一部分标为完成或失败；失败的部分还会再试一次。主导智能体逐个合并完成的部分，每合并一个就运行一次检查（如果你要求了，就改为每个部分开一个拉取请求），然后报告改了什么、哪些失败了。它的横条显示“战役 · 已完成 12/40 个部分 · 2 个失败”，它的看板会在帖子旁边显示各个部分以及每部分的状态。参见[战役：分成许多部分的一项大改动](/guide/engineering#campaigns-a-big-change-in-many-parts)。

## 对某一轮征求第二意见

第二意见会让另一家公司的模型，对照你的要求检查智能体在某一轮中做了什么：它改了哪些文件、运行了哪些命令、回复了什么。审查者会找出遗漏的地方（要求了却没做，或者说做了其实没做）、错误的地方（bug、错误的事实或数字、理解错了要求）、有风险的地方（可能弄坏东西、丢失数据或泄露机密的更改），以及多余的地方（没人要求、反而碍事的更改）。它把智能体的回复当作有待核实的说法，而不是证据。

### 发起一次

1. 打开会话的菜单（⋯），选择**第二意见**。
2. 在**由谁检查**下选择审查者。推荐的那个排在最前面。
3. 在**哪一轮**下选择要检查的那一轮。默认已选好最近完成的一轮；列表里最多有 12 个最近的轮次，每个都注明了时间和改动了多少个文件。
4. 按**询问**（按钮上会写着审查者的名字，例如**询问 Codex**）。

那一轮下面会立刻出现一张卡片，审查者回答后（通常在一两分钟内）卡片就会填上内容。仍在运行的一轮要等它结束后才能检查。在手机上，对话框会从屏幕底部弹出。

### 谁可以检查这份工作

只有和做这份工作的模型来自不同公司的模型才可以，这样就没有人检查自家的工作：

- **Claude Code** 会话，或任何运行 Anthropic 模型的会话，可以由 **Codex**（通过 Codex 程序）检查，也可以由 Custom 的某个非 Anthropic 模型检查。
- **Codex** 会话，或任何运行 OpenAI 模型的会话，可以由 **Claude**（Sonnet，通过 Claude Code）检查，也可以由 Custom 的某个非 OpenAI 模型检查。
- 其他任何会话（Custom，或者使用其他厂商模型的其他智能体）可以由 Claude、Codex 检查，也可以由 Custom 中与该会话的模型来自不同厂商的某个模型检查。

Custom 的模型就是你在[设置 → 模型](/settings?s=models)中添加的那些。审查者只读不写：Claude 和 Codex 可能会打开会话文件夹里的文件来核对某个具体的地方，但不会改动任何东西。除了这一轮本身，审查者还会看到你在这个会话中的第一条消息，以及你在那一轮之前发的消息，作为背景。当改动太大、无法全部展示时，会省略一部分，卡片上也会注明。

### 卡片上显示什么

卡片的标题写着**第二意见**和审查者的名字，然后是：

- 工作中：“正在检查成果”和已经用了多长时间，还有一行说明审查者正在读什么。
- 完成后：按严重程度列出的问题数（“1 个严重 · 2 个重要”）、**看起来不错**（如果有次要问题，会附上数量），或者在回答无法解读为具体问题时显示**没有明确结论**。
- 如果失败了：**没有回答**，附上原因（审查者的程序没有装在这里、它在 8 分钟内没有给出回答，或者应用在此期间重启了），以及**重试**。

点击标题可以展开或折叠卡片。里面是审查者的总结和它发现的问题，最严重的在前。每个问题都包含：

- 它的严重程度：**严重**（照现在这样是错的、坏的或不安全的）、**重要**（在依赖这份工作之前先修好）或**次要**（值得看一眼，不改也行）；
- 一个简短的标题，以及涉及的文件和行（点击它可以在那个位置打开文件）；
- 哪里不对、为什么重要，以及怎么修。

当有更严重的问题时，次要问题会折叠在**显示 N 个次要问题**下面（**隐藏次要问题**会再把它们折叠起来）。点 × 可以关掉这张卡片。

### 把它的意见发给智能体

- 每个问题旁边的发送按钮（一个纸飞机图标：**发给智能体**）会把它放进消息框，你可以直接发送，也可以先编辑。
- **全部发给智能体**会一次把显示出来的所有问题都放进消息框。
- 智能体正在工作时，**全部排队**（或**加入队列**）会把它们加入会话的队列，等它这一轮结束时再发给智能体。

这条消息会写明审查者，列出每一点及其严重程度和文件，并请智能体对照自己的工作逐一核实，修好确实成立的问题，并说明哪些没有处理、为什么。

## 在竞技场中比较模型

模型竞技场会把同一个提示词同时发给两三个模型，让你可以并排比较它们的回答，留下最好的那个。你保留的每个回答都会计入一项评分，显示哪些模型在你自己的任务上胜出。

### 开始一场对局

1. 在开始页上像平常一样选好智能体和模型：这就是对局中的第一个模型。
2. 打开**选项** → **竞技场**，选择**比较模型**（“把同一个提示词发给更多模型，并排比较”）。
3. 在“除了你选的模型，还要询问（最多 2 个）”下面，再勾选一两个模型。列表中 Claude Code、Codex 和 Custom 各有几个模型，还有你添加的其他智能体；列表很长时，可以用**查找模型**输入框缩小范围。
4. 输入提示词，然后按**开始**。

“竞技场”一行会显示“+1 个模型”或“+2 个模型”，选项按钮上也会写明它。这个浏览器会记住你上次的选择，但竞技场不会为你的下一个会话保持开启。

每个模型都在自己的会话中工作，使用相同的提示词、附件、文件夹和会话设置（助手、记忆、花费上限），以及它的智能体平常的思考强度和权限。在 git 仓库中，请在文件夹菜单里打开**新建工作树**，这样每个模型都会得到一份自己的代码副本，而不是全都在同一个文件夹里改动。如果某个模型无法启动，应用会告诉你，对局会在没有它的情况下继续。

### 比较回答，保留最好的

对局中的每个会话在消息框上方都有一个横条：**竞技场** · “同一提示词也发给了其他模型”，以及**比较回答**。点它会打开比较页面：顶部是提示词，每个模型一栏，显示它最新的回复，回复一到就会填进去。在宽屏上各栏并排显示，在手机上则上下排列。

- **保留这个**（在那个模型回复之后）会保留它的回答。它的会话赢得这场对局，其他会话则被归档：不再出现在你的会话列表中，但仍然可以打开。之后各栏会显示**已保留**和**已归档**。
- **打开**会转到某个模型的会话。在被保留的那一栏里，它显示为**在这里继续**，可以和胜出者接着对话。
- **哪些模型胜出**（在手机上是**排行榜**）会打开用量 → 竞技场。

### 看看哪些模型胜出

[用量 → 竞技场](/arena)（在搜索框 Ctrl+K 中叫“模型竞技场”）显示**哪些模型在你的任务上胜出**：每个模型的**评分**、它在参加过的对局中被保留了多少次（**已保留**），以及它的**胜率**（手机上不显示）。这个评分是 Elo 评分，也就是给国际象棋选手排名用的那种，从 1000 起算：在你做出选择的每场对局中，你保留的回答都算作击败了其他每一个回答。

在它下面，**对局**列出你最近的对局（最多 100 场）：提示词、参赛模型和时间，并标出胜出者；还没决定的对局则标为**打开**。点击其中一场就可以比较它的回答。

## 给会话设花费上限

花费上限是一个会话按 API 价格最多可以花的钱：也就是它用掉的 token 如果通过 API 计费要花多少，不管你实际是用哪种套餐付费。花到上限时，智能体就会停下，直到你提高上限。凡是会运行很多智能体的功能，配上它都很合适：深度研究、集群、子会话、竞技场对局。

### 哪些花费会计入

- 会话自身的模型调用，包括它的智能体自带的帮手（例如 Claude Code 的子智能体）。
- 它启动的子会话：它的上限也涵盖它们。
- 这台电脑上的模型（通过 Ollama 或 vLLM）不花钱。
- 价格未知的 token 无法计入。如果会话可能因此实际花得更多，上限对话框会注明。

关于会话的总体花费，请看[用量、限额和费用](/guide/usage)。

### 开始时设置上限

在开始页上打开**选项** → **花费上限**。输入一个美元金额，然后按**设置**（或 Enter），或者选 $1.00、$5.00、$10.00 或 $25.00。**无上限**会取消它。之后选项按钮上会写明这个上限（“$5.00 花费上限”）。

和深度研究、集群或竞技场不同，你选的上限会一直保留：在你更改它之前，你之后的会话无论在哪台设备上开始，都会带着它。

### 设置或更改会话的上限

打开会话的菜单（⋯）→ **会话设置** → **花费上限**（旁边显示当前的上限）。对话框会显示**目前已花费**：如果这个会话有子会话，会分别列出它自己和子会话的花费；如果它是子会话，还会显示父会话的上限已经花掉了多少。在**上限**里输入金额，或者选 $1.00、$5.00、$10.00 或 $25.00，然后按**设置上限**（或**修改**）。**取消上限**会把它去掉。

上限可以从 $0.01 到 $100,000。如果设的上限不高于会话已经花掉的金额，对话框会提醒你，会话将保持停止状态。在手机上，对话框会从屏幕底部弹出。

### 消息框上方的横条

会话设有上限时，消息框上方的横条会显示已经花掉了多少（“$1.20 / $5.00”），旁边有一条逐渐填满的进度条：到 80% 时变成琥珀色，到达上限时变成红色，并显示**已达上限**。如果子会话也花掉了一部分，它会加上“含子会话”（在较宽的屏幕上）；把鼠标指向金额就能看到各自花了多少。**修改**（达到上限后是**提高**）会打开上限对话框。

### 达到上限时会怎样

每次模型调用之后都会检查上限，所以一轮会在达到上限的那次调用之后立刻停下（总额最后可能会略高于上限）：

- 智能体停下，那一轮下面会出现一条说明，写着“已在花费上限处停止”和上限已花掉的金额，以及**提高上限…**。还会有一条提示写明是哪个会话停下了。
- 它正在运行的子会话也会停下。它们的说明会写明启动它们的会话已达到花费上限，并有**打开**可以转过去。
- 新消息要等着。你发送的消息不会被发出：会有提示说已达上限，你的文字会留在消息框里。队列中的消息会被搁置（“队列已暂停”），直到你提高或取消上限。

### 提高或取消上限

点击横条上的**提高**或说明里的**提高上限…**（或者使用会话的菜单），然后设一个高于会话已花金额的上限，或者把上限取消。之后，队列中被搁置的消息就会发出。因父会话的上限而停下的子会话，在父会话的上限提高后，就能再次接收消息。

### 子会话的上限

每个新的子会话都有自己的上限：父会话上限的剩余额度，按父会话加上最多可同时工作的子会话数平均分配，它得到其中一份。父会话的上限仍然涵盖它们全部，所以一旦达到这个上限，它们都会停下。剩余额度用完后，智能体就不能再启动子会话，并会被告知用手头已有的结果完成工作。

### 定时任务和应用的上限

- **定时任务**：任务的编辑器（[设置 → 定时任务](/settings?s=tasks)、**新建任务**，或任务菜单 → **编辑**）在它那一行设置里有开始页上的那个**花费上限**，而**每次运行**下的**花费上限 $** 一栏设置的也是同一个上限；留空表示没有上限。每次运行的会话到达上限就会停下。它适用于启动新会话的运行；发到现有会话中的运行，则在那个会话自己的上限内工作。智能体在对话中为你设置的任务，每次运行都会沿用那个对话的设置，包括它的上限。请看[定时任务](/guide/tasks)。
- **应用**：应用的**限制**里有**单次运行最多可花费（US$）**。请看[应用](/guide/apps)。

## 问问智能体

- “为一栋 1930 年代的房子做一次关于热泵的深度研究，同时 6 个研究员，出一份 Word 报告，花费上限 10 美元。”
- “我那个‘电动车充电桩对比’会话里的深度研究进行到哪一步了？”
- “给这个会话设 5 美元的花费上限，再告诉我它到目前为止花了多少。”
- “让每个会话最多同时运行 6 个子会话，并把集群规模设为 8 个智能体。”
- “对我那个‘账单重构’会话的最后一轮征求第二意见，并告诉我它发现了什么。”
- “在我的竞技场里，哪些模型胜出？最近那场对局，保留 Claude Code 的回答。”
