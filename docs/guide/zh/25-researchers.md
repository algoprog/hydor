# 研究：论文、写作和实验室

Hydor 能帮你处理研究周边的工作：跟上你所在领域的进展，阅读和整理论文，在论文投出去之前检查它，回复审稿意见和展示你的工作，以及你实验室的实验和报告。其中大部分是[应用](/apps)页面上**研究**、**写作**、**实验室**和**工作**分类下的现成应用，你开口时智能体也会替你运行它们；论文的检查在 [LaTeX 编辑器](/guide/library)中，你的训练运行在[系统 → 实验](/guide/experiments)中。要审阅别人的投稿？请使用[保密会话](/guide/sessions#keep-a-session-confidential)。

## 跟上你所在领域的进展

有六个现成应用帮你跟上所在领域的进展：它们在应用页面的**研究**分类下（打开[应用](/apps)，选**研究**标签）。其中五个在自己的页面上打开，并且可以每天自动更新：**论文雷达**、**引用提醒**、**新模型追踪**、**截稿雷达**和**动态相关工作**。第六个是**研究空白发现器**，在你需要时通过表单运行，智能体也可以在任何会话中替你运行它。

它们会适度地读取开放服务：arXiv、OpenAlex、Semantic Scholar、Hugging Face，以及 GitHub 上的截稿日期列表 ccfddl 和 ai-deadlines。它们都不需要密钥，但有两个密钥会有帮助：**OpenAlex API 密钥**（免费：没有它时，每次更新最多只向 OpenAlex 请求两次，用的是你所在网络中所有人共享的一小份额度）和 **Semantic Scholar API 密钥**（申请即可免费获得：没有它时 Semantic Scholar 常常很忙，会改由 OpenAlex 回答，但就没有引用你的那些句子了）。在应用的设置（它页面顶部的滑块图标）中、**它需要的密钥**下面填写它们：它们会存入你的保险库，并且只会发送给这些服务。

在应用自己的页面上，顶部的**更新**会立刻做出新的一份，滑块图标里是它的设置：**每天更新**（在你打开之前一直是关闭的）、时间，以及它的问题。页面下方的**更早**会列出之前的各份，每一份都按原样打开。在第一份之前，页面只会问应用必不可少的信息（你作为作者的名字、你投稿的会议）；**做出第一个**会把你的回答保存为它的设置。一旦它每天更新，“设置 → 定时任务”里也会列出它（见[定时任务](/guide/tasks)）。

### 论文雷达

[论文雷达](/apps/t/paper-radar)每天早上为你带来你所在领域的新论文，按与你工作的相关程度排序，每篇都附一句话，说明它做了什么、为什么对你重要。

- **它读什么**：arXiv 上你关注的分类里的新论文（最多几百篇，取最近三天提交的，中断一段时间后会往前多取一些）、任何领域里与你的主题相关的论文，以及你关注的人的论文；还有 OpenAlex 上与你的主题相关的论文（期刊和会议论文集）。之前某次更新看过的论文不会再出现。
- **怎样排序**：对照你的项目（它们的名称、简介和最近的会话）、你的主题和你的档案来排序。开启[按含义搜索](/settings?s=memory&find=Search%20by%20meaning)时，用你电脑上的嵌入模型按含义排序，否则按字词排序。你收藏的论文会把排序拉向它们；你放到一边的则会把排序推开。你关注的人的论文总是排在最前。
- **页面**：**今天**：当天的论文，放在每篇最契合的项目或主题下面（在顶部选一个，或选**全部**）。每张卡片都有它发表的地方和时间、标题（指向它的链接）、作者、一句话说明它做了什么以及为什么适合你，还有 **☆ 保存**、**引用**（复制它的 BibTeX）、**PDF**、**深入研究**（针对它的一份[深度研究报告](/apps/t/deep-research)，需要几分钟）和**不适合我**（它会收起来，并提供**撤销**）。**已保存的论文**按从新到旧列出你收藏的论文，带有**全部复制为 BibTeX**，每篇还有**引用**、**加入阅读清单**、**深入研究**和**移除**。
- **它的设置**：**要关注的领域**（arXiv 的分类，用名称或代码：Information Retrieval 或 cs.IR，Computation and Language 或 cs.CL；不是分类的领域会被当作主题）、**主题**（每行一个）、**要关注的人**（每行一个，写法和他们论文上印的名字一样）和**论文数量**（除非你修改，否则是 15，可在 5 到 40 之间）。留空时，它会从你的档案和项目中推断领域和主题。

每次更新会向辅助模型提一两个简短的问题（每篇论文对你意味着什么），需要一两分钟。

### 引用提醒

[引用提醒](/apps/t/citation-alerts)告诉你自它上次查看以来谁引用了你的论文，附上引用你的那句话，并说明对方是基于你的工作、与它比较，还是对它提出质疑。

- **页面**：**新增**：按你的论文分组的新引用：每条是怎样引用你的（**基于**、**比较**、**质疑**或**提及**，由辅助模型根据那句话判断；可以在顶部只看一种）、那句话（其中提到你论文的地方会标出来）、一句话说明它对你的工作说了什么，以及引用你的论文（一个链接）、它的作者、发表的地方和时间，带有**复制这句话**。**你的论文**列出你的论文，以及它们的引用数和其中有多少是新的。
- **它怎样找到它们**：它在 Semantic Scholar 上找到你（Semantic Scholar 忙时改用 OpenAlex），取你有引用的论文（引用最多的和最新的，每次更新三十篇），并查询最近谁引用了每一篇。看过的引用会保存下来，所以每次更新只显示新的；第一次时，只有上个月的引用算作新的。没有附带句子的引用论文，是该服务还没有读过全文的论文。
- **它的设置**：**你的作者身份**（你的名字，写法和你论文上印的一样，或者你的 Semantic Scholar ID（一串数字），或 OpenAlex ID（A 加数字））和**只看这些论文**（标题、DOI 或 arXiv ID，每行一个；留空：你的所有论文）。对大多数人来说，每周一次就够了：打开**每天更新**，或者请智能体把它改成每周一次。

### 新模型追踪

[新模型追踪](/apps/t/new-model-watch)在 Hugging Face 上留意某一类新模型（重排序模型、嵌入模型等），按你的限制检查它们，并对每个模型运行你自己的评估，这样只有超过你最佳成绩的模型才会让你知道。

- **它看什么**：这一类中最新的模型（名称里带有你给出的词），要等它们发布满你设定的天数（除非你修改，否则是 7 天），并且到那时有足够的下载量；每次更新取下载最多的八个（其余的等下一次）。同一模型的其他格式副本（GGUF、ONNX、量化版）会被排除，除非你给出的词要求它们。它会读取每个模型的页面和模型卡片，了解它的许可证、大小和用途，并排除你的许可证或大小要求所排除的模型。
- **你的评估**：给出一条命令，在模型名称的位置写 `{model}`（`python eval.py --model {model}`），以及它的文件夹、它打印的分数（`ndcg@10`）、分数越高越好还是越低越好，以及你目前的最佳成绩。之后每个值得一试的新模型都会在[实验](/system/experiments)中运行（分组为“New-model watch”，每个占一块 GPU，在它的队列中），有模型超过你的最佳成绩时，“实验”会告诉你；下一次更新会读取每次运行的分数。没有命令时，它只会列出新模型。
- **页面**：**模型**：每个模型都有它的状态（**新增**、**评估中**、**已评估**、**胜出**（超过你的最佳成绩）、**未运行**、**已跳过**、**太新**）、它的模型卡片怎么说、它的大小、许可证、下载量和点赞数，以及它的分数；超过你最佳成绩的排在最前。**你的评估**说明运行的是什么，带有**打开“实验”**。

### 截稿雷达

[截稿雷达](/apps/t/deadline-radar)把你投稿的各个会议的截稿日期放在一条按你的时区显示的时间线上，在每个截稿日期之前提醒你，并附上征稿启事、页数限制和模板的链接。

- **日期从哪里来**：GitHub 上的两个开放列表，ccfddl 的和 ai-deadlines 的，合在一起。每个截稿时间都会从征稿启事给出的时区（大多是 AoE，即 Anywhere on Earth，也就是 UTC−12）换算到你的时区，应用从你的浏览器获取你的时区。
- **页面**：**时间安排**：接下来的每个截稿日期，附上它在你所在地的日期和时间、要交什么（按征稿启事的说法）、会议在哪里举办、**征稿启事**和**模板**链接和页数限制，以及还剩多少时间（按你查看的时刻计算）；每个会议的下一个摘要截稿或论文截稿会突出显示。可以在顶部只看一个会议；**复制截止日期**会把它们复制成一行行文字；**显示已过去的**会展开最近几个月的截稿日期。**会议**完整显示每个会议、它的等级、下一个截稿日期和网站，以及两个列表都不认识的名称。
- **提醒**：每次更新会在你设定的那几天（除非你修改，否则是截稿前 14、3 和 1 天）给你发通知，每个提醒只发一次，所有提醒合在一条通知里。打开**每天更新**，提醒才能及时送到。
- **它的设置**：**你关注的会议**（按你的叫法，用逗号分隔：SIGIR、ACL、EMNLP、NeurIPS、The Web Conference、KDD……）和**提醒我**（提前几天，用逗号分隔；留空：不提醒）。为了找到每个会议征稿启事里的页数限制和模板，它会为每个会议搜索一次征稿启事并阅读（由辅助模型记下来）。

### 动态相关工作

[动态相关工作](/apps/t/living-related-work)为你的每个主题维护一个页面，随着新论文出现而增长：每篇论文都有一句话概括，并说明它与主题的关系，按方向分组，新的会标出来。

- **增长情况**：第一次时，它会取 arXiv 上每个主题最好的论文和过去一年里最新的论文，以及 OpenAlex 上引用最多的论文；之后只取此后发表的。引用你的种子论文的论文会进入每个主题。辅助模型会留下相关工作章节应该引用的论文，用一句话概括每篇，说明它的关系（与主题和你的种子论文的关系），并把它归入一个方向。
- **页面**：**相关工作**：每个主题及其论文，按方向排列，从新到旧，最近一次更新新增的标为**新增**（在顶部选一个主题）。每篇论文都有它的引用键、**BibTeX**（复制它的条目）和**不相关**（它会永久离开这个主题）。**起草相关工作**会让一个智能体用 LaTeX 写出这个主题的章节，每个方向一段，使用你的论文的 `\cite` 键：写完后会显示出来，带有**复制 LaTeX** 和**复制 .bib**（需要几分钟；你离开也会继续）。**导出 BibTeX** 会汇集这个主题的所有条目供你复制。**本次新增**列出最近一次更新新增的论文。
- **它的设置**：**主题**（每行一个）、**种子论文**（标题、arXiv ID 或 DOI，每行一个）和**每个主题最多论文数**（除非你修改，否则是 80）。

### 研究空白发现器

[研究空白发现器](/apps/t/gap-finder)把你的论文与某个领域本月的论文交叉，找出项目点子，检查每个点子是否已有前人工作，并按你拥有的算力估算它的规模。它从自己的表单运行，也可以由智能体在会话中替你运行。

- **你要提供的**：**你的论文**（你作为作者的名字，会带来你最新的和引用最多的论文；或者它们的标题或 arXiv ID，每行一个）、**研究领域**（用文字描述，或一个 arXiv 分类：conversational search、cs.IR）、**你拥有的算力**（除非你另外说明，否则是“one 24 GB GPU”，即一块 24 GB 的 GPU）和**想法数量**（5）。
- **它做什么**：它读取你的论文和这个领域过去一个月的论文，按与你论文的关系给这个月的论文排序，并让辅助模型提出把两者交叉起来的点子。对每个点子，它会在 arXiv 和 Semantic Scholar 上搜索前人工作，并让辅助模型作出判断：**新增**、**部分已有人做过**或**已有人做过**，附上最接近的论文；还有要做的第一个实验、它在你的算力上需要多少资源，以及它是**合适**、**吃紧**还是**太大**。
- **视图**：**研究想法**：全新的排在前面（可以在顶部只看一种判断），每个都说明它交叉了什么、为什么作出这个判断、最接近的工作（一个链接）、第一个实验及其成本，还有**规划它**（打开研究冲刺应用，以这个点子作为它的问题）、**深入研究**（一份关于相近工作的深度研究报告）和**复制**。**交叉组合了什么**列出它用到的你的论文和本月的论文。

## 阅读和整理论文

[应用页面](/apps)上**研究**分类下有三个现成应用，帮你处理你读的论文：**阅读清单**保存它们，**文献矩阵**在一张电子表格里比较几篇论文，**复现论文**通过运行论文的代码检查它的数字是否站得住。可以在那里打开它们，也可以在任何会话中直接说出你想做的事（“把 1706.03762 加到我的阅读清单”），智能体会替你运行它们（[让智能体替你运行应用](/guide/apps#have-an-agent-run-an-app-for-you)）。

无论你怎样给出一篇论文，它们都能找到：DOI、arXiv ID、链接（arXiv、DOI 链接、ACL Anthology、OpenReview、出版商的页面或 PDF）、标题，或者这台电脑上的 PDF。它们只从开放的副本读取论文（arXiv、OpenAlex 知道的开放副本、论文自己的页面），从不绕过付费墙：没有开放副本的论文会根据摘要来读，应用也会说明这一点。

### 阅读清单

[阅读清单](/apps/t/reading-list)打开时显示的是你的论文，而不是表单：它是一个工作的地方。

- **添加论文**：点 **+ 添加**，然后填写**论文**（DOI、arXiv ID、链接或标题），愿意的话还可以填它的**项目**、**标签**（用逗号分隔）和**状态**。**添加**会查找它，并连同作者、年份、发表处、摘要、指向它和开放 PDF 的链接，以及它的 BibTeX 条目一起保存。已有的论文不会重复添加（DOI、arXiv ID 或标题相同）：会补上它缺少的信息，你的备注、标签和状态保持不变。什么都没找到的论文会以你给出的标题保存，并据此生成一个条目：请检查一下这种论文。
- **找到你的论文**：顶部显示你有多少篇待读、在读和已读（点击一项只显示那些论文），分布在多少个项目中。**搜索你的论文**按论文里的任何字词查找，**全部**、**待读**、**在读**和**已读**只显示一种状态。每篇论文都显示它的作者、发表处和年份、项目和标签（点击一个只显示它的论文；它的 **✕** 会重新显示全部），以及**待读**、**在读**和**已读**，用来改变它的状态：**已读**会记下日期。
- **论文自己的页面**：点击它的标题。页面上有**它的页面**和 **PDF**（这台电脑上的论文则是**打开 PDF**）、它的状态、摘要、项目和标签（各带**保存**）、你的**备注**（**保存备注**）、它的 BibTeX（**复制 BibTeX**）和**从清单中移除**。**复现它**会打开[复现论文](#reproduce-a-paper)，并填好这篇论文。
- **按项目**：每个项目，以及它有多少篇论文、你读了多少篇；点击一个项目只显示它的论文。写上你的某个[项目](/guide/projects)的名称，它的论文就归入那个项目（你重命名项目时也会跟着走），也可以用你喜欢的任何名称。
- **更多**里有**导入 .bib**（粘贴它，或者给出这台电脑上一个 .bib 文件的路径，并为它新增的论文设定项目和标签：已有的论文会被补全，你的内容保留）、**导出 .bib**（**当前显示的**，即你的搜索和筛选所显示的，或**全部**：下载一个文件，或者**复制**）和**与 Zotero 同步**（见下文）。
- **生成文献矩阵**：勾选论文（它们左边的方框），会出现一条横栏，显示你选了多少篇，带有**生成文献矩阵**（用它们启动[文献矩阵](#literature-matrix)）和**清除**。

当智能体替你添加论文时，它的卡片会显示**论文**：清单中这篇论文现在的样子、它是否是新加的、**打开你的阅读清单**，以及可以复制的 BibTeX。

### 与 Zotero 保持同步

**更多** → **与 Zotero 同步** → **立即同步**会让清单和你的 Zotero 文库保持一致。

1. 第一次时，页面会要求你提供 **Zotero API 密钥**：**获取**会打开 Zotero 的密钥页面，在那里创建一个可以读取你文库的密钥（如果也要把论文同步过去，还要允许写入）。粘贴它并按**保存**：它会存入你的保险库，只供 Zotero 使用（[把密钥存放在保险库中](/guide/connections#keep-keys-in-the-vault)）。**Zotero 用户 ID** 可以留空：会根据密钥找到它（如果是群组的文库，请填 `groups/` 加群组的编号）。然后再按一次**立即同步**。
2. Zotero 里的内容会同步过来：新论文会被添加，已有的论文会被补全，按 DOI、arXiv ID 或标题匹配。两边不一致时以 Zotero 的信息为准，你的状态、备注和项目仍然归你。
3. 只在这里有的论文会作为新条目发送到 Zotero。

第一次之后，每次同步只传送自上次同步以来改变的内容。你在 Zotero 中删除的论文会留在这里，不再关联，也绝不会再发回去。你的论文上方有一行文字，说明上次同步的时间和做了什么（“从 Zotero 新增 12 篇，发送了 3 篇”），带有**再次同步**。

### 文献矩阵

[文献矩阵](/apps/t/literature-matrix)把几篇论文并排阅读，并填写一张电子表格：每篇论文一行，你要比较的每一项一列，每个单元格写着论文怎么说，以及它在哪里说的（页码或章节）。

- **论文**：每行一篇（最多三十篇），每篇是一个 DOI、arXiv ID、链接、标题，或者这台电脑上的 PDF。也可以来自你的阅读清单：写一行英文，例如“my reading list, tag: dense”（或者一个项目，或者一种状态：“my reading list, to read”）。阅读清单上的**生成文献矩阵**会用你选中的论文填好它。
- **各列**：每行一个；除非你修改，否则是 **Task**、**Data**、**Method**、**Metrics**、**Results** 和 **Limits**（任务、数据、方法、指标、结果和局限）。
- **项目**：它的电子表格放进你的哪个项目。这时单独一行“my reading list”（后面什么都不加）就会取这个项目的论文。

它一次读三篇论文（有开放副本时读全文，没有时读摘要），让一个快速模型填写每一行，写出这些论文合起来说明了什么，并把矩阵作为电子表格保存在你的[资料库](/guide/library#spreadsheets)中，第二个工作表列出这些论文。它的视图有**矩阵**（它读了多少篇、**在资料库中打开**、**复制为表格**、矩阵本身、它没能读的论文及原因，以及**再加一列**：写上列名，**加上它重新生成**会带上这一列再运行一次）、**论文**（每篇都有一句话说明它做了什么，以及是从什么读来的）和**跨论文综述**（它们在哪些地方一致、哪些地方不一致，还有什么悬而未决，带有**复制**）。

### 复现论文

[复现论文](/apps/t/reproduce-paper)运行论文自己的代码，看它的数字是否站得住：它找到代码，搭建环境，获取数据和检查点，运行评估，把数字和论文的表格对比，并说明花了哪些功夫。

- **论文**（也可以用**或者上传**）、**它的代码**（一个链接或这台电脑上的文件夹；留空时会去寻找）、**要复现的内容**，按论文的说法（“表 2 中 MS MARCO dev 上 BM25 + monoT5 那一行”）、**限制**（它可以使用的时间、磁盘和 GPU：除非你修改，否则是“At most 4 hours, 100 GB of disk and 1 GPU”，即最多 4 小时、100 GB 磁盘和 1 块 GPU）和**工作位置**（一个文件夹；留空时每次运行都新建一个）。

它读取论文，并在其中寻找它的代码；论文没有给出代码时，它会同时在 GitHub 和网上搜索，挑出最可能的仓库。一个快速模型会确定确切的设置（数据和划分、模型和检查点、各项设置）以及要对上的数字（按论文印出的样子）。然后一个智能体按 **reproduce-paper** 技能说的方式去做：按仓库的说明搭一个干净的环境（venv、conda 或 Docker），准备数据和检查点，先在一小部分数据上跑一遍，再正式运行，把它做的每处改动及原因都记下来，并在工作文件夹里写一份报告 `REPRODUCTION.md`。需要 GPU 或要跑好几个小时的正式运行会交给[实验](/guide/experiments)，它会等待空闲的 GPU，并保存运行的记录和日志：应用会等这些运行结束，而不占用一个会话，然后由一个智能体读取它们的数字并完成报告。最后，每个数字都会和论文的数字并排放在一起：在 0–100 的刻度上相差半个点以内（在 0–1 的刻度上是 0.005）算作复现成功。

它的视图有**复现成功了吗？**（结论、有多少个数字接近、花了多少小时、做了哪些修复、它的仓库、**打开文件夹**、它在“实验”中的运行，以及没有复现成功时的**重试**；然后是论文的数字与我们的数字并排，附上差值，接近的标为绿色，以及论文给出的设置）、**所花的功夫**（每一步及其分钟数，以及每处改动和修复）和**报告**（带有**复制报告**）。

它在这台电脑上运行代码，可能要花好几个小时：它会守住你的限制，一旦要超出某个限制，就会停下来报告已有的结果。拿不到的代码或不公开的数据，它都会直说。

**边读边高亮论文。** 在“文件”中打开论文的 PDF，按**突出显示**：选中一段文字，或者在公式或图周围拖出一个方框，用四种颜色之一把它高亮，并在上面写一条备注。**询问**会就这一部分去问智能体（“这个公式表达的是什么？”），**备注**会逐页列出你标记的所有内容。**保存到项目**会把你的高亮和备注作为一份以论文命名的文档放进项目的知识库，并随时更新，让项目的会话能找到它们；**保存到 PDF** 会把它们写进文件，供其他应用使用。见[阅读和高亮 PDF](/guide/files-git#read-and-highlight-a-pdf)。

## 投稿前检查论文

在论文投出去之前，LaTeX 编辑器会像会议的初审和审稿人那样检查它：它的参考文献、它是否暴露了你的身份、它的页数和字体、会议要求的各个部分，以及它表格里的数字。打开你的论文（[你的 LaTeX 文档](/library?kind=tex)），选择**工具 → 投稿前检查**。

1. 选择投到哪里：**ACL Rolling Review**（长文或短文；**EMNLP** 和 **NAACL** 通过它收稿）、**SIGIR**（长文或短文）、**CIKM**、**WSDM**、**TheWebConf**、**KDD**、**NeurIPS**、**ICLR**、**ICML**、**AAAI**、**IEEE 期刊**、**ACM 期刊**，或者**其他**，自己设定页数限制和**匿名评审**。下面有一行说明这个会议的要求：页数限制、哪些不计入页数、是否匿名评审，以及必需的部分。会议和期刊每年都会调整规则，所以这一行也链接到征稿启事。检查会为每篇论文记住它的投稿目标，第一次时则选论文自己的样式所指向的那个。
2. **检查**会排版论文、读取它的 PDF、在网上查找它的参考文献，并随时显示它的发现。只有参考文献的标题、DOI 和 arXiv ID 会被发送给 Crossref、arXiv、OpenAlex、Semantic Scholar 和 DBLP；这些服务的回答会保存几天，没有响应的服务会在发现下方列出。OpenAlex 和 Semantic Scholar 对带着你自己免费密钥的程序回应得更顺畅：在[密钥](/apps/connected?tab=keys)中把它添加为 OPENALEX_API_KEY（用于 api.openalex.org）或 SEMANTIC_SCHOLAR_API_KEY（用于 api.semanticscholar.org），检查就会使用它。

它的发现分成五组，每条发现都标为**必须修复**、**请检查**或**供参考**：

- **参考文献**：被引用了但参考文献中没有对应条目的键（或者引用时的大小写和条目不同）、从未被引用的条目、同一篇论文用了两个键，以及缺少其类型所需信息的条目（期刊文章的期刊、会议论文的论文集、年份）。每个被引用的条目都会按它的 DOI、arXiv ID（都没有时按标题）查找，并与这些服务列出的信息比较：标题、作者、年份和发表处。对预印本，会查找它是否已有正式发表的版本，审稿人会希望你引用那个版本。到处都找不到的论文会被提示可能并不存在：请你自己核实，因为这些服务也会有遗漏。
- **匿名性**（在匿名评审时）：模板处于终稿模式时显示的作者姓名（ACL、NeurIPS、ICML、ICLR 和 acmart 的模板都有匿名模式）；**\thanks** 脚注；致谢章节；可能暴露你或你实验室的链接（你自己的仓库、个人主页）；引用旁边的“our previous work”（我们之前的工作）；以及 PDF 自身的 Author 和 Title 字段。
- **格式**：计入页数限制的页数（算到参考文献开始为止，或者扣除会议不计入的部分，比如 ACL 的 Limitations）、参考文献的页数，以及会议限制总页数时的总页数；Type 3 字体和未嵌入的字体；对模板的页边距、字体和间距的修改，以及负的 **\vspace**（作为提示：有些是允许的）；显示为 ?? 的交叉引用和文献引用；**TODO**、**XXX** 和 **\todo** 标记；远远伸进页边的行；以及无法排版时的错误。
- **必需部分**：摘要，以及会议要求的内容：ACL 的 Limitations（局限性）章节、NeurIPS Paper Checklist（论文清单）（以及仍为 **\answerTODO** 的回答）、ICML 的 Impact Statement（影响声明）、ICLR 的 AI 使用声明、CIKM 的生成式 AI 使用披露、IEEE 的 Index Terms、ACM 的 CCS 概念和关键词。
- **数字**：见[与你的运行相符的数字](#numbers-that-match-your-runs)。

带有发现所在文件和行号的按钮会在源码中显示它。在修改安全的地方，**修复**会进行修改：按这些服务列出的样子改写条目，键保持不变，所以你的引用不用改（**查看条目**会先显示它）；换成预印本的正式发表版本；把模板切换到匿名模式；把致谢注释掉；清空 PDF 的 Author 字段；删除一条 **\todo** 备注；移动加粗；更新一张表格。修复和编辑器里的任何其他修改一样：**撤销**可以撤回，**保存**会把它保存为新版本。在没有安全修改的地方，**问智能体**会去问编辑器旁边的智能体，请求中带着这条发现；**请智能体修正**会一次把它们全部交给智能体。

**添加为评论**会把未解决的发现作为文档的评论放到对应的文字上（见 [LaTeX 文档](/guide/library#latex-documents)），这样你、你与之分享论文的人以及智能体都能在原处看到每一条；被要求回复评论的智能体会修正它们并把它们标为已解决。再检查一次，它会告诉你自上次检查以来修正了多少条、还剩多少条、新出现了多少条；这时**添加为评论**会把已修正的那些评论标为已解决。

智能体也会对你资料库中的论文或你的 LaTeX 项目运行同样的检查：“在我投 ACL 之前检查一下我的论文”。

### 与你的运行相符的数字

检查会逐个数字地读取论文的每一张表格：

- **最佳值加粗。** 在每一列中，加粗应该标在最佳值上。哪个方向更好取决于列标题：loss、error、latency 或 perplexity 越低越好；accuracy、F1、nDCG 或 BLEU 越高越好；箭头（↓ 或 ↑）会直接说明。列标题没有说明时，默认越高越好，发现中也会这样说明。每一组行（两条横线之间）各自加粗最佳值、并列的情况，以及把指标放在行里的表格，都没有问题。**移动粗体**会把它放到最佳值上。
- **由“实验”生成的表格。** 你从[实验](/system/experiments)放进论文的表格（**生成表格**，然后**放进 LaTeX 文档**）上方有一行 `% hydor:table …`。检查会根据它的运行现在的样子重新算出这张表，并标出此后变化的每个数字，以及新出现或消失的显著性标记。**更新表格**会换上新的表格。
- **其他表格。** 它们的数字会在论文所属项目（或它的文件夹）已完成的运行中查找，按表格的舍入方式舍入，也会按百分比查找。找到了多少个，只作为供参考的信息说明，从不当作问题：一个数字可能来自另一篇论文，或者来自在别处做的运行。

### arXiv 投稿包

打开的 LaTeX 文档顶部的**导出 → arXiv 投稿包（.zip）**（在手机上是**更多**（⋯）→ **下载为**）会把已保存的论文打成一个 .zip，用来上传到 arXiv；arXiv 会按你发送的样子公开源码。它要做的事都已勾选：

- **删除注释**，而且是安全地删除：`\%` 会保留，TeX 原样处理的内容（verbatim 文本、listings、**\verb**、**\url** 和 **\href** 的地址）也会保留；`\begin{comment}` 块会被删除，勾选**也删除 \iffalse … \fi 块**时，这些块也会删除。
- **只包含论文用到的文件**：**\includegraphics** 显示的图片、它读取的文件、它自己的样式和文档类。
- **加入 .bbl，去掉 .bib**：也就是在这里排版时的参考文献，arXiv 会使用它。取消勾选则发送 .bib，让 arXiv 自己运行 BibTeX。
- 勾选时，**把 \input 和 \include 的文件并入 main.tex** 和**在开头加上 \pdfoutput=1**（arXiv 要求使用 pdfLaTeX 的旧方式）。

名称中的空格会换成短横线，源码也会相应修改。**生成投稿包**会按投稿包现在的样子排版一次（和任何文档一样在同一个沙盒中），确认它能编译通过，然后下载它。对话框会说明包里有什么、哪些被省略或重命名了、排版结果如何、它的大小与 arXiv 50 MB 上限的对比，以及在 arXiv 上该选哪个处理器。它会记住你的选择。

### 终稿、换模板，以及在应用中使用你的论文

**工具 → 你的论文**里还有其余的功能：

- **改成终稿**会请编辑器旁边的智能体根据会议的规则写出终稿版本：模板的终稿模式，恢复作者和他们的单位，恢复致谢，版权或权利声明块，终稿要加上的内容，以及它的页数限制。如果源码里没有作者、单位和致谢，请把它们告诉智能体。
- **迁移到另一个模板**会请智能体把论文迁移到另一个会议的模板（或者 Springer 的 LNCS、Elsevier 的模板、普通的 article），作为评审版或终稿，保留它的文字、图、表和参考文献。
- **arXiv 投稿包（.zip）**，同上。
- **像审稿人那样审阅它**、**回复审稿意见**和**制作演讲、海报和推文串**会打开对应的应用，并填好你的论文（它的 PDF；对于演讲，则是它源码所在的文件夹）：见[审阅、回复和展示你的论文](#review-answer-and-present-your-paper)。

尚未保存的内容会先保存，这样每项功能拿到的都是你看到的论文。

## 审阅、回复和展示你的论文

[应用页面](/apps)上**写作**分类下有四个现成应用，帮你处理自己的论文：**审稿人模拟器**像会议的审稿人那样审阅你的草稿，**反驳工作台**起草你对收到的审稿意见的回复，**论文转演讲、海报和推文串**制作你展示论文要用的东西，**插图医生**让论文的图适合印刷。前三个从这台电脑上的 PDF、.tex 文件或 LaTeX 项目的文件夹、一个链接，或者你资料库中的 LaTeX 文档（粘贴它的地址）读取你的论文；**或者上传**则可以改用一个 PDF。

### 审稿人模拟器

[审稿人模拟器](/apps/t/reviewer-simulator)在真正的审稿人之前审阅你的草稿，用的是会议自己的审稿表和评分，并列出审稿人可能会要求的东西，最危险的排在最前。

- **你的论文**、**会议/期刊**（**ACL Rolling Review**、**SIGIR**、**NeurIPS**、**ICLR**、**ICML**、**KDD**、**CIKM**、**WSDM**、**TheWebConf**、**期刊**或**其他**，每个都用它 2025 年的审稿表）、**审稿人数量**（1 到 5；除非你修改，否则是 3）和**需要重点关注的地方**。

它会安排几位审稿人，每人都有自己的角度（依次是：方法专家、领域专家、持怀疑态度的实证派、来自相邻领域的细心读者，以及可复现性审稿人），各自并行填写会议的审稿表。然后由一位领域主席写出元评审和可能的结果，并按每个缺点让论文被拒的可能性给它们排序。这些审稿意见来自模型：它们能在真正的审稿人之前找出弱点，但不是对录用结果的预测。

它的视图有**审稿意见**（会议、可能的结果、总体评分的平均值，然后是每份审稿意见：审稿人和角度、评分、概述、优点、缺点和问题）、**元评审**（带有**复制**和**复制全部审稿意见**；然后是**可能导致被拒的问题，最危险的在前**：每个缺点及其原因、可能性和修正办法）、**基线和消融实验**（审稿人会要求什么、为什么，以及需要的工作量）和**投稿前要做的事**（一份可以逐项勾掉的清单，以及**回复这些审稿意见**，它会用这些意见启动反驳工作台，让你演练回复）。

### 反驳工作台

[反驳工作台](/apps/t/rebuttal-workbench)在会议规定的限制内，逐条起草你对收到的审稿意见的回复。

- **审稿意见**（把它们全部粘贴进来，每份放在它的审稿人下面：“Reviewer 1”“R2”、OpenReview 的“Reviewer xYz1”……）、**你的论文**（也可以用**或者上传**；可选，让回复能指向论文的章节）、**长度上限**（按会议的规定：字符数或词数，按审稿人、按要点或总计；除非你修改，否则是“2,500 characters per reviewer”，即每位审稿人 2,500 个字符）和**语气**（**礼貌而坚定**、**热情而感激**或**简洁扼要**）。

它按审稿人拆分审稿意见，并行提取每份意见里的要点，合并几位审稿人提出的同一个要点，并把它们分类：误读（你的论文已经回答了）、需要实验、需要文字（澄清、论证、引用），或次要。它会找出你的论文对每个要点是怎么说的，在每个要点分到的限额内起草回复，再把回复组合起来，对照限制计数。需要新结果的回复会留下 [占位符] 让你填写：它从不编造结果。

它的视图有**提出的要点**（整份回复的一句话概括；**全部要点**、**误读**、**需要补实验**、**需要补充文字**和**次要**只显示一种；每个要点都有谁提出的、他们的原话、草拟的回复、它的长度与分到的限额对比，以及**复制**）、**待办**（要做的实验和要改的论文内容，可以逐项勾掉）和**完整反驳**（每位审稿人的回复与限制对比，以及**复制完整反驳**）。

### 论文转演讲、海报和推文串

[论文转演讲、海报和推文串](/apps/t/paper-to-talk)制作你展示论文要用的东西：用上论文真实的图和公式、按时间安排好并附上讲稿的幻灯片；一张 A0 海报；发到 X、Bluesky 和 LinkedIn 的帖子；以及一个项目主页。

- **你的论文**（最好是它的 LaTeX 项目文件夹，这样能用上它的图；来自 arXiv 时，会为此获取它的源码）、**演讲时长（分钟）**（除非你修改，否则是 15）、**听众**（**本领域的研究者**、**其他领域的研究者**或**普通听众**）、要做什么（**幻灯片**、**A0 海报**、**推文串（X、Bluesky、LinkedIn）**和**项目主页**）以及**项目**（它做出的东西放进你的哪个项目）。

它先规划演讲（大约一分钟一张幻灯片，每张一个要点，从问题讲到结论），由一个程序分配时间，让各部分加起来正好是设定的时长，然后并行做出你要的东西：幻灯片，你可以在资料库中编辑和放映（[幻灯片](/guide/library#slides)）；海报，作为一份 LaTeX 文档（[LaTeX 文档](/guide/library#latex-documents)）；帖子；以及项目主页，你可以直接发布（[发布页面](/guide/library#publish-a-page)）。

它的视图有**做好的内容**（演讲的核心信息和一句开场白，然后是做出的每样东西，带有**打开**）、**演讲**（整场演讲排成一条，每张幻灯片的宽度对应它的分钟数，然后是每张幻灯片：它的分钟数、标题、要点、图、公式和讲稿）和**推文串**（**X**、**Bluesky** 和 **LinkedIn** 分别显示各自的帖子，带编号，每条都有**复制**，还有**复制推文串**；LinkedIn 只有一条帖子，带有**复制帖子**）。

### 插图医生

[插图医生](/apps/t/figure-doctor)让论文的图适合印刷：和栏一样宽，用论文的字体，用色盲读者也能区分的颜色，保存为嵌入了字体的矢量 PDF，全都使用同一个样式文件。

- **你的绘图代码**（这台电脑上的一个脚本、一个笔记本，或者装着它们的文件夹，用 matplotlib 或 seaborn 制作）、**会议的模板**（**ACL, EMNLP, NAACL**、**ACM (SIGIR, KDD, CIKM, WSDM, TheWebConf)**、**IEEE**、**ICML**、**NeurIPS, ICLR**、**Springer LNCS** 或**其他（请填宽度）**）、**宽度**（**单栏**或**跨双栏**）、**或者填宽度（英寸）**（用于其他模板）和**论文的字体**（**与模板一致**、**Times New Roman**、**Computer Modern**、**Linux Libertine** 或 **Helvetica**）。

一个程序先确定样式（以英寸为单位的宽度、字体及其字号、适合色盲读者的配色），然后一个智能体就地修改你的脚本：先把每个脚本复制一份放在旁边（name.orig.py），并保留每张图原来样子的图片。之后每个脚本都使用旁边的同一个样式文件 `paper.mplstyle`；每张图都保存为矢量 PDF，并检查它的字体：全部嵌入，没有 Type 3 字体（很多会议拒收这种字体）。它会运行你的脚本，所以这台电脑上需要有它们所需的东西（Python、matplotlib 和它们的数据）。

它的视图有**修改前后**（它使用的尺寸、字体和颜色，然后是每张图原来的样子和现在的样子，带有**打开 PDF** 和改了什么）、**样式文件**（`paper.mplstyle`，带有**复制**和使用方法）和**有哪些变化**（每处改动，以及字体检查的结果）。

你会话中的智能体也懂这些手艺，来自 Hydor 自带的技能（**peer-review**、**reproduce-paper** 和 **figures-for-papers**：见[技能](/guide/skills)）：请它和你一起审阅一篇论文、回复一位审稿人，或者修一张图，它会用同样的方式去做。

## 管理实验室的日常工作

[应用](/apps)页面上**实验室**分类下有三个现成应用，帮你处理实验室的日常工作：标注数据并对照你的标注检查模型，从假设到报告在你自己的代码上验证一个想法，以及调节模型的设置。冲刺和参数扫描会在[实验](/guide/experiments)中运行它们的作业，所以“实验”需要有一台带 GPU 的电脑（或一个计算集群）。

### 标注工作台

**标注工作台**让你和一个模型标注同一批文本样本，这样你能看到你们在哪里有分歧，以及其余的文本能在多大程度上放心交给模型。从**应用**中打开它，然后填写：

- **标签**，用逗号分隔：最多九个，每个对应 1 到 9 中的一个按键。**如何标注**：你的标注准则，用你自己的话写；模型也会按它来标注。
- 文本：**CSV 或 JSON lines 文件**、按名称（例如 stanfordnlp/imdb）或地址指定的 **Hugging Face 数据集**（有多个划分时用**数据划分**指定，配置写在斜杠前面，例如 plain_text/test），或者粘贴的文本，每行一条。**文本所在的列**会自动找到（名为 text、review 或 sentence 的列，否则取文本最长的那一列）：猜错时请写出列名。
- **标注数量**：随机抽取，除非你修改，否则是 100，最多 1,000。

它读取文本（数据集通过 Hugging Face 的 datasets server 读取，从随机位置读取几页数据行），把样本打乱顺序，让辅助模型每次标注二十条，每条附一个简短的理由。之后，这次运行的页面就是你工作的地方：

- **标注**：一次一条文本，每个标签一个大按钮。按下一个按钮，或者它的按键（**1** 到 **9**）：只有这时才会显示模型的标签，显示在下一条文本上方的一行里（你们不一致时还附上它的理由），所以它绝不会影响你。**暂时跳过**（**S**）把一条文本放到最后，**修改**（**Z**）撤回上一条，备注（按 **N** 开始写）会跟着它的文本。进度条显示你做到了哪里。
- **分歧**：你和模型标注不同的每条文本，你的标签和备注与模型的标签和理由并排显示。**重新标注**会把它送回**标注**。
- **一致率**：你们给出相同标签的比例、Cohen's κ（扣除纯属偶然的一致之后的一致程度：1 是完全一致，0 不比偶然好，高于 0.6 算相当一致）以及纯属偶然会得到的一致程度，还有混淆矩阵：左侧是你的标签，顶部是模型的标签。
- **导出**：**CSV** 或 **JSON 行** 会下载你标注过的文本，每条都带有你的标签、模型的标签及其理由，以及你的备注。**发布到 Hugging Face** 会在那里创建一个独立的数据集（除非你选择**所有人**，否则是私有的），包含数据和一张数据集卡片，卡片说明它是怎么标注的，附上你的标注准则以及你和模型的一致程度。它需要一个有写入权限的 Hugging Face 令牌：没有它应用照样能用，所以第一次发布时会提示你；可以在应用表单下面添加（**Hugging Face 令牌**，标为可选），或者在**应用 → 已连接的应用 → 密钥**中以 HF_TOKEN 添加。**删除其中的文本**会删除一组文本的内容和标签。

每一组都是独立的一次运行，它的文本和你的标签作为应用的记录保存：应用的页面会在最近的运行中列出你的各组，每一组都会从你上次停下的地方打开。

### 研究冲刺

**研究冲刺**在你自己的代码上，通过一次短期冲刺来推进一个研究问题，每一步都由你批准。填写**你的研究问题**、**仓库**（这台电脑上的一个 Git 仓库）、**它需要知道的**（重要的指标、基线及其数字、怎样训练和评估、哪些不能改）、**可用的 GPU 小时数**（除非你修改，否则是 8，供它所有的运行共用）和**假设数量**（一到五个）。然后：

1. 辅助模型根据你的问题和仓库的 README 提出假设，每个都说明什么会支持它、什么会否定它，以及检验它的实验。
2. 勾选**每一步都让我批准**时（除非你取消勾选，否则是勾选的），运行会等你：保留这些假设，或者写出要改为检验的假设，每行一个。这个问题会显示在运行的页面上、你的收件箱里，并作为一条通知发给你。
3. 一个智能体在你的工作副本旁边为仓库建一个工作树，放在一个新分支（sprint/…）上，它从不改动你的工作副本。它在那里写下计划（SPRINT.md）和运行所需的代码，提交它们，并列出各次运行：一个基线，以及每个假设的运行，带有随机种子。会超出你 GPU 小时数的运行会被排除，并一一列出。
4. 在花掉任何 GPU 时间之前，它会再次等你：开始这些运行，或者拒绝，冲刺就停在那里（计划和代码留在分支上）。
5. “实验”运行它们，并标上这次冲刺，冲刺会等它们全部结束。
6. 一张结果表把每个条件与基线对比，并附上显著性；一个智能体在 Jupyter 笔记本中分析这些运行（笔记本保存在你的[资料库](/library)中），对每个假设作出判断（支持、不支持或不明确，附上证据），并写一份简短的报告。

它的视图有**冲刺**（问题、进展如何、它的分支，以及每个假设及其结论和证据）、**运行记录**（结果表，以及每次运行及其指标）和**报告**（可以阅读和复制，带有**打开笔记本**和下一步可以尝试什么）。从 API 或定时任务运行时，没有人在场批准，所以它会一路运行到底。

### 参数扫描规划

**参数扫描规划**在预算内为一个训练脚本规划超参数扫描，启动它，提前停止糟糕的试验，并总结哪些设置要紧。填写**脚本或命令**、**它的文件夹**、**指标**（按脚本打印或写出的样子：metric=value 形式的行，或 JSON）和**哪个方向更好**、**要调的参数**（每行一个，带上要尝试的值，例如 lr: 1e-4, 3e-4, 1e-3；留空则由它来找）、**预算**（运行次数或 GPU 小时数：“20 runs”“10 GPU hours”）和**提前停止表现差的试验**。

- 一个智能体读取脚本，既不运行也不修改它：它的参数、一次运行要多久，以及多早能看出一次运行不行。它提出要尝试的设置和取值（你给出了就用你的），再由一个程序让它们符合预算：放得下时尝试所有组合，否则在预算允许的范围内随机抽取尽可能多的组合。
- 勾选**先让我检查计划**时，运行会等你：按原样开始，或者写出修改，每行一个设置（lr: 3e-4, 1e-3 表示改用其他取值，drop dropout 表示去掉一个设置）。
- “实验”把这次扫描作为一个实验来运行；勾选**提前停止表现差的试验**时，明显比目前最好的结果差的运行会被停止，以节省它的 GPU 时间。
- 运行都结束后，一个程序找出最好的一次运行，以及每个设置有多重要（各次运行之间指标的差异中，有多大比例可以由它的取值来解释），辅助模型再说明这意味着什么，以及下一步可以尝试什么。

它的视图有**结果**（最佳运行的设置和指标、它的发现、下一步可以尝试什么，以及代表每个设置权重的条形）、**按参数**（每个设置各个取值下的指标，以箱线图显示）和**所有运行**。

## 报告：你的一周和实验记录本

[应用](/apps)页面上**工作**分类下有两个现成应用，根据 Hydor 对你工作的了解写出你做了什么：你的会话（这里的会话，以及 Hydor 读取的、在 VS Code 或终端中运行的 Claude Code 和 Codex 会话）、你在这些会话工作过的 Git 仓库中的提交、你在“实验”中的运行、你在资料库中做出的东西，以及你在阅读清单中标为已读的论文。关闭了记忆的会话和保密会话不计在内，智能体为完成任务的某些部分而启动的会话的工作也不计在内（它们算作父会话的工作）。两个应用都在自己的页面上打开，并且可以自动更新。

### 每周进展报告

**每周进展报告**把你的一周变成一份给导师、团队或经理的进展汇报：完成了什么、带数字的结果、遇到的困难和阻碍你的事、下周的计划，以及要问的问题。它在自己的页面上打开，显示本周的报告（截至撰写当天的七天）：标题和摘要、用数字概括的一周，然后是**本周完成**、**结果**、**问题与阻碍**、**下周**和**问题**。

- **复制为 Markdown** 和**复制为邮件**（一行主题，然后是一段简短的留言，开头和结尾都像你自己写的那样）会把它放到你的剪贴板上；**保存为文档**会把它保存在你的资料库中，可以修改，也可以导出为 Word 或 PDF。
- **更新**会立刻写出本周的报告。下面的**更早**列出之前的各周，点一下就能打开。
- **设置**，即顶部的滑块图标：**自动更新**（在你打开之前一直是关闭的）会在每周五 16:00 写出一份新的报告；在开关下面，可以选别的日子（**每天**、**每个工作日**，或**每周一次**，在你选的某一天）和时间。它是一个[定时任务](/guide/tasks)，所以[设置 → 定时任务](/settings?s=tasks)里也会列出它。下面是：**面向谁**（你的导师、你的团队或经理：它会为他们而写）、**项目**（全部项目，或者按名称选一部分）和**包含哪些内容**（“只写研究，不写费用”）。

### 实验记录本

**实验记录本**为你工作过的每一天保存一条带日期的条目：尝试了什么、发现和决定了什么，以及还有什么悬而未决，附上当天的会话、提交、运行、文件和资料库内容的链接。它的条目是应用自己的记录，和[记忆](/guide/memory)分开保存。它在自己的页面上打开，显示这些条目，最新的排在最前：

- **搜索记录本**按字词和含义（开启[按含义搜索](/settings?s=memory&find=Search%20by%20meaning)时）查找条目，最相关的排在最前；**全部记录**会把它们全部显示回来。
- 每条条目下面的**复制链接**会复制它自己页面的地址，那个页面按写下时的样子显示这条条目：可以在论文、报告或笔记中引用它。
- **更新**会立刻写出今天的条目，**补写之前的某一天**会补上你漏掉的某一天。重写某一天会替换它原来的条目；什么都没做的日子不会有条目。
- **设置**：**自动更新**（在你打开之前一直是关闭的）会在每天晚上 21:00 写出当天的条目，日子和时间都可以自己选；**项目**可以只限于某些项目。
