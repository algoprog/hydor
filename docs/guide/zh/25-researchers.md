# 研究：论文、写作与实验室

Hydor 可以帮你处理研究周边的各项工作：跟进你所在的领域、阅读和整理论文、在论文发出前进行检查、回复评审意见、展示你的成果，以及管理实验室的实验和报告。大部分功能都以现成应用的形式提供，位于[应用](/apps)页面的 **研究**、**写作**、**实验室** 和 **工作** 下，你也可以直接让智能体帮你运行；论文的检查项在 [LaTeX 编辑器](/guide/library)中，训练运行则在[实验](/guide/experiments)中查看。要评审别人的投稿？请使用[保密会话](/guide/sessions#keep-a-session-confidential)。

## 跟进你的领域

有六款现成的应用帮你跟进所在领域：它们在“应用”页面的 **研究** 分类下（打开[应用](/apps)，选择 **研究** 标签）。其中五款有自己的专属页面，并且可以每天自动更新：**论文雷达**、**引用提醒**、**新模型追踪**、**截稿雷达**和**动态相关工作**。第六款 **研究空白发现器** 在你提出要求时通过表单运行，智能体也可以在任何会话中替你运行它。

它们会以温和的方式读取开放服务：arXiv、OpenAlex、Semantic Scholar、Hugging Face，以及 GitHub 上的截止日期列表 ccfddl 和 ai-deadlines。Hydor 自己会把对每个服务的调用错开（arXiv 间隔三秒，Semantic Scholar 间隔一秒），某个服务一时繁忙时还会再请求几次；仍然拿不到的内容会显示在运行结果下方，成为一行可以展开查看的说明（见[网络掉链子时的处理](/guide/apps#when-the-web-lets-a-step-down)）。它们都不强制要求密钥，但有两个会有帮助：**OpenAlex API 密钥**（免费；没有它时，每次更新最多只能请求 OpenAlex 两次，额度很小，而且与你所在网络的所有人共用）和 **Semantic Scholar API 密钥**（可免费申请；没有它时 Semantic Scholar 经常繁忙，会改由 OpenAlex 来回答，但没有引用你的那些句子）。请在应用的设置中填写，也就是应用页面顶部的滑块里的 **它需要的密钥**：密钥会存入你的保险库，并且只会发送给这些服务。

你在[关于你](/settings?s=apps&find=About%20you)中填写的内容（**你的领域**、**你关注的主题**、**你阅读的会议和期刊**、**作为作者的你**和 **你能在什么上运行**）会替你填好这些应用的问题，所以你只需要说一次：在表单上，它显示为一行简短的文字，旁边有 **修改**；而拥有专属页面的应用会以这些内容作为设置的起点（见[应用了解你的哪些信息](/guide/apps#what-apps-know-about-you)）。你在某个应用自己页面里设置的内容只保留在该应用中；对于其他应用，“关于你”里没有合适位置的内容（审稿表单的会议或期刊、反驳意见的字数限制和语气、文献矩阵的列、某个仓库或文件夹）会以你上一次的回答作为起点。凡是只给你自己看的文字，应用会用你的语言来写：**论文雷达**对每篇论文的那一行说明、**引用提醒**对每个引用句子的概括、**新模型追踪**的摘要、**截稿雷达**对每份征稿的备注、**研究空白发现器**的想法、[探索](/guide/apps#explore)的杂志，以及 **实验记录本** 的条目（引用的类型、结论、规模、检索词，以及论文和会议期刊的名称保持原样，以免读取它们的程序出错）。所有要发给别人或写进论文的内容，则保持论文所用的语言：审稿意见、反驳意见、相关工作章节、文献矩阵、幻灯片、海报、串文、图表和每周报告。

在应用自己的页面上，顶部的 **更新** 会立刻生成一期新内容，滑块里是它的设置：**每天更新**（在你打开之前默认关闭）、更新时间，以及它的各项问题。页面下方，**更早** 列出之前的各期，点开后与当时的样子一致。在生成第一期之前，页面只会询问应用不可或缺的信息（你作为作者的姓名、你关注的会议和期刊）；点击 **做出第一个** 会把你的回答保存为它的设置。一旦它开启每天更新，设置 → 定时任务中也会列出它（见[定时任务](/guide/tasks)）。

### 论文雷达

[论文雷达](/apps/t/paper-radar)每天早上为你带来所在领域的新论文，并按照与你工作的相关程度排序，每篇都附有一句话，说明它做了什么，以及为什么对你重要。

- **它读什么**：你关注的类别里 arXiv 的新论文（最多几百篇，为最近三天提交的，间隔一段时间后会更多）、任何领域中与你的主题相关的论文，以及你关注的人的论文；还有 OpenAlex 上同样与你的主题相关的论文（期刊和会议论文集）。之前某一期已经展示过的论文不会再出现；找到了但排在截止线以下的论文，可能会在另一天再次出现。
- **它如何排序**：依据你的项目（项目名称、描述和最近的会话）、你的主题和你的个人资料。当[按含义搜索](/settings?s=memory&find=Search%20by%20meaning)开启时，使用你电脑上的嵌入模型按含义来比较，否则按字面用词比较。你保存的论文会把排序拉向它们，你搁置的论文则会把排序推离它们。你关注的人写的论文始终排在最前面。
- **页面**：**今天**，当天的论文会归入最适合它的项目或主题之下（在顶部选择其一，或选择 **全部**）。每张卡片上有论文发表的地点和时间、标题（链接到论文）、作者、一句话说明它做了什么以及为什么适合你，还有 **☆ 保存**、**引用**（复制它的 BibTeX）、**PDF**、**深入研究**（为它生成一份几分钟的[深度研究报告](/apps/t/deep-research)）和 **不适合我**（卡片会折叠起来，并出现 **撤销**）。**已保存的论文** 按时间从新到旧列出你保存的论文，并带有 **全部复制为 BibTeX**，每篇论文还有 **引用**、**加入阅读清单**、**深入研究** 和 **移除**。
- **它的设置**：**要关注的领域**（arXiv 的类别，可以写名称或代码：Information Retrieval 或 cs.IR，Computation and Language 或 cs.CL；不属于任何类别的领域会被当作主题；默认取自“关于你”中的 **你的领域**）、**主题**（每行一个；取自 **你关注的主题**）、**要关注的人**（每行一个，按他们的论文上署名的写法）和 **论文数量**（默认 15，范围 5 到 40）。留空时，它会根据你的个人资料和项目自行推断领域和主题。

每次更新会向辅助模型提一两个简短的问题（每篇论文对你意味着什么），需要一两分钟。

### 引用提醒

[引用提醒](/apps/t/citation-alerts)会告诉你自上次查看以来谁引用了你的论文，附上引用你的那句话，以及对方是在你的工作之上继续研究、与之比较，还是提出异议。

- **页面**：**新增**，按你的论文列出新的引用：每处引用是如何引用你的（**建立在其上**、**与之比较**、**提出异议**或 **仅提及**，由辅助模型根据句子判断；可在顶部只显示其中一类）、标出你论文被提及之处的那句话、一句话说明它对你的工作说了什么，以及引用你的论文（带链接）、其作者、发表的地点和时间，并带有 **复制这句话**。**你的论文** 列出你的论文、它们的引用情况，以及其中有多少是新增的。
- **它如何找到这些引用**：它先在 Semantic Scholar 上找到你（该服务繁忙时改用 OpenAlex）；如果你在“关于你”中提供了 ID（OpenAlex ID 或 ORCID，可以精确找到你，而仅凭姓名可能会找到同名的人），就按 ID 查找；然后取出有引用的论文（引用最多的和最新的，每次更新三十篇），再逐篇询问最近有谁引用了它。它已经见过的引用会被保存，所以每次更新只显示新的内容；第一次运行时，只有上个月的引用算作新增。没有句子的引用论文，是指该服务还没有读过它的全文。当 Semantic Scholar 太忙而给不出句子时，由 OpenAlex 告诉你谁引用了你，页面会在列表上方明确说明这一次无法读取句子，下次更新时会再试，而这些引用会保留下来等待读取：一旦 Semantic Scholar 有了回应，下次更新会把每一条连同它的句子重新显示出来。
- **它的设置**：**你的作者身份**（你的论文上署名的写法，或你的 Semantic Scholar ID（数字）、OpenAlex ID（A 加数字）或 ORCID；默认取自“关于你”中的 **作为作者的你**，只要姓名仍是你的，就会使用其中的 ID）和 **只看这些论文**（标题、DOI 或 arXiv ID，每行一个；留空表示你的全部论文）。对大多数人来说每周一次就足够了：可以打开 **每天更新**，或者让智能体把它改成每周更新。

### 新模型追踪

[新模型追踪](/apps/t/new-model-watch)盯着 Hugging Face 上某一类新模型（重排序模型、嵌入模型等），对照你的限制条件进行检查，并对每个模型运行你自己的评估，这样你只会收到超过你当前最佳成绩的模型的消息。

- **它看什么**：这一类中最新的模型（名称中包含你给出的词），要求发布已满你设定的时长（默认 7 天），并且到那时下载量足够；每次更新处理下载量最多的八个（其余的等下一次）。其他格式的模型副本（GGUF、ONNX、量化版）会被排除，除非你的关键词明确要求包含它们。它会读取每个模型的页面和模型卡，了解其许可证、大小和用途，并排除那些被你的许可证或大小要求拒之门外的模型。
- **你的评估**：给出一条命令，在模型名称的位置用 `{model}` 代替（`python eval.py --model {model}`），再给出它所在的文件夹、它输出的分数（`ndcg@10`）、分数越高越好还是越低越好，以及你目前的最佳成绩。之后每个值得一试的新模型都会在[实验](/experiments)中运行（分组为“New-model watch”，每个占用一块 GPU，在它的队列里排队），当某个模型比你的最佳成绩更好时，它会通知你；下次更新会读取每次运行的分数。没有命令时，它只列出新模型。
- **页面**：**模型**，每个模型都标明所处状态（**新增**、**评估中**、**已评估**、**超过** 你的最佳成绩、**未运行**、**已跳过**、**太新**）、模型卡上的说明、大小、许可证、下载量和点赞数，以及它的分数；超过你最佳成绩的排在最前面。**你的评估** 说明当前运行的是什么，并带有 **打开“实验”**。

### 截稿雷达

[截稿雷达](/apps/t/deadline-radar)把你关注的会议和期刊的截止日期放在同一条时间线上，并按你所在的时区显示，在每个截止日期之前提醒你，还附上征稿启事、页数限制和模板的链接。

- **日期从哪里来**：来自 GitHub 上的两份开放列表，ccfddl 和 ai-deadlines，二者合并使用。两份列表都没有的会议或期刊，会到网上查找：搜索它下一个截止日期，读取最合适的页面，并让辅助模型记下日期、时区以及会议的名称和年份；这样的截止日期会注明取自它的官网，并附上页面链接，方便你去核对。只有网上也查不到的会议或期刊，才会在 **会议** 中列为未找到。每个截止日期都会从征稿启事给出的时区（大多数写的是 AoE，即 Anywhere on Earth，也就是 UTC−12）换算成你的时区，你的时区由应用从浏览器中获取。
- **页面**：**时间安排**，列出之后的每个截止日期，包括你所在地的日期和时间、征稿启事所写的截稿内容、会议举办地点、**征稿启事** 页面（找到的那一个，在各次更新之间保留，否则用会议官网）、**模板** 链接和页数限制，以及剩余时间（按你查看时计算）；每个会议或期刊的下一个摘要或论文截止日期会突出显示。可以在顶部只显示某一个会议或期刊；**复制截止日期** 会把它们复制为一行一条的文字；**显示过去的** 会展开最近几个月已经过去的截止日期。**会议** 完整显示每个会议或期刊、它的级别、下一个截止日期和官网，以及两份列表都不认识的名称。
- **提醒**：每次更新都会针对你设定的天数（默认 14、3 和 1，可修改）内的截止日期给你发送通知，每条提醒只发一次，全部合并在同一条通知里。请打开 **每天更新**，这样提醒才能及时送到。
- **它的设置**：**你关注的会议**（按你习惯的叫法填写，用逗号分隔：SIGIR、ACL、EMNLP、NeurIPS、The Web Conference、KDD……；默认取自“关于你”中的 **你阅读的会议和期刊**）和 **提醒我**（提前的天数，用逗号分隔；留空表示不提醒）。为了查到每份征稿的页数限制和模板，它会为每个会议搜索一次征稿启事并读取它（由辅助模型记录这些信息）。

### 动态相关工作

[动态相关工作](/apps/t/living-related-work)为你的每个主题维护一个页面，随着新论文的出现不断增长：每篇论文都有概括，说明它与主题的关系，按主题分组，并标出新的论文。

- **增长情况**：第一次运行时，它会取 arXiv 上每个主题的最佳论文和过去一年的最新论文，以及 OpenAlex 上被引用最多的论文；之后则取此后新发表的论文。引用你的种子论文的那些论文，会进入每一个主题。辅助模型会留下相关工作章节应当引用的论文，用一句话概括每篇，说明它与主题（以及你的种子论文）的关系，并把它归入某个主题组。
- **页面**：**相关工作**，每个主题下的论文按主题组排列，最新的在前，最近一次更新新加入的标有 **新增**（在顶部选择某一个主题）。每篇论文都有它的引用键、**BibTeX**（复制它的条目）和 **不相关**（它会永久从该主题中移除）。**起草相关工作** 会让辅助模型用 LaTeX 写出该主题的章节，每个主题组一段，依据你的论文中最多约 60,000 个字符的内容（取最新的；它会说明省略了多少），并使用你论文中的 `\cite` 键（不属于其中任何一个的键会被删掉，页面会注明）：完成后会显示 **复制 LaTeX** 和 **复制 .bib**（需要几分钟；你离开页面它也会继续）。**导出 BibTeX** 会汇集该主题的所有条目供你复制。**本次新增** 列出最近一次更新新加入的内容。
- **它的设置**：**主题**（每行一个）、**种子论文**（标题、arXiv ID 或 DOI，每行一个）和 **每个主题最多论文数**（默认 80）。

### 研究空白发现器

[研究空白发现器](/apps/t/gap-finder)把你的论文与某个领域本月的论文交叉组合，得出项目想法，检查每个想法是否已有前人工作，并根据你拥有的算力评估其规模。它通过自己的表单运行，也可以由智能体在会话中替你运行。

- **你要提供什么**：**你的论文**（你作为作者的姓名，会带出你最新和被引用最多的论文，也可以填论文标题或 arXiv ID，每行一个；姓名默认取自“关于你”中的 **作为作者的你**，与之一起保存的 ORCID 或 OpenAlex ID 可以精确找到你，只要姓名还是那一个）、**研究领域**（用文字描述，或填 arXiv 类别：conversational search、cs.IR；用逗号分隔多个时会一起搜索；默认取自 **你的领域**）、**你拥有的算力**（除非你另行说明，默认是一块 24 GB 的 GPU；默认取自 **你能在什么上运行**）和 **想法数量**（5）。
- **它做什么**：它读取你的论文和该领域过去一个月的论文，按与你论文的相关程度给本月论文排序，让辅助模型提出将两者交叉的想法。然后每次三个，检查每个想法是否已有前人工作：在 arXiv、OpenAlex 和 Semantic Scholar 上运行多组能以其他叫法找到它的检索，加入引用最接近的论文或与之相关的工作，再由辅助模型（其中较强的那个）把最接近的几篇与该想法进行比较，判定为 **新**、**部分已有人做过** 或 **已有人做过**，并给出最接近的论文。检查无法判断的想法会标为 **未验证**，绝不会标为新的。之后给出应先做的第一个实验、在你的算力上需要付出多少，以及它是 **合适**、**紧张** 还是 **太大**。
- **视图**：**研究想法**，新的排在最前（可在顶部只显示某一种结论），每个想法都有它交叉组合了什么、为什么得出这个结论、最接近的工作（带链接）、第一个实验及其成本，还有 **规划它**（用该想法作为问题，打开研究冲刺应用）、**深入研究**（对相近工作生成一份深度研究报告）和 **复制**。**交叉组合了什么** 列出它用到的你的论文和本月的论文。
- **在任何会话中做同样的检查**：智能体在推进任何想法或结果、或称其为新颖之前，会用它来检查。它最多耗时两分钟，结果显示为一张卡片 **这是新的吗？**，结论为 **看起来是新的**、**部分已知**、**已有人做过** 或 **未判断**，并列出最接近的论文（每篇链接到来源）以及相同和不同之处。什么都没找到并不能证明它是新的。检索内容会发送给上述三个服务，因此保密会话中没有这项功能。

## 阅读和整理论文

在[应用页面](/apps)的 **研究** 下有三个现成的应用，可以帮你处理读到的论文：**阅读清单** 负责保存论文，**文献矩阵** 在电子表格中对比多篇论文，**复现论文** 则通过运行论文的代码来检查其中的数字是否站得住脚。你可以在那里打开它们，也可以在任意会话中直接说出你想做的事（“把 1706.03762 添加到我的阅读清单”），由智能体替你运行（[让智能体替你运行应用](/guide/apps#have-an-agent-run-an-app-for-you)）。

无论你用哪种方式给出论文，它们都能找到：DOI、arXiv 编号、链接（arXiv、DOI、ACL Anthology、OpenReview、出版商页面或 PDF 的链接）、标题，或者这台电脑上的一个 PDF。它们只读取公开的版本（arXiv、OpenAlex 已知的公开版本、论文自己的页面），绝不越过付费墙：没有公开版本的论文只会根据摘要来读，应用也会如实告诉你。

### 阅读清单

[阅读清单](/apps/t/reading-list)打开后显示的是你的论文，而不是一个表单：这是一个可以直接上手工作的地方。

- **添加论文**：点击 **+ 添加**，然后填写 **论文**（DOI、arXiv 编号、链接或标题），也可以填写它的 **项目**、**标签**（用逗号分隔）和 **状态**。点击 **添加** 后，它会查找这篇论文，并连同作者、年份、发表场所、摘要、论文及公开 PDF 的链接和 BibTeX 条目一起保存。已有的论文不会重复添加（DOI、arXiv 编号或标题相同）：缺少的信息会被补全，而你的备注、标签和状态保持原样。如果什么都查不到，它会按你给的标题保存，并据此生成一个条目：请留意检查这样的论文。
- **找到你的论文**：顶部会显示待读、在读和已读的论文数量（点击其中一个，只显示对应的论文），以及论文分布在多少个项目中。**搜索你的论文** 可以按论文中的任意字词查找，**全部**、**待读**、**在读** 和 **已读** 则分别显示某一种状态的论文。每篇论文会显示作者、发表场所和年份，它的项目和标签（点击某个标签，只显示带该标签的论文；点击它的 **✕** 再次显示全部），以及 **待读**、**在读** 和 **已读**，用来更改它的进度：选择 **已读** 会记下当天的日期。
- **论文自己的页面**：点击它的标题。页面上有 **它的页面** 和 **PDF**（对于这台电脑上的 PDF，则是 **打开 PDF**）、阅读进度、摘要、所属项目和标签（各自带有 **保存**）、你的 **备注**（**保存备注**）、它的 BibTeX（**复制 BibTeX**）以及 **从清单中移除**。**复现它** 会打开[复现论文](#reproduce-a-paper)，并自动填好这篇论文。
- **按项目**：列出每个项目，以及其中的论文数量和你已读的数量；点击某个项目，即可显示它的论文。你可以填写你的某个[项目](/guide/projects)的名称，这样论文就归入该项目（项目改名后论文会随之更新），也可以随意取一个名字。
- **更多** 中有 **导入 .bib**（粘贴内容，或给出这台电脑上某个 .bib 文件的路径，并为新增的论文指定项目和标签：已有的论文会被补全，你原有的内容保持不变）、**导出 .bib**（**当前显示的**，即按你的搜索和筛选所显示的论文，或 **全部**：可以下载为文件，也可以 **复制**）以及 **与 Zotero 同步**（见下文）。
- **生成文献矩阵**：勾选论文（每篇左侧的方框），会出现一个栏，显示你选了多少篇，其中有 **生成文献矩阵**，点击后会用这些论文启动[文献矩阵](#literature-matrix)，还有 **清除**。

当智能体替你添加论文时，它的卡片会显示 **论文**：论文在清单中现在的样子、它是否是新添加的、**打开你的阅读清单**，以及可复制的 BibTeX。

### 与 Zotero 保持同步

依次点击 **更多** → **与 Zotero 同步** → **立即同步**，即可让清单与你的 Zotero 资料库保持一致。

1. 第一次同步时，页面会要求你提供 **Zotero API 密钥**：点击 **获取** 会打开 Zotero 的密钥页面，你可以在那里创建一个可以读取你资料库的密钥（如果希望论文也能写入 Zotero，还需要写入权限）。粘贴密钥后点击 **保存**：它会存入你的保管库，只供 Zotero 使用（[把密钥存放在保管库中](/guide/connections#keep-keys-in-the-vault)）。**Zotero 用户 ID** 可以留空：它会根据密钥自动找到（如果是群组的资料库，请填写 `groups/` 加上群组编号）。然后再次点击 **立即同步**。
2. Zotero 中的内容会被导入：新论文会被添加，已有的论文会被补全，匹配依据是 DOI、arXiv 编号或标题。如果两边的详细信息不一致，以 Zotero 的为准，而你的状态、备注和项目仍归你所有。
3. 只存在于这里的论文会作为新条目发送到 Zotero。

第一次之后的每次同步，只会处理自上次同步以来发生变化的内容。你在 Zotero 中删除的论文会保留在这里，不再与之关联，也绝不会被重新发送回去。你的论文上方有一行文字，说明上次同步的时间和做了什么（“从 Zotero 新增 12 篇，向它发送 3 篇”），旁边是 **再次同步**。

### 文献矩阵

[文献矩阵](/apps/t/literature-matrix)会并排阅读多篇论文，并填写一张电子表格：每篇论文一行，每个对比项一列，每个单元格里是论文的说法，以及出处（所在的页码或章节）。

- **论文**：每行一篇（最多三十篇），可以是 DOI、arXiv 编号、链接、标题或这台电脑上的一个 PDF。也可以来自你的阅读清单：写成类似“我的阅读清单，标签：dense”的一行（也可以按项目或状态：“我的阅读清单，待读”）。阅读清单中的 **生成文献矩阵** 会自动填入你选中的论文。
- **各列**：每行一列；在你修改之前是 **任务**、**数据**、**做法**、**指标**、**结果** 和 **限制**，之后则是你上次使用的那些列。
- **项目**：存放其电子表格的那个项目。这时，只写“我的阅读清单”而后面不加任何内容的一行，会取该项目的论文。

它每次读三篇论文（有公开版本时读全文，没有时读摘要），由一个快速模型填写每一行，再写出这些论文合在一起说明了什么，并把矩阵作为[电子表格](/guide/library#spreadsheets)保存在项目的文件中，另有第二个工作表列出这些论文。它的视图包含 **矩阵**（读了多少篇、**打开电子表格**、**复制为表格**、矩阵本身、未能读取的论文及原因，还有 **再加一列**：给出一个列名，点击 **加上它重新生成** 就会连同这一列再运行一次）、**论文**（每篇用一句话说明它做了什么，以及读取的来源）和 **跨论文综述**（它们在哪些方面一致、哪些方面有分歧、还有哪些问题悬而未决，带有 **复制**）。

### 为论点找到支撑的论文

在 [LaTeX 编辑器](/guide/library#latex-documents)中写作时，选中一句需要引用的话，然后选择 **插入 → 为此查找引用文献**。辅助模型会把这个论点转化为对 OpenAlex 和 arXiv 的搜索，并阅读搜到论文的摘要；对话框会列出为该论点提供有力或部分支撑的论文，每篇用一行说明原因，并附上作者、年份、发表场所和摘要。**引用** 会把这篇论文的 BibTeX 添加到你的参考文献中（使用 doi.org 或 arXiv 自己的条目，并采用一个尚未被占用的键），同时在论点之后加上 `\cite`，第二篇会并入第一篇的引用中；**添加** 则只添加条目。只会发送这个论点和它周围的文字，绝不会发送论文的其余部分。

同一个编辑器还可以校对你的论文（**工具 → 用 AI 校对**），改写你选中的文字，同时保留每一个命令、公式、`\cite` 和 `\ref`（**编辑 → 用 AI 改写**），根据你的描述写出公式、表格或算法（Ctrl+K），从图片中读取公式，解释并修复 TeX 的错误，以及整理参考文献；详见 [LaTeX 文档](/guide/library#latex-documents)。

### 复现论文

[复现论文](/apps/t/reproduce-paper)会运行论文自己的代码，看看其中的数字是否成立：它会找到代码、搭建环境、获取数据和检查点、运行评测、把数字与论文的表格对比，并说明所花的功夫。**限制** 以你上次给出的内容为起点，你在“关于你”中保存的 **你能在什么上运行** 也会交给智能体，这样它就能选择适合你机器的运行方式。

- **论文**（或 **或者上传**）、**它的代码**（链接或这台电脑上的文件夹；留空时会去查找）、**要复现的内容**，按论文的叫法填写（“表 2，MS MARCO dev 上的 BM25 + monoT5 一行”）、**限制**（它可以使用的时间、磁盘和 GPU：在你修改之前是“最多 4 小时、100 GB 磁盘和 1 块 GPU”）以及 **工作位置**（一个文件夹；留空时每次运行都会新建一个）。

它会阅读论文并从中查找代码；如果论文没有提到代码，它会同时在 GitHub 和网络上搜索，并挑选最有可能的仓库。一个快速模型会确定确切的设置（数据和划分、模型和检查点、各项设置）以及需要对上的数字，按论文印出的为准。然后由一个智能体按照 **reproduce-paper** 技能的要求去做：按仓库的说明建立干净的环境（venv、conda 或 Docker），获取数据和检查点，先在一小部分数据上运行，再进行真正的运行，它所做的每一处改动及原因都会记录下来，最后在工作文件夹中生成一份报告 `REPRODUCTION.md`。需要 GPU 或数小时的真正运行会交给[实验](/guide/experiments)，它会等待空闲的 GPU，并保存运行的记录和日志：应用会等这些运行结束，而不会让某个会话一直处于忙碌状态，随后由一个智能体读取它们的数字并完成报告。最后，每个数字都会与论文中的数字并排放置：在 0–100 的刻度上相差不超过半个点（在 0–1 的刻度上为 0.005）就算复现成功。

它的视图包含 **复现成功了吗？**（结论、有多少个数字接近、所用的小时数和做出的修复、它的仓库、**打开文件夹**、它在实验中的运行，以及未能复现时的 **重试**；接着是论文的数字与我们的数字并排放置及其差值，接近的以绿色显示，还有论文给出的设置）、**所花的功夫**（每一步及其分钟数，以及每一处改动和修复）和 **报告**（带有 **复制报告**）。

它会在这台电脑上运行代码，可能要花几个小时：它会遵守你设定的限制，一旦将要超出某项限制，就会停下来并报告已有的结果。对于拿不到的代码或不公开的数据，它会直截了当地说明。

**边读边为论文做突出显示。** 在文件中打开论文的 PDF，然后点击 **突出显示**：选中一段文字，或者拖出一个框圈住公式或图，就能用四种颜色之一把它标出来，并在上面写一条备注。**询问** 会让智能体只针对这一部分作答（“这个公式说的是什么？”），**备注** 则逐页列出你标记的所有内容。**保存到项目** 会把你的突出显示和备注整理成一份以论文命名的文档，放入项目的知识中并保持更新，这样项目的会话就能找到它们；**保存到 PDF** 则把它们写入文件，供其他应用使用。详见[阅读并突出显示 PDF](/guide/files-git#read-and-highlight-a-pdf)。

## 投稿前检查论文

论文投出之前，LaTeX 编辑器会像会议或期刊的初审人员和审稿人那样检查它：参考文献、是否暴露了你的身份、页数和字体、会议或期刊要求的各个部分，以及表格中的数字。打开你的论文（项目文件中的一个 LaTeX 文档：项目详情 → **文件**），然后选择 **工具 → 投稿前检查**。

1. 选择投稿目标：**ACL Rolling Review**（长文或短文；**EMNLP** 和 **NAACL** 的论文都通过它投稿）、**SIGIR**（长文或短文）、**CIKM**、**WSDM**、**TheWebConf**、**KDD**、**NeurIPS**、**ICLR**、**ICML**、**AAAI**、**IEEE 期刊**、**ACM 期刊**或**其他**；选择“其他”时，可以自行设置页数上限和**匿名评审**。下方有一行说明该会议或期刊的要求：页数上限、哪些内容不计入页数、是否匿名评审，以及必需的部分。各会议和期刊每年都会修改规则，所以这一行还附有征稿通知的链接。检查会为每篇论文记住所选的会议或期刊，首次使用时会选择论文自身的样式所指向的那一个。
2. 点击 **检查** 后，系统会排版论文、读取它的 PDF、在线查询参考文献，并随结果产生逐步显示。只会发送参考文献的标题、DOI 和 arXiv 编号，发送给 Crossref、arXiv、OpenAlex、Semantic Scholar 和 DBLP；这些服务返回的内容会保留几天，没有响应的服务会在检查结果下方列出。OpenAlex 和 Semantic Scholar 对使用自己免费密钥的程序响应更积极：在[密钥](/apps/connected?tab=keys)中把它添加为 OPENALEX_API_KEY（用于 api.openalex.org）或 SEMANTIC_SCHOLAR_API_KEY（用于 api.semanticscholar.org），检查就会使用它。

检查结果分为五组，每一项都标有 **必须修复**、**请检查** 或 **供参考**：

- **参考文献**：被引用但在参考文献列表中没有对应条目的键（或引用时的大小写与条目不一致）、从未被引用的条目、同一篇论文使用了两个键，以及缺少该类型所需内容的条目（期刊文章缺期刊名、会议论文缺论文集、缺年份）。每个被引用的条目都会按 DOI、arXiv 编号或标题查询，并与各服务所列的信息比对：标题、作者、年份和发表位置。预印本会被查找是否有正式发表的版本，审稿人期望你引用正式版本。如果某篇论文在任何地方都找不到，会提示它可能并不存在：请自行核实，因为这些服务也可能有遗漏。
- **匿名性**（适用于匿名评审的情况）：你的姓名（当模板处于最终版时；ACL、NeurIPS、ICML、ICLR 和 acmart 都有匿名版）；**\thanks** 注释；致谢部分；可能暴露你或你的实验室的链接（你自己的代码仓库、个人主页）；引用旁的“我们之前的工作”；以及 PDF 自身的作者（Author）和标题（Title）字段。
- **格式**：计入页数上限的页面（到参考文献开始之前，或排除会议或期刊不计入的部分，例如 ACL 的 Limitations）、参考文献的页数，以及在有总页数上限时的总页数；Type 3 字体和未嵌入的字体；对模板页边距、字体和间距的改动，以及负的 **\vspace**（作为提示：有些是允许的）；显示为 ?? 的参考文献和引用；**TODO**、**XXX** 和 **\todo** 标记；远远伸入页边距的行；以及无法排版时的错误。
- **必需部分**：摘要，以及会议或期刊要求的内容：ACL 的 Limitations 部分、NeurIPS 的 Paper Checklist（以及仍为 **\answerTODO** 的回答）、ICML 的 Impact Statement、ICLR 的 AI 使用声明、CIKM 的 GenAI 披露、IEEE 的 Index Terms、ACM 的 CCS concepts 和关键词。
- **数字**：见[与你的运行结果相符的数字](#numbers-that-match-your-runs)。

点击带有文件名和行号的按钮，可以在源文件中定位到该项。在修改安全的地方，**修复** 会直接进行修改：按各服务所列的信息更新条目，保持键不变，因此你的引用不受影响（**查看条目** 会先显示它）；换成预印本的正式发表版本；把模板切换到匿名版；把致谢注释掉；清除 PDF 的 Author 字段；删除 **\todo** 备注；移动粗体；更新表格。修复和编辑器中的其他改动一样：**撤销** 可以撤回，**保存** 会把它保存为新版本。在没有安全改法的地方，**问智能体** 会向编辑器旁边的智能体发出请求，并附上该检查项；**请智能体修正** 则一次性把全部检查项交给它。

**添加为评论** 会把未处理的检查项作为文档评论放在相应的文字上（见 [LaTeX 文档](/guide/library#latex-documents)），这样你、与你共享论文的人和智能体都能在相应位置看到它们；被要求回复评论的智能体会修正这些问题并把评论标为已解决。再次检查时，会告诉你自上次检查以来已修复多少项、还剩多少项、新增多少项；之后 **添加为评论** 会把已修复项的评论标为已解决。

智能体也可以对你保存的论文或你的 LaTeX 项目运行同样的检查：“投稿 ACL 之前，帮我检查一下我的论文”。

### 与你的运行结果相符的数字

检查会逐个数字地读取论文中的每一张表格：

- **最佳值加粗。** 在每一列中，粗体应标出最佳值。哪个方向更好取决于该列的表头：损失、误差、延迟或困惑度越低越好；准确率、F1、nDCG 或 BLEU 越高越好；箭头（↓ 或 ↑）会直接说明。表头没有说明时，默认越高越好，检查项中会注明这一点。对每一组行（两条横线之间）的最佳值加粗、并列最佳，以及指标放在行中的表格，都没有问题。**移动粗体** 会把粗体放到最佳值上。
- **由实验生成的表格。** 你从[实验](/experiments)放进论文的表格（**生成表格**，然后 **放进 LaTeX 文档**），上方会有一行 `% hydor:table …`。检查会根据这些运行目前的状态重新计算该表格，并标出自那以后发生变化的每个数字，以及新增或消失的显著性标记。**更新表格** 会换上新的表格。
- **其他表格。** 它们的数字会在论文所在项目（或其文件夹）已完成的运行中查找，按表格的舍入方式取整，也按百分比查找。找到了多少个会作为供参考的信息给出，绝不会当作问题：某个数字可能来自另一篇论文，或来自在别处进行的运行。

### arXiv 投稿包

在打开的 LaTeX 文档顶部选择 **导出 → arXiv 投稿包（.zip）**（在手机上是 **更多**（⋯）→ **下载为**），会把已保存的论文打包成一个 .zip，用于上传到 arXiv；arXiv 会按你提交的原样发布源文件。以下选项已默认勾选：

- **删除注释**，并且是安全地删除：`\%` 会保留，TeX 按原样处理的内容也会保留（verbatim 文本、listings、**\verb**，以及 **\url** 和 **\href** 的地址）；`\begin{comment}` 块会被删除，勾选 **也删除 \iffalse … \fi 块** 后，这些块也会一并删除。
- **只包含论文用到的文件**：**\includegraphics** 实际显示的图片、它读取的文件、它自己的样式和文档类。
- **加入 .bbl，去掉 .bib**：即在这里排版时生成的参考文献，arXiv 使用的就是它。取消勾选则会发送 .bib，由 arXiv 运行 BibTeX。
- **把 \input 和 \include 的文件并入 main.tex** 和 **在开头加上 \pdfoutput=1**（arXiv 要求使用 pdfLaTeX 的旧方式），勾选后生效。

带空格的文件名会被换成连字符，源文件中的引用也会随之更改。**生成投稿包** 会在与任何文档相同的沙盒中对投稿包进行排版，以确认它能顺利编译，然后下载。对话框会说明包中有什么、哪些被省略或重命名、排版情况如何、大小与 arXiv 50 MB 上限相比如何，以及在 arXiv 上应选择哪种处理器。它会记住你的选择。

### 终稿、另一个模板，以及在应用中处理你的论文

**工具 → 你的论文** 提供其余功能：

- **改成终稿** 会请编辑器旁边的智能体按会议或期刊的规则写出最终版本：模板的最终版、恢复作者及其单位、恢复致谢、版权或权利声明块、最终版新增的内容，以及它的页数上限。如果源文件中没有作者、单位和致谢，请把它们告诉智能体。
- **迁移到另一个模板** 会请智能体把论文迁移到另一个会议或期刊的模板（或 Springer 的 LNCS、Elsevier 的模板、普通 article），作为送审版或终稿，同时保留论文的文字、图、表格和参考文献。
- **arXiv 投稿包（.zip）**，见上文。
- **像审稿人那样审阅它**、**回复审稿意见** 和 **制作演讲、海报和推文串** 会打开相应的应用，并填入你的论文（它的 PDF；制作演讲时则是其源文件所在的文件夹）：见[审阅、回复并展示你的论文](#review-answer-and-present-your-paper)。

尚未保存的内容会先被保存，这样每个功能拿到的都是你所看到的论文。

## 证明：用 Lean 检查

[Lean](https://lean-lang.org) 是一个证明检查器：它读取用它自己的语言写成的证明，只有每一步都能推出时才接受，所以被它接受的证明就是正确的。智能体用自然语言写的证明可能读起来很顺，实际上却是错的；有了 Lean，它们就能检查这些证明。

在[设置 → 通用 → Lean（证明检查器）](/settings?s=general&find=Lean%20%28proof%20checker%29) 中**安装**一次即可：**安装**会下载约 620 MB（在你的电脑上共占约 3 GB）。如果你自己装了 Lean，就使用你的版本，并且绝不改动它。大多数实际的数学内容还需要 Lean 的大型数学库 **Mathlib**：**添加 Mathlib** 会下载它，下载量约 600 MB，解压后在电脑上约占 8 GB（连同 Lean 本身约 11 GB，添加时需要有 10 GB 可用空间）。这需要几分钟，并且需要 git。检查一个导入整个 Mathlib 的文件需要几秒钟（电脑启动后第一次约半分钟），给出结论大约要三倍时间，运行期间占用 6 到 8 GB 内存，其中大部分是 Mathlib 自身的文件；只导入所需部分的文件则轻量得多。该行菜单中的**移除**会删掉应用添加的内容。你自己的、用到 Mathlib 的 Lean 项目照常保留它自己的副本：应用添加的这一份只用于单个文件和代码片段。请在项目文件夹中用 `lake exe cache get` 为项目获取一次副本（每个项目约再占 8 GB）：在此之前，应用不会在其中运行任何内容，并会告诉你原因，而不是未经询问就下载，或花几个小时从源码编译 Mathlib。智能体发现缺少 Lean 时，会用一张卡片询问你并标明大小，在你同意前不会下载任何内容。如果某个项目要求其他版本的 Lean，第一次使用时会下载那个版本。

**智能体能用它做什么**：边写证明边检查；在 Lean 的各个库中搜索已经证明过的结论（通过 [Loogle](https://loogle.lean-lang.org) 和 [LeanSearch](https://leansearch.net) 这两个公共服务，因此搜索内容会离开你的电脑；[机密会话](/guide/sessions#keep-a-session-confidential)只检查证明，不做搜索）；以及给出判定。检查 Lean 文件会运行其中写的代码，所以在计划模式下绝不执行；在智能体运行命令前需要询问你的情况下，检查会在沙盒中运行，只能访问会话的文件夹，且不能联网（如果电脑上没有沙盒，会先询问你）。

**先确认命题。** Lean 只能判断证明是否符合所写的命题，而用 Lean 写出的命题可能与你的本意不同（你指实数，它写成了整数；你指“至多”，它写成了“小于”；或者带了一个永远不可能成立的假设）。所以在证明之前，智能体会先用 Lean 写出命题，只依据 Lean 文本用普通的数学语言复述给你，列出它与你的要求有哪些不同，然后等你回答 **It says what I mean**（这就是我的意思）或 **Not quite**（不完全是）。已经确认的命题，它不会不经询问就改动。

**判定**有两种。一是“已证明”：文件编译无错误，没有任何省略，每个定理只依赖 Lean 的三条标准公理，并且 Lean 的核心检查器接受每一步。二是“除指明的缺口外已证明”。**sorry** 是 Lean 中表示“证明略”的词：含有它的文件仍可能编译通过，但其中相应的内容并未得到证明。判定只说明证明了哪个命题，不说明它是不是正确的那个命题：那是由你确认的。

**作为目标的检查项。** 每个会话都有一个给出同样判定的命令：**leancheck**。设定一个[目标](/guide/goals)，把命令检查项设为 `leancheck Proofs/Main.lean`，智能体就会一直工作，直到证明成立；加上 `--theorem` 和一个名称，则只检查那一个定理。

**在 LaTeX 编辑器中**，**工具 → 检查证明…** 会请编辑器旁的智能体逐步审查光标处（或你选中的几行）的证明，并带行号逐个报告缺口：证明按现有写法是否成立、补上缺口后成立，还是不成立。**工具 → 用 Lean 形式化…** 会请它用 Lean 表述该定理，并在证明前与你确认命题。两者都只是把请求填进输入框：由你过目后发送。用自然语言检查证明不需要 Lean。

## 审阅、回复并展示你的论文

[应用页面](/apps)的**写作**分类下有四个现成的应用，可以帮你处理自己的论文：**审稿人模拟器**会像会议/期刊的审稿人那样审阅你的草稿，**反驳工作台**会为你收到的审稿意见起草回复，**论文转演讲、海报和推文串**会做出用来展示论文的内容，**插图医生**则让论文里的图表达到印刷要求。前三个应用可以从这台电脑上的 PDF、.tex 文件或 LaTeX 项目文件夹、链接，或者你保存的 LaTeX 文档（粘贴它的地址）来读取你的论文；**或者上传**则改为上传一份 PDF。

### 审稿人模拟器

[审稿人模拟器](/apps/t/reviewer-simulator)会赶在真正的审稿人之前审阅你的草稿，使用该会议/期刊自己的审稿表和评分，并列出审稿人可能会要求你做的事，最危险的在前。

- **你的论文**、**会议/期刊**（**ACL Rolling Review**、**SIGIR**、**NeurIPS**、**ICLR**、**ICML**、**KDD**、**CIKM**、**WSDM**、**TheWebConf**、**期刊**或**其他**，各自采用其 2025 年的审稿表）、**审稿人数量**（1 到 5；不改的话是 3）和**需要重点关注的地方**。

你上次选的会议/期刊，下次会再次出现在这里。如果论文无法读取（没有公开版本，或者 PDF 里没有文字），运行会立刻停止并告诉你原因，同时说明换一种方式提供论文的办法：用**或者上传**上传它的 PDF，填写它的 .tex 文件或 LaTeX 文件夹的路径，或者填写它的 arXiv 编号或链接。

它会安排好各位审稿人，每人有自己的角度（依次是：方法专家、领域专家、持怀疑态度的实证研究者、来自相邻领域的细心读者，以及可复现性审稿人），然后各自同时填写该会议/期刊的审稿表。接着由领域主席写出元评审，给出可能的结果，并按每个弱点导致论文被拒的可能性高低对它们排序。这些审稿意见出自模型：它们能赶在真正的审稿人之前找出薄弱之处，但并不是对最终决定的预测。

它的界面包括 **审稿意见**（会议或期刊、可能的结果、平均总分，然后是每份审稿意见：审稿人及其角度、评分、摘要、优点、缺点和问题）、**元评审**（带有 **复制** 和 **复制全部审稿意见**；接着是 **可能导致被拒的问题，最危险的在前**：每项缺点附有原因、可能性和解决办法）、**基线和消融实验**（审稿人会要求做什么、为什么、需要多少工作量；列表下方的 **运行这些…** 会打开开始页面，并带上一条请智能体运行这些实验的请求，由你选择论文代码所在的文件夹和智能体，读过之后发送）和 **投稿前要做的事**（一份可逐项勾选的清单，以及 **回复这些审稿意见**，它会带着这些意见启动反驳工作台，让你预演反驳）。

### 反驳工作台

[反驳工作台](/apps/t/rebuttal-workbench)会逐点起草你对收到的审稿意见的回复，并控制在该会议/期刊的长度限制之内。

- **审稿意见**（全部粘贴进来，每份写在各自审稿人的名下：“Reviewer 1”“R2”，或 OpenReview 上的“Reviewer xYz1”……）、**你的论文**（或**或者上传**；可选，用于让回复指向论文中的相应章节）、**长度上限**（按会议/期刊的规定：按字符或单词计，按每位审稿人、每个要点或总共计算；不改的话是“每位审稿人 2,500 个字符”）和**语气**（**礼貌而坚定**、**热情而感激**或**简洁扼要**）。长度上限和语气会沿用你上次填写的。

它会按审稿人拆分审稿意见，把每个人的要点并排提取出来，合并多位审稿人提出的同一个要点，并给它们分类：误读（你的论文其实已经回答了）、需要补实验、需要补充文字（澄清、论证或引用），或者次要问题。它会找出你的论文在每一点上是怎么说的，在各自分得的长度范围内起草每条回复，并把反驳整合起来，按长度上限统计字数。如果某条回复需要新的结果，它会留下 [占位符] 让你填写：它绝不会编造结果。

它的界面包括 **提出的要点**（用一行话概括反驳；**全部要点**、**误读**、**需要补实验**、**需要补充文字** 和 **次要** 分别只显示某一类；每个要点附有提出者、对方的原话、回复草稿、回复长度与分配额度的对比，以及 **复制**）、**待办**（需要做的实验和论文中需要做的修改，可逐项勾选；实验下方的 **运行这些…** 会打开开始页面，并带上一条请智能体运行这些实验的请求，你选好论文代码所在的文件夹后再发送）和 **完整反驳**（对每位审稿人的回复与长度上限的对比，以及 **复制完整反驳**）。

### 论文转演讲、海报和推文串

[论文转演讲、海报和推文串](/apps/t/paper-to-talk)会做出用来展示你论文的内容：带有论文真实插图和公式、有计时并附讲稿的幻灯片；A0 海报；适用于 X、Bluesky 和 LinkedIn 的帖子；以及项目主页。

- **你的论文**（最好提供它的 LaTeX 项目文件夹，这样能取到插图；如果来自 arXiv，会下载它的源文件来取插图）、**演讲时长（分钟）**（不改的话是 15）、**听众**（**本领域的研究者**、**其他领域的研究者**或**普通听众**）、要做什么（**幻灯片**、**A0 海报**、**推文串（X、Bluesky、LinkedIn）**和**项目主页**）以及**项目**（做好的内容要放进你的哪个项目）。

如果论文无法读取，运行同样会停止，并说明换一种方式提供论文的办法。它会规划演讲（大约每分钟一张幻灯片，每张一个观点，从问题讲到要点总结），由一个程序分配各部分的分钟数，使它们加起来正好等于总时长，然后同时做出你要的内容：幻灯片，你可以在项目文件中编辑并从那里放映（[幻灯片](/guide/library#slides)）；LaTeX 文档形式的海报（[LaTeX 文档](/guide/library#latex-documents)）；帖子；以及可以直接发布的项目主页（[发布网页](/guide/library#publish-a-page)）。

它的视图里有**做好的内容**（演讲的核心信息和一句开场白，然后是做好的每一项，附有**打开**）、**演讲**（把演讲显示为一条长带，每张幻灯片的宽度与它的分钟数成正比，然后是每张幻灯片：分钟数、标题、要点、插图、公式和讲稿）和**推文串**（**X**、**Bluesky** 和 **LinkedIn** 分别显示各自的帖子，带编号，每条都有**复制**，另有**复制推文串**；LinkedIn 只有一条帖子，对应的是**复制帖子**）。

### 插图医生

[插图医生](/apps/t/figure-doctor)会让你论文里的图表达到印刷要求：宽度与栏宽一致，使用论文的字体，配色能让色盲读者区分开，保存为嵌入字体的矢量 PDF，全部由一个样式文件统一控制。

- **你的绘图代码**（这台电脑上的脚本、笔记本或装有它们的文件夹，用 matplotlib 或 seaborn 制作）、**会议/期刊的模板**（它、**或者填宽度（英寸）**和**论文的字体**会沿用你上次的回答；可选 **ACL, EMNLP, NAACL**、**ACM (SIGIR, KDD, CIKM, WSDM, TheWebConf)**、**IEEE**、**ICML**、**NeurIPS, ICLR**、**Springer LNCS** 或**其他（请填宽度）**）、**宽度**（**单栏**或**跨双栏**）、**或者填宽度（英寸）**（适用于其他模板）和**论文的字体**（**与模板一致**、**Times New Roman**、**Computer Modern**、**Linux Libertine** 或 **Helvetica**）。

一个程序会算出样式（以英寸为单位的宽度、字体及其字号、适合色盲读者的配色），然后由一个智能体就地修改你的脚本，修改前会先把每个脚本复制到它旁边（name.orig.py），并保留每张图原来的样子。之后每个脚本都会使用放在它们旁边的同一个样式文件 `paper.mplstyle`；每张图都保存为矢量 PDF，并检查其中的字体：全部嵌入，没有 Type 3 字体，因为很多会议/期刊不接受这种字体。它会运行你的脚本，所以这台电脑上需要具备脚本所需的环境（Python、matplotlib 和它们的数据）。

它的视图里有**修改前后**（它用的尺寸、字体和颜色，然后是每张图修改前和现在的样子，附有**打开 PDF** 和有哪些变化）、**样式文件**（`paper.mplstyle`，带有**复制**和使用方法）和**有哪些变化**（每一处修改，以及字体检查的结果）。

你会话中的智能体也掌握这些本领，它们来自 Hydor 自带的技能（**peer-review**、**reproduce-paper** 和 **figures-for-papers**：参见[技能](/guide/skills)）：你可以请其中一个陪你审阅论文、回复某一位审稿人，或者修改某一张图，它的工作方式是一样的。

## 运行实验室的工作

在 [应用](/apps) 页面的 **实验室** 下，有三个现成的应用，帮你处理实验室的日常工作：标注数据并对照你的标注检查模型，从假设到报告在你自己的代码上验证一个想法，以及调整模型的参数。冲刺和扫描都在 [实验](/guide/experiments) 中运行任务，所以需要有一台带 GPU 的电脑（或集群）。

### 标注工作台

**标注工作台** 让你和模型对同一批抽样文本分别标注，这样你能看到双方在哪里有分歧，以及模型在其余文本上能被信任到什么程度。从 **应用** 中打开它，然后填写：

- **标签**，用逗号分隔：最多九个，分别对应 1 到 9 的按键。**如何标注**：用你自己的话写下标注准则，模型也会按它来标注。
- 文本：**CSV 或 JSON 行文件**、按名称（如 stanfordnlp/imdb）或地址给出的 **hugging Face 数据集**（有多个划分时填写 **数据划分**，配置写在斜杠前面，如 plain_text/test），或者粘贴文本，一行一条。**文本所在的列** 会自动识别（名为 text、review 或 sentence 的列，否则取文本最长的那一列）：识别有误时，请自己指定。
- **标注数量**：随机抽取，默认 100 条，最多 1,000 条。

它会读取文本（数据集通过 Hugging Face 的 datasets 服务器读取，从随机位置取几页数据），按随机顺序抽样，并让辅助模型每次标注二十条，每条附上简短的理由。之后在这次运行的页面上进行操作：

- **标注**：一次一条文本，每个标签对应一个大按钮。点一个按钮，或按它的按键（**1** 到 **9**）：只有这时才会显示模型的标签，出现在下一条文本上方的一行里（有分歧时还会附上理由），这样它不会影响你的判断。**暂时跳过**（**S**）会把一条文本移到最后，**修改**（**Z**）会撤回上一条，备注（按 **N** 开始写）会跟这条文本保存在一起。进度条显示你已经完成多少。
- **分歧**：你和模型标注不一致的每条文本，你的标签和备注与模型的标签和理由并排显示。**重新标注** 会把它送回 **标注**。
- **一致率**：你们给出相同标签的频率、Cohen's κ（扣除纯靠运气也会有的一致后的一致程度：1 为完全一致，0 不比碰运气好，高于 0.6 为相当一致）、纯靠运气会得到的一致率，以及混淆矩阵：纵向是你的标签，横向是模型的标签。
- **导出**：**CSV** 或 **JSON 行** 会下载你标注过的文本，每条带有你的标签、模型的标签及其理由，以及你的备注。**发布到 Hugging Face** 会在那里创建一个属于它自己的数据集（除非你选择 **所有人**，否则为私有），其中有数据和一张说明标注方式的卡片，包含你的准则以及你和模型的一致程度。这需要一个有写入权限的 Hugging Face 令牌：应用其他功能不需要它，所以你第一次发布时会提示这一点；可以把它填在应用表单下方（**Hugging Face 令牌**，标为可选），或在 **应用 → 已连接的应用 → 密钥** 中以 HF_TOKEN 添加。**删除其中的文本** 会删除一组数据中的文本和标签。

每一组数据都是一次独立的运行，并把它的文本和你的标注作为应用的记录保存下来：应用页面会在最近的运行中列出你的各组数据，点开任何一组都会回到你上次停下的地方。

### 研究冲刺

**研究冲刺** 会在你自己的代码上，让一个研究问题经历一次简短的冲刺，每一步都由你批准。填写 **你的研究问题**、**仓库**（你电脑上的一个 Git 仓库；默认使用你上次填写的那个）、**它需要知道的**（重要的指标、基线及其数值、如何训练和评估、哪些内容不能改）、**可用的 GPU 小时数**（默认 8，为它所有运行的总和）和 **假设数量**（一到五个）。你在“关于你”中保存的 **你能在什么上运行** 会传给提出假设的模型和规划运行的智能体，让方案适合你的机器。然后：

1. 辅助模型根据你的问题和仓库的 README 提出假设，每个假设都写明什么结果支持它、什么结果反驳它，以及用哪个实验来检验。接着像 Gap finder 检查想法那样，逐个检查是否已有相关研究，并附上最接近的已有工作；已经为人所知的假设会注明。
2. 勾选了 **每一步都让我批准** 时（默认勾选，除非你取消），运行会等你处理：保留这些假设，或者写下你想检验的假设来替换，一行一个。每个假设下面是找到的最接近的已有工作。这个提问会出现在运行页面、你的收件箱和一条通知里。
3. 智能体会在仓库旁边，为一个新分支（sprint/…）创建一个工作树，与你的检出目录分开，它绝不会改动你的检出目录。它在那里写下计划（SPRINT.md）和运行所需的代码，提交它们，并列出各次运行：一个基线，加上每个假设的运行，带有随机种子。会超出你 GPU 小时数的运行会被剔除，并注明名称。
4. 在花费任何 GPU 时间之前，它会再次等你：开始运行，或者拒绝，冲刺就停在这里（计划和代码留在该分支上）。
5. 实验 会运行它们，并标上这次冲刺的标记，冲刺会等它们全部结束。
6. 结果表把每种条件与基线做比较，并给出显著性；智能体在一个 Jupyter 笔记本中分析这些运行，笔记本保存在项目的文件里，它会判定每个假设（得到支持、未得到支持或不确定，并附证据），并写出一份简短的报告。
7. 每个假设都会保存为项目的一条[研究发现](/guide/memory#findings-what-was-tried-and-what-came-of-it)（支持、推翻、不明确，未检验的则为待定），以它的运行和冲刺分支作为证据，让以后的会话知道尝试过什么。

它的视图包括 **冲刺**（问题、进展情况、分支，以及每个假设的结论、证据和最接近的工作）、**运行记录**（结果表，以及每次运行及其指标）和 **报告**（供阅读和复制，附 **打开笔记本** 和下一步建议）。通过 API 或定时任务运行时，没有人在场批准，所以它会一路执行到底。

### 参数扫描规划

**参数扫描规划** 会在预算内为一个训练脚本规划超参数扫描，启动它，提前停止表现差的试验，并写出哪些因素最重要。填写 **脚本或命令**、**它的文件夹**（默认使用你上次填写的那个；你在“关于你”中保存的 **你能在什么上运行** 会传给规划扫描的智能体）、**指标**（按脚本打印或写出的形式：metric=value 行，或 JSON）和 **哪个方向更好**、**要调的参数**（一行一个，附上要尝试的值，如 lr: 1e-4, 3e-4, 1e-3；留空则从脚本中找出）、**预算**（运行次数或 GPU 小时数：“20 次运行”“10 GPU 小时”）以及 **提前停止表现差的试验**。

- 智能体会读取脚本，但不运行也不改动它：看它的参数、一次运行要多久，以及表现差的运行何时能看出来。它提出要尝试的参数和值（你给了就用你的），再由一个程序把它们配合预算：能放得下就取每一种组合，否则在允许的数量内随机抽取。
- 勾选 **先让我检查计划** 时，运行会等你：按原样开始，或者写下修改，每个参数一行（lr: 3e-4, 1e-3 表示换用其他值，drop dropout 表示去掉某个参数）。
- 实验 把这次扫描作为一个实验运行；启用 **提前停止表现差的试验** 后，明显比目前最好的结果差的运行会被停止，以节省它的 GPU 时间。
- 运行结束后，一个程序会找出最佳运行，以及每个参数的影响有多大（它的取值能解释各次运行间指标波动的比例），辅助模型会说明这意味着什么以及接下来可以尝试什么。

它的视图有 **结果**（最佳运行的参数和指标、发现的内容、接下来可以尝试的事，以及每个参数权重的条形图）、**按参数**（每个参数各个取值对应的指标，以箱形图显示）和 **所有运行**。

## 报告：你的一周和你的实验记录本

在 [应用](/apps) 页面的 **工作** 下，有两个现成的应用，根据 Hydor 所了解的你的工作，把你做过的事写成文字：你的会话（这里的会话，以及 Hydor 读取的 VS Code 或终端中的 Claude Code 和 Codex 会话）、你在会话工作过的 Git 仓库里的提交、你的 实验 运行、你创建或保留的内容，以及你在阅读列表中标为已读的论文。关闭了记忆的会话和机密会话不会计入，智能体为任务的某些部分启动的会话所做的工作也不单独计入（算在它们的上级会话里）。两者都在各自的页面中打开，并且可以自动更新。

### 每周进展报告

**每周进展报告** 把你的一周变成给导师、团队或经理的更新：完成了什么、带数字的结果、问题和阻碍你的事、下周计划，以及要问的问题。它在自己的页面中打开，显示本周的报告（截至撰写当天的七天）：标题和摘要、数字里的这一周，然后是 **本周完成**、**结果**、**问题与阻碍**、**下周** 和 **问题**。

- **复制为 Markdown** 和 **复制为邮件**（一行主题，再加一段开头和结尾都像你自己写的简短说明）会把它放到你的剪贴板；**保存为文档** 会把它保存为文档，可以修改并导出为 Word 或 PDF。
- **更新** 会立即写出本周的报告。其下的 **更早** 列出之前各周的报告，点一下即可打开。
- **设置**，位于顶部的滑块：**自动更新**（打开前为关闭状态）会在每周五 16:00 写一份新的；开关下面可以选择其他日期（**每天**、**每个工作日**、**每周一次**选某一天）和时间。它是一个 [定时任务](/guide/tasks)，所以 [设置 → 定时任务](/settings?s=tasks) 中也会列出它。再往下是：**面向谁**（你的导师、团队或经理：它会按他们的需要来写）、**项目**（全部，或按名称选择部分）和 **包含哪些内容**（“只写研究，不写费用”）。

### 实验记录本

**实验记录本** 为你工作的每一天保存一条带日期的记录：尝试了什么、发现和决定了什么、还有什么悬而未决，并附有当天的会话、提交、运行、文件和保留内容的链接。它的记录是应用自己的记录，与 [记忆](/guide/memory) 分开保存。它在自己的页面中打开，并按从新到旧列出这些记录：

- **搜索记录本** 按字词和含义（[按含义搜索](/settings?s=memory&find=Search%20by%20meaning) 打开时）查找记录，最相关的排在最前；**全部记录** 会把它们全部找回来。
- 每条记录下方的 **复制链接** 会复制它自己页面的地址，页面显示的是这条记录写成时的样子：可用于在论文、报告或备注中引用。
- **更新** 会立即写出今天的记录，**补写之前的某一天** 则补写你错过的某一天。重新写过的一天会取代原来的记录；你什么都没做的一天不会有记录。
- **设置**：**自动更新**（打开前为关闭状态）会在每晚 21:00，按你选的日期和时间写出当天的记录；**项目** 可以把它限定在某些项目。
- **你的语言**：记录是你自己的笔记，所以用你使用 Hydor 的语言来写。每周报告则不同：它是发给你的导师或团队的，会保持你工作所用的语言。
