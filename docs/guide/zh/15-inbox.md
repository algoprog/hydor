# 收件箱与通知

智能体会自己完成工作，但有时也需要你：一次批准、一个回答、一张表单、一个密钥，或者在某些内容发出之前等你确认。本主题介绍收件箱、其中的发件箱，以及通知。收件箱把来自所有会话和所有机器、正在等你处理的事项汇集起来，让你在一处统一回应；发件箱存放等你确认的调用；通知会在会话完成、失败或需要你时告诉你，无论是在应用内、在你的电脑上，还是在应用已关闭的手机上。

![收件箱：来自所有会话、正在等你处理的事项](images/inbox.webp)

## 打开收件箱

收件箱就是栏上的 **收件箱** 图块，带有托盘图标，位于 **实验** 的正下方，**搜索** 在它下面（拖动其他图块时，它们仍会留在原位）。图块角上的数字表示有多少事项在等你。在手机上，先用 **菜单**（≡）打开侧边栏：这个按钮在抽屉的顶部。你也可以在搜索框中输入“收件箱”（Ctrl+K，Mac 上为 ⌘K）。[打开收件箱](/inbox)。

它的标题会告诉你有多少事项在等你（“3 项等你处理”）。最新的排在最上面。随着会话开始或停止等待，列表会自动更新，你查看时每隔几秒还会再检查一次。

没有待处理事项时，会显示“没有事项在等你”。

起始页也会显示在等你处理的事项，首先是消息框下方的 **你不在时**，其中列出自你上次访问以来已完成的事项和自动运行的事项（参见[你不在时](/guide/start#while-you-were-away)）。

## 收件箱中会显示什么

所有智能体在等你处理的事项，来自这台机器上的每个会话（包括定时任务和应用启动的会话），也来自你的其他机器：

- **批准**：智能体想运行的命令、想修改的文件、想使用的工具。
- 智能体向你提出的**问题**，以及等你批准的**计划**。
- 服务在中途请你填写的**表单**（“Notion 请你填写一张表单”），或它请你打开的页面。
- **需要你操作的浏览器**：“需要你在浏览器中操作：…”（登录或通过验证），“在付款或下单前停下：…”，或“想打开 …，在这台机器上或其网络中”。
- **智能体索要的密钥**：“索要密钥：OPENWEATHER_KEY”，并附上需要它的原因。
- **智能体建议的技能**：“建议新建技能：…”或“建议修改 … 技能”，并附上理由。
- **在别处等你的会话**：“在 VS Code 中等你”（或在终端中），针对在应用之外运行的会话。
- **应用的问题**：你的某个应用运行到 **问一个人** 步骤时在等待。
- **来自你分享过项目或内容的人的评论**：“Maria 评论了“论文第 3 章””，附上对方写的内容，直到你或智能体回复，或评论被标记为已解决。**打开** 会打开该文档、图片、视频或声音。
- **发件箱中等待的调用**：智能体调用了你设为 先问我 的已连接账户的工具，例如发送电子邮件的工具。它们排在最前面，位于 **发件箱** 之下。

每个事项都会显示它在哪个会话中等待（带智能体的图标），以及已经等了多久。

## 直接在收件箱中回应批准、问题和表单

批准、问题和表单显示为与会话中相同的卡片，因此你无需打开会话就能回应。每张卡片上方是会话的名称，点击它可打开该会话。卡片的第一行说明被问到的内容以及已经等了多久。

- **批准** 会显示智能体想做什么：命令、对文件的修改（以差异形式）或工具的输入。点击其中一个按钮：**允许**、智能体提供的“始终”选项（例如 **在此会话中允许所有编辑** 或 **在此会话中允许**），或 **拒绝**。点击 **拒绝…** 会先打开一个框，“可选：告诉智能体改做什么”；你可以给智能体写几句话，然后点击 **拒绝**。
- **计划**（来自 Claude Code）会显示计划内容，以及 **批准，自动接受编辑**、**批准，编辑前先询问** 和 **继续规划**。
- **问题** 会显示它的选项：选一个（允许时可选多个），或在 **其他——输入你自己的答案** 下输入你自己的回答；你可以为回答附上文件。然后点击 **发送回答**，或 **跳过**。
- **来自服务的表单** 会显示服务的消息和它的字段。填写后点击 **发送**，或 **拒绝**，或 **暂不**。没有需要填写内容的表单会询问 **允许**，而不是 **发送**。当服务请你打开页面时，**打开** 会在新标签页中打开它。

回应之后，该事项会离开收件箱，智能体继续工作。各选项的含义详见[批准或拒绝智能体想做的事](/guide/sessions#approve-or-deny-what-the-agent-wants-to-do)和[回答问题并批准计划](/guide/sessions#answer-questions-and-approve-plans)。

## 发件箱：等你确认的调用

当智能体调用你设为 **先问我** 的已连接账户的工具时（[已连接的应用、密钥和工具](/guide/connections#ask-first-calls-that-wait-for-your-ok)），这次调用不会被执行。它会在收件箱顶部、**发件箱** 之下等待，每个调用一张卡片，直到你发送或丢弃它。智能体不会等你：它会立即得知这次调用正在等你确认。

每张卡片会显示：

- 账户和工具（“Gmail · send_email”），以及已经等了多久；
- **等你确认**、智能体的图标和它来自的会话（点击会话名称可打开），以及当调用由某个任务的运行发出时，对应的定时任务；
- 这个工具的作用，用服务自己的话说明；
- 以可修改的表单显示的调用内容。电子邮件显示 **到**、**抄送**、**主题** 和 **正文**；聊天消息显示发往的位置及其 **文本**；帖子显示其 **文本**。其他工具显示它们自己的字段，工具必需的字段带有红色 *。多个地址放在同一个字段中，用逗号分隔。

然后：

- **发送** 会按表单当前的内容发出调用。即使智能体早已结束，Hydor 也会自己发出。卡片离开收件箱，并有通知说明已发送。
- **丢弃** 会放弃这次调用：它永远不会被执行。
- **全部发送**，在包含多个调用的会话的卡片上方，会按原样、按它们被搁置的顺序全部发送。

如果服务返回错误，卡片会保留，并显示 **没有发出：** 和原因，以及 **重新发送**。被搁置的调用在重启后仍会等待，并保留 30 天。

在会话中，有一行标出调用被搁置的位置：**在发件箱中等你确认**，并带有 **打开发件箱**。你做出决定后，它会显示 **经你确认后已发送**，并附上服务回答的开头部分，或 **已丢弃：没有发送**。当你再次向会话写消息时，它的智能体会得知其调用的结果。

被搁置的调用会像批准一样通知你，在应用内、在你的电脑上和在你的手机上：“在发件箱中等你确认：…”。点按它可打开收件箱，你可以在那里阅读草稿、修改它，并在手机上发送。

## 在等待的地方处理其余事项

其他事项在它们等待的地方回应。每个事项都有一个图标、被问到的内容、一行详情、会话和时间，以及 **打开**，它会带你到那里：

- **需要你操作的浏览器** 会打开会话，它的浏览器显示在消息框上方，供你接管（[搜索与浏览器](/guide/web)）。
- **密钥** 或 **登录** 会打开会话，并显示用于输入它的卡片（[已连接的应用、密钥和工具](/guide/connections)）。
- **技能建议** 会打开会话，并显示用于批准或拒绝的卡片；如果该会话已不存在，则打开 **设置 → 技能库**（[技能](/guide/skills)）。
- **在 VS Code 或终端中等待的会话** 会在这里打开，让你看到它在等什么；请在它运行所在的程序中回应。
- **应用的问题** 会打开它的运行，那里有一张卡片在询问：**是** 或 **否**，或它的表单和 **发送回答**（[应用](/guide/apps#apps-with-steps)）。

## 在你其他机器上等待的事项

如果你添加了其他运行 Hydor 的机器（[在一个应用中使用其他机器](/guide/devices#use-other-machines-from-one-app)），收件箱会询问每台在线的机器，并同时列出那里等待的事项。列表随后按机器分组，显示在每台机器的名称之下；**当前显示** 标出应用此刻正在显示的机器。你可以直接在这里回应来自其他机器的批准、问题和表单，就像回应这台机器的一样。

无法发送其列表的机器（例如运行旧版本的机器）会显示为一行，“那里有 2 个会话在等你”，并带有 **打开**，可前往那台机器。

## 收件箱按钮上的数字

收件箱按钮角上的小数字统计等你批准或回答的会话数：包括这台机器，以及你其他在线的机器。超过 99 时显示 **99+**。将指针停在按钮上，会显示“收件箱：3 项等你处理”。

这个数字统计的是会话，而不是事项，所以有两个批准的会话只算一次。发件箱中被搁置的调用每个算一次。收件箱中有些事项不会计入：索要的密钥、需要你操作的浏览器、待审阅的技能。

## 浏览器标签页中的数字

当应用所显示的机器上的会话在等你批准或回答时，浏览器标签页的标题会以它们的数量开头：“(2) Hydor”。你在其他标签页中也能看到，无需切换回来。

## 应用如何通知你

当会话完成、失败或需要你时，应用会以适合你当前所处情形的方式通知你：

- **应用在视野内**：屏幕底部（电脑上在右下角）会滑入一张小卡片。它显示智能体的图标和一个彩色圆点（完成为绿色，需要你为琥珀色，失败为红色）、会话的名称，以及状态和回复的开头。点击它可打开会话，点击 ✕ 可关闭。它会在几秒后消失，但指针停在上面时会一直保留。关于同一会话的较新通知会取代较早的卡片。
- **应用在你没有查看的标签页中打开着**：来自你系统的通知，前提是你已开启 **通知此设备**。
- **应用已关闭**，或手机在你的口袋里：推送通知，前提是你已在那台设备上开启 **通知此设备**。
- **桌面应用（Mac、Windows、Linux）**：你电脑自己的通知（在 Mac 上位于通知中心），无论应用的窗口在最前面、在其他窗口后面还是已关闭（应用会留在菜单栏、通知区域或系统托盘中），以及应用在登录时启动但没有打开窗口时也一样。点击它可在应用的窗口中打开那个会话。关于同一会话的较新通知会取代较早的通知。只有当你的系统没有显示应用的通知时，窗口内的小卡片才会显示。当窗口不在眼前时（已关闭、隐藏、最小化或在其他应用后面），应用的图标还会统计有新通知的会话，每个只算一次：Mac 上是 Dock 图标上的数字，Windows 上是任务栏按钮上的数字（窗口打开时；关闭到通知区域后没有任务栏按钮），在显示计数的 Linux 桌面（例如 Ubuntu 的 Dock 和 KDE）上是启动器上的数字。即使开启了勿扰模式或专注模式它也会显示，并在你把窗口带到最前面时立即消失。在 Mac 上，只要 Hydor 可以在其图标上显示标记，它就会显示：**系统设置 → 通知 → Hydor → 标记应用图标**（允许 Hydor 的通知后默认开启）。

你不会收到关于此刻正在查看的会话的通知。只有当它启动的所有内容都不再运行时，会话才算完成：当它的后台任务（例如开发服务器这样的命令、监视器）、它的子智能体，或它启动的作业仍在工作时，通知会等待，直到它们结束才会出现。你暂停提醒的会话，如果需要你，会立即从暂停中返回。在免提模式下，应用还会在它跟随的会话完成或需要你时大声说出来（[文档、图片、视频和语音](/guide/documents-voice)）。

## 每条通知说了什么

通知的标题是会话的名称（名称过长时会被截短）。正文说明发生了什么：

- **已完成**，后面是智能体最后一条回复的开头。只有一轮对话耗时至少十秒才会发送，所以简短的来回交流不会打扰你。
- 当会话需要你时，会说明它需要什么：
  - 对于简单的“是或否”批准，会写出智能体想做的事，以及它的第一行（“运行命令：npm test”）；
  - 其他情况显示“需要你的批准”或“有一个问题要问你”；
  - 对于它的浏览器，会说明浏览器需要什么：“需要你在浏览器中操作：…”“在付款前停下了：…”“请求打开 …”或“网页询问：…”；
  - 对于在 VS Code 或终端中的会话，显示“正在 VS Code 中等你”，只有在一分钟后它仍在等待时才会发送（因为你很可能就在旁边）；
  - 对于被扣在发件箱中的调用，显示“在发件箱中等你确认：”，以及账户、工具和发送对象。点按它会打开收件箱。
- **失败**，后面是错误信息。

为一个目标工作的会话，会在每件需要你处理或让它结束的事情上各发一条通知，而不是每一轮之后都发一条“已完成”（[目标](/guide/goals)）。只有在目标正在进行时才会压下“已完成”通知，等你处理时则不会：

- “目标的检查项已准备好，等你查看”，表示智能体已提出检查项，正等你点击**开始**；以及“有一项检查无法运行：…”，说明是哪一项以及原因，表示点击**开始**时发现有检查项无法运行；
- 智能体的提问，表示它在问下一步该走哪条路；“目标需要你：…”，表示它被只有你能提供的东西卡住了；以及“目标需要你：“…”是否成立？”，表示有一项检查只有你能确认；
- “目标在等待：会话的队列已暂停：请在那里点按“继续””，表示有消息在一个被搁置的队列中等待；
- “目标已暂停：…”并附上原因。以下情况会带通知暂停：消息无法发送；文件无法保存（在测量之前、在某一轮检查之前，或在恢复它们之前：“…所以第 4 轮没有被撤销。继续以再次检查。”）；恢复某一轮的文件没有完成（“恢复第 4 轮的文件没有完成，所以文件可能只恢复了一部分。文件夹中原有的一切都已保存：在第 4 轮上点“仍然保留…”可以找回它。继续会从文件当前的状态接着进行。”）；由于会话在检查运行期间一直在文件夹中工作，某一轮连续三次无法检查（“第 4 轮无法检查：… 继续以再次检查。”）；一项已通过的检查无法再运行（““测试通过”无法运行：…””）；最终检查无法运行（“无法联系到审阅者，所以最终检查没有运行。继续以再试一次。”）；智能体在你的套餐用量上限处停下，而应用不会自动让它继续；应用重启第二次打断了智能体的一轮；或者应用在循环的一条消息正要发出时重启，而再次发送也没有成功（“循环的消息没有送达智能体…”）。你自己按下的暂停、在你停止智能体之后的暂停（“你停止了智能体。”）以及一轮失败之后的暂停，只会显示在状态栏中，不发通知；
- “目标在达到上限时停止：…”，并说明上限（“已运行完 12 轮”“已花费 $10.00，共 $10.00 的额度”）；
- “目标已达成：…”，并附上目标内容；
- “目标未能设定：…”，表示你用**目标**启动的会话无法拥有目标（Hydor 子智能体、计划模式、没有可作为目标的消息）。

定时任务的运行会用智能体写的一行话说明进展如何。没有新内容可报告的运行不会打扰你，失败的运行一定会通知你，被阻止的运行显示为“已阻止：…”，连续失败后被暂停的任务也会这样说明（[定时任务](/guide/tasks)）。

来自你其他机器的通知会通过这台机器送达，所以一台设备就能收到所有机器的消息：通知的正文以机器名称开头，应用中的卡片会写明“在”那台机器“上”。

## 为这台设备开启通知

[设置 → 应用 → 通知](/settings?s=notifications)的**这台设备**分组中有两个开关和一个测试。开关在每台设备（每个浏览器）上各自设置：

- [**通知此设备**](/settings?s=notifications&find=Notify%20this%20device)：当会话完成、失败或需要你回答时发出通知，即使应用已关闭。开启时会向浏览器请求显示通知的权限。每台设备各自开启：你的手机和电脑要分别开启。在桌面应用（Mac、Windows、Linux）中它始终开启：应用运行期间，即使窗口已关闭，通知也会以 Mac、Windows 或你的桌面环境的通知形式送达。在 Mac 上，macOS 会询问一次是否允许 Hydor 发送通知：请允许，并通过**系统设置 → 通知 → Hydor**选择通知的显示方式。当系统没有显示通知时，该行会说明，而在此期间通知会显示在应用内；它的 **(i)** 会告诉你在哪里允许（在 Windows 上是**设置 → 系统 → 通知**）。打开开关即可允许：系统设置会打开到 Hydor 的通知页面（在 Windows 上是设置 → 系统 → 通知），你回到应用后，会出现一条测试通知，表明通知可以正常工作。
- [**声音**](/settings?s=notifications&find=Sound)：应用打开时，每条通知都会伴有一声简短的提示音，会话完成时音调上扬，需要你或失败时音调下降。默认关闭；开启时会播放一次提示音。在桌面应用中，提示音只会随应用在窗口内显示的通知播放；系统通知会发出它们自己的声音。
- [**发送测试**](/settings?s=notifications&find=Send%20a%20test)（**试一试**这一行，在**通知此设备**开启后显示）：向每台已开启通知的设备发送一条通知。内容为“此设备上的通知可以正常工作。”，并在应用不在前台时显示，所以请切换到别处来查看。会有一条消息告诉你它发送到了多少台设备，或者显示“没有设备收到。”在桌面应用中，**试一试**一开始就会显示：**发送测试**会立即在这台电脑上显示一条通知，即使应用就在前台。如果系统没有显示，会出现提示“没有显示。请在系统设置中允许 Hydor 发送通知。”

在手机上设置的方法：

1. 在手机上打开应用。这需要通过 HTTPS 提供服务：[设置 → 应用 → 在手机上使用](/settings?s=phone)可以通过 Tailscale 私密地做到这一点，它的二维码会在手机上打开应用，接着进行下面的步骤（[通过 Tailscale 在手机上使用](/guide/devices#use-it-on-your-phone-with-tailscale)）。
2. 在 iPhone 或 iPad 上，先把应用添加到主屏幕（**分享** → **添加到主屏幕**），然后从那里打开。在此之前，该设置会提示这一点，且无法开启。
3. 打开**设置 → 应用 → 通知**，开启**通知此设备**。手机询问时选择允许通知。
4. 点按**发送测试**，然后离开应用，查看通知送达。

如果设置显示通知“已在浏览器设置中对此网站禁用”，请先在浏览器设置中为应用的地址允许通知，然后再开启。如果显示“此浏览器无法在这里接收通知”，说明浏览器无法在这个地址接收通知，通常是因为应用是通过普通 HTTP 而不是 HTTPS 打开的。

如果有一天开关又自己关了，说明浏览器的推送服务丢弃了这台设备：请重新开启。当手机关机或离线时，通知最多会为它保留一天。同一会话较新的通知会取代设备上较旧的通知。

要停止通知，请在那台设备上关闭**通知此设备**。

## 直接在通知中批准或拒绝

当会话在等待一个简单的“是或否”批准时（命令、文件更改或工具；不包括问题、表单或计划），它的通知会带有两个按钮，使用卡片自己的文字，例如**允许**和**拒绝**，前提是浏览器会在通知上显示按钮。

- 点按其中一个即可作答，无需打开应用。一条安静的通知会确认你的操作，例如“允许：运行命令”。
- 如果回答无法送出（浏览器已退出登录，或你已在别处回答过），会打开该会话，让你在那里回答。
- 点按通知本身可以打开会话；如果已有应用窗口打开，就会在那个窗口中打开。
- 桌面应用的通知没有按钮：点击通知即可打开会话，并在那里回答。
- 被扣在发件箱中的调用同样没有按钮，这样你可以先看清将要发出的内容：点按通知，然后在收件箱中发送。

来自你其他机器的批准也可以用同样的方式回答：回答会通过这台机器送达那台机器。

## 询问智能体

智能体可以读取有哪些事情在等你，也可以发送测试通知。但它们不能替你回答其他会话的批准。可以试试这些：

- “现在有什么在等我处理？最紧急的排在前面。”
- “哪些会话在向我要密钥，是做什么用的？”
- “我的发件箱里有什么在等待？在我发送之前把邮件读给我听。”
- “总结每个等待中的会话需要我做什么，每个一行。”
- “发送一条测试通知，让我确认手机能收到。”
