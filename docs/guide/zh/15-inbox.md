# 收件箱和通知

智能体会自己干活，但时不时也需要你：一次批准、一个回答、一张表单、一个密钥。本主题介绍收件箱和通知。收件箱把每个会话、每台机器上等你处理的事都收在一起，让你在一个地方统一答复；通知则会在会话完成、失败或需要你时告诉你：在应用里、在你的电脑上，或者在没有打开应用的手机上。

![收件箱：所有会话中等你处理的事](images/inbox.webp)

## 打开收件箱

收件箱就是侧边栏顶部、Naget Agent 名字旁边的那个托盘按钮。在手机上，先用**菜单**（≡）打开侧边栏：按钮就在抽屉的顶部。你也可以在搜索框（Ctrl+K，Mac 上是 ⌘K）里输入“收件箱”。[打开收件箱](/inbox)。

它的顶部会告诉你有多少事在等你（“3 个在等你”）。最新的排在最上面。会话开始或停止等待时，列表会自己更新；你看着它的时候，它每隔几秒还会再检查一次。

没有事情等你时，它会显示“没有等你处理的事”。

## 收件箱里会出现什么

这里有智能体在等你处理的一切，来自这台机器上的每个会话（包括定时任务和模板启动的会话），也来自你的其他机器：

- **批准请求**：智能体想运行的命令、想修改的文件、想使用的工具。
- 智能体问你的**问题**，以及等你批准的**计划**。
- 已连接的应用在中途请你填写的**表单**（“Notion 请你填写一张表单”），或请你打开的页面。
- **需要你的浏览器**：“需要你在浏览器中操作：…”（用于登录或通过某项验证）、“在付款或下单前停下了：…”，或“想要打开本机或其网络中的 …”。
- **智能体索要的密钥**：“请求密钥：OPENWEATHER_KEY”，并附上它为什么需要。
- **智能体建议的技能**：“建议一个新技能：…”或“建议修改 … 技能”，并附上理由。
- **在别处等你的会话**：“在 VS Code 中等你处理”（或在终端中），针对在应用之外运行的会话。
- **模板的问题**：你的某个模板的一次运行停在**问一个人**这一步，等你回答。

每一项都会显示它在哪个会话里等待（带有该智能体的图标），以及已经等了多久。

## 直接在收件箱里答复批准、问题和表单

批准请求、问题和表单显示为和会话里一样的卡片，所以你不用打开会话就能答复。每张卡片上方是会话的名称；点击它即可打开该会话。卡片的第一行说明要你做什么，以及已经等了多久。

- **批准请求**会显示智能体想做什么：命令、对文件的修改（以差异形式显示），或工具的输入。点击其中一个按钮：**允许**、智能体提供的“始终”类选项（例如**在此会话中允许所有编辑**或**在此会话中允许**），或**拒绝**。点击 **拒绝…** 会先打开一个框：“可选：告诉智能体改做什么”；你可以给智能体留一句话，然后点击**拒绝**。
- **计划**（来自 Claude Code）会显示计划内容，并带有**批准，自动接受编辑**、**批准，编辑前询问**和**继续规划**。
- **问题**会列出它的选项：选一个（允许时可以选多个），或者在**其他——输入你自己的答案**下面输入你自己的回答；回答里还可以附上文件。然后点击**发送回答**，或**跳过**。
- **已连接应用发来的表单**会显示该应用的消息和它的字段。填好后点击**发送**，或者点击**拒绝**或**暂不**。没有内容要填的表单显示的是**允许**，而不是**发送**。当应用请你打开一个页面时，点击**打开**即可在新标签页中打开它。

答复之后，这一项就会离开收件箱，智能体继续工作。每个选项的含义见[批准或拒绝智能体想做的事](/guide/sessions#approve-or-deny-what-the-agent-wants-to-do)和[回答问题和批准计划](/guide/sessions#answer-questions-and-approve-plans)。

## 在原处打开其余事项

其他事项要到它们等待的地方去答复。每一项都有一个图标、要你做的事、一行详情、所在会话和时间，还有**打开**，带你去那里：

- **需要你的浏览器**：打开会话，它的浏览器会显示在消息框上方，由你接手操作（[搜索和浏览器](/guide/web)）。
- **密钥**或**登录信息**：打开会话，里面有让你输入它的卡片（[连接、密钥和工具](/guide/connections)）。
- **技能建议**：打开会话，里面有让你批准或拒绝的卡片；如果那个会话已经不在了，则打开**设置 → 技能库**（[技能](/guide/skills)）。
- **在 VS Code 或终端中等待的会话**：在这里打开它，让你看到它在等什么；答复它要到它所运行的程序里去。
- **模板的问题**会打开它的运行，那里有一张卡片向你提问：**是**或**否**，或者它的表单和**发送回答**（[模板](/guide/templates#templates-with-steps)）。

## 你其他机器上等待的事项

如果你添加了其他运行 Naget Agent 的机器（[在一个应用里使用其他机器](/guide/devices#use-other-machines-from-one-app)），收件箱会询问每台在线的机器，把那里等待的事项也列出来。这时列表会按机器分组，放在各台机器的名称下面；**当前显示**标出应用此刻正在显示的那台机器。来自另一台机器的批准请求、问题和表单，你也可以就在这里答复，和这台机器上的一样。

无法发送列表的机器（例如运行着旧版本的机器）只显示为一行：“那里有 2 个会话在等你”，并带有**打开**，可前往那台机器。

## 收件箱按钮上的数字

收件箱按钮角上的小数字，统计正在等你批准或答复的会话：包括这台机器上的，以及你其他在线机器上的。超过 99 时显示 **99+**。把鼠标指向这个按钮，会看到“收件箱：3 项等你处理”。

这个数字统计的是会话，不是事项，所以有两条批准请求的会话只算一次。收件箱里有些事项不计入其中：索要的密钥、需要你的浏览器、待审阅的技能。

## 浏览器标签页里的计数

当应用所显示的机器上有会话在等你批准或答复时，浏览器标签页的标题会以它们的数量开头：“(2) Naget Agent”。你在其他标签页里也能看到，不用切换回来。

## 应用如何通知你

当会话完成、失败或需要你时，应用会根据你所在的地方，用合适的方式告诉你：

- **应用就在眼前**：屏幕底部（电脑上是右下角）会滑出一张小卡片。它显示智能体的图标和一个彩色圆点（完成时为绿色，需要你时为琥珀色，失败时为红色）、会话名称，以及状态和回复的开头。点击它可打开会话，点 ✕ 则关闭它。几秒后它会自己离开，但鼠标停在上面时会一直留着。同一会话有了更新的提醒时，会取代旧的卡片。
- **应用开在你没在看的标签页里**：只要你开启了**通知此设备**，就会收到系统发出的通知。
- **应用已关闭**，或者手机在你口袋里：只要你在那台设备上开启了**通知此设备**，就会收到推送通知。

你正在查看的会话不会给你发提醒。被你延后的会话如果需要你，会立刻结束延后回来。在免提模式下，应用还会在它跟随的会话完成或需要你时说出来（[文档、图片和语音](/guide/documents-voice)）。

## 每条通知说些什么

通知的标题是会话名称（太长时会截短）。正文说明发生了什么：

- **已完成**，后面是智能体最后一条回复的开头。只有在持续至少十秒的一轮之后才会发出，所以快速的一问一答不会打扰你。
- 会话需要你时，说明它需要什么：
  - 对于简单的“是或否”批准，说明智能体想做什么，并附上第一行（“运行命令：npm test”）；
  - 否则是“需要你的批准”或“有个问题要问你”；
  - 对于它的浏览器，说明浏览器需要什么：“需要你在浏览器中操作：…”、“在付款前停下了：…”、“请求打开 …”或“页面询问：…”；
  - 对于在 VS Code 或终端中的会话，是“在 VS Code 中等你处理”，只有一分钟后它仍在等待时才会发送（因为你很可能就在那边）。
- **失败**，后面是错误信息。

朝着目标工作的会话，在目标达成时会说“目标已达成：…”，停下时会说“目标需要你：…”或“目标已暂停：…”（[给会话设定目标](/guide/sessions#give-the-session-a-goal)）。

定时任务的每次运行，都会用智能体写的一句话说明运行得怎么样。没有新内容可报告的运行不会打扰你，失败的运行总会告诉你，受阻的运行显示为“受阻：…”，连续失败后被暂停的任务也会告诉你（[定时任务](/guide/tasks)）。

来自你其他机器的提醒会经由这台机器转来，所以一台设备就能收到所有机器的消息：通知正文以机器名称开头，应用里的卡片会注明“位于”那台机器。

## 为此设备开启通知

[设置 → 应用 → 通知](/settings?s=notifications)里有两个开关（每台设备、每个浏览器各自设置）和一个测试：

- [**通知此设备**](/settings?s=notifications&find=Notify%20this%20device)：会话完成、失败或需要你答复时发出通知，即使应用已关闭也会收到。开启时，浏览器会请求显示通知的权限。每台设备各自开启：你的手机和电脑要分别设置。
- [**声音**](/settings?s=notifications&find=Sound)：应用打开时，每条提醒都伴随一声简短的提示音：会话完成时音调上扬，需要你或失败时音调下降。默认关闭；开启时会播放一次提示音。
- [**发送测试**](/settings?s=notifications&find=Send%20a%20test)（在**试一试**这一行，开启**通知此设备**后才会显示）：向每台开启了通知的设备发送一条通知。通知的内容是“通知在这台设备上可以正常工作。”它只在应用不在眼前时显示，所以要先从应用切换走才能看到。随后会有一条消息告诉你它发送到了几台设备，或显示“没有设备收到。”

在手机上设置：

1. 在手机上打开应用。为此，应用必须通过 HTTPS 提供（[从其他设备访问应用](/guide/devices#reach-the-app-from-another-device)）。
2. 在 iPhone 或 iPad 上，先把应用添加到主屏幕（**分享** → **添加到主屏幕**），然后从那里打开它。在此之前，这个设置会提示你这一点，并且无法开启。
3. 打开**设置 → 应用 → 通知**，开启**通知此设备**。手机询问时，允许通知。
4. 轻点**发送测试**，然后离开应用，看着通知送达。

如果这个设置显示通知“已在浏览器设置中为此网站屏蔽”，请先在浏览器设置中允许这个应用地址的通知，再开启它。如果显示“此浏览器无法在这里接收通知”，说明浏览器无法在这个地址接收通知，常见原因是应用通过普通 HTTP 而不是 HTTPS 打开。

如果哪天这个开关又变成了关闭，说明浏览器的推送服务丢掉了这台设备：再开启一次即可。手机关机或离线时，通知最多会为它保留一天。同一会话的新通知会在设备上取代旧的那条。

要停止接收，在那台设备上关闭**通知此设备**即可。

## 在通知里批准或拒绝

当会话在等一个简单的“是或否”批准时（命令、文件修改或工具；不包括问题、表单或计划），只要浏览器能在通知上显示按钮，它的通知就会带两个按钮，用的是卡片上的原话，例如**允许**和**拒绝**。

- 轻点其中一个，就能在不打开应用的情况下答复。随后会有一条静默通知确认，例如“允许：运行命令”。
- 如果答复没能送达（浏览器已退出登录，或你已经在别处答复过），会话会打开，让你在那里答复。
- 轻点通知本身可打开会话；如果已经有一个打开的应用窗口，就在那个窗口里打开。

来自你其他机器的批准请求也可以这样答复：答复会经由这台机器送到那台机器。

## 问问智能体

智能体可以读取等你处理的事项，也可以发送测试通知。它们不能替你答复其他会话的批准请求。可以试试这些：

- “现在有哪些事在等我？最紧急的排在前面。”
- “哪些会话在向我要密钥？要来做什么？”
- “用一句话概括每个等待中的会话需要我做什么。”
- “发一条测试通知，我看看手机能不能收到。”
