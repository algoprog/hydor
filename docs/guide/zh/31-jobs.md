# 作业

“作业”页面把你的会话在后台运行的长时间工作集中在一处，并按标签分类，标签说明每项工作属于哪一类，例如实验、数据收集或构建：训练运行、建立索引、下载和子智能体。对每一项工作，你都能看到它已运行多久、进展到哪里、大约还剩多长时间、哪些在等待开始以及在等什么，还有已完成的工作是如何结束的。你可以在这里查看作业的输出并停止它，也可以让智能体把几件事依次运行。

![“作业”页面：四个汇总卡片、每个标签一个标签块，以及按标签分组、显示进度和剩余时间的进行中作业](images/jobs.webp)

## “作业”显示什么

点击侧栏中的 **作业**，或前往 [作业](/jobs)。在手机上，它位于抽屉底部的工具中。图标上的数字表示有多少个作业正在运行。

以下任何一项都算作业：

- 你的某个会话的后台任务：一条命令、一个监控（对日志或程序的监视），或智能体自身程序（例如 Claude Code）的子智能体。你在 Hydor 之外（在 VS Code 或终端中）运行的会话，其后台任务也会显示；
- 智能体作为作业启动的工作（见[智能体如何把工作放到这里](#how-agents-put-work-here)）；
- [实验](/guide/experiments)中正在运行或在队列中等待的一次运行；
- 一个 Hydor 子智能体，即由另一个会话为完成其部分工作而启动的会话，在它工作期间显示（见[子智能体](/guide/sessions#subagents)）。

顶部的四个卡片做了汇总：

- **正在运行** 和 **排队中**：有多少个作业在运行，多少个在等待；
- **全部完成**：所有这些工作预计何时完成，例如“约 2 小时 10 分钟后”。除非每个作业都还有预估时间，否则显示短横线，子智能体不计入，因为它们从来没有预估；
- **今天完成**：今天结束了多少个。旁边的“1 个失败”（或其他数量）可带你查看这些作业。

卡片下方是每个[标签](#tags)对应的标签块、项目菜单（**所有项目**，见[查看某个项目的作业](#see-one-projects-jobs)）和 **筛选任务** 输入框。在输入框中输入内容，只会显示名称、命令、会话、项目或标签中含有这些词的作业；没有匹配项时，**显示所有任务** 可让所有内容重新显示。再往下是 **进行中**、**服务器** 和 **已完成**，各自在有内容可显示时才会出现。卡片只统计标签、项目和筛选之后剩下的内容。正在运行的服务器不计入卡片，也不计入侧栏上的数字。页面会自动更新。

当没有任何作业在运行或等待时，你会看到“后台目前没有运行任何内容。”

## 进行中

**进行中** 包含正在运行和正在等待的作业，每个标签一张卡片；没有标签的作业放在最后一张卡片 **无标签** 中。卡片顶部显示标签、其作业中有多少在运行和等待（例如“3 个正在运行 · 1 个排队中”），并且在每个作业都有预估时，显示它们预计何时完成（“约 34 分钟后完成”）。当一张卡片中的所有工作都来自同一个会话时，该会话及其项目也会在这里标出，各行则不再重复。点击卡片顶部可将其折叠或再次展开；应用会在此浏览器中记住这一设置。在你筛选或选定了某个标签时，所有卡片都不会折叠。在没有任何作业带标签时，作业只是直接列出，不按标签分卡片。

每个作业占一行。它的图标表示类型（将鼠标指向图标可看到 **命令**、**监控**、**Claude Code 子智能体**、**Hydor 子智能体**、**实验运行** 或 **职位**），图标上的圆点表示其状态。名称旁边是其他标签；将鼠标指向名称可看到它的命令。名称下方是它的当前状况、启动它的会话以及它的[项目](#see-one-projects-jobs)（各为一个链接），还有它最后输出的内容。

点击某一行可打开[作业面板](#a-jobs-panel-and-stop)。其 **⋯** 菜单中有 **详情和输出**、**打开会话**（实验运行则为 **打开运行**）、**编辑标签…** 和 **停止**。

## 正在运行

正在运行的作业会显示已运行多久（“已运行 12 分 05 秒”）。当作业能报告进展到哪里时，会有一个带百分比的进度条；将鼠标指向进度条可看到作业自己的计数，例如“步骤 120/500”。当没有剩余时间可显示时，这个计数会显示在进度条下方。

### 剩余时间

在有依据时，该行会显示“约剩 1 小时 12 分钟”。应用会采用下列依据中它拥有的第一项：

1. 作业自己输出的剩余时间，许多进度条都会这样做；
2. 到目前为止它的进度推进的速度；
3. 智能体在启动作业时给出的预估；
4. 同一条命令在同一个文件夹中此前用了多长时间（前提是它在最近一周内顺利完成）。

将鼠标指向时间可看到采用的是哪一项；作业面板中也会说明。旁边的 **（猜测）** 表示这是个粗略的估计：只有一次进度读数、智能体的预估或一次早先的运行。当作业运行的时间超出预期时，会改为显示 **已超出预估时间**。没有任何依据时，则不显示时间。

## 排队中

排队中的作业尚未开始。它的那一行会说明原因：

- **正在等待** 和其他作业的名称：它们全部顺利完成后，它才会开始。点击名称可找到对应的行。被其他作业等待的作业会显示 **然后：** 以及接下来是谁；
- **队列中的下一个** 和队列的名称，或它的位置，例如“gpu 队列中第 3 位”：队列一次只运行一个作业，按到达顺序，涵盖你所有的会话。排在最前面的作业可能仍在等待另一个作业，它后面的也都要等待；
- **正在等待空闲的 GPU** 或 **正在等待空闲名额**：某次实验运行在等待空位（见[队列如何选择](/guide/experiments#how-the-queue-chooses)）。

当排在它前面的作业有预估时，它还会说明预计何时开始，例如“约 40 分钟后开始”。

对排队中的作业点击 **停止**，意味着它永远不会启动，等待它的作业也不会启动。如果被其他作业等待的某个作业失败或被停止，那么等待它的作业同样永远不会启动。

## 服务器

有些命令自己永远不会结束：开发服务器、Web 或 API 服务器、笔记本，或是会话留在后台运行的模型服务器。“作业”会根据命令识别它们，并把它们列在 **服务器** 下，显示各自已运行多久，不显示剩余时间。它们会一直运行，直到你停止它们，和其他命令一样使用 **停止**。它们不计入正在运行的作业，**时间安排** 视图也不包含它们。一旦某个服务器结束，它就会进入 **已完成**。

## 已完成

**已完成** 保留过去 7 天内结束的作业，最新的在前，每天一个标题：**今天**、**昨天**，然后是日期。你会看到最近的十个，**全部显示** 可显示其余的。每个作业都会说明它如何结束、何时结束以及用了多长时间：

- **完成**：顺利完成；
- **失败**，如有退出码则一并显示（程序结束时返回的数字；不是 0 就表示出了问题）；
- **已停止**：你或某个智能体停止了它；
- **从未启动**，以及原因，例如它等待的某个作业失败了；
- **结束时间**：在被加入“作业”时就已在运行的工作结束了，没有人看到它是否顺利。

当有作业失败时，把 **全部** 切换为 **失败**，即可只看这些。某一行 **⋯** 菜单中的 **从此列表中移除** 会移除该行，**清除** 会在询问后移除全部，包括被标签、项目菜单或筛选隐藏的那些。这只是整理列表：你的会话和实验运行都会保留。

## 标签

标签说明一项工作属于哪一类，例如 `experiments` 或 `data-collection`，这样你一眼就能看出正在运行什么，也可以一次只查看一类工作。标签从不表示项目或主题；每个作业旁边已经显示了你的会话和项目。一个作业最多有 3 个标签，使用小写字母，单词之间用连字符：“Data collection”会保存为 `data-collection`。第一个标签决定它列在哪里。

工作有九大类，几乎所有工作都能归入其中之一：

- `experiments`：训练、评估、参数扫描和基准测试；
- `data-collection`：爬取、抓取、下载、查询服务、标注或生成数据；
- `data-processing`：清洗、转换、索引和嵌入数据；
- `development`：编写或修改代码、文档或译文，以及审查它们；
- `builds`：构建、编译和打包；
- `tests`：测试套件、类型检查和代码检查；
- `deployment`：发布、上线和运行服务器；
- `analysis`：研究、报告、绘图和统计；
- `maintenance`：备份、清理和更新。

每项工作都单独打上标签：它从不沿用所属会话的标签，所以同一个会话的构建、测试和下载，各自归入各自的类别。你不必自己给任何东西打标签：

- 启动作业的智能体会给它打标签，只要工作符合，就会使用已在使用的标签，这样同一类工作会保持同一个名称。告诉智能体你想用哪个标签，它就会使用；
- [实验](/guide/experiments)的一次运行始终带有 `experiments` 标签；
- 其他没有标签的工作（会话的后台命令、其子智能体和服务器，以及未带标签启动的作业）由[辅助模型](/settings?s=models&find=Helper%20model)打标签，它会查看该项工作自己的名称、类型和命令，并从同样的标签中选择。它在后台完成这件事，所以这样的标签可能在工作出现片刻之后才出现。对[保密会话](/guide/sessions#keep-a-session-confidential)，它从不会被询问；环境变量 `HYDOR_JOBS_TAGGER=0` 可将它关闭。

大类标签有各自的颜色，无论在哪里显示都相同。

### 更改标签

你可以更改任何作业的标签，无论是谁打的标签。在作业的 **⋯** 菜单中选择 **编辑标签…**，或点击其面板中标签旁边的铅笔图标。输入标签并用逗号隔开，或点击 **可选标签** 下的标签（先是正在使用的标签，然后是大类标签），再点击 **保存**。对话框会说明到目前为止是谁给作业打的标签：“启动它的智能体给它打了标签。”“你给它打了标签。”“辅助模型给它打了标签。如有错误请修改。”，对于实验运行则是“实验运行会被打上 experiments 标签。”

保存一个空的输入框可移除你设置的标签。此后该作业没有自己的标签，辅助模型可能会再次给它打标签，如上所述。

### 查看某个标签

点击某个标签块，即可只查看列在它之下的工作：卡片、**进行中**、**服务器**、**已完成** 和时间安排都会随之变化。标签块上的数字是它的作业中正在运行或等待的数量。点击 **全部** 可再次查看所有内容；**无标签** 标签块显示[没有标签的工作](/jobs?untagged=1)。

你选定的标签是页面地址的一部分（地址末尾是 `?tag=` 加标签名），因此你可以将它加入书签，或发送到手机上。标签块按每个作业的第一个标签归类；要通过作业的其他标签找到它，请在 **筛选任务** 中输入该标签。

## 查看某个项目的作业

项目菜单位于 **筛选任务** 旁边。它显示 **所有项目**，或你所选项目的名称及其标记。打开它即可选择：

- **所有项目**：所有作业；
- 在这里有作业的某个项目；旁边的数字表示其中有多少在运行或等待；
- **不放在项目中**：不属于任何项目的作业。

卡片、**进行中**、**服务器**、**已完成** 和时间安排随后只显示这些作业。选择某个项目会让你回到标签块 **全部**，标签块及其数字只涵盖该项目的作业；点击其中一个，即可查看该项目内的这个标签。选定某个项目时，各行不再显示项目名称。一旦有作业属于某个项目，该菜单才会显示。

你选定的项目同样是页面地址的一部分（`?project=` 加其 ID，或 `?project=none`），因此你可以将它加入书签。某个[分组](/guide/projects#bring-projects-together-in-a-group)的作业包含它所汇集的各项目的作业。当某个项目有作业在运行或等待，或有服务器留在运行时，它自己的页面会在[概览](/guide/projects#overview)下显示它们。

作业属于其会话所在的项目。如果没有（它的会话不在任何项目中，或它没有会话，例如你从自己的终端启动的作业，或在“实验”页面上启动的运行），它就属于其所在文件夹所对应的项目。当一个项目的文件夹位于另一个项目之内时，内层的项目获得它。分组，以及文件夹是你的主目录或整个磁盘的项目，永远不会这样获得作业。作业面板会写明它的 **项目**。

## 时间安排视图

在右上角切换 **列表** 和 **时间安排**；应用会在此浏览器中记住你的选择。时间安排为每个正在运行或等待的作业沿着时钟画一条横条，名称前有一个其标签颜色的圆点。标签块、项目菜单和 **筛选任务** 对它的筛选方式与对列表相同：

- **目前已运行** 是实心的，**预计** 是其后的条纹部分；
- **排队中** 的作业是虚线，位于它们应当开始的位置；
- 带有 **无预估** 的横条会逐渐淡出；
- 标有 **当前** 的线表示此刻，细线把作业与等待它的作业连接起来。

超出预估时间的作业会变成琥珀色。将鼠标指向横条可看到其状态和时间，点击它可打开该作业的面板。在窄屏幕上，图表可横向滚动，名称保持不动。已完成的作业列在它的下方。

## 作业面板与停止

面板会在页面右侧打开（在手机上占满整个屏幕）。顶部是作业的名称、状态、标签，以及 **打开会话**（或 **打开运行**）和 **停止**。下面是目前已知的信息，例如它所属的会话、项目和文件夹，开始时间，还剩多长时间以及这一估计的依据，它在等待什么，以及它是如何结束的。再往下是它的命令，旁边有一个复制命令的按钮。

**输出** 显示作业已打印内容的末尾部分，作业运行期间每隔几秒刷新一次；除非你向上滚动，否则最新的几行会始终保持在视野中。对于子智能体，它会列出各个步骤。有些作业，例如 Hydor 子智能体和 Codex 的后台任务，在这里没有输出：请使用 **打开会话**。

**停止** 会先询问确认，然后结束作业：作业或命令会被停止，实验运行会像在它自己的页面上那样被停止，Hydor 子智能体的会话也会被停止。作业到目前为止已完成的工作会保留。在 Hydor 之外的会话中运行的工作，以及 Codex 的后台任务，无法在这里停止，所以它们没有 **停止**。

## 智能体如何把工作放到这里

你不需要做任何设置。会话启动的后台任务会自动显示在这里。应用启动的每个会话还有一个名为 `job` 的命令，并且智能体被告知在处理耗时较长的工作（超过约十分钟的任何工作）时使用它，这样这些工作就会显示在这里，带有名称、表示工作类型的标签、进度和剩余时间（参见[每个智能体都有的四个命令](/guide/agents#four-commands-every-agent-has)）。

用日常的话说出你想要什么，其余的交给智能体：

- **依次运行**：“在索引构建完成后运行评估”。第二个作业会等待第一个作业，如果第一个失败，它就不会启动；
- **一次一个**：“把这些参数扫描放进一个队列”。队列名称相同的作业会轮流运行；
- **预计耗时**：智能体可以给出自己的估计，在作业的进度提供更多信息之前，会一直使用这个估计；
- **工作类型**：“把这个爬取任务标记为 data-collection”。智能体还可以列出正在使用的标签，以及尚未使用的宽泛标签，并在之后修改任何作业的标签；
- **已在运行的工作**：“把你之前启动的训练显示在作业里”。智能体会把它加进来而不重新启动它（`job adopt`）；Windows 上不可用。它结束时会显示 **结束时间**，因为没有人能知道它结果如何。

当会话启动的作业仍在等待或运行时（无论是它用 `job` 运行的作业，还是它启动的实验运行），该会话就不算结束：它的圆点会继续呈蓝色呼吸状，状态显示“工作中 · 1 个在后台”，即使它的智能体已经停止也是如此，而它的 **已完成** 通知要等到作业结束后才会出现。消息框旁边的停止按钮不会停止这些作业：请在这里停止它们。

如果智能体启动作业时无法连接到应用，命令仍会照常运行，只是不会显示在这里。

## 向智能体提问

- “在索引构建完成后，把评估作为作业运行。”
- “把这个爬取任务标记为 data-collection。”
- “只显示正在运行的实验。”
- “我的 Thesis 项目里有什么正在运行？”
- “把你之前启动的训练显示在作业里。”
- “把这三个参数扫描放进队列，逐个运行。”
- “还有什么在运行，什么时候能完成？”
- “停止下载，改为把测试作为作业运行。”
- “上一次构建为什么失败？查看它的作业输出。”
