# The app's API

Everything the app's pages do goes through its HTTP API, and agents use the same API (with the app_api tool) to read the app's state and change it for you. This topic lists the endpoints by area, with what each takes and returns. It is written for agents and developers; you don't need it to use the app.

## How agents use it

- An agent calls an endpoint with **app_api** (`method`, `path`, `body`), as the signed-in user, inside the app itself. Reading (`GET`) runs at once.
- A change shows the user a card first, with what changes (before → after for a setting) and the call itself. Give `summary`, the change in a few plain words, as its title. The user can allow it once, allow such changes for the rest of the session, or say no. Deleting, starting agent work, adding MCP servers or machines, changing what agents may do and similar changes ask every time.
- To have the user fill in or check details on that card, give `form`: fields as a JSON schema's properties (`type`, `title`, `description`, `enum`, `default`, `format`…), each named by its address in `body` (`name`, `settings.results`), filled in from `body`; the user's answers go into `body` before the call.
- Read the current state before changing it: most settings are read with `GET` at the same address their `PUT` or `PATCH` writes.
- In Plan mode (and Codex's Read only) an agent only reads. With Claude Code's Bypass or Codex's Full access no card shows; Custom's Full access asks only for the changes that ask every time.
- Never through app_api: the password and signing in, keys' values (ask with request_secret), a signature's picture or any change to one (ask_signature and place_signature), making access tokens and API keys, answering approval cards and the cards that ask the user to decide, a session's permissions and spending cap, files, terminals, notebooks and git (agents use their own tools), the live browser (the browser tools), the Mac's screen, mouse and keyboard and macOS's permissions for them (the computer tools; the user allows those in Settings).
- Links for the user: the app's address plus the page: `/s/<session key>`, `/projects/<id>`, `/apps/<id>`, `/pages/<id>`, `/settings?s=<section>`, `/guide/<topic>#<section>`.

## Settings kept on each device

These live in the user's browser, one set per device, so they are not in the API. An agent changes them on the devices showing its session, with no card:

- `PUT /device` — Body: `{ theme?: 'dark'|'light'|'system', themeName?: string — a theme's name ("Midnight", "Sage", or one of the user's), language?: 'en'|'zh'|'el' — reloads the page, sound?: boolean — a chime with each notice, enter?: 'join'|'queue' — what Enter does while an agent works, terminalSuggestions?: boolean, sidebar?: boolean — shown on a computer, groupSessions?: boolean — the sidebar's groups for projects and folders (false: the sessions by day only) }`.

## The guide and Agent Guidelines

- `GET /api/guide` — the whole guide. Returns: `{ topics: [{ id, title, summary, body (Markdown), sections: [{ id, title, text }] }] }`. Agents read it with app_guide instead.
- `GET /api/guide/images/:name` — a picture in the guide (docs/guide/images), such as `projects.webp`. Query: `theme?` (`light`: its light version, when there is one). Returns: the image.
- `GET /api/guidelines` — Agent Guidelines: for every session, and a project's or a session's. Query: `key?` (a session key: its own guidelines, and its project's), `space?` (a project's id). Returns: `{ global: string, space?: { id, name, text }, session?: { key, text } }`.
- `PUT /api/guidelines` — changes the levels given, leaving the others. Body: `{ global?: string, space?: { id: string, text: string }, session?: { key: string, text: string } }` (each at most 20,000 characters; an empty text clears that level). Returns: the same as GET for that session and project. A changed session's agent follows the new guidelines from the next message.
- `GET /api/setup/instructions` — the instruction files Claude Code or Codex reads on its own for a session in a folder (CLAUDE.md, AGENTS.md and the like), in the order it reads them. Query: `agent: 'claude'|'codex'`, `cwd?` (the folder; the app's default when left out). Returns: `{ files: [{ path, scope: 'user'|'parent'|'project'|'local'|'rules', exists: boolean, size?, primary? }] }`. A file's text is read and changed with an agent's own file tools.
- `POST /api/setup/instructions` — creates one of those files where it is missing (with a title line). Body: `{ agent: 'claude'|'codex', path: string — one the GET lists, cwd?: string }`. Returns: `{ path }`.

## Conventions

- Session keys are `claude:<id>`, `codex:<id>` or `acp:<id>` (after the colon, 4 to 80 letters, digits, `.`, `_`, `-`); URL-encode them in paths (`claude%3A…`). Other keys get 400 "Bad session key".
- Times are Unix milliseconds. Errors come back as `{ error: string }` with an HTTP status (400 bad input, 404 not found, 409 not possible right now).
- Attachments, where a body takes them: `images?: [{ mediaType: 'image/png'|'image/jpeg'|'image/gif'|'image/webp', data: string (base64), name?: string }]` (at most 8 are kept) and `files?: [{ name: string, data: string (base64) }]` (at most 20; saved in the app's uploads folder and listed by path at the end of the message as "Attached files:").
- A `SessionSummary` has: `key, agent ('claude'|'codex'|'acp'), id, title, cwd, gitBranch, model, createdAt, updatedAt, firstPrompt, lastPrompt, stats { userMessages, turns, toolCalls, commands, filesChanged, linesAdded, linesRemoved, tokensIn, tokensOut, tokensCached, costUsd }, live ({ status: 'starting'|'idle'|'working'|'waiting'|'stopping'|'exited'|'error', model, effort, mode, pendingApprovals, contextTokens, contextWindow, backgroundTasks, goal } or null when the agent is not running), external ({ status, client, pid } when it runs in VS Code or a terminal), archived, pinned, order, snoozedUntil, doneAt, seenAt (unread when doneAt > seenAt), queue [{ id, text, at, att }], queueHeld, goal { objective, status: 'active'|'paused'|'blocked'|'limited' }, worktree { path, branch, base, repo }, pr { url, number, title, state, checks }, resumeAt, account, acpAgent, acpName, extra { memory, assistant, capUsd, parent, space, swarm, research, arena, confidential }, prefs { model, effort, mode }, forkFrom, handoffFrom, handoffTo`.
- **Careful** marks a route that, used on a session other than the one the agent is in, does something the user would not expect (spends money, sends words in their name, stops work, deletes, changes files or publishes). Use it on another session only when the user asked for exactly that.

## The app and the start page

- `GET /api/bootstrap` — what the pages load first. Returns: `{ version, home, dataDir, defaultCwd (the default folder), autoFolders: string[] (folders no one picks: where the app makes task folders, apps' runs and worktrees, its data folder and the temporary folder; the sidebar groups no sessions by them), folderNames: { [folder]: name } (folders Codex keeps projects in, by the project's name, such as a ChatGPT project's folder), folderOrigins: { [folder]: [{ agent, account?, sources: string[], sessions }] } (each folder two or more sessions worked in: empty when its first session was started in Hydor; else where its sessions from outside came from, by agent and added account, with the apps they were started in as the agent wrote them down, such as `claude-vscode` or `cli`, the most sessions first), host (machine name), start (the start page's last picks, as PUT /api/start), prefs { claude, codex } (each agent's last model/effort/mode/account), accounts [{ id, agent, name }] (added accounts), acpAgents [{ id, name, command, builtin }] (Custom is id 'console'), themes, update, tourSeen, indexing }`.
- `PUT /api/start` — changes what the start page opens with next time, on every device (merges: send only what changes; `null` clears a field). Body: `{ agent?: 'claude'|'codex'|'acp:<id>' (Custom: 'acp:console'), runs?: { '<agent key as above>': { model?: string|null, effort?: string|null, mode?: string|null, account?: string ('' = the agent's own sign-in) } } (joins that agent's earlier run; null = the agent's default), assistant?: string (assistant id: general, researcher, writer, coder, tutor, planner, analyst or your own), space?: string (a project's id), task?: boolean (true = a new task folder), cwd?: string (absolute path; left out on read if the folder is gone), worktree?: boolean, memory?: false|null (false = start without memory), capUsd?: number|null (> 0, ≤ 1,000,000) }`. Returns: the whole start settings after the change. Open start pages update at once.
- `GET /api/catalog/:agent` — an agent's models, permissions modes and commands. `:agent` is `claude`, `codex` or `acp` (then `?acp=<id>`, `console` for Custom; another ACP agent's lists are known only after it has run once). Returns: `{ models [{ value, label, isDefault, efforts: string[], defaultEffort, description, local? (Custom's: it runs on this computer or your private network) }], modes [{ value, label, description }], defaultMode, commands? [{ name, description }] (Claude Code's slash commands and skills), modeNote?, prefs }`. Mode values: Claude Code `default` (Ask), `acceptEdits`, `auto`, `plan`, `bypassPermissions`; Codex `plan`, `read-only`, `auto`, `auto-review`, `full`; Custom `ask`, `edits`, `auto`, `full`, `plan`.
- `GET /api/fs/recent?picked=1` — the folders the start page offers: up to 12 folders sessions worked in lately, newest first, without the ones Hydor made (task folders, app runs, worktrees). Without `picked=1`: up to 30 folders, those included. Returns: `{ dirs: string[] }`.
- `GET /api/git/repo-info?path=<folder>` — whether a folder is in a git repository (the start page then offers a worktree). Returns: `{ info: { repo, branch, sub } | null }`.

## Finding sessions

- `GET /api/sessions` — the session list, newest first, pinned first. Query: `agent?=claude|codex|acp`, `archived?=1` (only archived ones; default: only not archived), `limit?` (1–1000, default 300), `offset?`, `cwd?` (exact folder). Returns: `{ sessions: SessionSummary[], total }`. Child sessions are listed too; their parent is `extra.parent`.
- `GET /api/search?q=<words>` — the sidebar's session search: titles, first messages and folders, then the words said in messages. Archived sessions are included. Returns: `{ hits: [{ key, agent, title, cwd, updatedAt, kind ('title' or where the words were found), snippet (matches between \u0001 and \u0002), ts }] }`.
- `GET /api/find?q=<words>` — what the search box (Ctrl+K) asks the server (up to 300 characters). Query: `in?: string — places to look in, comma-separated (sessions, messages, spaces, pages, templates (apps), files, memory, tasks, assistants, skills, connections, settings, actions, guide); none: everywhere`. Returns: `{ meaning (search by meaning answered), sessions [{ key, agent, title, firstPrompt, cwd, updatedAt, score }] (by title, and by meaning when on), messages [as /api/search hits] (up to 10), notes [{ id, scope, scopeKey, kind, text, updatedAt }] (memory notes, when memory is on), alike [{ id, score }] (other things alike in meaning, by the search box's ids: go:<page>, sec:<section>, opt:<section>:<words>, app:…, task:…, asst:…, skill:…, page:…, conn:…, space:…) }`.
- `GET /api/find/scope` — where the search box looks: its **Search in** menu, the same on every device. Returns: `{ in: string[] }` (the places picked; empty: everywhere).
- `PUT /api/find/scope` — sets it; open search boxes change at once. Body: `{ in: string[] — the places to look in, from: sessions, messages (words said in sessions), spaces, pages, templates (apps), files, memory, tasks (scheduled tasks), assistants, skills, connections, settings (with themes), actions (the app's pages and actions: Go to, Actions), guide (Help); [] or all of them: everywhere }`. Returns: `{ in }` (in the menu's order). A name it does not know is refused (400).
- `GET /api/sessions/:key` — one session. Returns: `{ summary: SessionSummary|null, live, overlay { items, approvals [{ id, title, kind, detail, options [{ id, label }], questions? }] } }`. The approvals are what the session waits on the user for; agents must leave them to the user.
- `GET /api/sessions/:key/timeline` — the conversation, a page at a time. Query: `before?` (an item index; default the end), `limit?` (default 300, at most 2000), `whole?=1` (start the page at a turn's start). Returns: `{ items [{ id, seq, kind: 'user'|'assistant'|'tool'|'thinking'|'system'|'turn', ts, text?, tool? { name, category, title, status, output (shortened), files } }], total, start }`.
- `GET /api/sessions/:key/items/:id` — one timeline item in full (output and diffs not shortened). Returns: the item.
- `GET /api/sessions/:key/find?q=<text>` — your messages and the agent's that contain the text, any case (at least 2 characters; up to 500 matches), oldest first. Returns: `{ matches [{ seq, kind: 'user'|'assistant', snippet (match between \u0001 and \u0002) }] }`.
- `GET /api/sessions/:key/changes` — every file the session changed, the most changed first. Returns: `{ files [{ path, added, removed, edits [{ itemId, ts, change { path, op: 'edit'|'create'|'write'|'delete'|'move', added, removed, diff (cut at 60,000 characters: diffTruncated) } }] }] }`.
- `GET /api/sessions/:key/commands` — every shell command the agent ran, oldest first. Returns: `{ commands: [timeline tool items] }` (tool.title is the command, tool.status, tool.exitCode, tool.output shortened).
- `GET /api/sessions/:key/notes` — what the app added under turns (memory updates, second opinions, spending cap notes, child session cards). Returns: `{ notes [{ id, kind, at, anchor, data }] }`.
- `GET /api/commits/:key/show?hash=` — one commit an agent made in session `:key` (from a session note of kind "commits", whose `data.commits` lists `{ hash, subject, branch?, repo, own?, author?, at, files, added, removed }`). Returns: `{ hash, author, email?, ts, message, parents, refs, head, pushed, files: [{ path, added, removed, binary?, status?, from?, diff }] }`. 404 when the commit is not in one of the session's notes.
- `GET /api/sessions/:key/extra` — the session's settings beyond its agent's own. Returns: `{ extra { memory?, assistant?, capUsd?, parent?, space?, swarm?, research?, arena?, connections?, confidential? } }`.
- `GET /api/sessions/:key/tasks/:taskId/log` — a background task's latest output (Claude Code sessions only; task ids are in `live.backgroundTasks`). Returns: `{ kind: 'output'|'agent', text?, entries?, size?, truncated?, updatedAt }`.

## The inbox (read only)

- `GET /api/inbox` — everything waiting on the user on this machine, newest first: approvals, questions and forms in sessions, a browser that needs them, a key an agent asked for, a skill to review, sessions waiting in VS Code or a terminal. Returns: `{ items [{ id, kind: 'approval'|'question'|'form'|'browser'|'key'|'skill'|'elsewhere', title, detail?, key? (session), session? (its title), agent?, at, path (where it is answered in the app), approval? }] }`. Report these to the user; answering them is theirs to do.

## Starting sessions

- `POST /api/sessions` — starts a session, as the start page does; the agent begins on `prompt` at once. Body: `{ agent: 'claude'|'codex'|'acp', acpAgent?: string (required for 'acp': 'console' for Custom, or an id from Settings → More agents), prompt?: string, cwd?: string (an existing folder; `~` works; empty = the default folder), model?: string, effort?: string, mode?: string (a mode value from /api/catalog; default Claude Code 'default', Codex 'auto'), account?: string (an added account's id), worktree?: boolean (a new branch and folder; cwd must be in a git repository), title?: string, extra?: { assistant?: string, memory?: false, capUsd?: number, space?: string (a project's or a group's id: the session gets its guidelines; pass its folder as cwd and its assistant), connections?: { '<connection id>': true }, research?: { breadth (1–8), depth (1–5), queries (10–500), format: 'page'|'document' }, swarm?: true | 'campaign' (a swarm on a hard problem, or a campaign: one big change in parts, each member in a worktree; cwd must be in a git repository), arena?: { with: [{ agent, acpAgent?, model? }] } (up to 2 more models: each gets the same prompt in a session of its own), confidential?: true (a confidential session: agent 'acp' with acpAgent 'console', and a model `GET /api/confidential` lists, or none for the best of them; memory goes off; not with research, swarm or arena: 400), help?: true | string (a question asked on the Help page, or about the guide topic with this id: the agent answers from the guide, and the session's model, effort and mode don't become the agent's remembered defaults) }, images?, files?, paths?: string[] (files and folders already on this computer, up to 20: the message lists them by path under "Attached files", a folder with a slash at its end, and PNG, JPEG, GIF or WebP pictures up to 5 MB also go to the model to look at; paths that aren't there are left out) }`. Returns: `{ key }`. To start in a new task folder as the start page does, first `POST /api/assistants/task-folder { prompt }` → `{ path }` and pass that as cwd. The model, effort, mode and account also become that agent's remembered defaults. **Careful**: research, swarm and arena run several agents and cost several times as much; say so before using them.
- `POST /api/sessions/:key/fork` — a new session that starts with this conversation (all of it, or up to `at`), then `text`; the original stays. Claude Code, Codex and Custom only; not for a session open in another app (409). Body: `{ text: string (required, unless attachments), at?: string (Claude Code: a reply's `entry` id from the timeline; Custom: a turn id), images?, files? }`. Returns: `{ key }` (titled "<title> · fork").
- `POST /api/sessions/:key/handoff` — "Continue in …": a new session on another agent in the same folder, starting with this conversation (first request plus the latest messages within about 60,000 characters) and `text`. From Claude Code or Codex sessions only, to the other one or to Custom; never from a confidential session (400). Body: `{ agent: 'claude'|'codex'|'acp', acpAgent?: 'console' (required with 'acp'), text?: string (default "Continue where the conversation left off."), model?, effort?, mode?, account?, images?, files? }`. Returns: `{ key }`. The two sessions link to each other.
- `POST /api/sessions/:key/rewind` — "Edit from here": continues from just before one of your messages with new text, in a copy that takes the title; **the original is archived**. Claude Code, Codex and Custom; 409 "Stop the agent first" while a turn runs. Body: `{ itemId: string (a user message's id from the timeline), text: string (required), restoreFiles?: boolean (put the files back as they were before that message: Claude Code, Custom, or any session in a worktree; Codex needs a worktree) }`. Returns: `{ key }`. **Careful**: restoreFiles changes files on disk.

## Talking to a session

- `POST /api/sessions/:key/message` — sends a message now: into the running turn for Claude Code and Codex, or as a new turn; ACP agents (Custom included) queue it while they work. Starts the agent first if it is stopped (409 if the session runs in another app: use takeover). A reached spending cap refuses it. Body: `{ text: string, images?, files? }` (text or an attachment required). Returns: `{ ok }`. **Careful**: on another session this speaks in the user's name and makes that agent work.
- `POST /api/sessions/:key/queue` — adds a message to send when the running turn ends (sent at once if the agent is running, idle, and the queue is not paused; a stopped agent's queue waits until it runs again). Body: `{ text: string, images?, files? }`. Returns: `{ ok }`. **Careful** as for message.
- `POST /api/sessions/:key/queue/:id/send` — sends one queued message now, into the running turn (starts the agent if needed). Returns: `{ ok }` (404 if it already went out). **Careful** as for message.
- `POST /api/sessions/:key/queue/:id/edit` — changes a queued message. Body: `{ text: string, keep?: string[] (refs of attachments to keep, 'img:<n>'/'file:<n>' from queue[].att; leave out to keep all), images?, files? (new ones, with keep) }`. Returns: `{ ok }`.
- `POST /api/sessions/:key/queue/order` — reorders the queue. Body: `{ ids: string[] }` (ids missing keep their place after these). Returns: `{ ok }`.
- `POST /api/sessions/:key/queue/:id/delete` — takes a message off the queue; its attachments are deleted. Returns: `{ ok }`.
- `POST /api/sessions/:key/queue/resume` — lets a paused queue go out again (after a stop or a restart). Returns: `{ ok }`.

## Running and stopping

- `POST /api/sessions/:key/start` — resumes a stopped session's agent with its whole conversation (nothing is sent). Body: `{ model?, effort?, mode? }` (default: what it last used). Returns: `{ ok }`. 409 if it runs in VS Code or a terminal.
- `POST /api/sessions/:key/interrupt` — stops the running turn (as Stop or Esc); the agent stays ready and the queue pauses. Returns: `{ ok }` (409 if the agent is not running). **Careful**: stops another session's work.
- `POST /api/sessions/:key/stop` — ends the agent's process; the session and its history stay; the queue pauses. Returns: `{ ok }`. **Careful** as for interrupt.
- `POST /api/sessions/:key/tasks/:taskId/stop` — stops one background task (ids in `live.backgroundTasks`). Returns: `{ ok }`. **Careful**: its work ends unfinished.
- `POST /api/sessions/:key/takeover` — continues here a Claude Code session open in VS Code or a terminal: **ends that process** (stopping what it does), then resumes it here, with a message if given. Not for Codex (409). Body: `{ text?, images?, files? }`. Returns: `{ ok }`. **Careful**: always ask the user first; they may be working in that app.
- `POST /api/sessions/:key/resume-at` — "Resume at reset": continues a Claude Code or Codex session stopped by a usage limit by sending "Continue where you left off." (the page uses the reset time plus a minute); replaces an earlier one. Only for limits: the app keeps the time on the account's reset as it moves, and continues at once when the account is not at a limit. Body: `{ at: number (ms, not more than a minute in the past) }`. Returns: `{ ok }`. Not a way to schedule messages (use a scheduled task), and not snooze (that is `/flags`).
- `DELETE /api/sessions/:key/resume-at` — cancels that. Returns: `{ ok }`.

## Session settings

- `POST /api/sessions/:key/config` — changes the model, effort or permissions mode; applies to the running agent at once and is kept for the session (and as that agent's remembered default). Body: `{ model?: string|null, effort?: string|null, mode?: string|null }` (send only what changes; values from /api/catalog; a confidential session takes only another model on this computer). Returns: `{ ok }`. **Careful**: a mode like `bypassPermissions` or `full` lets the agent act without asking; never raise permissions without the user's explicit word.
- `PATCH /api/sessions/:key/extra` — merges into the session's settings beyond its agent's own; `null` removes a field. The page uses it for memory: `{ memory: false }` turns memory off for this session, `{ memory: null }` back on. Returns: `{ extra }`. `confidential` is set only when a session starts and never removed, and a confidential session keeps memory off and takes no swarm, research or arena (400). The spending cap has its own route (`PUT /api/budget/:key { capUsd }`, from $0.01 to $100,000), and connected accounts theirs.
- `POST /api/sessions/:key/goal` — a goal the agent keeps working towards, turn after turn. Body: `{ action: 'set'|'pause'|'resume'|'clear', objective?: string (required for set; up to 4,000 characters; say what "done" looks like) }`. Claude Code: set and clear only (sent as a /goal message: at once when the agent is free, queued while it works); Codex and Custom: all four; other ACP agents: 400. Returns: `{ ok }`. **Careful**: a goal keeps an agent working (and spending) until it holds.
- `POST /api/sessions/:key/compact` — replaces the conversation so far with a summary to free context (Claude Code and Codex; 400 for ACP agents; 409 while a turn runs). Starts the agent if stopped. Returns: `{ ok }`.

## Organizing sessions

- `POST /api/sessions/:key/rename` — sets the title. Body: `{ title: string }` (trimmed, up to 200 characters; empty gives back the agent's own title). Returns: `{ ok }`.
- `POST /api/sessions/:key/flags` — pin, archive or snooze (send only what changes). Body: `{ pinned?: boolean, archived?: boolean, snoozedUntil?: number|null (ms in the future; null unsnoozes) }`. Returns: `{ ok }`. A snoozed session comes back at that time, or as soon as it needs the user.
- `POST /api/sessions/order` — the order of a sidebar group (Active or Pinned) after a drag. Body: `{ keys: string[] }` (top to bottom, up to 1,000 session keys). Returns: `{ ok }`.
- `POST /api/sessions/:key/settle` — "Settle: done for now": stops the agent (409 "It is still working; stop it first" while a turn runs) and marks the session read; history and worktree stay. Returns: `{ ok }`.
- `POST /api/sessions/:key/seen` — marks the session read (it finished since the user last looked). Returns: `{ ok }`.
- `DELETE /api/sessions/:key` — stops the session and deletes its history from disk (Claude Code's and Codex's own files too), its queued messages and its notes. Cannot be undone. Returns: `{ ok }`. **Careful**: confirm with the user, naming the session; prefer archiving.

## Worktrees

- `GET /api/sessions/:key/worktree` — the session's worktree (404 if it has none). Returns: `{ path, branch, base, repo, exists, dirty (uncommitted files), ahead, behind (commits against base) }`.
- `POST /api/sessions/:key/worktree/remove` — removes the worktree's folder (stops the agent first); the session keeps its history; other sessions in the same worktree lose it too. The branch stays unless asked, or when it has nothing new. Body: `{ deleteBranch?: boolean, force?: boolean (needed when there are uncommitted changes, which are then lost) }`. Returns: `{ branchKept: boolean }`. **Careful**: deletes files; force and deleteBranch can lose work.

## Pull requests and review (from a session's branch)

- `GET /api/sessions/:key/pr/draft` — what a pull request would hold. Returns: `{ head, base, remote, host? { provider, owner, repo } (missing when no account in Settings → Source control covers it), commits [{ sha, subject }], stat { files, added, removed }, dirty, pushed, existing? }`.
- `POST /api/sessions/:key/pr/describe` — a model drafts a title and description from the commits and diff (needs commits). Returns: `{ title, body }`.
- `POST /api/sessions/:key/pr` — commits (if asked), **pushes the branch** and opens the pull request on GitHub or Gitea, linked to the session. Body: `{ title: string (required), body?: string (Markdown), draft?: boolean, commitAll?: boolean (commit uncommitted changes first, with the title as message) }`. Returns: `{ pr { url, number, title, state, checks?, repo } }`. **Careful**: publishes to the remote; only when the user asked.
- `POST /api/sessions/:key/pr/link` — links an existing pull request by its address. Body: `{ url: string }`. Returns: `{ pr }`.
- `POST /api/sessions/:key/pr/refresh` — reads its state and checks now. Returns: `{ pr }`.
- `DELETE /api/sessions/:key/pr` — unlinks it (it stays on its host). Returns: `{ ok }`.
- `GET /api/sessions/:key/review` — everything the branch changes since its base, uncommitted work included. Returns: `{ head, base, files [{ path, status, added, removed, diff, binary? }], uncommitted, guide? }`.
- `POST /api/sessions/:key/review/guide` — a model writes a reading order with a note per file. Returns: `{ guide { summary, steps [{ path, note }] } }`.

## Read-only links (listed only; documented with sharing)

- `GET /api/sessions/:key/guest-links` — the links that work now.
- `POST /api/sessions/:key/guest-links` — makes a link (`{ days?: number|null }`, at most 365; null = until turned off); returns `{ id, token }`, the address being `/g/<token>`. 409 for a confidential session. **Careful**: anyone with it can read the session.
- `DELETE /api/guest-links/:id` — turns one off.

## Projects

A project: `{ id ("sp…"), name, color, description?, folder (where its sessions work; fixed once made), instructions? (its guidelines, told to every session in it), assistant? (the id of the assistant its sessions start as), sharedKnowledge?: false (present only when its sessions leave the shared knowledge out), members? (project ids: it is a group), createdAt }`.

Elsewhere a project's id is in fields named `space`, and lists of projects in `spaces`: the name projects had before. Their old addresses, `/api/spaces/…`, still work.

- `GET /api/projects` — every project, oldest first, with counts. Returns: `{ spaces: [{ …space, sessions: number (sessions started in it), lastAt?: ms (when one of them was last at work), docs: number (documents in its own knowledge bases), skills: number (skills of its own), library: number (what it holds in the Library: pages, decks, documents, spreadsheets, LaTeX documents, pictures and videos) }] }`.
- `GET /api/projects/suggestions` — folders worth a project of their own: those sessions worked in, or changed files in, in the last 90 days, that no project has yet (neither its folder nor one of the folders it works with), the most used and most recent first, at most 6. A session counts for the folder it ran in and, less, for each other folder whose files it changed; a folder inside a git repository counts as the repository; sessions in a project don't count. The home folder, hidden folders, temporary ones, the app's own (task folders, apps' runs, worktrees) and those hidden with the route below are left out. Returns: `{ folders: [{ path, sessions: number — sessions that worked in it or changed its files, changed: number — of those, how many only changed its files, lastAt: ms }] }`.
- `POST /api/projects/suggestions/hide` — "Not a project": stops suggesting a folder (the folder itself is untouched). Body: `{ folder: string — its full path }` (400 "Which folder?" otherwise). Returns: `{ folders }` as above.
- `GET /api/projects/:id` — one project and its sessions. Returns: `{ space, sessions: string[] — session keys, the last at work first, at most 100 }`. 404 "No such project".
- `POST /api/projects` — makes a project, or a group when `members` is given. Body: `{ name: string — required, cut at 60 chars (400 "Give the project a name" when empty); color?: "amber"|"blue"|"green"|"pink"|"violet"|"teal"|"orange"|"slate" — default: the next in turn, any other value becomes blue; description?: string — what it is about, cut at 300; folder?: string — an existing folder to make the project around (a full path or ~/…; 400 "No folder at …" when it isn't one); left out, the app makes a new one: <task folders>/Projects/<name in lowercase with dashes> (default ~/Hydor/Projects/…, with -2, -3… when taken); folders?: string[] — other folders of the user's it works with, where they are (full paths or ~/…; 400 "No folder at …" when one isn't a folder): each once, at most 12, its own folder and folders inside it left out; its sessions are told of them, and Claude Code works in them as in its own; instructions?: string — its guidelines (Agent Guidelines), cut at 20,000; assistant?: string — an assistant id (GET /api/assistants), cut at 80; sharedKnowledge?: boolean — false: its sessions search only its own documents (default: the shared knowledge too); members?: string[] — project ids to bring together: existing projects that aren't groups, each once, at most 12 (others are silently dropped) }`. Returns: the project.
- `PATCH /api/projects/:id` — changes a project. It merges: only the fields given change, the rest are kept. Body: the same fields as POST except `folder`, which can't change. `""` clears description, instructions or assistant; `folders` replaces the list of folders it works with (`[]` leaves none; the folders themselves are untouched); `sharedKnowledge: true` (or anything but false) brings the shared knowledge back; `members: []` turns a group back into a plain project; giving members to a project that is itself in a group fails with 400 ("… is in a group already…"). Returns: the project. 404 "No such project".
- `DELETE /api/projects/:id` — deletes a project. Its folder, files, sessions and memory notes stay; its knowledge bases become shared; its skills join the skill library (one whose name the library has already gets the project's after it: research → research-thesis); it leaves every group it was in (a group left with no projects becomes a plain project). Returns: `{ ok: true, skills: string[] — the names its skills have in the skill library now }`.
- `GET /api/projects/:id/skills` — a project's own skills (only its sessions get them, with the skill library; a group's sessions get its projects' too), the ones removed that can come back, and the skills it switches on or off for its own sessions. Returns: `{ skills: [{ name, description (when to use it), triggers: string[] (keywords for Custom), overrides?: true (the library has a skill of that name, which this one takes the place of in the project), path, updatedAt: ms, uses: number (times agents loaded it in the project or a group that brings it in), lastUsed?: ms }], removed: [{ name, at }], switches: { [key]: boolean } (key: a skill of the library or of the project by its name, Claude Code's or Codex's own as "claude:<name>" or "codex:<name>"; true: on for the project's sessions, false: off; a skill not named is as Settings → Skills has it, the project's own on), members?: [{ id, name, skills: [as above] }] (a group: the skills of the projects it brings together, which its sessions get too) }`. 404 "No such project".
- `PUT /api/projects/:id/skill-switches` — turns a skill on or off for the project's sessions alone, whatever Settings → Skills says for every other session, or back to that. Body: `{ name: string — the skill's name as the skills list shows it, agent?: 'claude'|'codex' — for one of that agent's own skills (GET /api/setup/skills?cwd=<the project's folder>); left out, a skill of the library or of the project, on: boolean | null — null: as Settings → Skills has it again }`. A project's sessions get it when they start (Custom from its next turn): the library's and the project's skills in their skill list, Claude Code's own as its settings for the session, Codex's own as its thread's settings; the agents' own settings files are not changed. At most 400 switches. Returns: `{ switches }` as in GET /api/projects/:id/skills. 400 for a name that isn't a skill's, another agent, or an `on` that is not true, false or null; 404 "No such project".
- `DELETE /api/projects/:id/skill-switches` — every skill back to what Settings → Skills says, for the project's sessions too. Returns: `{ switches: {} }`. 404 "No such project".
- `GET /api/projects/:id/skills/:name` — one of a project's skills, whole, with its history of changes. Returns: `{ name, text (the whole SKILL.md), source: 'space', space: { id, name }, file, history: [{ id, name, at, action: 'create'|'update'|'remove'|'restore', key?, diff, added, removed }] }`. 404 when the project has no skill of that name.
- `POST /api/projects/:id/skills` — adds a skill to the project, or copies one of the skill library into it to change for the project alone. Body: `{ name: string — lowercase words with dashes (other text is turned into that: "Citation style" → citation-style; 400 when it ends up shorter than 2 characters), description: string — when to use it, one line of at least 10 characters ("Use when citing a source in the thesis"), body: string — the steps, checks and mistakes to avoid, in Markdown (more than a few words; the whole skill at most 20,000 characters), triggers?: string[] — up to 12 keywords that bring it into Custom's turn }`, or `{ from: string — a library skill's name: copied with its other files }`. A skill that looks like it holds a secret is refused (400). Returns: the skill, as in the list. 409 when the project has a skill of that name already; 404 when `from` names no library skill.
- `PUT /api/projects/:id/skills/:name` — changes one of the project's skills. It merges: only the fields given change (its keywords stay unless `triggers` is given). Body: `{ name?, description?, body?, triggers? }` as for POST; a new `name` renames it, its other files, history and switch going along (409 when the project has a skill of that name). Returns: the skill. 404 when the project has no skill of that name.
- `DELETE /api/projects/:id/skills/:name` — removes one of the project's skills: its sessions stop seeing it (or get the library's skill of that name again, as Settings → Skills has it: the removed skill's switch goes with it). Its text stays in its history. Returns: `{ ok: true }`. 404 when the project has no skill of that name.
- `POST /api/projects/:id/skills/:name/restore` — brings back a skill the project had, as it was when removed. No body. Returns: `{ ok: true }`. 404 when there is nothing to bring back; 409 when the project has a skill of that name.
To start a session in a project as the start page does, call `POST /api/sessions` (Starting sessions, above) with `cwd`: the project's `folder`, and `extra: { space: <space id>, assistant?: <its assistant> }`. The server then adds the project's guidelines, what its folder holds now and the other folders it works with (in a group, each member project's name, folders and guidelines too; Claude Code gets access to all those folders) and scopes the session's document search to the project; it doesn't fill in the folder or the assistant from the project. To add a file to a project as the Files page does, copy it into the project's `folder` with your own tools; to add a folder, append it to the project's `folders` with PATCH.

## Shared knowledge and a project's documents

A knowledge base: `{ id ("kb…"), name, description?, space? (the project it belongs to: only that project's sessions search it; none: shared), createdAt, sources: [{ id, kind: "files"|"folder", path, name, addedAt }] (kind "files" is the base's own "Files you added" folder, made with it), filesDir (where dropped files are kept, in the app's data folder), docs, passages, embedded (passages ready for search by meaning), errors: [{ path, error }] (documents that could not be read, at most 20), indexing?: { done, total } (being read now), indexedAt? }`.

- `GET /api/knowledge` — every knowledge base, and whether search by meaning is on (Settings → Memory). Returns: `{ bases: KnowledgeBase[], meaning: boolean }`. A base whose `space` no longer exists counts as shared.
- `GET /api/knowledge/:id/docs` — the documents a base holds, by path, at most 2,000. Returns: `{ docs: [{ id, base, path, title (the file's name), format, size, passages, status: "indexed"|"empty" (no text in it)|"error", error?, indexedAt }] }`. 404 "No such knowledge base".
- `POST /api/knowledge/search` — searches the documents as agents do. Body: `{ query: string — a question; "exact words" in quotes or a /pattern/ is searched for exactly; mode?: "auto" (words and meaning, the default)|"words"|"meaning"|"exact"; space?: string|null — search only what a session in that project searches (null or "": a session in no project, so the shared knowledge alone); left out: every base; bases?: string[] — only these bases, by id or name; limit?: number — default 10, at most 30 }`. Returns: `{ hits: [{ ref ("kb:<n>"), base, baseName, docId, path, title, part? (the page, slide, sheet or heading), text (an excerpt, ≤900 chars), score, by: ("words"|"meaning"|"exact")[] }], meaning: boolean — whether search by meaning took part }`. Exact hits come in reading order, the others best first.
- `POST /api/knowledge` — makes an empty knowledge base. Body: `{ name?: string — cut at 60, default "My documents"; description?: string — cut at 300; space?: string — a project's id to make it that project's own; left out or "": shared }`. Returns: the knowledge base.
- `PATCH /api/knowledge/:id` — renames a base or moves it. It merges: only the fields given change. Body: `{ name?: string — cut at 60, not empty (400 "Give it a name"); description?: string — "" clears it; space?: string|null — a project's id to move it into, null or "" to make it shared }`. Returns: the knowledge base.
- `POST /api/knowledge/:id/folders` — adds a folder on this computer to a base. It is read where it is (nothing copied), at once, then again a minute after the app starts and every hour: new and changed files are read, deleted ones leave. Hidden files and folders, tool folders (node_modules, .git, dist, build, venv…) and pictures are skipped; at most 20,000 files, 12 levels deep. Body: `{ path: string — a full path or ~/… (400 "Which folder?" when empty, "No folder at …" or "… is not a folder") }`. Adding a folder the base already has changes nothing. Returns: the source `{ id, kind: "folder", path, name, addedAt }`.
- `POST /api/knowledge/:id/scan` — reads the base again now: files just dropped in, folders that changed. No body. Returns: `{ ok: true }`; `GET /api/knowledge` shows `indexing` while it reads.
- `DELETE /api/knowledge/:id/sources/:sid` — stops reading a folder: its documents leave the base; the folder itself is untouched. 400 for the "files" source ("Remove the files themselves instead"). Returns: `{ ok: true }`.
- `DELETE /api/knowledge/:id/docs/:doc` — removes a document that was dropped into the base, deleting the base's copy of it. 400 for a document in a folder on this computer (remove it there, or stop reading the folder). Returns: `{ ok: true }`.
- `DELETE /api/knowledge/:id` — deletes a base: its passages, their vectors and the files dropped into it. Folders on this computer stay as they are. Returns: `{ ok: true }`.
Files from the user's device are added by uploading them into the base's `filesDir` (the files routes, as the page does) and then calling `POST /api/knowledge/:id/scan`. An agent adds documents that are already on this computer with `POST /api/knowledge/:id/folders`.

## Assistants

An assistant object: `{ id, name, icon, description, instructions, agent?, acpAgent?, model?, tools?, connections?, skills?, mode?, folder?, builtin?, source? }`. The seven built-ins (ids `general`, `researcher`, `writer`, `coder`, `tutor`, `planner`, `analyst`) come first, have `builtin: true`, and can be duplicated (read one, then POST it under a new name) but not changed or deleted.

- `GET /api/assistants` — every assistant (built-ins first, then the user's own) and the settings beside them. Returns: `{ assistants: Assistant[], taskRoot: string — where new task folders go, defaultTaskRoot: string — ~/Hydor (~/Naget where an older install made it), cleanUp: boolean — agents clean up after a task }`.
- `GET /api/assistants/import?cwd=` — Claude Code agent files that can be imported: those in `~/.claude/agents` and, with `cwd` (optional, a folder path), in `<cwd>/.claude/agents` (up to 200 per folder). Returns: `{ files: [{ path, scope: "user"|"project", name, description, imported?: string — the id of the assistant already made from it }] }`.
- `POST /api/assistants` — makes a new assistant of the user's own (at most 200; its id is made from the name, like `bookkeeper-3f9a`). Body: `{ name: string — required, ≤60 chars; icon?: "sparkles"|"telescope"|"pen-line"|"code"|"graduation-cap"|"calendar-check"|"chart-column"|"bot"|"briefcase"|"book-open"|"calculator"|"chef-hat"|"dumbbell"|"heart"|"languages"|"lightbulb"|"megaphone"|"music"|"palette"|"plane"|"house"|"mail"|"scale"|"shield"|"wallet"|"stethoscope"|"leaf"|"newspaper"|"wrench"|"users" — any other value becomes "bot"; description?: string — one line, ≤160; instructions?: string — who it is and how it works, ≤20,000; agent?: "claude"|"codex"|"acp" — the agent it suggests, left out = keep the start page's; acpAgent?: string — required with agent "acp": "console" is Custom, else an agent id from Settings → More agents; model?: string — the model it suggests, in that agent's own names (kept only with an agent); tools?: ("read"|"edit"|"run"|"web"|"mcp")[] — what it may use (read files, create and change files, run commands, use the web, other tools = MCP servers and plugins); left out or all five = everything, [] = none of them (the app's own tools stay on); connections?: string[] — connection ids (Settings → Connections) turned on in its sessions, ≤50; skills?: string[] — skill names to favor, ≤30; mode?: "ask"|"edits"|"full"|"plan" — its permission mode, left out = keep the start page's; folder?: "task"|"project" — where its sessions start when no folder is picked: a new task folder (default) or the folder on the start page }`. Returns: `{ assistant: Assistant, assistants, taskRoot, defaultTaskRoot, cleanUp }`.
- `PUT /api/assistants/:id` — changes one of the user's own assistants. It replaces the assistant whole with the body (same fields as POST; any field left out is cleared, so send the full object back with your change; send `source` back to keep an imported one linked to its file). 400 for a built-in, 404 for an unknown id. Returns: `{ assistant, assistants, taskRoot, defaultTaskRoot, cleanUp }`.
- `DELETE /api/assistants/:id` — deletes one of the user's own assistants (400 for a built-in). Sessions started with it carry on without its instructions. Returns: `{ assistants, taskRoot, defaultTaskRoot, cleanUp }`.
- `PUT /api/assistants/session/:key` — switches a session to another assistant, as its message box does: its agent works as that one from the next message on (it is told of the switch with that message; an idle Claude Code or Codex agent starts afresh first, with the new instructions and limits, and the conversation carries on). The connections the assistant turns on replace the previous one's in the session (the session's other choices stay); its permission mode is set on the session, and its model when it suggests the session's own agent. Body: `{ id: string — an assistant id (GET /api/assistants) }`. Returns: `{ extra: SessionExtra — the session's settings now, model?: string, mode?: string — what it set, in the agent's own names }`. 404 "No such assistant" or "No such session".
- `PUT /api/assistants/settings` — changes the settings beside the list; only the fields given change. Body: `{ taskRoot?: string — the folder new task folders go in (new projects' own folders go in its Projects subfolder): a full path or one starting with ~/, "" for the default ~/Hydor; cleanUp?: boolean — every agent cleans up after a task (on by default) }`. Returns: `{ assistants, taskRoot, defaultTaskRoot, cleanUp }`.
- `POST /api/assistants/import` — makes an assistant from a Claude Code agent file (name, description, model, tools, permissionMode and skills from its frontmatter; the text below as its instructions; it works in the folder on the start page). Importing the same file path again updates the assistant made from it (its icon kept). Body: `{ path?: string — an .md agent file on this computer, ≤256 KB; text?: string — the file's text instead of a path, ≤256 KB; name?: string — the file name, used for pasted text whose frontmatter has no name }` (one of path or text). Returns: `{ assistant, assistants, taskRoot, defaultTaskRoot, cleanUp }`.
- `POST /api/assistants/task-folder` — makes a new, empty task folder now, the way the start page does for a session without a folder: under `taskRoot`, named by today's date in the user's time zone and a few words of the prompt (`2026-10-31-plan-trip-lisbon`, `-2` when taken). Body: `{ prompt?: string — the task, for the name }`. Returns: `{ path: string }`.
To start a session as an assistant the way the start page does, call `POST /api/sessions` (Starting sessions, above) with `extra: { assistant: <id>, connections?: { <connection id>: true, … } }` (its connections), the agent, model and mode it suggests (the mode in that agent's names: ask/edits/full/plan are default/acceptEdits/bypassPermissions/plan for Claude Code, read-only/auto/full/plan for Codex, ask/edits/full/plan for Custom), and `cwd` from `POST /api/assistants/task-folder` when its `folder` is "task" and the user named no folder. The server adds the assistant's instructions, skills and tool limits by itself; it does not fill in the agent, model, mode, connections or folder.

## Memory

Notes ("entries") belong to a place: `scope` "global" (about the user, `scopeKey` ""), "repo" (a project: `scopeKey` is the project's folder as memory keys it, i.e. the root of its Git repository, the main repository's for a worktree, or the folder itself outside Git; never the home folder) or "session" (`scopeKey` is the session's key). Kinds: "note", "topic" (sums up related notes) and "profile" (a place's summary agents get first). Times are milliseconds since 1970. An entry as the routes return it: `{ id, scope, scopeKey, kind, text, status: "active"|"deleted", createdAt, updatedAt, expiresAt?, usedAt?, uses, covers? (topics/profiles: notes summed up), session?, turn? (who wrote or changed it last), source: "user"|"agent"|"auto" (auto = the helper's tidy-up or an expiry), scopeLabel ("About you", the project's folder name, or the session's title), sessionTitle? }`. A change (in a tidy-up report or a memory chip): `{ entry, action: "added"|"updated"|"deleted"|"expiry", scope, scopeKey, kind?, before?, after?, expiresAt?, expiredBefore?, why?, source, undone? }`.

- `GET /api/memory` — memory's state: the switches, counts, the user's profile, how many notes agents start with, search by meaning, the last tidy-up. Returns: `{ enabled: boolean (memory for all sessions), counts: { global, repo, session } (active notes, past-end-date ones and the user's profile left out), profile: entry | null (the user's profile; its text may have several lines), profileWords: number (the most words it may have: 1,000 unless changed), profileFit?: { running: boolean, at, error? } (the helper model shortening a profile longer than that, or why it could not lately), topK: number (how many notes and topics about the user and the project agents start with, besides the profile: 10 unless changed), meaning: { on, status: "off"|"setting-up"|"starting"|"ready"|"failed", detail? (progress or why it failed), model, where: "auto"|"cpu", device? ("CPU" or the GPU's name), embedded, total }, tidyOn: boolean, tidy?: { at, running?, changes: change[], changesAt? (set when the latest found nothing and these are an earlier run's), checked, error? }, stale: number (notes suggested for removal) }`.
- `PUT /api/memory` — changes the switches; only the fields given change. Body: `{ enabled?: boolean — memory for all sessions, topK?: integer 1–50 — how many notes agents start with (Settings offers 5, 10, 20, 40), profileWords?: integer 50–5000 — the most words the user's profile may have (Settings offers 250, 500, 1000, 2000; a profile longer than a new limit is shortened by the helper model in the background), meaning?: boolean — search by meaning (on unless turned off; it sets itself up a minute after the app first starts, at once when turned on: a few minutes, then a 1.2 GB model download), device?: "auto"|"cpu" — where it runs (auto: a GPU with room, else the CPU), retry?: true — try again after it failed, tidy?: boolean — tidy up each night }`. Returns: the state, as `GET /api/memory`.
- `GET /api/memory/entries` — lists notes. Query: `q?: string — search: with status active, every word must match (the last as a word's start) plus, when search by meaning runs, notes alike in meaning, best first, at most 100; with deleted/all, a plain all-words filter`, `scope?: "global"|"repo"|"session"`, `key?: string — one place's scopeKey`, `status?: "active" (default)|"deleted"|"all"`, `kind?: "note"|"topic"|"profile"`, `ids?: "1,2,3" — these entries in any status (at most 200)`, `stale?: "1" — only the notes no agent needed for 120 days (about the user or projects, plain notes without an end date; at most 100; other parameters ignored)`. Without `q`, newest change first. Returns: `{ entries: entry[] }`.
- `GET /api/memory/profile` — the user's profile: what every agent gets at the start of a session while memory is on, right after the user's guidelines. Returns: `{ profile: entry | null, maxWords: number }`.
- `PUT /api/memory/profile` — writes the user's profile as the user (agents use their own tool, update_user_profile). Body: `{ text: string — the whole profile, lines kept; "" clears it (it stays among the deleted notes for 30 days); refused (400) when it seems to hold a password, key, token or card number, or has more than 40,000 characters }`. Longer than its words, it is saved as written and the helper model shortens it to fit in the background (`GET /api/memory` shows `profileFit`). Returns: `{ profile: entry | null, maxWords: number, fitting: boolean (a shortening started) }`.
- `POST /api/memory/profile/fit` — shortens the user's profile to its words now, with the helper model in the background (after it could not). Returns: `{ started: boolean }` (false when it fits already).
- `GET /api/memory/entries/:id/history` — one note's history, newest first. Returns: `{ history: [{ id, entry, at, action: "added"|"updated"|"deleted"|"restored"|"expiry", before?, after? (for expiry: the end date as an ISO time, none when taken away), why?, session?, sessionTitle?, turn?, source }] }`.
- `GET /api/memory/entries/:id/children` — the notes a topic or profile sums up (any status, at most 500). Returns: `{ entries: entry[] }`.
- `POST /api/memory/entries` — adds a note as the user. Body: `{ text: string — at least 2 characters; kept as one paragraph, cut at 500; refused (400) when it seems to hold a password, key, token or card number, scope?: "global" (default)|"repo"|"session", key?: string — required unless global: the project's folder exactly as memory keys it (see above; another folder makes another place) or the session's key, expiresAt?: number — when it stops being true, from now to five years on }`. Returns: `{ entry }`.
- `PATCH /api/memory/entries/:id` — edits a note: its text, its end date, or both (other fields untouched). Body: `{ text?: string — new text (same rules as above; on a deleted note it restores it with this text), expiresAt?: number|null — new end date, from now to five years on; null takes it away }`. Returns: `{ entry }` (404 when the entry is gone).
- `DELETE /api/memory/entries/:id` — deletes a note: it stays restorable for 30 days. Query: `forever?: "1" — erase it and its history at once (cannot be undone)`. Returns: `{ ok: true }`.
- `POST /api/memory/entries/:id/restore` — brings back a deleted note (an end date that has passed is dropped). Returns: `{ entry }` (404 when it is not deleted).
- `POST /api/memory/entries/:id/keep` — keeps a note suggested for removal: it counts as needed now and leaves the stale list. Returns: `{ ok: true }`.
- `POST /api/memory/tidy` — starts a tidy-up now with the helper model, in the background (works whether or not the nightly one is on; 400 when memory is off). Returns: `{ started: true }`; `GET /api/memory` shows `tidy.running`, then its changes or error.
- `POST /api/memory/tidy/undo` — undoes one change of the last tidy-up: what it added goes, what it changed gets its old text back, what it deleted returns, an end date it set is taken away. Body: `{ index: number — the change's position in tidy.changes }`. Returns: `{ tidy }` (the report, that change marked undone).
- `POST /api/memory/notes/:id/undo` — undoes one change from the memory chip under a reply (the session note of kind "memory", from `GET /api/sessions/:key/notes`; its `data.changes` lists the changes). Body: `{ index: number — the change's position in data.changes }`. An added note goes, an updated one gets its old text back, a removed one returns. Returns: `{ note }` (the session note, that change marked undone).
- `DELETE /api/memory` — clears all memory: every note, all history. Cannot be undone. Body: `{ confirm: "all" }` (required). Returns: `{ cleared: number }`.

## Skill library

Settings → Agents → Skills shows these with the agents' own skills (below). Skill names (`:name`) are lowercase letters, digits and dashes, up to 64 characters.

- `GET /api/skillpack` — the skill library: every skill (built in, the user's, and those of enabled plugins), proposals waiting for the user, removed skills of the user's, the keywords switch, and the projects with skills of their own. - `POST /api/apps` — makes an app. Body: `{ recipe: Recipe (or its fields at the top level), mcp?: boolean — offered to other agents as a tool (default true), public?: Public, slug?: string — its address (default from the name, made unique), template?: string — the ready-made id it started from }`. Gives 400 saying what to fix: an empty prompt without steps, a flow whose values come later or name nothing, a rule that cannot be read, a tool a step cannot call on its own, a collection it does not keep, a package that cannot be installed safely; or public.on without a Custom model. The packages it requires start installing. Returns: `{ app: App, warnings: string[] — what may surprise, such as a value that is empty when a Decide goes the other way }`.
- `POST /api/apps/check` — checks a recipe without saving it, as POST does. Body: `{ recipe: Recipe }`. Returns: `{ errors: string[], warnings: string[] }`.
- `PUT /api/apps/:id` — changes an app. Body: as POST. The recipe is replaced whole, so GET it first and send every part (its flow, data, memory and requires too); a body with neither a prompt nor steps is refused. `public` merges into the current public settings. `mcp`, `agents`, `slug` and `template` keep their values when left out; a new `slug` changes the address. Returns: `{ app: App, warnings: string[] }`.
- `DELETE /api/apps/:id` — deletes an app with its runs, batches, keys, public page and the data it keeps (an app installed from a file, its page's Uninstall, too). Its active runs are stopped first; their sessions stay; it leaves the pinned apps. Returns: `{ ok: true }`.
- `POST /api/apps/:id/uninstall` — uninstalls a ready-made app (`tpl:<id>`): it leaves your apps and agents' tools, runs no more (409) and waits under Ready-made apps to install on the Apps page; its runs and records stay, its Update automatically task goes, and it leaves the pinned apps. Returns: `{ template, installed: false, agents }`.
- `POST /api/apps/:id/install` — installs a ready-made app (`tpl:<id>`) again. Body (the user's own pages only): `{ secrets?: { NAME: value }, allow?: [NAME] }` — keys it needs, saved to the vault. Returns: `{ template, installed: true, agents }`.
- `PUT /api/apps/:id/agents` — whether agents in your sessions may run an app (yours by id or slug, or `tpl:<id>`): its page's Agents can use it. Body: `{ on: boolean }`. Returns: `{ agents: boolean, made: boolean — it is made for that (when false, agents never get it) }`.

## App runs

- `POST /api/apps/:id/runs` — runs an app now, in the background (yours by id or slug, or ready-made as `tpl:<id>`). Body: `{ flow?: string — another of its flows (absent or "run": the main one; its inputs are that flow's), inputs?: { [fieldId]: string|number|boolean } — checked against the form (text ≤2,000, long/file ≤60,000 characters; choice must match an option; dates YYYY-MM-DD; yes/no), files?: { [fileFieldId]: { name: string, data: base64 } } (≤25 MB each), agent?: claude|codex|acp, acpAgent?, model?, effort?, mode? — ready-made apps only (default Claude Code, mode auto), recipe?: Recipe — test this recipe instead (:id "test" for one not saved), source?: "test"|"screen", pause?: string[] — a test run (with steps) pauses before these steps until told to go on (POST /api/apps/runs/:runId/go), freeze?: { from: runId, steps: string[] } — a test run's steps that give what they gave in that earlier run of the same app, without running again, secrets?: { NAME: value }, allow?: [NAME] — the user's own pages only: keys it needs, saved to the vault first (allow: saved keys that may now go to its hosts too) }`. Gives 400 saying what to fix in the form, 409 `{ error, secrets: [{ name, label, help?, url?, optional? }] }` when the flow it runs needs keys the vault does not have (the keys that flow names, and an optional key the flow signs its requests with, as the Annotation workbench's publish flow does with HF_TOKEN; the optional ones are listed too, to ask for together; a run started by an agent: tell the user to add them on its page, or run it with use_app, whose card asks), and 429 past the app's runs a day. Returns: `{ run: Run }`.
- `GET /api/apps/:id/runs` — an app's runs, newest first, 50 at a time (ready-made: `tpl:<id>`). Query: `before?: number — createdAt of the oldest run seen, to get older ones`. Returns: `{ runs: [Run] }`.
- `GET /api/apps/runs/:runId` — one run, with how it is going and its follow-ups. Returns: `{ run: Run, progress: { steps: [{ title, status: running|ok|error }] (last 8), said?, waiting?, own?: true — a run with steps: the titles are the app's own words, paused?: string[] — a test run paused before these steps (see …/go) }, recipe: { name, icon, color, fields, answer, agent, acpAgent, model, ui?: Ui — the view its answer shows in (its app's as it is now, a test's as it was tried; none for a run of another of its flows), assets?: { [name]: { sha, mime, bytes } } — its app's own files, steps?: true — its main flow works in steps }, slug: string|null, asks: [{ id, text, at, reply?, updated: boolean — handed in a new result }], first?: string — the reply to the task itself, queued: [{ id, text, at }], noAsks?: string — why it takes no follow-ups (runs with steps take none), steps?: [Step] — a run with steps: every step so far, with what it gave, question?: { step, question, fields?, since } — an Ask a person step waiting for the answer }`. With a view, also `view: { … }` — what its view keeps for it (see Apps: views).
- `POST /api/apps/runs/:runId/ask` — a follow-up that refines the result. It goes to the run's session and waits its turn if the agent is busy. Body: `{ text: string — ≤20,000 characters }`. Gives 409 for public-page runs, runs not started yet, and runs whose session is gone or open in another program. Returns: `{ run: Run }`.
- `POST /api/apps/:id/examples/run` — tries its examples (or those named): a test run each, whose checks are read when it ends. Body: `{ recipe?: Recipe — try this instead of the app as saved (the builder's, unsaved; :id may be "test"), only?: string[] — example ids, trial?: boolean — a change tried before it is used (Firm it up): its runs' example is "trial:<id>", and they are not the examples' last try }`. Returns: `{ runs: [{ example, run?: Run, error?: string — why it could not start }] }`. A run that tried an example has `example`, and once it has ended `checks: [{ rule, ok, why? — what it saw }]`.
- `GET /api/apps/:id/examples` — a saved app's examples, each with its last run. Returns: `{ examples: [{ id, name?, flow?, inputs, checks?, last?: Run }] }`.
- `GET /api/apps/schema.json` — the JSON Schema of an app's app.json (its folder's), for an editor's completion and checks.
- `GET /api/apps/:id/folder` — its folder of files, if it has one. Returns: `{ folder: { path, error? — the mistake in it, which changed nothing } | null, suggested: string — where one would go }`.
- `POST /api/apps/:id/folder` — makes its folder and keeps it in step with the app: each change saved there is a version by "folder", a save here writes it again. Body: `{ path?: string — an empty folder, or one of this app's (default: Hydor/Apps/<address> in the home folder) }`. Returns: `{ app, folder }`. The folder: app.json (the recipe, with { file } for texts kept in files), instructions/<step>.md, steps/<step>.js|py (export default async function step(input) { … } / def step(input):), screens/<name>.html, ui/<element>.html and .css and ui/style.css (its view's elements and style), graph.json, .naget/app.schema.json and step.d.ts.
- `DELETE /api/apps/:id/folder` — stops keeping it in step; the files stay. Returns: `{ app }`.
- `GET /api/apps/:id/versions` — its versions, newest first: each save that changed what it does (not where its steps sit in the graph, nor its screens). Returns: `{ versions: [{ n, at, by: "you"|"agent"|"folder"|"install", line — what changed (or the why of the save), examples?: { tried, passed, seconds, costUsd } — its examples tried with it as saved: the latest run of each, and a run's average time and cost }] }`. A run's `version` is the one it ran (none: a try of changes not saved). A save takes `why` (≤300) for its version's line.
- `GET /api/apps/:id/versions/:n` — one version, whole. Returns: `{ version: { n, at, by, line }, recipe: Recipe }`; save the recipe (PUT /api/apps/:id) to bring it back as the newest version.
- `GET /api/apps/:id/advice` — what its latest runs (the last 12) say of its steps. Returns: `{ rescued: [{ step, title, runs, of — in how many of the runs read, error — why it failed the last time, run — that run }] — steps that failed and had an agent do their work, firm: [{ step, title, runs, calls: string[] — the tools its agent called each time, in order, steps: [Step] — fixed steps to put in its place (a tool step for each call, then a model step that keeps its id), agent: { seconds, costUsd } — what its agent took a run, on average, inputs: [object] — the answers of the runs it was seen in }] — agent steps that did the same in each of their last runs (at least 3) }`. Put the steps in with the app's flow and try them (examples/run with trial, or a test run) before saving them.
- `POST /api/apps/runs/:runId/answer` — answers the run's waiting Ask a person step, and the run goes on. Body: `{ step?: string — its path, as GET gives it in question.step, yes?: boolean — for a yes or no, values?: { [fieldId]: answer } — for its form }`. Gives 409 when nothing waits for an answer there, 400 when the answer does not fit. Returns: `{ ok: true }`.
- `POST /api/apps/runs/:runId/again` — runs a run with steps again from one of its steps: the same answers, the app as it is now, and the steps before that one giving what they gave in this run (marked `reused` in its steps, at no cost). Or, with `inputs` (what a view's again does), runs any app's run again from the start with some answers changed: the others as they were, its files along. Body: `{ from?: string — a step's id in the main list of steps (default: the first: all run again), recipe?: Recipe — run this instead of the app as it is (a test from the builder; the run is a test), inputs?: { [fieldId]: answer } — the answers that change }`. Gives 409 while it still runs (from a step) or when a file it had is gone, 400 when the app has no such step or question now, or (from a step) the run had files. Returns: `{ run }`.
- `POST /api/apps/runs/:runId/stop` — stops a run: one waiting in line ends at once, a working one is interrupted.
- `POST /api/apps/runs/:runId/go` — a test run paused before a step (its progress has `paused: [stepPath]`, its status is waiting) goes on. Body: `{ step?: boolean — run one step, then pause before the next }`. Returns: `{ ok: true }`; 409 when it is not paused. Returns: `{ ok: true }`.
- `DELETE /api/apps/runs/:runId` — removes an ended run from the lists, with its steps (409 while it is going); sessions stay. Returns: `{ ok: true }`.

## Apps: keys and files

An app names the keys it needs (`secrets` in its recipe), never their values: the user gives each one on its page, on the card that installs it, or on its card in a session (use_app asks for those the vault lacks), and it goes to the vault under that name with the hosts the app gives (a key the vault has keeps the user's own hosts). Its runs are told each key's name and how to use it (http_request `auth: NAME`, the browser, run_with_secrets). An app's own files (`assets`) are kept by the app and show by name as `asset:<name>`; the files an answer points at are kept too. Both are served at `/app-media/<sha>/<name>`, an address nobody can guess, which views (in their sandboxed frame) and public pages can reach without the sign-in; anything but a picture, video, sound or PDF downloads instead of opening.

- `GET /api/apps/:id/secrets` — the keys it needs and how the vault has them (yours, or `tpl:<id>`). Returns: `{ secrets: [SecretState] }`.
- `POST /api/apps/:id/secrets` — saves values for the keys it needs (the user's pages only: agents are refused, as for any key's value). Body: `{ values?: { NAME: value } — only its own keys are taken, allow?: [NAME] — saved keys that may now go to its hosts too (and to commands, when it needs that) }`. Returns: `{ secrets: [SecretState] }`.
- `POST /api/apps/assets` — keeps a file for an app being edited, without changing any app (its Edit saves the entry with the app). Body: `{ name: string — a file name, no folders (≤100), data?: base64 (≤100 MB), url?: https:// or data: address, caption? }`. Returns: `{ name, asset: { sha, mime, bytes, caption? } }`.
- `POST /api/apps/:id/assets` — adds one of its files, or replaces the one with that name, and saves the app as a new version. Body: as above. Gives 400 for a name that cannot be one or past 100 files, 413 past 100 MB, or 150 MB for all its files. Returns: `{ app: App }`.
- `DELETE /api/apps/:id/assets/:name` — removes one of its files from it (a new version; earlier versions keep theirs). Returns: `{ app: App }`.

## Apps: what they keep

An app with `data` keeps collections of records between its runs: its steps (Keep data), its agents (with their app_data tool), its view and these routes share them. A ready-made app keeps them too, under `tpl:<id>` (Paper radar's saved papers, `/api/apps/tpl:paper-radar/data/saved`; the Annotation workbench's `items`; the Lab notebook's `entries`), while it is installed: its own page reads and changes them. Fields with kinds are checked and tidied (numbers, dates, yes or no); unknown fields are refused. The Reading list's papers are `GET /api/apps/tpl:reading-list/data/papers` (fields title, authors, year, venue, doi, arxiv, url, pdf, abstract, bibtex, key, tags, status — To read, Reading or Read —, notes, project — one of your projects' id, or the words given when they name none —, project_name — its name, to show —, added, read_on, zotero_key, zotero_version), and its syncs with Zotero `…/data/syncs`.

- `GET /api/apps/:id/data` — the collections it keeps. Returns: `{ collections: [{ name, count, fields: [field] | null, description: string | null }], limits: { collections, records, record, find } }`.
- `GET /api/apps/:id/data/:collection` — records, oldest first; or with `ask`, those that answer a question best; or, with `format`, a file to download. Query: `q?: words anywhere in a record, where?: JSON — { "field": value, "other": { "<": 10 } } (=, !=, <, >, <=, >=, contains, in, empty), sort?: field or -field, limit?: ≤1,000 (default 100; 1,000 for a download), format?: csv|jsonl — the records as a CSV file (a row each) or JSON lines (one object a line), as an attachment, fields?: a,b,c — the fields to put in it (default: the collection's own), name?: the file's name`; or `ask: a question — by words (BM25) and by meaning (each record's vector, when search by meaning is on), joined by rank, mode?: auto|words|meaning, limit?: ≤100 (default 10)`. Returns: `{ records: [{ id, createdAt, updatedAt, …fields }], count — how many match in all }`; with ask, each record has its `score`, best first, and `meaning: boolean` says whether meaning took part.
- `POST /api/apps/:id/data/:collection` — adds a record. Body: `{ record: { …fields, id?: string — keeps this id (letters, digits, - and _) } }`. Gives 400 naming a field it does not have or a value that does not fit, 409 for an id it has, 413 past 64 KB or 20,000 records. Returns: `{ record }`.
- `PATCH /api/apps/:id/data/:collection/:recordId` — changes a record: the fields in `set` replace its own; null clears one. Body: `{ set: { …fields } }`. Returns: `{ record }`.
- `DELETE /api/apps/:id/data/:collection/:recordId` — removes a record. Returns: `{ ok: true, removed: 0|1 }`.
- `DELETE /api/apps/:id/data/:collection` — removes every record of a collection. Returns: `{ ok: true, removed: number }`.

## Apps: screens

An app's screen is a page of its own (Pages keeps it with its versions, and leaves it out of the library) that its page shows in place of its form. It is HTML as any page (`<body class="n-page">`, the kit's classes and colours) and runs with `window.hydor.app` for its app (`window.naget.app`, its name before the rename, works too):

- `hydor.app.flows` — `[{ id, title, inputs: [field], outputs: [{ id, label }] }]` ("run" is the main one); `hydor.app.collections` — `[{ name, fields }]`.
- `hydor.app.run(flow = "run", inputs)` — the run as it starts `{ id, status, … }`; `hydor.app.wait(id)` — `{ run, steps }` once it has ended; `hydor.app.get(id)`; `hydor.app.runs({ flow?, limit? })` — its latest runs.
- `hydor.app.data(name)` — `.find({ where?, search?, sort?, limit? })` → `{ records, count }`; `.search(question, { mode?, limit? })` → the records that answer it best, by words and by meaning; `.add(record)`; `.update(id, set)`; `.remove(id)`; `.watch(fn)` — called when the list changes.
- `hydor.app.on("run", fn)` — each change of its runs; `hydor.app.on("data", fn)` — a list's name when it changes.
- `hydor.app.chat(text, id?)` — a message to its agent: a new conversation, or more of the one named; `hydor.app.conversation(id)`; both give `{ id, status, working, messages: [{ from: you|agent, text, queued? }], error? }`. `hydor.app.chats()` — its latest conversations `[{ id, at, first, status }]`.
- App parts, elements that use it: `<n-form flow="run" submit="Words" keep>` (the flow's inputs as a form that runs it; the page hears an `n-run` event with `{ run, steps }`), `<n-button flow="name" inputs='{"field":"value"}' plain>Words</n-button>`, `<n-result flow="run">` (its latest answer, live), `<n-runs flow="run" limit="5">`, `<n-table data="list" columns="a,b" edit="aYesNoField" search remove where='{"read":false}' sort="-createdAt" limit="100">` (records, live), `<n-count data="list" where='{…}'>`, `<n-chat placeholder="Words" hint="Words" fresh>` (a conversation with its agent: the latest one unless `fresh`, with a box to write in, New conversation and Earlier conversations).

- `GET /api/apps/:id/screens` — its screens. Returns: `{ screens: [{ name, page, title, version }] }`.
- `GET /api/apps/:id/screens/:name` — one screen with its HTML. Returns: `{ screen: { name, page, title, version, html } }`.
- `GET /api/apps/:id/chats` — its conversations with its agent (a screen's `<n-chat>`), newest first, 20 at most. Each is a run of its own (kept apart from its runs): read it with `GET /api/apps/runs/:runId` (its first message is `run.inputs.message`, the replies `first` and `asks`), go on with it with `POST /api/apps/runs/:runId/ask`. Returns: `{ chats: [{ id, at, first — its first message, status }] }`.
- `POST /api/apps/:id/chats` — starts a conversation with its agent: its agent, model, tools, records and memory, and an `app_run` tool to run its flows and wait for what they give. Counts against its runs a day. Body: `{ text: string — the first message, ≤20,000 characters }`. Returns: `{ run: Run }` (source `chat`).
- `POST /api/apps/:id/screens` — gives it a screen: the HTML given, or one made from its parts (its form, its answer, a table for each list it keeps and a conversation with its agent when it keeps one, its runs). Body: `{ name?: string — "main" (the default) opens on its page, title?: string, html?: string — ≤2 MB }`. Gives 409 when it has a screen of that name. Returns: `{ screen, app: App }`.
- `PUT /api/apps/:id/screens/:name` — a new version of a screen (the earlier ones stay, in Pages). Body: `{ html: string, title?: string }`. Returns: `{ screen }`.
- `DELETE /api/apps/:id/screens/:name` — removes a screen and its page. Returns: `{ app: App }`.

## Apps: views

An app's view (`ui` in its recipe) is how its answer looks: pages of blocks, elements of its own that its values fill each time they show, and events, which say what a click does. A run's page shows the run's answer in it (**Plain answer** shows the card and tables instead); pages with `on: "app"` show on the app's own page in place of its form. A view draws in the sandbox pages use, with the kit's classes and colours (`var(--n-card)`, `var(--n-accent)`…), light or dark as the app is. A save checks it and says what to fix; app_try says which names it uses that a try's answer did not give.

**Ui**: `{ pages: [Page] (≤12), elements?: { [name]: { html: string — a template (≤40,000), css?: string — its style: rules for what is inside it, & for the element itself (≤20,000), description?: string } } (≤40; a name in small letters, digits and -, not a built-in's), events?: { [name]: [Action] (≤8) } (≤60), style?: string — CSS for the whole view (@keyframes, fonts, classes several share), widgets?: { [name]: Widget } (≤12; names apart from its elements and the built-ins), libs?: { [specifier]: exact version } (≤16) — npm packages its widgets import, loaded from jsDelivr: "three": "0.170.0", "chart.js/auto": "4.4.6", a stylesheet as its path ("leaflet/dist/leaflet.css": "1.9.4"); a package's other modules by path ("three/examples/jsm/controls/OrbitControls.js") come from the same version }`.
**Widget**: `{ code: string — an ES module (≤60,000) whose default export draws it: export default function (el, value, view) { … }; el: the element to draw in, value: what fills it (the block's data, as for an element), view: { with — the block's with, theme: { accent, fg, muted, line, card, soft, bg, dark } (rgb() colours), lang, asset(name) → its file's address, media(src) → an address as it shows, event(name, item?) — fires one of the view's events ({{event.*}} is the item's fields), set(name, value) — a value of the view's state, state, resize() }; it may return a function that cleans up, css?: string — its style (& for itself), description?, height?: CSS length — its height until it draws (default 320px) }`. A block places one as it places an element (`element: "<widget>"`), a template with `<n-widget name="<widget>" value="{{result.points|json}}"></n-widget>`. Its code runs in the view's sandbox: it reaches the app only through view.event and view.set.
**Page**: `{ id, title — its tab, on?: run|app (default run), tab?: false — no tab of its own, opened by an event, if?: Value — shown only when that is there, blocks: [Block] (≤40) }`.
**Block**: `{ title?, element?: one of its elements or widgets, or a built-in: text|markdown|list|checklist (ticks kept with the run)|table|chart (bars)|image|video|audio|map|plot|answer (the plain card)|form|runs|chat (the app's own page), html?: a template for this place, text?: Markdown with {{values}} — one of element, html and text, data?: Value — what fills it ("result.days", "inputs", "data.items", "state.picked", "page.item", "last.result"), each?: boolean — drawn once for each item, where?: { field: value | { "<"|">"|"<="|">="|"!="|"contains": value } } — an empty value matches all, sort?: field|-field, limit?: number, layout?: list|grid|row, width?: full|half|third|two-thirds, empty?: text — when there is nothing, if?: Value, with?: { columns?, label?, value?, flow?, limit?, placeholder?, submit? } — a built-in's settings }`.
**Media elements** take what fills them as addresses (`https://…`, `/app-media/…`, `asset:<name>`), media items `{ src, caption? }`, or rows with the field named in `with.src` (and `with.caption`): `image` (`with: { columns?: 1–6, height?: "180px", fit?: cover|contain }`; a click opens it large), `video` (a file, or a YouTube or Vimeo link, shown as its still and played over the page on a click: their players cannot run in the sandbox; `with: { poster? }`), `audio`. `map` draws rows with a latitude and longitude (`with: { lat?, lng? — the fields (lat/latitude, lng/lon/longitude unless named), label?, popup?, line?: true|"dashed" — joined in order, numbered?: true, zoom?, height?, tiles? — https://…{z}/{x}/{y} for other tiles, attribution?, event? — fired with the place clicked, empty? }`; OpenStreetMap's tiles by default). `plot` draws rows with Plotly (`with: { kind: line|bar|hbar|scatter|area|pie|donut|histogram|box|heatmap|scatter3d|line3d|surface, x?, y?: field or [fields], z?, series? — one trace per value of a field, stacked?: true (bar), title?, xLabel?, yLabel?, zLabel?, height?, event? }`), or a Plotly figure `{ data, layout }` (or a grid of numbers for a surface or heatmap) as its value. Templates may place them too: `<n-map value="{{result.stops|json}}" lat="lat" lng="lng" line>`, `<n-plot value="{{result.costs|json}}" kind="bar" x="day" y="cost">`. They load Leaflet and Plotly from jsDelivr, so they need the device online.
**Templates**: HTML with `{{name}}` (escaped), `{{#name}}…{{/name}}` (for each item of a list; once for a record, or a value that is there), `{{^name}}…{{/name}}` (when it is empty) and `{{name|format|format:arg}}`. Names: `result.<answer field>`, `inputs.<question>`, `run.status`, `run.createdAt`, `run.costUsd`, `app.name`, `state.<name>` (the view's own values), `page.item` (what its page was opened with), `data.<list>` (the records it keeps), `last.result` (on the app's own page: its latest run), `today`, `now`; in an element drawn for an item, the item's fields by name, `{{.}}` or `{{item}}` for the item, and `@index`, `@number`, `@first`, `@last`, `@key` (its id, else its place in the list, as in `state.done.@key`). Formats: date, shortdate, longdate, day, month, weekday, year, time, ago, number, percent, plus:n, times:n, upper, lower, slug, initials, short:n, host, url, count, first, last, take:n, join:sep, split:sep, unique:field, sort:field, where:field=value (or !=), sum:field, is:x, not:x, has:x, over:n, under:n, empty, or:text, yesno, markdown, lines, json; an argument that starts with $ is a value (`where:topic=$state.topic`). A **Value** is a name with formats, with ! in front for "not there" (`result.flags|count|over:2`). `data-event="name"` on anything makes a click on it the event (a form's submit, a field's change, a search box as it is typed in), and `data-key` on it names the item `@key` stands for. `asset:<name>` in a `src`, `href` or `poster` shows one of the app's own files. Scripts, frames and `on…` attributes are left out (a widget is the way to run code).
**Action**: `{ do, confirm?: text — asked first; no stops the event }` and one of: `page` (`page`, `item?`), `back`, `set` (`name`, `value`, `keep?`), `toggle` (`name`, `keep?`), `say` (`text`), `copy` (`text`), `open` (`url`: an address of this app, or https://…), `ask` (`text`: a follow-up to the run's agent; a one-task app's runs only), `run` (`flow`, `inputs?`, `as?`: its run as `state.<as>`, with `working`, `status`, `result`, `error`), `again` (`inputs`: the answers that change; a new run, its files along, which opens), `start` (`app`: an app's id or address, or `tpl:<id>` for a ready-made one; `inputs`; it opens), `data` (`op`: add|update|remove, `collection`, `record?`, `id?`). Their texts and values take names: `{{item}}` (what the element was filled with), `{{event.x}}` (the clicked element's `data-x`, a form's field `x`, a field's `{{event.value}}`, and `{{event.text}}`, what it says on screen, in the app's language) and every name a template takes; one `{{name}}` alone keeps its value as it is (a list stays a list). `keep` keeps a value with the run (or the app's own page). On a public page a view keeps only page, back, set, toggle, say, copy and open, and keeps nothing.

- `PUT /api/apps/runs/:runId/view` — keeps one value of a run's view (what `keep` keeps: a tick, a value an event set). Body: `{ name: string — up to four parts of letters, digits, - and _, joined by dots ("done.3"), value: any JSON | null — null removes it }`. Gives 400 for a name that cannot be one, 413 past 64 KB or 500 values. Returns: `{ view: { …what it keeps } }`.
- `PUT /api/apps/:id/view` — keeps one value of its own page's view (its pages with on: "app"), yours or a ready-made one (`tpl:<id>`, Explore's stories read). Body: as above. Gives 400 when its view has no page of its own. Returns: `{ view }`.
- `PUT /api/apps/:id/home` — the settings of an app that opens on its own page (yours, or `tpl:<id>` for a ready-made one such as Explore, the Weekly progress report or the Lab notebook): the answers its runs from there take, and Update automatically, a scheduled task (origin `daily:<id>`, listed with the others) that runs it with them at a time, every day or on some days of the week. Body: `{ inputs?: { question: answer } — only its form's questions are kept, daily?: { on?: boolean, time?: "HH:MM", days?: [0–6] | null — 0 is Sunday: [1,2,3,4,5] on weekdays, [5] once a week on Fridays; null every day } }`. Gives 400 when it has no page of its own, for a time or days that are not ones, or for turning it on while a question it needs is empty (or it needs a file each time); 503 without scheduled tasks. Returns: `{ home: Home }`.

## Apps: as a file

An app travels as one file: a .json, or a .hydor-app (a zip of its app.json, data/ with its records, assets/ with its own files, and apps/ with the apps its steps call, their files in apps/<address>/). ## Pages (the Library)

Agents also have their own tools for pages: show_html shows a page in the conversation, save_page saves a new page or (with an id) a new version of one, save_slides, save_doc, save_sheet, save_latex and save_notebook do the same for slide decks, documents, spreadsheets, LaTeX documents and Jupyter notebooks (each with libraryFolder: a Library folder by its name or a path such as "Thesis/Drafts", made when missing, and description: what it is, under 100 words, given with each new one; with an id and nothing else to save, the title and description change alone), get_page lists them all (with each one's project and folder, and with few, their descriptions), finds the ones that fit a query (by their titles and descriptions, by words and by meaning) or reads one (a page with its stored data, another kind as it is kept), export_page saves one as a file (PDF, Word, PowerPoint, Excel, CSV, Markdown, LaTeX, a notebook, a Python script or a web page). ## Plugins (for every agent)

Settings → Agents → Plugins. A plugin is a folder in the Agent Plugins 1.0 format (plugin.json, skills/, mcp.json; Claude Code's layout is read too) with the app's own extension `com.naget.agent` for what it needs. Every agent the app starts gets the enabled ones whose setup is done. `:name` is a plugin's name (lowercase letters, digits, dashes and dots). A plugin view (`plugin` below) is `{ name, title, version?, description?, author?, homepage?, repository?, license?, keywords: string[], category?, icon?, format: 'agent-plugins'|'claude', source: { kind: 'builtin' } | { kind: 'git', url, ref?, subdir?, commit? } | { kind: 'file', file } | { kind: 'folder', path, mine?: true (made in the app's editor) }, installed: boolean, enabled: boolean, setup: { state: 'none'|'installing'|'ready'|'failed'|'outdated', error?, at? }, skills: [{ name, description, category?, shadowedBy? (the skill agents get in its place) }], servers: [{ name, type: 'stdio'|'streamable-http'|'sse', command?, args?, url?, problem? }], instructions: boolean, files: [{ name, bytes }] (its own files), editable: boolean, claudeOnly: string[] (Claude Code parts left out), requires: { plugins: [{ name, range }], npm: { name: version }, pip: string[], python?, commands: [{ name, hint?, optional? }], files: [{ url, path, sha256?, size? }], keys: [{ name, description?, optional?, url? }] }, missing: { commands, keys, plugins } (what is not here), dependents: string[] (installed plugins that need it), agents: ('claude'|'codex'|'custom'|'acp')[], problems: string[], root (its folder), data (its data folder), installedAt?, readme? (details only) }`. A job (adding, setting up, updating) is `{ id, plugin, action: 'install'|'setup'|'update', state: 'running'|'done'|'failed', steps: [{ label, state: 'waiting'|'running'|'done'|'failed' }], log (the output's end), error?, startedAt, endedAt? }`; the pages also get it as it runs.

- `GET /api/plugins` — every plugin: installed and built in. Returns: `{ installed: [plugin], available: [plugin] (built-in ones not added yet), jobs: [job] (running, or ended in the last minute), folders: { installed, data, mine } }`.

Body: `{ url: string (owner/repo, https://…, a GitHub link to a folder …/tree/<branch>/<folder>, or git@host:path), ref?: string (a branch or tag), subdir?: string (a folder inside the repository) }`, or `{ file: { name, data: base64 } }` (a .zip, up to 160 MB, its plugin.json at the top or in its one folder), or `{ path: string (a folder; ~ works) }`. Returns: `{ token (for install, valid 30 minutes), view: plugin, brings: string[] (built-in plugins it needs that are added first), unavailable: string[] (plugins it needs that nobody has: it cannot be added), replaces?: string (a plugin of its name is installed) }`. 400 with the reason when it is not a plugin, its manifest is invalid, or Git fails.

## Experiments (System → Experiments)

Jobs that wait for free GPUs (or a cluster's queue), run on their own and are kept as records. Agents in sessions start and read runs with their own tools (experiment_run, experiment_sweep, experiment_list, experiment_get, experiment_stop, experiment_table); these routes serve the page and app_api. A run (`run` below) is `{ id, name, group — its experiment, command, cwd, where: "local" | "m:<machine>" | "c:<cluster>", gpus, gpuMemGb?, cpus?, memGb?, hours?, partition?, env?, params?: { name: value }, seed?, tags?, priority?, metricsFile?, scoresFile?, better?: { metric: "max"|"min" }, onCall?: { on, act: "tell"|"agent", watch?: ("nan"|"oom"|"stall"|"crash"|"diverge")[], stallMinutes?, rules?, agent?, model? }, notify?: { done?, failed?, when?: { metric, op: ">"|"<"|">="|"<=", value } }, report?, sweep?, project?, status: "queued"|"waiting"|"starting"|"running"|"done"|"failed"|"stopped"|"lost", why? — what it waits for or why it ended, in words, createdAt, startedAt?, endedAt? — ms, exitCode?, host?, gpuIds?, commit?, branch?, dirty?, untracked?, patchPath?, environment?: { host, Python, PyTorch, CUDA, driver, GPU… }, folder? — its own folder (log.txt, changes.patch, exit, metrics.json, scores.jsonl), logPath?, metrics?: { last: { metric: number }, best: { metric: number }, step? }, startedBy?: { session? | app? | page? }, from? — the run it is a new run of, remote?: { machine, id } — kept on another machine, machine?: { id, name } — listed from another machine, clusterJob?, stopping? — being stopped (why), outputAt?, events?: [{ at, kind: "queued"|"waiting"|"started"|"nan"|"oom"|"stall"|"crash"|"diverge"|"agent"|"stopped"|"done"|"failed"|"note", text, session? — the agent on call's }] }`.

- `GET /api/experiments/runs` — runs, newest first. Query: `group?`, `tag?`, `status?` (comma-separated, or `active` for those not ended), `cwd?` (runs in that folder or under it), `project?`, `sweep?`, `q?` (words in the name, experiment, command or id), `limit?` (default 200, at most 1000), `everywhere?` (`1`: every connected machine's runs too, each with `machine`). Returns: `{ runs: run[] }`.
- `GET /api/experiments/runs/:id` — one run with its events, its metrics' series and the end of its log (a run kept on another machine is read there). Query: `lines?` (default 300, at most 5000), `log?` (`0`: no log). Returns: `{ run, series: { metric: [step, value][] } — a few hundred points each, log: string, logSize: number — bytes }`.
- `GET /api/experiments/runs/:id/log` — the log after a point, to follow it. Query: `from` (bytes, as logSize or next gave). Returns: `{ text, next — where the next call starts, size }` (at most 256 KB at a time).
- `GET /api/experiments/runs/:id/patch` — the changes not committed it ran with. Returns: `{ patch: string | null }`.
- `POST /api/experiments/jobs` — a new job: in line here, sent to a cluster, or sent to another machine (kept there, followed here). Body: `{ command: string, cwd?: string — a folder that is there (default the app's), where?, gpus?: number — default 1 on a computer with GPUs, else 0, gpuMemGb?: number — free memory each (default a GPU almost all free), name?, group?, params?, seed?, tags?, priority?: -100–100, hours?, cpus?, memGb?, partition?, env?, metricsFile?, scoresFile?, better?, onCall?, notify?, report? }` (`{name}` placeholders in the command are filled from params and seed). Returns: `{ run }`; 400 says what is wrong.
- `POST /api/experiments/runs/:id/stop` — stops a run: one in line at once, one running with Ctrl-C, then harder after 10 s (it ends as stopped); on a cluster with scancel, on another machine there. Body: `{ why?: string }`. Returns: `{ run }` (`stopping` set while it ends).
- `POST /api/experiments/runs/:id/again` — runs it again, as it was or with changes. Body: any field of a new job, replacing the run's. Returns: `{ run }` (its `from` is the first run).
- `DELETE /api/experiments/runs/:id` — deletes an ended run's record, events, series and its own folder (never the job's own files). Returns: `{ ok: true }`; 409 while it has not ended.
- `GET /api/experiments/queue` — the queue now. Returns: `{ running, waiting, gpus: [{ index, name, memUsed, memTotal — MiB, util — %, run? — the run of yours holding it }], gpuNote?, cpuRunning, cpuSlots }`.
- `GET /api/experiments/settings` — Returns: `{ cpuSlots — jobs without a GPU running at once here }`.
- `PUT /api/experiments/settings` — Body: `{ cpuSlots: 1–64 }`. Returns: the settings.
- `GET /api/experiments/groups` — the experiments runs belong to, the latest first. Returns: `{ groups: [{ name, runs, done, lastAt }] }`.
- `POST /api/experiments/sweeps` — starts a sweep: one run per combination of the settings' values, in one experiment. Body: `{ command — with {name} for each setting, params: { name: values[] }, group: string, mode?: "grid"|"random", maxRuns? (at most 200), earlyStop?: { metric, better?: "max"|"min", afterSteps? } — stop a run worse than the median of the others at the same step }`, and any field of a new job for all its runs. Returns: `{ sweep: { id, group, command, params, mode, maxRuns?, earlyStop?, createdAt }, runs: run[] }`; 400 when a setting has no placeholder (nothing starts).
- `GET /api/experiments/sweeps/:id` — a sweep and its runs, oldest first. Returns: `{ sweep, runs }`.
- `GET /api/experiments/clusters` — the clusters runs can go to. Returns: `{ clusters: [{ id, name, host, kind: "slurm"|"ssh", workdir, setup?, partition?, account?, checked?: { at, ok, text } }] }`.
- `POST /api/experiments/clusters` — adds a cluster, or changes one (with its id). Body: `{ id?, name, host — an entry of ~/.ssh/config or user@host, kind?: "slurm"|"ssh" (default slurm), workdir? (default ~/hydor-runs), setup? — lines run before each job, partition?, account? }`. Returns: `{ cluster }`.
- `POST /api/experiments/clusters/check` — Check: `ssh host true`, then sinfo (SLURM) or nvidia-smi and tmux (plain SSH). Body: `{ id }` (a cluster kept: the result is kept with it) or `{ host, kind }`. Returns: `{ ok: boolean, text — what it found or what went wrong }`.
- `DELETE /api/experiments/clusters/:id` — removes a cluster. Returns: `{ ok: true }`; 409 while runs go on it.
- `GET /api/experiments/tables` — the results tables kept, newest first. Returns: `{ tables: table[] }`, a table being `{ id, spec, rows: [{ key, label, runs: string[], cells: [{ mean, std, n, best?, p?, pAdj? — after Holm's correction, significant? }] }], latex, markdown, csv, madeAt, footnote?, notes?: string[], tests?: string[] — each column's test }`.
- `POST /api/experiments/tables` — makes a results table and keeps it. Body: `{ runs?: string[] — run ids, group?: string — or every finished run of an experiment, rows?: "group" | "param:<name>", columns: [{ metric, better?: "max"|"min" (default by the name), label?, digits?, value?: "last"|"best", scale? }], baseline? — a row's key (default the first), test?: "welch"|"paired"|"bootstrap"|"none" (left out: paired over examples when the runs kept scores, else over seeds when they pair, else Welch), alpha? ## Confidential sessions

A confidential session (`extra.confidential: true`, set with `POST /api/sessions`) runs on Custom with a model on this computer or your private network, and nothing of it leaves the computer. The server keeps it so: its messages are refused while its model is elsewhere (409), and so are a switch to such a model, a hand-off, a read-only link, turning it off and memory on. Agents in other sessions don't reach it: app_api answers "That session is confidential" for its addresses and leaves it out of lists.

- `GET /api/confidential` — what a confidential session can use here. Query: `prefer?: string — a model id that leads the list when it is one of them`. Returns: `{ models: string[] — Custom's models on this computer or your private network (Ollama at a local address but not its cloud models, vLLM, endpoints at localhost, 127.x, ::1, 10.x, 172.16–31.x, 192.168.x, fc00::/7 or a .local name), the best first: native tool calls, then the largest; sandbox: boolean — commands run without network here (bubblewrap; false: each command asks the user); helper: boolean — the helper model runs here (it names confidential sessions; else their first words do) }`.

## Sharing a project (Projects → Share)

The owner invites people into one project, each with a link of their own (`/p/<token>`): they see its documents, sessions, runs and reading list, and comment on its documents under their name, or with `edit` change them too. Never the agents, files, settings or other projects. A person: `{ id ("ps…"), space — the project's id, name, role: "comment" (View and comment)|"edit" (Edit documents), createdAt, expiresAt? — when the link stops by itself (none: when it is stopped), seenAt? — when they last had it open, views — visits (half an hour apart), activity?: { at, what: "comment"|"reply"|"edit"|"read", page? — a Library item's id, title? } }`. Only a hash of the token is kept: it is returned once, when the link is made.

- `GET /api/projects/:id/shares` — who the project is shared with, the newest first (one whose link ran out stays listed a month). Returns: `{ shares: [Person], owner: string — the name they see the owner's comments under ("Owner" until set) }`. 404 "No such project".
- `POST /api/projects/:id/shares` — shares the project with someone. **Careful**: whoever has the link sees the project's documents, sessions, runs and reading list, and comments on (with edit, changes) its documents. Body: `{ name: string — required, cut at 60; role?: "comment"|"edit" — default "comment"; days?: number|null — how many days the link works, at most 365, default 30; null: until it is stopped }`. Returns: `{ share: Person, token }`; their address is `/p/<token>` (another machine's project: `/m/<machine>/p/<token>`). 400 without a name or with another role; 409 past 50 people.
- `PATCH /api/projects/:id/shares/:share` — changes what someone may do or until when; their link stays the same. Body: `{ role?: "comment"|"edit"; days?: number|null — from now, null: until stopped; name?: string }`. Returns: `{ share: Person }`. 404 once sharing with them stopped.
- `POST /api/projects/:id/shares/:share/link` — a new link for someone: the old one stops at once (and says so when opened); they stay the same person, their comments theirs. Returns: `{ share: Person, token }`.
- `DELETE /api/projects/:id/shares/:share` — stops sharing with someone: their link stops at once; what they wrote stays, under their name. Returns: `{ ok: true }`.
- `PUT /api/projects/sharing` — the name people see the owner's comments under, for every project. Body: `{ owner: string — cut at 60; "" for "Owner" }`. Returns: `{ owner }`.

A person's comments show in documents and LaTeX documents as `by: "person"` with their `name` (see **Comment** under Library), in `GET /api/inbox` (`kind: "comment"`) until someone replies or resolves them, and to agents through get_page under their name. A version a person saved has `who`.

## Engineering (Git: find what broke it; campaigns)

These use the routes above; Git's own routes are the user's alone.

- The engineering examples (Settings → Scheduled tasks → Start from an example → Engineering) are scheduled tasks: make one with `POST /api/tasks`, a repository folder as cwd and the prompt and schedule you would write, with `origin` set to say which example it is: "template:ci-doctor:github" (or :gitlab, :buildkite, :circleci), "template:issue-triage", "template:dependencies", "template:incident:sentry" (or :grafana, :datadog, :betterstack, :other). The task's row then says where its webhook address goes. CI doctor's filter: `{ path: "body.workflow_run.conclusion", value: "failure" }` on GitHub, `body.object_attributes.status` on GitLab, `body.build.state` on Buildkite and `body.workflow.status` on CircleCI each `"failed"`; Issue triage's: `{ path: "body.action", value: "opened" }`; the incident responder skips resolved notices (`{ path: "body.action", value: "resolved", skip: true }` for Sentry, `body.status` "resolved" for Grafana, `body.transition` "Recovered" for Datadog).
- Find what broke it starts a session: `POST /api/sessions` with cwd the repository's folder, `worktree: true`, and a prompt that says where it worked (a tag or commit), where it is broken, what is broken and, if there is one, a command that fails while it is broken; its agent follows the git-bisect skill.
- A campaign is a swarm: `POST /api/sessions` with `extra: { swarm: "campaign" }` and cwd in a git repository; `GET /api/swarm/:key` gives its parts and how each stands, `POST /api/swarm/:key/stop` stops its members.

## Not for agents

These routes serve the app’s own pages, need the user’s browser, or are the user’s alone; app_api refuses the ones an agent must never use.

- `POST /api/sessions/:key/approvals/:id` — answers an approval, question or form (`{ decision, message?, answers?, form? }`): the user's own decision; agents never answer another session's approvals.
- `POST /api/uploads` — saves files for an answer to a question; it only serves the approval cards.
- `GET /api/sessions/:key/image` — serves a message's picture as raw bytes.
- `GET /api/sessions/:key/queue/:id/attachment` — serves a queued message's attachment as a raw file.
- `GET /api/find/usage`, `POST /api/find/usage` — the search box's own record of what the user picks and visits; writing to it would skew what it suggests.
- `/ws` — the live socket the pages listen on (it streams).
- `GET /guest-api/:token` and the `/g/<token>` page — the public view of a read-only link, for guests.
- `/p/<token>` and `/p-api/<token>/…` — a shared project as the person at its link sees it (their own calls: the project, its documents and comments, its sessions, Edit documents' saves, the editors' pictures, files and LaTeX); the token is the permission, and an agent has the owner's routes above.
- `GET /agent/run/:token/assistant` — Custom's own runtime asks it before each turn which tools its session's assistant allows; it needs the running agent's token.
- `GET /api/memory/export` — downloads every active note to the browser as a file (`?format=json` with histories, or `?format=md`); `GET /api/memory/entries` gives the same notes as JSON.
- `POST /api/skillpack/proposals/:id/approve` — the user's own answer to a skill an agent proposed in a session (like an approval), given on the card, in Settings → Skill library or from the inbox; it saves a file every agent then reads. (Body: `{ text?: string, scope?: 'library'|'space' }`, the whole SKILL.md as edited, and for a session in a project where to keep it.)
- `POST /api/skillpack/proposals/:id/dismiss` — the same answer as a no. (Body: `{ note?: string }`, told to the proposing agent.)
- `POST /api/browser/profiles/:id/open` — opens a profile's browser so the user can sign in to sites through the live view: it needs the user at the screen.
- `GET /api/browser/sessions/:key` and `PATCH /api/browser/sessions/:key/options` — a session's browser view, profile and site lists, for the page. Agents have their own browser tools.
- `POST /api/browser/sessions/:key/open`, `/close`, `/watch` — the page opening or closing a session's browser, and asking for live-view frames.
- `POST /api/browser/sessions/:key/takeover`, `/input`, `/navigate`, `/nav`, `/tab`, `/dialog` — the user driving the browser by hand.
- `POST /api/browser/sessions/:key/asks/:id` — the user's own answer to what the browser waits for them on (Done, Can't, allowing a local address).
- `GET /api/browser/sessions/:key/steps/:n` — a step's picture as a raw JPEG; `<n>.json` says where the step acted on it, for its marks: `{ marks: [{ x, y — fractions of the picture, act: click|double|move|type|select|scroll|…, box? — the field typed into, dir? — a scroll's way }] }`.
- `GET /api/computer/sessions/:key/steps/:n` — a computer step's picture of the screen as a raw JPEG; `<n>.json` where its actions were on it, the same way (a drag with `from`).
- `GET /api/documents/preview?path=` — reads a file's contents for the file viewer.
- `POST /api/documents/pages` — has LibreOffice lay an Office file out as pages for the viewer.
- `GET /api/documents/pages.pdf` — sends that PDF file itself (raw file).
- `GET /api/pdf/info?path=` — a PDF's pages, form fields (each with its kind, value, choices, the words printed beside it and its boxes) and protections, for Files' **Fill & sign**. Agents use pdf_form and pdf_look.
- `GET /api/pdf/page?path=&page=&width=&fields=0` — a page of a PDF as a picture (raw PNG), without its form's fields with `fields=0` (Fill & sign draws its own over it).
- `GET /api/pdf-notes/page?path=&page=&width=` — a page of a PDF as a picture (raw PNG) for Files' reader, without the highlights saved into the file while the app keeps them as notes (the reader draws its own).
- `GET /api/pdf-notes/area?path=&page=&x=&y=&w=&h=&width=` — a part of a page as a picture (raw PNG): an area picked in the reader. Agents see the areas' pictures with pdf_notes.
- `POST /api/pdf/save` — Fill & sign's **Save**: the fields filled and what was placed on the pages (text, ticks, crosses, signatures), written as a copy beside the file or over it (its old version to the Trash). Agents use pdf_fill and pdf_write, and their signature tool.
- `GET /api/pages/:id/export` — sends a page, deck, document, spreadsheet, LaTeX document or notebook as a file itself (PDF, Word, PowerPoint, Excel, CSV, Markdown, LaTeX, a notebook (.ipynb), a Python script (.py) or a web page; the **Export** menu), or a deck's slides as pictures (`format=png`: a zip of the slides the slideshow shows, or with `slide=<number>` that slide alone as a PNG). A PowerPoint file's answer has an `X-Export-Note` header that says which fonts went inside it and which of them are compressed. Agents make the file with their export_page tool, which writes it where they can hand it over with present_files (and says the same of its fonts).
- `POST /api/pages/docs/print` — a document as it prints, changes not yet saved included (the editor's **Tools → Print**). Body: `{ model: object — the document, as save_doc takes it, title: string — its name }`. Returns: `{ html }`, its pages with their header, footer and page numbers.
- `GET /api/pages/assets/:sha`, `GET /api/pages/picture`, `GET /api/pages/fonts.css`, `GET /api/pages/fonts/*` — the pictures and Google fonts the slides and document editors show, and the pictures from the web in agents' replies (`/api/pages/picture?url=`: fetched by this server, public addresses only, and remembered for a while), served as they are (raw files).
- `POST /api/pages/videos` — the slides editor sending a video from a device (**Insert → Video → From this device**, or a video dropped on a slide), as raw bytes in pieces of ≤32 MB, in order: `?upload=<its own id: 8–40 letters a–z and digits>&offset=<where the piece starts>&total=<the video's bytes, ≤200 MB>`. Returns `{ received }` after each piece but the last, then `{ src: "naget-video:<sha>" — a video part's src, mime, bytes }`; 409 for a piece out of order, 413 over 200 MB, 415 when it is no MP4, MOV or WebM video. Agents put a video file on a slide with save_slides instead (its path as the video's src).
- `GET /api/pages/videos/:sha`, `GET /pg/video/:sha/:sig` — a deck's videos from a device, served as they are (raw files, with range requests so a player seeks): the first to the app's own pages, the second, signed by this server, where the app's sign-in is not (a deck's own page, its published copies, the conversation's frame).
- `GET /api/pages/tex/:key/:page`, `GET /api/pages/tex/:key/pdf` — a typeset LaTeX document's pages as pictures and its PDF, served as they are (raw files).
- `POST /api/voice/transcribe` — the page's microphone: the body is a raw recording.
- `POST /api/voice/command` — the hands-free page: it acts at once (starts sessions, answers approvals) with no card for the user to OK first.
- Deep research, child sessions, swarm, second opinion, model arena and spending caps: none left out; all their routes are listed above.
- `GET /api/search` (no path after it) is the sidebar's search through sessions, not web search: it belongs to Sessions.
- `POST /api/apps/:id/keys` — makes an API key whose value is shown only once; the person makes keys in the app's API & sharing tab.
- `POST /api/apps/:slug/run` and `GET /api/apps/:slug/run/:runId` — for programs outside Hydor, with the app's key (`Authorization: Bearer napp_…`, 30 calls a minute). Body `{ inputs | answers at the top level, files?, wait? (≤900 s) }`; the answer has `steps: [{ step, title, status, error? }]` for an app with steps. These calls can wait up to 900 s. Inside the app, use `POST /api/apps/:id/runs` and `GET /api/apps/runs/:runId`.
- `GET /api/apps/batches/:batchId/csv` — a CSV file download; `GET /api/apps/batches/:batchId` has the same data as JSON.
- `GET /a-api/:slug`, `POST /a-api/:slug/run`, `GET /a-api/:slug/run/:id` — a public page's own calls for its visitors (told apart by a cookie; runs start only from the page itself).
- `POST /api/sites` — publishes at once, without asking. Agents publish with their own publish_site tool, whose card lets the user decide and pick a private or public link.
- `POST /api/sites/requests/:id` — the user's answer on a publish card (Publish or Not now, and the kind of link).
- `GET /pg/:token`, `GET /pg/:token/html`, `GET /pg/:token/manifest.webmanifest`, `POST /pg/:token/storage` — a saved page's own address, for the browser that opens it (no sign-in; its storage calls are taken only from that page). Agents read and change a page's data with `POST /api/pages/:id/storage`.
- `GET /site/:token`, `GET /site/:token/*` — the published sites themselves, served to visitors.
- `GET /htmlframe` — the sandboxed frame every page renders in.
- `POST /hooks/:secret` — a webhook task's address, for outside services: no sign-in (the secret in the path is the permission), and it may require a signature. An agent starts a run with POST /api/tasks/:id/run.
- `GET /api/automations/proposals/:id`, `POST /api/automations/proposals/:id/confirm`, `POST /api/automations/proposals/:id/decline` — the card for a task an agent proposed with schedule_task or update_task: only the user answers it, and the agent hears the answer as a message.
- `POST /api/connections/secrets`, `PATCH /api/connections/secrets/:name` — these set a key's value, hosts, whether commands may use it, or how it is sent. Agents never set a key's value or where it may go: the user does, in Settings → Connections → Keys or on the key card.
- `POST /api/connections/:id` with `key` or a secret field — this sets a key's value.
- `GET /api/signatures/:id/image` — a saved signature's picture (raw PNG), for the app's own pages: agents never see it.
- `POST /api/signatures`, `PATCH /api/signatures/:id`, `DELETE /api/signatures/:id` — keep a signature drawn, typed or uploaded on the pad (Body: `{ name: string, kind: 'signature'|'initials', image: string — a base64 PNG with a see-through background, keep?: false — kept for a day }`), rename it, draw it again (`image`), keep one given for a day for good (`keep: true`), or delete it: the user's own, in Settings → App → Signatures, the documents editor and the cards. Agents ask for one with ask_signature.
- `POST /api/signatures/:id/asset` — puts a saved signature into a document of the Library as one of its pictures (the editor's **Insert → Signature**). Returns: `{ src: "naget-asset:<sha>", width, height }`. Agents place one with place_signature, which the user allows on a card.
- `GET /api/signatures/previews/:token` — a page as an agent would sign it, for the card that asks the user (raw PNG).
- `POST /api/connections/requests/:id` — the user's answer to a key or sign-in card; it carries the values.
- `POST /api/connections/requests/:id/dismiss` — the user's "Not now" on another session's card, which tells that session's agent.
- `POST /api/connections/:id/oauth`, `GET /api/connections/flows/:flow` — a browser sign-in; it needs the user's browser.
- `GET /connections/callback` — the OAuth callback.
- `POST|GET|DELETE /connections/mcp/:token/:app`, `GET /connections/launch/:token/:app`, `POST /connections/elicit/:token/:app` — how running agents reach their connected accounts. These use run-token addresses and work from this machine only.
- `POST /api/setup/mcp/login` — opens a terminal for the server's sign-in.
- `GET /api/push`, `POST /api/push/subscribe`, `POST /api/push/unsubscribe` — they need the browser's own push subscription: only the device itself turns Notify this device on or off.
- `POST /api/accounts/:agent/login` — starts a Claude Code or Codex sign-in; the user must open the link and approve in their browser.
- `POST /api/accounts/:agent/login/:flow` — finishes a sign-in with the code or localhost address the user copies from their browser.
- `DELETE /api/accounts/:agent/login/:flow` — cancels a sign-in in progress (part of the user's sign-in dialog).
- `POST /api/accounts/:agent/logout` — signs a CLI (or an added account, `?account=`) out for every terminal and editor; the user's own call, from Settings → Accounts.
- `PUT /api/models` with `openrouterKey`, `hfToken` or `endpoint.apiKey` — key values; the user types them in Settings.
- `POST /agent/run/:token/ensure`, `/describe`, `/review`, `GET /agent/run/:token/custom`, `/context`, `/assistant` — Custom's own calls during a run (start its vLLM model, describe images, Auto mode's check, settings, instructions), allowed only with that run's token.
- `/api/fs/*` (list, read, stat, raw, view-link, write, mkdir, rename, delete, exists, search, find, diff, recent, upload) and `/view/:token/*` — files: agents read and change files with their own tools, with the user's approvals; raw and view serve files to the browser.
- `/api/git/*` (repos, clone, clone/:id, repo, fetch, sync, pull, push, fetch-all, remote, diff, show, log, commit, message, discard, discard-hunk, ignore, revert, undo-commit, continue, abort, branches, switch, branch-delete, branch-rename, merge, compare, branch-only, tag, push-tags, stash, stash/show, stash/:action) — the Git page's own calls; agents use git through their own command tool, with the user's approvals.
- `/api/terminals*` (list, create, rename, close, context, complete, ask), `/ws/term/:id` and `/api/terminal-history` — the user's shells and their typed history; the socket streams.
- `/api/kernels*` and `/nbframe` — Jupyter kernels, run from the notebook page.
- `/api/uploads` — attachments sent with messages.
- `POST /api/access-tokens` and `POST /api/mcp/tokens` — each returns a secret token, shown once to the user (`{ id, token }`); the user makes them in Settings.
- `POST /api/preview/link` — a one-time link (valid 2 minutes) that signs the user's browser in to the preview port.
- `POST /api/preview/live` — opens a dev server's page in the app's own browser and streams it to the Preview page, where the user's browser can't reach the preview port: the user drives it from there (its frames and input go through the browser's live-view calls above, under the key it returns).
- `POST /api/auth/password` and `POST /api/auth/logout` — the password, and this browser's sign-in.
- `POST /mcp` and `POST /mcp/run/:token` — the MCP endpoints themselves (agents elsewhere with a token; each session's own tools).
- `/g/:token` and `/guest-api/:token` — what a guest's browser reads through a read-only link.
- `/p/:token` and `/p-api/:token/*` — what a person's browser reads and sends through a shared project's link.
- `/m/:id/*` — the app's pages forwarding to another machine's API and sockets.
