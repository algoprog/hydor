# Πράκτορες, λογαριασμοί και μοντέλα

Το Hydor εκτελεί διάφορους πράκτορες τεχνητής νοημοσύνης: Claude Code, Codex, Custom (ο δικός πράκτορας της εφαρμογής, για οποιοδήποτε μοντέλο) και άλλους πράκτορες που μιλούν ACP, όπως Gemini CLI, OpenCode, Qwen Code, Goose, Grok Build ή Antigravity CLI (ο πράκτορας της Google για το πακέτο Google AI που έχετε). Αυτό το θέμα εξηγεί πώς διαφέρουν, πώς εγκαθίστανται και παραμένουν ενημερωμένα τα προγράμματά τους, πώς γίνεται η σύνδεσή τους (και με περισσότερους από έναν λογαριασμούς) και από πού προέρχονται τα μοντέλα του Custom: από το OpenRouter, το Ollama, από μοντέλα του Hugging Face που τρέχουν σε αυτόν τον υπολογιστή ή από οποιοδήποτε endpoint συμβατό με OpenAI.

![Επιλογή του πράκτορα στην αρχική σελίδα: Claude Code, Codex ή Custom](images/agents-models.webp)

## Ποιον πράκτορα να χρησιμοποιήσω;

Πράκτορας είναι το πρόγραμμα που κάνει τη δουλειά σε μια συνεδρία: διαβάζει το μήνυμά σας, χρησιμοποιεί εργαλεία (αρχεία, εντολές, το διαδίκτυο) και απαντά. Το μοντέλο είναι η τεχνητή νοημοσύνη πίσω από αυτόν. Κάθε πράκτορας εδώ παίρνει την ίδια βοήθεια από την εφαρμογή (αναζήτηση στον ιστό, το πρόγραμμα περιήγησης, τη μνήμη, τις δεξιότητες, τις συνδέσεις σας), αλλά διαφέρουν ως προς την προέλευση των μοντέλων τους.

- **Claude Code** (Anthropic). Τρέχει με το πακέτο Claude που έχετε ή χρεώνει έναν λογαριασμό Anthropic API. Τα μοντέλα του είναι της Anthropic (Opus, Sonnet, Haiku). Έχει δικά του όρια χρήσης, που εμφανίζει η [σελίδα Χρήσης](/usage).
- **Codex** (OpenAI). Τρέχει με το πακέτο ChatGPT που έχετε. Τα μοντέλα του είναι της OpenAI. Έχει επίσης όρια χρήσης, που εμφανίζονται στη σελίδα Χρήσης. Το Codex έρχεται με την εφαρμογή.
- **Custom**, ο δικός πράκτορας της εφαρμογής. Τρέχει τα μοντέλα των πακέτων Claude και ChatGPT που έχετε (μέσω των συνδέσεων του Claude Code και του Codex) και οποιοδήποτε μοντέλο προσθέσετε στις [Ρυθμίσεις → Πράκτορες → Μοντέλα](/settings?s=models): μοντέλα μέσω OpenRouter, μοντέλα σε αυτόν τον υπολογιστή (με Ollama ή vLLM) ή οποιοδήποτε endpoint συμβατό με OpenAI. Χρησιμοποιήστε το για ανοιχτά μοντέλα, φθηνότερα μοντέλα ή μοντέλα που δεν φεύγουν ποτέ από τον υπολογιστή σας. Δείτε [Custom, ο δικός πράκτορας της εφαρμογής](/guide/custom).
- **Πράκτορες που μιλούν ACP**: Gemini CLI, OpenCode, Qwen Code, Goose, Kimi CLI, Auggie, Grok Build (ο πράκτορας προγραμματισμού της xAI, με τα μοντέλα Grok), Antigravity CLI (ο πράκτορας προγραμματισμού της Google, με το πακέτο Google AI που έχετε) και άλλοι, ή μια δική σας εντολή. Το ACP (Agent Client Protocol) είναι ένας κοινός τρόπος για να μιλά μια εφαρμογή με ένα πρόγραμμα πράκτορα. Καθένας συνδέεται μία φορά και χρησιμοποιεί τα δικά του μοντέλα: οι περισσότεροι μέσα στο δικό τους πρόγραμμα, το Grok Build και το Antigravity CLI στις [Ρυθμίσεις → Πράκτορες → Λογαριασμοί](/settings?s=accounts). Από τις 18 Ιουνίου 2026, το Gemini CLI δεν εξυπηρετεί πλέον τα πακέτα Google AI Pro και Ultra (ούτε το Gemini Code Assist για ιδιώτες): για αυτά τα πακέτα ο πράκτορας τερματικού της Google είναι το Antigravity CLI (δείτε [Antigravity CLI](#antigravity-cli)). Το Gemini CLI παραμένει για κλειδί Gemini API ή για άδεια Gemini Code Assist Standard ή Enterprise.

Τι μπορεί να κάνει ο καθένας στην εφαρμογή:

- Στόχοι (η εφαρμογή κρατά τον πράκτορα να δουλεύει, γύρο μετά από γύρο, μέχρι να ισχύσουν οι έλεγχοι που έχετε συμφωνήσει· δείτε [Στόχοι](/guide/goals)): κάθε πράκτορας, Claude Code, Codex, Custom και οι άλλοι πράκτορες ACP. Ένα `/goal` που πληκτρολογείται σε συνομιλία Claude Code ή Codex είναι ο δικός τους, απλούστερος στόχος. Forks (αντίγραφο της συνεδρίας από μια προηγούμενη απάντηση): Claude Code, Codex και Custom. Όχι οι άλλοι πράκτορες ACP.
- **Συνέχεια στο…** (παράδοση της συνομιλίας σε άλλον πράκτορα): από το Claude Code ή το Codex, στο άλλο από τα δύο ή στο Custom.
- Ένταση σκέψης (πόσο σκληρά σκέφτεται το μοντέλο): Claude Code, Codex, Grok Build και Antigravity CLI, καθώς και κάθε άλλος πράκτορας ACP τα μοντέλα του οποίου την προσφέρουν.
- Περισσότεροι από έναν λογαριασμοί και αλλαγή λογαριασμού όταν συμπληρωθεί ένα όριο: Claude Code, Codex και Grok Build. Τα όρια χρήσης του πακέτου εμφανίζονται στη σελίδα Χρήσης: για αυτά τα τρία, και μια κάρτα για το Antigravity CLI που λέει πού μπορείτε να δείτε τη χρήση του (έχει μία μόνο σύνδεση και λειτουργεί μόνο σε συνεδρίες που ξεκινάτε εσείς· δείτε [Antigravity CLI](#antigravity-cli)).
- Επαναφορές ορίων και πίστωση API όταν συμπληρωθεί ένα όριο: μόνο Claude Code και Codex.

## Επιλογή πράκτορα και μοντέλου για μια νέα συνεδρία

Στην αρχική σελίδα (`/`), η γραμμή κάτω από το πλαίσιο μηνύματος δείχνει ποιος κάνει τη δουλειά.

1. Κάντε κλικ στο **Τρέχει σε**. Η λίστα δείχνει **Claude Code** («Anthropic · πακέτο Claude ή κλειδί API»), **Codex** («OpenAI · πακέτο ChatGPT ή κλειδί API»), **Custom** («Οποιοδήποτε μοντέλο: OpenRouter, Ollama, vLLM») και κάθε πράκτορα που προσθέσατε στις Ρυθμίσεις → Περισσότεροι πράκτορες («Πράκτορας ACP · » και η εντολή του). Στο κάτω μέρος, το **Μοντέλα για το Custom** ανοίγει τις Ρυθμίσεις → Μοντέλα και το **Προσθήκη ή διαχείριση πρακτόρων** ανοίγει τις Ρυθμίσεις → Περισσότεροι πράκτορες.
2. Κάντε κλικ στο **Μοντέλο** και επιλέξτε ένα. Το **Αυτόματα**, στην κορυφή και επιλεγμένο αρχικά, αφήνει τις βαθμίδες να επιλέξουν: Καλύτερο, και Μέγιστο αν το πρόβλημα αποδειχθεί πολύ δύσκολο (δείτε [Βαθμίδες: ένα μοντέλο για κάθε είδος εργασίας](#tiers-a-model-for-each-kind-of-job)). Από κάτω η λίστα δείχνει μόνο τα μοντέλα του συγκεκριμένου πράκτορα. Η προεπιλογή του πράκτορα επισημαίνεται ως «προεπιλογή». Οι παλαιότερες εκδόσεις ενός μοντέλου περιμένουν πίσω από μια γραμμή όπως «2 παλαιότερα μοντέλα»· κάντε κλικ σε αυτήν για να τις δείτε. Όταν υπάρχουν περισσότερα από οκτώ μοντέλα, ένα πλαίσιο **Αναζήτηση μοντέλων** βρίσκεται στην κορυφή: πληκτρολογήστε μερικά γράμματα και πατήστε Enter για να επιλέξετε το πρώτο αποτέλεσμα. Όταν ο πράκτορας δεν ξεκίνησε όπως το ζήτησε η εφαρμογή για τα μοντέλα του, το μενού το λέει, με τα δικά του λόγια για τον λόγο, και το **Δοκιμάστε ξανά** ρωτά ξανά.
3. Στις **Επιλογές** θα βρείτε την **Ένταση σκέψης** (για πράκτορες και μοντέλα που την έχουν: Προεπιλογή, Χαμηλό, Μέτριο, Υψηλό και ούτω καθεξής· για το Grok Build, δείτε [Ένταση σκέψης για το Grok Build](#effort-for-grok-build)) και τα **Δικαιώματα** (τι μπορεί να κάνει ο πράκτορας χωρίς να σας ρωτήσει). Το Shift+Tab στο πλαίσιο μηνύματος αλλάζει επίσης τα δικαιώματα.

Η αρχική σελίδα θυμάται τι επιλέξατε για κάθε χώρο όπου εργάζεστε (κάθε έργο, κάθε φάκελο και τον **Νέος φάκελος εργασίας**), σε όλες τις συσκευές: το μοντέλο, η ένταση σκέψης και τα δικαιώματα κάθε προγράμματος επιστρέφουν εκεί όπως τα αφήσατε (δείτε [Τι θυμάται η αρχική σελίδα](/guide/sessions#what-the-start-page-remembers)).

Ένας πράκτορας ACP εκτός του Custom δείχνει τις επιλογές **Μοντέλο** και **Δικαιώματα** μόνο μετά την πρώτη συνεδρία του: εμφανίζουν ό,τι πρόσφερε ο πράκτορας την τελευταία φορά που έτρεξε. Εξαίρεση αποτελεί το Grok Build: τα μοντέλα του, με τις εντάσεις που δέχεται το καθένα, εμφανίζονται μόλις προστεθεί, επειδή η εφαρμογή τα ζητά από το Grok. Τα μοντέλα και οι εντάσεις του Antigravity CLI εμφανίζονται μετά την πρώτη συνεδρία, όταν η εφαρμογή τα μαθαίνει καθώς ανοίγει η συνεδρία.

Με ενεργή την επιλογή **Επιλογές** → **Εμπιστευτική λειτουργία**, το **Τρέχει σε** είναι **Custom** και το **Μοντέλο** εμφανίζει μόνο τα μοντέλα που βρίσκονται σε αυτόν τον υπολογιστή ή στο ιδιωτικό σας δίκτυο, με το καλύτερο από αυτά επιλεγμένο πρώτο: δείτε [Διατήρηση μιας συνεδρίας εμπιστευτικής](/guide/sessions#keep-a-session-confidential).

Σε τηλέφωνο, καθένα από αυτά τα μενού ανοίγει ως φύλλο από το κάτω μέρος της οθόνης.

## Αλλαγή μοντέλου στη μέση μιας συνεδρίας

Σε μια συνεδρία, το μοντέλο, η ένταση σκέψης και τα δικαιώματα βρίσκονται κάτω από το πλαίσιο μηνύματος. Είναι ένα μικρό κουμπί που γράφει κάτι σαν «Opus 5.5 · Υψηλό · Σχέδιο»: κάντε κλικ σε αυτό για **Μοντέλο**, **Ένταση σκέψης** και **Δικαιώματα**.

Επιλέξτε άλλο μοντέλο και η συνεδρία συνεχίζει με αυτό:

- Το Claude Code αλλάζει αμέσως.
- Το Codex χρησιμοποιεί το νέο μοντέλο από την επόμενη στροφή του και μετά.
- Το Custom το χρησιμοποιεί από το επόμενο βήμα του, ακόμη και στη μέση μιας στροφής.
- Ένας άλλος πράκτορας ACP αλλάζει αν προσφέρει επιλογή μοντέλων.

Η **Ένταση σκέψης** της συνεδρίας λειτουργεί με τον ίδιο τρόπο. Επιλέξτε μία και ο πράκτορας που εκτελείται τη χρησιμοποιεί από την επόμενη στροφή του και μετά. Αν το μοντέλο στο οποίο αλλάζετε δεν δέχεται την ένταση που είχατε, ο επιλογέας δείχνει την προεπιλογή του μοντέλου και το μοντέλο τρέχει με αυτήν.

Το μενού μοντέλων εμφανίζει μόνο τα μοντέλα του πράκτορα της ίδιας της συνεδρίας· σε μια εμπιστευτική συνεδρία, μόνο εκείνα που βρίσκονται σε αυτόν τον υπολογιστή ή στο ιδιωτικό σας δίκτυο. Για να μεταφέρετε μια συνομιλία σε άλλον πράκτορα, χρησιμοποιήστε το μενού της συνεδρίας (⋯) → **Συνέχεια στο Codex**, **Συνέχεια στο Claude Code** ή **Συνέχεια στο Custom Agent** (από συνεδρίες Claude Code και Codex· το Custom εμφανίζεται μόλις αποκτήσει μοντέλο). Το επόμενο μήνυμά σας ξεκινά τότε μια νέα συνεδρία αυτού του πράκτορα στον ίδιο φάκελο, με τη συνομιλία μέχρι εκείνη τη στιγμή. Μια συνεδρία που έχει σταματήσει συνεχίζει με το μοντέλο που χρησιμοποίησε τελευταία, εκτός αν επιλέξετε άλλο πριν στείλετε.

## Ένταση σκέψης για το Grok Build

Τα μοντέλα του Grok δέχονται μια ένταση συλλογισμού, την ίδια επιλογή που δίνουν το Claude Code και το Codex:

- Grok 4.6 (και νεότερα μοντέλα που προσφέρουν το ίδιο): **xhigh**, **high**, **medium** ή **low**. Το **Υψηλό** είναι η προεπιλογή.
- Grok 4.5: **υψηλό**, **μέτρια** ή **χαμηλό**.

Στην αρχική σελίδα, επιλέξτε **Grok Build** στο **Τρέχει σε** και μετά **Επιλογές** → **Ένταση σκέψης**: εμφανίζει τις εντάσεις του μοντέλου που επιλέξατε, με την **Προεπιλογή**. Εμφανίζονται μόλις προστεθεί το Grok Build, ακόμη και πριν από την πρώτη του συνεδρία. Μια συνεδρία Grok Build που εκτελείται αλλάζει την ένταση σκέψης από τον δικό της επιλογέα **Ένταση σκέψης** (το κουμπί κάτω από το πλαίσιο μηνύματος), και μια εκτέλεση [εφαρμογής](/guide/apps) δέχεται επίσης μία. Όταν αλλάζετε μια συνεδρία σε μοντέλο που δεν δέχεται την ένταση που είχατε (xhigh στο Grok 4.5), ο επιλογέας δείχνει την προεπιλογή του μοντέλου και με αυτήν τρέχει το μοντέλο.

Δεν ισχύει μόνο για το Grok: κάθε άλλος πράκτορας που μιλά ACP και τα μοντέλα του οποίου προσφέρουν εντάσεις παίρνει την ίδια επιλογή **Ένταση σκέψης**.

## Βαθμίδες: ένα μοντέλο για κάθε είδος εργασίας

Οι πράκτορες επιλέγουν μοντέλα ανά βαθμίδα αντί για όνομα: **Γρήγορο** για μικρές, πολύ σαφείς εργασίες των οποίων το αποτέλεσμα μπορεί να ελεγχθεί, **Τυπικό** για σαφείς εργασίες μεσαίου μεγέθους, **Καλύτερο** για τον κύριο πράκτορα μιας συνεδρίας, που σχεδιάζει, καθοδηγεί υποπράκτορες και ελέγχει τη δουλειά τους, και **Μέγιστο** για τα δυσκολότερα προβλήματα. Το μεγαλύτερο μέρος μιας δουλειάς αποτελείται από σαφή κομμάτια που ένα φθηνότερο μοντέλο κάνει καλά, οπότε μια συνεδρία κοστίζει λιγότερο με αυτόν τον τρόπο χωρίς να χειροτερεύει το αποτέλεσμα: το ισχυρότερο μοντέλο της παρέας εξακολουθεί να σχεδιάζει τη δουλειά και να την ελέγχει.

Στην αρχική σελίδα, το **Μοντέλο** ανοίγει στο **Αυτόματα**: η συνεδρία ξεκινά στο Καλύτερο (το ίδιο **Αυτόματα** ξεκινά τις συνεδρίες μιας [προγραμματισμένης εργασίας](/guide/tasks#model-effort-permissions-and-other-options), και μια [εφαρμογή](/guide/apps) μπορεί να σκέφτεται με μια βαθμίδα αντί για μοντέλο με όνομα). Ο κύριος πράκτοράς της αναθέτει σαφή κομμάτια σε υποπράκτορες στο Τυπικό και στο Γρήγορο, και μπορεί να μεταβεί μόνος του στο Μέγιστο όταν ένα πρόβλημα αποδειχθεί δυσκολότερο απ' όσο μπορεί να διαχειριστεί το Καλύτερο (μια διόρθωση που απέτυχε δύο φορές, μια αιτία που δεν μπορεί να βρει, μια απόδειξη)· μια γραμμή στη συνομιλία το λέει, με τον λόγο. Ένα αίτημα δεν στέλνεται στο Μέγιστο μόνο από τη διατύπωσή του: το Καλύτερο λύνει τα περισσότερα από όσα φαίνονται δύσκολα, με μικρότερο κόστος. Επιλέξτε αντί γι' αυτό ένα μοντέλο με όνομα και η συνεδρία σκέφτεται με εκείνο· οι υποπράκτορές της εξακολουθούν να παίρνουν βαθμίδες. Ένας πράκτορας δικός σας μπορεί να σκέφτεται με μία μόνο βαθμίδα (δείτε [Με τι σκέφτεται ένας πράκτορας: βαθμίδες](/guide/agents#what-an-agent-thinks-with-tiers)).

Οι [Ρυθμίσεις → Πράκτορες → Μοντέλα → Βαθμίδες](/settings?s=models&find=Tiers) λένε τι σημαίνει κάθε βαθμίδα για κάθε πρόγραμμα: μία γραμμή για κάθε βαθμίδα, με έναν διακόπτη δίπλα στον τίτλο της ομάδας για την επιλογή του προγράμματος (**Claude Code**, **Codex** ή **Custom**), και σε κάθε γραμμή ένα μοντέλο και, για το Claude Code και το Codex, μια ένταση σκέψης. Το (i) μιας βαθμίδας λέει περισσότερα γι' αυτήν. Αρχικά, για το Claude Code, το Γρήγορο είναι το Haiku, το Τυπικό είναι το Sonnet, το Καλύτερο είναι το Opus και το Μέγιστο είναι το νεότερο Fable· για το Codex, το Γρήγορο είναι το Luna, το Τυπικό είναι το Terra, το Καλύτερο είναι το Sol και το Μέγιστο είναι το Astra (σε πακέτο χωρίς κάποιο από αυτά, το πλησιέστερο που προσφέρει, με περισσότερη ένταση σκέψης για την ανώτερη βαθμίδα όπου δύο μοιράζονται ένα μοντέλο)· οι βαθμίδες του Custom συμπληρώνονται μόνες τους: μια βαθμίδα που αφήνετε ως έχει παίρνει το νεότερο μοντέλο του είδους της από τα μοντέλα που έχει το Custom. Από το πακέτο Claude που έχετε, αυτό είναι το Haiku για το Γρήγορο, το Sonnet για το Τυπικό, το Opus για το Καλύτερο και το νεότερο Fable για το Μέγιστο· αλλιώς, από το πακέτο ChatGPT που έχετε, τα Luna, Terra, Sol και Astra· αλλιώς, από τα μοντέλα που προσθέσατε και δεν βρίσκονται σε αυτόν τον υπολογιστή (OpenRouter, ένα endpoint) και των οποίων τα ονόματα δηλώνουν μία από αυτές τις οικογένειες. Ένα μοντέλο σε αυτόν τον υπολογιστή δεν επιλέγεται ποτέ για εσάς, επειδή το όνομά του δεν δείχνει πόσο ισχυρό είναι, και ένα μικρό μοντέλο (Haiku, Luna) δεν γίνεται ποτέ Καλύτερο: με μόνο μικρά ή τοπικά μοντέλα οι βαθμίδες μένουν κενές μέχρι να επιλέξετε, και μια συνεδρία Custom κρατά τότε το μοντέλο που επέλεξε. Μόλις το Καλύτερο ορίσει ένα μοντέλο, η αρχική σελίδα προσφέρει το **Αυτόματα** για το Custom, και οι συνεδρίες του καθοδηγούν υποπράκτορες (υποπράκτορες του Hydor, όπως σε κάθε συνεδρία). Στην καρτέλα **Custom** μπορείτε να ονομάσετε οποιοδήποτε από τα μοντέλα του για μια βαθμίδα (δείτε [Από πού προέρχονται τα μοντέλα του Custom](#where-customs-models-come-from)). Μια βαθμίδα που αφήνετε ως έχει ακολουθεί το νεότερο μοντέλο του είδους της στο πρόγραμμά της. Η **Επαναφορά προεπιλογών**, στο μενού **⋯** δίπλα στον τίτλο, τις επαναφέρει, μαζί με τις επιλογές του Custom.

Δύο διακόπτες στην ομάδα **Βαθμίδες στις συνεδρίες** κάτω από τις βαθμίδες λένε πώς τις χρησιμοποιούν οι συνεδρίες:

- **Καθοδήγηση με υποπράκτορες** (αρχικά ενεργό): στον κύριο πράκτορα μιας συνεδρίας λέγεται να σχεδιάζει, να αναθέτει σαφή κομμάτια σε υποπράκτορες σε φθηνότερες βαθμίδες και να ελέγχει τη δουλειά τους, και ένας υποπράκτορας που ζητείται χωρίς βαθμίδα παίρνει το Τυπικό. Όταν είναι ανενεργό, οι πράκτορες δουλεύουν μόνοι τους εκτός αν επιλέξουν διαφορετικά, και η αρχική σελίδα και η φόρμα εργασίας δεν έχουν Αυτόματα.
- **Μέγιστο για δύσκολα προβλήματα** (αρχικά ενεργό): ένας κύριος πράκτορας στο Αυτόματα μπορεί να μεταβεί μόνος του στο Μέγιστο όταν ένα πρόβλημα αποδειχθεί πολύ δύσκολο για το Καλύτερο. Όταν είναι ανενεργό, οι συνεδρίες στο Αυτόματα μένουν στο Καλύτερο.

## Τα προγράμματα πρακτόρων εγκαθίστανται και ενημερώνονται μόνα τους

Το Claude Code, το Codex, το Gemini CLI, το Grok Build και τα υπόλοιπα είναι προγράμματα σε αυτόν τον υπολογιστή. Δεν χρειάζεται να τα εγκαταστήσετε με το χέρι. Εξαίρεση αποτελεί το Antigravity CLI: η Google ζητά να το εγκαθιστούν οι ίδιοι οι χρήστες, οπότε η εφαρμογή δεν το κάνει (δείτε [Antigravity CLI](#antigravity-cli)). Ενημερώνεται μόνο του.

Ανοίξτε τις [Ρυθμίσεις → Πράκτορες → Λογαριασμοί](/settings?s=accounts&find=Agent%20programs) και δείτε την ομάδα **Προγράμματα πρακτόρων**. Απαριθμεί το Claude Code, το Codex, το Gemini CLI, το OpenCode, το Qwen Code, το Auggie, το Grok Build (αφού το προσθέσετε) και τους πράκτορες που χρειάζονται προσαρμογέα ACP, καθένα με την έκδοση που τρέχουν οι συνεδρίες και την προέλευσή του:

- **δική σας εγκατάσταση**: το εγκαταστήσατε εσείς (για το Grok Build, και με το δικό της πρόγραμμα εγκατάστασης της xAI, που το τοποθετεί στο `~/.grok/bin`).
- **εγκαταστάθηκε από την εφαρμογή**: η εφαρμογή το εγκατέστησε στον δικό της φάκελο.
- **έρχεται με την εφαρμογή**: το Codex συνοδεύει την εφαρμογή.
- **Όχι εδώ: εγκαθίσταται μόνο του την πρώτη φορά που χρησιμοποιείται**: λείπει. Κάντε κλικ στην **Εγκατάσταση** για να το αποκτήσετε τώρα.

Μια γραμμή λέει επίσης «… είναι διαθέσιμη» όταν υπάρχει νεότερη έκδοση. Η γραμμή του Codex προσθέτει «δική σας στο τερματικό: …» όταν έχετε και δικό σας Codex: οι συνεδρίες τρέχουν αυτό της εφαρμογής και ένα τερματικό τρέχει το δικό σας.

Ένα πρόγραμμα που λείπει εγκαθίσταται επίσης μόνο του την πρώτη φορά που χρειάζεται: το Claude Code όταν συνδέεστε σε αυτό ή ξεκινάτε μια συνεδρία Claude Code, ένας πράκτορας ACP όταν τον προσθέτετε στις Ρυθμίσεις → Πράκτορες → Περισσότεροι πράκτορες ή ξεκινάτε μια συνεδρία με αυτόν. Η εφαρμογή τα εγκαθιστά με npm στον δικό της φάκελο, οπότε δεν χρειάζεστε δικαιώματα διαχειριστή.

Το Goose, το Kimi CLI, το Antigravity CLI και μερικοί άλλοι πράκτορες δεν βρίσκονται σε αυτή τη λίστα: εγκαταστήστε τους μόνοι σας (οι Ρυθμίσεις → Πράκτορες → Περισσότεροι πράκτορες δείχνουν πού θα τους βρείτε). Ένας πράκτορας που χρειάζεται προσαρμογέα ACP εγκαθίσταται σε δύο μέρη, τον προσαρμογέα και τον ίδιο τον πράκτορα· η λίστα δείχνει μία γραμμή και για τα δύο.

## Διατηρήστε ενημερωμένα τα προγράμματα πρακτόρων

Με ενεργή την [**Αυτόματη ενημέρωση**](/settings?s=accounts&find=Update%20automatically), στην τελευταία γραμμή των **Προγράμματα πρακτόρων** (είναι ενεργή, εκτός αν την απενεργοποιήσετε), η εφαρμογή ενημερώνει κάθε πρόγραμμα πράκτορα στην πιο πρόσφατη έκδοσή του μία φορά την ημέρα. Η πρώτη εκτέλεση γίνεται περίπου δέκα λεπτά μετά την εκκίνηση της εφαρμογής.

- Τα αντίγραφα που εγκατέστησε η εφαρμογή ενημερώνονται με npm, στον δικό της φάκελο. Το Codex αλλάζει σε αντίγραφο νεότερο από αυτό που συνόδευε την εφαρμογή.
- Οι δικές σας εγκαταστάσεις ενημερώνονται με το δικό τους πρόγραμμα ενημέρωσης: `claude update` για το Claude Code, `codex update` για το Codex (αυτό που εκτελεί το τερματικό σας), `opencode upgrade` για το OpenCode, `grok update` για το Grok Build.
- Το Gemini CLI, το Qwen Code, το Auggie, το Grok Build ή ένας πράκτορας με προσαρμογέα ACP που εγκαταστήσατε με `npm install -g` ενημερώνονται με npm, όταν ο χρήστης σας έχει δικαίωμα εγγραφής σε αυτόν τον φάκελο. Ό,τι έχει εγκατασταθεί με άλλον τρόπο μένει σε εσάς να το ενημερώσετε με τον τρόπο που το εγκαταστήσατε.
- Το Claude Code ακολουθεί τη δική του γραμμή εκδόσεων: τη σταθερή (stable) όταν οι ρυθμίσεις του έχουν `"autoUpdatesChannel": "stable"`, αλλιώς την πιο πρόσφατη.
- Αν απενεργοποιήσατε τις δικές του ενημερώσεις του Claude Code με `DISABLE_AUTOUPDATER=1` (το κάνει η εικόνα Docker), η εφαρμογή δεν ενημερώνει ούτε εκείνη μόνη της το Claude Code σας. Η **Ενημέρωση τώρα** όμως το ενημερώνει.

Η εφαρμογή κρατά μια νέα έκδοση μόνο όταν λειτουργεί με τον τρόπο που τη χρησιμοποιούν οι συνεδρίες. Το Claude Code πρέπει να απαντά όταν ξεκινά μια συνεδρία και να εμφανίζει τη λίστα των μοντέλων του, το Codex πρέπει να ξεκινά τον διακομιστή εφαρμογής του και να εμφανίζει τη λίστα των μοντέλων του, και τα υπόλοιπα πρέπει να ξεκινούν και να δηλώνουν την έκδοσή τους. Τίποτα από αυτά δεν απαιτεί σύνδεση ούτε καταναλώνει από το πλάνο σας. Κάθε πρόγραμμα έχει ένα λεπτό για να απαντήσει και μετρά μόνο ο χρόνος που ο υπολογιστής είναι ξύπνιος, επομένως ένα Mac που αδρανοποιείται στη μέση του ελέγχου δεν χάνει το λεπτό του. Ένα πρόγραμμα που αργεί να απαντήσει την πρώτη φορά (το Mac εξετάζει ένα νέο πρόγραμμα πριν το εκτελέσει για πρώτη φορά) ξεκινά ξανά με δύο επιπλέον λεπτά και αποτυγχάνει μόνο αν δεν απαντήσει ούτε τότε. Μια έκδοση που αποτυγχάνει αναιρείται:

- Ένα αντίγραφο που εγκατέστησε η εφαρμογή, ή δικό σας που ενημέρωσε με npm, επιστρέφει στην προηγούμενη έκδοση.
- Για το δικό σας Claude Code, οι συνεδρίες συνεχίζουν να εκτελούν την προηγούμενη έκδοση, που το πρόγραμμα εγκατάστασης του Claude Code κρατά δίπλα στη νέα. Η εντολή `claude` σε ένα τερματικό μένει στη νέα. Η γραμμή εμφανίζει «… δεν λειτούργησε εδώ».
- Μια έκδοση που απέτυχε δεν ξαναδοκιμάζεται μόνη της, δοκιμάζεται όμως η επόμενη, και η **Ενημέρωση τώρα** την ξαναδοκιμάζει.

Κάτω από αυτή τη γραμμή αναγράφεται πότε έλεγξε τελευταία φορά η εφαρμογή, για παράδειγμα «Ενημερωμένο · έλεγχος πριν από 2 ώρες», με το κουμπί **Έλεγχος τώρα** για νέο έλεγχο. Όταν υπάρχουν νεότερες εκδόσεις, το αναφέρει, με το κουμπί **Ενημέρωση τώρα** για να τις εγκαταστήσετε όλες μαζί (δεν υπάρχει κουμπί ανά πρόγραμμα)· όσο εργάζεται, εμφανίζει ποιο πρόγραμμα ενημερώνει. Οι γραμμές από κάτω λένε τι άλλαξε η τελευταία ενημέρωση, για παράδειγμα «Claude Code 2.1.308 → 2.1.316», ή γιατί δεν μπόρεσε να εγκατασταθεί μια έκδοση.

Οι συνεδρίες που εκτελούνται συνεχίζουν με την έκδοση με την οποία ξεκίνησαν· οι νέες συνεδρίες χρησιμοποιούν τη νέα. Με την **Αυτόματη ενημέρωση** απενεργοποιημένη, η εφαρμογή εξακολουθεί να ελέγχει μία φορά την ημέρα και να εμφανίζει τι έχει κυκλοφορήσει, αλλά δεν εγκαθιστά τίποτα μέχρι να κάνετε κλικ στην **Ενημέρωση τώρα**.

## Σύνδεση στο Claude Code, στο Codex και στο Grok Build

Το Claude Code και το Codex χρειάζονται σύνδεση για να λειτουργήσουν, το ίδιο και το Grok Build αφού το προσθέσετε (δείτε [Προσθήκη του Gemini CLI, του OpenCode και άλλων πρακτόρων ACP](#add-gemini-cli-opencode-and-other-acp-agents)). Ανοίξτε τις [Ρυθμίσεις → Πράκτορες → Λογαριασμοί](/settings?s=accounts) (σε κινητό, οι Ρυθμίσεις είναι μια λίστα ενοτήτων: πατήστε **Λογαριασμοί** κάτω από τους Πράκτορες· ο τίτλος στο πάνω μέρος σάς γυρίζει πίσω). Η ομάδα **Λογαριασμοί** (το (i) της λέει ότι πρόκειται για τις συνδέσεις στο Claude Code, στο Codex και στο Grok Build που χρησιμοποιούν οι συνεδρίες σας, ότι μπορείτε να προσθέσετε και άλλη συνδρομή, για παράδειγμα μία επαγγελματική και μία προσωπική, και να επιλέγετε μία όταν ξεκινάτε μια συνεδρία) εμφανίζει πρώτα τη δική του σύνδεση κάθε πράκτορα και μετά τους λογαριασμούς που προσθέσατε γι' αυτόν. Η σύνδεση του ίδιου του Grok Build έχει επίσης δική της γραμμή εκεί, **Grok Build**, που εμφανίζεται μόλις το προσθέσετε. Κάθε γραμμή δείχνει ένα πράσινο σημάδι ελέγχου με το email, το πλάνο και τη μέθοδο σύνδεσης, ή ένα κόκκινο σταυρό με το «Δεν έχει γίνει σύνδεση» ή με το τι πήγε στραβά.

Για να συνδεθείτε:

1. Κάντε κλικ στην **Σύνδεση** δίπλα στον πράκτορα.
2. Επιλέξτε πώς:
   - Claude Code: **Συνδρομή Claude** (το πλάνο σας στο Claude) ή **Console (χρέωση API)** (ένας λογαριασμός API της Anthropic).
   - Codex: **Κωδικός συσκευής** ή **Ανακατεύθυνση προγράμματος περιήγησης**.
   - Grok Build: δεν υπάρχει κάτι να επιλέξετε, συνδέεται πάντα με κωδικό.
3. Κάντε κλικ στην **Λήψη συνδέσμου σύνδεσης**.
4. Ακολουθήστε τα βήματα που εμφανίζει το παράθυρο:
   - Claude Code: ανοίξτε τον σύνδεσμο (**Άνοιγμα σελίδας σύνδεσης**), εγκρίνετε την πρόσβαση στο πρόγραμμα περιήγησής σας, έπειτα επικολλήστε τον κωδικό που εμφανίζει η σελίδα στο πεδίο **Επικολλήστε τον κωδικό από τη σελίδα** και κάντε κλικ στην **Ολοκλήρωση σύνδεσης**.
   - Codex, Κωδικός συσκευής: ανοίξτε τον σύνδεσμο σε οποιαδήποτε συσκευή, συνδεθείτε στο ChatGPT και εισαγάγετε τον κωδικό μίας χρήσης που εμφανίζεται στο παράθυρο. Το παράθυρο καταλαβαίνει μόνο του πότε τελειώσατε.
   - Codex, Ανακατεύθυνση προγράμματος περιήγησης: αφού συνδεθείτε, το πρόγραμμα περιήγησής σας προσπαθεί να ανοίξει μια σελίδα «localhost» και αποτυγχάνει. Αντιγράψτε τη διεύθυνση αυτής της σελίδας, επικολλήστε την στο πεδίο **Επικολλήστε τη διεύθυνση localhost από το πρόγραμμα περιήγησης** και κάντε κλικ στην **Ολοκλήρωση σύνδεσης**.
   - Grok Build: λαμβάνετε έναν σύνδεσμο και έναν κωδικό μίας χρήσης. Ανοίξτε τον σύνδεσμο σε οποιαδήποτε συσκευή, συνδεθείτε με τον λογαριασμό σας στο Grok και επιβεβαιώστε τον κωδικό (**2. Επιβεβαιώστε αυτόν τον κωδικό**). Δεν επικολλάτε τίποτα πίσω: το παράθυρο καταλαβαίνει μόνο του πότε τελειώσατε.

Όταν όλα πάνε καλά, βλέπετε «Το Claude Code είναι συνδεδεμένο» (ή το Codex, ή το Grok Build). Αν αποτύχει, το παράθυρο λέει γιατί· κάντε κλικ στο **Δοκιμάστε ξανά**.

Το Antigravity CLI, ο πράκτορας της Google για το πλάνο Google AI σας, έχει δική του γραμμή **Antigravity CLI** στην ίδια ομάδα μόλις το προσθέσετε. Η σύνδεσή του λειτουργεί λίγο διαφορετικά: δείτε [Antigravity CLI](#antigravity-cli).

Μόλις συνδεθείτε, το κουμπί γράφει **Αλλαγή λογαριασμού**: ξεκινά την ίδια σύνδεση για άλλον λογαριασμό (για το Grok Build, με νέο κωδικό). Η **Αποσύνδεση** βρίσκεται στο μενού **⋯** της γραμμής: αποσυνδέει το πρόγραμμα σε αυτόν τον υπολογιστή, για κάθε τερματικό και πρόγραμμα επεξεργασίας που το χρησιμοποιεί, αφού επιβεβαιώσετε.

Αν ξεκινήσετε μια συνεδρία Grok Build ενώ είστε αποσυνδεδεμένοι, η συνεδρία σταματά με το μήνυμα «Το Grok Build δεν είναι συνδεδεμένο: συνδεθείτε με τον λογαριασμό σας στο Grok από τις Ρυθμίσεις → Πράκτορες → Λογαριασμοί και δοκιμάστε ξανά.» Συνδεθείτε εκεί και στείλτε ξανά το μήνυμά σας. Ένα κλειδί API του xAI στη μεταβλητή `XAI_API_KEY`, στο περιβάλλον των πρακτόρων, λειτουργεί για το Grok Build αντί για συνδρομή.

Η περιήγηση καλωσορίσματος (από τη **Βοήθεια** στην πλευρική στήλη) ρωτά ποιους πράκτορες και ποια μοντέλα θέλετε να χρησιμοποιήσετε και σας καθοδηγεί και σε αυτές τις συνδέσεις.

## Προσθήκη δεύτερου λογαριασμού (επαγγελματικός και προσωπικός)

Μπορείτε να συνδεθείτε με περισσότερους από έναν λογαριασμούς Claude Code, Codex ή Grok Build, για παράδειγμα ένα επαγγελματικό και ένα προσωπικό πλάνο, και να επιλέγετε έναν ανά συνεδρία.

1. Ανοίξτε τις [Ρυθμίσεις → Πράκτορες → Λογαριασμοί](/settings?s=accounts&find=Accounts).
2. Κάντε κλικ στην **Προσθήκη λογαριασμού**, δίπλα στον τίτλο της ομάδας **Λογαριασμοί**.
3. Επιλέξτε **Claude Code**, **Codex** ή **Grok Build** (προσφέρεται μόλις ρυθμιστεί το Grok Build· το Antigravity CLI δεν προσφέρεται ποτέ: έχει μία μόνο σύνδεση, δείτε [Antigravity CLI](#antigravity-cli)), πληκτρολογήστε ένα όνομα (έως 40 χαρακτήρες, όπως «Εργασία» ή «Προσωπικός») και κάντε κλικ στην **Προσθήκη και σύνδεση**.
4. Ανοίγει το παράθυρο σύνδεσης για τον νέο λογαριασμό. Συνδεθείτε όπως περιγράφεται παραπάνω.

Κάθε λογαριασμός που προσθέτετε συνδέεται ξεχωριστά και κρατά το δικό του ιστορικό συνεδριών. Οι ρυθμίσεις, οι οδηγίες, οι δεξιότητες και τα πρόσθετά σας είναι κοινά με την κύρια σύνδεση του πράκτορα, επομένως οι αλλαγές ισχύουν και για τους δύο. Για το Claude Code, ένας φάκελος που έχετε εμπιστευτεί με την κύρια σύνδεση είναι έμπιστος και με έναν λογαριασμό που προσθέσατε, οπότε στις συνεδρίες του ισχύουν οι κανόνες δικαιωμάτων του ίδιου του φακέλου. Δύο λογαριασμοί του ίδιου πράκτορα δεν μπορούν να έχουν το ίδιο όνομα.

Ένας λογαριασμός Grok Build που προσθέσατε έχει δικό του φάκελο με τη σύνδεσή του και το δικό του ιστορικό συνεδριών του Grok. Μοιράζεται με την κύρια σύνδεσή σας τις ρυθμίσεις του ίδιου του Grok CLI: τη διαμόρφωσή του, τους κανόνες του (`AGENTS.md`), τις δεξιότητες, τα πρόσθετα και τις συνδέσεις MCP.

Κάθε λογαριασμός που προσθέτετε έχει τη δική του γραμμή, κάτω από τη δική του σύνδεση του πράκτορα, με **Σύνδεση** ή **Αλλαγή λογαριασμού**· το μενού **⋯** της περιέχει **Αποσύνδεση**, **Μετονομασία** και **Αφαίρεση**:

- Η **Μετονομασία** ζητά ένα νέο όνομα.
- Η **Αποσύνδεση** σταματά τη λειτουργία των συνεδριών που εκτελούνται με αυτόν τον λογαριασμό μέχρι να συνδεθεί ξανά.
- Η **Αφαίρεση** βγάζει τον λογαριασμό από την εφαρμογή. Οι συνεδρίες του φεύγουν από τη λίστα, αλλά το ιστορικό τους μένει στον δίσκο, εκτός αν επιλέξετε και το **Να διαγραφούν επίσης η σύνδεσή του και το ιστορικό των συνεδριών του**. Δεν μπορείτε να αφαιρέσετε έναν λογαριασμό όσο εκτελούνται συνεδρίες με αυτόν: σταματήστε τις πρώτα.

Η [σελίδα Χρήση](/usage) εμφανίζει μια κάρτα για κάθε λογαριασμό Claude Code, Codex ή Grok Build που προσθέσατε, με τα δικά του όρια.

## Επιλογή του λογαριασμού με τον οποίο εκτελείται μια συνεδρία

Όταν ο πράκτορας που επιλέξατε έχει λογαριασμούς που προσθέσατε (για το Grok Build, αφού προσθέσετε έναν), οι **Επιλογές** της αρχικής σελίδας εμφανίζουν μια γραμμή **Λογαριασμός**. Κάντε κλικ σε αυτήν:

- Η **Η σύνδεσή σας** είναι ο λογαριασμός του ίδιου του προγράμματος (ο πρώτος για τον συγκεκριμένο πράκτορα στους **Λογαριασμοί**· για το Grok Build, «Ο λογαριασμός του ίδιου του Grok Build CLI»).
- Κάθε λογαριασμός που προσθέσατε εμφανίζεται με το όνομά του.
- Η **Διαχείριση λογαριασμών** ανοίγει τις Ρυθμίσεις → Πράκτορες → Λογαριασμοί.

Η αρχική σελίδα θυμάται την επιλογή σας για αυτόν τον πράκτορα, ίδια σε κάθε σημείο. Μια συνεδρία που εκτελείται με λογαριασμό που προσθέσατε δείχνει το όνομα αυτού του λογαριασμού, με ένα εικονίδιο προσώπου, στο πάνω μέρος της συνεδρίας. Αν αυτός ο λογαριασμός φτάσει σε όριο χρήσης, η ειδοποίηση ορίου πάνω από το πλαίσιο μηνύματος αφορά αυτόν τον λογαριασμό. Ο λογαριασμός ορίζεται όταν ξεκινά η συνεδρία. Αλλάζει μόνος του μόνο με την **Αλλαγή λογαριασμού στο όριο** (παρακάτω).

Για να μετακινήσετε μόνοι σας μια συνεδρία σε άλλον λογαριασμό, κάντε κλικ στο δικό της chip **Λογαριασμός** και επιλέξτε έναν. Αυτό λειτουργεί για συνεδρίες Claude Code, Codex και Grok Build και ισχύει από το επόμενο μήνυμά σας. Το ιστορικό Grok μιας συνεδρίας Grok Build μετακινείται μαζί της· αν το Grok δεν μπορεί να την ξανανοίξει με τον άλλον λογαριασμό, ξεκινά από την αρχή εκεί, με μια σημείωση.

## Χρήση όλων των λογαριασμών σας: αλλαγή στο όριο

Με δύο ή περισσότερους λογαριασμούς για τον ίδιο πράκτορα, η εφαρμογή μπορεί να τους χρησιμοποιήσει όλους: όταν ένας εξαντλήσει τη χρήση του, η δουλειά σας συνεχίζεται με έναν άλλο. Ανοίξτε τις [Ρυθμίσεις → Πράκτορες → Λογαριασμοί](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit) και βρείτε την **Αλλαγή λογαριασμού στο όριο**, στην ομάδα **Σε όριο χρήσης** κάτω από τους **Λογαριασμοί**, που εμφανίζεται μόλις προσθέσετε οποιονδήποτε λογαριασμό, και του Grok Build (το (i) της λέει ότι όταν ο λογαριασμός μιας συνεδρίας εξαντλήσει τη χρήση του, η συνεδρία μετακινείται σε άλλον λογαριασμό του ίδιου πράκτορα που έχει ακόμη χρήση και συνεχίζει, και ότι οι νέες συνεδρίες προσπερνούν έναν λογαριασμό που βρίσκεται στο όριό του). Είναι ενεργή εξαρχής (απενεργοποιήστε την εκεί αν προτιμάτε να επιλέγετε εσείς τον λογαριασμό) και λειτουργεί ακόμη και όταν δεν είναι ανοιχτό κανένα πρόγραμμα περιήγησης.

- Όταν ένας γύρος σταματά επειδή ο λογαριασμός της συνεδρίας έφτασε στο όριο χρήσης του, η εφαρμογή επιλέγει έναν άλλο συνδεδεμένο λογαριασμό του ίδιου πράκτορα που έχει ακόμη χρήση (τον λιγότερο χρησιμοποιημένο), μετακινεί εκεί τη συνεδρία με όλο το ιστορικό της και στέλνει το μήνυμα «… έφτασε στο όριο χρήσης του, οπότε αυτή η συνεδρία εκτελείται πλέον στον …. Συνεχίστε από εκεί που σταματήσατε.» Μια σύντομη σημείωση στο κάτω μέρος της οθόνης λέει σε ποιον λογαριασμό μετακινήθηκε.
- Οι υποπράκτορες που εκτελεί μια συνεδρία Claude Code στο παρασκήνιο συνεχίζουν κι αυτοί. Όσοι εργάζονταν ακόμη όταν χτύπησε το όριο σταματούν στο επόμενο βήμα τους με τη δουλειά τους διατηρημένη, και η εφαρμογή τους περιμένει (έως δύο λεπτά) πριν μετακινήσει τη συνεδρία. Το μήνυμα τους κατονομάζει και ο πράκτορας συνεχίζει τον καθένα από εκεί που σταμάτησε. Αν μόνο οι υποπράκτορες φτάσουν σε όριο (ένα όριο μόνο για το μοντέλο τους), η συνεδρία μετακινείται όταν τελειώσει ο γύρος της και κανένας τους δεν εργάζεται πια.
- Οι Υποπράκτορες του Hydor (οι συνεδρίες που ξεκινά ένας πράκτορας για να κάνει μέρος της δουλειάς του) είναι συνεδρίες από μόνες τους, οπότε καθεμία μετακινείται μόνη της όταν ένα όριο σταματά τον γύρο της. Ο πράκτορας που την ξεκίνησε ενημερώνεται ότι συνεχίζει, όχι ότι απέτυχε, και λαμβάνει την απάντησή της όταν τελειώσει.
- Μετρούν η κύρια σύνδεσή σας και κάθε λογαριασμός που προσθέσατε. Οι λογαριασμοί Claude Code αντικαθίστανται από λογαριασμούς Claude Code, του Codex από του Codex, του Grok Build από του Grok Build. Το Antigravity CLI δεν έχει άλλους λογαριασμούς για να μετακινηθεί, οπότε αυτό δεν ισχύει ποτέ γι' αυτό (δείτε [Antigravity CLI](#antigravity-cli)).
- Ένας λογαριασμός Grok Build βρίσκεται στο όριό του όταν φτάσει στο εβδομαδιαίο όριό του, στο όριο της πίστωσής του ή στο όριο δαπανών της χρέωσης κατά τη χρήση. Η συνεδρία τότε μετακινείται σε άλλον συνδεδεμένο λογαριασμό Grok που έχει ακόμη χρήση (τον λιγότερο χρησιμοποιημένο) και συνεχίζει με το «… έφτασε στο όριο χρήσης του, οπότε αυτή η συνεδρία εκτελείται πλέον στον …». Ένα σύντομο όριο ρυθμού (μια ριπή αιτημάτων) δεν μετακινεί τίποτα: περνά από μόνο του. Η ειδοποίηση ορίου πάνω από το πλαίσιο μηνύματος εμφανίζεται και για συνεδρίες Grok.
- Ένας στόχος που τον οδηγεί η εφαρμογή ανήκει στην εφαρμογή, οπότε συνεχίζεται στον νέο λογαριασμό. Ένας στόχος που πληκτρολογήθηκε ως `/goal` στο Codex μετακινείται με τη συνεδρία και συνεχίζεται.
- Μετράει η χρήση που απομένει για το μοντέλο της συνεδρίας. Ένα όριο μόνο για ένα μοντέλο, όπως ένα εβδομαδιαίο όριο για το Fable, σταματά μόνο τις συνεδρίες με αυτό το μοντέλο: μια συνεδρία με Sonnet ή Opus μεταφέρεται κανονικά σε λογαριασμό που έχει εξαντλήσει μόνο το μερίδιό του για το Fable. Ένας λογαριασμός του οποίου η συνδρομή δεν περιλαμβάνει το μοντέλο της συνεδρίας παραλείπεται για αυτήν (το Claude Code λέει ότι το μοντέλο «requires usage credits», όπως το Fable σε συνδρομή Pro): η συνεδρία μεταφέρεται σε λογαριασμό του οποίου η συνδρομή περιλαμβάνει το μοντέλο, ή περιμένει να μηδενιστεί ο πρώτος από αυτούς, και η σημείωση λέει «Η συνδρομή του λογαριασμού … δεν περιλαμβάνει το …».
- Όταν όλοι οι λογαριασμοί βρίσκονται στο όριό τους, δεν μετακινείται τίποτα (εκτός αν είναι ενεργή η **Χρήση πίστωσης API στο όριο**, παρακάτω, για το Claude Code). Με ενεργή τη **Συνέχεια μετά από όρια χρήσης**, η συνεδρία συνεχίζει όταν γίνει επαναφορά του πρώτου λογαριασμού, σε αυτόν τον λογαριασμό. Αυτό ισχύει και για τις συνεδρίες Grok Build. Περισσότερα στο [Χρήση, όρια και κόστος](/guide/usage#continue-sessions-automatically-after-a-limit).
- Αν μια συνεδρία δεν μπορεί να μετακινηθεί, ένα σύντομο σημείωμα στο κάτω μέρος της οθόνης λέει γιατί, και η συνεδρία μένει στον λογαριασμό της: με ενεργή τη **Συνέχεια μετά από όρια χρήσης**, συνεχίζει όταν επαναφερθεί αυτός ο λογαριασμός. Ένα αντίγραφο του ιστορικού της συνεδρίας που άφησε στον άλλον λογαριασμό μια προηγούμενη μετακίνηση δεν εμποδίζει τη μετακίνηση: το ιστορικό αντικαθιστά αυτό το αντίγραφο, και ό,τι διαφέρει στο αντίγραφο πηγαίνει στον κάδο της σελίδας Αρχεία (**Κάδος**).
- Μια νέα συνεδρία που ξεκινά με λογαριασμό που βρίσκεται στο όριό του ξεκινά αντί γι' αυτόν με έναν που έχει ακόμη χρήση, και ένα μήνυμα που στέλνετε σε συνεδρία της οποίας ο λογαριασμός βρίσκεται στο όριό του μετακινεί πρώτα τη συνεδρία, ώστε το μήνυμα να μην απορριφθεί. Μαζί με το μήνυμά σας, ο πράκτορας μαθαίνει ότι εκτελείται πλέον με λογαριασμό που έχει ακόμη χρήση, ώστε να μην περιμένει την επαναφορά του παλιού λογαριασμού, και ποιοι από τους υποπράκτορές του μπορούν να συνεχίσουν.
- Οι συνεδρίες που ανοίγουν στο VS Code ή σε τερματικό μένουν στον λογαριασμό τους.
- Οι επαναφορές ορίων (πιστώσεις επαναφοράς του Codex, χορηγήσεις επαναφοράς του Claude) και η πίστωση API εξακολουθούν να ισχύουν μόνο για το Claude Code και το Codex.
- Οι δικές της γρήγορες ερωτήσεις της εφαρμογής προς το Claude Code ή το Codex (το Βοηθητικό μοντέλο σε **Αυτόματα**, τα γρήγορα βήματα μοντέλου μιας εφαρμογής, οι περιγραφές pull request, οι προτάσεις εντολών) πηγαίνουν με τον ίδιο τρόπο στον επόμενο συνδεδεμένο λογαριασμό σας όταν ένας βρίσκεται στο όριό του ή είναι αποσυνδεδεμένος. Όταν ούτε το Claude Code ούτε το Codex μπορούν να απαντήσουν, παρεμβαίνει ένα από τα Custom μοντέλα σας (δείτε [Όταν ένας λογαριασμός είναι αποσυνδεδεμένος](#when-an-account-is-signed-out)).

## Όταν ένας λογαριασμός έχει αποσυνδεθεί

Ένας λογαριασμός του Claude Code, του Codex ή του Grok Build μπορεί να αποσυνδεθεί: η σύνδεσή του έληξε ή ανακλήθηκε, και το πρόγραμμα εμφανίζει το μήνυμα «Not logged in · Please run /login» ή «401 Unauthorized». Η εφαρμογή βρίσκει μια λύση όποτε μπορεί και σας ζητά να συνδεθείτε ξανά μόνο όταν τίποτε άλλο δεν μπορεί να κάνει τη δουλειά.

Το Antigravity CLI δεν έχει άλλον λογαριασμό στον οποίο να μεταβεί. Αν ξεκινήσετε μια συνεδρία ενώ είναι αποσυνδεδεμένο, η συνεδρία σταματά με το μήνυμα «Antigravity CLI is not signed in: sign in with your Google account in Settings → Agents → Accounts, then try again.», και η γραμμή του εκεί δείχνει ότι είναι αποσυνδεδεμένο. Συνδεθείτε εκεί και στείλτε ξανά το μήνυμά σας.

- **Οι συνεδρίες σας.** Όταν ο γύρος μιας συνεδρίας απορρίπτεται επειδή ο λογαριασμός της έχει αποσυνδεθεί, και η ρύθμιση [Αλλαγή λογαριασμού στο όριο](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit) είναι ενεργή (είναι ενεργή από την αρχή), η συνεδρία μεταφέρεται, μαζί με όλο το ιστορικό της, σε έναν άλλο συνδεδεμένο λογαριασμό του ίδιου πράκτορα που έχει ακόμη διαθέσιμη χρήση, και συνεχίζει. Μια σύντομη σημείωση στο κάτω μέρος της οθόνης αναφέρει «<session>: <account> is signed out, so it continues on <other account>», και ο πράκτορας ενημερώνεται με το μήνυμα «… is signed out, so this session now runs on …. Continue where you left off.» Ένα μήνυμα που στέλνετε σε μια συνεδρία της οποίας ο λογαριασμός βρέθηκε αποσυνδεδεμένος πριν από λίγο μεταφέρει πρώτα τη συνεδρία με τον ίδιο τρόπο, ώστε το μήνυμα να μην απορριφθεί.
- **Όταν μια συνεδρία δεν μπορεί να μεταφερθεί.** Όταν η ρύθμιση **Αλλαγή λογαριασμού στο όριο** είναι ανενεργή, ή όταν κανένας άλλος λογαριασμός αυτού του πράκτορα δεν έχει διαθέσιμη χρήση, η συνεδρία σταματά. Πάνω από το πλαίσιο μηνύματός της εμφανίζεται ένα banner που αναφέρει «<account> is signed out» και «This session continues once you sign in again.», με ένα κουμπί **Σύνδεση**. Μόλις συνδεθείτε ξανά, εδώ ή σε τερματικό, η συνεδρία συνεχίζει από μόνη της, και ο πράκτορας ενημερώνεται με το μήνυμα «Signed in again. Continue where you left off.»
- **Εργασία παρασκηνίου.** Οι μικρές εργασίες του [βοηθητικού μοντέλου](/settings?s=models&find=Helper%20model) στη ρύθμιση **Αυτόματα** (τίτλοι συνεδριών, σημειώσεις μνήμης, σύντομη επεξεργασία [του προφίλ σας](/guide/memory#your-profile), γρήγορα βήματα μοντέλου μιας εφαρμογής, περιγραφές pull request…) προσπερνούν έναν αποσυνδεδεμένο λογαριασμό για 15 λεπτά και μετά τον δοκιμάζουν ξανά, ώστε να γίνεται αντιληπτή μια σύνδεση που κάνατε σε τερματικό. Απαντά ο επόμενος συνδεδεμένος λογαριασμός και μετά το Codex. Όταν ούτε το Claude Code ούτε το Codex μπορούν να απαντήσουν (αποσυνδεδεμένα, σε όριο ή μη εγκατεστημένα), τη δουλειά αναλαμβάνει ένα από τα μοντέλα σας **Custom**: αυτό που ονομάζει η βαθμίδα **Γρήγορο** του Custom στις [Ρυθμίσεις → Πράκτορες → Μοντέλα → Βαθμίδες](/settings?s=models&find=Tiers) (έπειτα **Τυπικό**, και για τις σπάνιες μεγαλύτερες εργασίες **Καλύτερο**, μετά **Μέγιστο**), διαφορετικά το φθηνότερο μοντέλο που έχετε προσθέσει (ένα μοντέλο σε αυτόν τον υπολογιστή θεωρείται δωρεάν). Δοκιμάζονται το πολύ δύο. Το κόστος του υπολογίζεται όπως η χρήση οποιουδήποτε μοντέλου Custom.
- **Η προτροπή για σύνδεση.** Μόνο όταν τίποτε δεν μπορούσε να κάνει τη δουλειά και ένας λογαριασμός ήταν αποσυνδεδεμένος, εμφανίζεται μια κάρτα σε κάθε σελίδα, κάτω δεξιά (πάνω από το πλαίσιο μηνύματος σε τηλέφωνο). Ο τίτλος της είναι «Sign in to Claude Code again» (ή Codex, ή Grok Build), από κάτω «<account> is signed out.», και ο λόγος για τον οποίο το ζητά: «Background work needs it (shortening your profile), and no other account or Custom model could do it.» ή, για μια συνεδρία που σταμάτησε, «… continues once you sign in.» Το κουμπί **Σύνδεση** ανοίγει το ίδιο παράθυρο σύνδεσης με τις [Ρυθμίσεις → Πράκτορες → Λογαριασμοί](/settings?s=accounts). Το κουμπί **Όχι τώρα** κρύβει την κάρτα για μία ώρα· μια συνεδρία που σταματά εξαιτίας της εμφανίζει ξανά την κάρτα, και το banner στη συνεδρία αυτή παραμένει. Εμφανίζονται το πολύ δύο κάρτες ταυτόχρονα, και μετά το «+N more» σας πηγαίνει στις Ρυθμίσεις → Πράκτορες → Λογαριασμοί. Μια κάρτα εξαφανίζεται μόλις ο λογαριασμός συνδεθεί ξανά, από την κάρτα, από τις Ρυθμίσεις ή σε τερματικό (η εφαρμογή το αντιλαμβάνεται στην επόμενη κλήση της που περνά). Εξαφανίζεται επίσης όταν η εργασία παρασκηνίου ολοκληρώνεται ξανά με άλλον τρόπο (απαντά άλλος λογαριασμός ή ένα μοντέλο Custom). Όταν και το Claude Code και το Codex είναι αποσυνδεδεμένα, ερώτηση γίνεται μόνο για το Claude Code, που απαντά πρώτο.

Το προφίλ σας το δείχνει επίσης: όταν η σύντμησή του απέτυχε επειδή ένας λογαριασμός είναι αποσυνδεδεμένος, ο λόγος που αναγράφεται από κάτω το αναφέρει («Your Claude Code account “Work” is signed out, and no other account or Custom model could do this: sign in again (Settings → Agents → Accounts).») και εμφανίζεται η κάρτα.

## Χρήση πίστωσης API όταν όλοι οι λογαριασμοί έχουν φτάσει στο όριό τους

Αν έχετε ένα κλειδί API της Anthropic (από το [console.anthropic.com](https://console.anthropic.com) → API keys), οι συνεδρίες σας του Claude Code μπορούν να συνεχίσουν με αυτό όταν όλοι οι λογαριασμοί του Claude Code έχουν φτάσει στο όριο χρήσης τους, αντί να σταματήσουν. Έχει κόστος: η συνεδρία χρεώνεται από την Anthropic με τιμές API για όσο εκτελείται με αυτόν τον τρόπο, και δεν καλύπτεται από τη συνδρομή σας.

1. Ανοίξτε τις [Ρυθμίσεις → Πράκτορες → Λογαριασμοί](/settings?s=accounts&find=Use%20API%20credit%20at%20a%20limit). Στη γραμμή ενός λογαριασμού Claude Code στους **Λογαριασμοί** (η κύρια σύνδεσή σας ή κάποιος που προσθέσατε), κάντε κλικ στο **⋯** και μετά στο **Προσθήκη κλειδιού API…**.
2. Επικολλήστε το κλειδί στο **Κλειδί API της Anthropic** και κάντε κλικ στο **Αποθήκευση κλειδιού**. Η εφαρμογή το ελέγχει με την Anthropic και το διατηρεί κρυπτογραφημένο σε αυτόν τον υπολογιστή. Η γραμμή εμφανίζει τότε μια ετικέτα **Πίστωση API**. Το **Αλλαγή κλειδιού API…** το αντικαθιστά και το **Αφαίρεση κλειδιού API** το διαγράφει.
3. Ενεργοποιήστε τη ρύθμιση **Χρήση πίστωσης API στο όριο**, στην ομάδα **Σε όριο χρήσης** (το (i) της αναφέρει ότι, όταν όλοι οι λογαριασμοί του Claude Code έχουν φτάσει στο όριο χρήσης τους, οι συνεδρίες συνεχίζουν με χρέωση στο κλειδί API ενός λογαριασμού αντί να σταματήσουν, και ότι είναι ανενεργή μέχρι να την ενεργοποιήσετε). Εμφανίζεται μόλις συνδεθεί το Claude Code ή προσθέσετε έναν λογαριασμό Claude Code.

Τι συμβαίνει τότε:

- Όταν ο λογαριασμός μιας συνεδρίας του Claude Code φτάσει στο όριο χρήσης του, η εφαρμογή δοκιμάζει πρώτα ό,τι κάνει η ρύθμιση **Αλλαγή λογαριασμού στο όριο**: έναν άλλο λογαριασμό με διαθέσιμη χρήση. Μόνο όταν κανένας δεν έχει άλλη διαθέσιμη χρήση και η ρύθμιση είναι ενεργή, η συνεδρία συνεχίζει με χρέωση στο κλειδί API.
- Η συνεδρία παραμένει στον δικό της λογαριασμό, οπότε το ιστορικό της δεν μεταφέρεται. Αν ο λογαριασμός αυτός δεν έχει κλειδί, χρησιμοποιείται το κλειδί ενός άλλου λογαριασμού του Claude Code.
- Η συνεδρία εμφανίζει μια ετικέτα **Πίστωση API** δίπλα στον λογαριασμό της στο επάνω μέρος. Τοποθετήστε το δείκτη του ποντικιού πάνω της για να δείτε τον λόγο.
- Όταν ένα πρόγραμμα συνδρομής έχει πάλι διαθέσιμη χρήση, η συνεδρία επιστρέφει σε αυτό μετά το τέλος του επόμενου γύρου της: στον δικό της λογαριασμό ή σε έναν άλλο με διαθέσιμη χρήση. Δεν χρειάζεται να κάνετε τίποτα.
- Αν η εφαρμογή δεν μπορεί να διαβάσει τη χρήση ενός λογαριασμού, δεν μεταφέρει ποτέ τη δουλειά σας σε χρέωση API.
- Το Codex δεν επηρεάζεται: δεν έχει πίστωση API.

## Προσθήκη Gemini CLI, OpenCode και άλλων πρακτόρων ACP

Ανοίξτε [Ρυθμίσεις → Πράκτορες → Περισσότεροι πράκτορες](/settings?s=agents&find=Agents%20that%20speak%20ACP).

- Η ενότητα **Οι πράκτορές σας** (εμφανίζονται δίπλα στον Claude Code και στο Codex όταν ξεκινάτε μια συνεδρία) εμφανίζει πρώτα το Custom και μετά τους πράκτορες που προσθέσατε. Κάθε πράκτορας έχει ένα σημάδι επιλογής όταν το πρόγραμμά του είναι εγκατεστημένο εδώ, ή ένα σταυρό και την ένδειξη «δεν είναι εγκατεστημένο».
- Η ενότητα **Πράκτορες που μιλούν ACP** (εγκαταστήστε έναν, συνδεθείτε μία φορά στο δικό του CLI και μετά προσθέστε τον εδώ) εμφανίζει τους γνωστούς πράκτορες που δεν έχετε προσθέσει ακόμη: Gemini CLI, OpenCode, Qwen Code, Goose, Kimi CLI, Auggie, Grok Build, Antigravity CLI και άλλους. Πρώτοι εμφανίζονται οι εγκατεστημένοι. Μια γραμμή που γράφει «Δεν είναι εγκατεστημένο» εξηγεί πώς να το αποκτήσετε. Η λίστα δείχνει τους πρώτους λίγους που δεν είναι εγκατεστημένοι· το **Εμφάνιση όλων** δείχνει τους υπόλοιπους.

Για να προσθέσετε έναν:

1. Κάντε κλικ στην **Προσθήκη** στο τέλος της γραμμής του. Το κουμπί ξεχωρίζει όταν το πρόγραμμα είναι ήδη εγκατεστημένο.
2. Αν η εφαρμογή ξέρει πώς να τον εγκαταστήσει (Gemini CLI, OpenCode, Qwen Code, Auggie, Grok Build και οι πράκτορες που χρειάζονται προσαρμογέα ACP), τον εγκαθιστά αμέσως, στο παρασκήνιο. Τους Goose, Kimi CLI, Antigravity CLI και τους υπόλοιπους τους εγκαθιστάτε μόνοι σας, με την εντολή ή τη διεύθυνση που αναγράφεται στη γραμμή τους.
3. Συνδεθείτε μία φορά στο δικό του πρόγραμμα του πράκτορα: ανοίξτε το [Τερματικό](/terminal), εκτελέστε την εντολή του (για παράδειγμα `gemini`) και ακολουθήστε τη σύνδεσή του. Αν το παραλείψετε, η συνεδρία θα σας πει: «Το Gemini CLI δεν είναι συνδεδεμένο. Εκτελέστε μία φορά το gemini σε ένα τερματικό, συνδεθείτε εκεί και δοκιμάστε ξανά.» Εξαίρεση αποτελούν το Grok Build και το Antigravity CLI: συνδέονται από το [Ρυθμίσεις → Πράκτορες → Λογαριασμοί](/settings?s=accounts).

Το Gemini CLI προορίζεται για κλειδί API του Gemini ή για άδεια Gemini Code Assist Standard ή Enterprise· η προεπιλογή του εδώ το ξεκινά με `--acp`. Από τις 18 Ιουνίου 2026 δεν εξυπηρετεί πλέον τα Google AI Pro και Ultra (ούτε το Gemini Code Assist για ιδιώτες): για αυτά τα προγράμματα χρησιμοποιήστε το Antigravity CLI.

Ο πράκτορας εμφανίζεται πλέον στη λίστα **Τρέχει σε** της αρχικής σελίδας.

Για να αλλάξετε έναν πράκτορα που προσθέσατε, κάντε κλικ στην **Επεξεργασία**. Για να τον αφαιρέσετε, ανοίξτε το μενού **⋯** του, επιλέξτε **Αφαίρεση** και επιβεβαιώστε: οι συνεδρίες του παραμένουν στη λίστα, αλλά για να τις συνεχίσετε πρέπει να ρυθμίσετε ξανά τον πράκτορα. Το Custom είναι ενσωματωμένο: η γραμμή του γράφει «Ενσωματωμένο: μοντέλα από OpenRouter, Ollama και vLLM, στις Ρυθμίσεις → Μοντέλα» και έχει ένα κουμπί **Μοντέλα** αντί για Επεξεργασία και Αφαίρεση.

### Grok Build

Το **Grok Build** είναι ο πράκτορας προγραμματισμού της xAI (το πρόγραμμα `grok`). Κάντε κλικ στην **Προσθήκη** στη γραμμή του και αυτό είναι όλο: η εφαρμογή το εγκαθιστά από το npm (`@xai-official/grok`) την πρώτη φορά που χρειάζεται, ή χρησιμοποιεί ένα που υπάρχει ήδη εδώ, μαζί με ένα από το δικό της πρόγραμμα εγκατάστασης της xAI στο `~/.grok/bin`. Στη συνέχεια εμφανίζεται στα **Προγράμματα πρακτόρων** και ενημερώνεται μαζί με τα υπόλοιπα. Το Hydor το εκτελεί μέσω ACP, με τα δικά του εργαλεία της εφαρμογής, τις κάρτες έγκρισης και τα μοντέλα του Grok.

Συνδέεται διαφορετικά από τους άλλους πράκτορες ACP: όχι στο Τερματικό, αλλά στο [Ρυθμίσεις → Πράκτορες → Λογαριασμοί](/settings?s=accounts), όπου εμφανίζεται μια γραμμή **Grok Build** αμέσως μόλις προστεθεί (δείτε [Σύνδεση του Claude Code, του Codex και του Grok Build](#sign-claude-code-codex-and-grok-build-in)). Μπορείτε να προσθέσετε εκεί και περισσότερους λογαριασμούς Grok.

### Antigravity CLI

Το **Antigravity CLI** είναι ο πράκτορας προγραμματισμού της Google για το τερματικό (το πρόγραμμα `agy`) και αυτός που λειτουργεί με το πρόγραμμα Google AI σας. Από τις 18 Ιουνίου 2026 το Gemini CLI δεν εξυπηρετεί πλέον τα Google AI Pro και Ultra (ούτε το Gemini Code Assist για ιδιώτες). Το Gemini CLI παραμένει για κλειδί API του Gemini ή για άδεια Gemini Code Assist Standard ή Enterprise.

**Εγκαταστήστε το μόνοι σας.** Η Google ζητά να το εγκαθιστούν οι ίδιοι οι χρήστες, γι' αυτό η εφαρμογή δεν το κάνει. Η γραμμή του στο [Ρυθμίσεις → Πράκτορες → Περισσότεροι πράκτορες](/settings?s=agents&find=Agents%20that%20speak%20ACP) (στην ενότητα **Πράκτορες που μιλούν ACP**, με όνομα **Antigravity CLI** και την εντολή `agy acp`) δείχνει το πρόγραμμα εγκατάστασης της Google. Σε macOS και Linux, εκτελέστε αυτό στο [Τερματικό](/terminal)· τοποθετεί το `agy` στο `~/.local/bin`:

```
curl -fsSL https://antigravity.google/cli/install.sh | bash
```

Στα Windows, εκτελέστε αυτό στο PowerShell:

```
irm https://antigravity.google/cli/install.ps1 | iex
```

Ενημερώνεται μόνο του, γι' αυτό δεν περιλαμβάνεται στα **Προγράμματα πρακτόρων** που η εφαρμογή διατηρεί ενημερωμένα. Μόλις εγκατασταθεί, κάντε κλικ στην **Προσθήκη** στη γραμμή του.

**Σύνδεση.** Μόλις προστεθεί, το [Ρυθμίσεις → Πράκτορες → Λογαριασμοί](/settings?s=accounts) εμφανίζει μια γραμμή **Antigravity CLI**, με δική της σύνδεση:

1. Κάντε κλικ στη **Σύνδεση** και μετά στη **Λήψη συνδέσμου σύνδεσης**.
2. Κάντε κλικ στο **1. Ανοίξτε αυτόν τον σύνδεσμο**: είναι η σελίδα σύνδεσης της Google. Συνδεθείτε με τον λογαριασμό σας Google, έναν προσωπικό με Google AI Pro, Ultra, Plus ή το δωρεάν πρόγραμμα του Antigravity. Η σελίδα εμφανίζει στη συνέχεια έναν κωδικό.
3. Επικολλήστε τον κωδικό στο **2. Επικολλήστε τον κωδικό από τη σελίδα** (ή ολόκληρη τη διεύθυνση της σελίδας στην οποία καταλήγετε) και κάντε κλικ στην **Ολοκλήρωση σύνδεσης**.

Η γραμμή δείχνει τότε το email και, αφού ανοίξει μια συνεδρία, το πρόγραμμα (για παράδειγμα Google AI Pro). Η **Αποσύνδεση**, στο μενού **⋯** της γραμμής, αποσυνδέει το Antigravity CLI σε αυτόν τον υπολογιστή, για κάθε πρόγραμμα που το χρησιμοποιεί. Στην εφαρμογή τερματικού, η εντολή `hydor accounts sign-in antigravity` κάνει την ίδια σύνδεση. Αν ξεκινήσετε μια συνεδρία ενώ είναι αποσυνδεδεμένο, σταματά με το μήνυμα «Το Antigravity CLI δεν είναι συνδεδεμένο: συνδεθείτε με τον λογαριασμό σας Google στις Ρυθμίσεις → Πράκτορες → Λογαριασμοί και δοκιμάστε ξανά.»

**Μοντέλα και ένταση σκέψης.** Σε μια συνεδρία, το **Μοντέλο** εμφανίζει τα δικά του μοντέλα του Antigravity CLI (μοντέλα Gemini 4, Gemini 3.8 Flash και άλλα που προσφέρει το πρόγραμμά σας), η **Ένταση σκέψης** τα επίπεδα σκέψης του (low, medium, high, xhigh και max) και τα **Δικαιώματα** τις λειτουργίες δικαιωμάτων του. Εμφανίζονται μετά την πρώτη του συνεδρία, όταν η εφαρμογή τα μαθαίνει καθώς ανοίγει η συνεδρία. Τα εργαλεία της εφαρμογής και οι κάρτες έγκρισης λειτουργούν όπως και με τους άλλους πράκτορες ACP.

**Τι σημαίνουν εδώ οι όροι της Google.** Κάτω από τη γραμμή, η εφαρμογή γράφει: «Οι όροι της Google για τα προγράμματά της επιτρέπουν το Antigravity CLI μόνο σε συνεδρίες που ξεκινάτε και οδηγείτε εσείς οι ίδιοι, γι' αυτό έχει μία μόνο σύνδεση και δεν εργάζεται ποτέ στο παρασκήνιο.» Στο Hydor αυτό σημαίνει:

- **Μόνο μία σύνδεση.** Δεν μπορείτε να προσθέσετε περισσότερους λογαριασμούς Antigravity CLI: η **Προσθήκη λογαριασμού** δεν το προσφέρει και η **Αλλαγή λογαριασμού στο όριο** δεν ισχύει ποτέ για αυτό.
- **Μόνο συνεδρίες που ξεκινάτε εσείς.** Μπορούν να ξεκινήσουν μία η αρχική σελίδα, η εφαρμογή τερματικού, μια εφαρμογή συνομιλίας (Telegram και παρόμοιες) και η φωνή χωρίς χέρια. Ένας προγραμματισμός, ένας υποπράκτορας που ξεκινά άλλος πράκτορας, μια εκτέλεση [εφαρμογής](/guide/apps), η αρένα ή οτιδήποτε άλλο ξεκινά η εφαρμογή απορρίπτεται: «Το Antigravity CLI εκτελείται μόνο σε συνεδρίες που ξεκινάτε και οδηγείτε εσείς οι ίδιοι: οι όροι της Google για τα προγράμματά της αποκλείουν εργασία που ξεκινά η εφαρμογή ή άλλος πράκτορας (προγραμματισμοί, υποπράκτορες, εφαρμογές). Επιλέξτε άλλον πράκτορα για αυτό.»
- **Κανένα μήνυμα από την ίδια την εφαρμογή.** Η εφαρμογή δεν του στέλνει ποτέ μήνυμα από μόνη της. Ό,τι θα έστελνε (το αποτέλεσμα ενός υποπράκτορα, την απάντηση μιας εφαρμογής, μια υπενθύμιση) εμφανίζεται στη συνεδρία ως σημείωση: «Δεν στάλθηκε στο Antigravity CLI, που δέχεται μόνο τα μηνύματα που στέλνετε εσείς οι ίδιοι (όροι της Google για τα προγράμματά της). Για να του το μεταβιβάσετε, στείλτε το μόνοι σας:» ακολουθούμενη από το κείμενο. Ό,τι κάνετε εσείς οι ίδιοι (απάντηση σε κάρτα, αποθήκευση κλειδιού, η φωνή σας) εξακολουθεί να το φτάνει.
- **Καμία συνέχιση από μόνο του.** Μετά από ένα όριο δεν συνεχίζει ποτέ από μόνο του: δεν υπάρχει **Συνέχεια μετά από όρια χρήσης** για αυτό ούτε κουμπί **Συνέχεια με την επαναφορά**. Δείτε [Χρήση, όρια και κόστος](/guide/usage#what-happens-when-you-hit-a-limit).

Η χρήση της σύνδεσής του από οποιοδήποτε άλλο πρόγραμμα, ή η εναλλαγή λογαριασμών, μπορεί να οδηγήσει στην αναστολή της πρόσβασης του λογαριασμού Google στο Antigravity (το λέει η Google στις συχνές της ερωτήσεις), γι' αυτό χρησιμοποιήστε το μόνο όπως περιγράφεται εδώ. Για εργασία χωρίς επίβλεψη, όπως προγραμματισμοί, υποπράκτορες και εφαρμογές, η λύση είναι ένα κλειδί API του Gemini με το Gemini CLI.

Η χρήση του εμφανίζεται ως κάρτα στη [σελίδα Χρήση](/usage), με το email και το πρόγραμμα αλλά χωρίς μετρητές: δείτε [Ανάγνωση των ορίων ενός προγράμματος](/guide/usage#read-a-plans-limits).

### Προσθήκη δικού σας πράκτορα

Οποιοδήποτε πρόγραμμα μιλά ACP μπορεί να τρέξει εδώ.

1. Κάντε κλικ στην **Προσθήκη δικού σας**, δίπλα στον τίτλο **Οι πράκτορές σας**.
2. Συμπληρώστε:
   - **Όνομα**: πώς εμφανίζεται στις λίστες, για παράδειγμα «Gemini CLI».
   - **Εντολή**: το πρόγραμμα που θα ξεκινήσει, για παράδειγμα `gemini`, ή μια πλήρης διαδρομή.
   - **Ορίσματα**: ό,τι το ξεκινά σε λειτουργία ACP, για παράδειγμα `--acp`.
   - **Μεταβλητές περιβάλλοντος (προαιρετικά, ένα NAME=value ανά γραμμή)**: ρυθμίσεις που χρειάζεται το πρόγραμμα, όπως μια μεταβλητή για κλειδί API.
3. Κάντε κλικ στην **Αποθήκευση**.

Η εντολή πρέπει να ξεκινά τον πράκτορα σε λειτουργία ACP, επικοινωνώντας μέσω της τυπικής εισόδου και εξόδου του.

### Πράκτορες που ρυθμίζετε στο δικό τους πρόγραμμα

Μερικοί πράκτορες της λίστας είναι προγράμματα που ρυθμίζετε μόνοι σας, και λίγα πράγματα διαφέρουν από εκείνους που εγκαθιστά η εφαρμογή για εσάς:

- Η γραμμή τους στους **Περισσότεροι πράκτορες** δείχνει την εντολή ή τη διεύθυνση με την οποία εγκαθίστανται. Η εφαρμογή δεν εκτελεί για εσάς κάποιο σενάριο από το διαδίκτυο: εγκαταστήστε τον μόνοι σας, στο [Τερματικό](/terminal) ή με τον τρόπο που λέει η γραμμή.
- Συνδεθείτε μία φορά στο δικό του πρόγραμμα του πράκτορα, επίσης στο Τερματικό (για παράδειγμα εκτελέστε την εντολή του και ακολουθήστε τη σύνδεσή του, ή επιλέξτε εκεί το μοντέλο του). Από εκεί και πέρα η εφαρμογή τον ξεκινά. Κρατά τις δικές του συνεδρίες και τη μνήμη του στον δικό του φάκελο και οι κάρτες έγκρισής του είναι αυτές που προσφέρει ο ίδιος.
- Ένας από αυτούς συνδέεται σε μια δική του πύλη: ρυθμίστε την πρώτα, με τη δική του εντολή ρύθμισης του πράκτορα, και κρατήστε την πύλη σε λειτουργία.
- Όταν ένας πράκτορας δεν μιλά ο ίδιος ACP, χρειάζεται έναν προσαρμογέα ACP. Η εφαρμογή εγκαθιστά τον προσαρμογέα μαζί με τον πράκτορα, και τα δύο με npm στον δικό της φάκελο, χωρίς να εκτελεί τα σενάρια εγκατάστασής τους. Ένας πράκτορας που εγκαταστήσατε μόνοι σας χρησιμοποιείται όταν βρίσκεται στο PATH.
- Ένας πράκτορας που δεν δέχεται διακομιστές MCP λειτουργεί μόνο με τα δικά του εργαλεία: τα εργαλεία της εφαρμογής (σελίδες, αναζήτηση…) δεν τον φτάνουν και η συνεδρία το λέει όταν ξεκινά. Εξακολουθεί να λαμβάνει τις οδηγίες της εφαρμογής, τις σημειώσεις μνήμης και τις δεξιότητες με το πρώτο μήνυμα.

### Τι μπορούν και τι δεν μπορούν να κάνουν εδώ οι πράκτορες ACP

Η εφαρμογή ανοίγει μια συνεδρία στον φάκελο που επιλέγετε, δείχνει τα μηνύματα και τα βήματα του πράκτορα και σας ρωτά κάθε φορά που ο πράκτορας ζητά άδεια. Μερικά πράγματα λειτουργούν διαφορετικά από τον Claude Code και το Codex:

- Δέχεται ένα μήνυμα τη φορά. Ένα μήνυμα που στέλνετε ενώ εργάζεται περιμένει στην ουρά πάνω από το πλαίσιο μηνύματος και φεύγει όταν τελειώσει ο γύρος. (Το Custom λειτουργεί κι αυτό έτσι.)
- Ένας πράκτορας που δεν μπορεί να ανοίξει ξανά προηγούμενες συνεδρίες ξεκινά από την αρχή όταν συνεχίζετε μια παλιά, χωρίς τη συζήτηση που προηγήθηκε. Η συνεδρία το αναφέρει. Το ίδιο συμβαίνει όταν ένας πράκτορας μπορούσε παλαιότερα να ανοίξει ξανά μια συνεδρία αλλά πλέον δεν μπορεί: συνεχίζει από την αρχή, με μια σημείωση, αντί να αποτύχει.
- Οι εικόνες που επισυνάπτετε τον φτάνουν μόνο αν δέχεται εικόνες.
- Οι διακλαδώσεις (forks) και οι παραδόσεις δεν είναι διαθέσιμες (το Custom έχει forks). Οι στόχοι είναι διαθέσιμοι: τους οδηγεί ο δικός της βρόχος της εφαρμογής για κάθε πράκτορα.
- Το Antigravity CLI λειτουργεί μόνο σε συνεδρίες που ξεκινάτε και οδηγείτε εσείς οι ίδιοι, με μία μόνο σύνδεση (δείτε [Antigravity CLI](#antigravity-cli)).
- Τα εργαλεία της εφαρμογής (σελίδες, αναζήτηση, μνήμη…) φτάνουν σε έναν πράκτορα ως διακομιστής MCP: μέσω διεύθυνσης όταν ο πράκτορας το δέχεται, αλλιώς μέσω ενός μικρού προγράμματος που ξεκινά η εφαρμογή για αυτόν. Ένας πράκτορας που δεν δέχεται κανένα από αυτά λειτουργεί μόνο με τα δικά του εργαλεία, αλλά εξακολουθεί να λαμβάνει τις οδηγίες, τις σημειώσεις μνήμης και τις δεξιότητες.

## Από πού προέρχονται τα μοντέλα του Custom

Το Custom εκτελεί τα μοντέλα των προγραμμάτων σας Claude και ChatGPT, μοντέλα σε αυτόν τον υπολογιστή και μοντέλα στο σύννεφο, με τα ίδια εργαλεία, τις ίδιες δεξιότητες και τους ίδιους διακομιστές MCP όπως οι άλλοι πράκτορες. Επιλέξτε Custom στην αρχική σελίδα και μετά το μοντέλο. Προέρχονται από τρία μέρη:

- **Οι συνδρομές σου**: τα μοντέλα των συνδρομών σας Claude και ChatGPT, μέσω των συνδέσεων του Claude Code και του Codex σε αυτόν τον υπολογιστή. Δεν χρειάζεται καμία ρύθμιση: όταν το Claude Code είναι συνδεδεμένο, το μενού **Μοντέλο** του Custom προσφέρει τα Claude Opus, Fable, Sonnet και Haiku (πάντα το νεότερο από το καθένα), και όταν το Codex είναι συνδεδεμένο με ChatGPT, προσφέρει τα μοντέλα που περιλαμβάνει η συνδρομή σας ChatGPT (για παράδειγμα GPT-6 Luna). Αν ένα πρόγραμμα βρεθεί αποσυνδεδεμένο, τα μοντέλα του φεύγουν από το μενού μέχρι να το συνδέσετε ξανά, ενώ ένα Codex συνδεδεμένο με κλειδί API αντί για ChatGPT δεν δανείζει κανένα. Χρησιμοποιούν το όριο χρήσης της συνδρομής σας, όχι κλειδί API ούτε χρέωση ανά token, γι' αυτό μια συνεδρία Custom με κάποιο από αυτά δείχνει $0 για εκείνα τα βήματα. Το μενού **Ένταση σκέψης** προσφέρει για το καθένα τα επίπεδα έντασης που δηλώνει το πρόγραμμά του· όσο είναι επιλεγμένη η **Προεπιλογή**, χρησιμοποιείται η προεπιλογή του ίδιου του προγράμματος. Κάθε λογαριασμός του προγράμματος δοκιμάζεται με τη σειρά, όπως και σε άλλες μεμονωμένες εργασίες: αν ένας λογαριασμός έχει φτάσει στο όριο χρήσης ή είναι αποσυνδεδεμένος, το βήμα περνά στον επόμενο λογαριασμό σας (με ενεργή την **Αλλαγή λογαριασμού στο όριο**). Μια [εμπιστευτική συνεδρία](/guide/sessions#keep-a-session-confidential) δεν τα χρησιμοποιεί ποτέ, επειδή εκτελούνται σε διακομιστές της Anthropic ή της OpenAI. Δείτε [Custom](/guide/custom#what-custom-is-and-when-to-use-it) για τον τρόπο που απαντούν.
- **Σε αυτόν τον υπολογιστή**: μοντέλα εγκατεστημένα εδώ (Ollama, vLLM) και τελικά σημεία στο δίκτυό σας.
- **Στο σύννεφο**: το OpenRouter, τελικά σημεία αλλού και τα μοντέλα σύννεφου του Ollama.

Μπορείτε να τα επιλέξετε οπουδήποτε επιλέγονται τα μοντέλα του Custom: στην αρχική σελίδα, στο μενού μοντέλου μιας συνεδρίας, στις βαθμίδες του Custom, στο βοηθητικό μοντέλο και στο μοντέλο ενός πράκτορα ή μιας εφαρμογής.

Το [Ρυθμίσεις → Πράκτορες → Μοντέλα](/settings?s=models) έχει ό,τι χρειάζονται τα μοντέλα του Custom. Η σελίδα έχει επτά ενότητες, από πάνω προς τα κάτω:

- **Βοηθητικό μοντέλο**: το μοντέλο για τις μικρές εργασίες της εφαρμογής.
- **Βαθμίδες**: ένα μοντέλο για κάθε είδος εργασίας (δείτε [Βαθμίδες: ένα μοντέλο για κάθε είδος εργασίας](#tiers-a-model-for-each-kind-of-job)).
- **Οι συνδρομές σου**: μία γραμμή για τον Claude Code και μία για το Codex, με τα μοντέλα που δανείζει στο Custom. Μια γραμμή γράφει «Αποσυνδεδεμένο: συνδεθείτε ξανά για να χρησιμοποιήσετε αυτά τα μοντέλα» με σύνδεσμο προς τους **Λογαριασμοί**, ή «Δεν είναι εγκατεστημένο σε αυτόν τον υπολογιστή».
- **Σε αυτό το μηχάνημα**: τι διαθέτει αυτός ο υπολογιστής και τα μοντέλα που είναι εγκατεστημένα εδώ.
- **Προσθήκη μοντέλου από το Hugging Face**: αναζήτηση, έλεγχος και εγκατάσταση ανοιχτών μοντέλων.
- **OpenRouter**: εκατοντάδες μοντέλα με ένα κλειδί, σε τρεις ομάδες: το κλειδί σας, τα μοντέλα που προσθέσατε και μια αναζήτηση για να προσθέσετε κι άλλα.
- **Περιβάλλοντα εκτέλεσης και τελικά σημεία**: Ollama, vLLM, άλλοι διακομιστές συμβατοί με OpenAI και ένα token του Hugging Face.

Στο μενού **Μοντέλο** του Custom, τα μοντέλα ομαδοποιούνται κάτω από τα **Οι συνδρομές σου**, **Σε αυτόν τον υπολογιστή** και **Στο σύννεφο**, και κάθε γραμμή λέει μέσω τίνος λειτουργεί: «Claude Code», «Codex», «OpenRouter», «Ollama», «vLLM» ή το όνομα ενός τελικού σημείου. Τοποθετήστε τον δείκτη πάνω σε ένα μοντέλο για να δείτε πού εκτελείται και πόσα διαβάζει ταυτόχρονα, για παράδειγμα «OpenRouter · 128K context» ή «vLLM, σε αυτό το μηχάνημα · 32K context · ξεκινά όταν χρησιμοποιείται». Οι λίστες ανανεώνονται μόνες τους κάθε λεπτό.

## Επιλογή του βοηθητικού μοντέλου

Το βοηθητικό μοντέλο κάνει μικρές εργασίες δίπλα στις συνεδρίες σας, εκτός οποιασδήποτε συζήτησης:

- ονομασία κάθε νέας συνεδρίας από το αίτημά σας (ο τίτλος της στην πλευρική στήλη)·
- έλεγχος των βημάτων στη λειτουργία Auto του Custom και κρίση των ελέγχων ενός στόχου που πρέπει να βρει αληθείς ένας αξιολογητής (ο αξιολογητής είναι ένα μοντέλο που δεν έκανε καμία από τις εργασίες και, σε μια εμπιστευτική συνεδρία, είναι ένα μοντέλο σε αυτόν τον υπολογιστή)·
- τακτοποίηση της μνήμης περίπου μία φορά την ημέρα, εκμάθηση από τις συζητήσεις που έγιναν στο μεταξύ και απόδοση τίτλων στις σημειώσεις για το ευρετήριο με το οποίο ξεκινούν οι πράκτορες·
- απάντηση σε μία ερώτηση για μια ιστοσελίδα που έχει ανοιχτή το πρόγραμμα περιήγησης·
- ανάγνωση των φίλτρων (ιστότοποι, ημερομηνίες, είδη σελίδων, γλώσσες) που δηλώνουν οι λέξεις μιας αναζήτησης στον ιστό, πριν αναζητήσει το Naget Search (δείτε [Πώς αναζητούν οι πράκτορες στον ιστό](/guide/web#how-agents-search-the-web))·
- περιγραφή εικόνων για ένα μοντέλο Custom που δεν μπορεί να τις δει·
- σύνοψη μιας μεγάλης απάντησης από έναν υποπράκτορα του Hydor·
- σύνταξη μιας εφαρμογής ή μιας προγραμματισμένης εργασίας από μια συνεδρία·
- φωνητική λειτουργία χωρίς χέρια.

Ανοίξτε τις [Ρυθμίσεις → Agents → Models](/settings?s=models&find=Helper%20model) και κάντε κλικ στο μενού **Μοντέλο** στην ομάδα **Βοηθητικό μοντέλο** (το (i) της απαριθμεί τις μικρές εργασίες):

- **Αυτόματα** (η προεπιλογή): το Claude Haiku μέσω του Claude Code ή το Codex όταν το Claude Code δεν μπορεί να απαντήσει. Ένας λογαριασμός που έχει φτάσει στο όριο χρήσης περνά την ερώτηση πρώτα στον επόμενο συνδεδεμένο λογαριασμό σας (με ενεργή την επιλογή **Αλλαγή λογαριασμού στο όριο**), ενώ ένας αποσυνδεδεμένος λογαριασμός παραλείπεται. Όταν κανένα από τα δύο προγράμματα δεν μπορεί να απαντήσει, τη δουλειά αναλαμβάνει ένα από τα μοντέλα σας Custom (αυτό που ονομάζει η βαθμίδα **Γρήγορο** του Custom, αλλιώς το φθηνότερο από όσα προσθέσατε· τα μοντέλα των συνδρομών σας παραλείπονται εδώ, αφού περνούν από τα ίδια δύο προγράμματα) και μόνο όταν κανένα δεν μπορεί να την κάνει, μια κάρτα σάς ζητά να συνδεθείτε (δείτε [Όταν ένας λογαριασμός είναι αποσυνδεδεμένος](#when-an-account-is-signed-out)). Όταν δεν απαντά κανένα, το σφάλμα εξηγεί γιατί για καθένα: «You've hit your weekly limit», ένα μοντέλο που το πρόγραμμα Codex σας δεν προσφέρει…
- Οποιοδήποτε από τα μοντέλα του Custom, ομαδοποιημένα όπως στο μενού **Μοντέλο** του Custom (**Οι συνδρομές σου**, **Σε αυτόν τον υπολογιστή** και **Στο σύννεφο**), με το μέσο από το οποίο περνά (Claude Code, Codex, OpenRouter, Ollama, vLLM ή το όνομα ενός endpoint) και την ένδειξη «βλέπει εικόνες» για όσα μπορούν να βλέπουν. Και ένα μοντέλο του προγράμματος Claude ή ChatGPT που έχετε μπορεί να γίνει βοηθητικό: απαντά μέσω του Claude Code ή του Codex με τη χρήση του προγράμματός σας.

Το Αυτόματα δεν μπορεί να δει εικόνες. Αν χρησιμοποιείτε το Custom με ένα μοντέλο που δεν βλέπει εικόνες, επιλέξτε ένα βοηθητικό μοντέλο που βλέπει εικόνες, αλλιώς το Custom δεν μπορεί να έχει περιγραφές για τις εικόνες σας.

## Δείτε τι μπορεί να τρέξει αυτός ο υπολογιστής

Η ενότητα **Σε αυτό το μηχάνημα** στις [Ρυθμίσεις → Agents → Models](/settings?s=models&find=On%20this%20machine) ξεκινά με μια σύνοψη αυτού του υπολογιστή:

- **Γραφικά**: οι κάρτες γραφικών (GPU) και η μνήμη τους· σε Mac με Apple silicon, το τσιπ του («Apple M3 Max», του οποίου τα γραφικά μοιράζονται τη μνήμη του υπολογιστή)· ή «No GPU» (τα μοντέλα τρέχουν τότε στον επεξεργαστή).
- **Μνήμη και δίσκος**: η μνήμη του υπολογιστή, συνολική και ελεύθερη, και ο ελεύθερος χώρος του δίσκου με όσο καταλαμβάνουν τα εγκατεστημένα μοντέλα.
- **Τρέχει με**: αν είναι εγκατεστημένα το **Ollama** και το **vLLM**, με τις εκδόσεις τους, ή ένας σύνδεσμος για την εγκατάστασή τους.
- Με κάρτα γραφικών, πόσο μεγάλο μοντέλο χωράει: «Fits about 30B parameters at 4-bit on one GPU» (σε Mac: «Fits about 40B parameters at 4-bit»). Οι παράμετροι είναι ένα μέτρο του μεγέθους ενός μοντέλου· το 4-bit είναι μια συνηθισμένη συμπιεσμένη μορφή που χρειάζεται περίπου το ένα τέταρτο της μνήμης.

Από κάτω:

- **Downloads in progress**, καθεμία με γραμμή προόδου, πόσο έχει ολοκληρωθεί και αν είναι για το Ollama ή το vLLM. Η **Ακύρωση** σταματά μία. Μια αποτυχημένη ή ακυρωμένη δείχνει τον λόγο, με την επιλογή **Κλείσιμο**.
- **Installed models** (τα πρώτα λίγα, μετά **Εμφάνιση όλων**), καθένα με το περιβάλλον εκτέλεσής του (Ollama ή vLLM), το μέγεθος, λεπτομέρειες (όπως το μέγεθος και η συμπίεσή του για τα μοντέλα Ollama), «βλέπει εικόνες» όπου μπορεί, και αν τρέχει.
  - Ένα μοντέλο vLLM έχει **Έναρξη** και **Διακοπή**. Ξεκινά μόνο του όταν μια συνεδρία το χρησιμοποιήσει για πρώτη φορά (η πρώτη εκκίνηση παίρνει ένα-δύο λεπτά), στην κάρτα γραφικών με τη μεγαλύτερη ελεύθερη μνήμη (στα 8-bit όταν δεν θα χωρούσε εκεί ως έχει) ή μοιρασμένο σε 2, 4 ή 8 από αυτές όταν καμία κάρτα δεν έχει χώρο για αυτό («running on GPUs 1, 2»)· σε Mac, στο Apple silicon του. Συνεχίζει να τρέχει, ακόμη και όταν η εφαρμογή επανεκκινηθεί, μέχρι να κάνετε κλικ στη **Διακοπή**. Αν δεν μπορεί να ξεκινήσει, ο λόγος εμφανίζεται από κάτω.
  - Η **Αφαίρεση**, στο μενού **⋯** του μοντέλου, διαγράφει τα αρχεία του μοντέλου από αυτόν τον υπολογιστή, αφού επιβεβαιώσετε. Μπορείτε να το εγκαταστήσετε ξανά αργότερα.

Όταν δεν υπάρχει κανένα ακόμη: «No models here yet: add one from Hugging Face below.»

## Προσθήκη μοντέλου από το Hugging Face

Το Hugging Face είναι ο βασικός ιστότοπος για ανοιχτά μοντέλα. Η ομάδα [Add a model from Hugging Face](/settings?s=models&find=Add%20a%20model%20from%20Hugging%20Face) (προτάσεις για αυτόν τον υπολογιστή ή αναζήτηση σε ολόκληρο τον ιστότοπο) προτείνει μερικά, κάνει αναζήτηση και σας λέει, πριν κατεβεί οτιδήποτε, πώς θα έτρεχε κάθε μοντέλο σε αυτόν τον υπολογιστή.

### Προτάσεις για αυτόν τον υπολογιστή

Πριν αναζητήσετε, η ομάδα απαριθμεί τα μοντέλα που προτείνει η εφαρμογή και τρέχουν σε αυτόν τον υπολογιστή, ανάλογα με τα χαρακτηριστικά του:

- **LFM3-VL 2B** (Liquid AI): μικρό και γρήγορο, και διαβάζει εικόνες. Τρέχει σχεδόν σε κάθε υπολογιστή.
- **Gemma 4 12B** (Google): ένα ικανό μοντέλο γενικής χρήσης που διαβάζει εικόνες, για υπολογιστή με καλή κάρτα γραφικών.
- **Flint** (Recursive): φτιαγμένο για πράκτορες προγραμματισμού, για Mac με Apple silicon και 32 GB ή περισσότερα.
- **GLM-5.3 Flash** (Z.ai): ανάμεσα στα ισχυρότερα ανοιχτά μοντέλα, για διακομιστή με αρκετές μεγάλες κάρτες γραφικών.

Καθένα δείχνει αν τρέχει καλά ή αργά εδώ, πώς θα έτρεχε («vLLM at 8-bit, on GPU 0», «vLLM, split across 2 GPUs», «vLLM, on Apple silicon»), το μέγεθος λήψης του και την επιλογή **Εγκατάσταση**. Η ένδειξη **Το καλύτερο εδώ** σημειώνει το ισχυρότερο από όσα τρέχουν καλά. Τρέχουν με vLLM από προεπιλογή· ένας υπολογιστής που δεν έχει ούτε κάρτα γραφικών NVIDIA ούτε Apple silicon παίρνει αντί γι' αυτό την έκδοση του μικρού μοντέλου για το Ollama. Ακολουθεί μια προειδοποίηση όταν αυτό που τα τρέχει δεν έχει ρυθμιστεί ακόμη («vLLM is not set up», «Ollama is not running»): δείτε [Σύνδεση του Ollama, του vLLM ή άλλου endpoint](#connect-ollama-vllm-or-another-endpoint). Η γραμμή **2 more for bigger computers** (ή όσα άλλα) δείχνει τα υπόλοιπα, με όσα χρειάζεται το καθένα. Η εισαγωγική περιήγηση προτείνει τα ίδια.

### Αναζήτηση και φίλτρα

1. Πληκτρολογήστε στο πεδίο **Αναζήτηση στο Hugging Face ή επικόλληση org/name**: ένα όνομα όπως `qwen3`, ή το πλήρες όνομα ενός μοντέλου (`org/name`) ή τη διεύθυνσή του στο huggingface.co. Πριν πληκτρολογήσετε, προτείνει μερικά ονόματα ή **δείτε αυτά με τις περισσότερες λήψεις**.
2. Περιορίστε τη λίστα με τα φίλτρα (μπορείτε να τα συνδυάσετε):
   - **Τρέχει καλά εδώ**: μόνο μοντέλα που θα έτρεχαν καλά σε αυτόν τον υπολογιστή.
   - **GGUF · Ollama**: μοντέλα σε μορφή GGUF, που τρέχει το Ollama.
   - **vLLM**: μοντέλα σε μορφή safetensors, που τρέχει το vLLM σε κάρτα γραφικών.
   - **Βλέπει εικόνες**: μοντέλα που διαβάζουν και εικόνες.
3. Αλλάξτε τη σειρά με το μενού στα δεξιά: **Περισσότερες λήψεις**, **Δημοφιλή**, **Πιο αγαπημένα** ή **Νεότερα**.

Παίρνετε έως 40 μοντέλα, τα πρώτα οκτώ αρχικά και **Εμφάνιση όλων** για τα υπόλοιπα. Ένα μοντέλο που ονομάσατε πλήρως εμφανίζεται πρώτο, ακόμη και όταν η αναζήτηση δεν το περιλαμβάνει, και το πάτημα του Enter το ελέγχει αμέσως.

Κάθε γραμμή δείχνει τον δημιουργό και το όνομα, τη μορφή του (**GGUF** ή **vLLM**), **Εικόνες** αν βλέπει εικόνες, **Περιορισμένο** αν ο δημιουργός του ζητά πρώτα να αποδεχτείτε όρους, το μέγεθός του σε παραμέτρους, τις λήψεις των τελευταίων 30 ημερών, τα likes και πότε άλλαξε τελευταία φορά.

### Η πρώτη εκτίμηση

Κάτω από κάθε μοντέλο, μια έγχρωμη ετικέτα δίνει μια πρώτη εκτίμηση μόνο από το μέγεθός του:

- **Runs well with vLLM** ή **Runs well with Ollama**, με μια πρόχειρη ταχύτητα («about 40 tokens/s»· το token είναι ένα κομμάτι λέξης): χωράει στη μνήμη της κάρτας γραφικών σας.
- **Στον επεξεργαστή, αργά** ή **Στον επεξεργαστή, πολύ αργά**: χωράει μόνο στη μνήμη του υπολογιστή, οπότε τρέχει στον επεξεργαστή. Μόνο το Ollama μπορεί να το κάνει αυτό.
- **Πολύ μεγάλο για αυτόν τον υπολογιστή**: δεν χωράει ή η λήψη δεν χωράει στον δίσκο.
- **At 4-bit with Ollama: runs well…**: το μοντέλο όπως είναι αποθηκευμένο είναι πολύ μεγάλο, αλλά η συμπιεσμένη έκδοσή του στα 4-bit θα έτρεχε καλά με το Ollama.

Τοποθετήστε τον δείκτη πάνω στην ετικέτα για να δείτε τους αριθμούς πίσω από αυτήν.

### Έλεγχος πριν από τη λήψη

Κάντε κλικ στον **Έλεγχο** ενός μοντέλου για να δείτε ακριβώς πώς θα έτρεχε εδώ. Το πάνελ δείχνει το μέγεθός του, πόσα διαβάζει ταυτόχρονα (το πλαίσιό του), αν βλέπει εικόνες και, στη συνέχεια:

- Για ένα μοντέλο GGUF: «Runs with Ollama» και κάθε διαθέσιμο μέγεθος (τα μικρότερα αρχεία ανταλλάσσουν λίγη ποιότητα με ταχύτητα και μνήμη), από το μικρότερο. Κάθε γραμμή δίνει την εκτίμησή της, τη μνήμη που χρειάζεται, πόσο γρήγορα περίπου θα έτρεχε και το μέγεθος λήψης, με ένα κουμπί **Εγκατάσταση**. Η Εγκατάσταση είναι γκριζαρισμένη όσο το Ollama δεν τρέχει εδώ ή για ένα μέγεθος που είναι πολύ μεγάλο.
- Για ένα μοντέλο vLLM: «Runs with vLLM, which starts it on a GPU when a session uses it», τα ίδια στοιχεία, σημειώσεις για το ποια κάρτα γραφικών θα χρησιμοποιούσε και ένα κουμπί **Λήψη**. Αν το vLLM δεν είναι εγκατεστημένο ή το vLLM σας δεν μπορεί ακόμη να τρέξει αυτό το είδος μοντέλου, το αναφέρει, και όταν υπάρχει έκδοση GGUF προσφέρει **έλεγχος** για εκείνη.
- Για οτιδήποτε άλλο: «No weights this app can run (safetensors for vLLM, GGUF for Ollama).»

Οι αριθμοί προϋποθέτουν συζήτηση έως περίπου 32.000 tokens, το μήκος που δίνεται σε ένα μοντέλο σε αυτόν τον υπολογιστή. Το **Κλείσιμο** διπλώνει το πάνελ.

### Εγκατάσταση και τι συμβαίνει μετά

Κάντε κλικ στην **Εγκατάσταση** (Ollama) ή στη **Λήψη** (vLLM). Η λήψη εμφανίζεται στο **Σε αυτό το μηχάνημα** με την πρόοδό της. Όταν ολοκληρωθεί, το μοντέλο εμφανίζεται στο μενού **Μοντέλο** του Custom. Μια λήψη vLLM που διακόπηκε συνεχίζεται από εκεί που σταμάτησε όταν δοκιμάσετε ξανά. Ένα μοντέλο vLLM που είναι πολύ μεγάλο για οποιαδήποτε κάρτα γραφικών αποθηκεύεται στα 8-bit (FP8) καθώς ξεκινά, κάτι που υποδιπλασιάζει τη μνήμη που παίρνουν τα βάρη του με μικρή απώλεια (από τις κάρτες RTX 30 της NVIDIA και την A100 και μετά)· αν και πάλι δεν χωράει, μοιράζεται σε περισσότερες κάρτες, αν μαζί έχουν χώρο.

### Περιορισμένα και ιδιωτικά μοντέλα

Ορισμένοι δημιουργοί ζητούν πρώτα να αποδεχτείτε τους όρους τους· τα μοντέλα τους εμφανίζουν την ένδειξη **Περιορισμένο**. Αποδεχτείτε τους όρους στη σελίδα του μοντέλου στο huggingface.co και στη συνέχεια προσθέστε ένα token του Hugging Face (δείτε [Token του Hugging Face](#hugging-face-token)). Και τα ιδιωτικά μοντέλα χρειάζονται το token.

## Χρήση μοντέλων μέσω του OpenRouter

Το OpenRouter (openrouter.ai) σάς δίνει εκατοντάδες μοντέλα από πολλούς δημιουργούς με ένα μόνο κλειδί, με πληρωμή ανά χρήση.

### Προσθήκη του κλειδιού σας

1. Αποκτήστε ένα κλειδί στο openrouter.ai (οι σύνδεσμοι της ενότητας οδηγούν εκεί).
2. Στις [Ρυθμίσεις → Agents → Models](/settings?s=models&find=OpenRouter), κάντε κλικ στην **Προσθήκη κλειδιού** στη γραμμή **Το κλειδί σας για το OpenRouter**, επικολλήστε το στο **Το κλειδί σας OpenRouter: sk-or-…** στο παράθυρο διαλόγου και κάντε κλικ στην **Αποθήκευση**.

Η γραμμή δείχνει τότε **Συνδέθηκε στο OpenRouter** με την αρχή και το τέλος του κλειδιού σας. Η **Αφαίρεση κλειδιού**, στο μενού **⋯** της, ξεχνά το κλειδί. Το κλειδί παραμένει στον διακομιστή και δεν εμφανίζεται ποτέ ξανά.

Μπορείτε επίσης να το προσθέσετε όταν χρειαστεί για πρώτη φορά: ένας πράκτορας που πρόκειται να φτιάξει μια εικόνα, ένα σχέδιο, ένα βίντεο ή έναν ήχο χωρίς αυτό το ζητά με μια κάρτα στη συνομιλία ([Όταν ένας πράκτορας χρειάζεται το κλειδί του OpenRouter](/guide/documents-voice#when-an-agent-needs-the-openrouter-key)), και τα εργαλεία AI των επεξεργαστών το ζητούν στο παράθυρό τους. Και στις δύο περιπτώσεις φυλάσσεται εδώ.

### Προτεινόμενα μοντέλα

Πριν αναζητήσετε, τα **Προτεινόμενα**, στην ομάδα **Προσθήκη μοντέλων OpenRouter**, απαριθμούν τέσσερα μοντέλα για το Custom, με τον λόγο για το καθένα: **GPT-6 Luna** (Fast and cheap), **Grok 4.7** (Good, with fewer refusals), **GPT-6.1 Sol** (Better) και **Claude Opus 5.5** (Best overall). Η **Προσθήκη** βάζει ένα στις λίστες επιλογής. Για εικόνες, μουσική, φωνές και βίντεο, οι επιλογές της εφαρμογής είναι το Seedream 5.0 Pro (και το Flash, γρηγορότερο και φθηνότερο), το Lyria 3 Pro, το Seed Audio 1.0 και το Seedance 2.5: δείτε [Ρυθμίσεις → Δυνατότητες → Images, video and audio](/settings?s=images).

### Αναζήτηση στον κατάλογο

Στην ίδια ομάδα, πληκτρολογήστε στο **Αναζήτηση στο OpenRouter: deepseek, qwen, claude…**, ή κάντε κλικ σε ένα από τα προτεινόμενα ονόματα ή στο **δείτε τα νεότερα**. Φίλτρα:

- **Κλήσεις εργαλείων**: μοντέλα που καλούν εργαλεία εγγενώς, με τον τρόπο που τα χρησιμοποιεί καλύτερα το Custom (η **Καλύτερη αντιστοιχία** βάζει αυτά πρώτα).
- **Βλέπει εικόνες**
- **Συλλογισμός**: μοντέλα που σκέφτονται πριν απαντήσουν.
- **Δωρεάν**

Το μενού στα δεξιά ταξινομεί τα αποτελέσματα: **Καλύτερη αντιστοιχία** (όσο αναζητάτε με όνομα), **Νεότερα**, **Φθηνότερα** ή **Μεγαλύτερο πλαίσιο**. Παίρνετε έως 50 μοντέλα, τα πρώτα οκτώ αρχικά και **Εμφάνιση όλων** για τα υπόλοιπα.

Κάθε μοντέλο δείχνει τον δημιουργό, το όνομα και ετικέτες: **Πιο πρόσφατα** (πάντα η νεότερη έκδοση του δημιουργού), **Νέο** (καταχωρίστηκε τις τελευταίες τρεις εβδομάδες), **Δωρεάν**, **Συλλογισμός**, **Εικόνες** και **Χωρίς εγγενή εργαλεία** (το Custom τότε περιγράφει τα εργαλεία του στις οδηγίες και διαβάζει τις κλήσεις του από το κείμενό του). Από κάτω: πόσα διαβάζει ταυτόχρονα («128K context»), η μεγαλύτερη απάντησή του («16K out»), η τιμή του ανά εκατομμύριο tokens εισόδου και εξόδου, ο μήνας που καταχωρίστηκε, μια σύντομη περιγραφή και το όνομά του στο OpenRouter.

### Προσθήκη μοντέλων στις λίστες επιλογής

Κάντε κλικ στην **Προσθήκη** σε ένα μοντέλο. Η γραμμή του λέει τότε **Προστέθηκε** και το μοντέλο εμφανίζεται στην ομάδα **Τα μοντέλα σας στο OpenRouter** («In the model pickers») πάνω από την αναζήτηση και στο μενού **Μοντέλο** του Custom. Κάντε κλικ στο × σε ένα από αυτά για να το βγάλετε από τα μενού. Μέχρι να προσθέσετε τουλάχιστον ένα, το OpenRouter δεν προσφέρει κανένα μοντέλο («Add at least one model to use OpenRouter.»).

### Ένταση σκέψης για τα μοντέλα του OpenRouter

Ένα μοντέλο με συλλογισμό προσφέρει, στο μενού **Ένταση σκέψης**, τις εντάσεις που αναφέρει γι' αυτό το OpenRouter, από τις **Κανένα** (χωρίς συλλογισμό), **Μινιμαλιστικό**, **Χαμηλό**, **Μεσαίο**, **Υψηλό**, **Xhigh** και **Μέγιστο**. Το Custom ζητά μεσαία ένταση όσο είναι επιλεγμένη η **Προεπιλογή**, και αλλιώς την ένταση που διαλέγετε. Ένα μοντέλο του οποίου οι εντάσεις δεν περιλαμβάνουν τη μεσαία κρατά τη δική του προεπιλογή, ενώ ένα μοντέλο που δεν αναφέρει καμία δεν έχει ρύθμιση **Ένταση σκέψης** και του ζητείται η μεσαία.

## Σύνδεση του Ollama, του vLLM ή άλλου τελικού σημείου

Η ομάδα **Περιβάλλοντα εκτέλεσης και τελικά σημεία** συνδέει τα προγράμματα που εκτελούν μοντέλα. Ανοίξτε την από το [Ρυθμίσεις → Πράκτορες → Μοντέλα](/settings?s=models&find=Runtimes%20and%20endpoints).

### Ollama

Το Ollama είναι ένα δωρεάν πρόγραμμα που εκτελεί μοντέλα στον υπολογιστή σας, στην κάρτα γραφικών ή στον επεξεργαστή. Η γραμμή του γράφει «σε λειτουργία» μαζί με την έκδοσή του, ή «δεν εκτελείται σε αυτή τη διεύθυνση» με έναν σύνδεσμο **Εγκατάσταση Ollama**. Η διεύθυνσή του είναι `http://127.0.0.1:11434`, εκτός αν την αλλάξετε: πληκτρολογήστε μια άλλη στο πεδίο και δίπλα της εμφανίζεται το κουμπί **Αποθήκευση**. Κάθε μοντέλο αυτού του Ollama εμφανίζεται στη λίστα μοντέλων του Custom, ακόμη και όσα κατεβάσατε εκτός εφαρμογής.

### vLLM

Το vLLM είναι ένας γρήγορος διακομιστής για μοντέλα σε κάρτες γραφικών NVIDIA και ο τρόπος με τον οποίο εκτελούνται εδώ από προεπιλογή τα μοντέλα από το Hugging Face. Ένα μοντέλο που είναι πολύ μεγάλο για μία κάρτα εκτελείται σε αυτό στα 8 bit ή μοιρασμένο σε 2, 4 ή 8 κάρτες. Σε Mac, το vLLM εκτελείται σε Apple silicon με το πρόσθετο Metal (vllm-metal). Η εφαρμογή το βρίσκει μόνη της στο PATH ή σε περιβάλλον conda ή venv και εμφανίζει την έκδοσή του και πού βρίσκεται. Αν γράφει «δεν βρέθηκε (pip install vllm), ή δώστε την εντολή του», εγκαταστήστε το ή πληκτρολογήστε στο πεδίο την πλήρη διαδρομή της εντολής `vllm` και κάντε κλικ στο **Αποθήκευση** (εμφανίζεται μόλις πληκτρολογήσετε). Αφήστε το πεδίο κενό για να ψάξει η εφαρμογή μόνη της.

### Άλλα τελικά σημεία συμβατά με το OpenAI

Πολλά προγράμματα και υπηρεσίες απαντούν με τον ίδιο τρόπο με το API του OpenAI: το LM Studio, ο διακομιστής του llama.cpp, άλλοι πάροχοι. Για να προσθέσετε ένα:

1. Κάντε κλικ στο **Προσθήκη τελικού σημείου**, δίπλα στον τίτλο της ομάδας.
2. Στο παράθυρο διαλόγου, πληκτρολογήστε ένα **Όνομα**, τη διεύθυνσή του (όπως `http://localhost:1234/v1`) και ένα **Κλειδί (προαιρετικό)**.
3. Κάντε κλικ στο **Προσθήκη**.

Το τελικό σημείο εμφανίζεται ως γραμμή με τη διεύθυνσή του και τον αριθμό των μοντέλων που προσφέρει. Τα μοντέλα του εμφανίζονται στη λίστα του Custom ως «μοντέλο (όνομα)». Το × το αφαιρεί. Αν προσθέσετε άλλο τελικό σημείο με το ίδιο όνομα, αντικαθιστά το πρώτο.

Κάντε κλικ στον **Ορισμό των δυνατοτήτων κάθε μοντέλου** κάτω από τη γραμμή για να δείτε τα μοντέλα του, το καθένα με δύο επιλογές: **Βλέπει εικόνες** και **Ένταση σκέψης**. Η καθεμία είναι **Αυτόματα**, **Ναι** ή **Όχι**. Ένα μοντέλο που κάνει συλλογισμό έχει και τρίτη, τα **Επίπεδα έντασης σκέψης**. Ένα μοντέλο που βλέπει εικόνες λαμβάνει τα στιγμιότυπα οθόνης και τις εικόνες ως εικόνες, ενώ ένα μοντέλο που δεν βλέπει λαμβάνει μια περιγραφή τους (δείτε [Εικόνες για μοντέλα που δεν βλέπουν](/guide/custom#images-for-models-that-dont-see)). Ένα μοντέλο που κάνει συλλογισμό προσφέρει τα επίπεδά του στο μενού **Ένταση σκέψης** (Low, Medium και High, εκτός αν ορίσετε άλλα), και το Custom στέλνει αυτό που διαλέγετε ως `reasoning_effort`, τη ρύθμιση που δέχονται οι διακομιστές οι συμβατοί με το OpenAI (δεν στέλνεται τίποτα όσο είναι επιλεγμένη η **Προεπιλογή**). Το **Αυτόματα** ακολουθεί ό,τι λέει το τελικό σημείο για το μοντέλο, και το μενού δείχνει ποιο είναι αυτό: οι διακομιστές που περιγράφουν τα μοντέλα τους (με τον τρόπο του OpenRouter, του Mistral και άλλων) το αναφέρουν στη λίστα των μοντέλων τους, και για μια πύλη LiteLLM το Hydor ζητά επίσης τις πληροφορίες μοντέλων της, με το ίδιο κλειδί. Ένα τελικό σημείο που δεν λέει τίποτα λογίζεται ως όχι: ορίστε **Ναι** για τα μοντέλα που ξέρετε ότι βλέπουν εικόνες ή κάνουν συλλογισμό. Ό,τι ορίσετε διατηρείται όταν προσθέσετε ξανά το τελικό σημείο.

Για να αλλάξετε τα επίπεδα ενός μοντέλου, κάντε κλικ στα **Επίπεδα έντασης σκέψης** δίπλα του. Σημειώστε όσα δέχεται από τα `none`, `minimal`, `low`, `medium`, `high`, `xhigh` και `max`, ή πληκτρολογήστε στο **Άλλο επίπεδο** κάποιο άλλο που δέχεται το τελικό σημείο και κάντε κλικ στην **Προσθήκη** (μία λέξη· τουλάχιστον ένα επίπεδο μένει σημειωμένο). Η **Χρήση low, medium και high** επαναφέρει τα τρία συνηθισμένα. Το ποια επίπεδα δέχεται ένα μοντέλο το καθορίζει ο διακομιστής του: αν απορρίψει κάποιο, το Custom στέλνει ξανά το αίτημα χωρίς αυτό, και το μοντέλο εκτελείται με τη δική του προεπιλογή.

Μια [εμπιστευτική συνεδρία](/guide/sessions#keep-a-session-confidential) μπορεί να χρησιμοποιεί τελικό σημείο του οποίου η διεύθυνση είναι αυτός ο υπολογιστής ή το ιδιωτικό σας δίκτυο: `localhost`, `127.0.0.1`, `::1`, `10.…`, `192.168.…`, `172.16.…` έως `172.31.…`, ή όνομα που τελειώνει σε `.local`. Κάθε άλλη διεύθυνση θεωρείται διαδικτυακή, ακόμη και αν οδηγεί στον δικό σας διακομιστή: χρησιμοποιήστε αντί γι' αυτήν την ιδιωτική του διεύθυνση. Το ίδιο ισχύει και για τη διεύθυνση του Ollama, ενώ τα μοντέλα cloud του Ollama (τα ονόματά τους τελειώνουν σε «cloud») θεωρούνται πάντα διαδικτυακά.

### Token του Hugging Face

Ένα [token του Hugging Face](/settings?s=models&find=Hugging%20Face%20token) επιτρέπει στην εφαρμογή να κατεβάζει μοντέλα με περιορισμένη πρόσβαση ή ιδιωτικά (η γραμμή γράφει «Μόνο για μοντέλα με περιορισμένη πρόσβαση ή ιδιωτικά»). Δημιουργήστε ένα στις ρυθμίσεις του λογαριασμού σας στο Hugging Face, κάντε κλικ στο **Προσθήκη token**, επικολλήστε το στο παράθυρο διαλόγου (ξεκινά με `hf_`) και κάντε κλικ στο **Αποθήκευση**. Η γραμμή δείχνει τότε την αρχή και το τέλος του, με την **Αφαίρεση token** στο μενού **⋯** της.
