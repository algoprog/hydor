# 複数のエージェントによるディープリサーチとセカンドオピニオン

エージェント1つでは足りないとき、アプリは複数のエージェントに仕事を任せられます。ディープリサーチは、質問のあらゆる部分にリサーチャーを送り出し、出典付きのレポートを返します。サブエージェントは、エージェントの作業の一部を引き受けます。スウォームは、難しい問題に複数の角度から同時に取り組みます。キャンペーンは、1つの大きな変更を多くの部分に分けて行います。ほかにも、別の会社のモデルにターンの作業を確認させたり、1つのプロンプトを複数のモデルに送って最良の回答を残したり、セッションが使える金額に上限を設けて、これらの作業で費用が膨らまないようにしたりできます。

## ディープリサーチを実行する

ディープリサーチは、多くの情報源が必要な質問に向いています。選択肢の比較、主張の検証、テーマの調査、ある事柄についてわかっていることの洗い出しなどです。開始したエージェントが全体を取りまとめます。検索を計画し、質問の各部分にリサーチャーを送り、残された疑問を掘り下げ、重要な主張を2つの情報源で確認し、すべての出典を明記したレポートを届けます。

### オンにする

1. スタート画面でメッセージ欄の下の行の右にあるチップの**オプション**を開き、**リサーチ**を選びます。
2. **ディープリサーチ**（「幅広く検索し、情報源を確認して引用します」）を選びます。その下に設定が表示されます。
3. 数値と、希望するレポートの種類を設定します（下記参照）。
4. メッセージ欄に質問を入力し、**開始**を押します。

リサーチの行には「ディープ · 検索60回」（検索の予算）と表示され、オプションのチップにも「ディープリサーチ」と表示されます。1つのエージェントに戻すには**オフ**（「エージェント1つが、必要に応じて検索しながら回答します」）を選びます。

スマートフォンでは、オプションは画面下からシートとして開き、その上にリサーチが開きます。

ディープリサーチとスウォーム（またはキャンペーン）は、どちらもHydorサブエージェントのチームで動くため、使えるのは一方だけです。一方をオンにすると、もう一方はオフになります。

初めて**ディープリサーチ**を選ぶと、「ディープリサーチを使う前に」というダイアログが表示されます。何をするものか、どんな場合に価値があるか、どんな場合には向かないか、費用はどのくらいかが説明されています。続けるには**ディープリサーチを使う**を、元の状態のままにするには**キャンセル**を押します。このダイアログは、どの端末でも、どこで選んでも（スタート画面、スケジュールタスクのオプション、セッションのダイアログ）、ヒントがオンかオフかにかかわらず、1人につき一度だけ表示されます。エージェントにヒントをもう一度表示するよう頼むと、再び表示されます。

スタート画面で決める必要はありません。すでに進行中のセッションでは、メニュー（⋯）→**セッション設定**→**ディープリサーチ**を開きます。ヒントには「オフ」または検索回数（「検索60回」）が表示されます。ダイアログには**オフ**と**ディープリサーチ**があり、設定は上記と同じです（**同時リサーチャー数**、**ラウンド数**、**検索の合計**、**レポート**）。終わったら**保存**を押すか、**キャンセル**を押します。変更は次のメッセージから反映されます。そのメッセージの前に、セッションのエージェント（Claude CodeまたはCodex）が新しい指示とツールで再起動し、会話はそれまでの続きから進みます。ディープリサーチをオンにするとスウォームがオフになり、その逆も同様です。メッセージ欄の**+**の横にあるチップ（その**オプション**）にも、**権限**の下に同じ**ディープリサーチ**の行があります。

機密セッションや、ほかのセッションが開始したセッション（スウォームのメンバー、リサーチャー、サブエージェント）には、この項目は表示されません。

スケジュールタスクでは、実行のたびにディープリサーチを行えます。エディタに同じ**リサーチ**設定があります（[スケジュールタスク](/guide/tasks)）。

### 設定

- **同時リサーチャー数**（1〜8、初期値は4）：各ラウンドで同時に検索するリサーチャーの数です。各ラウンドの幅になります。
- **ラウンド数**（1〜5、初期値は2）：リサーチを何ラウンド行うかです。各ラウンドは、前のラウンドで残された疑問を追います。これらのあとに、確認のラウンドが1回あります。
- **検索の合計**（10〜500、10刻み、初期値は60）：リサーチ全体で使えるウェブ検索の回数です。リードとリサーチャーの分を合わせて数えます。
- **レポート**：**ページ**または**Word**。

ブラウザは、次回のディープリサーチ用に数値を記憶します。モードそのものは記憶されません。ディープリサーチは1回の回答の数倍の費用がかかるため、新しいセッションは毎回リサーチがオフの状態で始まります。

### 処理の流れ

1. **プラン.** リードは、質問が本当は何を問うているのか、完全な回答には何が必要かを整理します。それを小さな問いに分け、それぞれに表現を変えた検索をいくつか用意します。役立つ場合は他の言語も使い、決め手になる情報源（公式データ、論文、一次資料、信頼できる報道）を狙います。重要な点が不明なときは、ユーザーに一度だけ簡潔に尋ねます。そうでなければ前提を明示して先へ進みます。
2. **最初のラウンド.** 設定した人数を上限に、小さな問い1つにつきリサーチャー1人を起動します。各リサーチャーはHydorサブエージェントで、それぞれ専用の指示を受け取ります。質問全体、担当部分、検索の出発点、自分の分として使う検索のおおよその回数、報告すべき内容です。そのあとリードは待機し、各リサーチャーの報告がメッセージとして届きます。
3. **追加のラウンド.** リードは報告を読み、抜けている部分、矛盾、1つの情報源だけに頼っている主張に新しいリサーチャーを送ります。重要な疑問が残っていなければ、そのラウンドは省略します。各ラウンドのあとには、わかったことと次の予定を1行で伝えます。
4. **確認.** 回答の根拠となる主張を一覧にします。それぞれ独立した2つの情報源が必要で、1つの情報源にしか基づかない場合や、見解が分かれている場合はその旨を記します。リサーチャー（またはリード自身）が引用されたページを開き、重要な主張や数値が本当にあるかを確かめます。確認できなかったものは修正または削除されます。
5. **レポート.** レポートを書きます。わかりやすいタイトル、最初に数文の結論、続いて各セクション、主張ごとに番号付きの引用、最後に情報源（タイトル、サイト、日付、リンク）を載せます。不確かな点や見解が分かれている点とその理由も明記し、会話では短い要約を伝えます。

リサーチャーは、アプリ独自のウェブ検索で検索し、ページリーダーでページを読みます（[検索とブラウザ](/guide/web)）。すべての検索が予算に数えられるよう、ディープリサーチ中はClaude CodeとCodexの組み込みウェブ検索はオフになります。予算を使い切ると検索は拒否され、エージェントは手元の情報からレポートを書くよう指示されます。同様に、設定したラウンドと確認のラウンドが終わると、リードはそれ以上リサーチャーを起動できません。

### セッションで進行を見る

リードのセッションのメッセージ欄の上にあるバーに、リサーチの状況が表示されます。**ディープリサーチ** · 「計画中」、続いて「ラウンド1／2 · リサーチャー4人が作業中」、ラウンドの合間は「報告を読んでいます」、リサーチャーが重要な主張を確認している間は「情報源を確認中」、「レポートを作成中」、最後に「レポートの準備ができました」と表示され、あわせて予算の使用状況（「60回中12回の検索」）も表示されます。レポートができると、バーの右にある**レポートを開く**でレポートを開けます。ページまたはWordドキュメントです。バーにポインターを合わせると、リサーチの設定とレポートの種類を確認できます。

各リサーチャーは、リードの会話の中でリサーチャー全員が共有する1枚のカード（「リサーチャー4人」）に1行ずつ表示され、ほかの[Hydorサブエージェント](/guide/research#follow-subagents)と同じようにサイドバーのリードの下にも並びます。各リサーチャーからの報告は、「返信元」とそのタイトルの1行として表示され、見つかった内容の冒頭が添えられます。行をクリックすると全文を読めます。リサーチャーを開くと作業の様子を見られます。そのバーには「リサーチ中：」とリードのタイトルが表示され、**リード**で元に戻れます。

### レポート

- **ページ**：レポートは、保存されるページとして残ります。会話に表示され、セッションのプロジェクトのファイル（その詳細→**ファイル**）に保存されます。セッションにプロジェクトがない場合は、会話と一緒に保存されます（[ページ、ドキュメント、画像](/guide/library)）。
- **Word**：レポートは、セッションのフォルダにあるWordドキュメント（.docx）です。アプリの**word-documents**スキルで作成され、開いたりダウンロードしたりできるファイルカードとして表示されます（[ドキュメント、画像、動画、音声](/guide/documents-voice#open-or-download-the-files-an-agent-made)）。

ディープリサーチでは、多くのエージェントが同時に動きます。開始する前に、同じオプションメニューで支出上限を設定してください。上限は、リードとすべてのリサーチャーの分を対象とします（[セッションに支出上限を設ける](/guide/research#put-a-spending-cap-on-a-session)）。

## エージェントからサブエージェントに作業を任せる

どのエージェントも、自分の仕事のうち独立した部分をサブエージェントに任せられます。サブエージェントは同時に作業を進め、終わると結果を報告します。サブエージェントには2種類あり、アプリがどちらかを表示します。**Hydorサブエージェント**は、Hydorが開始する独立したセッションで、任意のエージェントとモデルを使えます。会話のサブエージェントカードに1行表示され、サイドバーでは親の下に並び、独自のコストと支出上限の独自の割り当てを持ちます。開いて話しかけることもでき、その返信はメッセージとして親に戻ります。**Claude Codeサブエージェント**は、Claude Codeがセッション内で仕事の短い部分のために実行するものです（Codexの場合は「Codexサブエージェント」）。Hydorサブエージェントと同じように、会話のカードに1行、サイドバーとメッセージ欄の上のトレイに1行表示され、開いて読める専用のページもありますが、話しかけることはできません。使った分はセッション自身の分として数えられ、支出上限の割り当てもありません。トレイと各行には、それぞれの種類が表示されます（「Hydorサブエージェント · Claude Code · Sonnet 5.5」や「Claude Codeサブエージェント · Explore · Sonnet 5.5」）。ポインタを合わせると、実行しているものが表示されます（[サブエージェント](/guide/sessions#subagents)）。このセクションの残りは、Hydorサブエージェントについて説明します。

オンにする操作は必要ありません。普通の言葉で頼むか（「サブエージェント3つで、仕入れ先を1社ずつ調べて」「ドキュメントはそっちでやって、テストはCodexに書かせて」）、仕事がうまく分かれるときにエージェント自身に判断させます。セッションのメインエージェントは、最初からこのように働くよう指示されています。計画と確認は自分で行い、はっきりした部分を安いティアのサブエージェントに任せるため、仕事のコストが下がります（[ティア：仕事の種類ごとのモデル](/guide/agents-models#tiers-a-model-for-each-kind-of-job)を参照してください。そこの**サブエージェントを主導**で、この動作をオフにできます）。

エージェントは、Hydorサブエージェントごとに次のものを選びます。

- **エージェントとモデル**：Custom（[設定 → モデル](/settings?s=models)にある任意のモデル）、Claude Code、Codex、または追加した別のエージェント（Gemini CLI、OpenCodeなど）。既定では、Hydorサブエージェントは開始元のセッションと同じエージェントで動きます。大量の作業には安価なモデルやローカルモデルが向き、難しい部分にはClaude CodeやCodexが向いています。
- 担当部分の**ティア**：**高速**は小さくてごく明確な仕事向け、**標準**は中くらいの規模の明確なタスク向け（指定がないときにHydorサブエージェントが使うティア）、**最高**はそれだけで完結する難しい部分向けです。そのエージェントプログラムでのティアのモデルは[設定 → モデル → ティア](/settings?s=models&find=Tiers)で決まります。Hydorサブエージェントは、親自身のティアより上のティアでは動きません。また、ユーザーのエージェントは、そのサブエージェントのティアにより低い上限を設けることもできます。
- 通常のサブエージェントの代わりに、名前を指定した**ユーザーのエージェント**：そのエージェント自身の指示、ツール、ティアで作業します（[他のエージェントに作業を任せるエージェント](/guide/agents#agents-that-hand-work-to-other-agents)を参照してください）。自分の会話を持つエージェントには、代わりに受信トレイに作業が届き、手が空いたときに返信が戻ります。
- **フォルダ**：親のフォルダ。別のフォルダを指定した場合はそちらになります。
- 必要な場合は**ワークツリー**：フォルダのGitリポジトリを新しいブランチに別コピーしたもので、サブエージェントの変更がほかの変更と混ざりません。
- **短いタイトル**：表示される名前になります。

Hydorサブエージェントには親の会話の内容は一切見えないため、エージェントが必要な情報をすべて含めた指示書を書いて渡します。作業中は誰も見張っていません。小さな疑問は自分で判断し、判断したことを伝え、先に進めなくなったときだけ止まって質問します。

### 返信が戻る仕組み

Hydorサブエージェントのターンが終わると、その返信がメッセージとして親に戻り、親が起こされます。親が作業中の場合、メッセージは親のターンが終わるまでキューで待ちます。

親の会話では、返信は1行で表示されます。「Reply from」、サブエージェントのタイトル、書かれた内容の冒頭です。この行をクリックして返信を読み（長い場合は要約）、**セッションを開く**または**返信をすべて読む**でサブエージェントに移動します。完了前に停止したサブエージェントは「… was stopped」、失敗したものは「… stopped with an error」と表示されます。使用量の上限に達しても続行するものは「… carries on after a usage limit」と表示され、どのように続行するかも示されます。

バックグラウンドで作業したClaude CodeサブエージェントやCodexサブエージェントも、同じように戻ります。「Reply from」とタイトル（または「… was stopped」「… stopped with an error」）に、書かれた内容の冒頭が付いた1行で、クリックして返信を読み、**セッションを開く**で移動できます。Codexサブエージェントの返信は、行を開いたときにその会話から取得されます（「Loading its reply」）。親がまだ作業中に届いた返信は、その前後のステップの間にそのまま表示されます。

- 約4,000文字より長い返信は、補助モデルが書いた短い要約として届きます（[エージェント、アカウント、モデル](/guide/agents-models)）。親は全文を読むこともできます。
- Hydorサブエージェントがエラーで停止した場合や、完了前に停止された場合も、親に通知されます。
- 使用量の上限でHydorサブエージェントのターンが止まっても続行する場合（別のアカウントやAPIクレジットを使う、または上限のリセット後に自動で再開する）は、エラーではなくその旨が親に通知されるため、親が作業をやり直すことはありません。サブエージェントの返信は、終わったときに届きます。停止したままのものだけがエラーとして報告されます。詳しくは[すべてのアカウントを使う：上限でアカウントを切り替える](/guide/agents-models#use-all-your-accounts-switch-at-a-limit)を参照してください。
- 高速または標準で開始したHydorサブエージェントは、返信が簡易チェック（補助モデルが指示書と返信を読みます）に通らなかった場合や、エラーで停止した場合、1つ上のティアでもう一度実行されます。上がるのは最高までで、リードに許可された最上位のティアを超えることはありません。この場合、起きたことと理由が親に通知されます。チェックされるのは指示書に対する返信だけで、その後のメッセージへの返信は対象外です。ユーザーのエージェントでは、これをオフにできます（**チェックに失敗したらティアを上げる**）。親も、結果が不十分だと判断したときに、自分でサブエージェントのティアを上げられます。
- 親はいつでもHydorサブエージェントの状況を確認でき（それぞれの作業内容、エージェントとモデル、使った金額、最新の返信の冒頭）、いずれかにさらに作業を送れます。
- アプリが停止している間に終わったターンの返信は、アプリの再起動時に渡されます。

Hydorサブエージェントを開いて、ほかのセッションと同じように話しかけられます。ターンの最後にサブエージェントが返信した内容も、親に戻ります。

### サブエージェントを追跡する

- **親の会話で**：1つのターンが開始したサブエージェントは、そのターンの下に1枚のカードにまとめて表示されます。Hydorサブエージェントは1枚、プログラム自身のサブエージェントは別の1枚です。先頭の行には、数と種類、全員に共通する情報（「Hydorサブエージェント3件 · Claude Code · Sonnet 5.5」「Claude Codeサブエージェント6件 · Sonnet 5.5」、ディープリサーチでは「リサーチャー4人」）、状況（「5 working · 1 done」、ほかに「1 needs you」「1 stopped」「1 failed」）が表示されます。クリックするとカードを折りたたんだり開いたりできます。いずれかが作業中または確認待ちの間は開いたままで、すべて終わると先頭の行だけに折りたたまれます。その下には、サブエージェントごとに1行が表示されます。状態を示す色の点（作業中は青、確認待ちは黄、完了は緑、停止はグレー、失敗は赤）、タイトル、広い画面では他と異なる情報（種類やモデル、そのエージェントとして働くユーザーのエージェント、ティア）、状況（作業時間、「Needs you」、完了時は「3 min ago」、「Stopped」、「Failed」）です。Hydorサブエージェントの行には使った金額も表示され、ティアを上げたものにポインタを合わせると、最初のティアと理由とともに「Stepped up from」が表示されます。Claude CodeサブエージェントとCodexサブエージェントには、独自のコストはありません。行をクリックするとサブエージェントが開きます。ほかが作業中の間、完了したものは1行にまとめて折りたたまれ（「4 finished: 」とそのタイトル。クリックすると表示されます）、失敗したものは単独の行のまま残ります。作業中が6件を超えると5件が表示され、**Show 3 more**が付きます。1つだけサブエージェントを開始したターンでは、種類付きの1行カードで表示されます（「Claude Codeサブエージェント · Explore · Sonnet 5.5」）。1つを停止するには、その行にポインタを合わせる（またはTabキーで移動する）と、時間の代わりに**停止**が表示されます（タッチ画面では小さな停止ボタンが常に表示されます）。Hydorサブエージェントはすぐに停止し、Claude Codeサブエージェントは先に確認があり（「Stop this subagent?」）、Codexサブエージェントはここから1つずつ停止することはできません。カードの**⋯**メニューには**Stop 5 subagents**（停止できる数付き）があり、確認なしですべて停止します。
- **サイドバーで**：サブエージェントは親の下に置かれ、「3 subagents · 1 needs you · 2 working」のような1行にまとめて折りたたまれます。プログラム自身のサブエージェントが含まれる場合は「5 subagents · 1 working」のようになります。行をクリックすると展開され（プログラムのサブエージェントの行には⋯メニューはありません）、そのうちの1つを開いている間は開いたままです。サイドバーがドロワーになる携帯電話では、行をタップするとドロワーを閉じずに展開されます。
- **サブエージェント内で**：メッセージ欄の上のバーに「Subagent of」と親のタイトル（「its replies go back there」）が表示され、**親を開く**があります。Claude CodeサブエージェントとCodexサブエージェントのページは読み取り専用です。与えられたタスク、ステップ、返信が作業中にリアルタイムで表示され、メッセージ欄の代わりに「Claude Code subagent of」と親のタイトルが表示されたバーがあり、**親を開く**はありますが、**再開**もセッションメニューもありません。Claude Codeサブエージェントが作業中は、ヘッダーの**停止**で停止できます（先に確認があります）。メッセージの送信、再開、フォーク、引き継ぎ、削除はできません。そのプログラムが親のセッション内で実行しているため、話しかける相手は親です。

承認や回答が必要なHydorサブエージェントは、ほかのセッションと同じようにユーザーを待ち、受信トレイに表示されます（[受信トレイと通知](/guide/inbox)）。

### Hydorサブエージェントにできること・できないこと

- **1階層まで。** Hydorサブエージェントは、自分のHydorサブエージェントを開始できません。その部分は自分でこなし、ほかに必要なことを伝えます。
- **より自由な権限は与えられません。** Hydorサブエージェントは、開始元のセッションより自由な権限を持つことはありません。Claude Code、Codex、Customのいずれかで動く場合は、親の権限を超えない範囲で、そのエージェントの最も自由な権限が与えられます。そのほかのエージェント（Gemini CLIなど）は、そのエージェントの既定の権限で始まります。
- **上限の割り当て。** 親に支出上限がある場合、新しいHydorサブエージェントごとに、残りの一部が割り当てられ、親の上限がすべてをカバーします（[サブエージェントの上限](/guide/research#caps-for-subagents)）。
- **同じアカウント。** 親と同じエージェント（Claude CodeまたはCodex）で動くHydorサブエージェントは、親のアカウントを使います。
- **同時に動くのは数件。** 1つのセッションのHydorサブエージェントのうち、同時に作業できるのは決まった数だけです。エージェントは、1つが終わるのを待ってから次を開始します。

### 同時に動く数を設定する

[設定 → 機能 → サブエージェント](/settings?s=children)で、**サブエージェント**グループの**セッションごとの同時作業数**を−と＋で設定します（その(i)には、Hydorサブエージェントに適用される上限が一覧されています）（[設定へ移動](/settings?s=children&find=Working%20at%20once%2C%20per%20session)）。1〜12の範囲で、初期値は4です。数えるのはセッションごとのHydorサブエージェントで、アプリ全体ではありません。ディープリサーチでは代わりに**同時リサーチャー数**、スウォームでは**スウォームの規模**を使います。

## 難しい問題にスウォームを使う

スウォームは、1つの問題にエージェントのチームを投入する機能です。リードエージェントが、問題を本当に異なる切り口（異なる方法、前提、見方）に分け、切り口ごとにメンバーを開始します。メンバーは試したことや見つけたことを共有のボードに投稿し、互いの投稿を読み、メッセージを送り合います。リードは全体を舵取りし、終わったメンバーが出るたびに新たなメンバーを開始し、答えを確認してから報告します。

進め方がいくつも考えられる難しい問題向けです。たとえば証明、なかなか直らないバグ、取りかかり方がはっきりしない疑問などです。コストは、エージェント1つの場合の数倍かかります。

### スウォームを開始する

1. 開始ページで**オプション**を開き、**スウォーム**を選びます。
2. **スウォーム**を選びます（「最大5つのエージェントが同時に、それぞれ別の切り口で取り組みます」。数字はスウォームの規模です）。
3. タスクを入力して**開始**を押します。

スウォームの行には「オン · 同時に5」と表示され、オプションのチップにも名前が表示されます。そのメニューの下部にある**スウォームの規模**から、その設定に移動できます。ディープリサーチと同様に、このモードは次のセッションには引き継がれず、2つのうち一方しかオンにできません。同じオプションメニューで設定した支出上限は、リードとすべてのメンバーをまとめて対象にします。スケジュールタスクのエディタにも同じ**スウォーム**の設定があり、実行のたびにスウォームを使えます。

初めて**スウォーム**（または**キャンペーン**）を選ぶと、「スウォームを使う前に」というダイアログが表示され、できること、向いている用途、向いていない用途、コストが説明されます。**スウォームを使う**を押して進むか、**キャンセル**を押してオフのままにします。このダイアログはモードごとに1回、ユーザーごとにすべてのデバイスで表示され、ヒントのオン・オフには関係ありません。エージェントにヒントをもう一度表示するよう頼んだ場合も、再び表示されます。

セッションの途中でも、スウォームのオン・オフやキャンペーンへの切り替えができます。セッションのメニュー（⋯）→ **セッション設定** → **スウォーム**（ヒントには**オフ**、**オン**、**キャンペーン**のいずれかが表示されます）を開き、**オフ**、**スウォーム**、**キャンペーン**から選びます。変更は次のメッセージから有効になります。そのメッセージの前にセッションのエージェント（Claude CodeまたはCodex）が新しい指示とツールで再起動し、会話は続きます。スウォームをオンにするとディープリサーチはオフになり、その逆も同様です。機密セッションと、別のセッションが開始したセッション（メンバー、リサーチャー、サブエージェント）には、この項目はありません。メッセージ欄の**+**の横にあるチップ（**オプション**）にも、**権限**の下に同じ**スウォーム**の行があります。

### スウォームの仕組み

1. リードは、タスクが何を求めているか、確認済みの答えとはどのようなものかを整理し、スウォームの規模を上限として、異なる切り口を選びます（証明なら、直接的な議論、背理法、帰納法、小さなケースと計算機による探索、既知の結果など）。
2. 切り口ごとにメンバーを1つ開始します。各メンバーはHydorサブエージェントで、問題全体、担当の切り口、完了の基準、確認方法を書いた指示書を受け取り、切り口をタイトルにします。リードが別のモデルや思考レベルを選ばない限り、メンバーはリードと同じモデルと思考レベルで動きます。
3. メンバーは作業しながらボードに投稿します。種類は、**進捗**（試したことと現在地）、**発見**（他のメンバーがすぐ使える結果）、**質問**（答えが必要なこと）、**メモ**です。数ステップごとにボードを読み、互いの発見を土台にし、誰かが除外したものは省き、自分への質問に答えます。
4. リードにはボードの内容がまとめて届きます。発見、質問、リード宛てのメッセージは約1分以内に届き、進捗だけの場合は数分おきです。リードは有用な発見を共有し、行き詰まったメンバーや他と重複しているメンバーには新しい切り口を割り当て、あるメンバーに別のメンバーの結果の確認を依頼し、他のメンバーが終わるにつれて、まだ誰も試していない案のメンバーを開始します。
5. 結論を出す前に、リードは答えを独立して確認します。別のメンバー、計算、またはリード自身の慎重な確認のいずれかで行います。
6. 問題が解けたか、切り口を使い切ると、作業中のメンバーを停止し、答えを報告します。報告には、結果、見つけ方と確認方法、失敗した切り口とその理由が含まれます。

切り口を終えたメンバーは、リードに報告を送ります。作業していないメンバーに宛てたメッセージは、そのメンバーを起こします。

**ゴール付きのスウォーム**：スウォームを率いるセッションには、アプリがチェックするゴールを設定できます。その場合、各ラウンドはスウォーム全体の作業となり、完了かどうかを判断するのはリードではなくアプリです。[スウォームのためのゴール](/guide/goals#a-goal-for-a-swarm)をご覧ください。

### 進行を追う：バーとボード

リードのセッションでは、メッセージ欄の上にバーが表示されます。最初は**スウォーム** · 「切り口を選んでいます」、その後は「3件作業中 · 2件完了 · 14件の投稿」のような表示と、**ボード**が並びます。各メンバーのセッションにもバーがあり、「参加中のスウォーム」とリードのタイトル（「投稿と報告はそちらに送られます」）、**ボード**、**リード**が表示されます。サイドバーでは、メンバーはリードの下にまとめられ、「スウォームメンバー5件 · 3件作業中」のような1行で表示されます。

**ボード**を開くとスウォームボードが表示されます（スマートフォンでは画面の下から開きます）。

- **メンバー**：作業中の人数と同時に作業できる人数、続いて各メンバーと現在の作業内容が表示されます。終わったメンバーには「ターンを終了」、「停止」、「エラーで停止」と表示されます。メンバーをクリックするとそのセッションが開きます。**リードを開く**でリードに移動します。リードが切り口を選ぶ前は、まだ何も開始されていないと表示されます。
- **投稿**：投稿されたすべての内容が新しい順に表示されます。各投稿には、書いた人（リード、またはメンバーのタイトル）、特定の1人のメンバーまたはリード宛ての場合はその宛先、種類（進捗、発見、質問、メモ）、経過時間が表示されます。**すべて**、**発見**、**質問**で切り替えられます。新しい投稿は届き次第表示されます。

### メンバーを停止する

ボードの**すべて停止**（メンバーが作業中のときに表示されます）は、作業中のメンバーをすべて停止します。停止したメンバーはそれまでの作業内容を保持し、新しい投稿があっても起こされなくなります。リードには停止したことが通知され、リードは停止したメンバーにさらに作業を割り当てることもできます。問題が解けたときは、リードが自分でメンバーを停止します。

### スウォームの規模を設定する

[設定 → 機能 → サブエージェント](/settings?s=children)の**スウォームの規模**（**スウォーム**グループ内。[移動する](/settings?s=children&find=Swarm%20size)）で、1つのスウォームまたはキャンペーンで同時に作業するメンバーの数を1〜16の範囲で設定します。初期値は5です。メンバー1つあたりのコストはエージェント1つ分ほどで、リードは終わったメンバーが出るたびに新たなメンバーを開始します。

## キャンペーンで大きな変更を1つ行う

キャンペーンはもう1つのスウォームで、1つの難しい問題ではなく、コードベース全体にわたる大きな変更向けです。たとえば、移行、フレームワークのアップグレード、全体にわたる名前の変更などです。同じ場所の**オプション** → **スウォーム** → **キャンペーン**（「1つの大きな変更を、ワークツリーごとに分けて実行します」）で選びます。Gitリポジトリのフォルダで使えます。スウォームの行には「キャンペーン · 同時に5」と表示されます。すでに進行中のセッションでは、メニュー（⋯）→ **セッション設定** → **スウォーム** → **キャンペーン**で、次のメッセージから同じ設定になります。

リードは変更を部分（パッケージ、モジュール、フォルダ）に分け、計画として投稿します。メンバーは、スウォームの規模を上限として、新しいワークツリー内の専用ブランチで各部分を作成し、チェックを実行して、その部分を完了または失敗として投稿します。失敗した部分はもう1回試されます。リードは完了した部分を1つずつマージし、そのたびにチェックを実行します（依頼があれば、部分ごとにプルリクエストを作成します）。そして、変更された内容と失敗した内容を報告します。バーには「キャンペーン · 40件中12件完了 · 2件失敗」のように表示され、ボードには投稿とともに各部分とその状況が表示されます。[キャンペーン：多数の部分に分けた大きな変更](/guide/engineering#campaigns-a-big-change-in-many-parts)をご覧ください。

## ターンのセカンドオピニオンを得る

セカンドオピニオンは、別の会社のモデルに、エージェントが1つのターンで行ったことを、依頼内容と照らして確認させる機能です。変更したファイル、実行したコマンド、返信が対象です。レビュアーは、足りないもの（頼まれたのに未実施、または実施したと主張しているのに未実施）、誤り（バグ、誤った事実や数値、依頼の読み違い）、リスク（何かを壊す、データを失う、秘密情報を漏らす可能性のある変更）、余計なもの（誰も頼んでおらず、邪魔になる変更）を探します。エージェントの返信は証拠ではなく、確認すべき主張として扱います。

### セカンドオピニオンを依頼する

1. セッションのメニュー（⋯）を開き、**セカンドオピニオン**を選びます。
2. **確認する担当**でレビュアーを選びます。おすすめが先頭に表示されます。
3. **対象のターン**で確認するターンを選びます。完了した最新のターンが選択済みで、最近のターンが12件まで、時刻と変更したファイル数とともに一覧表示されます。
4. **質問**を押します（ボタンにはレビュアー名が入ります。たとえば**Codexに質問**）。

そのターンの下にカードがすぐに表示され、レビュアーが回答すると内容が入ります。通常、1〜2分以内です。実行中のターンは、終わるまで確認できません。スマートフォンでは、ダイアログが画面の下から開きます。

### 作業を確認できる担当

作業をしたモデルとは別の会社のモデルだけが確認できます。自分の作業を自分で確認することはありません。

- **Claude Code**のセッション、またはAnthropicのモデルを使うセッションは、**Codex**（Codexプログラム経由）か、CustomのモデルのうちAnthropic製ではないものが確認できます。
- **Codex**のセッション、またはOpenAIのモデルを使うセッションは、**Claude**（Sonnet、Claude Code経由）か、CustomのモデルのうちOpenAI製ではないものが確認できます。
- それ以外のセッション（Custom、または他社製モデルを使う別のエージェント）は、Claude、Codex、またはセッションのモデルとは別のメーカーのCustomのモデルが確認できます。

Customのモデルとは、[設定 → モデル](/settings?s=models)で追加したモデルです。レビュアーは読み取りのみを行います。ClaudeとCodexは、特定の点を確認するためにセッションのフォルダ内のファイルを開くことがありますが、何も変更しません。ターン自体に加えて、レビュアーにはセッションの最初のメッセージと、そのターンの前のメッセージが文脈として渡されます。変更が大きすぎて全体を表示できないときは、一部が省かれ、カードにその旨が表示されます。

### カードの内容

カードの見出しには**セカンドオピニオン**とレビュアー名が表示され、その下に次の内容が表示されます。

- 作業中：「作業を確認しています」と経過時間、レビュアーが何を読んでいるかを示す1行。
- 完了時：重大度別の発見（「致命的1件 · 重要2件」）、**問題なし**（軽微な指摘があれば件数付き）、または回答を発見として読み取れなかった場合は**はっきりした判定なし**。
- 失敗時：理由付きの**回答なし**（ここにレビュアーのプログラムがインストールされていない、8分以内に回答がなかった、または途中でアプリが再起動した）と**もう一度試す**。

見出しをクリックすると、カードを開閉できます。中にはレビュアーの要約と発見が、重大なものから順に表示されます。各発見には次の内容があります。

- 重大度：**致命的**（現状では誤り、破損、または危険）、**重要**（作業を信頼する前に修正すべき）、**軽微**（確認する価値はあるが、そのままでもよい）。
- 短いタイトルと、該当するファイルと行（クリックするとその位置でファイルが開きます）。
- 何が問題か、なぜ重要か、どう直すか。

より重大な発見がある場合、軽微なものは**軽微なものをN件表示**の下にまとめられます（**軽微なものを隠す**で再びまとめられます）。×を押すとカードを閉じます。

### 指摘をエージェントに送る

- 発見の横にある送信ボタン（紙飛行機：**エージェントに送信**）を押すと、その発見がメッセージ欄に入り、送信や編集ができます。
- **すべてエージェントに送信**を押すと、表示中のすべての発見が一度にメッセージ欄に入ります。
- エージェントが作業中の間は、**すべてキューに追加**（または**キューに追加**）を押すと、セッションのキューに追加され、ターンが終わったときにエージェントへ送られます。

メッセージにはレビュアー名が入り、各指摘が重大度とファイルとともに並びます。エージェントには、それぞれの指摘を自分の作業と照らして確認し、妥当なものを修正し、対応しないものはその理由とともに伝えるよう求めます。

## アリーナでモデルを比較する

モデルアリーナは、同じプロンプトを2つまたは3つのモデルに同時に送るので、回答を並べて比較し、最も良いものを残せます。残した回答は評価に反映され、自分のタスクで勝つモデルがわかります。

### 対戦を開始する

1. スタートページで、いつもどおりエージェントとモデルを選びます。これが対戦の最初のモデルになります。
2. **オプション** → **アリーナ** を開き、**モデルを比較**（「同じプロンプトを、さらに多くのモデルに並べて送ります」）を選びます。
3. 「選んだモデルに加えて、こちらにも質問（最大2つ）」で、モデルを1つまたは2つ追加でチェックします。一覧には、Claude Code、Codex、Customのモデルがそれぞれいくつか表示され、追加した他のエージェントのモデルも含まれます。一覧が長いときは、**モデルを探す**欄で絞り込めます。
4. プロンプトを入力して **開始** を押します。

アリーナの行には「+1モデル」または「+2モデル」と表示され、オプションのチップにも反映されます。このブラウザは最後の選択を記憶しますが、アリーナは次のセッションでは自動的にオンになりません。

**モデルを比較** を初めて選ぶと、「アリーナを使う前に」というダイアログが表示され、アリーナの内容、向いている用途、向いていない用途、費用について説明されます。続けるには「アリーナを使う」を押し、やめるには **キャンセル** を押します。このダイアログは、ヒントがオンでもオフでも、どのデバイスでも1回だけ表示されます。ディープリサーチやスウォームと違い、アリーナはスタートページ専用の選択肢です。最初のメッセージを他のモデルにも送るため、すでに進行中のセッションに追加することはできません。

各モデルは、同じプロンプト、添付ファイル、フォルダ、セッション設定（エージェント、メモリ、支出上限）と、そのエージェントの通常の思考レベルおよび権限で、それぞれ独自のセッションとして動きます。Gitリポジトリでは、フォルダメニューで **新しいワークツリー** をオンにすると、全モデルが1つのフォルダを書き換えるのではなく、モデルごとに別のコードのコピーで作業できます。起動できないモデルがあった場合は、アプリがその旨を知らせ、そのモデルを除いて対戦が続きます。

### 回答を比較して最良のものを残す

対戦中の各セッションでは、メッセージ欄の上にバーが表示されます。**アリーナ** · 「同じプロンプトが他のモデルにも送られました」と、**回答を比較** が並びます。これを押すと比較ページが開き、上にプロンプト、その下にモデルごとの列が表示されて、それぞれの最新の返信が届くたびに埋まっていきます。列は、広い画面では横に並び、スマートフォンでは縦に並びます。

- **これを残す**（そのモデルが返信したあと）は、その回答を残します。そのセッションが対戦に勝ち、他のセッションはアーカイブされます。セッション一覧からは消えますが、開くことはできます。列には **残した** と **アーカイブ済み** と表示されます。
- **開く** は、そのモデルのセッションに移動します。残したセッションでは **ここで続ける** と表示され、勝ったモデルとの会話を続けられます。
- **勝つモデル**（スマートフォンでは **ボード**）は、使用量 → アリーナを開きます。

### 勝つモデルを確認する

[使用量 → アリーナ](/arena)（検索ボックスでCtrl+Kを押すと「モデルアリーナ」）には、**自分のタスクで勝つモデル** が表示されます。モデルごとに **評価**、対戦した中で **残した** 回数、**勝率**（スマートフォンでは非表示）が並びます。評価はイロレーティングで、チェスの選手のランク付けに使われる方式です。初期値は1000で、決着をつけた対戦ごとに、残した回答が他の回答すべてに勝ったものとして計算されます。

その下の **対戦** には、最新の対戦が最大100件表示されます。プロンプト、モデル、日時が並び、勝者が示されます。まだ決着をつけていない対戦には **開く** と表示されます。クリックすると、その回答を比較できます。

## セッションに支出上限を設定する

支出上限は、セッションが使える最大額で、API料金で計算されます。実際に契約しているプランに関係なく、トークンをAPI経由で使った場合の費用です。上限に達すると、上限を上げるまでエージェントは停止します。ディープリサーチ、スウォーム、サブエージェント、アリーナの対戦など、多数のエージェントを動かす機能と相性が良い設定です。

### 計算に含まれるもの

- セッション自身のモデル呼び出し。そのエージェント自身のサブエージェント（たとえばClaude Codeサブエージェント）も含みます。
- セッションが起動したHydorサブエージェント。上限はこれらもカバーします。
- このコンピューター上のモデル（OllamaまたはvLLM経由）は無料です。
- 価格が不明なトークンは計算できません。そのためにセッションの支出がもっと多い可能性があるときは、上限のダイアログでお知らせします。

セッション全体の費用については、[使用量、制限、費用](/guide/usage)をご覧ください。

### 開始時に上限を設定する

スタートページで **オプション** → **支出上限** を開きます。ドル単位で金額を入力して **設定**（またはEnter）を押すか、$1.00、$5.00、$10.00、$25.00から選びます。**上限なし** を選ぶと解除されます。すると、オプションのチップに上限（「$5.00上限」）が表示されます。

ディープリサーチ、スウォーム、アリーナと違い、選んだ上限は保持されます。変更するまで、どのデバイスでも次のセッションがその上限で始まります。

### セッションの上限を設定または変更する

セッションのメニュー（⋯）→ **セッション設定** → **支出上限** を開きます（現在の上限は横に表示されます）。ダイアログには **これまでの支出** が表示され、Hydorサブエージェントがある場合は、このセッション分とその分に分けて示されます（「このセッション$1.20、Hydorサブエージェント$0.80」。ダイアログには「起動したサブエージェントも含まれます。」とも表示されます）。Hydorサブエージェントの場合は、親の上限のうちどれだけ使われたかも表示されます。**上限** に金額を入力するか、$1.00、$5.00、$10.00、$25.00から選び、**上限を設定**（または **変化**）を押します。**上限を解除** を押すと上限がなくなります。

上限は$0.01から$100,000まで設定できます。セッションがすでに使った額以下にすると、セッションは停止したままになるという警告がダイアログに表示されます。スマートフォンでは、ダイアログは画面の下から開きます。

### メッセージ欄の上のバー

セッションに上限があるあいだは、メッセージ欄の上のバーに、上限に対する支出（「$5.00中$1.20」）が、埋まっていく線とともに表示されます。80%からは琥珀色、上限に達すると赤になり、**上限に達しました** と表示されます。Hydorサブエージェントが使った分があるときは、（広い画面では）「サブエージェント含む」が追加されます。金額にポインタを合わせると内訳が見られます。**変化**（上限に達したあとは **上げる**）を押すと、上限のダイアログが開きます。

### 上限に達したときの動作

上限はモデル呼び出しのたびに確認されるため、ターンは上限に達した呼び出しの直後に停止します（合計が上限を少し超えることがあります）。

- エージェントが停止し、ターンの下に「支出上限で停止しました」と、上限に対する支出額、そして **上限を上げる…** が表示されます。停止したセッションは通知でも示されます。
- 実行中のHydorサブエージェントも停止します。その表示には、起動元のセッションが支出上限に達したことと、そこへ移動する **開く** が表示されます。
- 新しいメッセージは待機します。送信したメッセージは送られず、上限に達したという通知が表示されて、入力した文章はメッセージ欄に戻ります。キュー内のメッセージは、上限を上げるか解除するまで保留されます（「キューは保留中です」）。

### 上限を上げる、または解除する

バーの **上げる** か、表示の **上限を上げる…** を押し（またはセッションのメニューを使い）、セッションの支出額より大きい上限を設定するか、上限を解除します。すると、キューに保留されていたメッセージが送信されます。親の上限で停止したHydorサブエージェントは、親の上限が上がるとメッセージを再び受け付けます。

### サブエージェントの上限

新しいHydorサブエージェントには、それぞれ専用の上限が設定されます。親の上限の残りを、親と同時に動けるHydorサブエージェントの数で等分した額です。親の上限はすべてを引き続きカバーするため、親の上限に達すると全員が停止します。残りがなくなると、エージェントはHydorサブエージェントをこれ以上起動できなくなり、手持ちの結果で終えるよう伝えられます。

### スケジュールタスクとアプリの上限

- **スケジュールタスク**：タスクのエディタ（[設定 → スケジュールタスク](/settings?s=tasks)、**新しいタスク**、またはタスクのメニュー → **編集**）では、設定の行にスタートページと同じ **支出上限** があり、**実行ごと** の **上限：$** で同じ上限を設定できます。空欄にすると上限なしです。各実行のセッションは、この上限で停止します。これは新しいセッションを開始する実行に適用されます。既存のセッションに投稿する実行は、そのセッション自身の上限の範囲で動きます。会話の中でエージェントに設定してもらったタスクは、実行のたびに、その会話の設定（上限を含む）で始まります。[スケジュールタスク](/guide/tasks)をご覧ください。
- **アプリ**：アプリの **上限** に **1回の実行で使える最大額（US$）** があります。[アプリ](/guide/apps)をご覧ください。
