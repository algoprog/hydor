# ターミナルでのHydor

`hydor`コマンドは、アプリのページで行う操作をターミナルで行えます。エージェントと対話してその作業をリアルタイムで追う、エージェントが求める承認や質問への回答をする、スクリプトから1件のリクエストを実行して答えを受け取る、アプリが保持するすべて（セッション、プロジェクト、エージェント、メモリ、スキル、プラグイン、キー、スケジュールタスク、使用量、すべての設定）を管理する、といったことが可能です。ページでしかできない操作（署名の描画、スライドや図のエディタ）では、そのページのアドレスが表示されます。アプリと同じHydorを使うため、ターミナルで開始したセッションはアプリに表示され、アプリで開始したセッションはターミナルで続けられます。入力中はシェルが補完してくれます。

![hydorコマンド：ウェルカムボックスと、スラッシュを入力すると開くメニュー](images/terminal.webp)

## コマンドを入手する

- **インストーラーでインストールした場合**（`./install.sh`）：`~/.local/bin`がPATHに含まれていれば、インストーラーが`hydor`をそこにリンクし、その旨を表示します。含まれていない場合は、コマンドの場所を表示します。場所はHydorのフォルダ内の`bin/hydor.mjs`で、そのまま実行することも、コマンドを置いているフォルダにリンクすることもできます。
- **Dockerの場合**：イメージにコマンドが含まれています。`docker exec -it hydor hydor`を実行すると、コンテナ内のエージェントと対話できます。
- **Macアプリ**は、起動のたびにコマンドを自動でPATHに追加します。`hydor`を`~/.local/bin`、`~/bin`、`/usr/local/bin`、`/opt/homebrew/bin`のうち、PATHに含まれていて書き込み権限もある最初のフォルダにリンクします。該当するフォルダがない場合は`~/.local/bin`を使い、そのフォルダがPATHに入るよう、Hydorのものと分かる印を付けた1行をシェルの起動ファイル（zshでは`~/.zprofile`）に追加します。その後、新しいターミナルのウィンドウを開いてください。コマンドはアプリ自身のNode.jsで動作し、アプリが終了している場合は`hydor`がアプリを開きます。ディスクイメージから実行した場合や、アプリを**アプリケーション**に移動する前は、何も行いません。アプリ内では、`hydor update`、`hydor service install`、`hydor serve`を実行しても、アプリ自身がそれを行うという案内が表示されるだけです。
- **LinuxとWindowsのデスクトップアプリ**も、起動のたびに同じ処理を行います。パスワードの入力や確認は不要です。**Linux**（AppImageまたは.deb）では、コマンドは`~/.local/bin`、`~/bin`、`/usr/local/bin`のうち、PATHに含まれていて書き込み権限もある最初のフォルダに置かれる小さな`hydor`ファイルです。該当するフォルダがない場合は`~/.local/bin`を使い、Hydorのものと分かる印を付けた1行をシェルの起動ファイルに追加します。.deb自体の`/usr/bin/hydor`はアプリのウィンドウを開くため、このコマンドはPATH上でそれより前に置かれます。**Windows**では、Windowsがすでに検索対象にしているWindowsAppsフォルダに`hydor.cmd`を置きます。置けない場合は`%LOCALAPPDATA%\Hydor\bin`に置き、PATHに追加します。その後、新しいターミナル（Windows Terminal、PowerShell、コマンドプロンプト）を開いてください。Macと同様に、コマンドはアプリ自身のNode.jsで動作し、アプリが終了している場合は`hydor`がアプリを開きます。また、`hydor update`、`hydor service install`、`hydor serve`は、アプリ自身がそれを行うという案内を表示するだけです。別の`hydor`がすでにPATH上にある場合（インストーラーが作成する、gitから取得したコピーへのリンクなど）、アプリは何も変更しません。別のコンピューターにあるHydorのコピーからでも、そのコンピューターのHydorを使えます。詳しくは[別のコンピューターのHydorを使う](#use-another-computers-hydor)をご覧ください。

`hydor help`は、できることをグループ分けして1行ずつ一覧表示します。`hydor help <command>`はコマンドの使い方、オプション、例を表示し、`hydor help options`はすべてのオプションを一覧表示し、`hydor help <command> <verb>`は動詞（サブコマンド）の説明を表示します。メンテナンス用のコマンドも同じ名前で使えます。`hydor service status`、`hydor setup-token`、`hydor update`などです（`node dist/server/cli.js …`も引き続き使えます）。コマンド、オプション、動詞を間違えて入力すると、「Did you mean …?」（もしかして…？）と候補が表示されます。エラーは赤で表示されます。

コマンド名で始まるメッセージは、コマンドと取り違えられないよう、引用符で囲む（`hydor "find the bug in login"`）か、`hydor chat`の後に入力します。

先にHydorを起動しておく必要はありません。このコンピューターで何も応答しない場合、コマンドがHydorをバックグラウンドで起動し、**Starting Hydor…**と表示します。コマンドが終了してもHydorは起動したままなので、セッションは続行されます。`hydor status`を実行すると、使用しているHydor、そのバージョン、サービスとして動作しているかどうか、動作中の内容が表示されます。デスクトップアプリがあるコンピューターでは、アプリが終了していればアプリが開かれます。コマンドが独自のサーバーを起動することはありません。

## シェルでのTab補完

最初に一度だけ有効にします。

```bash
hydor completion install
```

使用しているシェル（bash、zsh、fish）向けに設定されます。シェルが探す場所にスクリプトを書き込み、zshと、bash-completionのないbashでは、`.zshrc`または`.bashrc`に1行を追加します。その後、新しいターミナルを開いてください。再度実行しても、二重に変更されることはありません。`hydor completion bash`（または`zsh`、`fish`）を実行すると、代わりにスクリプトが表示されるので、好きな場所に置けます：`source <(hydor completion bash)`。

以降は、Tabキーで入力内容が補完されます。コマンド、その動詞とオプション、それらが受け取る対象が補完されます。`hydor show `や`hydor send `の後では、セッションのキーがタイトル付きで一覧表示されます。`--model`の後ではモデル、`--as`の後ではエージェント、`--cwd`の後ではフォルダが表示されます。同様に、プロジェクト、スキル、プラグイン、設定、ガイドのトピックなども、このHydorにあるものが補完されます。Hydorがすぐに応答しない場合は、Hydorなしで補完できるものだけを提示し、シェルを待たせることはありません。

## エージェントと対話する

フォルダで `hydor` を実行するか、`hydor` に続けてメッセージを入力します（`hydor fix the failing test`）。最初のメッセージで、そのフォルダでのセッションが始まります。

チャットは、上の枠線に **HYDΩR** とバージョンが入ったウェルカムパネルで始まります。中には、ブランチ名を添えたフォルダ（Gitにブランチがない場合、ブランチは表示されません）、応答するプログラム（**Claude Code**、**Codex**、**Custom**）、モデル（ティアのあるHydorで、仕事に応じてモデルが選ばれる場合は **自動**）、権限モードが · で区切られて並びます。モードは、エージェントが確認なしで動くときは赤、プランのときはアクセントカラーで表示されます。さらに、ヒントの行 `/ commands · @ files · ! shell · ↑ history · Ctrl+R search · /help` が続きます。枠の幅は、フォルダの名前が何であっても変わりません。

表示された内容はターミナル自体の履歴に残るため、SSH接続中やtmuxでも、さかのぼって見たりコピーしたりできます。

- **自分のメッセージ**は、`›` の後に表示されます。
- **エージェントのテキスト**は、見出し、リスト、引用、表、リンク（言葉の後にアドレス）、コード（折り返されないので、コピーしてそのまま実行できます）とともに、届いた順に表示されます。
- **各ステップ**は1行で表示されます。読んだもの、検索したもの、編集したもの（追加・削除した行数つき）、実行したもの（かかった時間つき。失敗したときは終了コードと、その下にエラーの1行目）が分かります。
- **思考**は、「Thought for 8 s」のような薄い1行で表示されます。`--thinking` を付けて起動すると全文が、`-v` を付けると各ステップの出力の最初の数行が表示されます。
- **サブエージェント**：エージェントが作業の一部を[Hydorサブエージェント](/guide/research#let-an-agent-hand-work-to-subagents)に任せると「Subagent started」、返答が戻ると「Subagent finished」（失敗したときは「Subagent failed」）と表示されます。Claude Codeは、自身のサブエージェントをバックグラウンドで動かし、その作業中にターンを終えることもあります。その場合、下部の行にバックグラウンドで動いているものが表示され、1つ終わるたびに「Finished in the background」と表示され、エージェントは自動で作業を続けます。開発サーバーのように、バックグラウンドで動かしたままのコマンドが、作業の妨げになることはありません。`/subagents` を使うと、すべてのサブエージェントと、それぞれの作業内容（およびサブエージェントにかかった費用）が一覧で表示されます。
- **各ターンの終わり**：かかった時間、費用、モデル、作業したサブエージェントの数（「1 subagent」「3 subagents」）が表示されます。

下部の数行は、エージェントの作業中に更新されます。書き込み中のテキスト、進行中のステップ、動いているサブエージェント、経過時間つきのカラーのスピナー（「Working」の上をシマーが流れます）、そして入力行です。Escキーまたは Ctrl+C でターンを止められます。

### 入力行

入力は2本の細い線の間にあり、その下にステータス行があります。ステータス行には、ブランチ名つきのフォルダ、モデルとモード、ここまでの費用が表示され、右側には `/help` があります。

- **グレーのサジェスト**が、過去のメッセージから、入力した文字の後に表示されます。**→** で全体を、**Alt+→** で1語分を取り込めます。サジェストのオン・オフは **設定 → アプリ → 一般 → ターミナルのサジェスト** で切り替えます（[設定](/settings?s=general&find=Terminal%20suggestions)）。
- **Ctrl+R** で過去のメッセージを検索できます。言葉の一部を入力し、**↑** と **↓** で候補に移動して **Enter** を押すと、送信せずに入力行に入るので、先に修正できます。**Esc** で中止します。
- メッセージは複数行にでき、貼り付けた内容はそのまま丸ごと入ります。

### 補完メニュー

入力に合わせて入力行の下にメニューが開き、キーを押すたびに更新されます。

| 入力 | メニューに表示されるもの |
| --- | --- |
| `/` | コマンドと、それぞれの説明。最初にチャット自体のコマンド、続いてプログラム自体のコマンド（たとえばClaude Codeのコマンドやスキル）が並びます。 |
| `/model `、`/mode `、`/effort `、`/agent `、`/subagents `、`/open ` | そのコマンドの値：モデル、モード、思考レベル、自分のエージェント、サブエージェント、開く場所。 |
| `@` と数文字 | セッションのフォルダ内のファイル（あいまい検索）：`@clits` で `src/cli.ts` が見つかります。末尾に `/` を付けると、そのフォルダの中を見られます。 |

**↑** と **↓** で移動し、**Tab** で選択中の行を補完し、**Enter** で補完して実行します（値が必要なコマンドでは、代わりにそのコマンドの値のメニューが開きます）。**Esc** でメニューを閉じます。あいまい検索なので、コマンドの文字は連続していなくてもかまいません。`mdl` で `/model` が見つかります。

### ピッカー

`/sessions`、`/resume`、`/model`、`/effort`、`/mode`、`/agent` は、値を付けずに入力するとピッカーが開きます。1行がハイライトされたリストです。**↑** と **↓** で移動し、入力すると絞り込まれ、**Enter** で選び、**Esc** で閉じます。リストが9行以下なら、数字キーでも選べます。キーを付けずに `hydor resume` を実行すると、自分のセッションの同じピッカーが開きます。

### `!` でシェルコマンドを実行

行の先頭に `!` を付けると、残りがセッションのフォルダでシェルコマンドとして実行されます：`!git status`、`!npm test`。実行中はチャットがターミナルを渡すので、対話型のプログラムも使え（`!vim notes.md`、`!htop`）、終了すると戻ります。行が `!` で始まっている間は、プロンプトが黄色になります。エージェントには、コマンドも出力も見えません。見せたいときは、メッセージで伝えてください。このコンピューターのHydorでのみ使えます。

### エージェントの質問に答える

エージェントが承認を必要とするときは、対象（コマンド、ファイルの変更、プラン）と、その下に選択肢が表示されます。

- **y** で許可する最初の選択肢、**n** で拒否、または選択肢の**数値**（「Always allow」など）を押します。
- 拒否したうえで、代わりにしてほしいことを伝えるには、それを入力して Enter を押します。

質問には番号つきの選択肢が表示されます。番号を押して選びます（複数選べる質問では複数選び、その後 Enter）。または、自分の答えを入力して Enter を押します。Esc でスキップします。フォームは、項目を1つずつ尋ねます。それぞれの答えを入力して Enter を押すか、表示されている内容のままにするには Enter だけを押します。ファイルは、このコンピューター上のパスで指定します。

アプリが必要なリクエストもあります。署名に関するものや、自分のアプリのキーなどです。その場合、ターミナルにそう表示され、アプリでのセッションのアドレスが示されます。

### エージェントのブラウザが待っているとき

エージェントのブラウザが待っている内容は、承認待ちがあればその後に、カードとしてチャットに表示されます。文言はアプリと同じです（[エージェントが使うブラウザ](/guide/web#the-browser-agents-use)を参照）。

- 「Needs you in the browser: …」：ログイン、確認、またはエージェントが判断できないことのためで、その下にページのアドレスが表示されます。
- 「Stopped before paying or ordering: …. That is yours to do」
- 「Wants to open localhost:3000, on this machine or its network」
- 「Wants to press “Send” on mail.example.com」：ブラウザがサインイン済みのサイトで、送信、投稿、削除、送金を行うボタンの場合です（[送信、投稿、削除を行うボタン](/guide/web#buttons-that-send-post-or-delete)を参照）。カードには、許可した場合にだけ押すと書き添えられます。
- ページのポップアップの質問：サイトからの質問（またはページを離れるかどうかの確認）が、そのメッセージとともに表示されます。

カードにはキーが表示され、1回押すだけで答えられます。

- アドレスやボタンの場合：**y** で許可し（アドレスはこのセッションの間）、**n** で許可しません。
- ログイン、確認、支払いなど、ページ上で本人にしかできないことの場合：**o** でアプリのセッションのページをブラウザで開き、そこで引き継げます。**d** で完了を伝え、**n** でできない（支払いの場合は、今はしない）ことを伝えます。
- ポップアップの質問の場合：**y** はOK（「Leave this page?」ならLeave）、**n** はキャンセル（Stay）です。アラートにはOKしかありません。テキストの入力を求められたときは、答えを入力して Enter を押すか、**y** で表示されている内容のまま進めるか、**n** でキャンセルします。

ターミナルではページ自体を表示できないので、引き継ぐには **o** を使ってください。答えると、カードは1行に縮まります：「Done in the browser」「Skipped」「Allowed」「Not allowed」。

### 作業中のとき

入力行は、そのまま使えます。エージェントの作業中に送ったメッセージを Enter でどう扱うかは、[設定 → アプリ → 一般](/settings?s=general&find=Sending%20while%20an%20agent%20works)の **エージェントの作業中に送信** で決まります。**ターンに参加**（アプリと同じ、初期設定）では実行中のターンに入れられ、**待つ**ではキューに入り、ターンが終わると送られます（**queued** と表示されます）。どちらを設定していても、1通のメッセージについては、次の2つのコマンドで決められます。

- `/queue <message>` は、常にターンの終了を待ちます。
- `/now <message>` は、常に実行中のターンに参加します。

デバイスの2つの設定、**エージェントの作業中に送信** と **ターミナルのサジェスト** は、チャット自体の設定です。ここで設定するには、`hydor settings set general.sending-while-an-agent-works wait` を使うか、エージェントに変更を頼みます（[設定](#settings)を参照）。チャットはすぐにそれに従います。

### キー

- **Enter** で送信します。**Alt+Enter**、**Ctrl+J**、または行末の `\` の後に Enter で、改行します。貼り付けた内容は、改行も含めてそのまま入ります。
- **↑** と **↓** で過去のメッセージをたどれます（直近500件が保存されます）。複数行のメッセージでは、まずその行の間を移動します。メニューが開いているときは、メニューの中を移動します。
- **←**、**→**、**Home**、**End**、**Ctrl+A**、**Ctrl+E** で移動します。**Alt+←** と **Alt+→** は1語ずつ移動します。**Ctrl+W** はカーソルの前の1語を削除し、**Ctrl+U** と **Ctrl+K** は、カーソルの前と後ろの行の残りを削除します。
- **Tab** でメニューを開き、選択中の行を確定します。**Ctrl+R** で過去のメッセージを検索します。
- **Esc** でメニューを閉じるか、ターンを止めます。**Ctrl+C** は、ターンが実行中ならそれを止め、テキストがあれば行を消去し、どちらでもなければ2回押すと終了します。空の行で **Ctrl+D** を押すと終了します。**Ctrl+L** で画面を消去します。**Ctrl+Z** でチャットを一時停止します（`fg` で戻ります）。

`/keys` で、チャット内にキーの一覧が表示されます。終了してもセッションは続いており、戻り方がターミナルに表示されます。

### コマンド

入力行に入力します（`/` で一覧が表示されます）。

- `/help`：コマンド、キー、その他（`@`、`!`）を、**コマンド**、**キー**、**Also** のセクションに分けて表示します。`/keys` はキーだけを表示します。
- `/new`（とメッセージ）：同じフォルダでの新しいセッション。
- `/sessions`（または `/resume`）：続ける別のセッションを選びます。
- `/model`、`/effort`、`/mode`：モデル、思考の深さ、確認なしでできることを変更します。名前を付けないと、それぞれピッカーが開きます。
- `/agent`：次のメッセージから、[自分のエージェント](/guide/agents)の1つとして作業します。
- `/subagents`：サブエージェント（バックグラウンドのものも含む）と、それぞれの作業内容（およびサブエージェントにかかった費用）。`/subagents 2` で、2番目のサブエージェントの会話が表示されます。
- `/tiers`、`/usage`、`/cost`：各ティアがどのモデルにあたるか、プランの使用量と上限、このセッションとそのサブエージェントにかかった費用。
- `/copy`：エージェントの最後の返答をクリップボードにコピーします（SSH接続中やtmuxでも使えます）。`/clear` で画面を消去します。
- `/queue` と `/now`：設定に関係なく、メッセージを待たせるか、ターンに参加させます（[作業中のとき](#while-it-works)）。
- `/stop`、`/rename`、`/open`、`/quit`：ターンとバックグラウンドのサブエージェントを止める、セッション名を変更する、アプリでのセッションのアドレスを表示する、終了する。
- `/hydor <command>`：以降のセクションにあるコマンドを、チャット内で実行します（[チャットの中で](#inside-the-chat)）。

それ以外の `/command` は、そのままエージェントに送られます。プログラム自体のコマンドやスキルのためです。

ターミナルが対応していれば、フルカラーで表示されます。`NO_COLOR` や `--no-color` で無効にでき、パイプ経由の場合も無効になります。

## セッションを続ける

- `hydor -c` は、いるフォルダの最新のセッションを続けます。
- `hydor resume` は、最新のセッションのピッカーを開きます。`hydor resume 6f1e2a3b` は、そのセッションを続けます。

最後の数ターンが最初に表示され、それぞれの作業は1行にまとめられます（「Ran 3 commands, read 4 files」）。`hydor show` ですべてが表示されます。

## セッションの始め方を選ぶ

次のオプションは、`hydor`、`hydor run`、`hydor resume` で使えます。

- `--agent claude`、`codex`、`custom`、または[別のエージェントプログラム](/guide/agents-models)の名前：どのプログラムが応答するかを指定します。
- `--model`（モデルの名前、または自動にする `auto`）、`--effort`、`--mode ask`、`edits`、`plan`、`full`（またはプログラム自体のモード名）。
- `--as Researcher`：[自分のエージェント](/guide/agents)の1つとして始めます。
- `--cwd`（フォルダ。省略すると、いるフォルダ）、`--worktree`（専用のブランチとフォルダ）、`--cap 2`（最大$2まで使う）、`--no-memory`、`--title`。

省略した項目は、アプリのスタートページで最後に選ばれたものから、次にアプリの初期設定から決まります。

## スクリプトからの1回のリクエスト

`hydor run "…"`（または `hydor -p "…"`）は、メッセージを渡してセッションを開始し、作業が終わるまで見届けて、エージェントの最後の返信を出力し、終了します。終わったとは、ターンが終了し、作業中のサブエージェントや返信待ちのサブエージェントがいなくなり（バックグラウンドのClaude Code自身のサブエージェントも含み、エージェントのものでもサブエージェントのものでも同じです）、キューに待っているものが何もない状態を指します。サブエージェントを待つためにターンを終えたエージェントは、サブエージェントの返信や終了で再開され、実行はそのターンも待ちます。開発サーバーのようにバックグラウンドで動かしたままのコマンドは、終了を妨げません。`--timeout` やCtrl+Cで止めると、バックグラウンドのサブエージェントもターンと一緒に停止します。メッセージを何も指定しない場合は、パイプで渡された内容をメッセージとして読み取ります：`git diff | hydor run "この変更をレビューして"`。

- ターミナルでは、端に短い行が表示され、何が起きているかが分かります（各ステップ、サブエージェントの開始と終了）。`-q` で非表示にできます。
- 回答する人がいないため、承認や質問が出ると実行が止まり、何を求められたかが表示され、セッションはアプリまたは `hydor resume` での対応待ちになります。エージェントのブラウザが待つ内容（ログイン、支払い、許可するアドレスやボタン、ポップアップの質問）も同様で、実行は次のように表示します：「エージェントのブラウザ：mail.example.comで「Delete」を押そうとしています」。`--mode full`（または `-y`）を付けると、エージェントは何も確認しません。
- `--json` は最後にオブジェクトを1つ出力します。内容は `key`、`url`、`status`、`reply`、`model`、`costUsd`（サブエージェントの分を含む）、`tokens`、`durationMs`、`turns`、`children`（各Hydorサブエージェントの `title`、`label`、`tier`、`costUsd`、`status`）、失敗した場合は `error` です。`--stream-json` は変更のたびに1行ずつ出力し（`item`、`live`、`note`）、最後の行に上記のオブジェクトを出力します。
- `--timeout 300` を指定すると、300秒でターンを停止します。

終了時には、スクリプトで確認できる終了コードが返ります。

| コード | 状況 |
| --- | --- |
| 0 | 完了 |
| 1 | セッションが失敗した（エラー、または名前が表示されるプランの使用量上限）、またはHydorが拒否した |
| 2 | コマンドの使い方が正しくない |
| 3 | 回答が必要 |
| 124 | `--timeout` より時間がかかった |
| 130 | Ctrl+Cが押された（先にターンが停止されます） |

## ターミナルからアプリのすべてを操作する

アプリの各部分には専用のコマンドがあり、そのページでできることが動詞として用意されています。動詞を省くと一覧が表示されます。`hydor projects` は `hydor projects list` と同じです。`hydor help` は以下のようにグループ分けして一覧を表示し、Tabキーで動詞、オプション、コマンドが受け取る対象を補完できます。

すべてのコマンドに共通する動作：

- **対象の指定**：コマンドが1件の対象（セッション、プロジェクト、エージェント、スキルなど）を受け取る場合は、IDまたはその先頭部分、あるいは名前やタイトルを指定します（大文字・小文字は区別されず、1件だけに絞れる場合）。2件以上に一致すると、最大5件まで表示されます。ターミナルでは、名前を省略すると候補の一覧から選べます。
- **変更**：項目はオプションで指定します（`--description`、`--name`）。長いテキストは、`--file <path>`、`-` でパイプした内容、またはどちらもないターミナルでは現在のテキストを開いたエディタ（`$VISUAL`、`$EDITOR`）から渡せます。変更せずに保存すると、何も変わりません。
- **削除**：`Remove “name”? [y/N]` と確認されます。`-y`（または `--yes`）を付けると「はい」と答えたことになります。ターミナルがなく `-y` もない場合は、推測せずに実行を拒否します。
- **`--json`**：アプリのAPIが返した内容を、そのまま出力します。スクリプト向けです。
- **終了コード**：完了した場合は0、Hydorが拒否または失敗した場合は1（理由が表示されます）、コマンドの使い方が正しくない場合は2（入力すべき内容が表示されます）です。
- **別のコンピューターのHydor**：すべてのコマンドで `--server` と `--token` が使えます。
- **ページでしかできない操作**：コマンドがその旨とページのアドレスを表示します。`hydor open … --browser` でそのページを開けます。

### セッション

| コマンド | 内容 |
| --- | --- |
| `hydor sessions` | 最新のセッションを、状態を示す印付きで表示します。● 作業中、● 対応待ち、✓ 完了、✗ エラー。動詞はセッションのメニューと同じ操作です。`search`、`rename`、`archive` と `unarchive`、`pin` と `unpin`、`read`、`snooze`、プロジェクトへの `move`、`fork`、`goal`、`share`（読み取り専用のリンク）、`changes`（変更したファイル）、`commands`（実行したコマンド）、`queue`（待機中のメッセージ。`queue clear` と `queue remove` もあります）、`show`、`export`（会話をMarkdownファイルに出力。`-o -` で画面に表示、`--library` でセッションのプロジェクトにドキュメントとして保存）、`send`、`stop`、`delete`。 |
| `hydor inbox` | 対応待ちの項目（承認、質問、エージェントが求めたキー、確認待ちのスキル）。`list` と、1件を表示して回答先を確認する `show` があります。 |
| `hydor outbox` | 確認待ちで保留中の呼び出し（接続済みアカウントのツールで「先に確認」に設定したもの）。`list`、入力内容付きで1件を表示する `show`、`send`（そのまま、または `--set NAME=value` で項目を変更して送信）、`drop` があります。 |
| `hydor away` | 前回の訪問以降の出来事を、スタートページの**不在中の出来事**と同じ形で表示します。対応待ちの項目、完了または失敗したセッション、自動で実行されたものとその費用、今日これから実行されるものが含まれます。`hydor away seen` で、すべてを確認済みにします。 |

`hydor show 6f1e2a3b` は `hydor sessions show 6f1e2a3b` と同じで、`send` と `stop` も同様です。短い形式も引き続き使えます。

```bash
hydor sessions search login          # ログインに関するセッション
hydor sessions rename 6f1e "ログインのバグを修正"
hydor sessions fork 6f1e "代わりにキャッシュで試す"
hydor sessions export 6f1e -o notes.md  # 会話をMarkdownで出力
hydor inbox
hydor away                           # 不在中の出来事
```

### 作業

| コマンド | 内容 |
| --- | --- |
| `hydor projects` | `list`、`show`、`new`、`rename`、`edit`（説明、ガイドライン、開始時のエージェント、フォルダ）、`sessions`、`files`（読み込むドキュメント。`files add` と `files remove`）、`remove`。 |
| `hydor tasks` | [スケジュールタスク](/guide/tasks)と、自動で始まるその他の作業を扱います。`list`、`show`、`new`（実行タイミングは `--every 2h`、`--at 09:00 --days weekdays`、`--cron`、`--once`。または `--webhook`、`--watch-feed`、`--watch-page`、`--watch-folder`、接続済みアプリの新着項目を監視する `--watch-account`（`--tool` と併用）。カレンダーの各予定の前の時刻を指定する `--before 30m` もあります）、`edit`、`pause`、`resume`、`run`（一時停止中でも今すぐ実行）、`runs`（最新の実行。`--reply` で最後の返信）、`remove`。コマンドやJSONのアドレスの監視はページで行います。ボードのカードの更新は、ボードのものとして一覧に表示されます（「Shop · Sales by day: refresh」）。これらには `pause`、`resume`、`run` が使え、`show` が変更場所（ボード）を案内します。 |
| `hydor apps` | 自分の[アプリ](/guide/apps)と用意済みのアプリを扱います。`list`、`show`、`run`（フォームの回答を `field=value` で、または `--input` のJSONで渡します。回答と費用が表示されます）、`runs`、`run-show`（1件の実行）、`remove`。`hydor app …`（sなし）は、ファイルとしてアプリを作ります。`new`、`folder`、`dev`、`try`、`export`、`import`。 |
| `hydor files`（`hydor library` も可） | エージェントが作ったものや保存したものを、プロジェクトの**ファイル**と同じ形で扱います（[ページ、画像、動画、サイト](/guide/library)）。`list`（`--kind`、`--project`）、`search`、`show`（ドキュメントのテキスト、ボードのカード、または項目の概要）、`export`（`--to pdf`、`docx`、`pptx`…、`-o file`）、`open`（エディタのアドレス）、`remove`、`refreshes`（ボード上で更新されるもの、その時刻、費用）、`refresh`（ボードのカード、またはすべてを今すぐ更新）。 |
| `hydor experiments` | トレーニングと評価の実行：`list`、`show`、`stop`。実行の開始はエージェントとページから行います。 |

```bash
hydor projects new Thesis
hydor projects edit thesis --file guidelines.md
hydor tasks new --at 09:00 --days weekdays "未読メールを要約して"
hydor apps run trip-planner destination=Lisbon days=5
hydor files export "Q3 report" --to pdf -o q3.pdf
```

### エージェントとモデル

| コマンド | 内容 |
| --- | --- |
| `hydor models` と `hydor tiers` | 各プログラムが提供するモデルと、各[ティア](/guide/agents-models#tiers-a-model-for-each-kind-of-job)がどのモデルを指すかを表示・設定します（`hydor tiers set claude best opus --effort high`、`hydor tiers reset`。`hydor tiers team off` と `hydor tiers hard off` は**サブエージェントを主導**と**難問には最大**をオフにし、`on` で再びオンにします）。 |
| `hydor usage` | 各プランの使用量と上限、およびリセットの時期を表示します。 |
| `hydor agents` | [自分のエージェント](/guide/agents)を扱います。`list`、`show`、`new`、`edit`、`results`、`export`、`install`、`remove`（組み込みのものはコピーできますが、変更はできません）。エージェントの結果の送り先は、`new` と `edit` の `--results-to` で、送り先ごとに1回ずつ指定します。`library`（同じページを更新）、`library:new`、`sheet`（専用のスプレッドシートに1行追加）、`sheet:<spreadsheet>#<tab>`、`email:<addresses>`、`notify`、`file:<path>`、`webhook:<url>`、`none`。出力フィールドはエージェントのページで設定します（`hydor open agents`）。`results` は返された結果を1件ずつ1行で一覧表示します。`export` はエージェントを `.hydor-agent` ファイルとして保存し（`-o` で名前を指定）、含まれなかったものを表示します。`install <file>` はファイルの内容と必要なものを表示して確認した上で、同名の既存エージェントの隣にインストールします。`--replace` を付けると置き換えます（`--schedules` を付けると、ファイルが提案するスケジュールを一時停止の状態で追加します）。[エージェントをファイルとして共有する](/guide/agents#share-an-agent-as-a-file)も参照してください。 |
| `hydor accounts` | Claude CodeとCodexのサインインを扱います。`list`、`show`（1つのアカウントについて、サインイン中のユーザーとプラン、新しいセッションがそのアカウントで始まるかどうか、使用量と上限、APIキーが登録されているかどうか（キー自体は表示されません）、上限に達したときにセッションが切り替わるかどうか）、`add <program> <name>`（別のアカウントを追加し、すぐにサインイン）、`sign-in`、`sign-out`、`remove`、`use`（新しいセッションが使うアカウントの指定）。APIクレジット用のAPIキーと、使用量の上限での切り替えは設定です（`accounts.*`）。 |

```bash
hydor agents new Bookkeeper --tools read,edit --tier standard
hydor agents edit bookkeeper --results-to sheet --results-to email:sam@example.com
hydor agents export bookkeeper -o ~/Desktop/bookkeeper.hydor-agent
hydor agents install bookkeeper.hydor-agent --schedules
hydor tiers set claude best opus --effort high
hydor accounts add claude Work
hydor accounts use work
```

### エージェントが知っていて使うもの

| コマンド | 内容 |
| --- | --- |
| `hydor memory` | エージェントがユーザーについて覚えていること：`list`、`search`、`show`、`add`、`edit`、`forget`（30日間は復元可能）、`restore`。すべてのエージェントが最初に読む内容は `profile` と `profile edit` で扱います。`--scope`、`--project`、`--session` で、誰のメモかを指定します。 |
| `hydor guidelines` | すべてのエージェントが従う内容を `show` と `edit` で扱います。すべてのセッション向け、プロジェクト向け（`--project`）、1つのセッション向け（`--session`）があります。 |
| `hydor skills` | エージェントが使うスキル：`list`、`show`、`on`、`off`、`add`（`SKILL.md` またはフォルダから）、`remove`。`--agent claude` または `--agent codex` は、それぞれのプログラム独自のスキル向けです。 |
| `hydor plugins` | スキルとツールを含むアドオン：`list`、`show`、`on`、`off`、`add`（組み込み、Gitのアドレス、.zip、フォルダ）、`remove`。独自のプラグインの作り方はそのページにあります（`hydor open plugins`）。 |
| `hydor mcp` | Claude CodeとCodex向けのツールサーバー（MCP）：`list`、`show`（1つのサーバーについて、プログラム、スコープ、コマンドまたはアドレス、環境変数とヘッダーの名前（値は非表示）、オンかオフか、`--tools` を付けるとツールの数）、`status`（各サーバーを起動し、動作するものを表示）、`add`、`edit`、`remove`。 |
| `hydor connections` | [接続済みアプリ](/guide/connections)（Notion、GitHub、Gmailなど）：`list`、`show`、`services`（接続できるもの）、`connect <service>`（非表示で入力するキー、またはコマンドが待機する間にブラウザで行うサインイン）、`disconnect`。接続のどのツールをオンにするかは、そのページで設定します。 |
| `hydor keys` | [保管庫](/guide/connections)：キーの名前とそれぞれの使用先を表示する `list`、`set <NAME>`、`remove <NAME>`。値は、入力内容を非表示にして尋ねるか、パイプした内容から読み取ります。オプションとして入力することはなく（シェルに履歴が残るため）、表示されることもありません。 |

```bash
hydor memory add 短い回答が好み
hydor memory forget 42
hydor skills off research
hydor mcp add github --env GITHUB_TOKEN -- npx -y gh-mcp
hydor keys set GITHUB_TOKEN --domain github.com
hydor guidelines edit --project thesis
hydor connections connect notion --browser
```

### 設定

`hydor settings` では、[設定](/settings)のすべてのオプションを、3つのグループ（**アプリ**、**エージェント**、**機能**）とそのセクションに沿って扱えます。各オプションにはIDがあり、`general.resume-after-usage-limits` のように、セクション名に続けてオプションの語句を並べた形です。オプションは、そのIDのほか、セクションと語句の先頭部分（`general.resume`）、あるいは1つだけに絞れる場合は語句のみで指定できます。Tabキーで補完できます。

ターミナルで `hydor settings` だけを実行すると、ブラウザが開きます。セクションを選び、続けてオプションを選びます。**↑**と**↓**、または文字入力で探し、**Enter**でセクションを開くかオプションを変更し（スイッチは切り替わり、選択肢は値を表示し、数値やテキストは入力し、ボタンは先に確認します）、**Esc**で戻ります。パイプした場合は、すべてのオプションを一覧表示します。スクリプトや簡単な変更には、次のコマンドを使います。

| コマンド | 内容 |
| --- | --- |
| `hydor settings list [section]` | すべてのオプションを値とともに、または1つのセクションのオプションを表示します。 |
| `hydor settings get <option>` | 1つのオプションの値と、受け付ける内容を表示します。 |
| `hydor settings set <option> <value>` | 値を変更します。スイッチは `on` か `off`、選択肢はその値のいずれか、数値は整数、リストは項目をカンマで区切って指定します（`none` で空にします）。キーやトークンは非表示で入力するか、パイプした内容から読み取ります。長いテキストは `--file` またはエディタから渡せます。 |
| `hydor settings run <option>` | ページのボタン（**テストを送信**、**今すぐ確認**など）を押します。何かを削除またはダウンロードする場合は、先に確認します。 |
| `hydor settings open [section]` | アプリ内のセクションまたはオプションのアドレスを表示します。 |

```bash
hydor settings list memory
hydor settings get general.resume-after-usage-limits
hydor settings set general.resume-after-usage-limits on
hydor settings set search.providers duckduckgo,naget
hydor settings run notifications.send-a-test
```

アプリが各ブラウザに保存するもの（テーマ、言語、通知音）は、ここからは変更できません。該当するオプションはその旨とページのアドレスを表示します。ページでしか変更できないオプションも同様です。ターミナルに属する2つのデバイス設定、**エージェントの作業中に送信**と**ターミナルのサジェスト**はチャット独自のもので、`hydor settings set` で変更できます。

### find、guide、open、api

- `hydor find rate limit` は、検索ボックス（**Ctrl+K**）と同じ範囲（ページ、設定とそのオプション、セッション、メモリ、スキルなど）を検索します。`--in settings` は設定だけを検索し、`--urls` は各結果の下にアドレスを表示し、`--open 2` は2番目の結果をブラウザで開きます。
- `hydor guide` はガイドのトピックを一覧表示します。`hydor guide projects` はターミナルで1つのトピックを表示し、`hydor guide projects "what a project is"` はそのトピックの1つのセクションを表示します。`--sections` はトピックのセクションを一覧表示します。
- `hydor open` はアプリのアドレスを表示します。`hydor open published`、`hydor open settings memory`、`hydor open project thesis`、`hydor open guide projects`、`hydor open 6f1e2a3b`（セッション）は、それぞれのページのアドレスを表示します。`--browser` を付けると、ブラウザでも開きます。ページでしかできない操作に進むための方法で、スライド、スプレッドシート、画像、図のエディタ、署名、テーマの色、サービスへのサインインなどがあります。
- `hydor api GET /api/projects` は、アプリのAPIの任意のエンドポイントを呼び出し、そのJSONを表示します（`hydor api POST /api/projects -d '{"name":"Thesis"}'`。本文は `@file` や `-` からも渡せます）。エンドポイントは[APIのトピック](/guide/api)にあります。

### チャット内での利用

`/hydor <command>` は、上記のどのコマンドも会話を離れずに実行します。`/hydor sessions`、`/hydor memory search docker`、`/hydor settings get general.resume-after-usage-limits` のように使います。`/` メニューと、`/help` の**その他**の部分にあります。`/hydor ` の後には、メニューに領域、その動詞、各コマンドが受け取る対象（プロジェクト、セッション、設定、フォルダなど。シェルでTabキーが補完するもの）が順に表示され、`-` を入力するとオプションが表示されます。コマンドの出力は入力行の上に表示され、使い方が誤っている場合やHydorが拒否した応答は赤で表示されます。チャットはそのまま続けられます。コマンドはシェルと同じように確認を求めますが、チャット内で行います。質問（削除の確認など）は最初の行が**いいえ**の選択画面で表示され、キーやトークンは入力行に入力して（ドットで表示され、履歴には残りません）、エディタが必要な場合は `!` と同様にターミナルが渡されます。チャットではパイプ入力ができないため、長いテキストは `--file <path>` で渡します（省略するとエディタで書けます）。専用のスラッシュコマンドがあるコマンド（`models` には `/model`、`tiers` には `/tiers`、`usage` には `/usage`）や、シェル向けのコマンド（`run`、`serve`）の場合は、その旨と使うべきコマンドが表示されます。

## このHydorを管理する

- `hydor status` は、Hydorが動作しているか、バージョンとアドレス、データの保存場所、サービスとして動いているか、どのセッションが作業中か、または対応が必要かを表示します（印は `hydor sessions` と同じです）。
- `hydor serve` は、ここでHydorをフォアグラウンドで実行し、Ctrl+Cで止めるまで動かします。`hydor service install` はバックグラウンドのサービスとして動かし続け、`hydor update` は最新のコードを取得してビルドし、再起動します。`hydor set-password`、`hydor setup-token`、`hydor access-token` は、名前のとおりの操作を行います。Macアプリでは、`hydor update`、`hydor service install`、`hydor serve` を実行すると、アプリ自身がその操作を行うことが表示されます。
- `hydor open` はアプリのアドレスを表示し、`--browser` を付けるとブラウザで開きます。
- `hydor machines phone` は、ここでTailscaleがインストールされ、サインインしているか、tailnet上でアプリが提供されているアドレスを表示し、スマートフォンのカメラで読み取れるQRコードも表示します。`hydor machines phone serve` はアプリを自分のデバイスに公開し（通常のアドレスを別のものが使っている場合は `--port 8443` を指定します）、`hydor machines phone stop` は公開をやめます。これは[設定 → アプリ → スマートフォンで使う](/settings?s=phone)と同じ操作です。

## 別のコンピューターのHydorを使う

そのコンピューターでアクセストークンを作成します（そのコンピューターの[設定 → アプリ → マシン](/settings?s=machines&find=Access%20from%20other%20machines)で **新しいトークン** を選ぶか、そこで `hydor access-token "my laptop"` を実行します）。続いて、そのアドレスを指定します。

```bash
hydor --server https://hydor.example.com --token acm_… sessions
```

または、`HYDOR_URL` と `HYDOR_TOKEN` を一度設定しておきます。フォルダは相手のコンピューターのものです。`--cwd` で相手側のフォルダを指定しない限り、セッションはそのコンピューターの既定のフォルダで始まります（このコンピューター自身のアドレス、たとえば `http://localhost:8790` を指定した場合は、現在いるフォルダが使われます）。`!` コマンドは、このコンピューターのHydorでのみ使えます。このコンピューターでは、コマンドが初回に専用のトークンを作成し、[設定 → アプリ → マシン](/settings?s=machines&find=Access%20from%20other%20machines)に「This computer's command line」として表示されます。このHydorに別のコンピューターのセッションやページを表示するには、そのコンピューターをマシンとして追加します。`hydor machines` は、このHydorが使っているマシンと、応答があるかどうかを一覧表示します。`hydor machines add Lab --url https://lab.example.com` で追加できます（`--url` の代わりに `--ssh <host>` を指定すると、SSH経由で接続します。アクセストークンは入力しても表示されないか、`--file -` で渡します）。`hydor machines remove lab` で、そのマシンを使わないようにできます。

## 色とパイプ

色は、ターミナルでは有効（対応していればトゥルーカラー）で、出力がファイルや別のプログラムに送られる場合、`NO_COLOR` が設定されている場合、`--no-color` を付けた場合は無効になります。`FORCE_COLOR` を設定すると有効になります。入力がパイプで渡される場合（`echo "…" | hydor`）は、`hydor run` として動作します。出力だけがパイプされる場合は、会話が色や変化する行なしで表示され、入力した各行が送信されます。このとき `hydor sessions` などの一覧は、同じ列を色なしで表示し、長い内容も切り詰めないため、スクリプトで読み取れます。幅の狭いターミナルでは、名前やタイトルを切り詰める代わりに、列ごと省略されます（最初に説明、次にアドレスや経過時間などの順です）。記号を表示できない環境（Linuxコンソール、UTF-8ではないロケール、古いWindowsコンソール）では、コマンドは通常の文字で描画します。枠には `+-|`、プロンプトには `>`、印には `*`、`+`、`x`、ロゴにはHYDORを使います。`HYDOR_ASCII=1` を設定するとどこでもこの表示になり、`HYDOR_ASCII=0` を設定すると無効になります。ファイルや別のプログラムへの出力は、`HYDOR_ASCII=1` を設定しない限り、記号がそのまま使われます。

- 「ターミナルが、ターンの終了を待ってからメッセージを送るようにして。」
