# ターミナルでのHydor

`hydor`コマンドは、アプリのページで行う操作をターミナルで行えるようにします。エージェントと対話してその作業をリアルタイムで確認する、エージェントが求める内容を承認し質問に答える、スクリプトから1件のリクエストを実行して回答を受け取る、アプリが保持するすべて（セッション、プロジェクト、エージェント、メモリ、スキル、プラグイン、キー、スケジュールタスク、使用量、あらゆる設定）を管理する、といったことができます。ページでしかできない操作（署名の描画、スライドや図のエディタ）では、コマンドがそのページのアドレスを表示します。アプリと同じHydorを使うため、ターミナルで始めたセッションはアプリにも表示され、アプリで始めたセッションはターミナルで続けられます。シェルでは入力中に補完が働きます。

![hydorコマンド：ウェルカムボックスと、スラッシュを入力すると開くメニュー](images/terminal.webp)

## コマンドを入手する

- **インストーラーでインストールした場合**（`./install.sh`）：`~/.local/bin`がPATHに含まれていれば、インストーラーが`hydor`をそこにリンクし、その旨を表示します。含まれていない場合は、コマンドの場所を表示します。場所はHydorのフォルダ内の`bin/hydor.mjs`で、そのまま実行することも、コマンドを置いているフォルダにリンクすることもできます。
- **Dockerの場合**：イメージにコマンドが含まれています。`docker exec -it hydor hydor`を実行すると、コンテナ内のエージェントと対話できます。
- **Macアプリ**は、起動のたびに自動でPATHにコマンドを追加します。`hydor`を`~/.local/bin`、`~/bin`、`/usr/local/bin`、`/opt/homebrew/bin`のうち、PATHに含まれていて書き込み権限のある最初のフォルダにリンクします。該当するものがない場合は`~/.local/bin`を使い、そのフォルダがPATHに入るように、Hydorのものと分かる印を付けた1行をシェルの起動ファイル（zshでは`~/.zprofile`）に追加します。その後、新しいTerminalウィンドウを開いてください。コマンドはアプリ自身のNode.jsで動作し、アプリが閉じているときは`hydor`がアプリを開きます。ディスクイメージから実行した場合や、アプリを**アプリケーション**に移動する前は、何も行いません。アプリ内では、`hydor update`、`hydor service install`、`hydor serve`はアプリ自身が行うことを伝えるだけです。
- **LinuxとWindowsのデスクトップアプリ**も、起動のたびに同じ処理を行います。パスワードの入力も確認もありません。**Linux**（AppImageまたは.deb）では、コマンドは`~/.local/bin`、`~/bin`、`/usr/local/bin`のうち、PATHに含まれていて書き込み権限のある最初のフォルダに置かれる小さな`hydor`ファイルです。該当するものがない場合は`~/.local/bin`を使い、Hydorのものと分かる印を付けた1行をシェルの起動ファイルに追加します。.debに含まれる`/usr/bin/hydor`はアプリのウィンドウを開くため、このコマンドをPATH上でそれより前に置きます。**Windows**では、Windowsがすでに検索対象にしているWindowsAppsフォルダに`hydor.cmd`を置きます。置けない場合は`%LOCALAPPDATA%\Hydor\bin`に置き、そのフォルダをPATHに追加します。その後、新しいターミナル（Windows Terminal、PowerShell、コマンドプロンプト）を開いてください。Macと同様に、コマンドはアプリ自身のNode.jsで動作し、アプリが閉じているときは`hydor`がアプリを開き、`hydor update`、`hydor service install`、`hydor serve`はアプリ自身が行うことを伝えるだけです。別の`hydor`がすでにPATH上にある場合（インストーラーがgitのコピーに作るリンクなど）は、アプリは何も変更しません。別のコンピューターにあるHydorのコピーからでも、そちらのHydorを使えます。[別のコンピューターのHydorを使う](#use-another-computers-hydor)を参照してください。

`hydor help`は、できることをグループごとに1行ずつ一覧表示します。`hydor help <command>`はコマンドの使い方、オプション、例を表示し、`hydor help options`はすべてのオプションを一覧表示し、`hydor help <command> <verb>`は動詞（サブコマンド）の使い方を表示します。メンテナンス用のコマンドも同じ名前で使えます。`hydor service status`、`hydor setup-token`、`hydor update`などです（`node dist/server/cli.js …`も引き続き使えます）。コマンド、オプション、動詞を打ち間違えると、「Did you mean …?」と候補が表示されます。エラーは赤で表示されます。

コマンド名で始まるメッセージは、コマンドと間違われないように、引用符で囲む（`hydor "find the bug in login"`）か、`hydor chat`の後に書きます。

先にHydorを起動しておく必要はありません。このコンピューターで応答がないときは、コマンドがバックグラウンドでHydorを起動して**Starting Hydor…**と表示し、終了後も起動したままにするので、セッションは続きます。`hydor status`は、使用しているHydor、そのバージョン、サービスとして動いているかどうか、動作中の内容を表示します。デスクトップアプリがあるコンピューターでは、アプリが閉じていればアプリが開きます。コマンドが独自にサーバーを起動することはありません。

## シェルでのTab補完

最初に一度だけ有効にします。

```bash
hydor completion install
```

使っているシェル（bash、zsh、fish）に合わせて設定されます。シェルが読み込む場所にスクリプトを書き込み、zshと、bash-completionのないbashでは、`.zshrc`または`.bashrc`に1行を追加します。その後、新しいターミナルを開いてください。もう一度実行しても、変更が重複することはありません。`hydor completion bash`（または`zsh`、`fish`）は、代わりにスクリプトを表示するので、好きな場所に置けます：`source <(hydor completion bash)`。

有効にすると、Tabキーで入力中の内容が補完されます。コマンド、その動詞とオプション、それらが取る対象が補完されます。`hydor show `や`hydor send `の後では、セッションのキーがタイトル付きで一覧表示されます。`--model`の後ではモデル、`--as`の後ではエージェント、`--cwd`の後ではフォルダが表示されます。同様に、プロジェクト、スキル、プラグイン、設定、ガイドのトピックなども、このHydorにあるものが補完されます。Hydorの応答が遅いときは、Hydorなしで補完できるものだけを提示し、シェルが待たされることはありません。

## エージェントと話す

フォルダで `hydor` を実行するか、`hydor` に続けてメッセージを入力します（`hydor fix the failing test`）。最初のメッセージで、そのフォルダにセッションが始まります。

チャットは、上の枠線に **HYDΩR** とそのバージョンが入ったウェルカムパネルで始まります。パネルの中には、Gitのブランチ上の「on」のフォルダ（ブランチがない場合はブランチは表示されません）、応答するプログラム（**Claude Code**、**Codex**、**Custom**）、モデル（ティアのあるHydorでは、仕事に応じてモデルが選ばれる場合は **自動**）、権限モードが · で区切られて並びます。エージェントが確認なしで動く場合、モードは赤で表示され、プランの場合はアクセントカラーで表示されます。最後に、ヒントの行があります：`/ commands · @ files · ! shell · ↑ history · Ctrl+R search · /help`。枠の幅は、フォルダ名に関係なく一定です。

画面に表示された内容はターミナル自体の履歴に残るので、SSH経由やtmuxでも、さかのぼって見たりコピーしたりできます。

- **自分のメッセージ**は `›` の後に表示されます。
- **エージェントのテキスト**は、見出し、リスト、引用、表、リンク（言葉の後ろにアドレス）、コード（折り返されないので、コピーしてそのまま実行できます）とともに、届いた順に表示されます。
- **各ステップ**は1行で表示されます。読んだもの、検索したもの、編集したもの（追加・削除された行数つき）、実行したもの（かかった時間つき。失敗した場合は終了コードと、その下にエラーの1行目）が分かります。
- **思考**は、「Thought for 8 s」のような薄い1行で表示されます。`--thinking` を付けて起動すると全文が表示され、`-v` を付けると各ステップの出力の最初の数行が表示されます。
- **サブエージェント**：エージェントが作業の一部を[Hydorサブエージェント](/guide/research#let-an-agent-hand-work-to-subagents)に任せると「Subagent started」と表示され、返信が戻ると「Subagent finished」（失敗した場合は「Subagent failed」）と表示されます。Claude Codeは、自身のサブエージェントをバックグラウンドで実行し、その作業中にターンを終えることもあります。その場合、下の行にバックグラウンドで動作中のものが表示され、1つ終わるごとに「Finished in the background」と表示され、エージェントは自動で作業を続けます。dev serverなど、バックグラウンドに残したコマンドが待たされることはありません。`/subagents` を使うと、すべてのサブエージェントと、それぞれの作業内容（サブエージェントにかかった費用も）が一覧で表示されます。
- **各ターンの終わり**：かかった時間、費用、モデル、作業したサブエージェントの数（「1 subagent」「3 subagents」）。

下部では、エージェントの作業中、数行が更新され続けます。書き込み中のテキスト、実行中のステップ、動作中のサブエージェント、経過時間つきのカラーのスピナー（「Working」の上をシマーが流れます）、そして入力行です。**Esc** または **Ctrl+C** でターンを停止できます。

### 入力行

入力は2本の細い罫線の間にあり、その下にステータス行があります。ブランチ上のフォルダ、モデルとモード、ここまでの費用が表示され、右側には `/help` があります。

- 入力した文字の後ろに、過去のメッセージからの**グレーのサジェスト**が表示されます。**→** で全体を、**Alt+→** で1単語分を受け入れます。オン・オフは **設定 → アプリ → 一般 → ターミナルのサジェスト** で切り替えられます（[設定](/settings?s=general&find=Terminal%20suggestions)）。
- **Ctrl+R** で過去のメッセージを検索できます。その言葉の一部を入力し、**↑** と **↓** で候補に移動し、**Enter** を押すと送信せずに入力行に入るので、先に修正できます。**Esc** で中止します。
- メッセージは複数行にでき、貼り付けた内容は丸ごと入ります。

### 補完メニュー

入力すると行の下にメニューが開き、キーを押すたびに更新されます。

| 入力 | メニューの内容 |
| --- | --- |
| `/` | コマンドと、それぞれの説明。チャット独自のものが先に、続いてプログラム独自のもの（たとえばClaude Codeのコマンドやスキル）が並びます。 |
| `/model `、`/mode `、`/effort `、`/agent `、`/subagents `、`/open ` | そのコマンドの値：モデル、モード、思考レベル、自分のエージェント、サブエージェント、開き先。 |
| `@` と数文字 | セッションのフォルダ内のファイル（あいまい検索）：`@clits` で `src/cli.ts` が見つかります。`/` で終えると、そのフォルダの中を見られます。 |

**↑** と **↓** で移動し、**Tab** で強調表示された行を補完し、**Enter** で補完して実行します（値が必要なコマンドでは、代わりにそのコマンドの値が開きます）。**Esc** でメニューを閉じます。あいまい検索なので、コマンドの文字が連続していなくても構いません：`mdl` で `/model` が見つかります。

### ピッカー

`/sessions`、`/resume`、`/model`、`/effort`、`/mode`、`/agent` を値なしで入力すると、ピッカーが開きます。1行が強調表示された一覧です。**↑** と **↓** で移動し、入力すると一覧が絞り込まれ、**Enter** で選び、**Esc** で閉じます。一覧が9行以下の場合は、数字キーでも選べます。`hydor resume` をキーなしで実行すると、自分のセッションの同じピッカーが開きます。

### `!` でシェルコマンドを実行

行の先頭を `!` にすると、残りがセッションのフォルダでシェルコマンドとして実行されます：`!git status`、`!npm test`。実行中はチャットがターミナルを明け渡し、終わると戻すので、対話型のプログラムも動きます（`!vim notes.md`、`!htop`）。行が `!` で始まっている間、プロンプトは黄色になります。エージェントには、コマンドも出力も見えません。見せたい場合は、メッセージで伝えてください。このコンピューターのHydorでのみ使えます。

### エージェントの質問に答える

エージェントが承認を必要とするとき、依頼の内容（コマンド、ファイルへの変更、プラン）と、その下に選択肢が表示されます。

- 許可する最初の選択肢には **y**、拒否するには **n** を押します。「Always allow」などの選択肢は、その**数値**を押します。
- 拒否して代わりの指示を伝えるには、その内容を入力して Enter を押します。

質問では選択肢に番号が付いて表示されます。数字を押して1つ選びます（複数選べる質問では複数選んでから Enter）。自分で答えを入力して Enter を押すこともできます。Esc でスキップします。フォームでは項目が1つずつ尋ねられます。それぞれ答えを入力して Enter を押すか、表示されている内容のままなら Enter を押します。ファイルは、このコンピューター上のパスで指定します。

アプリが必要な依頼もあります。署名や、自分のアプリ用のキーに関するものです。その場合、ターミナルがその旨を表示し、アプリ内のセッションのアドレスを示します。

### エージェントのブラウザが待っているとき

エージェントのブラウザが待っている内容は、承認が先にあればその後に、チャット内のカードとして表示されます。文言はアプリと同じです（[エージェントが使うブラウザ](/guide/web#the-browser-agents-use)を参照）。

- 「Needs you in the browser: …」：ログイン、確認、またはエージェントが判断に迷う場合に表示され、その下にページのアドレスが出ます。
- 「Stopped before paying or ordering: …. That is yours to do」
- 「Wants to open localhost:3000, on this machine or its network」
- 「Wants to press “Send” on mail.example.com」：サインイン済みのサイトで、送信、投稿、削除、送金を行うボタンの場合です（[送信・投稿・削除を行うボタン](/guide/web#buttons-that-send-post-or-delete)を参照）。カードには、許可した場合にのみ押すと添えられます。
- ページのポップアップの質問：サイトからの通知（またはページを離れるかの確認）が、そのメッセージとともに表示されます。

カードには使えるキーが表示され、1回押すだけで答えられます。

- アドレスまたはボタンの場合：**y** で許可（アドレスはこのセッションの間）、**n** で許可しません。
- ログイン、確認、支払いなど、ページ上で自分にしかできないものの場合：**o** でアプリのセッションのページをブラウザで開き、そこで引き継げます。**d** は完了したこと、**n** はできない（支払いの場合は今はしない）ことを伝えます。
- ポップアップの質問の場合：**y** は OK（「Leave this page?」では Leave）、**n** はキャンセル（Stay）です。アラートには OK しかありません。テキスト入力の場合は、答えを入力して Enter を押すか、**y** で表示されている内容のままにするか、**n** でキャンセルします。

ターミナルにはページ自体を表示できないので、引き継ぐには **o** を使います。答えが済むと、カードは1行に縮みます：「Done in the browser」「Skipped」「Allowed」「Not allowed」。

### 作業中は

入力行は常に使えます。エージェントの作業中にメッセージを送ったとき、Enter がどう動くかは、[設定 → アプリ → 一般](/settings?s=general&find=Sending%20while%20an%20agent%20works)の **エージェントの作業中に送信** で決まります。**ターンに参加**（アプリと同じく初期設定）は実行中のターンにメッセージを入れ、**待つ**はキューに入れて、ターンの終了時に送ります（**queued** と表示されます）。どちらの設定でも、次の2つのコマンドで、1通ごとに指定できます。

- `/queue <メッセージ>` は、常にターンの終了を待ちます。
- `/now <メッセージ>` は、常に実行中のターンに参加します。

デバイスの2つの設定、**エージェントの作業中に送信**と**ターミナルのサジェスト**はチャット専用です。ここで `hydor settings set general.sending-while-an-agent-works wait` のように設定するか、エージェントに頼んで変更してもらうと（[設定](#settings)を参照）、チャットにすぐ反映されます。

### キー

- **Enter** で送信します。**Alt+Enter**、**Ctrl+J**、または行末の `\` の後に Enter を押すと、改行が入ります。貼り付けた内容は、改行も含めて丸ごと入ります。
- **↑** と **↓** で過去のメッセージをたどります（直近500件が保持されます）。複数行のメッセージでは、まずその行の間を移動します。メニューが開いているときは、メニュー内を移動します。
- **←**、**→**、**Home**、**End**、**Ctrl+A**、**Ctrl+E** で移動します。**Alt+←** と **Alt+→** は1単語ずつ移動します。**Ctrl+W** はカーソルの前の単語を削除し、**Ctrl+U** と **Ctrl+K** はそれぞれカーソルより前、後ろの行の残りを削除します。
- **Tab** でメニューを開き、強調表示された行を決定します。**Ctrl+R** で過去のメッセージを検索します。
- **Esc** はメニューを閉じるか、ターンを停止します。**Ctrl+C** は、ターンの実行中は停止し、テキストがあれば行を消去し、それ以外では2回押すと終了します。空の行での **Ctrl+D** は終了です。**Ctrl+L** は画面を消去します。**Ctrl+Z** はチャットを一時停止します（`fg` で戻ります）。

`/keys` でチャット内にキーの一覧が表示されます。終了してもセッションは続いていて、ターミナルに戻り方が表示されます。

### コマンド

入力行に入力します（`/` で一覧が表示されます）。

- `/help`：コマンド、キー、その他（`@`、`!`）を、**コマンド**、**キー**、**Also** のセクションで表示します。`/keys` はキーだけを表示します。
- `/new`（とメッセージ）：同じフォルダで新しいセッションを始めます。
- `/sessions`（または `/resume`）：続ける別のセッションを選びます。
- `/model`、`/effort`、`/mode`：モデル、思考の深さ、確認なしでできることを変更します。名前なしで入力すると、それぞれピッカーが開きます。
- `/agent`：次のメッセージから、[自分のエージェント](/guide/agents)の1つとして作業します。
- `/subagents`：サブエージェント（バックグラウンドのものも）と、それぞれの作業内容（サブエージェントにかかった費用も）を表示します。`/subagents 2` は2番目のサブエージェントの会話を表示します。
- `/tiers`、`/usage`、`/cost`：各ティアが指すモデル、プランの使用量と上限、このセッションとサブエージェントにかかった費用を表示します。
- `/copy`：エージェントの最後の返信をクリップボードにコピーします（SSH経由やtmuxでも使えます）。`/clear` は画面を消去します。
- `/queue` と `/now`：設定に関係なく、メッセージを待たせるか、参加させるかを指定して送ります（[作業中は](#while-it-works)）。
- `/stop`、`/rename`、`/open`、`/quit`：ターンとバックグラウンドのサブエージェントを停止する、セッション名を変更する、アプリ内のアドレスを表示する、終了する。
- `/hydor <コマンド>`：以降のセクションのコマンドをチャット内で実行します（[チャットの中で](#inside-the-chat)）。

それ以外の `/command` は、そのままエージェントに送られます。プログラム独自のコマンドやスキルのためです。

ターミナルが対応していれば、色はトゥルーカラーです。`NO_COLOR` と `--no-color` で無効になり、パイプでも無効になります。

## セッションを続ける

- `hydor -c` は、今いるフォルダの最新のセッションを続けます。
- `hydor resume` は、最近のセッションのピッカーを開きます。`hydor resume 6f1e2a3b` は、そのセッションを続けます。

直近の数ターンが最初に表示され、それぞれの作業は1行にまとめられます（「Ran 3 commands, read 4 files」）。`hydor show` ですべてが表示されます。

## セッションの開始方法を選ぶ

次のオプションは、`hydor`、`hydor run`、`hydor resume` で使えます。

- `--agent claude`、`codex`、`custom`、または[別のエージェントプログラム](/guide/agents-models)の名前：どのプログラムが応答するかを指定します。
- `--model`（モデル名、または自動にする `auto`）、`--effort`、`--mode ask`、`edits`、`plan`、`full`（またはプログラム独自のモード名）。
- `--as Researcher`：[自分のエージェント](/guide/agents)の1つとして開始します。
- `--cwd`（フォルダ。省略すると今いるフォルダ）、`--worktree`（専用のブランチとフォルダ）、`--cap 2`（最大$2まで使用）、`--no-memory`、`--title`。

省略したものは、アプリのスタートページで最後に選んだ内容から、次にアプリの初期設定から決まります。

## スクリプトからの1回のリクエスト

`hydor run "…"`（または `hydor -p "…"`）は、メッセージを使ってセッションを開始し、作業が終わるまで見届け、エージェントの最後の返信を表示して終了します。終わるとは、ターンが終了し、作業中のサブエージェントや返信がまだ届いていないサブエージェントがなく（バックグラウンドのClaude Code独自のサブエージェントも含み、エージェントのものでもサブエージェントのものでも同様です）、キューに待機中のものがない状態を指します。サブエージェントの返信を待つためにターンを終えたエージェントは、その返信や終了によって再び起動され、実行はそのターンも待ちます。開発サーバーのようにバックグラウンドで動かしたままのコマンドは、終了を妨げません。`--timeout` の時間が過ぎたときやCtrl+Cを押したときは、ターンとともにバックグラウンドのサブエージェントも停止します。後ろに何も指定しない場合は、パイプで渡された内容をメッセージとして読み取ります：`git diff | hydor run "この変更をレビューして"`。

- ターミナルでは、側面に表示される短い行で、各ステップやサブエージェントの開始と終了など、進行状況が分かります。`-q` で非表示にできます。
- 答える人がいないため、承認や質問があると実行は停止し、何を求められたかを表示します。セッションは、アプリまたは `hydor resume` で操作を待ちます。エージェントのブラウザが待つもの（ログイン、支払い、許可するアドレスやボタン、ポップアップの質問）でも同様で、実行は「エージェントのブラウザ：mail.example.comで「Delete」を押そうとしています」のように伝えます。`--mode full`（または `-y`）を付けると、エージェントは何も確認しません。
- `--json` は、最後に1つのオブジェクトを出力します。内容は `key`、`url`、`status`、`reply`、`model`、`costUsd`（サブエージェントの分を含む）、`tokens`、`durationMs`、`turns`、`children`（各Hydorサブエージェントの `title`、`label`、`tier`、`costUsd`、`status`）で、失敗した場合は `error` も含まれます。`--stream-json` は、変更があるたびにその内容を1行ずつ出力し（`item`、`live`、`note`）、最後の行にそのオブジェクトを出力します。
- `--timeout 300` を指定すると、300秒後にターンを停止します。

終了時には、スクリプトで確認できる終了コードが返されます。

| コード | 内容 |
| --- | --- |
| 0 | 完了 |
| 1 | セッションが失敗した（エラー、または名前が示されるプランの使用量上限）、またはHydorが拒否した |
| 2 | コマンドの使い方が正しくない |
| 3 | 回答が必要 |
| 124 | `--timeout` より時間がかかった |
| 130 | Ctrl+Cが押された（先にターンが停止された） |

## ターミナルからアプリのすべてを操作する

アプリの各部分にはそれぞれ専用のコマンドがあり、そのページでできることに対応した動詞が用意されています。動詞を省略すると一覧が表示されます。`hydor projects` は `hydor projects list` と同じです。`hydor help` は以下のようにグループ分けしたコマンドを表示し、Tabキーで動詞、オプション、それらが取る対象を補完できます。

すべてのコマンドに共通する動作は次のとおりです。

- **名前の指定**：コマンドが何か1つ（セッション、プロジェクト、エージェント、スキルなど）を取る場合は、そのIDまたはIDの先頭部分、あるいは名前やタイトルを指定します（大文字・小文字は区別されず、1つに絞れる場合に有効）。2つ以上に一致した場合は、最大5件を一覧表示します。ターミナルで名前を省略すると、コマンドが選択用の一覧を表示します。
- **変更**：各項目はオプションで指定します（`--description`、`--name`）。長いテキストは、`--file <path>`、`-` でパイプ入力した内容、またはそのどちらもないターミナルではエディタ（`$VISUAL`、`$EDITOR`）で現在のテキストを開いて入力できます。変更せずに保存した場合、何も変わりません。
- **削除**：`Remove “name”? [y/N]` と確認されます。`-y`（または `--yes`）を付けると、はいと答えたことになります。ターミナルがなく `-y` もない場合は、推測で実行せずに拒否します。
- **`--json`**：アプリのAPIが返した内容を、そのままスクリプト向けに出力します。
- **終了コード**：0は完了、1はHydorが拒否した、または失敗した場合（理由が表示されます）、2はコマンドの使い方が正しくない場合（入力すべき内容が表示されます）です。
- **別のコンピューターのHydor**：すべてのコマンドで `--server` と `--token` が使えます。
- **ページでしかできない操作**：コマンドがその旨とページのアドレスを表示します。`hydor open … --browser` でそのページを開けます。

### セッション

| コマンド | 内容 |
| --- | --- |
| `hydor sessions` | 最新のセッションを、状態を示す印付きで表示します。● 作業中、● 対応待ち、✓ 完了、✗ エラー。動詞はセッションのメニューと同じ操作を行います：`search`、`rename`、`archive` と `unarchive`、`pin` と `unpin`、`read`、`snooze`、プロジェクトへの `move`、`fork`、`goal`（ゴールを文章で設定、または `--pause`、`--resume`、`--clear` で操作します。エージェントがチェックを提案し、アプリ内のカードで**開始**を押すまで何も始まりません）、`share`（読み取り専用リンク）、`changes`（変更されたファイル）、`commands`（実行されたコマンド）、`queue`（待機中のメッセージ。`queue clear` と `queue remove` もあります）、`show`、`export`（会話をMarkdownファイルに出力します。`-o -` で画面に表示、`--library` でセッションのプロジェクトにドキュメントとして保存）、`send`、`stop`、`delete`。 |
| `hydor inbox` | 対応待ちの項目（承認、質問、エージェントが求めたキー、確認するスキル）：`list`、および1件を表示して回答先を示す `show`。 |
| `hydor outbox` | 承認待ちで保留されている呼び出し（確認が必要な設定の接続済みアカウントのツール）：`list`、入力内容付きで1件を表示する `show`、`send`（そのまま、または `--set NAME=value` で項目を変更して送信）、`drop`。 |
| `hydor away` | 前回の訪問以降の出来事を、スタートページの**不在中の出来事**と同じ形で表示します。対応待ちの項目、完了または失敗したセッション、自動で実行されたものとその費用、今日これから実行されるもの。`hydor away seen` はすべてを確認済みにします。 |

`hydor show 6f1e2a3b` は `hydor sessions show 6f1e2a3b` と同じで、`send` と `stop` も同様です。短い形も引き続き使えます。

```bash
hydor sessions search login          # sessions about login
hydor sessions rename 6f1e "Fix the login bug"
hydor sessions fork 6f1e "try it with a cache instead"
hydor sessions export 6f1e -o notes.md  # the conversation as Markdown
hydor inbox
hydor away                           # what happened while you were away
```

### 作業

| コマンド | 内容 |
| --- | --- |
| `hydor projects` | `list`、`show`、`new`、`rename`、`edit`（説明、ガイドライン、開始時のエージェント、フォルダ）、`sessions`、`files`（読み込むドキュメント：`files add` と `files remove`）、`remove`。 |
| `hydor tasks` | [スケジュールタスク](/guide/tasks)と、自動で始まるその他の作業：`list`、`show`、`new`（実行タイミングの指定：`--every 2h`、`--at 09:00 --days weekdays`、`--cron`、`--once`。または `--webhook`、`--watch-feed`、`--watch-page`、`--watch-folder`、接続済みアプリの新着項目には `--watch-account` と `--tool`、カレンダーの各予定の前に実行するには `--before 30m`）、`edit`、`pause`、`resume`、`run`（一時停止中でもすぐに実行）、`runs`（最新の実行。`--reply` で最後の返信）、`remove`。コマンドやJSONのアドレスの監視はページで設定します。ボードのカードの更新はボードのものとして一覧に表示されます（「Shop · Sales by day: refresh」）：`pause`、`resume`、`run` が使え、`show` は変更場所（ボード上）を案内します。 |
| `hydor apps` | [アプリ](/guide/apps)と既成のアプリ：`list`、`show`、`run`（フォームの回答を `field=value` で、または `--input` のJSONで指定します。回答とその費用が表示されます）、`runs`、`run-show`（1件の実行）、`remove`。`hydor app …`（sなし）はアプリをファイルとして作成します：`new`、`folder`、`dev`、`try`、`export`、`import`。 |
| `hydor files`（`hydor library` も可） | エージェントが作成したものや保存したものを、プロジェクトの**ファイル**と同じ形で表示します（[ページ、画像、動画、サイト](/guide/library)）：`list`（`--kind`、`--project`）、`search`、`show`（ドキュメントのテキスト、ボードのカード、または項目の内容）、`export`（`--to pdf`、`docx`、`pptx`…、`-o file`）、`open`（エディタのアドレス）、`remove`、`refreshes`（ボード上で更新されるもの、そのタイミングと費用）、`refresh`（ボードのカード、またはすべてをすぐに更新）。 |
| `hydor experiments` | トレーニングと評価の実行：`list`、`show`、`stop`。実行の開始はエージェントとページで行います。 |

```bash
hydor projects new Thesis
hydor projects edit thesis --file guidelines.md
hydor tasks new --at 09:00 --days weekdays "Summarise my unread email"
hydor apps run trip-planner destination=Lisbon days=5
hydor files export "Q3 report" --to pdf -o q3.pdf
```

| コマンド | 内容 |
| --- | --- |
| `hydor models` と `hydor tiers` | 各プログラムが提供するモデルと、各[ティア](/guide/agents-models#tiers-a-model-for-each-kind-of-job)がどのモデルを指すか（`hydor tiers set claude best opus --effort high`、`hydor tiers reset`。`hydor tiers team off` と `hydor tiers hard off` は**サブエージェントを主導**と**難問には最大**をオフにし、`on` で再びオンにします）。 |
| `hydor usage` | 各プランの使用量と上限、およびリセットのタイミング。 |
| `hydor agents` | [エージェント](/guide/agents)：`list`、`show`、`new`、`edit`、`results`、`export`、`install`、`remove`（組み込みのものはコピーできますが、変更はできません）。エージェントの結果の出力先は `new` と `edit` の `--results-to` で、場所ごとに1回ずつ指定します：`library`（同じページを更新）、`library:new`、`sheet`（専用のスプレッドシートに1行追加）、`sheet:<spreadsheet>#<tab>`、`email:<addresses>`、`notify`、`file:<path>`、`webhook:<url>`、`none`。出力フィールドはエージェントのページで設定します（`hydor open agents`）。`results` はエージェントが返した結果を、1件につき1行で表示します。`export` は1つのエージェントを `.hydor-agent` ファイルとして保存し（`-o` で名前を指定）、含まれなかったものを表示します。`install <file>` はファイルの内容と必要なものを表示して確認したうえで、同名のエージェントとは別にインストールします（`--replace` を付けると置き換えます。`--schedules` を付けると、ファイルが提案するスケジュールを一時停止の状態で追加します）。[エージェントをファイルとして共有する](/guide/agents#share-an-agent-as-a-file)もご覧ください。 |
| `hydor accounts` | Claude CodeとCodexのサインイン：`list`、`show`（1つのアカウントについて、サインインしているユーザーとプラン、新しいセッションがそのアカウントで始まるか、使用量と上限、APIキーが登録されているか（キー自体は表示されません）、上限に達したときにセッションが切り替わるか）、`add <program> <name>`（別のアカウントを追加し、すぐにサインイン）、`sign-in`、`sign-out`、`remove`、`use`（新しいセッションが使うアカウント）。APIクレジット用のAPIキーと使用上限での切り替えは設定です（`accounts.*`）。 |

```bash
hydor agents new Bookkeeper --tools read,edit --tier standard
hydor agents edit bookkeeper --results-to sheet --results-to email:sam@example.com
hydor agents export bookkeeper -o ~/Desktop/bookkeeper.hydor-agent
hydor agents install bookkeeper.hydor-agent --schedules
hydor tiers set claude best opus --effort high
hydor accounts add claude Work
hydor accounts use work
```

| `hydor keys` | [保管庫](/guide/connections)：キーの名前と使用できる場所を表示する `list`、`set <NAME>`、`remove <NAME>`。値は、非表示で入力するか、パイプで渡した内容から読み取ります。オプションとして入力することはできず（シェルに履歴が残るため）、表示もされません。 |

### 設定

`hydor settings` は、[設定](/settings)のすべてのオプションを、3つのグループ（**アプリ**、**エージェント**、**機能**）とそのセクションごとに扱えます。各オプションにはIDがあります（例：`general.resume-after-usage-limits`）。セクション名に続いてオプション名の語が並ぶ形です。オプションは、そのID、セクションと語の先頭部分（`general.resume`）、または1つに絞れる場合は語だけで指定できます。Tabキーで補完もできます。

ターミナルで `hydor settings` だけを実行すると、ブラウザが開きます。セクションを選び、次にオプションを選びます。**↑**・**↓**と文字入力で検索でき、**Enter**でセクションを開くかオプションを変更し（スイッチは切り替わり、選択肢は値の一覧が表示され、数値やテキストは入力し、ボタンは先に確認されます）、**Esc**で戻ります。パイプで実行すると、すべてのオプションを一覧表示します。スクリプトや素早い変更には次を使います。

| コマンド | 内容 |
| --- | --- |
| `hydor settings list [section]` | すべてのオプションとその値、または1つのセクションのものを表示します。 |
| `hydor settings get <option>` | 1つのオプションの値と、指定できる内容を表示します。 |
| `hydor settings set <option> <value>` | 値を変更します。スイッチは `on` または `off`、選択肢はその値のいずれか、数値は整数、リストは項目をカンマで区切って指定します（`none` で空になります）。キーやトークンは非表示で入力するか、パイプで渡した内容から読み取ります。長いテキストは `--file` またはエディタで指定します。 |
| `hydor settings run <option>` | ページのボタン（**テストを送信**、**今すぐ確認**など）を押します。何かを削除またはダウンロードする場合は、先に確認されます。 |
| `hydor settings open [section]` | アプリ内のセクションまたはオプションのアドレスを表示します。 |

```bash
hydor settings list memory
hydor settings get general.resume-after-usage-limits
hydor settings set general.resume-after-usage-limits on
hydor settings set search.providers duckduckgo,naget
hydor settings run notifications.send-a-test
```

アプリが各ブラウザに保存する内容（テーマ、言語、通知音）は、ここからは変更できません。そのようなオプションは、その旨とページのアドレスを表示します。ページでしか変更できないオプションも同様です。ターミナル専用の2つのデバイス設定、**エージェントの作業中に送信**と**ターミナルのサジェスト**はチャット自体の設定で、`hydor settings set` で変更できます。

### find、guide、open、api

- `hydor find rate limit` は、検索ボックス（**Ctrl+K**）と同じ範囲を検索します。ページ、設定とそのオプション、セッション、メモリ、スキルなどです。`--in settings` ならその中だけを検索し、`--urls` は各結果の下にアドレスを表示し、`--open 2` は2番目の結果をブラウザで開きます。
- `hydor guide` はガイドのトピックを一覧表示します。`hydor guide projects` は1つのトピックをターミナルで読み、`hydor guide projects "what a project is"` はそのうちの1つのセクションを読みます。`--sections` はトピックのセクションを一覧表示します。
- `hydor open` はアプリのアドレスを表示します。`hydor open published`、`hydor open settings memory`、`hydor open project thesis`、`hydor open guide projects`、`hydor open 6f1e2a3b`（セッション）は、それぞれのページのアドレスを表示します。`--browser` を付けるとブラウザでも開きます。ページでしかできない操作、つまりスライド、スプレッドシート、画像、図のエディタ、署名、テーマの色、サービスへのサインインなどには、この方法でたどり着けます。
- `hydor api GET /api/projects` は、アプリのAPIの任意のエンドポイントを呼び出し、そのJSONを表示します（`hydor api POST /api/projects -d '{"name":"Thesis"}'`。本文は `@file` または `-` で渡せます）。エンドポイントは[APIのトピック](/guide/api)にあります。

### チャットの中で

`/hydor <command>` は、会話から離れずに上記のコマンドをすべて実行できます：`/hydor sessions`、`/hydor memory search docker`、`/hydor settings get general.resume-after-usage-limits`。`/` メニューと、`/help` の**Also**の部分にあります。`/hydor ` の後では、メニューに領域、その動詞、それぞれが取る対象（シェルでTabキーが補完するのと同じ、プロジェクト、セッション、設定、フォルダなど）が順に表示され、`-` を入力するとそのオプションが表示されます。コマンドの出力は入力行の上に表示され、誤った使い方やHydorが拒否した応答は赤で表示されます。チャットはそのまま続けられます。コマンドはシェルと同じように確認を求めますが、チャットの中で行われます。質問（削除の確認など）は選択画面で表示され、最初の行は**いいえ**です。キーやトークンは入力行に入力し、ドットで表示され、履歴には残りません。必要なエディタには、`!` と同じようにターミナルが渡されます。チャットではパイプ入力ができないため、長いテキストは `--file <path>` で渡します（省略するとエディタで書けます）。専用のスラッシュコマンドがあるコマンド（`models` には `/model`、`tiers` には `/tiers`、`usage` には `/usage`）や、シェル向けのコマンド（`run`、`serve`）は、その旨と使うべきものを表示します。

## このHydorを管理する

- `hydor status` は、Hydorが動作しているかどうか、バージョンとアドレス、データの保存場所、サービスとして動いているかどうか、そして作業中または対応が必要なセッションを表示します（マークは `hydor sessions` と同じです）。
- `hydor serve` は、ここでHydorをフォアグラウンドで実行します。Ctrl+Cで終了します。`hydor service install` はバックグラウンドサービスとして動かし続けます。`hydor update` は最新のコードを取得してビルドし、再起動します。`hydor set-password`、`hydor setup-token`、`hydor access-token` は、名前のとおりの操作を行います。Macアプリでは、`hydor update`、`hydor service install`、`hydor serve` を実行すると、その操作はアプリ自身が行うと表示されます。
- `hydor open` はアプリのアドレスを表示します。`--browser` を付けるとブラウザで開きます。
- `hydor machines phone` は、ここでTailscaleがインストールされサインインしているかどうかと、tailnet上でアプリが公開されているアドレスを表示します。スマートフォンのカメラで読み取れるQRコードも表示されます。`hydor machines phone serve` はアプリを自分のデバイスに公開します（通常のアドレスを別のものが使っている場合は `--port 8443` を指定します）。`hydor machines phone stop` は公開を止めます。[設定 → アプリ → スマートフォンで使う](/settings?s=phone)と同じ操作です。

## 別のコンピューターのHydorを使う

そのコンピューターでアクセストークンを作成します（そのコンピューターの[設定 → アプリ → マシン](/settings?s=machines&find=Access%20from%20other%20machines)の**新しいトークン**、またはそこで `hydor access-token "my laptop"` を実行します）。次に、そのアドレスを指定します。

```bash
hydor --server https://hydor.example.com --token acm_… sessions
```

または、`HYDOR_URL` と `HYDOR_TOKEN` を一度設定しておきます。フォルダは相手のコンピューターのものです。`--cwd` で相手側のフォルダを指定しない限り、セッションは相手側の既定のフォルダで始まります（`http://localhost:8790` のようにこのコンピューター自身を指すアドレスの場合は、現在のフォルダがそのまま使われます）。`!` コマンドは、このコンピューターのHydorでのみ使えます。このコンピューターでは、コマンドが初回に専用のトークンを作成します。このトークンは[設定 → アプリ → マシン](/settings?s=machines&find=Access%20from%20other%20machines)に「This computer's command line」として表示されます。このHydorに別のコンピューターのセッションやページを表示するには、マシンとして追加します。`hydor machines` は、このHydorが使っているマシンと応答の有無を一覧表示します。`hydor machines add Lab --url https://lab.example.com` で追加できます（SSH経由で接続する場合は `--url` の代わりに `--ssh <host>` を指定します。アクセストークンは非表示で入力するか、`--file -` で渡します）。`hydor machines remove lab` で、そのマシンを使わないようにします。

## 色とパイプ

色はターミナルでは有効で（対応していればトゥルーカラー）、出力がファイルや別のプログラムに渡される場合、`NO_COLOR` が設定されている場合、`--no-color` を指定した場合は無効になります。`FORCE_COLOR` を設定すると有効になります。入力をパイプで渡す場合（`echo "…" | hydor`）は、`hydor run` と同様に動作します。出力だけをパイプにした場合は、会話は色や書き換わる行なしで表示され、入力した各行がそのまま送信されます。このとき `hydor sessions` などの一覧は、同じ列を色なし・長い内容を切り詰めずに表示するため、スクリプトで読み取れます。幅の狭いターミナルでは、名前やタイトルを切り詰める代わりに、一覧の列ごと省略されます（最初に説明、次にアドレスや経過時間などの順です）。記号を表示できない環境（Linuxコンソール、UTF-8ではないロケール、古いWindowsコンソール）では、コマンドは通常の文字で描画します。枠には `+-|`、プロンプトには `>`、マークには `*`、`+`、`x`、ロゴにはHYDORを使います。`HYDOR_ASCII=1` を設定するとどこでもこの表示になり、`HYDOR_ASCII=0` を設定すると無効になります。ファイルや別のプログラムへの出力は、`HYDOR_ASCII=1` が設定されていない限り、記号がそのまま使われます。
