# 受信トレイと通知

エージェントは自力で作業を進めますが、ときどきユーザーの対応が必要になります。承認、回答、フォーム、キー、あるいは何かが送信される前の確認です。このトピックでは、すべてのセッションとマシンから、対応待ちのものを1か所に集めて答えられる受信トレイ、確認待ちの呼び出しを保留する送信トレイ、そしてセッションの完了・失敗・対応が必要になったときに、アプリ内、コンピューター、アプリを閉じた状態のスマートフォンでお知らせする通知について説明します。

![受信トレイ：すべてのセッションから、対応待ちのものを表示](images/inbox.webp)

## 受信トレイを開く

受信トレイは、アイコンバーにあるトレイのアイコンの**受信トレイ**タイルで、**アプリ**のすぐ下、その下に**検索**が並びます（ほかのタイルをドラッグして並べ替えても、この3つは動きません）。角の数字は、対応待ちの件数です。スマートフォンでは、まず**メニュー**（≡）でサイドバーを開きます。ボタンはドロワーの上部にあります。検索ボックスに「受信トレイ」と入力しても開けます（Ctrl+K、Macでは⌘K）。[受信トレイを開く](/inbox)

ヘッダーには、対応待ちの件数（「3件が対応待ち」）が表示されます。新しいものほど上に並びます。一覧は、セッションが待機を始めたり終えたりするたびに自動で更新され、表示している間も数秒ごとに再確認されます。

対応待ちのものがないときは、「対応待ちのものはありません」と表示されます。

スタートページにも対応待ちのものが表示されます。メッセージ欄の下の**不在中の出来事**の先頭に、前回の訪問以降に完了したものや自動で実行されたものとともに並びます（[不在中の出来事](/guide/start#while-you-were-away)を参照）。

## 受信トレイに表示されるもの

このマシンのすべてのセッション（スケジュールタスクやアプリが開始したセッションを含む）と、ほかのマシンから、エージェントがユーザーの対応を待っているものがすべて表示されます。

- **承認**：エージェントが実行したいコマンド、変更したいファイル、使いたいツール。
- エージェントからの**質問**と、承認待ちの**プラン**。
- サービスが途中で入力を求める**フォーム**（「Notionがフォームへの入力を求めています」）や、開くよう求められたページ。
- **ユーザーの対応が必要なブラウザ**：「ブラウザで対応が必要です：…」（ログインや確認のクリアのため）、「支払いまたは注文の前に停止しました：…」、「…を開こうとしています（このマシンまたはそのネットワーク上）」。
- **エージェントが求めたキー**：「キーを求めています：OPENWEATHER_KEY」と、その理由。
- **エージェントが提案するスキル**：「新しいスキルを提案：…」または「…スキルの変更を提案」と、その理由。
- **ほかの場所でユーザーを待っているセッション**：アプリの外で動いているセッションの「VS Codeで待機中」（またはターミナルで待機中）。
- **アプリの質問**：ユーザーのアプリの実行が**人に確認**ステップで待機しているもの。
- **プロジェクトやアイテムを共有した相手からのコメント**：「Mariaが「論文第3章」にコメントしました」と、その内容。ユーザーかエージェントが返信するか、解決済みになるまで表示されます。**開く**で、ドキュメント、画像、動画、音声が開きます。
- **送信トレイで保留中の呼び出し**：エージェントが、**事前に確認**に設定した接続済みアカウントのツール（メール送信など）を呼び出したもの。これらは**送信トレイ**の下の先頭に表示されます。

各項目には、待機しているセッション（エージェントのアイコン付き）と、待機時間が表示されます。

## 受信トレイでそのまま承認・質問・フォームに答える

承認、質問、フォームは、セッションで表示されるものと同じカードで表示されるため、セッションを開かずに答えられます。各カードの上にセッション名があり、クリックするとそのセッションが開きます。カードの1行目には、求められている内容と待機時間が表示されます。

- **承認**には、エージェントがしたいこと（コマンド、ファイルの変更（差分として）、ツールの入力）が表示されます。ボタンのどれかをクリックします。**許可**、エージェントが提示した場合は「常に」の選択肢（**このセッションですべての編集を許可**や**このセッションで許可**など）、または**拒否**です。**拒否…**をクリックすると、まず「任意：代わりにどうすべきかエージェントに伝える」というボックスが開きます。必要なら一言書いて、**拒否**をクリックします。
- **プラン**（Claude Codeから）には、プランとともに**承認、編集を自動承認**、**承認、編集前に確認**、**プランを続ける**が表示されます。
- **質問**には選択肢が表示されます。1つ（許可されている場合は複数）選ぶか、**その他：自分の回答を入力**に自由に入力します。回答にファイルを添付することもできます。そのあと**回答を送信**をクリックするか、**スキップ**します。
- **サービスからのフォーム**には、サービスのメッセージと入力欄が表示されます。入力して**送信**、または**辞退**、**今はしない**をクリックします。入力するものがないフォームでは、**送信**の代わりに**許可**が表示されます。サービスがページを開くよう求めている場合は、**開く**で新しいタブに開きます。

答えると、その項目は受信トレイから消え、エージェントが作業を続けます。各選択肢の意味は、[エージェントがしたいことを承認または拒否する](/guide/sessions#approve-or-deny-what-the-agent-wants-to-do)と[質問に答えてプランを承認する](/guide/sessions#answer-questions-and-approve-plans)で説明しています。

## 送信トレイ：承認待ちの呼び出し

エージェントが**事前に確認**に設定した接続済みアカウントのツールを呼び出すと（[接続済みアプリ、キー、ツール](/guide/connections#ask-first-calls-that-wait-for-your-ok)）、その呼び出しは実行されません。受信トレイの先頭の**送信トレイ**の下に、呼び出し1件につき1枚のカードとして、送信または破棄するまで待機します。エージェントはユーザーを待たず、呼び出しが承認待ちであることをすぐに知らされます。

各カードには次のものが表示されます。

- アカウントとツール（「Gmail · send_email」）と、待機時間。
- **承認待ち**、エージェントのアイコン、呼び出し元のセッション（セッション名をクリックすると開きます）、そしてタスクの実行が呼び出した場合はそのスケジュールタスク。
- ツールの機能（サービスの説明どおり）。
- 変更できるフォーム形式の呼び出し内容。メールには**宛先**、**Cc**、**件名**、**本文**が表示されます。チャットメッセージには送信先と**テキスト**、投稿には**テキスト**が表示されます。ほかのツールには、そのツール独自の項目が表示され、必須の項目には赤い*が付きます。複数のアドレスは、1つの欄にカンマで区切って入力します。

そのあと：

- **送信**は、フォームの現在の内容で呼び出しを実行します。エージェントの作業がとっくに終わっていても、Hydor自身が実行します。カードは受信トレイから消え、送信されたことが通知されます。
- **破棄**は呼び出しを破棄します。実行されることはありません。
- **すべて送信**は、1つのセッションに複数のカードがあるときにそれらの上に表示され、保留された順にそのままの内容ですべて送信します。

サービスがエラーを返した場合、カードは残り、**送信されませんでした：**と理由、**再送信**が表示されます。保留中の呼び出しは再起動をまたいで待機し、30日間保持されます。

セッションには、呼び出しが保留された位置に、**送信トレイで承認待ち**と**送信トレイを開く**の行が表示されます。決定すると、サービスの応答の冒頭とともに**承認のうえ送信済み**、または**破棄済み：未送信**と表示されます。セッションにもう一度書き込むと、エージェントは呼び出しがどうなったかを知らされます。

保留中の呼び出しは、承認と同様に、アプリ、コンピューター、スマートフォンに通知されます：「送信トレイで承認待ち：…」。タップすると受信トレイが開き、スマートフォンからでも下書きを読み、変更して送信できます。

## そのほかの項目は待機している場所で開く

そのほかの項目は、待機している場所で答えます。各項目には、アイコン、求められている内容、詳細の1行、セッション、時刻、そしてその場所へ移動する**開く**があります。

- **ユーザーの対応が必要なブラウザ**は、セッションを開きます。メッセージ欄の上にそのブラウザが表示され、操作を引き継げます（[検索とブラウザ](/guide/web)）。
- **キー**や**サインイン**は、入力用のカードがあるセッションを開きます（[接続済みアプリ、キー、ツール](/guide/connections)）。
- **スキルの提案**は、承認または辞退するカードがあるセッションを開きます。そのセッションがすでにない場合は**設定 → スキルライブラリ**を開きます（[スキル](/guide/skills)）。
- **VS Codeやターミナルで待機しているセッション**は、何を待っているかを確認できるようここで開きます。回答は、そのセッションが動いているプログラムで行います。
- **アプリの質問**は、その実行を開き、**はい**または**いいえ**、あるいはフォームと**回答を送信**のカードが表示されます（[アプリ](/guide/apps#apps-with-steps)）。

## ほかのマシンで待機しているもの

Hydorが動いているほかのマシンを追加している場合（[1つのアプリからほかのマシンを使う](/guide/devices#use-other-machines-from-one-app)）、受信トレイはオンラインの各マシンに問い合わせ、そこで待機しているものも一覧に表示します。一覧はマシンごとに、マシン名の下にグループ化されます。**表示中**は、アプリが現在表示しているマシンを示します。ほかのマシンの承認、質問、フォームも、このマシンと同じようにここで答えられます。

一覧を送信できないマシン（たとえば古いバージョンのもの）は、代わりに「そちらで2件のセッションが対応待ち」と1行で表示され、**開く**でそのマシンへ移動できます。

## 受信トレイボタンの数字

受信トレイボタンの角にある小さな数字は、承認や回答を待っているセッションの数です。このマシンと、オンラインのほかのマシンが対象です。99を超えると**99+**と表示されます。ボタンにポインターを合わせると「受信トレイ：3件が対応待ち」と表示されます。

数字はアイテムではなくセッションを数えるので、2件の承認があるセッションも1と数えます。送信トレイで保留中の呼び出しは、1件ごとに加算されます。受信トレイにあっても加算されないものもあります。求められたキー、対応が必要なブラウザ、確認待ちのスキルです。

## ブラウザのタブの件数

アプリが表示しているマシンのセッションが承認や回答を待っている間、ブラウザのタブのタイトルの先頭にその件数が付きます：「(2) Hydor」。ほかのタブからも、切り替えずに確認できます。

## アプリからのお知らせ

セッションが完了、失敗、またはユーザーの対応が必要になったとき、アプリは状況に合った方法でお知らせします。

- **アプリが表示されている**：画面の下部（コンピューターでは右下）に小さなカードが表示されます。エージェントのアイコンに色付きの点（完了は緑、対応が必要なときは黄、失敗は赤）、セッション名、そして状態と返信の冒頭が表示されます。クリックするとセッションが開き、✕で閉じます。数秒後に消えますが、ポインターを重ねている間は残ります。同じセッションの新しいお知らせは、古いカードと入れ替わります。
- **アプリが、見ていないタブで開いている**：**この端末に通知**をオンにしていれば、システムからの通知が届きます。
- **アプリが閉じている**、またはスマートフォンがポケットの中：その端末で**この端末に通知**をオンにしていれば、プッシュ通知が届きます。
- **デスクトップアプリ（Mac、Windows、Linux）**：コンピューター独自の通知（Macでは通知センター）が、アプリのウィンドウが前面にあっても、ほかのウィンドウの後ろにあっても、閉じていても届きます（アプリはメニューバー、通知領域、システムトレイに残ります）。ログイン時にウィンドウを開かずアプリが起動した場合も同様です。クリックすると、そのセッションがアプリのウィンドウで開きます。同じセッションの新しい通知は、古い通知と入れ替わります。ウィンドウ内の小さなカードは、システムがアプリの通知を表示していない場合にのみ表示されます。ウィンドウが離れている間（閉じている、非表示、最小化、またはほかのアプリの後ろ）は、アプリのアイコンにも、新しいお知らせがあるセッションの数が1回ずつ表示されます。Macでは Dock のアイコン、Windowsではタスクバーのボタン（ウィンドウが開いている間は表示されません。通知領域に閉じている場合、タスクバーのボタンはありません）、Linuxでは件数を表示するデスクトップ（UbuntuのドックやKDEなど）のランチャーに表示されます。おやすみモードやフォーカスがオンでも表示され、ウィンドウを前面に出すとすぐに消えます。MacではHydorがアイコンにバッジを付けられる間に表示されます：**システム設定 → 通知 → Hydor → アプリアイコンにバッジを表示**（Hydorの通知を許可すると、既定でオンになります）。

今見ているセッションについては、お知らせは届きません。セッションが完了したとみなされるのは、そのセッションが開始したものがすべて終了したときだけです。バックグラウンドタスク（開発サーバーなどのコマンド、モニター）やサブエージェントがまだ動いている間は、お知らせは待機し、それらが終わってから届きます。スヌーズしたセッションが対応を必要とする場合は、すぐにスヌーズから戻ります。ハンズフリーモードでは、追従しているセッションが完了したときや対応が必要になったときに、アプリが音声でもお知らせします（[ドキュメント、画像、動画、音声](/guide/documents-voice)）。

## 各通知の内容

通知のタイトルはセッション名です（長い場合は短縮されます）。本文には、何が起きたかが表示されます。

- **完了**に続いて、エージェントの最後の返信の冒頭。少なくとも10秒かかったターンのあとに届くため、短いやりとりでは通知されません。
- セッションが対応を必要とするときは、その内容：
  - 単純なはい・いいえの承認では、エージェントがしたいことと、その1行目（「コマンドを実行：npm test」）。
  - それ以外は「承認が必要です」または「質問があります」。
  - ブラウザについては、ブラウザが必要としていること：「ブラウザで対応が必要です：…」、「支払いの前に停止しました：…」、「…を開くよう求めています」、「ページからの確認：…」。
  - VS Codeやターミナルのセッションでは「VS Codeで待機中」。1分後にもまだ待機している場合にのみ送信されます（その場にいる可能性が高いため）。
  - 送信トレイで保留中の呼び出しでは、「送信トレイで承認待ち：」に続いて、アカウントとツール、そして送信先。タップすると受信トレイが開きます。
- **失敗**に続いて、エラー。

目標に取り組んでいるセッションは、目標が達成されると「目標を達成しました：…」、停止すると「目標にユーザーの対応が必要です：…」または「目標を一時停止しました：…」と表示されます（[セッションに目標を設定する](/guide/sessions#give-the-session-a-goal)）。

スケジュールタスクの実行は、エージェントが書いた1行で結果を知らせます。新しい報告のない実行は通知されず、失敗した実行は必ず通知され、ブロックされた実行は「ブロック：…」と表示され、連続して失敗したために一時停止したタスクはその旨が表示されます（[スケジュールタスク](/guide/tasks)）。

ほかのマシンからのお知らせはこのマシンを経由して届くので、1台のデバイスですべてのマシンの通知を受け取れます。通知の本文はそのマシンの名前で始まり、アプリ内のカードには、そのマシン「上」と表示されます。

## この端末の通知をオンにする

[設定 → アプリ → 通知](/settings?s=notifications)の**この端末**グループには、端末（ブラウザ）ごとに設定する2つのスイッチとテストがあります。

- [**この端末に通知**](/settings?s=notifications&find=Notify%20this%20device)：セッションが完了したとき、失敗したとき、回答が必要なときに、アプリを閉じていても通知します。オンにすると、ブラウザに通知の許可を求めます。オンにするのは端末ごとです。スマートフォンとコンピューターで別々に設定します。デスクトップアプリ（Mac、Windows、Linux）では常にオンで、アプリの実行中はウィンドウを閉じていても、Mac、Windows、またはお使いのデスクトップの通知として届きます。Macでは、Hydorからの通知を許可するかどうかをmacOSが一度だけ尋ねます。許可したうえで、表示方法は**システム設定 → 通知 → Hydor**で選びます。システムが通知を表示していないときは、その行にそう表示され、その間は通知がアプリ内に表示されます。行の**(i)**には、通知を許可する場所が表示されます（Windowsでは**設定 → システム → 通知**）。スイッチをオンにすると許可できます。システム設定のHydorの通知画面が開きます（Windowsでは設定 → システム → 通知）。アプリに戻ると、通知が機能していることを確かめるテスト通知が表示されます。
- [**音声**](/settings?s=notifications&find=Sound)：アプリを開いている間、通知のたびに短いチャイムが鳴ります。セッションが完了したときは音が上がり、回答が必要なときや失敗したときは音が下がります。初期状態ではオフで、オンにするとチャイムが一度鳴ります。デスクトップアプリでは、アプリがウィンドウ内に表示する通知にだけチャイムが鳴ります。システムの通知は、それぞれ独自の音で鳴ります。
- [**テストを送信**](/settings?s=notifications&find=Send%20a%20test)（**試す**の行。**この端末に通知**をオンにすると表示されます）：通知をオンにしたすべての端末に通知を送ります。「Notifications work on this device.」と表示され、アプリが画面に表示されていないときに届くので、別の画面に切り替えて確認してください。何台の端末に送ったかがメッセージで表示されます。どの端末にも届かなかった場合は「No device got it.」と表示されます。デスクトップアプリでは、**試す**は最初から表示されます。**テストを送信**を押すと、アプリが前面にあっても、このコンピューターにすぐ通知が表示されます。システムが通知を表示しない場合は、「It didn’t show. Allow notifications for Hydor in the system’s settings.」というメッセージが表示されます。

スマートフォンで設定するには：

1. スマートフォンでアプリを開きます。この設定にはHTTPSでの提供が必要です。[設定 → アプリ → スマートフォンで使う](/settings?s=phone)でTailscaleを使えば、非公開のまま設定できます。そのQRコードを読み取ると、以下の手順でスマートフォンにアプリが開きます（[TailscaleでスマートフォンからHydorを使う](/guide/devices#use-it-on-your-phone-with-tailscale)）。
2. iPhoneまたはiPadでは、先にアプリをホーム画面に追加し（**共有** → **ホーム画面に追加**）、そこから開きます。それまでは設定にその旨が表示され、オンにできません。
3. **設定 → アプリ → 通知**を開き、**この端末に通知**をオンにします。スマートフォンから求められたら、通知を許可します。
4. **テストを送信**をタップし、アプリを離れて通知が届くのを確認します。

通知が「Blocked for this site in the browser settings」と表示されている場合は、先にブラウザの設定でアプリのアドレスに対して通知を許可してから、オンにします。「This browser cannot receive notifications here」と表示されている場合は、このアドレスではブラウザが通知を受け取れません。多くの場合、アプリがHTTPSではなくHTTPで開かれていることが原因です。

スイッチがいつの間にかオフに戻っていたら、ブラウザのプッシュサービスがこの端末を外したためです。もう一度オンにしてください。スマートフォンの電源が切れているときやオフラインのときは、通知は最大1日待機します。同じセッションについて新しい通知が届くと、端末上の古い通知はそれに置き換わります。

通知を止めるには、その端末で**この端末に通知**をオフにします。

## 通知から承認または拒否する

セッションが単純なはい・いいえの承認（コマンド、ファイルの変更、ツール。質問、フォーム、プランは対象外）を待っているとき、ブラウザが通知にボタンを表示する環境では、通知にカードと同じ文言の2つのボタンが付きます。たとえば**許可**と**拒否**です。

- どちらかをタップすると、アプリを開かずに回答できます。「Allow: Run a command」のような控えめな通知で確認できます。
- 回答が送れなかった場合（ブラウザがサインアウトされていた、すでに別の場所で回答済みだった、など）は、セッションが開くので、そこで回答します。
- 通知そのものをタップすると、すでに開いているアプリのウィンドウがあればそこで、セッションが開きます。
- デスクトップアプリの通知にはボタンがありません。通知をクリックしてセッションを開き、そこで回答します。
- 送信トレイで保留されている呼び出しにもボタンはありません。送信される内容を先に確認できるよう、通知をタップして受信トレイから送信します。

ほかのマシンからの承認も同じ方法で回答できます。回答はこのマシンを経由して、そのマシンに届きます。

## エージェントに頼む

エージェントは、自分を待っている項目を読み取ったり、テスト通知を送ったりできます。ほかのセッションの承認を代わりに回答することはできません。試せる例：

- 「今、私の対応待ちになっているものは何？緊急度の高い順に教えて。」
- 「キーを求めているセッションはどれ？何のために必要？」
- 「送信トレイに待機しているものは何？送信前にメールの内容を読み上げて。」
- 「待機中の各セッションが私に何を求めているか、1行ずつにまとめて。」
- 「スマートフォンに通知が届くか確認したいので、テスト通知を送って。」
