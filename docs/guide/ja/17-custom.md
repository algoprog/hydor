# Custom、アプリ独自のエージェント

Customは、Hydor独自のエージェントです。ClaudeとChatGPTのプランのモデルに加え、OpenRouter、Ollama、vLLM、その他のOpenAI互換サーバーから追加したモデルを、Claude CodeやCodexと同じツール、スキル、接続で実行できます。このトピックでは、Customでできること、権限モードとコマンドの確認方法、自動モード、コマンド用のサンドボックス、ゴール、長い作業や性能の低いモデルへの対処、そして設定について説明します。

![設定 → モデル：補助モデルと、このコンピューター上のモデル](images/custom.webp)

## Customとは、どんなときに使うか

Claude CodeはAnthropicのモデルだけ、CodexはOpenAIのモデルだけを実行します。Customは、このコンピューター上のClaude CodeとCodexのサインインを通じて、ClaudeとChatGPTのプランのモデルも実行できます。さらに、[設定 → エージェント → モデル](/settings?s=models)で設定した任意のモデルも使えます。たとえば、自分のコンピューター上のオープンモデル、OpenRouter経由の低価格または無料のモデル、独自のサーバーなどです。プランのモデルには設定は不要です。Claude Codeにサインインしていれば、Customの**モデル**メニューにClaude Opus、Fable、Sonnet、Haikuが表示されます。CodexにChatGPTでサインインしていれば、ChatGPTのプランに含まれるモデルが表示されます。これらはすべて**契約中のサブスクリプション**の下に並びます。使われるのはプランの使用量で、APIキーではありません。Customのモデルの入手元とモデルの追加については、[エージェント、アカウント、モデル](/guide/agents-models#where-customs-models-come-from)をご覧ください。

次のような場合にCustomを使います。

- コンピューターの外に出ないモデル（OllamaやvLLM）を使いたい場合、またはセッション全体を外に出したくない場合。[機密セッション](/guide/sessions#keep-a-session-confidential)は常にCustomで実行され、このコンピューターまたは自分のネットワーク上のモデルだけを使います（プランのモデルは、AnthropicやOpenAIのサーバーで動くため使いません）。
- DeepSeek、Qwen、GLM、Kimiなど、特定のモデルを使いたい場合。
- ClaudeまたはChatGPTのプランのモデルでCustom独自のツールとルールを使いたい場合、費用を抑えたい場合、またはClaudeやChatGPTのプランを使い切ったときに（他のモデルで）作業を続けたい場合。

調査、執筆、ドキュメント作成、日常のタスクなど、何にでも役立ちます。コードプロジェクト（`package.json`、`Cargo.toml`、Gitリポジトリなどがあるフォルダ）では、慎重なエンジニアのように動きます。変更する前に読み、プロジェクト独自の指示に従い、完了を伝える前にプロジェクトのテストとチェックを実行します。

Customは、他のエージェントと同じく、プロジェクトの`AGENTS.md`や`CLAUDE.md`を読み、[エージェントガイドライン](/guide/guidelines)に従います。

## Customのセッションを始める

1. スタートページで**エージェント**をクリックし、**Custom**（「どのモデルでも：OpenRouter、Ollama、vLLM」）を選びます。
2. **モデル**をクリックして使うモデルを選びます。メニューに**自動**があれば、それも選べます。Customのティアは、持っているモデル（Claudeのプラン、ChatGPTのプラン、このコンピューター上にない追加モデルの順）から自動的に埋まります。最高ティアにモデルが割り当てられると、**自動**のセッションはそのモデルで始まり、サブエージェントを率います（[ティア：作業の種類ごとのモデル](/guide/agents-models#tiers-a-model-for-each-kind-of-job)をご覧ください）。リストが空の場合は、先にモデルを追加します。**エージェント** → **Custom用モデル**から追加できます。
3. **オプション**の下で**権限**を選びます（[Customが確認なしでできることを選ぶ](#choose-what-custom-may-do-without-asking)をご覧ください）。Customには思考レベルの設定がありません。
4. タスクを入力して、Enterキーを押します。

このコンピューター上でvLLMが提供するモデルは、セッションで初めて使うときに起動します。セッションには「vLLMで…を起動しています（初回は1～2分かかります）…」と表示されます。

Customは一度に1件のメッセージを処理します。作業中に送ったメッセージは、メッセージ欄の上のキューで待機し、ターンが終わると送信されます。

セッションの途中でも、メッセージ欄の下のメニューからモデルを切り替えられます。Customは、ターンの途中であっても、次のステップから新しいモデルを使います。

## Customでできること

- **ファイル**：読み取り（行番号付きのテキスト、長いファイルは一部ずつ、フォルダの内容）、作成、書き換え、編集、フォルダの一覧表示、名前や内容によるファイル検索ができます。このセッションでまだ読んでいないファイルを丸ごと書き換える前には、先に読むよう求められます。
- **ドキュメント**：PDF、Word、Excel、PowerPoint、OpenDocument、RTF、EPUBのファイルをテキストとして読み取ります。
- **画像**：添付した画像、開いた画像ファイル、Webページやツールからの画像を扱います。画像を認識できるモデルには画像がそのまま渡されます。認識できないモデルの場合は、補助モデルが画像を説明します（[画像を認識できないモデル向けの対応](#images-for-models-that-dont-see)をご覧ください）。
- **コマンド**：セッションのフォルダでシェルコマンドを実行します。実行時間は、既定で最大2分、上限は10分です。サーバー、ウォッチャーなど動き続けるコマンドはバックグラウンドで実行され、Customは必要なときに出力を読み、停止もできます。Customが終了すると、これらも停止します。次のターンでは、まだ動いているコマンドが知らされます。
- **Webページ**：見出し、リンク、リスト、表を含むきれいなテキストとしてページを取得します。オンラインのPDFやOfficeファイルもテキストとして読み取ります。アクセスできるのは公開アドレスだけです。このコンピューターやそのネットワークには、`curl`などのコマンドを使います。
- **プラン**：複数のステップがある作業では、セッションにチェックリストを表示し、項目を順に済ませていきます。
- **スキル**：作業に合ったスキルを読み込みます。対象は、プロジェクトのスキル、自分のスキル（Claude CodeとCodexのスキルフォルダ）、アプリの[スキルライブラリ](/guide/skills)です。グループ名と名前で把握しており、作業内容を数語で伝えて探すこともできます。
- **MCPサーバー**：Claude Code用に設定したツールサーバー（すべてのフォルダ用とこのフォルダ用）、プロジェクトの`.mcp.json`、Codexのものを使います。
- **アプリ独自のツール**：Web検索、ブラウザ、メモリ、ページ、[接続](/guide/connections)など、ここにあるすべてのエージェントが使えるものを利用できます。

各ステップは、わかりやすい名前（「index.tsを読み取り」「README.mdを編集」「https://…を取得」など）でセッションに表示され、差分や出力はクリックで確認できます。

## Customが確認なしでできることを選ぶ

**権限**の設定（スタートページの**オプション**の下、またはセッションのメッセージ欄の下のメニュー）で、Customが自分の判断で行うことを決めます。メッセージ欄でShift+Tabを押すと、次のモードに切り替わります。

- **質問**（既定）：ファイルを編集する前とコマンドを実行する前に確認します。見て回るだけのコマンド（`ls`、`cat`、`git status`など）は、そのまま実行されます。
- **編集を承認**：セッションのフォルダ内のファイルは確認なしで編集します。コマンドの実行前（見て回るだけのものを除く）と、フォルダの外に関わる操作の前には確認します。
- **自動**：通常のステップはそのまま進みます。危険なステップについては、簡易チェックで確認します。[自動モード](#auto-mode)をご覧ください。
- **フルアクセス**：ツールとコマンドが、承認の確認やコマンドの[サンドボックス](#the-sandbox-for-commands)なしで実行されます。管理者コマンドやフォルダ外の変更も含まれます。コンピューターのアカウントの権限で動くため、アカウントにない管理者権限が与えられるわけではありません。機密セッションでは、ネットワーク制限は引き続き適用されます。
- **プラン**：読み取りと計画だけを行います。Customはファイルを編集したりコマンドを実行したりできず、読み取り用のツールだけを使います。最後に番号付きのプランを示します。実行するには、別のモードに切り替えて、進めるよう伝えます。

フルアクセス以外では、常に確認するコマンドがあります。[常に確認するコマンド](#commands-that-always-ask)をご覧ください。

## Customの操作を承認または拒否する

Customが確認を必要とすると、セッションにカードが表示されます（[受信トレイ](/guide/inbox)にも表示されます）。タイトルには、そのステップの内容と確認が必要な理由が示されます。たとえば「/home/you/notes/plan.mdを編集 — セッションのフォルダの外のファイルを変更します」のように表示されます。コマンドの場合は、カードにコマンド全体が表示されます。

- **許可**：このステップを1回だけ実行します。
- **常に許可…**：このステップと、このセッションでこれ以降の同様のステップを、確認なしで実行します。ボタンには対象が示されます。「npm run buildを常に許可…」「すべての編集を許可」「~/dataでの読み取りを常に許可」「~/siteでの変更を常に許可」などです。
- **却下**：このステップを止めます。Customには、拒否されたことと、再び試さないことが伝えられます。

コマンドでの**常に許可**の仕組みは次のとおりです。Customはコマンドを`&&`、`;`、`|`などの区切りで部分に分け、それぞれを確認します。ルールは、そのコマンドの先頭の語（`git status`、`npm run build`、`docker compose up`）で、対象となったコマンドだけに適用されます。そのため、`&&`の後ろに別のコマンドを紛れ込ませることはできません。見て回るだけのコマンドには、ルールは不要です。

安全にできない場合、**常に許可**は表示されません。

- コマンド内に直接書かれたコード（`python -c "…"`など）の場合
- 事前に名前がわからないファイルの場合
- 自信を持って読み取れないコマンドの場合
- 危険なコマンドの場合（毎回確認します）

## 常に確認するコマンド

フルアクセス以外では、次のステップは、以前に許可していても、自動モードでも、毎回確認します。

- 管理者としての実行（`sudo`など）
- セッションのフォルダ外のファイルの削除、セッションのフォルダ自体の削除、事前に名前がわからないファイルの削除
- ダウンロードをそのままシェルに渡す、またはダウンロードしたものをすぐに実行する操作
- ディスクへの生データの書き込み、ディスクのフォーマットやパーティションの再設定
- コンピューターのシャットダウンや再起動
- スケジュールされたジョブ（`crontab`）の変更
- フォルダツリー全体の権限や所有者の変更
- SSHキーの変更、またはホームフォルダ内の設定ファイルや起動ファイル（`.bashrc`、`~/.config`など）の変更（セッションがそのフォルダで作業している場合を除く）

## フォルダ外のファイルと、キーを含むファイル

**質問**、**編集を承認**、**プラン**では、Customはセッションのフォルダの外にあるファイルを読み取る前や変更する前に確認します（一時フォルダは対象外です）。このとき**常に許可**は、そのフォルダを対象に、読み取りまたは変更に適用されます。

キーやパスワードを含むファイルは、フォルダ内であっても、読み取りや変更の前に確認します。対象は、`.env`ファイル（サンプルを除く）、SSHなどの秘密鍵、`.netrc`、`.npmrc`、認証情報ファイル、クラウドやパスワードストアのフォルダ、エージェント自身のサインイン、アプリ自身のデータです。Git自体の設定やフックの変更も確認します。このとき**常に許可**は、そのファイルだけに適用されます。

**自動**モードでは、これらについては自動のルールと簡易チェックが判断します。**フルアクセス**では確認しません。

## 自動モード

**自動モード**では、通常の作業は止まらずに進み、それ以外のものは確認が入ります。**権限**の下で**自動**を選びます。

確認が必要になるステップは、それぞれ次のチェックを順番に通ります。

1. モデルを使わない**固定ルール**：
   - そのまま進める：セッションのフォルダ内の編集、一時フォルダ内の新しい作業用ファイル、フォルダ内を読むだけのコマンド、プロジェクト自身のテスト、ビルド、リンター、型チェック。
   - 確認する：フォルダ外のファイルの上書き、[常に確認するリスト](#commands-that-always-ask)にあるもの、Gitの強制プッシュ、フォルダ外のファイルの書き込み・移動・削除、支払いサービスを呼び出すコマンド、接続済みアプリやMCPサーバーのツールのうち、何かを送信・投稿するものや、お金がかかるもの。
2. それ以外のすべてに対する、[補助モデル](/guide/agents-models#choose-the-helper-model)による**簡易チェック**。次の3通りのどれかで答えます。
   - **許可**：依頼した内容に明らかに沿っていて、フォルダ内にとどまり（または読み取りだけで）、簡単に元に戻せる。
   - **質問**：取り返しのつかない被害を生じさせるおそれがある、または影響が広い（データの削除、システム全体へのソフトウェアのインストール、設定の変更、パスワードやキーの使用、何かの送信や公開、お金の支払い、依頼していないこと）。
   - **拒否**：明らかに有害、または意図に反している。そのステップは実行されません。Customには理由が伝えられ、別の方法を探します。

簡易チェックが見られるのは、セッション内の自分のメッセージ（最初の1件と直近の10件）、設定していればゴール、フォルダ、そのステップ自体（編集の場合は新しいテキストの冒頭）だけです。Customが読み取った内容は一切見ないため、Webページやファイルによって何かを仕向けられることはありません。チェックが失敗した場合や45秒を超えた場合は、自分で判断します。同じターン内では、同じステップには同じ答えが返ります。[機密セッション](/guide/sessions#keep-a-session-confidential)では、チェックはこのコンピューター上にとどまります。補助モデルがここで動く場合は補助モデルが、そうでなければセッション自身のモデルが行います。

セッションでは、自動モードが通したステップに小さな**自動**ラベルが付きます。マウスを重ねると理由が表示されます。自動モードが止めたステップのラベルは赤で表示され、マウスを重ねると「自動モードが停止しました：…」と理由が表示されます。自動モードから確認を求めるカードは、「自動：」と理由で始まります。

[設定 → 機能 → Custom](/settings?s=custom&find=Auto%20mode)には**自動モード**の行があり、その(i)に自動モードの説明が同じ言葉で表示されます。ここで切り替える項目はありません。

## コマンド用サンドボックス

自動モードでは、Customのコマンドをサンドボックス内で実行できます。コマンドがファイルを変更できるのはセッションのフォルダと一時フォルダだけで、コンピューター上のそれ以外はすべて読み取り専用です。ネットワークは引き続き使えます。セッションがgitのワークツリーやリポジトリのサブフォルダで作業している場合は、gitがコミットできるよう、リポジトリ自体のフォルダも書き込み可能のままになります。パッケージマネージャーのキャッシュは一時フォルダに移されます。サンドボックスの仕組みはコンピューターによって異なります。

- **Linux**：bubblewrapを使います。コマンドがファイルを変更できるのは、セッションのフォルダ、一時フォルダ（`/tmp`）、リポジトリ自体のフォルダです。
- **Mac**：macOSに付属するサンドボックスのSeatbeltを使います。ルールは同じで、セッションのフォルダ、一時フォルダ、リポジトリ自体のフォルダです。
- **Windows**：コマンドは低整合性レベルで実行されます。これはWindowsの保護機能で、すべてを読み取れますが、ファイルを変更できるのは許可の印が付いたフォルダだけです。初回に、HydorがセッションのフォルダとリポジトリのフォルダにZ印を付け、その印は残ります。コマンドには専用の一時フォルダが `AppData\LocalLow\Hydor` に用意され、一時ファイルやパッケージのキャッシュに使われます。ホームフォルダ、ドライブ全体、Windows、Program Files、アプリデータのフォルダには印が付けられません。そのようなフォルダでは、コマンドはサンドボックスなしで実行されます。Gitのbashは、低整合性レベルでは通常のbashウィンドウと内部の仕組みを共有できないため、初回にHydorがサンドボックス用のGitプログラムのコピーを `AppData\Local\Hydor\sandbox` に作成します（同じファイルへのリンクで構成されているため、Gitが同じドライブにある場合は容量を使いません）。

コマンドがサンドボックスの制限に当たると、Customにサンドボックス内で実行されたことが伝えられます。Customはその範囲内で作業を進めるか、別の場所で必要な操作をお知らせします。

オンとオフを切り替えるには、[設定 → 機能 → Custom](/settings?s=custom&find=Sandbox%20for%20commands)を開き、**コマンド用サンドボックス**のスイッチを使います。初期設定ではオンです。システム全体にインストールする場合など、ツールが別の場所に書き込む必要があるときはオフにします。変更は、実行中のセッションに約15秒以内に反映されます。

サンドボックスを実行できない場合は、スイッチがグレーアウトされ、その行に理由が表示されます。その間、コマンドはサンドボックスなしで実行されます。Linuxでは、bubblewrapがインストールされていないか、実行できない状態（一部のコンテナなど）を意味します。Macでは、Seatbeltを起動できなかったことを意味します。Windowsでは、初回にHydorがWindows付属の.NET Frameworkで小さなヘルパーを作成し、さらにGit for Windows（コマンドの実行にはいずれにせよ必要です）も必要です。どちらかがない場合やヘルパーを起動できない場合は、その行に表示されます。確認モードと編集を承認モードでは、コマンドはサンドボックスを使いません。この2つのモードでは、見て回る以上のことをするコマンドはすべて、OKを待つか、**常に許可**で保存したルールを待ちます。

[機密セッション](/guide/sessions#keep-a-session-confidential)では、すべてのコマンドが、どのモードでも、このスイッチの設定にかかわらず、ネットワークなしで実行されます。そのため、インターネットにも、ほかのコンピューターにも、このコンピューターのサーバーにも接続できません。ファイルの扱いはモードの設定のままです。これはLinux（bubblewrap）とMac（Seatbelt）で機能します。Windowsではこの方法でネットワークを遮断できないため、Windowsと、サンドボックスを実行できない環境では、どのモードでも各コマンドが先に確認を求め、**常に許可**は使えません。Customにはその旨が伝えられ、ネットワークを使おうとしたコマンドには失敗の理由が通知されます。

## Customにゴールを設定する

ゴールを設定すると、ある条件が満たされるまで、Customがターンを重ねて作業を続けます。例：「npm testが通り、アップロードページが2 GBのファイルを扱える」。

1. セッションのメニュー（⋯）→ **ゴールを設定**を開きます。
2. 「完了」とはどういう状態かを、作業が終わったときに真になる条件として記述します。
3. **作業を開始**をクリックします（またはCtrl+Enterを押します。Macでは⌘Enter）。

Customはすぐに作業を始めます。ターンが実行中の場合は、そのターンが終わったときにゴールが確認されます。

各ターンのあと、補助モデルが証拠に照らしてゴールを確認します。証拠とは、各ステップが行ったことや示したこと（コマンドの出力、テスト結果、ファイル、読んだページ）です。Customが「終わった」と言うだけでは認められません。確認の結果は次のとおりです。

- **完了**：ゴールがクリアされ、「Goal met」という通知が届きます。
- **まだです**：確認によって次のステップが書かれ、次のメッセージとして送られます（「Goal check 3: not there yet…」）。
- **対応が必要**：ゴールに「stuck: the agent needs you」と質問が表示され、通知が届きます。セッションで答えてください。
- **待機中**：外部の何か（デプロイやダウンロード）を待っている状態です。3分後にもう一度確認します。

ユーザー自身のメッセージが優先されます。確認は、キューが空になるまで待ちます。

次の場合、ゴールは一時停止し、その理由が通知されます。

- 設定の**目標が一時停止するまでのラウンド数**で許可された回数だけ、次のステップを送った場合（変更しなければ30回）
- 3ラウンド続けて進展がなかった場合
- エージェントを停止した場合、ターンが失敗した場合、エージェントが実行されていなかった場合、または確認自体が失敗した場合

メッセージ欄の上にあるゴールバーには、ゴールの内容、現在の状況（「working on it」「paused」「stuck: the agent needs you」）、確認した回数と所要時間、直近の確認の理由が表示されます。**一時停止**を押すと、次のステップは送られなくなります（すでに実行中のターンは最後まで進みます）。**再開**は、最後の次のステップから続けます（ラウンド数は最初から数え直されます）。**クリア**は、ゴールに向けた作業を止めます。ゴールの実行中は、ターンごとではなく、達成されたときに通知が1回届きます。

ゴールを実行できるラウンド数を変更するには、[設定 → 機能 → Custom](/settings?s=custom&find=Rounds%20before%20a%20goal%20pauses)を開き、**目標**グループの**目標が一時停止するまでのラウンド数**の行で、**10**、**30**、**100**のいずれかを選びます。

## 長い会話と長い出力

どのモデルも、一度に読める量には限りがあります（コンテキスト）。Customは各会話を自動でその範囲内に収めるため、Customのセッションには圧縮ボタンがありません。

1. 会話が上限に近づくと（返信の余裕を残したうえで）、Customはまず古いツール出力を消去します。セッションには「Cleared old tool output to keep within the model's context.」と記録されます。
2. それでも足りない場合は、モデルが前半部分をメモにまとめ、作業はそのメモを土台に続きます（「Summarizing the earlier conversation to keep within the model's context…」）。次回からは、最初からやり直さずにそのメモを更新します。プランと使用中のスキルは、どちらの場合も保持されます。

モデルのサーバーが会話が長すぎると応答した場合、Customはそのモデルの本当の上限を学習し、すぐに内容を圧縮します。各リクエストに付くのは、直近の数枚の画像だけです。

作業中は、開始時にメモリがCustomに渡した内容は変わりません。そのため、モデルのサーバーは会話について保持している内容を再利用でき、より速く、低コストで済みます。内容を圧縮するたびに、最新のメッセージに合わせてメモリを読み直します（[エージェントが最初に受け取るもの](/guide/memory#what-an-agent-starts-with)を参照）。

メッセージ欄の横にあるリングは、モデルのコンテキストの使用率をパーセントで示します。ポイントすると、トークン数とその内訳が表示されます。**オプション**（メッセージ欄の下のチップ）の**コンテキスト**の行には「42% in use」と表示され、小さな矢印があります。これをクリックすると内訳の表示と非表示が切り替わり、最初は折りたたまれています。内訳は、**指示**、**プロジェクトの指示**、**メモリ**、**アプリの機能**、**スキル**、**ツール**、**会話**で、それぞれのトークン数と、割合を示す細いバーが表示されます。中身のない項目は表示されません。数値はテキストから推定し、モデルのサーバーが数えた値に合わせて調整したものです。Customは自動で内容を圧縮するため、Customのセッションではリングをクリックしても何も起こりません。Claude CodeとCodexのセッションでは、リングと**圧縮**が引き続き使えます（[メーターの見方](/guide/sessions#read-the-meters-context-cache-and-speed)を参照）。

長い出力で会話がいっぱいになることもありません。コマンド、ページ、ツールがモデルのコンテキストの一定割合を超える結果を返したときは、Customがその全体をセッション専用のフォルダ内のファイルに保存します。モデルには先頭と末尾（コマンドの場合は、エラーが出やすい末尾が中心）とファイルの場所が渡され、残りは分割して読むか、検索して確認します。これらのファイルは1週間後に削除されます。

## モデルが読むもの

モデルには、ユーザーのメッセージの前に、次の順で内容が渡されます。

- Custom自身のルール（作業の進め方、モード、フォルダ）、エージェントの指示、エージェントガイドライン：内訳の**指示**
- プロジェクトの指示（`AGENTS.md` または `CLAUDE.md`）：**プロジェクトの指示**
- リクエストに対して[メモリ](/guide/memory#what-an-agent-starts-with)が持っている内容：**メモリ**
- アプリの機能についての説明。返信の見た目、キーやパスワードをチャットに出さないこと、後片付け、備えているツールの使い方（画像、アプリ、ブラウザ、ドキュメントなど）：**アプリの機能**
- スキル（**スキル**）。グループ名で示されます。プロジェクト固有のもの、ユーザーのもの、続いてコーディングやドキュメントなどのライブラリのグループの順です。Customは名前を指定して読み込むことも、作業内容から探すこともできます。Customが扱えるスキルは最大200件で、そのうちプロジェクト固有のものとユーザーのものは合わせて最大40件です。最初のメッセージに合うスキルは、それぞれの用途とともに渡されます。
- ツール。完全な形で備えているものと、残りの短い一覧：**ツール**

機能が自分のツールについて示す指示は、そのツールと一緒に渡されます。ツールがCustomの短い一覧にあるあいだは、その指示も待機します。モデルがそのツールを調べたり使ったりしたときに追加されます。どのツールを使っていても常に必要なルールは、常に保持されます。Claude CodeとCodexには、これまでどおり、アプリの指示がすべて最初に渡されます。

そのため、コンテキストの小さいモデルへの最初のメッセージは、以前より短くなっています。各部分が使う量は、**オプション**の内訳で確認できます。[長い会話と長い出力](#long-conversations-and-long-output)を参照してください。

**メモリの量はモデルのコンテキストに合わせて調整されます。** コンテキストの小さいモデルでは、メモリが固定量を占めると作業ができなくなるため、メモリの割合はウィンドウに合わせて小さくなります（内訳の**メモリ**の行に、使用量が表示されます）。

- **12,000トークン未満**：コンテキストの最大6%の小さなブロックで、プロフィールの最初の120語（最初の部分だけであることも示されます）、最大3件のメモ、索引なしです。メモリは、ユーザーのメッセージや、モデルがファイルを読んだり変更したりするときには何も追加せず、Wikiの記事の行もプランも渡しません。モデルには、メモリツールでメモを調べられることが伝えられます。
- **約33,000トークンまで**（OpenRouter経由を除く）：コンテキストの最大6%のブロックで、プロフィールの最初の400語、最大5件のメモ、短い索引、Wikiの記事1行、プラン1行です。メッセージには最大1件のメモ（600文字）、ファイルを読んだり変更したりするときには1件（350文字）が付きます。
- **より大きなモデル**：[メモリがエージェントに渡す](/guide/memory#what-an-agent-starts-with)すべての内容です。コンテキスト全体から見れば小さな割合です。

目安として、メモリのブロックは、8,000トークンのモデルで約1,700文字、32,000トークンで3,800文字、200,000トークンで7,300文字になります。プロフィールの最初の部分だけを渡されたセッションでは、プロフィールを書き換えられません。モデルが追加すべき内容を伝えるか、[設定 → メモリ](/settings?s=memory&find=Your%20profile)で編集します。Wikiについての指示も短くなっています。CustomにはWikiメモリについての短い段落が常に渡され、情報源の保管、Wikiの確認、プランの採用の方法は、そのためのツールが提供されているときだけ渡されます。Customが会話を圧縮したあとは、セッションのチェックポイント（[チェックポイント](/guide/wiki-memory#checkpoints)を参照）がコンテキストの8%、最大16,000文字に切り詰められ、残りを読める場所が示されます。

## Customが弱いモデルに対処する仕組み

すべてのモデルが、ClaudeやGPTほどツールの扱いに慣れているわけではありません。Customはよくあるミスを検出し、モデルを正しい流れに戻します。

- **繰り返し**：前回から何も変わっていない同じステップは、3回目は実行されません（モデルには先ほどの結果を使うよう伝えます）。5回目になるとターンを停止します。
- **失敗するステップ**：失敗したステップが4回続くと、モデルに手を止めて考え直すよう伝えます。8回続くとターンを停止します。
- **堂々巡り**：ステップが同じところをぐるぐる回っている場合は、別の方法を試すようメモを添えます。
- **未完了の作業**：「～してみます」と言うだけで実行しない場合や、計画の項目が残ったまま止まった場合は、それぞれ1回ずつ作業に戻されます。コードを変更したのにプロジェクトのチェックを実行していない場合は、終了する前に実行するよう求められます。
- **長さ**：1回のターンは最大200ステップまでです。150ステップに達すると、最も重要な部分を仕上げるようモデルに伝えます。モデルの長さの上限で途切れた返信は、より短いステップに分けて続けられます。
- **壊れたツール呼び出し**：テキストとして書かれた呼び出しは読み取って実行し、引数がほぼ正しい呼び出しは修復します。また、綴りの間違ったツール名は正しいツールに対応付けるか、ツールの一覧を返して答えます。呼び出しをテキストで書く返信は、呼び出しの終わりで終了とみなします。その後にモデルが書いた内容（想像した結果、その上に重ねた別の呼び出し、同じ呼び出しの繰り返し）は実行も保持もされません。1回の返信から実行される呼び出しは最大6件です。
- **ツール呼び出しに対応していないモデル**：モデルのサーバーがツールを受け付けない場合、Customはツールを指示文で説明し、モデルが書いた内容から呼び出しを読み取ります。
- **Claude Code経由のClaude**：Anthropicは、プランのサインインを自社のプログラムにしか使わせません。そのため、プランのClaudeモデルはClaude Code自体を通じて、1ステップずつ応答します。Customのツールは指示文で説明され、Claudeはツール呼び出しを、ツール呼び出しに対応していないモデルと同じようにテキストで書きます。各ステップは前のステップのキャッシュを再利用します。Claude Codeはツール呼び出しの位置で返信を終えられないため、Customがそこで返信を終了し、Claudeが想像した結果を書く前にプログラムを停止します。Codexのモデルは別で、ChatGPTのプランで直接呼び出され、Customのツールが本物のツールとして使われます。
- **一時的な不具合**：返信の途中で接続が切れた場合や、サーバーが混み合っている場合は、Customが待ってから数回やり直します。プランのモデルを待っているステップの途中でアプリが再起動した場合（アップデートなど）は、アプリが戻った後にそのステップをもう一度依頼します。再起動のために終了したターンはその旨が表示され、メッセージを送ると続きから進められます。
- **多数のツール**：MCPサーバーや接続から多くのツールが提供される場合、モデルには短い一覧が表示され、必要なツールの詳しい説明を自分で調べます。機能ごとのツールに関する指示は、モデルがそのツールを調べたとき、または使うときに一緒に渡されます（[モデルが読む内容](#what-the-model-reads)を参照）。コンテキストが短いモデル（約32,000トークン以下で、OpenRouter経由ではないもの）には、より簡素なセットが渡されます。回答UIの案内はなく、ツールは名前だけの一覧になり、詳細付きのツールも減ります（HTMLのページを表示するツールも一覧に回されます）。また、小さなステップで進めるよう求められます。
- **モデルファミリーごと**に、開発元の推奨設定、学習に使われた編集形式、思考レベルがあるモデルではその思考レベルが適用されます。読み取りだけのステップは、待ち時間を減らすために同時に実行されます。

これらの理由でCustomがターンを停止した場合、返信の最後に「(Stopped: …)」と表示されます。

## 画像を認識できないモデルへの対応

画像を認識できるモデルには、画像がそのまま渡されます。このコンピューターにffmpegまたはImageMagickがある場合、画像は先に縮小されます。

画像を認識できないモデルには、補助モデルが各画像を言葉で説明します。何が写っているか、どこに何があるか、画像内の文字は一字一句そのまま書き写します。そのためには、画像を認識できる補助モデルが必要です。[設定 → エージェント → モデル](/settings?s=models&find=Helper%20model)を開き、**補助モデル**グループの**モデル**メニューで「画像を認識」と表示されているものを選びます。「自動」では使えません。選ばない場合、Customはモデルに、見えない画像があることを伝えます。機密セッションでは、このコンピューター上の補助モデルだけが画像を説明します（プランのモデルは使われません）。

## フォークとここから編集

CustomのセッションもClaude CodeやCodexのセッションと同様にフォークできます。セッションのメニュー（⋯）→ **フォーク**を選びます。また、**ここから編集**で、以前に送った自分のメッセージを変更することもできます。そのメッセージの直前までの会話をコピーして続きを進め、元のセッションはアーカイブされます。**このメッセージの前の状態にファイルを戻す**にチェックを入れると、それ以降のファイルの変更を取り消せます。Customの場合、取り消されるのはCustom自身の編集で変更されたファイルです。コマンドによる変更はそのまま残ります。

Customは各会話をディスクに保存するため、アプリを再起動しても続きから進められます。

## Customの費用

- OpenRouter経由のモデル：OpenRouterが各呼び出しの費用を報告し、セッションの支出にはその金額が使われます。OpenRouter上のClaudeモデルには、他のモデルが自動で行うのと同様に、会話をキャッシュに保持するよう依頼します。そのため各ステップは約10分の1の料金で読み戻されます。また、Customに提供されるツールはセッション中に変わっても1回までで（バックグラウンドで動くコマンド用のツールは、一度実行されると残ります）、これによりキャッシュが保たれます。
- ClaudeまたはChatGPTのプランのモデル（**契約中のサブスクリプション**）：トークンごとの料金ではなくプランの使用量が消費されるため、これらのステップではセッションに$0と表示されます。アカウントが使用上限に達した場合やサインアウトしている場合は、そのプログラムの次のアカウントにステップが引き継がれます（**上限時にアカウントを切り替え**がオンの場合）。
- このコンピューター上のモデル（Ollama、vLLM）：無料です。
- その他のエンドポイント：トークンは他のエージェントと同じ方法で価格が計算されます（[使用量、上限、費用](/guide/usage)を参照）。

セッションでは、支出上限を設定していなくても、メッセージボックスの上にAPI費用と、入力・キャッシュ済み・出力のトークン数が表示されます。料金はOpenRouterの応答から取得され、ストリーミングされた料金がない場合はその生成記録から取得されます。それも使えない場合は、OpenRouter自身のカタログ価格が代わりに使われます。価格を手動で入力する必要はありません。

[支出上限](/guide/usage#cap-what-a-session-spends)はCustomのセッションでも使えます。

## 設定 → 機能 → Custom

[設定 → 機能 → Custom](/settings?s=custom)（「自動モード、コマンド用サンドボックス、目標の実行期間」）には3つの行があります。

- **自動モード**（Customのモードの1つで、確認、編集を承認、フルアクセス、プランと並びます）：(i)に、自動モードで許可される操作、常に確認される操作、そして確認を補助モデルが行うことが説明されています。切り替える項目はありません。自動モードはセッションごとに**権限**で選びます。
- **コマンド用サンドボックス**（自動モードでは、コマンドがファイルを変更できるのは、セッションのフォルダと、Linuxでは/tmp、Macでは一時フォルダ、Windowsでは専用の一時フォルダのみです。フルアクセスでは、このサンドボックスも承認の確認もなしで実行されます）：スイッチで、初期設定ではオンです。このコンピューターでサンドボックスを実行できない場合（Linuxではbubblewrap、MacではSeatbelt、WindowsではGit for Windowsと.NET Framework）はグレーアウトされ、行にその理由が表示されます。
- **目標が一時停止するまでのラウンド数**（**目標**グループ内。/goalを使うと、Customは目標が達成されるまでターンを重ねて作業します。このラウンド数に達すると、ユーザーの判断を待って一時停止します）：**10**、**30**（初期設定）、**100**ラウンドから選びます。進展のないラウンドが3回続いた場合も一時停止します。

Customのモデルは[設定 → エージェント → モデル](/settings?s=models)にあり、チェックを行うモデルはそこの**補助モデル**です。

## エージェントに頼んでみましょう

- 「Customの自動モードのコマンドで、サンドボックスをオフにして。」
- 「Customの目標を最大100ラウンドまで実行させて。」
- 「Customのセッション『アップロードページ』に目標を設定して。npm testが通ることと、2GBのアップロードが動くこと。」
- 「自動モードはどの補助モデルを使っている？ その補助モデルは画像を認識できる？」
- 「このコンピューターは、機密セッションのコマンドをネットワークなしで実行できる？」
- 「OpenRouterからQwen3 Coderを追加して、Customで使えるようにして。」（OpenRouterのキーを設定した後）
- 「モデルの価格を入力しなくても、OpenRouterの使用量と費用を表示して。」
- 「ローカルモデルだと、Customへの最初のメッセージがこんなに長くなるのはなぜ？」
- 「Customのセッションのコンテキストはどのくらい埋まっていて、何が一番多くを占めている？」
- 「CustomのセッションをOpenRouterではなく、Claudeプランのソネットで実行して。」
- 「Customで最高のモデルはどれ？ Customのセッションは自動で始められる？」
