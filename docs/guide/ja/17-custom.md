# Custom、アプリ独自のエージェント

Customは、Hydor独自のエージェントです。ClaudeやChatGPTのプランのモデルに加え、OpenRouter、Ollama、vLLM、その他のOpenAI互換サーバーから追加したモデルも実行でき、Claude CodeやCodexと同じツール、スキル、接続を使えます。このトピックでは、Customにできること、権限モードとコマンドの確認方法、自動モード、コマンド用のサンドボックス、ゴール、長い作業や性能の低いモデルへの対処、そして設定について説明します。

![設定 → モデル：補助モデルと、このコンピューター上のモデル](images/custom.webp)

## Customとは、どんなときに使うか

Claude CodeはAnthropicのモデルだけ、CodexはOpenAIのモデルだけを実行します。Customは、このコンピューター上のClaude CodeとCodexのサインインを通じて、ClaudeやChatGPTのプランのモデルも実行できます。さらに、[設定 → エージェント → モデル](/settings?s=models)で設定した任意のモデルも使えます。自分のコンピューター上のオープンモデル、OpenRouter経由の安価または無料のモデル、独自のサーバーなどです。プランのモデルには設定は不要です。Claude Codeにサインインしていれば、Customの**モデル**メニューにClaude Opus、Fable、Sonnet、Haikuが表示されます。CodexにChatGPTでサインインしていれば、ChatGPTのプランに含まれるモデルが表示されます。いずれも**契約中のサブスクリプション**の下に並びます。これらはAPIキーではなく、プランの使用量を使います。Customのモデルの入手元と追加方法については、[エージェント、アカウント、モデル](/guide/agents-models#where-customs-models-come-from)をご覧ください。

次のような場合にCustomを使います。

- モデルをコンピューターの外に出したくない場合（OllamaやvLLM）。セッション全体を外に出したくない場合も同様です。[機密セッション](/guide/sessions#keep-a-session-confidential)は常にCustomで実行され、このコンピューターまたは自分のネットワーク上のモデルだけを使います（AnthropicやOpenAIのサーバーで動くプランのモデルは使いません）。
- DeepSeek、Qwen、GLM、Kimiなど、特定のモデルを使いたい場合。
- ClaudeやChatGPTのプランのモデルでCustom独自のツールとルールを使いたい場合、費用を抑えたい場合、またはClaudeやChatGPTのプランを使い切ったときに作業を続けたい場合（ほかのモデルを使用）。

調査、執筆、ドキュメント、日常のタスクなど、何にでも役立ちます。コードのプロジェクト（`package.json`、`Cargo.toml`、gitリポジトリなどがあるフォルダ）では、慎重なエンジニアのように動きます。変更する前に読み、プロジェクト独自の指示に従い、完了と報告する前にプロジェクトのテストとチェックを実行します。

Customは、ほかのエージェントと同様に、プロジェクトの`AGENTS.md`や`CLAUDE.md`を読み、[エージェントガイドライン](/guide/guidelines)に従います。

## Customのセッションを始める

1. スタートページで**エージェント**をクリックし、**Custom**（「任意のモデル：OpenRouter、Ollama、vLLM」）を選びます。
2. **モデル**をクリックして使うモデルを選びます。メニューに表示されていれば**自動**も選べます。Customのティアは、持っているモデルから自動的に埋まります（Claudeプランのモデル、次にChatGPTプランのモデル、次にこのコンピューター上にない追加したモデルの順）。最高ティアにモデルが指定されると、**自動**のセッションはそのモデルで始まり、サブエージェントを指揮します（[ティア：仕事の種類ごとのモデル](/guide/agents-models#tiers-a-model-for-each-kind-of-job)を参照）。リストが空の場合は、先にモデルを追加します。**エージェント** → **Custom用モデル**です。
3. **オプション**の下で**権限**を選びます（[Customが確認なしでできることを選ぶ](#choose-what-custom-may-do-without-asking)をご覧ください）。**思考レベル**は、推論するモデルを使う[エンドポイント](/guide/agents-models#other-openai-compatible-endpoints)で選べます（エンドポイントが推論対応と伝えている場合、または**推論の思考レベル**を**はい**に設定した場合）。それ以外のモデルには、Customの思考レベル設定はありません。
4. タスクを入力してEnterを押します。

このコンピューター上でvLLMが提供するモデルは、セッションが初めて使うときに起動します。セッションには「vLLMで…を起動しています（初回は1～2分かかります）…」と表示されます。

Customは一度に1つのメッセージを処理します。作業中に送ったメッセージはメッセージ欄の上のキューで待機し、ターンが終わると送信されます。

セッション中は、メッセージ欄の下のメニューからモデルを切り替えられます。Customは、ターンの途中でも次のステップから新しいモデルを使います。

## Customにできること

- **ファイル**：読み取り（行番号付きのテキスト、長いファイルの一部ずつ、フォルダの内容）、作成、書き換え、編集、フォルダの一覧表示、名前や内容によるファイル検索ができます。このセッションでまだ読んでいないファイルを丸ごと書き換える前には、先に読むよう求められます。
- **ドキュメント**：PDF、Word、Excel、PowerPoint、OpenDocument、RTF、EPUBのファイルをテキストとして読み取ります。
- **画像**：添付した画像、開いた画像ファイル、Webページやツールからの画像を扱えます。画像に対応したモデルには画像がそのまま渡されます（エンドポイントのモデルの場合は、エンドポイントが対応と伝えているか、**画像対応**を**はい**に設定したとき）。対応していないモデルには、補助モデルが画像を説明します（[画像に対応していないモデルの場合](#images-for-models-that-dont-see)をご覧ください）。
- **コマンド**：セッションのフォルダでシェルコマンドを実行します。実行時間は既定で最大2分、上限は10分です。サーバー、監視プロセスなど動き続けるコマンドはバックグラウンドで実行されます。Customは必要なときに出力を読み、停止もできます。Customが終了するとそれらも停止し、次のターンでは、まだ動いているものが通知されます。
- **Webページ**：見出し、リンク、リスト、表を含むきれいなテキストとしてページを取得します。オンラインのPDFやOfficeファイルもテキストとして読めます。アクセスできるのは公開アドレスだけです。このコンピューターやそのネットワークには、`curl`などのコマンドを使います。
- **プラン**：複数のステップがある作業では、セッションにチェックリストを表示し、項目にチェックを付けていきます。
- **スキル**：作業に合ったスキルを読み込みます。プロジェクトのもの、自分のもの（Claude CodeとCodexのスキルフォルダ）、アプリの[スキルライブラリ](/guide/skills)のものが対象です。グループと名前で把握しており、作業内容を表す短い言葉で探すこともできます。
- **MCPサーバー**：Claude Code用に設定したツールサーバー（すべてのフォルダ用とこのフォルダ用）、プロジェクトの`.mcp.json`、Codexのものを使います。
- **アプリ独自のツール**：Web検索、ブラウザ、メモリ、ページ、[接続](/guide/connections)など、ここのすべてのエージェントが使えるものです。

各ステップは、わかりやすい名前（「index.tsを読み取り」「README.mdを編集」「https://…を取得」など）でセッションに表示され、差分や出力はクリックで確認できます。

## Customが確認なしでできることを選ぶ

**権限**設定（スタートページの**オプション**、またはセッションのメッセージ欄の下のメニュー）で、Customが自分で行う範囲を決めます。メッセージ欄でShift+Tabを押すと、次のモードに切り替わります。

- **質問**（既定）：ファイルを編集する前とコマンドを実行する前に確認します。見るだけのコマンド（`ls`、`cat`、`git status`など）は自由に実行されます。
- **編集を承認**：セッションのフォルダ内のファイルは自由に編集します。コマンドの実行前（見るだけのものを除く）と、フォルダ外に対する操作の前に確認します。
- **自動**：通常のステップはそのまま進み、リスクのあるものは簡易チェックで確認します。[自動モード](#auto-mode)を参照してください。
- **フルアクセス**：ツールとコマンドが承認の確認もコマンドの[サンドボックス](#the-sandbox-for-commands)もなしで実行されます。管理者コマンドやフォルダ外の変更も含みます。コンピューターのアカウントの権限で動くため、アカウントにない管理者権限が与えられるわけではありません。機密セッションでは、ネットワークの制限は維持されます。
- **プラン**：読み取りと計画だけを行います。Customはファイルの編集もコマンドの実行もできず、読み取り用のツールだけを使います。最後に番号付きの計画を出します。実行するには、別のモードに切り替えて進めるよう伝えます。

**フルアクセス**以外では、一部のコマンドは常に確認します。[常に確認するコマンド](#commands-that-always-ask)を参照してください。

## Customの操作を承認または拒否する

Customに承認が必要なときは、セッション（および[受信トレイ](/guide/inbox)）にカードが表示されます。タイトルには、そのステップの内容と確認する理由が書かれています。たとえば「/home/you/notes/plan.mdを編集 — セッションのフォルダ外のファイルを変更します」のようになります。コマンドの場合は、カードにコマンド全体が表示されます。

- **許可**：この1回のステップを実行します。
- **常に許可…**：このステップと、このセッションでの同様のステップを、今後は確認なしで実行します。ボタンには対象が表示されます。「npm run build …を常に許可」「すべての編集を許可」「~/dataでの読み取りを常に許可」「~/siteでの変更を常に許可」などです。
- **却下**：このステップを止めます。Customには、断られたことと、再試行しないことが伝わります。

コマンドでの**常に許可**の仕組み：Customはコマンドを（`&&`、`;`、`|`などで）部分に分け、それぞれを確認します。ルールは、作成時のコマンドを最初の数語（`git status`、`npm run build`、`docker compose up`）で対象とするため、`&&`の後ろに別のコマンドを紛れ込ませることはできません。見るだけのコマンドにはルールは不要です。

安全にできない場合、**常に許可**は表示されません。

- コマンドの中に直接書かれたコード（`python -c "…"`など）
- 名前が事前にわからないファイル
- 確実に読み取れないコマンド
- リスクのあるコマンド（毎回確認します）

## 常に確認するコマンド

**フルアクセス**以外では、次のステップは、自動モードを含め、以前に許可していても毎回確認します。

- 管理者としての実行（`sudo`など）
- セッションのフォルダ外のファイルの削除、セッションのフォルダ自体の削除、事前に名前がわからないファイルの削除
- ダウンロードしたものをそのままシェルに渡すこと、またはダウンロードしてすぐ実行すること
- ディスクへの生データの書き込み、ディスクのフォーマットやパーティションの再設定
- コンピューターのシャットダウンや再起動
- スケジュールされたジョブ（`crontab`）の変更
- フォルダツリー全体の権限や所有者の変更
- SSHキーの変更、またはホームフォルダ内の設定ファイルや起動ファイル（`.bashrc`、`~/.config`など）の変更（セッションがそのフォルダで作業している場合を除く）

## フォルダ外のファイルと、キーを含むファイル

**質問**、**編集を承認**、**プラン**では、Customはセッションのフォルダ外のファイルを読む前や変更する前に確認します（一時フォルダは対象外です）。このとき**常に許可**は、そのフォルダを、読み取りまたは変更について対象にします。

キーやパスワードを含むファイルは、フォルダ内でも、読み取りや変更の前に確認します。`.env`ファイル（サンプルを除く）、SSHなどの秘密鍵、`.netrc`、`.npmrc`、認証情報ファイル、クラウドやパスワードストアのフォルダ、エージェント自身のサインイン、アプリ自身のデータです。ただし、メッセージに添付したファイルは例外です。アプリは自身のデータと一緒に保管しますが、Customは確認せずに読み取ります。別の会話で添付されたファイルは、引き続き確認します。gitの設定やフックの変更も確認します。このとき**常に許可**は、そのファイルだけを対象にします。

**自動**モードでは、代わりに自動モードのルールと簡易チェックが判断します。**フルアクセス**では確認しません。

## 自動モード

**自動モード**では、通常の作業は止まらずに進み、それ以外について確認します。**権限**で**自動**を選びます。

確認が必要になるステップは、次のチェックを順に通ります。

1. モデルを使わない**固定ルール**：
   - 進める：セッションのフォルダ内の編集、一時フォルダへの新しい作業用ファイル、フォルダ内で読み取るだけのコマンド、プロジェクト自身のテスト、ビルド、リンター、型チェック。
   - 確認する：フォルダ外のファイルの上書き、[常に確認するリスト](#commands-that-always-ask)にあるもの、gitの強制プッシュ、フォルダ外のファイルの書き込み、移動、削除、決済サービスを呼び出すコマンド、接続済みアカウントやMCPサーバーのツールのうち、何かを送信や投稿するもの、お金を使うもの。
2. それ以外はすべて、[補助モデル](/guide/agents-models#choose-the-helper-model)による**簡易チェック**。次の3通りのどれかで答えます。
   - **許可**：依頼した内容に明らかに沿っていて、フォルダ内にとどまり（または読み取りだけで）、元に戻しやすい。
   - **質問**：取り返しのつかない害を及ぼす可能性がある、またはより広い範囲に及ぶ（データの削除、システム全体へのソフトウェアのインストール、設定の変更、パスワードやキーの使用、何かの送信や公開、お金を使うこと、依頼していないこと）。
   - **拒否**：明らかに有害、または意図に反している。そのステップは実行されず、Customには理由が伝えられ、別の方法を探さなければなりません。

簡易チェックが見るのは、セッション内の自分のメッセージ（最初の1件と最新の10件）、設定していればゴール、フォルダ、そのステップ自体（編集の場合は新しいテキストの冒頭）だけです。Customが読んだ内容は一切見ないため、Webページやファイルに言いくるめられることはありません。チェックが失敗した場合や45秒を超えた場合は、自分で判断します。同じターン内では、同じステップには同じ答えが返ります。[機密セッション](/guide/sessions#keep-a-session-confidential)では、チェックはこのコンピューター上にとどまります。補助モデルがここで動いていればそれが、そうでなければセッション自身のモデルが行います。

セッションでは、自動モードが通したステップに小さな**自動**ラベルが付きます。ポインタを合わせると理由が表示されます。自動モードが止めたステップのラベルは赤で表示され、ポインタを合わせると「自動モードがこれを止めました：…」と理由が表示されます。自動モードがユーザーに回すカードは、「自動：」と理由で始まります。

[設定 → 機能 → Custom](/settings?s=custom&find=Auto%20mode)には**自動モード**の行があり、その(i)に自動モードの説明が同じ言葉で書かれています。ここで切り替える項目はありません。

## コマンド用サンドボックス

自動モードでは、Customのコマンドをサンドボックス内で実行できます。コマンドがファイルを変更できるのはセッションのフォルダと一時フォルダだけで、コンピューター上のそれ以外はすべて読み取り専用です。ネットワークは引き続き使えます。セッションがGitのワークツリーまたはリポジトリのサブフォルダで作業している場合は、gitがコミットできるよう、リポジトリ自体のフォルダにも書き込めます。パッケージマネージャーのキャッシュは一時フォルダに移ります。サンドボックスの仕組みは、お使いのコンピューターによって異なります。

- **Linux**：bubblewrapを使います。コマンドが変更できるのは、セッションのフォルダ、一時フォルダ（`/tmp`）、リポジトリ自体のフォルダ内のファイルです。
- **Mac**：macOSに付属のサンドボックスであるSeatbeltを使います。ルールは同じで、セッションのフォルダ、一時フォルダ、リポジトリ自体のフォルダです。
- **Windows**：コマンドは低整合性レベルで実行されます。これはWindowsの保護機能で、すべてを読み取れますが、ファイルを変更できるのは許可の印が付いたフォルダだけです。初回に、Hydorがセッションのフォルダ（とリポジトリ自体のフォルダ）に印を付け、その印は残ります。コマンドには専用の一時フォルダが `AppData\LocalLow\Hydor` に用意され、一時ファイルとパッケージのキャッシュに使われます。ホームフォルダ、ドライブ全体、Windows、Program Files、アプリデータのフォルダには印を付けません。このようなフォルダでは、コマンドはサンドボックスなしで実行されます。Gitのbashは、低整合性レベルでは通常のbashウィンドウと内部の動作を共有できないため、初回にHydorはサンドボックス内のコマンド用にGitのプログラムのコピーも `AppData\Local\Hydor\sandbox` に作ります（同じファイルへのリンクで作られるため、Gitが同じドライブにある場合は容量を取りません）。

コマンドがサンドボックスの制限に当たると、Customにはサンドボックス内で実行されたことが伝えられます。Customはその範囲内で作業を進めるか、別の場所で必要な操作をユーザーに伝えます。

オン・オフを切り替えるには、[設定 → 機能 → Custom](/settings?s=custom&find=Sandbox%20for%20commands)を開き、**コマンド用サンドボックス**のスイッチを使います。初期設定ではオンです。システム全体にインストールするなど、ツールがほかの場所に書き込む必要がある場合は、オフにします。変更は、実行中のセッションにおよそ15秒以内に反映されます。

サンドボックスを実行できない場合は、スイッチがグレーアウトされ、その行に理由が表示されます。その場合、コマンドはサンドボックスなしで実行されます。Linuxでは、bubblewrapがインストールされていないか、実行できない（一部のコンテナなど）ということです。Macでは、Seatbeltを起動できなかったということです。Windowsでは、初回にHydorがWindowsに付属の.NET Frameworkで小さなヘルパーを作り、さらにGit for Windows（コマンドの実行にはいずれにしても必要です）も必要です。どちらかが不足している場合やヘルパーを起動できない場合は、その行に表示されます。確認モードと編集を承認モードでは、コマンドはサンドボックスを使いません。この2つのモードでは、見て回る以上のことをするコマンドはすべて、ユーザーのOKか、**常に許可**で保存したルールを待ちます。

[機密セッション](/guide/sessions#keep-a-session-confidential)では、すべてのコマンドが、どのモードでも、このスイッチの設定にかかわらず、ネットワークなしで実行されます。そのため、インターネットにも、ほかのコンピューターにも、このコンピューターのサーバーにも接続できません。ファイルについては、モードごとの扱いのままです。これはLinux（bubblewrap）とMac（Seatbelt）で動作します。Windowsではこの方法でネットワークを遮断できないため、Windowsと、サンドボックスを実行できないすべての環境では、どのモードでも、コマンドごとに事前に確認が入り、**常に許可**はありません。Customにはその旨が伝えられ、ネットワークに接続しようとしたコマンドには失敗した理由が通知されます。

## Customにゴールを与える

Customも、ほかのすべてのエージェントと同じゴールを使えます。アプリ独自のループがラウンドを繰り返しながらCustomを動かし、ユーザーが合意したチェックがすべて満たされるまで続けます。セッションのメニュー（⋯）→ **ゴールを設定**を開くか、スタートページで**オプション** → **ゴール**をオンにすると、エージェントが合意用のチェックを提案します。各ラウンドで、アプリがチェックを自分で実行し、そのラウンドを採用するか（ワークツリーでは）元に戻し、転換点ではどちらに進むかをユーザーに尋ね、すべてのチェックが満たされたとき、ユーザーが止めたとき、または上限に達したときに停止します。画面を交えた詳しい説明は、[ゴール](/guide/goals)にあります。

現在はどのエージェントでも共通のものは、合意カード、チェック、ラウンド一覧、質問、ユーザーのルールと**ユーザーの判断**、そしてレポートです。Customのセッションで `/goal` と入力しても、特別なことは起こらなくなりました。ただのテキストです。Customに関することは2つあります。

- **レビュアー**のチェックと最終チェックは、作業に関わっていないモデルが判定します。[機密セッション](/guide/sessions#keep-a-session-confidential)では、このコンピューター上のモデルが判定します。それがない場合、チェックは実行できません。
- チェックのコマンドは、Custom自身のコマンドと同じ方法で実行されます。自動モードで**コマンド用サンドボックス**がオンの場合は、サンドボックス内でセッションのフォルダに限定されます。ほかのモードでは、Custom自身のコマンドと同様に実行されます。機密セッションでは、常にネットワークなしでサンドボックス内で実行されます。
- 新しいゴールに与えられるラウンド数は、[設定 → 機能 → ゴール](/settings?s=goals)の**ゴールを実行できるラウンド数**で決まります。この設定は、Customだけでなく、すべてのエージェントのゴールに適用されます。

このバージョンより前にCustomで実行中だったゴールは引き継がれません。新しく設定してください。

新しいゴールのラウンド数を変更するには、[設定 → 機能 → ゴール](/settings?s=goals&find=Rounds%20a%20goal%20may%20run)を開き、**ゴールを実行できるラウンド数**の行で**10**、**30**、**100**から選びます。ほかの数は合意カードで設定でき、エージェントが提案することもあります。

## 長い会話と長い出力

どのモデルも、一度に読める量には限りがあります（コンテキスト）。Customは会話をその範囲内に自動で収めるため、Customのセッションには圧縮ボタンがありません。

1. 会話が上限に近づくと（返信のための余裕を残して）、Customはまず古いツールの出力を消去します。セッションには「Cleared old tool output to keep within the model's context.」と記録されます。
2. それでも足りない場合は、モデルが前半部分をメモに要約し、作業はそのメモから続きます（「Summarizing the earlier conversation to keep within the model's context…」）。次回からは、最初からやり直さずにそのメモを更新します。プランと使用中のスキルは、どちらの場合も保持されます。

モデルのサーバーが会話が長すぎると応答した場合、Customはそのモデルの実際の上限を把握し、すぐに圧縮します。各リクエストに付くのは、最新の数枚の画像だけです。

開始時にメモリがCustomに渡した内容は、作業中は変わりません。そのため、モデルのサーバーは会話について保持している内容を再利用でき、高速で費用も抑えられます。圧縮するたびに、ユーザーの最新のメッセージに合わせてメモリを読み直します（[エージェントが最初に受け取るもの](/guide/memory#what-an-agent-starts-with)を参照）。

メッセージ欄の横にあるリングは、モデルのコンテキストがどれだけ埋まっているかをパーセントで示します。ポインターを合わせると、トークン数とその内訳が表示されます。**オプション**（メッセージ欄の下のチップ）の下にある**コンテキスト**の行には「42% in use」と表示され、小さな矢印があります。クリックすると内訳の表示と非表示を切り替えられ、初期状態では折りたたまれています。内訳は、**指示**、**プロジェクトの指示**、**メモリ**、**アプリの機能**、**スキル**、**ツール**、**会話**で、それぞれのトークン数と、割合を示す細いバーが表示されます。中身のない項目は表示されません。数値はテキストからの推定値で、モデルのサーバーが数えた値に合わせて調整されています。Customは自動で圧縮するため、Customのセッションではリングをクリックしても何も起こりません。Claude CodeとCodexのセッションでは、リングと**圧縮**が引き続き使えます（[メーターの見方](/guide/sessions#read-the-meters-context-cache-and-speed)を参照）。

長い出力で会話がいっぱいになることもありません。コマンド、ページ、ツールがモデルのコンテキストの一定割合を超える内容を返すと、Customはその全体をセッション専用のフォルダ内のファイルに保存します。モデルには、先頭と末尾（コマンドの場合は、エラーが現れる末尾が中心）とファイルの場所が渡され、残りは分けて読むか、検索して調べます。これらのファイルは1週間後に削除されます。

## モデルが読むもの

ユーザーのメッセージの前に、モデルには次の内容がこの順番で渡されます。

- Custom自身のルール（作業の進め方、モード、フォルダ）、エージェントの指示、エージェントガイドライン：内訳の**指示**
- プロジェクトの指示、つまり `AGENTS.md` または `CLAUDE.md`：**プロジェクトの指示**
- [メモリ](/guide/memory#what-an-agent-starts-with)がユーザーの依頼に対して持っている内容：**メモリ**
- アプリの機能についての説明：返信の見え方、キーやパスワードをチャットに出さないこと、後片付け、完全な形で持っているツール（画像、アプリ、ブラウザ、ドキュメントなど）の使い方：**アプリの機能**
- スキル（**スキル**）：グループ別に並び、プロジェクト独自のもの、ユーザーのもの、続いてコーディングやドキュメントなどライブラリのグループの順です。Customは名前を指定して読み込むことも、作業内容から探すこともできます。Customが取り込めるスキルは最大200件で、プロジェクトとユーザーのものは合わせて最大40件です。最初のメッセージに合うスキルは、それぞれの用途とともに渡されます。
- ツール：完全な形で持っているものと、残りの短い一覧：**ツール**

機能が自分のツールについて持つ指示は、そのツールと一緒に渡されます。ツールがCustomの短いツール一覧にある間は、その指示も待機し、モデルがそのツールを調べるか使うときに追加されます。どのツールを使っていても常に必要なルールは、いつも保持されます。Claude CodeとCodexには、従来どおり、アプリのすべての指示が最初に渡されます。

そのため、コンテキストの小さいモデルへの最初のメッセージは、以前より短くなっています。各部分が使う量は**オプション**の下の内訳で確認できます。[長い会話と長い出力](#long-conversations-and-long-output)を参照してください。

**メモリはモデルのコンテキストに合わせた大きさになります。** コンテキストの小さいモデルでは、メモリが一定量を占めると作業ができなくなります。そのため、メモリの割合はウィンドウに合わせて小さくなります（内訳の**メモリ**の行に使用量が表示されます）。

- **12,000トークン未満**：小さなブロックで、コンテキストの6%まで。プロフィールの最初の120語（最初の部分だけであることが示されます）、メモは最大3件、索引はありません。メッセージに付く内容や、モデルがファイルを読んだり変更したりするときの内容はメモリから追加されず、Wiki記事の行やプランも渡されません。モデルには、メモリツールでメモを検索できることが伝えられます。
- **約33,000トークンまで**（OpenRouter経由を除く）：コンテキストの6%までのブロックで、プロフィールの最初の400語、メモは最大5件、短い索引、Wiki記事の行を1つ、プランの行を1つ含みます。メッセージに付くメモは最大1件（600文字）、ファイルを読んだり変更したりするときのメモは1件（350文字）です。
- **より大きなモデル**：[メモリがエージェントに渡す](/guide/memory#what-an-agent-starts-with)内容のすべてで、コンテキストに占める割合は小さなものです。

目安として、メモリのブロックは、8,000トークンのモデルで約1,700文字、32,000トークンで3,800文字、200,000トークンで7,300文字になります。プロフィールの最初の部分だけを渡されたセッションでは、プロフィールを書き換えられません。モデルが追加すべき内容を伝えるか、[設定 → メモリ](/settings?s=memory&find=Your%20profile)で編集します。Wikiの指示も短縮されます。CustomにはWikiメモリについての短い段落が常に1つ渡され、ソースの保管、Wikiの確認、プランの採用の方法は、そのためのツールが提供されている間だけ渡されます。Customが会話を圧縮したあとは、セッションのチェックポイント（[チェックポイント](/guide/wiki-memory#checkpoints)を参照）が、コンテキストの8%、最大16,000文字に切り詰められ、残りを読める場所が付きます。

## Customが弱いモデルに対処する方法

どのモデルも、ClaudeやGPTほどツールの扱いに慣れているわけではありません。Customはよくあるミスを検知し、モデルを軌道に戻します。

- **繰り返し**：あれ以来何も変わっていない同じステップは、3回目は実行されません（モデルには前の結果を使うよう伝えられます）。5回目でターンが停止します。
- **失敗するステップ**：ステップが4回連続で失敗すると、モデルは立ち止まって考え直すよう指示されます。8回連続でターンが停止します。
- **堂々巡り**：ループして回り続けるステップには、別の方法を試すようメモが付きます。
- **未完了の作業**：「やってみます…」と言うだけで実行しないモデルや、プランの項目が残ったまま止まるモデルは、それぞれ1回ずつ作業に戻されます。コードを変更したのにプロジェクトのチェックを実行していない場合は、終了する前に実行するよう求められます。
- **長さ**：1ターンは最大200ステップで、150ステップに達するとモデルは最も重要な部分を仕上げるよう指示されます。モデルの長さの上限で途切れた返信は、より短いステップで続けられます。
- **壊れたツール呼び出し**：テキストとして書かれた呼び出しは読み取って実行され、引数がほぼ正しい呼び出しは修復され、綴りを間違えたツール名は正しい名前に照合されるか、ツールの一覧が返されます。呼び出しをテキストで書く返信は、呼び出しの終わりで終了します。その後にモデルが書いた内容（想像した結果、その上にさらに重ねた呼び出し、同じ呼び出しの繰り返し）は、実行も保持もされません。1回の返信から実行される呼び出しは最大6件です。
- **ツール呼び出しのないモデル**：モデルのサーバーがツールを受け付けない場合、Customは指示の中でツールを説明し、モデルが書いた内容から呼び出しを読み取ります。
- **Claude Code経由のClaude**：Anthropicはプランのサインインを自社のプログラムにのみ使わせています。そのため、ユーザーのプランのClaudeモデルは、Claude Code自体を通して1ステップずつ応答します。Customのツールは指示の中で説明され、Claudeはツール呼び出しをテキストとして書きます（ツール呼び出しのないモデルと同じです）。各ステップは直前のステップのキャッシュを再利用します。Claude Codeはツール呼び出しで返信を終えることができないため、Customがそこで返信を終了し、Claudeが想像した結果を書く前にプログラムを停止します。Codexのモデルは異なり、ユーザーのChatGPTプランに直接問い合わせ、Customのツールを本物のツールとして使います。
- **一時的な不具合**：返信の途中で接続が切れたりサーバーが混み合ったりすると、Customは待って数回やり直します。モデルを待つステップの最中にアプリが再起動した場合（アップデートなど）は、アプリが戻った時点でそのステップがもう一度依頼されます。再起動のために終了したターンにはその旨が表示され、メッセージを送れば続行できます。
- **多数のツール**：ツールが多い場合（MCPサーバーや接続から）、モデルには短い一覧が表示され、必要なツールの完全な説明を調べます。機能のツールについての指示は、モデルがそのツールを調べるか使うときに一緒に渡されます（[モデルが読むもの](#what-the-model-reads)を参照）。コンテキストの短いモデル（約32,000トークン以下、OpenRouter経由を除く）には、より絞ったセットが渡されます。回答UIの案内はなく、ツールは名前だけの一覧になり、完全な形のツールも少なくなります（HTMLのページを表示するツールも一覧で待機します）。また、小さなステップで進めるよう求められます。
- **モデルの系列ごと**に、作成元の推奨設定、学習時の編集形式、思考レベルがあるものにはその思考レベルが適用されます。読み取るだけのステップは、待ち時間を減らすため同時に実行されます。

これらの理由のいずれかでCustomがターンを停止すると、返信は「(Stopped: …)」で終わります。

## 見えないモデル向けの画像

画像を認識できるモデルには、画像がそのまま渡されます。エンドポイントのモデルは、エンドポイント側で画像を認識できると示されているか、その[行](/guide/agents-models#other-openai-compatible-endpoints)で **画像対応** を **はい** に設定しない限り、画像を認識できないモデルとして扱われます。このコンピューターにffmpegまたはImageMagickがある場合は、画像はあらかじめ小さく変換されます。

画像を認識できないモデルの場合は、補助モデルが各画像を言葉で説明します。何が写っているか、どこに何があるか、画像内の文字はそのまま書き写されます。そのためには、画像を認識できる補助モデルが必要です。[設定 → エージェント → モデル](/settings?s=models&find=Helper%20model)を開き、**補助モデル**グループの**モデル**メニューで「画像を認識」と表示されているものを選びます。「自動」は使えません。設定がない場合、Customはモデルに、見えない画像があることを伝えます。機密セッションでは、このコンピューター上の補助モデルだけが画像を説明します（契約プランのモデルは使われません）。

## フォークとここから編集

Customのセッションも、Claude CodeやCodexのセッションと同じようにフォークできます。セッションのメニュー（⋯）→ **フォーク**を選びます。また、以前に送ったメッセージは**ここから編集**で変更できます。そのメッセージの直前までの会話が複製されて続きが始まり、元のセッションはアーカイブされます。**このメッセージの前の状態にファイルを戻す**にチェックを入れると、それ以降のファイルの変更を取り消せます。Customの場合、対象はCustom自身の編集で変わったファイルで、コマンドによる変更はそのまま残ります。

Customは各会話をディスクに保存するため、アプリを再起動しても続きから再開できます。

## Customの費用

- OpenRouter経由のモデル：OpenRouterが各呼び出しの費用を報告し、セッションの支出にはその金額が使われます。ここでのClaudeモデルには、他のモデルが自動で行うのと同様に、会話をキャッシュに保持するよう依頼します。そのため各ステップでは約10分の1の料金で読み戻されます。また、Customに提供されるツールは1セッションにつき多くても1回しか変わらないので（バックグラウンドで動くコマンド用のツールは、一度実行されると残ります）、キャッシュが維持されます。
- ClaudeまたはChatGPTのプランのモデル（**契約中のサブスクリプション**にあるもの）：トークンごとの料金ではなくプランの使用量が消費されるため、これらのステップではセッションに$0と表示されます。使用量の上限に達した、またはサインアウトしているアカウントがあると、そのステップは同じプログラムの次のアカウントに引き継がれます（**上限時にアカウントを切り替え**がオンの場合）。
- このコンピューター上のモデル（Ollama、vLLM）：無料です。
- その他のエンドポイント：トークンは他のエージェントと同じように料金が計算されます（[使用量、上限、費用](/guide/usage)を参照）。

セッションでは、支出上限がなくても、メッセージ欄の上にAPI費用と入力・キャッシュ・出力のトークンが表示されます。料金はOpenRouterのレスポンスから取得され、ストリーミングで料金が届かない場合はその生成記録から取得されます。それも使えない場合は、OpenRouter自身のカタログ価格が使われます。モデルの価格を手動で入力する必要はありません。

[支出上限](/guide/usage#cap-what-a-session-spends)はCustomのセッションでも使えます。

## 設定 → 機能 → Custom

[設定 → 機能 → Custom](/settings?s=custom)（「自動モードとコマンド用サンドボックス」）には2つの項目があります。

- **自動モード**（Customのモードの1つで、確認、編集を承認、フルアクセス、プランと並びます）：(i)で、自動モードが許可する操作、常に確認する操作、そして補助モデルがチェックを行うことが説明されています。切り替える設定はなく、自動モードはセッションごとに**権限**で選びます。
- **コマンド用サンドボックス**（自動モードでは、コマンドがファイルを変更できるのは、セッションのフォルダと、Linuxでは/tmp、Macでは一時フォルダ、Windowsではコマンド専用の一時フォルダだけです。フルアクセスでは、このサンドボックスも承認の確認もなしで実行されます）：スイッチで、初期設定ではオンです。ここでサンドボックスを実行できない場合（Linuxはbubblewrap、MacはSeatbelt、WindowsはGit for Windowsと.NET Framework）はグレーアウトされ、その理由が項目に表示されます。

Customのモデルは[設定 → エージェント → モデル](/settings?s=models)にあり、チェックを行うモデルはそこの**補助モデル**です。

## エージェントに頼んでみる

- 「CustomのAutoモードのコマンドで、サンドボックスをオフにして。」
- 「新しいゴールには最大100ラウンドを与えて。」
- 「Customのセッション『アップロードページ』にゴールを設定して。npm testが通ること、2GBのアップロードが動くこと。行き詰まったときだけ質問して。」
- 「Autoモードはどの補助モデルを使っていて、画像は認識できる？」
- 「このコンピューターは、機密セッションのコマンドをネットワークなしで実行できる？」
- 「OpenRouterのQwen3 Coderを追加して、Customで使えるようにして。」（OpenRouterのキーを設定済みの場合）
- 「モデルの価格を入力せずに、OpenRouterの使用量と費用を表示して。」
- 「ローカルモデルだと、Customへの最初のメッセージが長くなるのはなぜ？」
- 「Customのセッションのコンテキストはどのくらい埋まっていて、何が一番多くを占めている？」
- 「OpenRouterではなく、Claudeプランのソネットでこのセッションを実行して。」
- 「Customで最高にあたるモデルはどれ？ Customのセッションは自動で始められる？」
