# Custom、アプリ独自のエージェント

Customは、Hydor独自のエージェントです。ClaudeとChatGPTのプランのモデルに加え、OpenRouter、Ollama、vLLM、その他のOpenAI互換サーバーから追加したモデルも実行でき、Claude CodeやCodexと同じツール、スキル、接続を使えます。このトピックでは、Customでできること、権限モードとコマンドの確認方法、自動モード、コマンド用のサンドボックス、ゴール、長い作業や性能の低いモデルへの対応、そして設定について説明します。

![設定 → モデル：補助モデルと、このコンピューター上のモデル](images/custom.webp)

## Customとは、どんなときに使うか

Claude CodeはAnthropicのモデルだけ、CodexはOpenAIのモデルだけを実行します。Customは、このコンピューター上のClaude CodeとCodexのサインインを通じて、ClaudeとChatGPTのプランのモデルも実行できます。さらに、[設定 → エージェント → モデル](/settings?s=models)で設定したモデルも使えます。自分のコンピューター上のオープンモデル、OpenRouter経由の安価または無料のモデル、独自のサーバーなどです。プランのモデルには設定は不要です。Claude Codeにサインインすると、Customの**モデル**メニューにClaude Opus、Fable、Sonnet、Haikuが表示されます。CodexにChatGPTでサインインすると、ChatGPTプランに含まれるモデルが表示されます。これらはすべて**契約中のサブスクリプション**の下に並びます。APIキーではなく、プランの使用量が消費されます。Customのモデルの入手元や追加方法については、[エージェント、アカウント、モデル](/guide/agents-models#where-customs-models-come-from)をご覧ください。

次のような場合にCustomを使います。

- 自分のコンピューターの外に出ないモデル（OllamaやvLLM）を使いたい場合、またはセッション全体を外に出したくない場合。[機密セッション](/guide/sessions#keep-a-session-confidential)は常にCustomで実行され、このコンピューターまたは自分のネットワーク上のモデルだけを使います（AnthropicやOpenAIのサーバーで動くプランのモデルは使いません）。
- DeepSeek、Qwen、GLM、Kimiなど、特定のモデルを使いたい場合。
- ClaudeやChatGPTのプランのモデルでCustom独自のツールとルールを使いたい場合、費用を抑えたい場合、またはClaudeやChatGPTのプランを使い切ったときに（別のモデルで）作業を続けたい場合。

調査、執筆、ドキュメント、日常のタスクなど、何にでも役立ちます。コードプロジェクト（`package.json`、`Cargo.toml`、Gitリポジトリなどがあるフォルダ）では、慎重なエンジニアのように動きます。変更する前に読み、プロジェクト独自の指示に従い、完了を伝える前にプロジェクトのテストとチェックを実行します。

Customは、他のエージェントと同じように、プロジェクトの`AGENTS.md`や`CLAUDE.md`を読み、[エージェントガイドライン](/guide/guidelines)に従います。

## Customのセッションを始める

1. スタートページで**エージェント**をクリックし、**Custom**（「どのモデルでも：OpenRouter、Ollama、vLLM」）を選びます。
2. **モデル**をクリックして、モデルを選びます。一覧が空の場合は、先にモデルを追加します。**エージェント** → **Custom用モデル**から追加できます。
3. **オプション**の**権限**を選びます（[Customが確認なしでできることを選ぶ](#choose-what-custom-may-do-without-asking)を参照）。Customには思考レベルの設定はありません。
4. タスクを入力して、Enterを押します。

vLLMで提供されるこのコンピューター上のモデルは、セッションが初めて使うときに起動します。セッションには「vLLMで…を起動しています（初回は1～2分かかります）…」と表示されます。

Customは一度に1件のメッセージを処理します。作業中に送ったメッセージは、メッセージ欄の上にあるキューで待機し、ターンの終了後に送信されます。

セッション中でも、メッセージ欄の下にあるメニューからモデルを切り替えられます。Customは、ターンの途中でも、次のステップから新しいモデルを使います。

## Customでできること

- **ファイル**：読み取り（行番号付きのテキスト、長いファイルを一部ずつ、フォルダの内容）、作成、書き換え、編集、フォルダの一覧表示、名前や内容によるファイルの検索ができます。このセッションでまだ読んでいないファイルを丸ごと書き換える前には、先に読むよう求められます。
- **ドキュメント**：PDF、Word、Excel、PowerPoint、OpenDocument、RTF、EPUBのファイルをテキストとして読み取ります。
- **画像**：添付した画像、開いた画像ファイル、Webページやツールからの画像を扱います。画像を認識できるモデルには画像がそのまま渡されます。認識できないモデルには、補助モデルが内容を説明します（[画像を認識できないモデル向けの画像](#images-for-models-that-dont-see)を参照）。
- **コマンド**：セッションのフォルダでシェルコマンドを実行します。実行時間は既定で最大2分、上限は10分です。サーバー、ウォッチャー、その他実行し続けるコマンドはバックグラウンドで動きます。Customは必要なときにその出力を読み、停止することもできます。Customが終了したときにも停止し、次のターンでは、まだ動いているコマンドが伝えられます。
- **Webページ**：見出し、リンク、リスト、表を含む、整ったテキストとしてページを取得します。オンラインのPDFやOfficeファイルもテキストとして読み取ります。アクセスできるのは公開アドレスだけです。このコンピューターやそのネットワークには、`curl`などのコマンドを使います。
- **プラン**：複数のステップがある作業では、チェックリストを作ってセッションに表示し、項目にチェックを付けていきます。
- **スキル**：作業に合ったスキルを読み込みます。プロジェクトのスキル、自分のスキル（Claude CodeとCodexのスキルフォルダ）、アプリの[スキルライブラリ](/guide/skills)が対象です。スキルはグループと名前で把握しており、作業内容を表す短い言葉で探すこともできます。
- **MCPサーバー**：Claude Code用に設定したツールサーバー（すべてのフォルダ用とこのフォルダ用）、プロジェクトの`.mcp.json`、Codexのものが使えます。
- **アプリ独自のツール**：Web検索、ブラウザ、メモリ、ページ、[接続](/guide/connections)など、ここにあるすべてのエージェントが使えるものです。

各ステップは、わかりやすい名前（「index.tsを読み取り」「README.mdを編集」「https://…を取得」など）でセッションに表示され、差分や出力はクリックで確認できます。

## Customが確認なしでできることを選ぶ

**権限**の設定（スタートページの**オプション**、またはセッションのメッセージ欄の下にあるメニュー）で、Customが自分の判断でできることが決まります。メッセージ欄でShift+Tabを押すと、次のモードに切り替わります。

- **質問**（既定）：ファイルを編集する前とコマンドを実行する前に確認します。見るだけのコマンド（`ls`、`cat`、`git status`など）は、確認なしで実行されます。
- **編集を承認**：セッションのフォルダ内のファイルは確認なしで編集します。コマンドの実行前（見るだけのものを除く）と、フォルダ外に対する操作の前には確認します。
- **自動**：定型の作業はそのまま進み、リスクのあるものについては簡易チェックで確認します。[自動モード](#auto-mode)を参照してください。
- **フルアクセス**：ツールとコマンドが、承認の確認もコマンドの[サンドボックス](#the-sandbox-for-commands)もなしで実行されます。管理者権限のコマンドやフォルダ外の変更も含みます。コンピューターのアカウントの権限で動くため、アカウントにない管理者権限が与えられるわけではありません。機密セッションでは、ネットワークの制限は引き続き適用されます。
- **プラン**：読み取りと計画だけを行います。Customはファイルを編集することもコマンドを実行することもできず、読み取り用のツールだけを使います。最後に番号付きの計画を示します。実行するには、別のモードに切り替えて、進めるよう伝えます。

フルアクセス以外では、常に確認するコマンドがあります。[常に確認するコマンド](#commands-that-always-ask)を参照してください。

## Customの操作を承認または拒否する

Customが確認を必要とするとき、セッション（と[受信トレイ](/guide/inbox)）にカードが表示されます。タイトルには、そのステップが何をするのか、なぜ確認するのかが示されます。たとえば「/home/you/notes/plan.mdを編集 — セッションのフォルダ外のファイルを変更します」のようになります。コマンドの場合は、カードにコマンド全体が表示されます。

- **許可**：この1回のステップだけを実行します。
- **常に許可 …**：実行し、このセッションでは今後、同様のステップも確認なしで実行します。ボタンには対象が表示されます。「npm run buildを常に許可 …」「すべての編集を許可」「~/dataの読み取りを常に許可」「~/siteの変更を常に許可」などです。
- **却下**：このステップを止めます。Customには、拒否されたこと、再試行しないことが伝わります。

コマンドでの**常に許可**の仕組み：Customはコマンドを`&&`、`;`、`|`などの区切りで部分に分け、それぞれを確認します。ルールは、最初の語（`git status`、`npm run build`、`docker compose up`）によって、作成の元になったコマンドだけを対象にします。そのため、`&&`の後ろに別のコマンドを紛れ込ませることはできません。見るだけのコマンドには、ルールは不要です。

安全にできない場合、**常に許可**は表示されません。

- コマンド内に直接書かれたコード（`python -c "…"`など）
- 事前に名前がわからないファイル
- 確実に読み取れないコマンド
- リスクのあるコマンド（毎回確認します）

## 常に確認するコマンド

フルアクセス以外では、次のステップは、自動を含め、以前に許可したかどうかにかかわらず、毎回確認します。

- 管理者としての実行（`sudo`など）
- セッションのフォルダ外のファイルの削除、セッションのフォルダ自体の削除、事前に名前がわからないファイルの削除
- ダウンロードしたものをそのままシェルに渡す、またはダウンロードしたものをすぐに実行する
- ディスクへの生データの書き込み、ディスクのフォーマットやパーティションの再設定
- コンピューターのシャットダウンや再起動
- スケジュールされたジョブ（`crontab`）の変更
- フォルダツリー全体の権限や所有者の変更
- SSHキーの変更、またはホームフォルダ内の設定や起動ファイル（`.bashrc`や`~/.config`など）の変更（セッションがそのフォルダで作業している場合を除く）

## フォルダ外のファイルとキーを含むファイル

質問、編集を承認、プランでは、Customはセッションのフォルダ外のファイルを読み取る前や変更する前に確認します（一時フォルダは対象外です）。このとき**常に許可**は、そのフォルダを、読み取りまたは変更について対象にします。

キーやパスワードを含むファイルは、フォルダ内であっても、読み取りや変更の前に確認します。`.env`ファイル（サンプルを除く）、SSHなどの秘密鍵、`.netrc`、`.npmrc`、認証情報ファイル、クラウドやパスワードストアのフォルダ、エージェント自身のサインイン、アプリ自身のデータが対象です。Git自体の設定やフックの変更も確認します。このとき**常に許可**は、そのファイルだけを対象にします。

自動モードでは、これらについては自動のルールと簡易チェックが判断します。フルアクセスでは確認しません。

## 自動モード

自動モードでは、定型の作業は中断せずに進み、それ以外は確認します。**権限**で**自動**を選びます。

確認が必要になるステップは、次の順にチェックされます。

1. モデルを使わない**固定ルール**：
   - そのまま進める：セッションのフォルダ内の編集、一時フォルダへの新しい作業用ファイルの作成、フォルダ内を読み取るだけのコマンド、プロジェクト自身のテスト、ビルド、リンター、型チェック。
   - 確認する：フォルダ外のファイルの上書き、[常に確認するリストー](#commands-that-always-ask)にあるすべてのもの、Gitでの強制プッシュ、フォルダ外のファイルの書き込み、移動、削除、決済サービスを呼び出すコマンド、送信や投稿、支払いを行う接続済みアカウントやMCPサーバーのツール。
2. それ以外はすべて、[補助モデル](/guide/agents-models#choose-the-helper-model)による**簡易チェック**。次の3通りのいずれかで答えます。
   - **許可**：依頼した内容に明らかに沿っていて、フォルダ内にとどまり（または読み取るだけで）、簡単に元に戻せる。
   - **質問**：長く残る害を及ぼす可能性があるか、影響範囲が広い（データの削除、システム全体へのソフトウェアのインストール、設定の変更、パスワードやキーの使用、送信や公開、支払い、依頼していないこと）。
   - **拒否**：明らかに有害であるか、意図に反する。ステップは実行されず、Customには理由が伝えられ、別の方法を探す必要があります。

簡易チェックが見るのは、セッション内の自分のメッセージ（最初の1件と直近の10件）、設定していればゴール、フォルダ、そしてステップ自体（編集の場合は、新しいテキストの冒頭）だけです。Customが読んだ内容は一切見ないため、Webページやファイルによって誘導されることはありません。チェックが失敗した場合や45秒以上かかった場合は、自分で判断します。同じターン内では、同じステップには同じ答えが返ります。[機密セッション](/guide/sessions#keep-a-session-confidential)では、チェックはこのコンピューター上にとどまります。補助モデルがここで動く場合はそれが、そうでない場合はセッション自身のモデルが行います。

セッションでは、自動が通したステップに小さな**自動**ラベルが付きます。ポインターを重ねると、理由が表示されます。自動が止めたステップでは、ラベルが赤で表示され、ポインターを重ねると「自動がこれを止めました：…」と理由が表示されます。自動から送られてくるカードは、「自動：」と理由で始まります。

[設定 → 機能 → Custom](/settings?s=custom&find=Auto%20mode)には**自動モード**の行があり、その（i）には自動モードについて同じ言葉で説明されています。ここで切り替えるものはありません。

## コマンド用サンドボックス

Customは自動モードで、コマンドをサンドボックス内で実行できます。サンドボックス内のコマンドが変更できるのは、セッションのフォルダと一時フォルダにあるファイルだけで、コンピューター上のそれ以外は読み取り専用です。ネットワークは引き続き使えます。セッションがGitのワークツリーやリポジトリのサブフォルダで作業している場合は、Gitがコミットできるように、リポジトリ自体のフォルダにも書き込めます。パッケージマネージャーのキャッシュは一時フォルダに移ります。サンドボックスの仕組みは、お使いのコンピューターによって異なります。

- **Linux**：bubblewrapを使います。コマンドが変更できるのは、セッションのフォルダ、一時フォルダ（`/tmp`）、リポジトリ自体のフォルダにあるファイルです。
- **Mac**：macOSに付属のサンドボックスであるSeatbeltを使います。ルールは同じで、セッションのフォルダ、一時フォルダ、リポジトリ自体のフォルダが対象です。
- **Windows**：コマンドは、Windowsの保護機能である低整合性レベルで実行されます。すべてを読み取れますが、変更できるのは、目印を付けたフォルダにあるファイルだけです。初回に、Hydorがセッションのフォルダ（とリポジトリ自体のフォルダ）に目印を付け、その目印は残ります。コマンドには専用の一時フォルダが`AppData\LocalLow\Hydor`に用意され、一時ファイルとパッケージのキャッシュに使われます。ホームフォルダ、ドライブ全体、Windows、Program Files、アプリデータのフォルダには目印が付かないため、こうしたフォルダではコマンドはサンドボックスなしで実行されます。Gitのbashは、低整合性レベルでは通常のbashウィンドウと動作に必要なデータを共有できないため、初回にHydorがサンドボックス内のコマンド用にGitのプログラムのコピーを`AppData\Local\Hydor\sandbox`に作ります（同じファイルへのリンクで構成されるので、Gitが同じドライブにある場合は容量を取りません）。

コマンドがサンドボックスの制限に当たると、サンドボックス内で実行されたことがCustomに伝わります。Customは、その範囲内で作業を進めるか、ほかの場所で必要な操作をお知らせします。

オンとオフを切り替えるには、[設定 → 機能 → Custom](/settings?s=custom&find=Sandbox%20for%20commands)を開き、**コマンド用サンドボックス**のスイッチを使います。初期設定ではオンです。システム全体にソフトウェアをインストールするときなど、ツールがほかの場所に書き込む必要がある場合は、オフにしてください。変更は、実行中のセッションに約15秒以内に反映されます。

サンドボックスを実行できない場合は、スイッチがグレー表示になり、その行に理由が表示されます。その間、コマンドはサンドボックスなしで実行されます。Linuxでは、bubblewrapがインストールされていないか、実行できない（一部のコンテナなど）ことを意味します。Macでは、Seatbeltを起動できなかったことを意味します。Windowsでは、初回にHydorがWindowsに付属の.NET Frameworkで小さなヘルパーを作成し、さらにGit for Windows（コマンドの実行にはもともと必要です）も必要です。どちらかが見つからない場合や、ヘルパーを起動できない場合は、その行に表示されます。確認モードと編集を承認モードでは、コマンドはサンドボックスを使いません。その場合、確認するだけにとどまらない操作を行うコマンドはすべて、承認を待つか、**常に許可**で保存したルールに従います。

[機密セッション](/guide/sessions#keep-a-session-confidential)では、どのモードでも、このスイッチの設定にかかわらず、すべてのコマンドがネットワークなしで実行されます。そのため、インターネットや、ほかのコンピューター、このコンピューターのサーバーには接続できません。ファイルの扱いは、モードの設定のままです。この機能はLinux（bubblewrap）とMac（Seatbelt）で動作します。Windowsではこの方法でネットワークを遮断できないため、Windowsと、サンドボックスを実行できない環境では、どのモードでも、コマンドごとに事前に確認が入ります。このとき**常に許可**は選べません。Customにはこのことが伝わり、ネットワークを使おうとしたコマンドには、失敗した理由が伝わります。

## Customにゴールを設定する

ゴールを設定すると、ある条件が満たされるまで、Customがターンを重ねて作業を続けます。たとえば「npm testが通り、アップロードページが2GBのファイルを扱える」といった条件です。

1. セッションのメニュー（⋯）→ **ゴールを設定**を開きます。
2. 「完了」がどのような状態かを、作業が終わったときに成り立つ条件として書きます。
3. **作業を開始**をクリックします（またはCtrl+Enter、Macでは⌘Enterを押します）。

Customはすぐに作業を始めます。ターンの実行中の場合は、そのターンが終わった時点でゴールが確認されます。

各ターンのあと、補助モデルが、作業の証拠（手順で行ったことと、その結果として示されたもの：コマンドの出力、テスト結果、ファイル、読み込んだページ）に照らしてゴールを確認します。Customが完了したと言っただけでは、完了とは見なされません。確認の結果は次のとおりです。

- **完了**：ゴールがクリアされ、「ゴール達成」という通知が届きます。
- **まだです**：確認の結果から次の手順が書かれ、次のメッセージとして送られます（「ゴール確認3：まだ達成していません…」）。
- **対応が必要**：ゴールに「行き詰まり：エージェントの対応が必要です」と質問が表示され、通知が届きます。セッションで答えてください。
- 外部の処理（デプロイやダウンロードなど）を**待機中**：3分後にもう一度確認します。

ユーザーご自身のメッセージが優先され、確認はキューが空になるまで待ちます。

次の場合は、ゴールが一時停止し、その理由が表示されます。

- **目標が一時停止するまでのラウンド数**で設定した数（変更しなければ30）だけ、次の手順を送った場合
- 3ラウンド続けて進展がなかった場合
- エージェントを停止した場合、ターンが失敗した場合、エージェントが実行中でなかった場合、または確認そのものが失敗した場合

メッセージ欄の上にあるゴールバーには、ゴール、現在の状況（「作業中」「一時停止中」「行き詰まり：エージェントの対応が必要です」）、確認した回数と経過時間、直近の確認の理由が表示されます。**一時停止**を押すと、それ以降は次の手順が送られなくなります（実行中のターンは最後まで進みます）。**再開**を押すと、最後の次の手順から続けます（ラウンドの回数は最初から数え直されます）。**クリア**を押すと、ゴールに向けた作業を終了します。ゴールの実行中は、ターンごとではなく、達成したときに一度だけ通知が届きます。

ゴールを実行できるラウンド数を変更するには、[設定 → 機能 → Custom](/settings?s=custom&find=Rounds%20before%20a%20goal%20pauses)を開き、**目標**グループの**目標が一時停止するまでのラウンド数**の行で、**10**、**30**、**100**のいずれかを選びます。

## 長い会話と長い出力

どのモデルも、一度に読める量には限りがあります（コンテキスト）。Customは、会話をその範囲内に自動で収めるため、Customのセッションには圧縮ボタンがありません。

1. 会話が上限に近づくと（返信のための余裕を残して）、Customはまず古いツールの出力を消去します。セッションには「モデルのコンテキストに収めるため、古いツールの出力を消去しました。」と記録されます。
2. それでも足りない場合は、モデルが前半部分をメモにまとめ、作業はそのメモを土台に続きます（「モデルのコンテキストに収めるため、前半の会話を要約しています…」）。次回からは、一からやり直すのではなく、そのメモを更新します。どちらの場合も、プランと使用中のスキルは保持されます。

モデルのサーバーが会話が長すぎると返してきた場合、Customはそのモデルの実際の上限を把握し、すぐに会話を圧縮します。各リクエストに付けられる画像は、直近の数枚だけです。

作業の開始時にメモリからCustomに渡された内容は、作業中は変わりません。そのため、モデルのサーバーは、保持している会話の内容を再利用でき、処理が速く、費用も抑えられます。会話を圧縮するたびに、最新のメッセージに合わせてメモリを読み直します（[エージェントが最初に受け取るもの](/guide/memory#what-an-agent-starts-with)を参照）。

メッセージ欄の横にあるリングは、モデルのコンテキストの使用率をパーセントで示します。ポイントすると、トークン数とその内訳が表示されます。**オプション**（メッセージ欄の下のチップ）の中の**コンテキスト**の行には「42%使用中」と表示され、小さな矢印があります。これをクリックすると、内訳の表示と非表示を切り替えられます（最初は折りたたまれています）。内訳は、**指示**、**プロジェクトの指示**、**メモリ**、**アプリの機能**、**スキル**、**ツール**、**会話**で、それぞれのトークン数と、割合を示す細いバーが付きます。中身のない項目は表示されません。数値はテキストから推定し、モデルのサーバーが数えた値に合わせて補正したものです。Customのセッションでは、Custom自身が会話を圧縮するため、リングをクリックしても何も起こりません。Claude CodeとCodexのセッションには、これまでどおりリングと**圧縮**があります（[メーターの見方](/guide/sessions#read-the-meters-context-cache-and-speed)を参照）。

長い出力で会話がいっぱいになることもありません。コマンド、ページ、ツールが、モデルのコンテキストの一定の割合を超える内容を返したときは、Customはその全体を、セッション専用のフォルダにあるファイルに保存します。モデルには、先頭と末尾（コマンドの場合は主に末尾で、エラーが出る部分です）と、ファイルの場所が渡されます。残りは、少しずつ読むか、検索して確認します。これらのファイルは1週間後に削除されます。

## モデルが読むもの

モデルには、ユーザーのメッセージより前に、次の内容がこの順番で渡されます。

- Custom自身のルール（作業の進め方、モード、フォルダ）、エージェントの指示、エージェントガイドライン：内訳の**指示**
- プロジェクトの指示（`AGENTS.md`または`CLAUDE.md`）：**プロジェクトの指示**
- 依頼に対して[メモリ](/guide/memory#what-an-agent-starts-with)が持っている内容：**メモリ**
- アプリの機能についての説明：返信の見え方、キーやパスワードをチャットに出さないこと、後片付け、使えるツールの使い方の詳細（画像、アプリ、ブラウザ、ドキュメントなど）：**アプリの機能**
- スキル（**スキル**）。グループ別に並び、プロジェクト固有のもの、ユーザー自身のもの、次にコーディングやドキュメントなど、ライブラリのグループのものの順です。Customは名前を指定して読み込むことも、作業の内容から探すこともできます。Customが扱えるスキルは最大200件で、そのうちプロジェクト固有のものとユーザー自身のものは合わせて最大40件です。最初のメッセージに合うスキルは、それぞれの用途の説明とともに渡されます。
- ツール。詳細を持つものと、残りの短い一覧：**ツール**

機能が自分のツールについて持つ指示は、そのツールとともに渡されます。ツールがCustomの短い一覧に載っている間は、その指示も待機しており、モデルがそのツールを調べたり使ったりしたときに追加されます。どのツールを使っていても適用されるルールは、常に保持されます。Claude CodeとCodexには、これまでどおり、アプリの指示のすべてが最初に渡されます。

そのため、コンテキストの小さいモデルへの最初のメッセージは、以前より短くなっています。各部分が使う量は、**オプション**の内訳で確認できます（[長い会話と長い出力](#long-conversations-and-long-output)を参照）。

**メモリの量は、モデルのコンテキストに合わせて調整されます。** コンテキストの小さいモデルでは、メモリが一定の量を使うと作業ができなくなってしまうため、メモリの割合はコンテキストの大きさに合わせて小さくなります（メモリが使う量は、内訳の**メモリ**の行で確認できます）。

- **12,000トークン未満**：コンテキストの最大6%の小さなブロックで、プロフィールの最初の120語（最初の部分だけであることが明記されます）、最大3件のメモが入り、インデックスはありません。メモリは、メッセージやモデルがファイルを読み取る・変更するときには何も追加せず、Wiki記事の行もプランも渡しません。メモリツールでメモを検索できることが、モデルに伝えられます。
- **約33,000トークンまで**（OpenRouter経由を除く）：コンテキストの最大6%のブロックで、プロフィールの最初の400語、最大5件のメモ、短いインデックス、Wiki記事の行1つ、プランの行1つが入ります。メッセージごとに付くメモは最大1件（600文字）、ファイルを読み取る・変更するときに付くメモは1件（350文字）です。
- **より大きなモデル**：[メモリがエージェントに渡す](/guide/memory#what-an-agent-starts-with)内容のすべてです。これはコンテキストのごく一部にすぎません。

目安として、メモリのブロックは、8,000トークンのモデルで約1,700文字、32,000トークンで3,800文字、200,000トークンで7,300文字になります。プロフィールの最初の部分だけを渡されたセッションでは、プロフィールを書き換えることはできません。モデルが追加すべき内容を知らせるか、[設定 → メモリ](/settings?s=memory&find=Your%20profile)で自分で編集します。Wikiの指示も短くなっています。Customには、Wikiメモリについての短い段落が常に渡され、ソースの保管方法、Wikiの確認方法、プランの採用方法は、それ用のツールが提供されている間だけ渡されます。Customが会話を圧縮したあとは、セッションのチェックポイント（[チェックポイント](/guide/wiki-memory#checkpoints)を参照）が、コンテキストの8%（最大16,000文字）に切り詰められ、残りを読む場所が添えられます。

## Customが弱めのモデルにどう対処するか

Claude や GPT ほどツールの扱いに慣れていないモデルもあります。Customはよくあるつまずきを見つけて、モデルを軌道に戻します。

- **繰り返し**：その後に何も変わっていない同じ手順は、3回目は実行されません（モデルには以前の結果を使うよう伝えます）。5回目になるとターンが止まります。
- **失敗する手順**：手順が4回続けて失敗すると、モデルに立ち止まって考え直すよう伝えます。8回続くとターンが止まります。
- **堂々巡り**：手順がループして回り続けている場合は、別の方法を試すようメモを伝えます。
- **未完了の作業**：「〜してみます」と言うだけで実行しないモデルや、計画の項目が残ったまま止まるモデルは、それぞれ1回ずつ作業に戻されます。プロジェクトのチェックを実行せずにコードを変更した場合は、終わる前にチェックを実行するよう求められます。
- **長さ**：1回のターンは最大200ステップです。150ステップに達すると、最も重要な部分を仕上げるようモデルに伝えます。モデルの長さの上限で途切れた返信は、より短いステップに分けて続けられます。
- **壊れたツール呼び出し**：テキストとして書かれた呼び出しは読み取って実行し、引数がほぼ合っている呼び出しは修復します。綴りの違うツール名は正しいものに対応づけるか、ツールの一覧を返して知らせます。呼び出しをテキストで書く返信は、その呼び出しの終わりで打ち切られます。呼び出しの後にモデルが書いた内容（想像した結果、その上に重ねた呼び出し、同じ呼び出しの繰り返し）は、実行も保持もされません。1回の返信から実行される呼び出しは最大6件です。
- **ツール呼び出しに対応しないモデル**：モデルのサーバーがツールを受け付けない場合、Customは指示文の中でツールを説明し、モデルが書いた内容から呼び出しを読み取ります。
- **Claude Code経由のClaude**：Anthropicは、プランのサインインを自社のプログラムにしか使わせません。そのため、プランのClaudeモデルはClaude Code自体を通じて、1ステップずつ応答します。Customのツールは指示文で説明され、ツール呼び出しをテキストで書くモデルと同じように、Claudeも呼び出しをテキストで書きます。各ステップは前のステップのキャッシュを再利用します。Claude Codeは返信をツール呼び出しの位置で終えられないため、Customがそこで返信を終え、Claudeが想像した結果を書く前にプログラムを停止します。Codexのモデルは別です。ChatGPTのプランで直接呼び出され、Customのツールは本物のツールとして渡されます。
- **一時的な不具合**：返信の途中で接続が切れた場合や、サーバーが混み合っている場合は、Customが待って数回やり直します。プランのモデルを待っているステップの途中でアプリが再起動した場合（アップデートなど）は、アプリが戻った後にそのステップをもう一度依頼します。再起動のために終わったターンにはその旨が表示され、メッセージを送ると続きから進められます。
- **多数のツール**：ツールが多い場合（MCPサーバーや接続から）、モデルには短い一覧が見え、必要なツールの詳しい説明は自分で調べます。機能のツールに関する指示は、モデルがそのツールを調べたとき、または使うときに一緒に渡されます（[モデルが読むもの](#what-the-model-reads)を参照）。コンテキストが短いモデル（約32,000トークン以下で、OpenRouter経由ではないもの）には、より軽量な構成が渡されます。回答UIに関するガイダンスはなく、ツールの一覧は名前だけで、詳細つきで渡されるツールも少なくなります（HTMLのページを表示するツールも一覧の中で待機します）。また、小さなステップで進めるよう求められます。
- **各モデルファミリー**には、開発元の推奨設定、学習時に使われた編集形式、そして対応するモデルには思考レベルが適用されます。読み取るだけのステップは、待ち時間を減らすために同時に実行されます。

これらのいずれかの理由でCustomがターンを止めると、返信は「(Stopped: …)」で終わります。

## 画像を見られないモデルへの対応

画像を見られるモデルには、画像がそのまま渡されます。このコンピューターにffmpegまたはImageMagickがある場合は、先に画像が縮小されます。

画像を見られないモデルには、補助モデルが各画像を言葉で説明します。何が写っているか、どこに何があるか、画像内の文字はそのまま書き写します。そのためには、画像を見られる補助モデルが必要です。[設定 → エージェント → モデル](/settings?s=models&find=Helper%20model)を開き、**補助モデル**グループの**モデル**メニューで「画像を認識」と表示されているものを選んでください。「自動」では使えません。選んでいない場合、Customはモデルに、見えない画像があることを伝えます。機密セッションでは、このコンピューター上の補助モデルだけが画像を説明します（プランのモデルは説明しません）。

## フォークとここから編集

Customのセッションも、Claude CodeやCodexのセッションと同じようにフォークできます。セッションのメニュー（⋯）→ **フォーク**です。自分の以前のメッセージを変更することもでき、そのときは**ここから編集**を使います。会話はそのメッセージの直前からのコピーで続き、元の会話はアーカイブされます。**このメッセージの前の状態にファイルを戻す**にチェックを入れると、それ以降のファイルの変更を元に戻せます。Customの場合、対象はCustom自身の編集で変更されたファイルです。コマンドによる変更はそのまま残ります。

Customは各会話をディスクに保存するので、アプリを再起動しても続きから進められます。

## Customの費用

- OpenRouter経由のモデル：OpenRouterが各呼び出しの費用を報告し、セッションの支出にはその金額が使われます。ここでのClaudeモデルには、他のモデルが自動で行うのと同じように、会話をキャッシュに保持するよう依頼します。そのため、各ステップは約10分の1の価格で会話を読み戻します。また、Customに渡されるツールはセッション中に変わっても1回までです（バックグラウンドで実行されるコマンド用のツールは、一度実行されると残ります）。これによりキャッシュが保たれます。
- ClaudeまたはChatGPTのプランのモデル（**契約中のサブスクリプション**）：トークンごとの金額ではなく、プランの使用量が消費されるため、これらのステップではセッションに$0と表示されます。使用量の上限に達したアカウントやサインアウトしたアカウントがある場合、そのステップは同じプログラムの次のアカウントに引き継がれます（**上限時にアカウントを切り替え**がオンの場合）。
- このコンピューター上のモデル（Ollama、vLLM）：無料です。
- その他のエンドポイント：トークンは他のエージェントと同じ基準で料金が計算されます（[使用量、上限、費用](/guide/usage)を参照）。

セッションでは、支出上限がなくても、メッセージ欄の上にAPI費用と、入力・キャッシュ・出力のトークン数が表示されます。料金はOpenRouterの応答から取得し、ストリームで届く料金がない場合は生成記録から取得します。それもない場合は、OpenRouter自身のカタログの価格が使われます。価格を手動で入力する必要はありません。

[支出上限](/guide/usage#cap-what-a-session-spends)はCustomのセッションでも使えます。

## 設定 → 機能 → Custom

[設定 → 機能 → Custom](/settings?s=custom)（「自動モード、コマンド用サンドボックス、目標を実行する長さ」）には3つの行があります。

- **自動モード**（Customのモードのひとつで、確認、編集を承認、フルアクセス、プランと並びます）：(i)に、自動モードで通すもの、常に確認するもの、チェックは補助モデルが行うことが書かれています。切り替えるものはありません。自動モードはセッションごとに**権限**で選びます。
- **コマンド用サンドボックス**（自動モードでは、コマンドはセッションのフォルダと、Linuxでは/tmp、Macでは一時フォルダ、Windowsでは専用の一時フォルダ内のファイルしか変更できません。フルアクセスでは、このサンドボックスも承認の確認もなしで実行されます）：スイッチで、初期状態ではオンです。ここでサンドボックスを実行できない場合（Linuxではbubblewrap、MacではSeatbelt、WindowsではGit for Windowsと.NET Framework）はグレーアウトされ、その理由が行に表示されます。
- **目標が一時停止するまでのラウンド数**（**目標**グループ内。/goalを使うと、Customは目標が満たされるまでターンを重ねて作業し、このラウンド数に達すると一時停止してユーザーの操作を待ちます）：**10**、**30**（初期値）、**100**ラウンドから選べます。進捗のないラウンドが3回続いた場合も一時停止します。

Customのモデルは[設定 → エージェント → モデル](/settings?s=models)にあり、チェックを行うモデルはそこの**補助モデル**です。

## エージェントに頼んでみましょう

- 「CustomのAutoモードのコマンドで、サンドボックスをオフにして。」
- 「Customの目標を最大100ラウンドまで実行できるようにして。」
- 「Customのセッション『アップロードページ』に目標を設定して：npm testが通り、2GBのアップロードも動くこと。」
- 「自動モードはどの補助モデルを使っていて、画像は見られる？」
- 「このコンピューターで、機密セッションのコマンドをネットワークなしで実行できる？」
- 「Customで使えるように、OpenRouterからQwen3 Coderを追加して。」（OpenRouterのキーを設定済みの場合）
- 「モデルの価格を入力せずに、OpenRouterの使用量と費用を見せて。」
- 「ローカルモデルだと、Customへの最初のメッセージがこんなに長いのはなぜ？」
- 「Customのセッションのコンテキストはどのくらい埋まっていて、何が一番多くを占めている？」
- 「CustomのセッションをOpenRouterではなく、ClaudeプランのSonnetで実行して。」
