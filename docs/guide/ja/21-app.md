# 外観、言語、アップデート

アプリの見た目と動作、そしてアプリを最新の状態に保つしくみについて説明します。ダークモードとライトモード、内蔵テーマと独自のテーマ、言語、アプリの動きの量、エージェントの作業中にEnterキーで何が起こるか、コンピューターの起動時の開始、エージェントの作業中にスリープさせない設定、アップデートとリリースノートを扱います。パスワード、サインアウト、アプリがデータを保存する場所についても説明します。

![設定 → 一般：テーマ](images/app.webp)

## ダーク、ライト、デバイスのモードを選ぶ

[設定 → アプリ → 一般](/settings?s=general&find=Appearance)を開きます。**外観**グループのタイトルの横に切り替えスイッチがあります。

- **ダーク**：常にダークテーマを使います。
- **ライト**：常にライトテーマを使います。
- **システム**：デバイスの設定に従います。デバイスがダークに設定されているとき（夜間など）はダークテーマ、それ以外はライトテーマになります。

モードはこのブラウザに保存されるため、スマートフォンとコンピューターで異なる設定にできます。検索ボックス（Ctrl+K、Macでは⌘K）にある**ライトとダークを切り替え**を使うと、モードがすぐにライトまたはダークに切り替わります。

## テーマを選ぶ

タイトルの下のグループ内に、各テーマの配色で表示した小さなアプリの画像が、**ダーク**と**ライト**の2段に並びます。アプリには4つのテーマが付属しています。

- **Hydorダーク**：セッションの背後は真っ黒で、パネルは青みがかった冷たい黒、アクセントはペリウィンクルです。初期設定のダークテーマです。
- **ミッドナイト**：セッションの背後は真っ黒で、パネルは温かみのある黒に近い色、アクセントはゴールドです。
- **Hydorライト**：温かみのあるオフホワイトに、深いゴールドのアクセントです。初期設定のライトテーマです。
- **セージ**：冷たい緑がかったグレーの紙のような色に、深いティールのアクセントです。

テーマをクリックすると使用できます。そのテーマがそのモードのテーマになり、モードもそれに切り替わります（モードが**システム**の場合を除きます。その場合は、デバイスがそのモードのときに表示されます）。モードごとに選択が保存されるので、夜はミッドナイト、昼はセージ、といった使い分けができます。**システム**がオンのときは、どちらが「表示中」かが各段に示されます。検索ボックスにテーマ名を入力しても見つかり、選ぶとそのテーマに切り替わります。

各画像にはメニュー（⋯）があります。コンピューターでは、ポインターを重ねると表示されます。

- **コピーして編集**：テーマのコピーを開いた状態でテーマエディタを開きます。
- **共有用にコピー**：テーマをテキストとしてコピークリップボードにコピーします。ほかの場所でインポートできます。
- **編集**と**削除**：自分で作ったテーマにのみ表示されます。削除する前に確認が表示され、そのテーマを使っていたデバイスはHydorのテーマに戻ります。

表示するテーマはブラウザごとに選びます。自分で作ったテーマはアプリに保存され、使用しているすべてのデバイスで利用できます。

## 独自のテーマを作る

1. 画像の下にある[**新しいテーマ**](/settings?s=general&find=New%20theme)をクリックします。エディタが開き、現在表示中のテーマのコピーが「My theme」という名前で表示されます（どのテーマでも**コピーして編集**を使って開くこともできます）。
2. 名前を付け、ベースとして**ダーク**か**ライト**を選びます。ベースによって、コードの色とターミナルでプログラムが出力する色が決まり、テーマで指定していない色も補われます。
3. 好きな色に変更します。色見本をクリックして色を選ぶか、`#1e3a2f`のような16進コードを入力します。
4. **テーマを保存**をクリックします。アプリはすぐにそのテーマを使います。

編集中はアプリ全体に変更が反映されるので、各色が使われている場所で確認できます。保存するまでは何も保持されません。**キャンセル**、✕（**保存せずに閉じる**）、Escのいずれかで、元のテーマに戻ります。**コピー**は**共有用にコピー**と同様に、テーマをテキストとしてコピーします。エディタはコンピューターでは右側のパネル、スマートフォンでは下から出てくるシートとして表示されます。

自分のテーマは最大40個まで作成できます。上限に達すると、**新しいテーマ**と**インポート**がグレーになります。

### 設定できる色

- **背景**：ページ（すべての背後）、サイドバー、カード（メッセージボックス、設定カード、パネル）、メニューとダイアログ、フィールド（入力欄や控えめな塗り）、ホバー（ポインターの下の行、チップ）、選択（開いている行、セカンダリボタン）。
- **テキスト**：テキスト、サブテキスト、薄いテキスト（ヒント、時刻、ラベル）。
- **罫線**：罫線、強い罫線（入力欄や枠付きボタン）。
- **アクセント**：アクセント（メインボタン、リンク、フォーカス、選択）、アクセント上のテキスト。
- **ステータス**：作業中、確認が必要・警告、完了・追加された行、失敗・削除された行、情報。
- **エージェント**：Claude、Codex。
- **コードとターミナル**：コードブロック、ターミナルの背景、ターミナルのテキスト。

テキストの色が、その下の背景に対して読みにくくなると、コントラスト比（例：2.8:1）とともに「読みにくい」という警告が表示されます。4.5:1であれば読みやすく、薄いテキストなら3:1が目安です。

## テーマを共有する、またはインポートする

テーマをほかの人、または自分のほかのHydorに渡すには：

1. テーマのメニュー（⋯）で**共有用にコピー**を選びます（エディタでは**コピー**）。テーマが短いテキストとしてコピーされます。
2. そのテキストを送ります。

受け取ったテーマを追加するには：

1. テーマ画像の下にある[**インポート**](/settings?s=general&find=Import)をクリックします。
2. **テーマをインポート**にテキストを貼り付けて、**テーマを追加**をクリックします。

テーマが自分のテーマに追加され、すぐに使用されます。テキストがテーマでない場合は「That is not a theme」と表示され、**共有用にコピー**で得られたテキストを入力するよう案内されます。

## 言語を変更する

[設定 → アプリ → 一般 → 外観 → 言語](/settings?s=general&find=Language)は、アプリの表示言語を選ぶメニューです。

- **English**（英語）
- **Deutsch**（ドイツ語）
- **Español**（スペイン語）
- **Français**（フランス語）
- **Português (Brasil)**（ポルトガル語、ブラジル）
- **Ελληνικά**（ギリシャ語）
- **日本語**
- **中文（简体）**（中国語、簡体字）

選ぶと、その言語でページが再読み込みされます。選択はこのブラウザに保存されます。初期設定では、ブラウザの言語に対応していればそれに従い、対応していなければ英語になります。

変わるのはアプリ自体の文言だけで、日付と時刻もその言語の書き方で表示されます。人やエージェントが書いた内容は元のままです。会話、メモリのメモ、自分で付けた名前や説明、ファイル、コード、ターミナルが対象です。

エージェントは選んだ言語で話しかけます。ほかの言語で書きかけた場合や言語を指定した場合を除き、その言語を使うよう依頼されます。コード、コマンド、ファイル名はそのままです。これは各エージェントの開始時または再開時に反映されます。通知もその言語で届き、スマートフォンでも同様です。アプリは開くたびにエージェントへ言語を伝えるため、デバイスごとに言語が異なる場合は、最後に開いたものにエージェントと通知が従います。

## 動きの量を選ぶ

[設定 → アプリ → 一般 → 外観 → モーション](/settings?s=general&find=Motion)で、このデバイスでアプリがどれだけ動くかを決めます。

- **全幅**（初期設定）：すべての動きを有効にします。ボタンは押している間に少し沈み、戻ると跳ね返ります。コピーするとチェックマークが描かれ、スイッチは弾むように切り替わり、アイコンバーのバーは開いたページまで滑らかに移動します。セッションのドットはステータスに応じて変わり（作業が終わると輪が広がり、確認が必要なときは2回脈打ちます）、リストは新しい位置へ滑らかに動いて空いた部分が詰まり、数字は新しい値までカウントされ、受信トレイのバッジが弾み、セッションが終わるとロゴの水が一度上がり、画像は表示されるまできらめき、完了したステップはチェックマークが描かれます。何かを開くときには、さらに5つの動きがあります。サイドバーは表示と非表示の切り替えでスライドし、ページの横の列（ブラウザの右列、ファイルページの**エージェントに質問**パネル）はスライドして出入りし、ページはほかのページへ移るときにクロスフェードし（ブラウザへ、またはブラウザからの移動を除く）、ライトとダークの見た目はテーマを切り替えるときに混ざり合い、ウィンドウは開くときに、背後で暗くなるページの上に入ってきます。ダイアログやウィンドウ（プロジェクトの詳細、ファイルのウィンドウ、アプリの上に開いたページ、エージェントエディタ）は、大きくなるにつれて少し上がり、そうしたウィンドウが画面下部に表示されるスマートフォンでは、シートのように下端から上がります。横のパネル（狭い画面でのセッションの詳細、バックグラウンドタスクのパネル）は右からスライドして入ります。検索ボックス（Ctrl+K）と画像・動画ビューアは素早くフェードインします。閉じるときはすぐに閉じます。
- **控えめ**：最後の5つを除く、上記のすべての動きです。ページやウィンドウを開くときにスライドやフェードは起こりません。
- **オフ**：どの動きもありません。進行中の作業だけは動き続けます。読み込み中のΩの水と、作業中のセッションのドットです。

各動きは約10分の1秒から4分の1秒で、開くものを待たせることはなく、進行中の作業以外は繰り返されません。デバイスの**視差効果を減らす**設定が常に優先されます。オンの場合、ここでの設定にかかわらず、アプリは**オフ**が選ばれているように動作します。選択はこのブラウザに保存されます。スマートフォンでは、サイドバーや列のスライドとページのクロスフェードは再生されませんが、ウィンドウは下から上がります。

## エージェントの作業中のEnterの動作を決める

**セッション**グループの[**エージェントの作業中に送信**](/settings?s=general&find=Sending%20while%20an%20agent%20works)では、エージェントがターンの途中のときにメッセージを送信した場合の動作を決めます。

- **ターンに参加**（初期設定）：Enterで進行中のターンにメッセージが追加され、エージェントはすぐにそれを考慮します。Ctrl+Enter（Macでは⌘Enter）では、代わりにターンの終了を待ちます。
- **待つ**：Enterでメッセージがキューに入り、ターンの終了後に送信されます。Ctrl+Enter（Macでは⌘Enter）では、代わりに進行中のターンに追加されます。

選択はこのブラウザに保存されます。キューについては[セッション](/guide/sessions)をご覧ください。

## ターミナルのサジェストをオンまたはオフにする

**ターミナル**グループの[**ターミナルのサジェスト**](/settings?s=general&find=Terminal%20suggestions)（初期設定はオン）は、アプリのターミナルでカーソルの後ろに、コマンドの続きとして最も可能性の高いものをグレーのテキストで表示します。→キーで受け入れます。オフにするとグレーのテキストが非表示になるだけで、Ctrl+Spaceでは引き続きサジェストが一覧表示されます。設定はこのブラウザに保存されます。[グレーのサジェスト](/guide/files-git#grey-suggestions)をご覧ください。

## 使用量の上限後にセッションを再開する

[**使用量の上限後に再開**](/settings?s=general&find=Resume%20after%20usage%20limits)（初期設定はオフ）：プランの使用量が尽きてターンが止まったとき、上限がリセットされた1分後にセッションが自動的に続行します。設定はアプリに保存されるため、ブラウザを開いていなくても動作します。詳しくは[使用量、上限、コスト](/guide/usage)をご覧ください。

## 非アクティブなセッションを削除する

アプリは、エージェント自身のプログラムの動作にかかわらず、すべてのセッションを保持します（[すべてのセッションが保持されます](/guide/usage#every-session-is-kept)を参照）。ただし、長い間誰も使っていないセッションは対象外です。[**非アクティブなセッションを削除**](/settings?s=general&find=Delete%20inactive%20sessions)（初期設定はオン）は、**1年**間非アクティブだったセッションを削除します。削除は1日に多くても数百件です。

- 非アクティブとみなす期間は、その行のスイッチの横のメニューで選びます：**3か月後**、**6か月後**、**1年後**、**2年後**、**5年後**。
- スイッチをオフにすると、すべてのセッションをずっと保持します。
- セッションは、最後に何かがあった時点から非アクティブとして数えます。
- 常に残るセッションがあります。ピン留めしたもの、作業中のもの、確認待ちのもの、キューにメッセージがあるもの、スヌーズ中のもの、上限後に再開する予定のもの、VS Codeやターミナルで実行中のもの、プルリクエストが開いているものです。
- 削除されたセッションは一覧から消え、会話も失われますが、その数値は[アクティビティ](/stats)に残ります。

設定はアプリに保存されるため、ブラウザを開いていなくても動作します。

## セッションごとに制限する

[**セッションごとに制限**](/settings?s=general&find=Limit%20each%20session)は、1つのセッションが使える量に上限を設けます。対象は、そのエージェントのプログラムと、それが実行するすべてのもの（コマンド、起動するサーバー）です。メモリ（**2 GBのメモリ**から**16 GBのメモリ**まで、または**メモリ制限なし**）とプロセッサ（**1個のプロセッサ**から**8個のプロセッサ**まで、または**プロセッサ制限なし**）を選びます。

- 制限は、次にセッションのエージェントが起動するときから有効になります。すでに実行中のセッションは、開始時の制限のままです。
- メモリを超えた場合は、より多くを要求したプログラムが停止されます。アプリや他のセッションは停止されません。エージェントはコマンドが終了したことを認識し、作業を続けられます。セッションの情報とシステム → モニターに「one stopped at its memory limit」と表示されます。
- プロセッサが上限に達すると、そのセッションのプログラムは遅くなりますが、コンピューターの残りは空いたままです。
- 制限はLinuxで、ユーザーのsystemd経由で機能します。各セッションは専用のスコープ内で実行されます。ほかの環境や、ユーザーのsystemdが動作していない場合は、メニューが無効になり、行の(i)に理由が表示されます。各セッションの使用量は引き続き[モニター](/system/monitor)で確認できます。

## コンピューターの起動時にアプリを開始する

**起動とアップデート**グループの[**このコンピューターの起動時に開始**](/settings?s=general&find=Start%20when%20this%20computer%20starts)は、コンピューターの再起動後やクラッシュ後にアプリを復帰させます。初期設定はオンです。インストーラーがアプリをサービスとして設定し、gitクローンから手動で起動したコピーは、初回実行時にサービスを設定します。スイッチでできることはアプリの実行方法によって異なり、その下の行（と(i)）に内容が表示されます。

- **ユーザーのサービスとして**（通常のインストール）：スイッチでオンとオフを切り替えます。誰かがログインする前の起動時にも開始します。行に、ログイン後にのみ開始すると表示されている場合は、コンピューターで一度`sudo loginctl enable-linger $USER`を実行すると変更できます。
- **システムサービスとして**：変更するには、コンピューターの管理者権限が必要です。
- **Dockerで**：再起動ポリシー（`restart: unless-stopped`）で復帰し、スイッチでは変更できません。
- **デスクトップアプリで**：ログイン時にバックグラウンドで開き、アイコンがメニューバー（Windowsではタスクバーの通知領域、Linuxではシステムトレイ）に表示され、ウィンドウは閉じた状態です。初めて開いたときからオンになっています（Macアプリは「アプリケーション」フォルダから開いた場合）。
- **それ以外の方法で起動した場合**：オンにすると、ユーザーのサービスとして設定されます。それができない場合（ユーザーのsystemdがない場合）は、その旨が行に表示されます。

ブラウザでの読み込み中、またはデスクトップアプリの起動中は、Ωの中で水が上がるロゴが表示されます。アプリの準備ができるとすぐに、ロゴの下にアプリが現れ、Ωの水が引くにつれてロゴが消え、周りの画面が晴れていきます。すぐにクリックや入力ができます。デバイスが視差効果の軽減を求めている場合は、ロゴはそのまま消えます。

## コンピューターをスリープさせない

デスクトップアプリ（Mac、Windows、Linux）では、**このコンピューターの起動時に開始**の下にある[**コンピューターをスリープさせない**](/settings?s=general&find=Keep%20the%20computer%20awake)が、作業がある間にコンピューターが自動でスリープするのを防ぎます。長い実行が途中で切れることはなく、7:00に設定したタスクは、次にノートパソコンを開いたときではなく7:00に実行されます。選択肢は3つあります。

- **エージェントの作業中とスケジュールタスクの前**（初期設定）：このコンピューター上でエージェントが作業している間（スケジュール実行、アプリの実行、サブエージェント、実行中の実験も含みます）。また、スケジュールタスク、エージェントのスケジュール、アプリのスケジュールの実行時刻が近づく数分前から、実行が始まるまでの間も含みます。
- **エージェントの作業中**：エージェントが作業している間だけです。スケジュールタスクは、コンピューターが起きているときに実行されます。
- **しない**：コンピューター自身の設定どおりにスリープします。

回答を待っているセッションは、作業中として数えません。数分おきに変化を確認するウォッチャー（[変化を監視する](/guide/tasks#watch-for-a-change)を参照）は、それだけではコンピューターをスリープさせない理由になりません。変化をきっかけに始まった実行だけが、作業している間、スリープを防ぎます。対象は、このコンピューターで動いているものだけで、ほかのマシンで動いているものは含みません。オプションの下の行には、コンピューターが今スリープしない状態かどうかとその理由（「スリープしません：エージェントが作業中」）が表示されます。作業が終わって数秒たつと、再びスリープすることがあります。

保たれるのはコンピューターの動作だけで、画面はこれまでどおり消えることがあります。ノートパソコンの蓋を閉じるとスリープしますし、自分でスリープを選んだ場合も同様です。これを決めるのはアプリではなくオペレーティングシステムです。すでにスリープ中のコンピューターは、タスクのために起きることはありません。再び起きた時点で実行が始まります。どんな時間帯でも実行が必要な作業には、デスクトップやサーバーのように電源を入れたままにできるコンピューターを使い、ノートパソコンやスマートフォンから接続してください（[1つのアプリでほかのマシンを使う](/guide/devices#use-other-machines-from-one-app)と[ほかのデバイスからアプリにアクセスする](/guide/devices#reach-the-app-from-another-device)を参照）。

このオプションはデスクトップアプリにのみ表示されます。サービスとしてインストールしたアプリ（またはDocker）では、コンピューターのスリープには手を加えません。

## アプリを最新の状態に保つ

gitからインストールしたもの（インストーラーまたはDockerによるもの）は、起動の数分後に新しいバージョンを確認し、その後は1日1回確認します。デスクトップアプリは、開いてから1分後に確認し、その後は4時間ごとに確認します。[設定 → App → 一般](/settings?s=general&find=Check%20now)の**起動とアップデート**の最後にあるバージョンの行は、実行中のバージョンの名前（**Hydor…**）で表示され、状況を示します。

- 「最新です・確認：…前」と表示され、**今すぐ確認**でもう一度すぐに確認できます。
- 新しいバージョンが出ているとき：「…件のアップデートあり」、最新の変更のタイトル、そして**今すぐ更新**が表示されます。新しいバージョンを取得してビルドし、アプリを再起動します。実行中のエージェントは再起動をまたいで作業を続け、このタブも自動で新しいバージョンに再読み込みされます。アプリが自分で再起動できない場合は、新しいバージョンの取得とビルドまでを行うので、アプリを再起動して使ってください。
- 更新中：「新しいバージョンを取得しています…」「パッケージをインストールしています…」「ビルドしています…」、続いて「再起動しています。このページは自動で再接続します…」と表示されます。
- 更新後の1週間は、直近の更新の結果が表示されます。更新した日時（どのバージョンからどのバージョンへか）、または失敗した理由です。

新しいバージョンが出ているときは、アイコンバーの**設定**にドットが表示されます。gitからインストールしていないものは確認できず、**今すぐ確認**でその旨が表示されます。行の（i）には、セッションが実行される場所と、その履歴の取得元が表示されます。

[**自動で更新**](/settings?s=general&find=Update%20automatically)（初期状態ではオン、バージョンの行の上にあります）は、新しいバージョンを自動でインストールします。gitからインストールしたものは、メッセージを送らない状態が5時間続いたあとに、1日1回までです。デスクトップアプリは、新しいバージョンが出ると1分前の通知のあとすぐに更新します（Linuxの.debでは先にパスワードを求められます）。実行中のエージェントは作業を続けます。自分で再起動できるアプリが必要です（インストーラーのサービス、Docker、またはApplicationsフォルダにあるMacアプリのように自分自身を置き換えられるデスクトップアプリ）。そうでない場合、スイッチはオフになり、その理由が表示されます。

ほかのデバイスで開いているページは、アプリが実行中より新しいバージョンになったことを検知し、**再読み込み**（「Hydorが更新されました」）を案内します。ページの描画に失敗した場合は、空のウィンドウではなく「このページは動作を停止しました」、問題の内容、**再読み込み**が表示されます。サイドバーは残り、ほかのページに移動すると再試行されます。

### 古いコピーを手動で更新する

GitHub上のHydorの履歴はバージョン0.78.0で書き換えられたため、それ以前にgitまたはDockerでインストールしたコピーは、それより先へ自力で更新できません。**今すぐ更新**は「Not possible to fast-forward, aborting.」で止まり、ほかのマシンのアプリからそのマシンを更新した場合（[1つのアプリでほかのマシンを使う](/guide/devices#use-other-machines-from-one-app)を参照）も同様で、そのページに対処方法が表示されます。そのマシン上で、インストールしたときと同じ方法で1回更新してください。以降は再び自動で更新されます。

- **インストーラーの場合**：そのマシンで再度実行します。コピーが新しい履歴に移され（変更したファイルは残ります）、ビルドされ、サービスが再起動されます。実行中のエージェントは作業を続けます：`curl -fsSL https://raw.githubusercontent.com/algoprog/hydor/main/install.sh | bash`。自分で選んだフォルダにインストールした場合は、そのフォルダを指定します：`curl -fsSL https://raw.githubusercontent.com/algoprog/hydor/main/install.sh | HYDOR_DIR=/that/folder bash`。
- **Dockerの場合**：新しいイメージを取得し、`compose.yaml`があるフォルダで、そのイメージからコンテナーを起動し直します：`docker compose pull && docker compose up -d`（または`docker pull algoprog/hydor`を実行し、以前と同じ方法で起動します）。アプリが保存しているデータはボリュームにあるため、失われるものはありません。イメージを自分でビルドしている場合は、先に次の項目のとおりクローンを更新してから、`docker compose up -d --build`を実行します。
- **自分のgitクローンの場合**：そのフォルダで`git fetch && git reset --keep @{u} && npm ci && npm run build`を実行し、アプリを再び起動します。`git reset --keep`は、変更したファイルを残し、上書きしてしまいそうな場合は途中で止まります。自分でコミットを作っている場合は、代わりに`git rebase --onto`でそれらを新しい履歴に移します。

新しいコピーは、書き換えられた履歴を自動で処理します。コピーに自分のコミットがない場合、**今すぐ更新**は、変更したファイルを残したまま新しい履歴に移します。コミットがある場合は、その旨を表示し、そのままにします。

### デスクトップアプリでのアップデート

デスクトップアプリ（Mac、Windows、Linux）は、公開されたバージョンを基準に更新します。[**自動で更新**](/settings?s=general&find=Update%20automatically)がオンの場合、新しいバージョンが出ると、席を外すのを待たずにすぐダウンロードし、リリースが示すビルドと一致するかを確認します。その後、2か所でお知らせします。

- 通知：「Hydor…の準備ができました」と表示され、1分後に再起動してインストールします。クリックするとアプリが開き、通知の**今すぐ再起動**ボタンで新しいバージョンをすぐにインストールできます。
- アプリで開いているすべてのページの隅に表示されるメモ：秒数をカウントダウンし（「42秒後に再起動してインストールします」）、**今すぐ再起動**と**あとで**が表示されます。

1分たつと、アプリは新しいバージョンで再起動します。実行中のエージェントは作業を続け、ウィンドウも自動で戻ります。インストール中、ウィンドウにはHydorのロゴと、そのΩの中で水位が上がっていく様子、「Hydor…にアップデート中」だけが表示され、閉じて新しいバージョンで開き直すまで続きます。開き直したときも同じロゴが表示されます（Linuxの.debは、その間にパスワードを求めます）。新しいバージョンを所定の場所に置けなかった場合は、ロゴが消えて元のままのアプリが表示され、その理由を伝えるメモが出ます。**あとで**を選ぶと4時間延期され、その後に通知とメモが再び表示されます。それまでの間は、アプリのアイコンのメニュー（メニューバー、通知領域、システムトレイ、およびアプリ自身のメニュー）にある**Restart to Update to …**で、好きなときにインストールできます。バージョンの行の**今すぐ再起動**でも同様です。この行には「バージョン…のインストール準備ができました」と、次に確認する時刻が表示されます。

**自動で更新**がオフのときは、自動でダウンロードされません。バージョンの行に「バージョン…が公開されました」と表示され、**今すぐ更新**でダウンロードして確認し、実行中のものの代わりに開きます。ダウンロード中は、バージョンの行に進み具合が表示され（「Hydor…をダウンロードしています 40%」、水で満たされていくバー、「38 / 94 MB」）、続いて「新しいバージョンを確認しています…」と表示されます。ほかのページでは隅のメモに同じ内容が表示されます。新しいバージョンが入りしだい、アプリがそれで再起動するためです。アプリが自動で始めたダウンロードは、進み具合がバージョンの行にだけ表示されます。

途中で止まったダウンロードは、止まったところから再開します。コンピューターがスリープしたとき、または接続が切れたり1分間無反応になったときは、できるだけ早く再開します。数分たっても進まない場合は、そこまでのデータを保持し、バージョンの行の下の行にどこまで進んだかを表示して、1時間後にそこから再試行します。**今すぐ更新**も同様です。

Windowsでは、新しいバージョンのインストーラーがウィンドウを表示せずに実行され、アプリに上書きインストールして再び開きます。Linuxの.debはインストールにパスワードが必要です。自動でダウンロードされたバージョンは待機し、**Restart to Update**（または**今すぐ再起動**）でパスワードを入力すると、新しいバージョンが開きます。

MacアプリまたはAppImageの新しいバージョンが起動しない場合は、以前のバージョンが自動で戻り、バージョンの行の下の行にその理由が表示されます。そのバージョンは、**今すぐ更新**を押したときにだけインストールされます。Macアプリは、Applicationsフォルダ（または書き込み可能なほかのフォルダ）からのみ自分で更新できます。ディスクイメージから開いた場合は、そこへ移動するよう案内が表示されます。AppImageも、ホームフォルダなど書き込み可能なフォルダが必要です。

## リリースノートを読む

バージョンごとにリリースノートがあり、使っている人にとって何が変わったかが書かれています。

- [設定 → App → 一般](/settings?s=general)の**起動とアップデート**の下部にあるバージョンの行で、**リリースノート**をクリックします。
- または、検索ボックスに「release notes」または「what's new」と入力します。

ノートには、すべてのバージョンが新しい順に日付付きで並びます。実行中のバージョンには「このバージョン」と表示され、設定はそこでノートを開きます。

アプリの更新後に1回、隅のメモに「Hydor…に更新しました」と**What's new**が表示され、そのバージョンのノートが開きます。表示は各ブラウザで1回で、ブラウザの初回アクセスでは表示されません。

## ツアーを始める

ウェルカムツアーは、AIが初めての人向けに作られています。最初に、依頼が片付くまでを描いた短い映像が流れます（自分の言葉で頼み、エージェントが順に作業し、結果ができあがります）。次に、何に作業を任せるかを尋ねられます。**Claude**または**ChatGPT**（すでに支払っているプランを使用）、**従量課金**（OpenRouter経由であらゆる会社のモデルを使用）、**無料・このコンピューター上で動作**（ここで動くモデル）、**ほかのエージェント**です。選んだものはそれぞれ、画面いっぱいのページで設定します。どのページも、画像と文言が同じ位置にあり、スクロールは不要です。サインイン、OpenRouterのキーの追加とエージェント用モデルの選択、続いて画像、音楽、音声、動画を作るモデルの選択、またはこのコンピューターに合うおすすめモデルの1クリックでのインストールを行います。各ページの横の画像は、選んだものを、Ωの周りのプールに流れ込む水の流れとして表し、選ぶほどプールが満ちていきます。下の小さなドットは現在位置を示し、その背景では波がゆるやかに漂います。ほかのエージェント（Claude Code、Codexなど）のフォルダがこのコンピューターにある場合は、もう1ページ**ほかのエージェントから移行しますか？**が表示され、見つかったものを示して、ツアーの上に[取り込み](/guide/memory#bring-in-from-other-assistants)を開きます。ない場合、このページは表示されません。デスクトップアプリで、このコンピューターにほかのブラウザが見つかった場合は、次のページ**ブックマークと履歴を取り込みますか？**に「Hydorには専用のブラウザがあります。このコンピューターのブラウザが持っている情報を取り込むと、よく使うサイトにすぐアクセスでき、アドレスバーにも候補が表示されます。すべてこのコンピューター上に保存されます。」と表示されます。**ブックマーク**と**履歴**の2つのスイッチ（どちらもオン）があり、その下に各ブラウザ（とそれぞれのプロファイル）がブックマーク数と履歴のページ数とともに並び、横に**インポート**があります。オンにしたものが取り込まれます。ブックマークは、ブックマークバーの末尾に作られる新しいフォルダ「Imported from Chrome」に入り（[ブックマークを取り込む](/guide/web#bring-in-bookmarks)のとおり）、履歴は[履歴](/guide/web#history)のとおりに取り込まれます。完了すると**取り込み済み**と表示され、問題（Safariの権限、ロックされたファイルなど）はそのブラウザの行に表示され、そこの**インポート**で再試行できます。Macで、macOSがHydorによるSafariの読み取りを許可していない間は、Safariの行に**インポート**の代わりに**システム設定を開く**が表示されます。これを押すと「システム設定 → プライバシーとセキュリティ → フルディスクアクセス」が開き、そこでHydorをオンにします。戻ってくると、行が再確認されます。先にHydorの再起動が必要な場合は、ツアーはこのページに戻ります。**次へ**で、取り込まずに進みます。ほかのブラウザが見つからない場合や、デスクトップアプリ以外では、このページは表示されません。その後は、アプリを部分ごとに案内し、途中で試せることも用意されています。メッセージボックスに1クリックで入れられる最初のタスクです。ステップ**完了を音で知らせる**は、このデバイスの通知をオンにします。デスクトップアプリでは、**通知をオンにする**でテスト通知が表示されます。システムがまだHydorの通知を表示していない場合は、許可するための設定（Macでは、システム設定のHydorの通知）が開き、戻ってくると再確認されます。デスクトップアプリでは、次のステップで**スマートフォンでも使いますか？**と尋ねられます。**設定する**を選ぶと、ツアーは[設定 → App → スマートフォンで使う](/settings?s=phone)で終わり、Tailscaleを使ってスマートフォンからアプリにプライベートに接続できます。**今はしない**を選ぶと先に進みます。ツアーは、アプリを初めて使うときに自動で開きます。

もう一度見るには、[設定 → App → 一般 → ヘルプ → ウェルカムツアー → **ツアーを始める**](/settings?s=general&find=Take%20the%20tour)、検索ボックスの**ツアーを始める**、またはアイコンバーの**ヘルプ**の上部にある**ツアーを始める**を使います。詳しくは[はじめに](/guide/start)をご覧ください。

ツアーのあとは、ヒントがアプリの残りの部分を、そこにたどり着いたときに紹介します。アプリの各部分が初めて画面に表示されたとき（受信トレイ、セッションのメニュー、Gitのページ、**設定 → メモリ**など）、その横に小さなカードが現れて用途を説明し、**詳細**を押すとこのガイドの該当箇所が開きます。ヒントは、一度に1つずつ、間をあけて表示され、入力中やメニューを開いているときには表示されません。

- **わかりました**を押すか、ヒントが指す部分を使うと、そのヒントはすべてのデバイスで完全に非表示になります。
- **ヒントをスキップ**は、すべてのデバイスですべてのヒントを止めます。ツアーの最初のページの**ツアーをスキップ**も同様です。✕でツアーを閉じた場合は、ヒントはオンのままです。
- これとは別に、エージェント1つ分の数倍の費用がかかるモードを初めて選ぶとき（**スウォーム**、**キャンペーン**、**ディープリサーチ**、**アリーナ**）、オンにする前に、その用途と費用を説明するダイアログが表示されます。表示はモードごとに1回で、すべてのデバイスに共通し、ヒントのオン・オフには関係ありません。エージェントにヒントをもう一度表示するよう頼むと、このダイアログも再び表示されます。
- 再びオンまたはオフにするには：[設定 → App → 一般 → ヘルプ → **ヒント**](/settings?s=general&find=Tips)。

## パスワードを変更する

アプリのパスワードは1つだけで、インストール時に決めたものです。変更するには、[設定 → アプリ → パスワード](/settings?s=security&find=Change%20password)を開き、**パスワードを変更**の行で**変更…**をクリックします。ダイアログが開きます。

1. **現在のパスワード**を入力します。
2. **新しいパスワード**（10文字以上）を入力し、**新しいパスワードを再入力**にも同じものを入力します。
3. **パスワードを変更**をクリックします（現在のパスワードを入力し、新しいパスワードが10文字に達するまでグレーのままです）。

変更すると、このブラウザ以外のすべてのブラウザ（スマートフォンや他のコンピューターなど）がサインアウトされます。現在のパスワードが違う場合や、新しいパスワード2つが一致しない場合は、何も変更されず、理由がアプリに表示されます。

パスワードを忘れた場合は、アプリが動いているコンピューターで、アプリのフォルダ内で次のコマンドを実行します：`node dist/server/cli.js set-password`（Dockerの場合：`docker compose exec -it hydor node dist/server/cli.js set-password`）。すべてのブラウザがサインアウトされ、パスワードの入力ミスで一時停止されていたアドレスも再びサインインできるようになります。

## このブラウザからサインアウトする

[設定 → アプリ → パスワード → このブラウザ → このブラウザからサインアウト](/settings?s=security&find=Sign%20out%20of%20this%20browser) → **サインアウト**をクリックすると、このブラウザだけがサインアウトされます。再びサインインするにはパスワードが必要です。

## アプリがデータを保存する場所

アプリは自身のデータを1つのフォルダ（データフォルダ）に保存します。場所はホームフォルダの `~/.hydor` です（バージョン0.5より前にインストールした場合は `~/.web-agent`、または `DATA_DIR` 設定で指定した場所）。ファイルページで削除したファイルは、このフォルダ内のゴミ箱に移動します。場所はファイルページの各場所のうち**ゴミ箱**で確認できます。フォルダには次のものが入っています。

- パスワード（ハッシュ化されたもので、パスワード自体は保存されません）
- セッション一覧、検索、設定、アプリのその他の記録を収めたデータベース
- 現在動いているエージェントのログ
- 送信待ちの添付ファイル（アプリ側のコピーは14日後に削除され、合計2 GB以内に保たれます）
- ファイルページのゴミ箱
- ノートブックのカーネルと、ターミナルが動作する専用サーバー
- 意味で検索をオンにした場合、そのための専用Python環境

会話そのものは、エージェントが書き込む場所に残ります。Claude Codeは `~/.claude/projects`、Codexは `~/.codex/sessions` で、アプリはそこから読み込みます（設定 → 一般のバージョン横の (i) にも記載があります）。Dockerの場合、これらはすべてコンテナの `/home/node` にあり、データボリュームに保存されます。

### ブラウザごとに保存されるもの

一部の選択は、それを行ったブラウザごとに保存されるため、デバイスごとに異なる設定にできます。

- モード（ダーク、ライト、システム）と、表示するダークテーマ・ライトテーマ
- 言語
- 動きの量（**動き**）
- エージェントの作業中にEnterキーを押したときの動作
- ターミナルの候補、通知音、このデバイスで通知を受け取るかどうか
- ファイルページのフォルダ、開いているファイル、最近使ったファイル、フォルダの表示方法（リストまたはタイル、および並び順）。ピン留めしたフォルダはサーバーに保存され、どのデバイスでも同じです
- ブランチをレビューする際に**確認済み**にしたファイル
- 「新機能」のお知らせを表示したかどうか

それ以外はアプリが保存しており、どのデバイスでも同じです。自分で作ったテーマ、**使用量の上限後に再開**、**非アクティブなセッションを削除**、**このコンピューターの起動時に開始**、**自動で更新**、ツアーを受けたかどうか、ヒント（オンかオフか、表示済みのもの）が該当します。
