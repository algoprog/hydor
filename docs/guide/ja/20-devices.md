# スマートフォン、他のマシン、共有

Hydorはどのブラウザでも使えます。スマートフォン、別のコンピューター、Hydorを動かしている複数のマシンのいずれからでも利用できます。このトピックでは次の内容を扱います。スマートフォンでの使い方（Tailscale経由で非公開に接続でき、数回のクリックで設定できます）、外出先から安全に接続する方法、1つのアプリから他のマシンを操作する方法、読み取り専用リンクでセッションを共有する方法、他の場所のエージェントがここでセッションを開始して操作できるようにする方法、プルリクエストの作成に使うGitHubまたはGiteaのアカウントの追加です。

![スマートフォンでのアプリ：ユーザーの対応を待っているセッション](images/devices.webp)

## スマートフォンでアプリを使う

スマートフォンのアプリはコンピューター版と同じアプリで、小さな画面に合わせたレイアウトになっています（コンピューターで狭いウィンドウにしたときも同じレイアウトになります）。変わる点は次のとおりです。

- **サイドバーはドロワーになります。** ページやセッションの左上にある**メニュー**（≡）をタップして開きます。画面全体に、セッション、受信トレイ、ツールが表示されます。セッションやツールをタップするとそこへ移動し、**メニューを閉じる**（✕）をタップすると戻ります。
- **ピッカーはシートとして開きます。** スタート画面では、プログラム、モデル、フォルダ、エージェント、**オプション**のメニューが、キーボードにかからない画面下部から上がってきて、背後のページは暗くなります。**オプション**の中の設定は、そのシートの上に重ねて開きます。セッションでは、メッセージ欄にあるモデル（と思考レベルや権限）のチップが同じようにシートを開きます。ダイアログも画面下部から上がってきます。
- **一度に1つずつ表示します。** 設定は一覧形式で、各セクションが独立したページになります。ファイルでは1つのフォルダが表示され、上部にその名前が出ます（名前をタップすると場所の一覧、**‹**で1つ上のフォルダ）。ファイルを開くとそのファイルだけのページになり、**戻る**で戻ります。Gitページにはリポジトリの一覧が表示され、1つ選ぶと戻る矢印付きで開きます。
- **マウスの代わりにタッチで操作します。** ファイルでは、行の⋯でメニューが開き、行を長押しすると選択されて、複数をまとめて操作できます。エディタは長い行を折り返します。ターミナルページには、スマートフォンにないキー（Ctrl、Alt、Esc、Tab、矢印キーなど）の列が追加されます。

スマートフォンからアプリを使うには、このコンピューターの外からアクセスできる状態にする必要があります。[設定 → アプリ → スマートフォンで使う](/settings?s=phone)なら、Tailscaleを使って数回のクリックで非公開のまま設定できます。詳しくは[Tailscaleでスマートフォンから使う](/guide/devices#use-it-on-your-phone-with-tailscale)をご覧ください。

### ホーム画面に追加する

ホーム画面にインストールすると、アプリは専用のアイコンから全画面で開き、ほかのアプリと同じように使えます。これにはアプリがHTTPSで提供されている必要があり、スマートフォンで使う設定を行えば満たされます。スマートフォンで開くと、[スマートフォンで使う](/settings?s=phone&find=Add%20to%20Home%20Screen)の**このスマートフォンで → ホーム画面に追加**に、手元のスマートフォン向けの手順が表示されます。ブラウザが対応している場合は**インストール**ボタンも表示されます。

- **iPhoneまたはiPad**：ブラウザでアプリを開き、**共有**、**ホーム画面に追加**の順にタップします。以後は新しいアイコンからHydorを開きます。
- **Android**：ブラウザでアプリを開き、メニューにあるアプリのインストールまたはホーム画面に追加のオプションを使います。

### 他のアプリからHydorに共有する

インストールすると、Hydorはメッセージアプリと同じように、スマートフォンやコンピューターの共有シートに表示されます。ほかのアプリから写真、PDF、Webページ、数行のテキストを共有して**Hydor**を選ぶと、スタート画面が開き、共有した内容がメッセージ欄に入った状態になります。文章とリンクはテキストとして、ファイルは添付として入ります。どうしたいかを一言添え、必要ならエージェントを選んで送信します。

- **Android**：Chrome、Edge、そのほかChromiumベースのブラウザで、ブラウザのメニュー（**Install app**または**Add to Home screen**）からアプリをインストールすると使えます。
- **コンピューター**：アプリをインストールした（アドレスバーのインストールボタン、またはブラウザのメニューの**Install Hydor**）ChromeとEdgeで、システムの共有シートから共有するアプリに対して使えます。
- **iPhoneとiPad**：Safariでは、Webアプリが共有を受け取れません。写真やファイルをエージェントに送るには、代わりにチャットアプリを使います（[チャットでできること](/guide/devices#what-a-chat-can-do)を参照）。テキストとリンクについては、ショートカットで対応できます。ショートカットアプリで、共有シートに表示されてテキストとURLを受け取るショートカットを作り、入力に**URL Encode**を追加し、続けて**Open URLs**で、アプリのアドレスに`/?prompt=`とエンコードしたテキストを続けたものを開きます（`https://hydor.example.com/?prompt=`とその結果をつなげた形です）。Safariでスタート画面が開き、テキストが入力欄に入ります。

共有するには、その端末でサインインしている必要があります。サインアウトした状態で行った共有はHydorに届かず、スタート画面にその旨が表示されます。共有にはメッセージ欄と同じく最大25 MBのファイルを付けられ、メッセージ欄の添付と同じ場所に保存されます。

### スマートフォンで通知を受け取る

セッションが完了したとき、失敗したとき、回答が必要なときに、アプリを閉じていてもスマートフォンに通知を届けられます。

1. スマートフォンで[設定 → アプリ → 通知](/settings?s=notifications&find=Notify%20this%20device)を開きます。
2. **この端末に通知**をオンにし、ブラウザから確認されたら通知を許可します。この設定は端末ごとに行います。
3. **テストを送信**で動作を確認できます（アプリが表示されていないときに通知が届きます）。

スマートフォンで開いた[スマートフォンで使う](/settings?s=phone)にも、**このスマートフォンで**の**ホーム画面に追加**の後に同じ**この端末に通知**のスイッチがあり、その**テストを送信**はそのスマートフォンにだけ送られます。

iPhoneやiPadでは、先にアプリをホーム画面に追加し、そこから開いてください。そうしないと、ブラウザは通知を受け取れません。サイトの通知がブロックされている場合は、先にブラウザの設定で許可してください。単純な「はい／いいえ」の承認には、スマートフォンがボタンを表示できる場合、通知そのものに**承認**と**拒否**が付きます。詳しくは[受信トレイと通知](/guide/inbox)をご覧ください。

## Telegram、Discord、SlackからエージェントとやりとりMessage

Telegram、Discord、Slackのチャットから、スマートフォンでもコンピューターでも、セッションの開始（自分のエージェントとしての開始も可能）、写真・ファイル・音声メッセージの送信、返信の確認、エージェントからの質問への回答ができます。いずれも自分用のボットまたはアプリを使い、[設定 → アプリ → チャットアプリ](/settings?s=chat)で設定します。Hydorのほうから外へ接続する仕組みです（Telegramには新着メッセージを問い合わせ、DiscordのGatewayとSlackのSocket ModeにはWebSocketを開きます）。そのため、どれもアプリがインターネット上のアドレスを持つ必要はありません。

### ボットまたはアプリを接続する

[チャットアプリ](/settings?s=chat)を開き、**ボット**グループで使いたいものの行を押します（接続するまでは**設定**と表示されます）。その下に手順が開きます。貼り付けた内容は保管庫に暗号化して保存され、アプリ上には二度と表示されません。

- **Telegram**：Telegramで@BotFatherを開き、`/newbot`を送って、ボットの名前とユーザー名を付けます。返ってきたトークン（`123456789:AA…`のような形式）を、[Telegram](/settings?s=chat&find=Telegram)の行の入力欄に貼り付けて**接続**を押します。
- **Discord**：Developer Portal（discord.com/developers/applications）で**New Application**を作成します。**ボット**の下で**Reset Token**を押してトークンをコピーし、ボットがユーザーの書いた内容を読めるように**Message Content Intent**をオンにします。トークンを[Discord](/settings?s=chat&find=Discord)の行に貼り付けて**接続**を押します。次に、**ボットをサーバーに追加**の行から、自分のサーバーにボットを追加します（Discordでは、同じサーバーにいるボットにしかメッセージを送れないため、自分用の小さなサーバーで十分です）。招待ではチャンネルの閲覧、メッセージの送信、メッセージ履歴の閲覧が求められ、Hydorはスラッシュコマンドを登録します。
- **Slack**：api.slack.com/appsで**Create New App → From a manifest**を選び、ワークスペースを選んで、**マニフェストをコピー**（[Slack](/settings?s=chat&find=Slack)の行の手順の中にあり、接続後は専用の行になります）でコピーしたマニフェストを貼り付けます。このマニフェストにより、Socket Modeが有効になり、ダイレクトメッセージとメンションが購読され、`/hydor`コマンドが追加され、ボットスコープ`app_mentions:read`、`chat:write`、`commands`、`files:read`（送られたファイル用）、`im:history`、`reactions:write`、`users:read`が要求されます。**Basic Information → App-Level Tokens**で`connections:write`スコープのトークン（`xapp-`で始まります）を生成し、**Install App**でアプリをワークスペースにインストールして、Bot User OAuth Token（`xoxb-`で始まります）をコピーします。両方を貼り付けて**接続**を押します。

接続すると、その下の最初の行にボットの名前と状態が表示されます（「メッセージを待機中」、または問題の内容。たとえばDiscordのMessage Content Intentがオフ、SlackのアプリにスコープがないなどMessage）。**接続**がトークンを拒否するのは、サービス側が明確に拒否した場合だけです。Telegram、Discord、Slackの応答が遅いとき、またはそのときに接続できないとき（新しいボットの作成直後の数分間に起こることがあります）は、Hydorはトークンを保持し、行に**接続中…**と理由が表示され、サービスが応答し次第、ボットは自動的に接続されます。Telegramのボットはメッセージを1か所でしか受け取れないため、別のHydorや別のプログラムが同じボットを使っている場合は、行にその旨が表示されます。行の**⋯**メニューには、別のトークンを入れる**トークンを変更**（Slackでは**トークンを変更**）と、Hydorから外す**接続を解除**があります。トークンを変更すると、別のボットのチャットは改めてリンクが必要になります。接続を解除しても、ボットやアプリはそのままユーザーのものです。

### チャットをリンクする

ボットを使えるのは、リンクしたチャットだけです。それ以外の人がボットを見つけても、個人用であることが伝えられます。

1. 行を開き、その中の[チャットをリンク](/settings?s=chat&find=Link%20a%20chat)の行を押します。1回だけ使える、10分間有効なコードが表示されます。
2. Telegramでは、**Telegramで開く**を押し、開いたチャットで**開始**を押すか、ボットにコードを送ります。DiscordとSlackでは、ボットまたはアプリにダイレクトメッセージでコードを送るか、チャンネルでコードを添えてメンションします。チャットが名前付きで行に表示されます。

チャンネルは、コードを送った本人にリンクされます。そこで応答するのはその人だけで、ボットにメンションしたときに限られます。チャットの横にあるゴミ箱ボタン（**リンクを解除**）で、そのチャットがエージェントを使う権限をなくせます。

### チャットでできること

- **やってほしいことを送る**：チャットが入っているセッションに送られます。なければ、スタート画面と同じように専用のタスクフォルダで新しいセッションが始まります。エージェントは**新しいセッションで使うもの**の行で設定したもの（**Claude Code**、**Codex**、**Custom**。選ぶまでは、Claude CodeとCodexのうちサインインしている最初のもの、どちらにもサインインしていなければCustom）で、**新しいセッションのエージェント**の行で自分のエージェントを選んでいればそのエージェントとして開始されます。エージェントの作業中に送ったものは、セッションのキューで待機します。
- **写真、ファイル、音声メッセージ**：人に送るときと同じように送れ、必要ならキャプションを付けられます。キャプションは一緒に届き、まとめて送った複数のもの（アルバム）は一緒に届きます。それぞれ、送り先のセッションのフォルダに元の名前で保存されます（写真と音声メッセージは届いた日時で名前が付きます。例：`photo-2026-11-15-0930.jpg`）。エージェントには、メッセージ欄の添付と同じ形で渡されます。画像は見る対象として、そのほかのファイルは開く対象としてです。設定 → 機能 → 音声の[サーバーでの音声認識](/settings?s=voice&find=Speech%20recognition%20on%20the%20server)がオンなら、音声メッセージは文字としてエージェントに届き、録音はフォルダに残ります。オフの場合は録音が音声ファイルとして送られ、チャットでオンにする方法が案内されます。Telegramではボットが取得できるファイルは最大20 MBで、HydorはDiscordとSlackから最大25 MBのファイルを受け取ります。大きすぎる場合はチャットで知らせます。ファイルの中身や他の人から転送されたメッセージは、外部のデータであることが明示されてエージェントに渡され、作業の材料として扱われ、指示としては扱われません。Slackでファイルを受け取るには`files:read`スコープが必要です。古いマニフェストで作ったアプリでは、**OAuth & Permissions**で追加してからインストールし直してください（ファイルを受け取れないときは、チャットでその旨が表示されます）。
- **自分のエージェント**：`/as`とエージェント名で、自分の[エージェント](/agents)の1つとして新しいセッションを開始します。たとえば、領収書の写真を付けて`/as Bookkeeper add this to October`のように送ります。`/as`と名前だけを送ると、そのチャットの次の新しいセッションがそのエージェントとして始まります。`/agents`（または`/as`だけ）では、自分のものが先頭に並び、それぞれボタン付きで一覧表示されます。専用の会話を1つ持つエージェントの場合は、チャットがその会話に入ります。Discordでは`/as`と入力するとエージェント名が補完されます。Slackでは`/hydor as Bookkeeper …`と書きます。[新しいセッションのエージェント](/settings?s=chat&find=New%20sessions%20as)の行を設定すると、そのチャットアプリからの新しいセッションがすべて、選んだエージェントとして始まります。
- **返信**：エージェントのターンが終わると返ってきます。アプリごとの書式で整えられ（Telegramの書式、DiscordのMarkdown（1メッセージ2,000文字まで）、Slackのmrkdwn（ブロック形式））、長い場合は最大10通に分けて届きます（残りはセッションに残ります）。作業中、TelegramとDiscordには「入力中…」が表示され、Slackではメッセージに砂時計が付きます。**Hydorで開く**は、アプリがインターネット上のアドレスを持っているか、tailnetで提供されている場合に、アプリでセッションを開きます（[Tailscaleでスマートフォンから使う](/guide/devices#use-it-on-your-phone-with-tailscale)を参照）。
- **エージェントからの質問**：単純な「はい／いいえ」の質問には、回答用のボタンが付きます。それ以上のもの（フォームやプラン）には、アプリで回答するためのリンクが付きます。
- **コマンド**：`/new`は新しいセッションを開始します（`/new`に続けて内容を書くと、すぐに開始されます）。`/as`と`/agents`は自分のエージェントとして開始します（上記）。`/sessions`は最新のセッションを一覧表示し、1つ選んで続けられます。`/stop`はエージェントを止め、`/status`はチャットがどのセッションにいて何をしているかを知らせ、`/help`はコマンドを一覧表示します。Telegramではコマンドのメニューに、Discordではスラッシュコマンドとして表示されます。Slackでは`/hydor`の後ろに付けます（`/hydor new`。`/hydor`に続けてほかの言葉を書くと、セッションへのメッセージになります）。DiscordとSlackでは、`!new`、`!as`、`!status`などをメッセージとして入力しても使えます。
- **通知**：**すべてのセッションからの通知**の行がオンのとき（オフにしない限り初期状態でオンです）、完了、失敗、またはユーザーの対応が必要になったすべてのセッションが、チャットに通知されます。チャットから始めたセッションだけではありません。

スタンプ、投票、位置情報はエージェントには届きません。チャットでは、代わりに文章、写真、ファイル、音声メッセージを送るよう案内されます。

## 別のデバイスからアプリを使う

初期状態では、アプリはそれが動いているコンピューターでしか応答しません（`127.0.0.1` のポート8790）。アプリに接続でき、パスワードを知っている人は、そのコンピューター上でユーザー権限のままどんなコマンドでも実行できます。そのため、アクセス権はコンピューターへのSSHアクセスと同じように扱ってください。スマートフォンや別のコンピューターから使うには、ポートをネットワークに開放するのではなく、前段にHTTPSを置きます。いちばん簡単な方法は組み込まれています。下の[TailscaleでスマートフォンからHydorを使う](/guide/devices#use-it-on-your-phone-with-tailscale)をご覧ください。スマートフォンがアプリをインストールしたりプッシュ通知を受け取ったりするにも、HTTPSが必要です。

### Tailscaleでスマートフォンから使う

Tailscaleは、自分の端末どうしをつなぐ専用のプライベートネットワーク（tailnet）を作れる無料のアプリです。[設定 → アプリ → スマートフォンで使う](/settings?s=phone)で、Hydorをこのネットワーク上に `https://laptop.tail1234.ts.net` のようなアドレスで公開できます。このアドレスを開けるのは、自分のTailscaleアカウントにサインインしたスマートフォンとコンピューターだけで、インターネットには公開されません。そのうえで、アプリのパスワードも求められます。アプリを一般公開してしまうTailscale Funnelは、オンにしません。

1. このコンピューターにTailscaleをインストールし、サインインします（[tailscale.com/download](https://tailscale.com/download)）。準備ができると、セクションの**このコンピューターのTailscale**の行に「サインイン済みです。このコンピューターは you@example.com の laptop です。」と表示されます。それまでは、足りないもの（未インストール、未起動、未サインイン、オフ）が表示され、**Tailscaleを入手**か、すべき操作と**もう一度チェック**が並びます。
2. [**自分の端末に公開**](/settings?s=phone&find=Serve%20it%20on%20my%20devices)を押します。**アドレス**の行にアプリのアドレスが表示され、**コピー**と**開く**が使えます。アプリはこのアドレスを自動的に受け付けるので、編集するファイルはありません。
3. スマートフォンにもTailscaleをインストールし、同じアカウントでサインインします。
4. [**スマートフォンで開く**](/settings?s=phone&find=Open%20it%20on%20your%20phone)の下にあるQRコードをスマートフォンのカメラで読み取り（またはアドレスを入力し）、アプリのパスワードでサインインします。
5. スマートフォンでは**スマートフォンで使う**が開き、**このスマートフォンで**の下に次の項目が表示されます。**ホーム画面に追加**（iPhoneではSafariで、共有 → **ホーム画面に追加**。通知にはこの操作が必要です。Androidでは**インストール**、またはChromeのメニュー → **アプリをインストール**）、続いて**この端末に通知**、そしてそのスマートフォンだけに通知を送る**テストを送信**です。

**公開を停止**を押すと、アプリはtailnetから外れます。これは**自分の端末に公開**が行った操作だけを元に戻します。つまり、公開した1つのアドレスと、アプリが受け付けるアドレスに追加した分です。Tailscaleで公開しているほかのものは、そのままです。すでに手動でTailscaleを使ってアプリを公開していた場合は、セクションにそのことが表示され（「このページの外で、Tailscale自体を使って設定されています」）、**公開を停止**でそれもオフになります。

アプリを公開している間は、アプリが発行するリンクがこのアドレスで始まるので、スマートフォンでも開けます。チャットアプリでのセッションの**Open in Hydor**や、エージェントが示すセッションや保存したページへのリンクがその対象です。`ALLOWED_ORIGINS` に独自のアドレスが指定されている場合（[ほかの接続方法](/guide/devices#other-ways-to-reach-it)を参照）、リンクはそのアドレスのままです。

ターミナルでは、`hydor machines phone` で同じ内容が表示されQRコードが描画されます。残りは `hydor machines phone serve` と `hydor machines phone stop` で行えます（[ターミナル](/guide/terminal)を参照）。

### うまくいかないとき

セクションに、起きたことが1文で表示され、すべき操作が1つ示されます。

- **tailnetでServeとHTTPS証明書がまだオンになっていません。** Tailscaleがオンにするためのリンクを表示します。**オンにする**でそのリンクが開くので（Tailscaleにサインインして1回確認します）、そのあと**もう一度試す**を押します。
- **Linuxでは、Tailscaleが公開内容を変更できるのはオペレーターだけです。** 表示されたコマンド（`sudo tailscale set --operator=$USER`。自分のユーザー名が入ります）をターミナルで1回実行し、**もう一度試す**を押します。
- **そのアドレスには、すでに別のものが公開されています。** Hydorがそれを置き換えることはありません。**ポート8443で公開**を押すと、代わりに `https://laptop.tail1234.ts.net:8443` でアプリが公開されます。
- **このアドレスでFunnelがオンになっています。** Tailscale Funnelが手動でオンにされているため、インターネット上の誰でもアクセスできます。セクションにその旨と、オフにするコマンドが表示されます。
- **tailnetでHTTPS証明書がオフになっています。** **オンにする**を押すとTailscaleのDNS設定が開くので、MagicDNSとHTTPS Certificatesをオンにします。

### ほかの接続方法

自分で設定する場合は、次のどれでも使えます。

- **手動のTailscale**：このコンピューターで `tailscale serve --bg 8790` を実行すると、アプリが `https://<machine>.<tailnet>.ts.net` で公開され、自分の端末からのみ接続できます。
- **Cloudflare Tunnel**：トンネルを `http://localhost:8790` に向けます。Cloudflare Accessを使うと、手前に2つ目のログインを追加できます。
- **独自のリバースプロキシ**（Caddyなど）：自分のホスト名を `127.0.0.1:8790` に転送します。

プロキシが `Host` ヘッダーを書き換える場合は、アプリを開くアドレスをアプリに伝えます。`ALLOWED_ORIGINS=https://agents.example.com` のように指定します。このような設定は、サービスとしてインストールしたアプリでは `~/.config/hydor.env`（1行に `NAME=value` を1つ）に、Docker Composeでは `.env` に書きます。そのあと、アプリを再起動してください。

開発サーバーのプレビューは専用のポート（8791）を使います。[プレビューで開発サーバーを確認する](/guide/files-git#look-at-a-dev-server-with-preview)をご覧ください。

### パスワードがすべてを守る

パスワードがすべてを守ります。サインインしたブラウザは30日間サインインしたままになります。間違ったパスワードは、直近1時間について、入力元のアドレスごとに数えられます。

- 3回間違えると、サインインページに5文字の画像も表示され、**画像の文字**に入力する必要があります。これにより、プログラムによる当てずっぽうの試行を防ぎます。入力を間違えても何も問題はなく、横の丸い矢印の**新しい画像**を押すと別の画像になります。
- 10回間違えると、そのアドレスからは1時間サインインできません。正しいパスワードでも同じです。ページに残り時間が表示されます。
- どこからであれ合計10回間違えると、全員に画像が表示されます。60回に達すると、1時間が過ぎるまで誰もサインインできません。

上記のプロキシの内側では、プロキシが渡してくる、訪問者自身のアドレスが数えられます。ロックアウトされたときは、別のネットワーク（スマートフォンのモバイルデータなど）からサインインするか、待つか、コンピューター上で新しいパスワードを設定します。新しいパスワードを設定すると、すべての制限が解除されます。[パスワードを変更する](/guide/app#change-your-password)をご覧ください。

## 1つのアプリで別のマシンを使う

Hydorを複数のマシン（デスクトップ、GPUサーバー、クラウドコンピューター）で動かしている場合、そのうちの1台からすべてを使えます。各マシンは、自分のセッション、ファイル、ターミナル、サインイン、設定を持ちます。開いているアプリには一度に1台のマシンが表示され、サイドバーで切り替えます。

設定は[設定 → アプリ → マシン](/settings?s=machines)で行います。**マシン**グループ（タイトルの横に**マシンを追加**があります）は、まずこのマシン（「This server」とそのバージョン）が並び、続いて追加したマシンが並びます。それぞれに次の項目があります。

- ドット：応答していれば緑、接続中は灰色、応答しなければ赤です。
- 接続方法（`ssh gpu-box` またはアドレス）と状態：「オンライン」、「2件が対応待ち・1件が実行中」、「接続中…」、「接続できません」（理由つき）。
- **開く**（そのマシンのページ）と、**編集**と**外す**がある **⋯** メニュー。応答しないマシンには**今すぐ再試行**ボタンもあります。

### マシンを追加する

1. **相手のマシンで**Hydorをインストールし、このマシン用のアクセストークンを作ります。相手側の[設定 → アプリ → マシン](/settings?s=machines&find=Access%20from%20other%20machines)で**新しいトークン**を押すか、そのHydorフォルダで `node dist/server/cli.js access-token "my laptop"` を実行します。トークン（`acm_` で始まります）をコピーします。
2. **こちらで**[設定 → アプリ → マシン](/settings?s=machines&find=Add%20a%20machine)を開き、**マシンを追加**をクリックします。
3. **名前**を付けます（「GPU box」など）。
4. **接続方法**で、このマシンからの到達のしかたを選びます。
   - **SSH経由**（いちばん簡単です）：**SSHホスト**（`~/.ssh/config` にある名前、または `user@host`）と**ポート**（そちらでHydorが待ち受けているポート、8790）を入力します。このマシンは自分のSSHキーで接続を開きます。キーはパスフレーズの入力なしで使える必要があります。相手のマシンは自分の `127.0.0.1` だけで待ち受けたままなので、そちらで開放するものはありません。
   - **アドレスで接続**：プライベートネットワーク、TailscaleやWireGuardなどのVPN、またはHTTPSの背後にある場合に使います。例：`http://100.64.0.5:8790`。そちらのアプリは、このマシンから到達できる場所で待ち受けている必要があります（`HOST` 設定）。
5. **アクセストークン**を貼り付けて、**接続**をクリックします。

アプリは、マシンが応答することを確認してから保存します。応答がない場合は、ダイアログに理由（「GPU boxを使用できませんでした：…」）が表示され、何も追加されません。

### マシンを切り替える

マシンを追加すると、サイドバーの上部、**新しいセッション**の上に、現在のマシン名の行が表示されます。クリックすると、すべてのマシンが状態とともに表示され、表示中のものにはチェックが付きます。1つ選ぶと、そのマシンのページに移ります。**マシンを追加・変更**を押すと、設定 → マシンが開きます。

ほかのマシンのページでは、この行が強調表示されるので、今どこにいるかが分かります。この行は、今見ていないマシンで起きたことも知らせます。ほかのマシンのページを見ているときは、自分のマシンについても同じです。

- アクセントカラーの丸い印の数字は、前回そのマシンを見た後にそちらで完了したセッションの数です。ポインターを合わせると「他のマシンで完了：3」と表示されます。
- オレンジのドットは、そちらでセッションが対応を待っていることを示します。

「前回見た後」はマシンごとに数えます。ページがあるマシンを表示している間は、そのマシンの分は数えません。そのマシンから離れると、その後にそちらで完了したセッションが数えられ、再びそちらを見るまで続きます。見るというのは、そのセッションの1つを開くか、そのマシンに切り替えるだけでも構いません。

メニューでは、各マシンに「2件完了 · 1が対応待ち · 3件作業中」のような行が付きます（ほかのマシンのページにいるときは、自分のマシンにも付きます）。その下には、そちらで完了したセッションが最大3件、それぞれチェック（失敗したときは×）と時刻つきで並びます。クリックすると、そのマシンでそのセッションが開きます。[設定 → マシン](/settings?s=machines)にも同じ行が表示されます。

マシンの更新中は、その行に「更新中 · 45%」、またはいま進んでいるステップが表示されます。新しいバージョンに再起動中のマシンは、「接続できません」の代わりに、オレンジのドットを点滅させて「再起動中…」と表示し、自動的に戻ってきます。それ以外でマシンが応答しない場合は、ページに「…に接続できません」と表示され、**もう一度試す**、自分のマシンに戻るボタン、**設定 → マシン**が並びます。

行のあるサイドバーを隠している間は、代わりにアイコンバーの**セッション**タイルに小さなドットが付きます。ほかのマシンで何かが完了したときはアクセントカラー、そちらで対応待ちのものがあるときはオレンジです。

### マシンのHydorが古いとき

開いているアプリは、ほかのマシンのページを、そのマシンのHydorのバージョンにかかわらず、このアプリのバージョンで表示します。古いHydorのマシンでは、ページに必要なものが足りず、動かなくなるページがあるかもしれません。そのため、このアプリより古いHydorのマシンを選ぶと、先に「…のHydorは古いバージョンです」というページが表示されます。ここには両方のバージョンと、そのマシンのページがこのアプリのバージョンで開くこと、古いバージョンでは動かなくなるページがあることが書かれています。ボタンは3つあります。

- **更新…**（マシン名つき）：そのマシンを、ここから更新します。[設定 → アプリ → 一般](/settings?s=general&find=Check%20now)でバージョンの行にある**今すぐ更新**ボタンと同じ動作です（[アプリを最新の状態に保つ](/guide/app#keep-the-app-up-to-date)を参照）。gitからインストールしたコピーやDockerイメージは新しいバージョンを取得してビルドし、再起動します。デスクトップアプリは新しいバージョンをダウンロードして、再起動します。数分かかりますが、そこで動いているエージェントは作業を続けます。ページには各ステップ（「新しいバージョンを取得中」「パッケージをインストール中」「ビルド中」「再起動中。このページは自動的に再接続します」）が表示されます。gitからインストールしたコピーでは、さらにどこまで進んだかとして、パーセンテージ、水が満ちていくバー、「ステップ2／3 · 残り約2分」のような行が表示されます（デスクトップアプリでは、新しいバージョンのダウンロードの進み具合をバーで）。古いHydorのマシンは進み具合を伝えられないため、ページは、いまのステップとそれまでにかかった時間から推定し、分かるときだけ残り時間を表示します。マシンの行にも同じ「更新中 · 45%」が表示され、マシンが戻ると、そのマシンのページが自動的に開きます。0.78.0より古いgitやDockerのコピーは、Hydorの書き換えられた履歴を越えて自力で更新できません（「Not possible to fast-forward, aborting.」）。その場合、ページにそう表示され、そのマシンで1回実行するコマンドが示されます（[古いコピーを手動で更新する](/guide/app#update-an-older-copy-by-hand)を参照）。
- **このまま開く**：そのマシンのページをそのまま開きます。このブラウザタブでは、そのバージョンについて再び確認されることはありません。
- **開く**に続けて自分のマシン名：自分のマシンに戻ります。

ここから更新できない場合は、代わりに理由がページに表示されます。たとえば、今ある場所では自分自身を置き換えられないデスクトップアプリ（「Hydorをアプリケーションフォルダに移動してから更新してください。」）、更新元がないコピー（「…には自力で更新できる元がありません（upstreamのあるgitからインストールされていません）。そちらでHydorを更新するか、このまま開いてください。」）、更新の失敗（「更新できませんでした：…」）、先に再起動が必要な場合（「新しいバージョンは入っています。使うには…でHydorを再起動してください。」）、すでに更新元と同じ新しさの場合です。

ほかのマシンのページが描画に失敗すると、空のウィンドウではなく「このページは動作を停止しました」と原因が表示され、**再読み込み**と、自分のマシンの**開く**が出ます。サイドバーはそのまま残り、別のページに移るともう一度試されます。古いHydorのマシンでは、ページに上記の**更新…**が表示されます。このアプリより新しいHydorのマシンでは、このアプリを更新してから、もう一度そのマシンを開くよう表示されます。

### マシンをまたいで使えるもの

- **マシンのページにあるものは、すべてそのマシンのものです**：セッション、フォルダとファイル、Git、ターミナル、エージェントのサインイン、モデル、設定。
- **常にアプリを開いたマシンから来るものがあります**：パスワードとサインイン、マシンの一覧、通知、作成したテーマ、ウェルカムツアーとそのヒント。
- **すべてのマシンからのお知らせが届きます。** ほかのマシンからのお知らせにはそのマシン名が付き、プッシュ通知は自分のマシンを通して届き、[受信トレイ](/guide/inbox)には、すべてのマシンで対応を待っているものが並びます。アイコンバーの**受信トレイ**の件数にも含まれます。サイドバーのマシンの行は、ほかのマシンのうち、前回そちらを見た後に完了したセッションがあるものも知らせます（[マシンを切り替える](#switch-between-machines)を参照）。
- **プロジェクトはマシン間で移せます**：プロジェクトの ⋯ メニュー → **別のマシンに送信…** から、別のマシンへのコピー、移動、コピーとの同期ができます（[プロジェクトを別のマシンに送信する](/guide/projects#send-a-project-to-another-machine)を参照）。セッションは元のマシンに残ります。
- **読み取り専用リンク**は、ほかのマシンのセッションでも使えます（[読み取り専用リンクでセッションを共有する](/guide/devices#share-a-session-with-a-read-only-link)を参照）。
- **ほかのマシンでは使えないもの**：プレビュー（開くのは、アプリを開いたマシンの開発サーバーだけです）と、ほかのエージェントを接続する機能（各マシンのサーバーには、それぞれのアドレスで接続するためです）。
- ブラウザは、ファイルページのフォルダ、開いているファイル、最後に使ったターミナルを、マシンごとに別々に覚えています。

### マシンを変更する・外す

- **編集**では、名前、接続方法、アクセストークンを変更できます。トークンを空のままにすると、今のトークンが維持されます。接続方法を変更した場合は、保存する前にもう一度確認されます。
- **外す**は、先に確認が表示されます。そのマシンのセッションはそのマシンに残り、このアプリでは表示されなくなります。

### このマシンをほかのマシンから使えるようにする

**ほかのマシンからのアクセス**グループ（ほかのマシンのページでは**Access to**そのマシン）で、ほかのマシンがこのマシンに接続するためのトークンを作ります。このトークンを持つほかのHydorは、コマンドの実行を含め、ここで自分ができることをすべて行えます。そのため、接続するマシンごとにトークンを1つずつ作ってください。

1. グループのタイトルの横にある**新しいトークン**をクリックします。
2. **どのマシンで使いますか？**に答え（「My laptop」など）、**トークンを作成**をクリックします。
3. トークンをコピーして、相手のマシンの設定 → マシンに貼り付けます。トークンが表示されるのは、このときだけです。

各トークンには、作成日時と最終使用日時が表示されます。**⋮** メニューの**無効にする**（確認のあと）で、そのマシンをすぐに切り離せます。

## セッションを閲覧専用リンクで共有する

閲覧専用リンクを使うと、パスワードを知らない相手でも、1つのセッションの進行をリアルタイムで見られます。セッションのメニュー（⋯）→ **閲覧専用リンクを共有**を開きます。プロジェクト全体（ドキュメント、セッション、実行、読み物リスト、名前付きのコメント）を相手と共有する場合は、[人とプロジェクトを共有する](/guide/projects#share-a-project-with-people)を参照してください。保存した1つのもの（ドキュメント、ページ、画像、動画など）を共有してコメントや編集をしてもらう場合は、[人と共有する](/guide/library#share-with-people)を参照してください。

1. **有効期間**で、**1日**、**1週間**、**1か月**、**オフにするまで**のいずれかを選びます。
2. **リンクを作成**をクリックします。
3. リンクをコピーして送ります。リンクが表示されるのは1回だけですが、いつでも新しく作成できます。

**現在有効なリンク**には、そのセッションで有効なリンクが一覧表示されます。各リンクについて、作成日時、終了日時（オフにするまで有効なものは「期限なし」）、開かれた回数、最後に開かれた日時が分かります。**オフにする**（ゴミ箱アイコン）をクリックすると、リンクがすぐに無効になります。

### 相手に見えるもの

リンクを開くと、サイドバーも入力欄もない、そのセッションだけの画面が表示されます。セッションのタイトル、作業しているエージェント、「閲覧専用、Hydorから共有」、エージェントが作業中の間は「作業中」と表示されます。その下には会話が表示されます。自分のメッセージ、エージェントの返信、名前付きのステップ（各ファイルの変更で追加・削除された行数つき。変更内容そのものもクリックで確認できます）、エージェントが見せたページです。エージェントの作業中は、数秒ごとに自動で更新されます。

コマンドの出力、エージェントの思考、添付した画像（添付があったことのみ表示）、アプリ内のそのほかの内容は見えません。入力や変更もできません。期限が切れたリンクやオフにしたリンクには「このリンクは期限切れか、オフにされています」と表示されます。

## ほかのエージェントをこのアプリに接続する

別の場所で動くエージェント（ノートパソコンのClaude Code、Codex、Cursor、MCPに対応した任意のクライアント。MCPはエージェントがツールを呼び出すためのプロトコルです）は、アプリ自身のMCPサーバーを通じて、このマシンのセッションを一覧表示、閲覧、開始、操作できます。それぞれにトークンが必要で、[設定 → アプリ → ほかのエージェントを接続](/settings?s=connect)で作成します。トークンを持つエージェントは、ここで自分が行うのと同じようにセッションを開始・操作できます。

1. **トークン**グループのタイトルの横にある[**新しいトークン**](/settings?s=connect&find=New%20token)をクリックします。
2. **使う場所にちなんだ名前を付けてください**の欄に「ノートパソコンのClaude Code」のような名前を入力し、**トークンを作成**をクリックします。
3. 必要なものをここでコピーします（再表示はされません）。
   - **トークン**：トークンそのものです。
   - **Claude Code**：サーバーを追加するコマンド `claude mcp add --transport http hydor <address>/mcp --header "Authorization: Bearer <token>"` です。
   - **Codex**：`~/.codex/config.toml` に書く行です。トークンは環境変数 `HYDOR_TOKEN` に入れます。
   - **その他のクライアント（JSON）**：一般的なMCPサーバーの設定項目です。

アドレスはブラウザで開いているものと同じです。そのため、別のマシンのエージェントは、ブラウザと同じ方法でアプリに接続できる必要があります（[別のデバイスからアプリに接続する](/guide/devices#reach-the-app-from-another-device)を参照）。

**トークン**の一覧には、各トークンの名前、作成日時、最後に使われた日時が表示されます。エージェントやマシンごとに1つずつ作成すると、1つずつ**無効にする**ことができます（トークンの**⋯**メニューから）。無効にすると、そのエージェントはすぐに接続できなくなります。

### できること

トークンの下にある[**できること**](/settings?s=connect&find=What%20they%20can%20do)の行には(i)があり、トークンを持つエージェントが使えるツールが一覧表示されます。

- **list_sessions**と**read_session**：セッションを探し、内容を確認します（メッセージと、名前付きのステップ）。
- **start_session**：最初のメッセージを付けて、任意のフォルダで新しいClaude CodeまたはCodexのセッションを開始します。必要に応じて専用のワークツリーも使えます。開けるリンクが返されます。
- **send_message**：セッションを操作します。エージェントが処理中の場合、メッセージはそのターンが終わるまでセッションのキューで待機します。
- **list_models**：新しいセッションで使えるモデルです。

ほかのエージェントに提供するアプリ（アプリの**ほかのエージェントに提供**スイッチ。[アプリ](/guide/apps)を参照）もツールとして提供され、フォームの項目を指定してアプリを実行します。

このアプリで開始したセッションには、これらの設定は不要です。この項目は、アプリを開いているマシンにのみ表示され、ほかのマシンのページには表示されません。

## GitHubまたはGiteaのアカウントを追加する

プルリクエストは、[設定 → アプリ → ソース管理](/settings?s=scm)のアカウントを使って作成します。各アカウントは、そのサーバー上のリポジトリを対象とします。対象はGitHub、GitHub Enterpriseサーバー、Giteaサーバーです。プッシュ自体はこのコンピューターのgit設定（SSHキーや保存済みの認証情報）を使います。アカウントは、プルリクエストの作成とチェック状況の確認に使います。

1. **アカウント**グループのタイトルの横にある[**アカウントを追加**](/settings?s=scm&find=Add%20an%20account)をクリックします。ダイアログが開きます。
2. **GitHub**または**Gitea**を選びます。
3. GitHubの場合：このコンピューターのGitHub CLIがサインイン済みなら、**そのサインインを使う**をクリックするだけでアカウントが追加され、完了です。そうでない場合は**アクセストークン**を貼り付けます。リポジトリに対するPull requests（読み取りと書き込み）、Contents（読み取り）、Commit statuses（読み取り）の権限を持つ細粒度トークンです（**作成**をクリックするとGitHubのページが開きます）。**サーバーアドレス**はGitHub Enterpriseの場合のみ入力します。
4. Giteaの場合：**サーバーアドレス**（`https://gitea.example.com`）と、Giteaの設定 → アプリケーション → トークンを生成で作成した**アクセストークン**（リポジトリの読み取りと書き込みの権限）を入力します。
5. **追加**をクリックします。アプリはサーバーにトークンの持ち主を問い合わせてトークンを確認し、そのユーザー名でアカウントを一覧に表示します。

同じサーバーのアカウントをもう1つ追加すると、最初のアカウントが置き換えられます。各アカウントは1行で表示され、ユーザー名、サーバー、該当する場合は「GitHub CLI経由」と表示されます。**⋯**メニューには**サーバーを開く**と**外す**があり、**外す**は先に確認が表示されます。セッションにすでに関連付けられているプルリクエストは関連付けられたままですが、状態は更新されなくなります。

プルリクエストの作成と追跡の方法は、[セッションからプルリクエストを作成する](/guide/files-git#open-a-pull-request-from-a-session)を参照してください。
