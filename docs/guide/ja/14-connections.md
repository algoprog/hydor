# 接続済みアプリ、キー、ツール

普段使っているサービス（メール、Notion、GitHub、Stripe、このコンピューター上のフォルダなど）を、アプリページの**接続済みアプリ**で一度接続すれば、すべてのエージェントとアプリがそれらを利用できます。APIキーやサインイン情報は、エージェントが中身を見ることなく使える暗号化された保管庫に保存できます。Claude CodeとCodexにはツールサーバーを、Claude Codeにはプラグインを追加できます。エージェントに自分のアカウントで作業させたいとき、キーを使ってサービスを呼び出したいとき、標準では持っていないツールを使わせたいときに便利です。

![アプリ → 接続済みアプリ：接続したサービス、マーケットプレイス、キー](images/connections.webp)

## 接続、キー、ツールとは

エージェントは、ツールを与えるとより多くのことができるようになります。ツールを与える方法は3つあります。

- **接続済みアプリ**（[アプリ → 接続済みアプリ](/apps/connected)）：マーケットプレイスのサービスを一度接続すると、Claude Code、Codex、Custom、ACPに対応するエージェント、そしてそれらが実行するアプリのすべてで使えます。接続したアカウントごとに、そのツールがエージェントに提供されます。
- **保管庫**（同じページの**キー**タブ）：APIキー、トークン、サインイン用のパスワードを保管します。APIキーとは、プログラムからアカウントを使えるようにサービスが発行するパスワードのようなものです。エージェントはこれらを使って、サービスの呼び出し、サイトへのサインイン、プログラムの実行を行いますが、中身を見ることはありません。
- **MCPサーバーとプラグイン**（[設定 → MCPサーバー](/settings?s=mcp)と[設定 → プラグイン](/settings?s=plugins)）：Claude Code、Codex、Custom向けに自分で用意するツールサーバーと、スキルやツールをすべてのエージェントに追加するプラグインです（[プラグイン](/guide/plugins)を参照）。

MCP（Model Context Protocol）は、サービスがエージェントにツールを提供するための共通の仕組みです。接続したアカウントは、Hydorがすべてのエージェント向けに設定してサインインするMCPサーバーです。設定 → エージェントにあるMCPサーバーは、コマンドやアドレスを指定して手動で設定するものです。

## 接続済みアプリを開く

アイコンバーから**アプリ**を開き、その列で**接続済みアプリ**を選びます（スマートフォンでは**接続済みアプリ**タブ）。または[アプリ → 接続済みアプリ](/apps/connected)に移動します。（以前は「接続」として設定の中にありました。古いリンクからもここに移動します。）用途を説明する一文と**サービスを接続**の下に、3つのタブがあります。

- **接続済み**：接続したアカウントと、それぞれの状態です。タブの数字は接続数を表し、列の**接続済みアプリ**（スマートフォンではそのタブ）にも同じ数が表示されます。
- **マーケットプレイス**：接続できるすべてのサービスです。
- **キー**：保管庫です。タブの数字はキーの数を表します。

何かを接続済みの場合はページが**接続済み**で開き、まだ何も接続していない場合は**マーケットプレイス**で開きます。各タブには専用のアドレスがあります（`/apps/connected?tab=market`、`?tab=keys`）。スマートフォンではタブが横にスクロールし、ダイアログは画面の下から表示されます。

## マーケットプレイスでサービスを探す

[マーケットプレイスタブ](/apps/connected?tab=market)を開きます。

- 検索ボックス（「サービスを検索：メール、Notion、請求書…」）では、名前、説明、キーワード、カテゴリが対象になります。入力した単語はすべて一致する必要があります。
- カテゴリは、それぞれのサービス数とともに、1つずつ表示されます。**すべてのサービス**（チップでは**すべて**）、**メモとドキュメント**、**タスクとプロジェクト**、**メール、チャット、会議**、**カレンダーとスケジュール**、**ファイルとストレージ**、**デザインとメディア**、**開発ツール**、**クラウドとホスティング**、**データベースとデータ**、**分析とモニタリング**、**営業、マーケティング、サポート**、**支払いと金融**、**Webサイトとショップ**、**検索とWeb**、**AIと自動化**、**旅行と日常**、**このコンピューター**です。コンピューターではサービスの横に一覧で表示され、画面が狭い場合は検索ボックスの下に横スクロールのチップで表示されます。
- **おすすめ**：よく知られたサービス（Notion、Linear、GitHub、Figma、Stripe、Zapierなど）を大きなカードで並べた行です。検索やカテゴリの選択をしていない間だけ表示され、コンピューターでは矢印でスクロールできます。サービスはその下に、**すべてのサービス**（選んだカテゴリ、検索時は**見つかりました**）として件数とともに続きます。スマートフォンでは1つのリストの行として表示されます。

各カードには、サービスの名前、エージェントがそのサービスで何をできるか、接続の方法が表示されます。

- **ブラウザでサインイン**：ブラウザでアカウントにサインインします。
- **APIキー**：サービスが発行するキーを貼り付けます。
- **サインイン不要**：入力するものはありません。
- **このコンピューターで実行**：エージェントが必要とするときに、Hydorがここで起動するプログラムです。
- **ここで実行（キー使用）**：上と同じですが、指定したキーを使います。
- **アドレスとアプリパスワード**：メールアドレスと、メールプログラム用に作成したパスワードです（メール）。

名前の横のチェックマークは、サービスのサーバーが掲載内容どおりに応答することを誰かが確認済みであることを示します。**未確認**は、まだ誰も確認していないという意味です。接続したサービスには、ほかのサービスの**接続**の代わりに**接続済み**（または**もう一度サインイン**）と表示されます。

掲載されているサービスの例です。

- **メモ、タスク、プロジェクト**：Notion、Craft、Linear、Asana、Atlassian（JiraとConfluence）、ClickUp、monday.com、Todoist。
- **メール、チャット、カレンダー**：メール（アプリパスワードを使う任意のメールアカウント）、Gmail、Slack、Fireflies、Granola、Googleカレンダー、Calendly。
- **ファイルとデザイン**：Google Drive、Dropbox、Box、Figma、Canva、Miro、Gamma、Cloudinary。
- **開発ツールとホスティング**：GitHub、GitLab、Sentry、CircleCI、Postman、Cloudflare、Vercel、Netlify、Railway、Context7、DeepWiki。
- **データと分析**：Airtable、Supabase、Neon、PostgreSQL、MongoDB、SQLite、PostHog、Mixpanel、Amplitude、Datadog。
- **ビジネス**：Stripe、PayPal、Plaid、Square、HubSpot、Intercom、Attio、Klaviyo、Webflow、Wix、WordPress.com。
- **検索とWeb**：Exa、Perplexity、Tavily、Brave Search、Firecrawl、Wolfram、Playwrightブラウザ。
- **AIと日常生活**：Hugging Face、Zapier、AllTrails、Kiwi.com、trivago、Strava。
- **このコンピューター**：このコンピューター上のファイル（選んだフォルダ）、Git、時刻、メモリグラフ。

一致するサービスがない場合は、ページに**一致するサービスがありません**と表示されます。サービスは自分で追加することもできます。[マーケットプレイスにサービスを追加する](/guide/connections#add-a-service-to-the-marketplace)を参照してください。新しいサービスは、アプリのアップデートで追加されます。

## サービスを接続する

1. サービスのカードをクリックします。ダイアログに、サービスの機能、カテゴリ、接続方法、日付付きの**確認済み**（または**アドレスはまだ確認されていません**）が表示されます。**ウェブサイト**と**ドキュメント**はそのサービスへのリンクです。実行場所を示す欄には、サーバーのアドレス、またはここで実行するコマンドが表示されます。また、すべてのエージェントがサービスのツールを短い名前（Notionなら「notion」）で利用できること、セッションごとにオフにできることも記載されています。
2. 黄色い枠内の注意書きがあれば読みます。「このコンピューターにuv（uvx）が必要です。」のような事前に知っておくべきことや、サービスに独自のサインインクライアントが必要なことが書かれています。
3. ダイアログで求められる項目を入力し、**接続**、または**サインイン**とサービス名をクリックします。

接続後、サービスは**接続済み**タブに移り、バックグラウンドでテストされます。ダイアログで求められる内容は、サービスによって異なります。

### 入力不要のサービス

**接続**をクリックします。先に設定を求めるものもあります。GitLabはアドレスを求めます（自前で運用していなければgitlab.com）。このコンピューター上のファイルは、使用してよいフォルダをフルパスで1行に1つずつ求めます。読み書きできるのは、そのフォルダの中のファイルだけです。SQLiteはデータベースファイルを求めます。**任意**と書かれた項目は空のままでも構いません。項目の横の**取得**は、その値を入手できる場所へのリンクです。

### キーを使うサービス

インターネット上のサービスには**キー**欄があり、**キーを取得**からキーを作成するページに移動できます。ここで実行するサービスは、専用の欄（トークン、接続文字列など）にキーを入力します。キーを貼り付けて**接続**をクリックします。

キーは暗号化されて保管庫に保存されます。以降は、末尾の数文字だけが表示されます。たとえばGitHubでは、きめ細かい個人用アクセストークンを使います。これは、エージェントに許可するリポジトリや権限を限定できるキーです。

### ブラウザでサインインするサービス

1. **サインイン**とサービス名をクリックします。
2. コンピューターでは小さなウィンドウが開きます。スマートフォンでは、代わりに同じタブでサービスのサインインページが開きます。
3. サインインしてアクセスを許可します。その間、ダイアログには「サインインが完了するのをお待ちしています…」と表示されます。
4. 完了すると、アカウントが接続されたことを知らせる通知が表示されます。スマートフォンでは、アプリ → 接続済みアプリに戻ります。

トークンはこのコンピューター上で暗号化されたまま保存され、自動的に更新されます。エージェントがトークンを見ることはありません。サインインは15分以内に完了する必要があり、それを過ぎた場合は最初からやり直します。アクセスを拒否すると、「アクセスが許可されませんでした」と表示されます。

サービスによっては、自分で用意したサインインクライアント（OAuthアプリ）でしかサインインできません。たとえばAsana、Box、HubSpot、Slack、Googleのアプリなどです。これらのダイアログでは**独自のクライアントID（このサービスでは必須）**が開き、手順が表示されます。ほかのブラウザでのサインインでは、同じ内容が**独自のクライアントIDを使用（任意）**として用意されています。サービスがアプリの自動登録を認めていないと分かった場合にも、自動的に開きます。

1. サービスの開発者設定でクライアントを作成します。
2. **相手に伝えるコールバックアドレス**に表示されたアドレスを設定します（コピー用のボタンがあります）。
3. **クライアントID**と、ある場合は**クライアントシークレット**を貼り付けます。
4. **サインイン**とサービス名をクリックします。

### このコンピューターで実行するサービス

これらは、セッションのエージェントごとに、ここでプログラム（npxまたはuvx）を起動します。プログラムを先にダウンロードする必要がある場合、最初のテストには時間がかかることがあります。サービスに必要なキーは、起動時に保管庫から環境に渡されます。ほかのプログラムが読み取れるコマンドラインに表示されることはありません。

## メールを接続する

メールアカウントをアドレスとアプリパスワードで接続すると、エージェントがメールの閲覧、検索、整理、下書き、送信を行えるようになります。Gmail、iCloud Mail、Fastmail、Yahoo、AOL、GMX、WEB.DE、Zoho、Posteo、mailbox.org、Proton Mail（Proton Mail Bridge経由）のほか、ほとんどの職場や学校のメールで利用できます。

1. [マーケットプレイスタブ](/apps/connected?tab=market)を開き、**メール**（**メール、チャット、会議**の中、または「email」で検索）をクリックします。
2. **メールアドレス**を入力します。Hydorがメールサーバーを自動で見つけます。Hydorが把握しているプロバイダでは、そこでのアプリパスワードの作成方法が表示され、**作成方法**をクリックするとプロバイダ自身のヘルプページが開きます。
3. アプリパスワードを作成し（下記参照）、**アプリパスワード**に貼り付けます。
4. 必要であれば**名前**を入力します。送信するメールで相手に表示される名前です。
5. **接続**をクリックします。Hydorは、何かを保存する前に、受信と送信のサインインを試します。失敗した場合は、パスワードやユーザー名の間違い、通常のパスワードではなくアプリパスワードが必要なこと、サーバーが応答しなかったことなど、理由が表示されます。

アプリパスワードは、このコンピューターの保管庫に暗号化されて保存され、エージェントが見ることはありません。別のアカウントを接続するには、もう一度**メール**を開き、**別のアカウントを追加**をクリックします。

### アプリパスワードを作成する

アプリパスワードとは、メールプログラム専用の別のパスワードで、アカウントのセキュリティ設定で作成し、Webでのサインインに使うパスワードの代わりに使います。ほとんどのプロバイダでは、先に2段階認証を有効にする必要があります。

- **Gmail**：Googleアカウントで2段階認証プロセスを有効にしてから、**セキュリティ → アプリパスワード**を開きます。職場や学校のアカウントでは、管理者の許可が必要です。
- **iCloud Mail**：account.apple.comで**サインインとセキュリティ → App用パスワード**を開きます。
- **Fastmail**：**設定 → プライバシーとセキュリティ → アプリパスワードを管理**。
- **Yahoo**と**AOL**：**アカウントセキュリティ → アプリパスワードを生成**。
- **GMX**、**WEB.DE**、**Zoho**：先にメールボックスの設定でIMAPを有効にします。
- **Proton Mail**：Proton Mail Bridgeをインストールしてこのコンピューターでサインインし、Bridgeが表示するアドレス用のパスワードを使います。

### サーバーが見つからないとき

Hydorが把握していないプロバイダの場合は、プロバイダがメールプログラム向けに公開している設定を読み取ります。それを見つけるために、Mozillaが公開しているメールプロバイダのディレクトリにドメインを問い合わせます（アドレス全体を送ることはありません）。見つからない場合は、ドメインの前にimap.とsmtp.を付けて試し、サインインで確認します。

それでも失敗する場合は、**サーバーとユーザー名**を開き、プロバイダのヘルプページに載っている受信（IMAP）サーバーと送信（SMTP）サーバー、それぞれのポート、セキュリティ（**SSL/TLS**または**STARTTLS**）を入力します。ユーザー名がアドレス全体でない場合は、ユーザー名も入力します。暗号化されていない接続が許可されるのは、このコンピューター内（Proton Mail Bridgeのようなブリッジ）だけです。

### Outlook.comとMicrosoft 365

Outlook.com、Hotmail、Liveのアカウントと、Microsoft 365の職場や学校のアカウントは、今のところこの方法では接続できません。Microsoftがこれらのアプリパスワードを無効にしており、Microsoftのサインインが必要ですが、Hydorはまだ対応していません。このようなアドレスを入力すると、メールのダイアログにその旨が表示されます。

### メールアカウント

**接続済み**タブでは、メールの行にアカウントがアドレスで一覧表示されます。**テスト**は各アカウントにサインインして確認します。**アカウント**をクリックするとダイアログが開き、各アカウントに**テスト**、**変化**（新しいアプリパスワード、名前、サーバー）、**外す**があります。**外す**を選ぶと、そのアプリパスワードはここから削除されますが、メールボックスの中身は何も変わりません。最後のアカウントを外すとメールの接続が解除されます。**接続を解除**は、すべてのアカウントを外します。

### エージェントがメールでできること

エージェントは、これらのツールを「email」の名前で利用できます。アカウントが複数ある場合は、各ツールでアカウントのアドレスを指定します。指定しなければ、最初のアカウントが使われます。

- **list_folders**、**search_email**（送信者、宛先、件名、単語、日付、未読、フラグ付き、添付ファイル付きで検索し、新しい順）、**read_email**（送信者と宛先、本文、添付ファイルの名前とサイズ）。閲覧しても、メールは既読になりません。
- **save_attachments**は、メールの添付ファイルをセッションのフォルダに保存します。
- **mark_email**は、メールを既読または未読、フラグ付きまたはなしにします。**move_email**は、メールを別のフォルダに移動します。ゴミ箱には移動しません。
- **save_draft**は、メールを下書きフォルダに入れ、自分で送信できるようにします。何も送信されません。
- **send_email**は、新規メールまたはスレッドへの返信として、セッションのフォルダのファイルを添付して、メールをすぐに送信し、送信済みにコピーを残します。
- **delete_email**は、メールをゴミ箱に移動するか、完全に削除します。

エージェントによる送信や削除を防ぐには、**ツール**で**send_email**と**delete_email**をオフにします（[アカウントやツールの一部をオフにする](/guide/connections#turn-an-account-or-some-of-its-tools-off)を参照）。メールの内容は外部のデータとしてエージェントに渡され、指示として従わないよう伝えられています。新しいメールが届くたびにスケジュールタスクを開始することもできます。[変化を監視する](/guide/tasks#watch-for-a-change)を参照してください。

## 接続済みアカウントが動作するか確認する

**接続済み**タブでは、各アカウントの状態が次のように表示されます。

- **実行中**：最後に確認した時刻、オンになっているツールの数（「14個中12個のツールがオン」）、そのうち事前に確認するものの数（「3個は事前に確認」）。
- **まだテストしていません**。
- **再度サインインが必要です**：サインインの有効期限が切れ、更新できなかった状態です。
- **動作していません**：理由も表示されます。

**テスト**は、エージェントが使うときと同じ方法でサービスに接続し、ツールの一覧を取得します。アカウントが動作していること、ツールの数、または問題の内容が通知で表示されます。たとえば「キーが拒否されました」や「サインインが拒否されました：もう一度接続してください」（この場合、アカウントは**再度サインインが必要です**と表示されます）などです。アカウントは接続した直後に自動でテストされます。

## アカウントやツールの一部をオフにする

- **すべてのセッション**（スマートフォンではスイッチのみ）：オンの場合、セッションでオフにしていない限り、すべてのセッションのエージェントがそのアカウントを使えます。オフの場合、そのセッションでオンにしない限り、どのセッションでも使えません。新しく接続したアカウントはオンの状態から始まります。
- **ツール**：テストでアカウントのツールの一覧を取得すると、このボタンから一覧を開けます。各ツールには機能の説明と3つの選択肢があります。**オン**（エージェントが自由に使えます）、**事前に確認**（呼び出しのたびに、送信するまで**送信トレイ**で待機します。詳しくは後述）、**オフ**（エージェントは使えません）です。送信、投稿、公開、返信、招待、共有、削除、取り除き、支払い、送金、返金を行うツールには**外部に作用します**の印が付きます。オフにしたツールを使おうとしたエージェントには、そのツールがオフであることが伝えられます。

## 事前に確認：OKを待つ呼び出し

**事前に確認**にしたツールが、すぐに呼び出されることはありません。エージェント（Claude Code、Codex、Custom、その他のエージェント、スケジュールタスクの実行、またはアプリ）がツールを呼び出すと、Hydorがその呼び出しを保留します。エージェントには、呼び出しがOKを待っていることがすぐに伝えられます。エージェントは待たずに残りの作業を続けるか、その旨を伝えてターンを終えます。別の方法でやり直さないようにも指示されます。保留された呼び出しは、[受信トレイ](/inbox)の先頭にある**送信トレイ**に下書きとして置かれ、内容を変更してから**送信**または**破棄**できます（[送信トレイ：OKを待つ呼び出し](/guide/inbox#the-outbox-calls-held-for-your-ok)）。

- 今後接続するアカウントでは、外部に作用するツールはすべて**事前に確認**、それ以外は**オン**の状態から始まります。どのツールも**ツール**で変更できます。
- 以前に接続したアカウントのツールは、そのまま変わりません。すでにそれらを使っているものは引き続き動作します。そのカードには、「**送信・投稿・削除・支払いを行う3個のツールを事前に確認にする**」のような1行が表示されます。クリックすると、該当するツールをまとめて事前に確認にできます。自分で選んでいないのにそのようなツールがオンになっている間、この行が表示されます。
- 事前に確認はアカウントごとの自分用の設定なので、すべてのセッションと、**フルアクセス**を含むすべての権限モードで有効です。エージェントは、カードで確認を求めずに設定を変えることはできず、保留された呼び出しを自分で送信することもできません。エージェントがツールの使用前に確認を求める場合（Claude CodeやCustom自身のカード）でも、その確認は行われません。OKは送信トレイで一度出すだけです。
- ツールが外部に作用するかどうかは、名前、説明、サービスが示すヒント（「読み取り専用」や「削除する」など）から判断されます。印を確認し、そのほかのツールも必要に応じて自分で事前に確認にしてください。

何も外部に送らずにスケジュールタスクを試すには、**送信せずにテスト**を使います（[スケジュールタスク](/guide/tasks#try-a-task-with-a-test-run)）。

## 接続を変更する、もう一度サインインする

- **変化**（キーや設定があるアカウント向け）：入力済みの内容でダイアログをもう一度開きます。設定は値がそのまま残ります。キーとシークレットの欄には「保存済み：空のままにすると維持されます」と表示されます。置き換えるには新しい値を入力し、**保存**をクリックします。
- **もう一度サインイン**（ブラウザでサインインするアカウント向け）：サインインをやり直します。アカウントが**再度サインインが必要です**と表示されている間、サインインし直すまでエージェントはそのアカウントを使えません。

接続した後でマーケットプレイスがサービスのアドレスやサインイン方法を変更した場合、アカウントに「カタログに新しいアドレスまたはサインイン方法があります。もう一度接続するまで、これまでのものを使い続けます。」と表示されます。もう一度自分で接続するまで、キーやサインイン情報が新しいアドレスに送られることはありません。

## アカウントの接続を解除する

**接続を解除**（スマートフォンでは接続を外すアイコン）をクリックし、確認します。アカウントのサインイン情報やキーはここから削除され、エージェントはそのツールを使えなくなります。ブラウザでサインインするアカウントの場合、サービスに方法があれば、Hydorはトークンが不要になったこともサービスに伝えます。

## 1つのセッションで使うアカウントを選ぶ

**すべてのセッション**のスイッチがオンの接続済みアカウントは、すべてのセッションで使えます。1つのセッションだけ変更するには、次の手順にします。

1. セッションのメニュー（⋯）→ **セッション設定** → **接続済みアカウント**を開きます。
2. このセッションでアカウントをオンまたはオフにします。各アカウントには、「すべてのセッションと同じくオン」「すべてのセッションと同じくオフ」「ここだけオン」「ここだけオフ」のいずれかの状態が表示されます。
3. **完了**をクリックします。

インターネット上のサービスには、変更がすぐに反映されます。このコンピューター上で動くサービスには、エージェントが次に起動するときに反映されます。まだ何も接続していない場合、ダイアログには**接続済みアプリを開く**が表示されます。

エージェントは、自分として開始するセッションでアカウントをオンにすることもできます。詳しくは[エージェント](/guide/agents)をご覧ください。

## エージェントが接続済みアカウントを使う仕組み

- どの種類のエージェントも、同じ方法で接続済みアカウントを使えます。Claude Code、Codex、Custom、ACPエージェントは、サービスの短い名前でそのツールを使えます。
- セッションの開始時に、エージェントにはどのアカウントが接続されているかが伝えられ、作業に関係するときはそれらを使うよう指示されます。接続されているものや保存されているキーも、名前だけなら一覧できます。
- エージェントが使えるのは、そのセッションでオンになっていて、サインイン済みのアカウントだけです。サインインはバックグラウンドで更新されます。どのセッションでも使われていないアカウントも同様なので、長いセッションでも使い続けられます。
- キーやトークンが、エージェントの設定やコマンドラインに入ることはありません。サービスのツールが返す内容の中にある既知のキーの値は、伏せ字になります。
- 事前に確認のツールは、説明にそのことが書かれ、呼び出しがOKを待つことがエージェントに伝えられます。呼び出しを送信または破棄すると、セッションに結果が表示され、エージェントは次のメッセージとともにそれを知ります。
- スケジュールタスクは、アカウントに新しいもの（新しい取引、ファイル、チケット、支払い）が現れたとき、または接続済みカレンダーの各予定の一定時間前に開始できます。確認のたびに、Hydorがモデルを使わずに自分で、アカウントの読み取り専用のツールの1つを呼び出します。送信、変更、削除、支払いを行うツールは呼び出しません（[変化を監視する](/guide/tasks#watch-for-a-change)をご覧ください）。
- 検索ボックス（Ctrl+K、Macでは⌘K）でも、接続済みアカウントを検索できます。

## マーケットプレイスにサービスを追加する

マーケットプレイスへのサービスの追加や修正は、GitHubにあるHydorのリポジトリへのプルリクエストで、誰でも行えます。マーケットプレイスタブの下部にある**追加方法**から、その手順のガイドを開けます。

1. リポジトリの`catalog/`フォルダに、サービス用の小さなJSONファイルを、そこにあるガイドの説明に従って作成します。ファイルには、サービスの名前、エージェントがそれで何をできるかを説明する平易な1文、カテゴリ、アイコンと色、ホームページとドキュメント、サーバー（アドレス、またはここで動くコマンド）、サインイン方法（なし、ブラウザでのサインイン、キーのいずれか）、そして必要に応じて入力してもらう項目を記述します。
2. サービス独自のMCPサーバーが公開されたアドレスにある場合は、それを使います。そのようなサーバーがない場合や、このコンピューター上のファイルなどローカルでしかできないことには、ここで動くプログラムも歓迎されます。
3. ファイルにキーやトークンは書かないでください。各自が自分のキーを保管庫に入力します。
4. ガイドに書かれているチェックを実行します。ファイルがルールに合っているかを確認でき、サーバーの応答を問い合わせることもできます。
5. プルリクエストを送ります。マージされると、次回のアップデートで全員のマーケットプレイスにそのサービスが届きます。

## キーを保管庫に保存する

[キータブ](/apps/connected?tab=keys)を開きます。保管庫には、APIキー、トークン、サインイン用のパスワードが保管され、エージェントはそれらを見ることなく使えます。これらはこのコンピューター上で暗号化され、ここでもエージェントに対しても、二度と表示されません。表示されるのは末尾の数文字だけです。

エージェントは、Hydor独自のツール、つまりウェブリクエストツール、ブラウザ、そして許可した場合はこのコンピューター上のコマンドを通じてキーを使います。アプリが自分でキーを入れ、許可した場所にだけ入れます。

一覧の各キーには、次の情報が表示されます。

- 名前と、値を伏せたヒント（「…f3a9」など）
- メモ
- 送信を許可するホスト。このコンピューター上のコマンドが使える場合は**コマンド内**と表示されます（どちらもない場合は**許可されたホストはまだありません**）
- 最後に使われた時期（それまでは「未使用」）と、追加された時期または値が最後に変更された時期

キーがまだない場合、タブには、ここで追加するか、エージェントに求めてもらうこともできると表示されます。

アプリにもキーが必要な場合があります（天気サービスや地図プロバイダーのものなど）。アプリは必要なキーの名前を示し、それぞれをアプリのページ、インストール用のカード、またはセッション内のカードで渡します（[必要なキーを渡す](/guide/apps#give-it-the-keys-it-needs)）。キーはアプリが付けた名前とアプリが指定したホストでここに保存され、メモにはアプリの名前が入ります。

### キーを追加する

1. **キーを追加**をクリックします。
2. **名前**：エージェントがそのキーを呼ぶ名前です（WEATHER_API_KEYなど）。大文字、数字、アンダースコアで、2〜64文字、先頭は英字にします。入力した内容はこの形式の名前に変換され（「github token」はGITHUB_TOKENになります）、欄にもそのことが表示されます。
3. **値**：キーを貼り付けます。-----BEGINで始まるブロック（証明書や秘密鍵）でない限り、1行である必要があります。
4. **送信を許可するホスト**：サービスのアドレスをカンマで区切って入力します（api.example.comなど、最大20個）。キーは、これらのホストとそのサブドメインにだけ、httpsで送られます。1つも追加しないうちは、エージェントはそのキーを使えません。
5. **このコンピューター上のコマンドが使えるようにする**（最初はオフ）：データベースのパスワードやgit用のトークンなど、ここで動くプログラムが必要とするキーではオンにします。[キーを使うコマンド](/guide/connections#commands-that-use-a-key)をご覧ください。
6. **メモ**：キーの用途です。このメモはエージェントにも見えます。
7. **送信方法**（任意）：既定では、キーは「Bearer 」に続けてAuthorizationヘッダーに入れて送られます。**ヘッダー**（X-Api-Keyなど）と**キーの前に付ける文字**（ほかのヘッダーでは何も付けない）を変更できます。または**またはクエリパラメータとして**（api_keyなど）送ることもできます。
8. **保存**をクリックします。

保管庫にすでにある名前は使えません。そのキーには、新しい値を設定してください。

### キーに新しい値を設定する

キーの横にある円形の矢印（**新しい値**）をクリックし、**新しい値**に新しい値を貼り付けて、**置き換える**をクリックします。ホスト、メモ、送信方法はそのまま残ります。

### キーを送れる範囲を変更する

鉛筆のアイコン（**ホスト、メモ、送信方法**）をクリックし、ホスト、コマンドで使えるかどうか、メモ、送信方法を変更して、**保存**をクリックします。値はそのまま残ります。

### キーを削除する

ゴミ箱のアイコン（**削除**）をクリックし、確認します。エージェントはそのキーを使えなくなり、値は完全に失われます。確認の画面では、そのキーを使うアプリと、同じ名前で自分の値を持つ Web アプリ（そちらは残ります）を先に示します。

### エージェントがキーでできること・できないこと

- 名前を指定して、キーを使ってサービスを呼び出せます。アプリがリクエストにキーを入れます。設定された場所に入れるか、エージェントがアドレス、ヘッダー、本文の中に名前を二重の波括弧で書いた場所（{{GITHUB_TOKEN}}など）、またはベーシック認証のユーザー名とパスワードとして入れます。
- ブラウザで、サイトのサインインページに名前を指定してキーを入力できます。ただし、1行の入力欄に限り、キーのホストのいずれかのページで、httpsで（またはこのコンピューター上で）のみです。欄にはドットが表示され、エージェントには保管庫から入力されたことしか分かりません。
- **このコンピューター上のコマンドが使えるようにする**をオンにした場合に限り、このコンピューター上のコマンドに渡せます。ただし、そのコマンドを許可した後に限ります（[キーを使うコマンド](/guide/connections#commands-that-use-a-key)をご覧ください）。
- ウェブでは、許可したホストとそのサブドメインにだけ、httpsでのみ送れます。このコンピューターやそのローカルネットワークには送られません。キーを送ってはいけないホストへのリダイレクトには従いません。
- 1回の呼び出しに限り、キーを入れるヘッダーやクエリパラメータを変更できます。
- キーの名前、ホスト、メモは見えます。値は決して見えません。応答、ページ、コマンドの出力は、キーが伏せ字になって返されます。

## エージェントがキーを要求したとき

エージェントは、パスワードやトークン、キーをチャットに入力するよう求めないことになっています。保存されていないキーがタスクに必要なときは、代わりに会話の中にカードを表示します。タイトルは**エージェントがキーを要求**で、キーの名前と必要な理由（取得先が添えられていることもよくあります）が書かれています。

1. 入力欄にキーを貼り付けます。
2. **送信先：**を確認します。エージェントが提案したホストが入っています。必要に応じて変更してください。ホストがないと、エージェントはキーを使えません。
3. **保管庫に保存**をクリックします。

キーは会話には入らず、暗号化された保管庫にそのまま保存されます。カードはキーが保存されたことを知らせる表示に変わり、エージェントには「キーがある」というメッセージだけが届きます（キーの中身は伝わりません）。これでエージェントは作業を続けられます。

- **今はしない**を選ぶと辞退になります。エージェントには、今は渡したくないことが伝わり、キーなしで続けるか、ほかの方法を提案するよう指示されます。カードには渡さなかったことが表示され、気が変わったときのために**やはり入力する**が付いています。
- カードが待機している間は、[受信トレイ](/guide/inbox)にも「キーを要求」とキーの名前が表示されます。**開く**を押すと、そのセッションに移動します。
- 同じ名前のキーがすでに保管庫にある場合、エージェントにはそれを使うよう伝えられ、カードには保管庫にあることだけが表示されます。保存済みのキーが使えなくなったときは、エージェントが改めて要求できます。その場合、入力欄に保存済みのキーを置き換えることが表示されます。
- エージェントがこのコンピューター上のコマンドでキーを必要とするときは、カードに**このコンピューター上のコマンドが使えるようにする**も表示されます。最初はオンです。使わせたくない場合はオフにしてください。その場合でも、エージェントは指定されたホストでキーを使えます。すでに保存されているキーの場合、カードには**エージェントがコマンドでキーを使うことを要求**と表示されます。値をそのままにするには入力欄を空にして、**保管庫に保存**をクリックします。

### 複数の欄があるサインイン

サイトやサービスにサインインするとき、エージェントは必要な情報をまとめて要求します。カードには**エージェントがサインインを要求**と表示され、メールアドレスとパスワード、またはデータベースのアドレス、ユーザー、パスワードなど、項目ごとに入力欄があります。パスワードなどの秘密情報は入力中は隠れ、目のアイコンで表示できます。

1. 各欄に入力します。**任意**と表示された欄は空のままでかまいません。
2. **送信先：**を確認します。サインインの対象となるホストです。
3. **保管庫に保存**をクリックします。

秘密情報は、それぞれサインインの名前に基づいた別々のキーとして保管庫に保存されます（Voltaroのパスワードは VOLTARO_PASSWORD になります）。**エージェントにはこれが見えます**と表示された欄は、サーバーのアドレスのように秘密ではない情報です。ここに入力した内容はエージェントに渡され、保管庫には保存されません。保管庫にすでにある項目にはその旨が表示され、空にしておくと保存済みの値がそのまま使われます。保存後は、カードにキーの一覧が表示されます。エージェントはそのキーを使い、キーを見ることなく、指定されたホストに限って自分のブラウザでサインインできます。

### 1 枚のカードで複数のキーを、取得方法つきで

作業に 2 つ以上のキーが必要なときや、エージェントがキーの取得方法を説明できるときは、1 枚のカードにまとめて表示します。キーごとにタブが 1 つあります（スマートフォンでは開閉する行）。各タブには、誰がキーを発行するか、なぜ必要か、**How to get it** の短い番号つきの手順、提供元のページへのリンク（新しいタブで開きます）、入力欄があります。

1. 手順に従い、それぞれの値を欄に貼り付けます。入力中は隠れていて、目のアイコンで表示できます。欄の下の 1 行は正しい値の形を示し、貼り付けたものが明らかに違うときは警告します（止めることはありません）。
2. そのタブで**保存**をクリックします。表示されている場合は**今はスキップ**もできます。
3. 次へ進みます。タブの印で保存済み・スキップ・未入力がわかり、右上に件数が出ます。

- 保管庫にすでにあるキーは表示されません。**Use the one saved on**（日付つき）か**置換**を選びます。
- 必要なキーがすべて保存されたとき、または **Close without the rest** を押したときに、エージェントに伝わります。それぞれが保存・スキップ・未入力のどれかだけで、値は一切伝わりません。後から追加した任意のキーも伝わります。
- Hydor の中で動くアプリでは、支払いはテスト用のキー（sk_test_ で始まる）だけを受け付けます。本番のキーは拒否されます。
- Web アプリでは、明らかに別のものを貼り付けた場合（シークレットキーの欄に公開可能キーなど）、カードが警告します。
- **エージェントにはこれが見えます**の欄は、サインインのカードと同じく、入力したままエージェントに伝わります。

## キーを使うコマンド

作業によっては、このコンピューター上のプログラムでパスワードやトークンが必要になります。たとえば、トークンを使ったGitHubへのプッシュ、パスワードによるデータベースの読み取り、サービスを呼び出すスクリプトなどです。こうした場合のために、エージェントには、保管庫のキーを環境変数として（キーごとの名前で）渡して1つのコマンドを実行するツールがあります。コマンドの出力はキーを伏せ字にしてエージェントに返されます。

- コマンドに渡せるのは、**このコンピューター上のコマンドが使えるようにする**をオンにしたキーだけです。オンにするには、キーの鉛筆アイコンのダイアログを開くか、エージェントが要求したときのカードで設定します。
- このようなコマンドを実行する前に、カードにその内容が表示されます。**キーを使ってコマンドを実行**の後にキーの名前、続いてコマンドと用途が示されます。**許可**を押すと1回だけ実行されます。**このセッションで許可**を押すと、同じキーを使うこのセッションの以降のコマンドも、アプリを再起動するまで確認なしで実行されます。**しない**を押すと実行を止め、代わりにどうするかをエージェントに伝えられます。
- フルアクセスのセッションでは、ほかのコマンドと同様に、確認なしで実行されます。プランモードでは実行されません。
- コマンドはプログラムができることなら何でもでき、キーをほかへ送ることも可能です。内容を理解できるコマンドだけを許可し、このコンピューター上のプログラムが必要とするキーにだけオンにしてください。
- コマンドは2分で停止します。エージェントがより長い時間を指定した場合は、最大10分までです。

## サービスが求めるフォームに入力する

サービスによっては、タスクの途中で日付、選択、はい／いいえ、開くページなどの入力を求められることがあります。どのエージェントが作業していても、リクエストはセッション内のカードとして、エージェント自身の承認カードと並んで表示され、[受信トレイ](/guide/inbox)にも届きます。カードのタイトルで、サービスが何を求めているかが分かります。

- **…がフォームへの入力を求めています**：サービスからのメッセージに続いて、入力欄がフォームとして表示されます。テキストボックス、長文、数値、日付、はい／いいえのスイッチ、選択用のチップやリストがあります（サービスが複数選択を認めている場合は、チップを複数選べます）。**送信**をクリックしてください。必須の欄が空（「必須」）の場合や、数値でない値は、送信前にマークされます。サービスが受け付けられない回答（長すぎる、メールアドレスではない、選択数が足りないなど）は、直すべき点とともに拒否され、カードはそのまま残ります。
- **…がページを開くよう求めています**：リンクが表示されます。**開く**を押すと、ページが新しいタブで開きます（承認やサインインのため）。開いたことはサービスにも伝わります。
- **…が実行の許可を求めています**：シンプルなはい／いいえです。**許可**を押すと「はい」になります。

**辞退**は「いいえ」の意味です。**今はしない**は今回だけキャンセルします。サービスのカードは最長1時間待機します。それより前にエージェントのターンが終わると、リクエストはキャンセルされます。Codex向けに設定したMCPサーバーも、同じ種類のカードで確認します。

## Claude Code、Codex、Custom向けにMCPサーバーを設定する

[設定 → エージェント → MCPサーバー](/settings?s=mcp)を開きます。ここにあるのは自分で用意するツールサーバーで、マーケットプレイスにないツールや、自分で運用しているサーバー向けです。Claude CodeとCodexのサーバーはそれぞれ自身の設定に保存されます。CustomのサーバーはHydorが保持するので、どちらのプログラムがなくても追加できます。アプリ独自のエージェントであるCustomは、これらをすべて使用します（詳しくは[Custom](/guide/custom)をご覧ください）。新しいセッションが読み込みます。すでに実行中のセッションは、再起動したときに変更を反映します。

ページには、サーバーが**Claude Code**、**Codex**、**Custom**の3つのグループに分かれて表示され、ページのタイトルの横に**サーバーを追加**があります。設定されておらずサーバーもないClaude CodeやCodexのグループは表示されません。上部の**フォルダ**チップで、サーバーを表示するフォルダを選びます。Claude Codeでは、すべてのフォルダ向けだけでなく、特定のフォルダ向けにもサーバーを保持できるためです。各グループ名の横にある（i）には、変更がいつ反映されるかが説明されています。

各サーバーには次の情報が表示されます。

- 名前と種類：**コマンド**（このマシンが実行するプログラム）、または**HTTP**か**SSE**（アドレスにあるサーバー。SSEは古い方式）
- Claude Codeの場合は、適用範囲：**すべてのフォルダ**、**このフォルダ、自分のみ**、**このフォルダ、共有**
- **オフ**：Codex自身の設定でオフにされているCodexサーバー
- **Custom**グループでは、Customがほかから読み込むサーバーに**Claude Codeから**、**Codexから**、**.mcp.jsonから**のいずれか、ブラウザでサインインするサーバーに**サインイン済み**または**もう一度サインイン**
- コマンドまたはアドレス、および環境変数、ヘッダー、Bearerトークンの変数の名前。値はサーバー側に残り、表示されません
- 確認後は、サーバーの状態（行の末尾のバッジ）

### サーバーを追加する

[サーバーを追加](/settings?s=mcp&find=Add%20server)をクリックします。**MCPサーバーを追加**ダイアログで、次の項目を入力します。

- **追加先**：Claude Code、Codex、Custom、またはその複数。最初は設定済みのClaude CodeとCodexで、どちらもなければCustomです。設定されていないプログラムは選べず、ダイアログに理由が表示されます。CustomはClaude CodeとCodexのサーバーも使うので、Customだけに持たせたいサーバーや、どちらのプログラムもない場合にCustomへ追加します。
- **名前**：英字、数字、ドット、ハイフン、アンダースコアで64文字まで。先頭は英字か数字にします。エージェントは、ツールを「名前、スラッシュ、ツール名」の形で表示します。
- **入力**：**コマンド**、**HTTP**、**SSE**。CodexはSSEに対応していないため、SSEを選ぶとCodexは対象外になります。
- コマンドの場合：
  - **コマンド**：`npx -y @modelcontextprotocol/server-github` のようなコマンドライン全体。セッションの開始時にこのマシンで実行されます。スペースを含む引数は引用符で囲んでください。引数の先頭の ~ はホームフォルダを表します。
  - **環境**：KEY=value の形式で1行に1つ（# で始まる行は無視されます）。値はエージェントの設定ファイル（Customの場合は、Hydorがこのコンピュータに保持するファイル）に保存され、ここには二度と表示されません。
- HTTPまたはSSEの場合：
  - **URL**：サーバーのアドレス。http:// または https:// で始めます。
  - **ヘッダー**（Claude CodeとCustom用）：「名前: 値」の形式で1行に1つ。APIキーを使うサーバー向けです。ブラウザでのサインイン（OAuth）を使うサーバーには不要です。追加後、一覧からサインインしてください。
  - **Bearerトークンの変数**（Codex用、任意）：Codexがbearerトークンとして送信する値を持つ環境変数の名前。
- **Claude Codeでの使用場所**（Claude Codeだけを選んだ場合は**使用場所**）：
  - **すべてのフォルダ**：このマシン上のすべてのClaude Codeセッション。初期設定です。
  - **このフォルダ**：上部で選んだフォルダ内のセッションだけ。自分のClaude Code設定に保存されます。
  - **共有の.mcp.json**：そのフォルダの.mcp.jsonファイルに保存されるため、リポジトリで作業する全員が利用できます。

  CodexとCustomのサーバーは常にすべてのフォルダに適用されます。

ダイアログの**サーバーを追加**をクリックします。HydorはClaude CodeとCodexには各プログラム自身のコマンドを通じて追加するので、設定はそれぞれが想定する形のままです。Customのサーバーは自身で保持します。エージェントが拒否した場合は、サーバーを追加できなかったことと、エージェントのメッセージがダイアログに表示されます。問題を直して、もう一度**サーバーを追加**をクリックしてください。失敗したエージェントだけが再試行されます。CustomがすでにClaude CodeやCodexから読み込んでいるサーバーと同じ名前のサーバーは、Customではそのサーバーに置き換わります。

Customのサーバーを変更するには、その**⋯**メニューを開き、**編集**を選びます。変数とヘッダーは値が空の状態で一覧表示されます。空のままにすると保存済みの値が維持され、行を削除するとその項目が削除されます。コマンドやアドレスのサイトを変更した場合は、値を入力し直してください。

### 接続できるサーバーを確認する

グループのタイトルの末尾にある[接続を確認](/settings?s=mcp&find=Check%20connections)をクリックすると、新しいセッションと同じ方法ですべてのサーバーを起動し、それぞれの結果を表示します。**Custom**グループではCustomが読み込むものすべてを確認するため、確認後はClaude Code、Codex、フォルダの.mcp.jsonから読み込むサーバーもそこに表示されます。

- **接続済み**：ツールの数が付きます
- **サインインが必要**：Customの場合は、ブラウザでのサインイン（OAuth）を求めるサーバーです
- **もう一度サインイン**：Customで、サインインが終了して更新できなかった場合です
- **まだ接続中**
- **失敗**：理由が付きます（理由がない場合は「サーバーが起動しなかったか、応答しませんでした。」）
- **オフ**

モデルは使用されません。最大で1〜2分かかることがあります。Claude Codeの場合は上部で選んだフォルダで実行されるため、そのフォルダ専用のサーバーも対象になります。

### サーバーにサインインする

OAuthでサインインするアドレス指定のサーバーでは、一度サインインが必要です。

**Claude Code**と**Codex**では、確認で**サインインが必要**と表示されたときに出る**サインイン**をクリックするか、サーバーの**⋯**メニューから**ターミナルでサインイン（OAuth）**を選びます。アプリ内でターミナルが開き、そのサーバー向けのプログラム自身のサインインが実行されます。表示される手順に従ってください。

**Custom**（HTTPサーバー。Custom自身のものと、プログラムから読み込むもの）では、**サインイン**をクリックし、ダイアログでも**サインイン**をクリックします。[接続したアカウント](#services-you-sign-in-to-in-the-browser)と同じように、小さなウィンドウでサービス自身のページにサインインします（スマートフォンではそのタブのまま）。ほとんどのサーバーではHydorが自動で登録できます。できない場合は、サービスの開発者向け設定で作成するクライアントIDをダイアログが求め、サービスに指定するコールバックアドレスを表示します。トークンは暗号化してボールトに保存され、そのサーバーにだけ送られ、自動で更新されるので、Customがトークンを見ることはありません。**もう一度サインイン**は更新に失敗したときだけ表示されます。**⋯**メニューの**サインアウト**でサインインを削除できます。

### サーバーを外す

サーバーの**⋯**メニューを開き、**外す**を選んで、**外す**で確定します。エージェントはそのサーバーを読み込まなくなります。すでに実行中のセッションは、再起動するまで引き続き使います。Customのサーバーを外すと、ほかのサーバーがそのアドレスを使っていなければ、サインインも削除されます。

## Claude Codeにプラグインを追加する

Claude Codeには独自のプラグインがあります。スキル、コマンド、エージェント、フック、MCPサーバーをまとめたアドオンで、マーケットプレイス（GitHubリポジトリ、その他のgitリポジトリ、フォルダに置かれたプラグインのカタログ）から入手します。Claude Code専用です。[設定 → エージェント → プラグイン](/settings?s=plugins&find=Claude%20Code)の**Claude Code**タブにあります。Codex独自のプラグインは**Codex**タブにあります。すべてのエージェント向けのプラグインは**すべてのエージェント**タブにあります。詳しくは[プラグイン](/guide/plugins)をご覧ください。

### インストール済みのプラグイン

**インストール済み**には、このマシン上のClaude Codeのプラグインが表示されます。新しいClaude Codeセッションが読み込みます。それぞれに、名前、マーケットプレイス、バージョン、機能が表示されます。

- スイッチで、プラグインを削除せずにオフ／オンにできます。
- **⋯**メニューには**アンインストール**があり、確認後に実行されます。新しいClaude Codeセッションは、そのスキル、コマンド、サーバーを読み込まなくなります。

### プラグインを探してインストールする

**参照**には、マーケットプレイスからインストールできるすべてのプラグインが、インストール数の多い順に、インストール数とともに表示されます。**プラグインを検索**で絞り込めます。一度に40件表示され、**もっと見る**でさらに40件追加されます。

**インストール**をクリックして確認します。プラグインは、すべてのClaude Codeセッション向けにインストールされます。プラグインは、このマシンでコマンドを実行するフックやサーバーを追加することがあるため、信頼できるプラグインだけをインストールしてください。

HydorがClaude Codeにプラグインの一覧を問い合わせるのは最大で10分に1回で、変更のたびにも再度問い合わせます。初回は時間がかかることがあります。

### プラグインのマーケットプレイス

**マーケットプレイス**には、Claude Codeがプラグインをインストールするカタログが表示されます。

- 追加するには、グループのタイトルにある**追加**をクリックし、ダイアログにGitHubのowner/repo、git URL、またはフォルダを入力して、**追加**をクリックします。
- 削除するには、その行のゴミ箱アイコンをクリックして確認します。そのマーケットプレイスからインストールしたプラグインもアンインストールされます。

## エージェントに頼む

次のような作業は、カードでの確認を経て、エージェントに任せられます。エージェントがキーの値をアプリに入力することはありません。キーやサインインが必要なときは、入力するためのカードが表示されます。

- 「接続されているアカウントを教えてください。Notionをテストして、動くか教えてください。」
- 「今週届いた大家さんからの未読メールを探して、要約してください。」
- 「Annaの最後のメールに、木曜日なら会えると返信する下書きを作って、下書きに保存してください。」
- 「今月届いた請求書の添付ファイルを、このフォルダに保存してください。」
- 「Context7を接続して、エージェントがライブラリのドキュメントを調べられるようにしてください。」
- 「すべてのセッションでGmailをオフにして、このセッションだけオンのままにしてください。」
- 「Notionのツールを見せて、ページを削除するものはオフにしてください。」
- 「Gmailのツールのうち、送信や削除をするものは事前確認にして、残りはオンのままにしてください。」
- 「Claude CodeとCodex向けに、npx -y @modelcontextprotocol/server-memory を実行するMCPサーバーを追加して、接続できるか確認してください。」
- 「https://mcp.example.com/mcp のHTTP MCPサーバーをCustomに追加して、いつサインインを押せばいいか教えてください。」
- 「インストール数の多いClaude Codeプラグインを見せて、私が選んだものをインストールしてください。」
- 「Voltaroのアカウントにサインインして、今年の請求書をこのフォルダにダウンロードしてください。」（初回は、カードでサインイン情報を求められます。）
- 「保管庫にあるトークンで、このブランチをGitHubにプッシュしてください。」
- 「私の店に必要なキーを 1 枚のカードでまとめて聞いて、それぞれの取得方法を教えて」
