# エージェント、アカウント、モデル

Hydorは複数のAIエージェントを実行できます。Claude Code、Codex、Custom（アプリ独自のエージェントで、どのモデルでも使えます）、そしてGemini CLI、OpenCode、Qwen Code、Goose、Grok BuildなどのACPに対応したエージェントです。このトピックでは、それぞれの違い、プログラムのインストールと更新の仕組み、サインインの方法（複数アカウントも含む）、そしてCustomのモデルの入手元（OpenRouter、Ollama、このコンピューターで動かすHugging Faceのモデル、OpenAI互換のエンドポイント）を説明します。

![開始ページでのエージェントの選択：Claude Code、Codex、Custom](images/agents-models.webp)

## どのエージェントを使えばよいですか？

エージェントは、セッションで作業を行うプログラムです。メッセージを読み取り、ツール（ファイル、コマンド、ウェブ）を使い、回答します。モデルは、その裏側にあるAIです。ここにあるエージェントはどれも、アプリから同じ支援（ウェブ検索、ブラウザ、メモリ、スキル、接続）を受けられますが、モデルの入手元が異なります。

- **Claude Code**（Anthropic）。Claudeのプランで動くか、AnthropicのAPIアカウントに課金されます。モデルはAnthropicのもの（Opus、Sonnet、Haiku）です。独自の使用量の上限があり、[使用量ページ](/usage)で確認できます。
- **Codex**（OpenAI）。ChatGPTのプランで動きます。モデルはOpenAIのものです。こちらにも使用量の上限があり、使用量ページに表示されます。Codexはアプリに付属しています。
- **Custom**は、アプリ独自のエージェントです。ClaudeとChatGPTのプランのモデル（Claude CodeとCodexのサインイン経由）のほか、[設定 → エージェント → モデル](/settings?s=models)で追加した任意のモデルを実行します。OpenRouter経由のモデル、このコンピューター上のモデル（OllamaまたはvLLM）、OpenAI互換のエンドポイントのいずれも使えます。オープンモデルや低価格のモデル、コンピューターの外に出ないモデルを使いたいときに便利です。詳しくは[Custom、アプリ独自のエージェント](/guide/custom)をご覧ください。
- **ACPに対応したエージェント**：Gemini CLI、OpenCode、Qwen Code、Goose、Kimi CLI、Auggie、Grok Build（xAIのコーディングエージェントで、Grokのモデルを使います）など、または独自のコマンド。ACP（Agent Client Protocol）は、アプリがエージェントのプログラムと通信するための共通の方式です。それぞれ、自身のプログラムで一度サインインし、自身のモデルを使います。

アプリ内でそれぞれにできること：

- ゴール（条件が満たされるまでエージェントが作業を続ける機能）とフォーク（以前の返信からセッションのコピーを作る機能）：Claude Code、Codex、Custom。ほかのACPエージェントでは使えません。
- **続きを開く…**（会話を別のエージェントに引き継ぐ機能）：Claude CodeまたはCodexから、もう一方、またはCustomへ。
- 思考レベル（モデルがどれだけ深く考えるか）：Claude Code、Codex、Grok Build、およびモデルが対応しているその他のACPエージェント。
- 複数アカウント、プランの使用量上限、上限に達したときのアカウント切り替え：Claude Code、Codex、Grok Build。
- 上限のリセットと、上限に達したときのAPIクレジット：Claude CodeとCodexのみ。

## 新しいセッションのエージェントとモデルを選ぶ

開始ページ（`/`）では、メッセージ欄の下の行で、作業を行うエージェントを選びます。

1. **実行環境**をクリックします。一覧には、**Claude Code**（「Anthropic · ClaudeのプランまたはAPIキー」）、**Codex**（「OpenAI · ChatGPTのプランまたはAPIキー」）、**Custom**（「任意のモデル：OpenRouter、Ollama、vLLM」）、そして設定 → その他のエージェントで追加したすべてのエージェント（「ACPエージェント · 」とそのコマンド）が表示されます。一番下の**Custom用モデル**は設定 → モデルを開き、**エージェントを追加・管理**は設定 → その他のエージェントを開きます。
2. **モデル**をクリックして選びます。一番上にある**自動**は最初から選ばれていて、ティアに選択を任せます。最初は最高で、問題が難しすぎるとわかれば最大に移ります（[ティア：仕事の種類ごとのモデル](#tiers-a-model-for-each-kind-of-job)をご覧ください）。その下には、そのエージェント自身のモデルだけが表示されます。エージェントの既定のモデルには「デフォルト」と表示されます。モデルの古いバージョンは「古いモデル2件」のような行の奥にあり、クリックすると表示されます。モデルが8つを超えると、上部に**モデルを検索**ボックスが表示されます。数文字入力してEnterキーを押すと、最初に一致したものが選ばれます。エージェントがアプリの求めどおりにモデルを返さなかった場合は、メニューにその旨とエージェント自身による理由が表示され、**もう一度試す**で再度問い合わせます。
3. **オプション**には、**思考レベル**（対応するエージェントとモデルのみ：デフォルト、低、ミディアム、高など。Grok Buildについては[Grok Buildの思考レベル](#effort-for-grok-build)をご覧ください）と、**権限**（確認なしにエージェントができること）があります。メッセージ欄でShift+Tabを押しても権限を切り替えられます。

開始ページは、作業する場所ごと（各プロジェクト、各フォルダ、**新しいタスクフォルダ**）に選んだ内容を、すべてのデバイスで記憶します。各プログラムのモデル、思考レベル、権限は、前回の状態でそこに戻ります（[開始ページが記憶する内容](/guide/sessions#what-the-start-page-remembers)をご覧ください）。

Custom以外のACPエージェントでは、**モデル**と**権限**の選択肢は最初のセッションの後にはじめて表示されます。そこには、エージェントが前回の実行時に提示した内容が並びます。例外はGrok Buildです。アプリがGrokにモデルを問い合わせるため、追加した直後から、モデルと、それぞれが対応する思考レベルが表示されます。

**オプション**の**機密**をオンにすると、**実行環境**は**Custom**になり、**モデル**にはこのコンピューターまたはプライベートネットワーク上のモデルだけが並び、その中で最良のものが最初に選ばれます。[機密セッションにする](/guide/sessions#keep-a-session-confidential)をご覧ください。

スマートフォンでは、これらのメニューはそれぞれ画面下からシートとして開きます。

## セッションの途中でモデルを切り替える

セッション内では、モデル、思考レベル、権限がメッセージ欄の下にあります。「Opus 5.5 · 高 · プラン」のように表示される1つのチップになっていて、クリックすると**モデル**、**思考レベル**、**権限**が開きます。

別のモデルを選ぶと、セッションはそのモデルで続きます。

- Claude Codeはすぐに切り替わります。
- Codexは次のターンから新しいモデルを使います。
- Customは次のステップから、ターンの途中でも使います。
- ほかのACPエージェントは、モデルの選択肢があれば切り替わります。

セッションの**思考レベル**も同じ仕組みです。選ぶと、実行中のエージェントは次のターンからそれを使います。切り替え先のモデルが現在の思考レベルに対応していない場合、ピッカーにはそのモデルのデフォルトが表示され、モデルはそれで動きます。

モデルメニューには、そのセッション自身のエージェントのモデルだけが表示されます。機密セッションでは、このコンピューターまたはプライベートネットワーク上のモデルだけです。会話を別のエージェントに移すには、セッションのメニュー（⋯）→ **Claude Codeで続きを開く**、**Codexで続きを開く**、または**Custom Agentで続きを開く**を使います（Claude CodeとCodexのセッションから。Customはモデルを持つと表示されます）。次のメッセージで、同じフォルダに、これまでの会話を引き継いだそのエージェントの新しいセッションが始まります。停止したセッションは、送信前に別のモデルを選ばない限り、最後に使ったモデルで再開します。

## Grok Buildの思考レベル

Grokのモデルには推論の思考レベルがあり、Claude CodeやCodexと同じ選択ができます。

- Grok 4.6（および同じ選択肢を持つ新しいモデル）：**xhigh**、**高**、**ミディアム**、**低**。デフォルトは**高**です。
- Grok 4.5：**高**、**ミディアム**、**低**。

開始ページで**実行環境**の下の**Grok Build**を選び、**オプション** → **思考レベル**を開きます。選んだモデルの思考レベルが**デフォルト**とともに表示されます。Grok Buildを追加した直後、最初のセッションの前でも表示されます。実行中のGrok Buildセッションでは、メッセージ欄の下のチップにある**思考レベル**ピッカーで変更でき、[アプリ](/guide/apps)の実行でも指定できます。セッションを、現在の思考レベル（Grok 4.5でのxhigh）に対応しないモデルに切り替えると、ピッカーにはそのモデルのデフォルトが表示され、モデルはそれで動きます。

これはGrokだけのものではありません。ACPに対応し、モデルに思考レベルがあるほかのエージェントでも、同じ**思考レベル**の選択肢が使えます。

## ティア：仕事の種類ごとのモデル

エージェントは、モデルを名前ではなくティアで選びます。**高速**は結果を確認できる、小さくてごく明確な仕事向け、**標準**は中程度の規模の明確なタスク向け、**最高**は計画を立て、サブエージェントを率い、その作業を確認するセッションのメインエージェント向け、**最大**は最も難しい問題向けです。仕事の大半は、安価なモデルでも十分こなせる明確な部分でできています。そのため、結果を損なわずにセッションの費用を抑えられます。最も強力なモデルが、引き続き作業を計画し、確認するからです。

開始ページでは、**モデル**は**自動**になっていて、セッションは最高で始まります。メインエージェントは、明確な部分を標準と高速のサブエージェントに任せ、最高では手に負えない問題だとわかれば（2回失敗した修正、見つからない原因、証明など）自分を最大に移すことがあります。その際は、会話に理由を添えた1行が表示されます。依頼の文面だけで最大に送られることはありません。難しそうに見えるものの大半は、最高のほうが低コストで解決します。代わりに名前でモデルを選ぶと、セッションはそのモデルで考えます。それでも、そのサブエージェントにはティアが使われます。自分のエージェントを1つのティアで考えさせることもできます（[エージェントが考えに使うもの：ティア](/guide/agents#what-an-agent-thinks-with-tiers)をご覧ください）。

[設定 → エージェント → モデル → ティア](/settings?s=models&find=Tiers)では、プログラムごとに各ティアの意味を設定します。ティアごとに1行あり、グループのタイトルの横にあるスイッチでプログラム（**Claude Code**、**Codex**、**Custom**）を切り替えます。各行にはモデルがあり、Claude CodeとCodexでは思考レベルもあります。ティアの(i)で詳しい説明が見られます。初期設定では、Claude Codeは高速がHaiku、標準がSonnet、最高がOpus、最大が最新のFableです。Codexは高速がLuna、標準がTerra、最高がSol、最大がAstraです（どれかがないプランでは、提供されている最も近いもの。2つが同じモデルを共有する場合は、上位のティアに多めの思考レベルを割り当てます）。Customには初期設定がないため、そのセッションはCustomのモデルを選ぶまで選んだモデルのままです（このコンピューター上のモデルなら、高速は無料になります）。**Custom**タブでは、ClaudeまたはChatGPTのプランのモデルをティアに指定することもできます（[Customのモデルの入手元](#where-customs-models-come-from)をご覧ください）。手を加えなかったティアは、そのプログラムの同種の最新モデルに従います。タイトル横の**⋯**メニューにある**初期設定に戻す**で、元に戻せます。

ティアの下にある**セッションのティア**グループの2つのスイッチで、セッションがティアをどう使うかを決めます。

- **サブエージェントを主導**（初期設定ではオン）：セッションのメインエージェントは、計画を立て、明確な部分を安価なティアのサブエージェントに任せ、その作業を確認するよう指示されます。ティアを指定せずに依頼されたサブエージェントには標準が使われます。オフにすると、エージェントは別の判断をしない限り単独で作業し、開始ページに自動はなくなります。
- **難問には最大**（初期設定ではオン）：自動のメインエージェントは、最高では難しすぎる問題だとわかれば、自分を最大に移すことがあります。オフにすると、自動のセッションは最高のままです。

## エージェントプログラムは自動でインストール・更新されます

Claude Code、Codex、Gemini CLI、Grok Buildなどは、このコンピューター上のプログラムです。手動でインストールする必要はありません。

[設定 → エージェント → アカウント](/settings?s=accounts&find=Agent%20programs)を開き、**エージェントプログラム**グループを見ます。Claude Code、Codex、Gemini CLI、OpenCode、Qwen Code、Auggie、Grok Build（追加した場合）、およびACPアダプターが必要なエージェントが一覧に並び、それぞれにセッションが実行するバージョンと入手元が表示されます。

- **自分でインストール**：自分でインストールしたもの（Grok Buildの場合は、`~/.grok/bin`に入るxAI公式のインストーラーでも）。
- **アプリがインストール**：アプリが専用のフォルダにインストールしたもの。
- **アプリに付属**：Codexはアプリに付属しています。
- **未インストール：初めて使うときに自動でインストールされます**：入っていません。今すぐ入れるには**インストール**をクリックします。

新しいバージョンが出ている場合は、行に「… is out」とも表示されます。自分用のCodexもある場合、Codexの行には「yours in the terminal: …」が加わります。セッションではアプリのものが、ターミナルではご自身のものが実行されます。

入っていないプログラムは、最初に必要になったときにも自動でインストールされます。Claude Codeは、サインインしたときやClaude Codeのセッションを開始したとき、ACPエージェントは、設定 → エージェント → その他のエージェントで追加したときやそのセッションを開始したときです。アプリはnpmでそれらを専用のフォルダにインストールするため、管理者権限は不要です。

Goose、Kimi CLIなど一部のエージェントはこの一覧にありません。ご自身でインストールしてください（入手先は設定 → エージェント → その他のエージェントに表示されます）。ACPアダプターが必要なエージェントは、アダプターとエージェント本体の2つに分けてインストールされますが、一覧では両方で1行です。

## エージェントプログラムを最新の状態に保つ

[**自動で更新**](/settings?s=accounts&find=Update%20automatically)をオンにすると（**エージェントプログラム**の最後の行にあり、オフにしない限りオンです）、アプリが1日に1回、各エージェントプログラムを最新バージョンに更新します。最初の実行は、アプリの起動からおよそ10分後です。

- アプリがインストールしたコピーは、アプリ専用のフォルダでnpmを使って更新されます。Codexは、アプリに同梱されているものより新しいコピーに切り替わります。
- ご自身でインストールしたものは、それぞれの更新コマンドで更新されます。Claude Codeは`claude update`、Codexは`codex update`（ターミナルで実行されるもの）、OpenCodeは`opencode upgrade`、Grok Buildは`grok update`です。
- `npm install -g`でインストールしたGemini CLI、Qwen Code、Auggie、Grok Build、またはACPアダプタを持つエージェントは、そのフォルダにユーザーが書き込める場合に、npmで更新されます。それ以外の方法でインストールしたものは、インストールしたときと同じ方法でご自身で更新してください。
- Claude Codeは独自のリリースラインに従います。設定に`"autoUpdatesChannel": "stable"`がある場合は安定版、それ以外は最新版です。
- `DISABLE_AUTOUPDATER=1`でClaude Code自身の更新をオフにしている場合（Dockerイメージではオフです）、アプリもClaude Codeを自動では更新しません。**今すぐ更新**を押せば更新されます。

アプリは、新しいバージョンがセッションでの使い方どおりに動作する場合にのみ、そのバージョンを残します。Claude Codeはセッションの開始時に応答し、モデルを一覧表示できること、Codexはアプリサーバーを起動し、モデルを一覧表示できること、その他はそれぞれ起動してバージョンを返せることが必要です。確認にサインインは不要で、ご契約のプランも消費しません。応答までの猶予は1分で、コンピューターが起動している時間だけが数えられるため、確認の途中でスリープしたMacでも1分を使い切ることはありません。初回の応答が遅い場合（Macは新しいプログラムを初めて実行する前に内容を調べます）は、さらに2分の猶予をもって再度起動され、それでも応答しない場合に限り失敗となります。失敗したバージョンは元に戻されます。

- アプリがインストールしたコピー、またはご自身のものをnpmで更新したコピーは、以前のバージョンに戻ります。
- ご自身のClaude Codeの場合、セッションは以前のバージョンで動き続けます。以前のバージョンは、Claude Codeのインストーラーが新しいバージョンの隣に残しています。ターミナルの`claude`コマンドは新しいバージョンのままです。行には「… did not work here」と表示されます。
- 失敗したバージョンは自動では再試行されませんが、その次のバージョンは試行されます。また、**今すぐ更新**を押すと再度試行されます。

この行の下には、アプリが最後に確認した時刻が「Up to date · checked 2h ago」のように表示され、**今すぐ確認**でもう一度確認できます。新しいバージョンが公開されている場合はその旨が表示され、**今すぐ更新**ですべてまとめてインストールできます（プログラムごとのボタンはありません）。更新中は、どのプログラムを更新しているかが表示されます。その下の行には、直近の更新で変わった内容（「Claude Code 2.1.308 → 2.1.316」など）や、バージョンをインストールできなかった理由が表示されます。

実行中のセッションは開始時のバージョンのまま動き続け、新しいセッションは新しいバージョンを使います。**自動で更新**がオフの場合も、アプリは1日に1回確認して公開されているバージョンを表示しますが、**今すぐ更新**を押すまでインストールはしません。

## Claude Code、Codex、Grok Buildにサインインする

Claude CodeとCodexは、サインインしないと使えません。追加したGrok Buildも同様です（[Gemini CLI、OpenCode、その他のACPエージェントを追加する](#add-gemini-cli-opencode-and-other-acp-agents)を参照）。[設定 → エージェント → アカウント](/settings?s=accounts)を開きます（スマートフォンでは、設定はセクションの一覧です。エージェントの下の**アカウント**をタップします。上部のタイトルをタップすると戻ります）。**アカウント**グループ（その(i)には、これらがセッションで使うClaude Code、Codex、Grok Buildのサインインであること、仕事用と個人用など別のサブスクリプションを追加でき、セッションの開始時にどれかを選べることが書かれています）には、各エージェント自身のサインインが先に表示され、その後に追加したアカウントが並びます。Grok Build自身のサインインにもここに**Grok Build**という行があり、追加すると表示されます。各行には、メールアドレス、プラン、サインイン方法とともに緑のチェックが表示されます。サインインしていない場合や問題が起きた場合は、赤い×と「Not signed in」または問題の内容が表示されます。

サインインの手順：

1. エージェントの横の**サインイン**をクリックします。
2. 方法を選びます。
   - Claude Code：**Claudeサブスクリプション**（Claudeのプラン）または**コンソール（API課金）**（AnthropicのAPIアカウント）。
   - Codex：**デバイスコード**または**ブラウザのリダイレクト**。
   - Grok Build：選ぶものはなく、常にコードでサインインします。
3. **サインインリンクを取得**をクリックします。
4. ダイアログに表示される手順に従います。
   - Claude Code：リンクを開き（**サインインページを開く**）、ブラウザでアクセスを承認します。ページに表示されたコードを**ページに表示されたコードを貼り付け**に貼り付けて、**サインインを完了**をクリックします。
   - Codex、デバイスコード：任意のデバイスでリンクを開き、ChatGPTにサインインして、ダイアログに表示されるワンタイムコードを入力します。完了すると、ダイアログが自動的に検知します。
   - Codex、ブラウザのリダイレクト：サインイン後、ブラウザが「localhost」のページを開こうとして失敗します。そのページのアドレスをコピーし、**ブラウザのlocalhostアドレスを貼り付け**に貼り付けて、**サインインを完了**をクリックします。
   - Grok Build：リンクとワンタイムコードが表示されます。任意のデバイスでリンクを開き、Grokアカウントでサインインして、コードを確認します（**2. このコードを確認する**）。貼り付けるものはなく、完了するとダイアログが自動的に検知します。

成功すると、「Claude Code is signed in」（CodexやGrok Buildの場合はその名前）と表示されます。失敗した場合は、ダイアログに理由が表示されるので、**もう一度試す**をクリックします。

サインインすると、ボタンは**アカウントを切り替え**に変わります。別のアカウントで同じサインインを開始します（Grok Buildの場合は新しいコード）。**サインアウト**は行の**⋯**メニューにあり、確認後、このコンピューター上でそのプログラムをサインアウトします。そのプログラムを使うすべてのターミナルとエディタが対象です。

Grok Buildがサインアウトされた状態でセッションを開始すると、「Grok Build is not signed in: sign in with your Grok account in Settings → Agents → Accounts, then try again.」と表示されてセッションが停止します。そこでサインインして、メッセージをもう一度送信してください。エージェントの環境の`XAI_API_KEY`にxAIのAPIキーがある場合は、サブスクリプションの代わりにGrok Buildで使えます。

ウェルカムツアー（アイコンバーの**ヘルプ**から開けます）では、使いたいエージェントとモデルを尋ねられ、これらのサインインも順に案内されます。

## 2つ目のアカウントを追加する（仕事用と個人用）

Claude Code、Codex、Grok Buildのアカウントを複数サインインでき、たとえば仕事用プランと個人用プランを、セッションごとに選べます。

1. [設定 → エージェント → アカウント](/settings?s=accounts&find=Accounts)を開きます。
2. **アカウント**グループのタイトルの横にある**アカウントを追加**をクリックします。
3. **Claude Code**、**Codex**、**Grok Build**（Grok Buildを設定済みの場合に選べます）のいずれかを選び、名前（40文字まで。「仕事」や「個人」など）を入力して、**追加してサインイン**をクリックします。
4. 新しいアカウントのサインインダイアログが開きます。上記の手順でサインインします。

追加したアカウントはそれぞれ個別にサインインし、独自のセッション履歴を持ちます。設定、指示、スキル、プラグインは、そのエージェントのメインのサインインと共有されるため、変更は両方に反映されます。Claude Codeでは、メインのサインインで信頼したフォルダは、追加したアカウントでも信頼されるため、そのフォルダ自身の権限ルールがセッションで適用されます。同じエージェントの2つのアカウントに同じ名前は付けられません。

追加したGrok Buildアカウントには、サインイン情報とGrok自身のセッション履歴を入れた専用のフォルダがあります。Grok CLI自身の設定（config、ルール（`AGENTS.md`）、スキル、プラグイン、MCPのサインイン）は、メインのサインインと共有されます。

追加したアカウントにはそれぞれ専用の行があり、エージェント自身のサインインの下に表示されます。行には**サインイン**または**アカウントを切り替え**があり、**⋯**メニューには**サインアウト**、**名前を変更**、**外す**があります。

- **名前を変更**は、新しい名前を入力します。
- **サインアウト**すると、再びサインインするまで、このアカウントで動くセッションは動作しなくなります。
- **外す**と、アプリからアカウントが取り除かれます。そのセッションは一覧から消えますが、履歴はディスクに残ります。ただし、**サインイン情報とセッションの履歴も削除する**にチェックを入れた場合は削除されます。そのアカウントで実行中のセッションがある間は外せません。先に停止してください。

[使用量ページ](/usage)には、追加したClaude Code、Codex、Grok Buildのアカウントごとに、それぞれの上限を示すカードが表示されます。

## セッションを実行するアカウントを選ぶ

選んだエージェントに追加したアカウントがある場合（Grok Buildは、追加した後）、スタートページの**オプション**に**アカウント**の行が表示されます。クリックすると、次の項目が表示されます。

- **サインイン情報**は、そのプログラム自身のアカウントです（**アカウント**でそのエージェントの最初のもの。Grok Buildの場合は「The Grok Build CLI's own account」）。
- 追加したアカウントは、名前で一覧表示されます。
- **アカウントを管理**を開くと、設定 → エージェント → アカウントが開きます。

スタートページは、エージェントごとの選択を覚えていて、どの場所でも同じです。追加したアカウントで動くセッションでは、セッションの上部に、人のアイコンとともにそのアカウントの名前が表示されます。そのアカウントが使用上限に達した場合、メッセージボックスの上に表示される上限の通知は、そのアカウントについてのものです。アカウントはセッションの開始時に決まります。自動で変わるのは、**上限時にアカウントを切り替え**（後述）を使う場合のみです。

セッションを別のアカウントに自分で移すには、セッション自身の**アカウント**チップをクリックして選びます。Claude Code、Codex、Grok Buildのセッションで使え、次のメッセージから反映されます。Grok BuildセッションのGrok履歴も一緒に移ります。Grokが別のアカウントで開き直せない場合は、メモが表示され、そのアカウントで最初からやり直されます。

## すべてのアカウントを使う：上限時に切り替える

同じエージェントのアカウントが2つ以上あると、アプリはそのすべてを使えます。1つの使用量が尽きても、別のアカウントで作業が続きます。[設定 → エージェント → アカウント](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit)を開き、**アカウント**の下の**使用上限時**グループにある**上限時にアカウントを切り替え**を探してください。アカウントを1つでも追加するとすぐに表示されます（Grok Buildも含みます）。その(i)には、セッションのアカウントの使用量が尽きると、そのエージェントの使用量が残っている別のアカウントにセッションが移って続行されること、新しいセッションは上限に達したアカウントを避けることが書かれています。最初からオンです（ご自身でアカウントを選びたい場合は、そこでオフにしてください）。ブラウザを開いていなくても動作します。

- セッションのアカウントが使用上限に達してターンが止まると、アプリは、使用量が残っている同じエージェントの別のサインイン済みアカウント（最も使用量が少ないもの）を選び、全履歴とともにセッションを移して、「… reached its usage limit, so this session now runs on …. Continue where you left off.」と送信します。画面の下部に、どのアカウントに移ったかを示す短いメモが表示されます。
- Claude Codeセッションがバックグラウンドで実行しているサブエージェントも、そのまま続行されます。上限に達したときにまだ作業中だったものは、作業内容を保ったまま次のステップで停止し、アプリはセッションを移す前にそれらを待ちます（最長2分）。その後、メッセージにそれらの名前が示され、エージェントは停止したところから1つずつ続行します。サブエージェントだけが上限に達した場合（そのモデルだけの上限など）、ターンが終了し、どれも作業中でなくなった時点でセッションが移ります。
- Hydorサブエージェント（エージェントが作業の一部を任せるために開始するセッション）はそれぞれ独立したセッションなので、上限でターンが止まると、各自で移ります。それを開始したエージェントには、失敗ではなく続行することが伝えられ、完了すると返信を受け取ります。
- メインのサインインと追加したアカウントは、すべて対象です。Claude CodeアカウントはClaude Codeアカウントに、CodexはCodexに、Grok BuildはGrok Buildに引き継がれます。
- Grok Buildアカウントは、週ごとの上限、クレジットの上限、または従量課金の支出上限に達すると、上限に達した状態になります。その場合、セッションは使用量が残っている別のサインイン済みGrokアカウント（最も使用量が少ないもの）に移り、「… reached its usage limit, so this session now runs on …」で続行されます。短いレート制限（リクエストの集中）では何も移りません。自然に解消されます。メッセージボックスの上の上限の通知は、Grokのセッションでも表示されます。
- Codexのゴールはセッションとともに移り、続行されます。
- すべてのアカウントが上限に達している場合は、何も移りません（Claude Codeで、後述の**上限時にAPIクレジットを使う**がオンの場合を除きます）。**使用量の上限後に再開**がオンの場合は、最初のアカウントがリセットされたときに、そのアカウントでセッションが続行されます。これはGrok Buildセッションでも同じです。詳しくは[使用量、上限、コスト](/guide/usage#continue-sessions-automatically-after-a-limit)をご覧ください。
- 上限に達したアカウントで開始した新しいセッションは、代わりに使用量が残っているアカウントで始まります。また、アカウントが上限に達しているセッションにメッセージを送ると、まずセッションが移るため、メッセージが断られることはありません。メッセージとともに、エージェントには、使用量が残っているアカウントで動いていること、つまり古いアカウントのリセットを待たなくてよいこと、そしてどのサブエージェントが続行できるかが伝えられます。
- VS Codeやターミナルで開いているセッションは、そのアカウントのままです。
- 上限のリセット（Codexのリセットクレジット、Claudeのリセット付与）とAPIクレジットは、引き続きClaude CodeとCodexのみが対象です。
- アプリ自身がClaude CodeやCodexに送る簡単な質問（**自動**になっている補助モデル、アプリの簡単なモデルのステップ、プルリクエストの説明、コマンドの提案）は、1つが上限に達している場合やサインアウトしている場合に、同じように次のサインイン済みアカウントに送られます。Claude CodeもCodexも応答できない場合は、Customモデルのいずれかが代わりに応答します（[アカウントがサインアウトされているとき](#when-an-account-is-signed-out)を参照）。

## アカウントがサインアウトされたとき

Claude Code、Codex、Grok Buildのアカウントは、サインアウトされることがあります。サインインが終了したか取り消された場合で、プログラムは「Not logged in · Please run /login」または「401 Unauthorized」と表示します。アプリは可能な限り別の方法で対処し、ほかに方法がない場合にだけ、もう一度のサインインを求めます。

- **セッション.** アカウントがサインアウトされているためにセッションのターンが受け付けられなかった場合、[上限時にアカウントを切り替え](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit)がオンになっていれば（初期状態でオンです）、セッションは履歴ごと、使用量が残っている同じエージェントの別のサインイン済みアカウントに移り、そのまま続行されます。画面の下部に「<セッション>：<アカウント>がサインアウトされているため、<別のアカウント>で続行します」という短いメモが表示され、エージェントには「… is signed out, so this session now runs on …. Continue where you left off.」と伝えられます。少し前にサインアウトが判明したアカウントのセッションにメッセージを送った場合も、同じように先にセッションが移るため、メッセージが受け付けられないことはありません。
- **セッションが移れない場合。** **上限時にアカウントを切り替え**がオフの場合や、そのエージェントの使用量が残っている別のアカウントがない場合、セッションは停止します。メッセージ欄の上にバナーが表示され、「<アカウント>はサインアウトされています」「再度サインインすると、このセッションは続行されます。」と案内され、**サインイン**ボタンが付きます。ここまたはターミナルで再度サインインすると、セッションは自動的に続行され、エージェントには「Signed in again. Continue where you left off.」と伝えられます。
- **バックグラウンド処理。** **自動**に設定された[補助モデル](/settings?s=models&find=Helper%20model)の小さな処理（セッションのタイトル、メモリのメモ、[プロフィール](/guide/memory#your-profile)の短縮、アプリの簡単なモデル処理、プルリクエストの説明など）は、サインアウトされたアカウントを15分間飛ばし、その後で再び試します。そのため、ターミナルで行ったサインインも検出されます。次のサインイン済みアカウントが応答し、その次にCodexが応答します。Claude CodeもCodexも応答できない場合（サインアウト、上限到達、未インストール）は、**Custom**のモデルのいずれかが処理を担当します。担当するのは、[設定 → エージェント → モデル → ティア](/settings?s=models&find=Tiers)でCustomの**高速**ティアに指定されたモデルです（次に**標準**、まれに大きな処理では**最高**、その次に**最大**）。指定がなければ、追加したモデルのうち最も安いものです（このコンピューター上のモデルは無料として扱われます）。試すのは最大2つまでです。かかった費用は、ほかのCustomモデルの使用と同じように計上されます。
- **サインインの案内。** どの方法でも処理できず、アカウントがサインアウトされている場合にのみ、すべてのページの右下（スマートフォンではメッセージ欄の上）にカードが表示されます。タイトルは「Claude Codeに再度サインインしてください」（またはCodex、Grok Build）で、その下に「<アカウント>はサインアウトされています。」と表示され、理由も示されます。「バックグラウンド処理に必要です（プロフィールの短縮）。ほかのアカウントやCustomモデルでは処理できませんでした。」、またはセッションが停止した場合は「… サインインすると続行されます。」です。**サインイン**を押すと、[設定 → エージェント → アカウント](/settings?s=accounts)と同じサインインダイアログが開きます。**今はしない**を押すとカードは1時間非表示になります。ただし、これが原因で停止したセッションがあると、カードは再び表示され、そのセッションのバナーも残ります。カードは同時に最大2枚まで表示され、それ以上は「+N件」から設定 → エージェント → アカウントに移動できます。カードは、カードや設定、ターミナルのいずれかでアカウントが再びサインインされると消えます（アプリは、次に通った呼び出しで検出します）。また、別の方法（別のアカウントやCustomモデルの応答）でバックグラウンド処理が再び行えるようになった場合も消えます。Claude CodeとCodexの両方がサインアウトされている場合は、先に応答するClaude Codeについてのみ案内が表示されます。

プロフィールにも表示されます。アカウントがサインアウトされていて短縮に失敗した場合、その下の理由に表示され（「Claude Codeアカウント「Work」はサインアウトされています。ほかのアカウントやCustomモデルでは処理できませんでした。再度サインインしてください（設定 → エージェント → アカウント）。」）、カードも表示されます。

## すべてのアカウントが上限に達したときにAPIクレジットを使う

Anthropic APIキー（[console.anthropic.com](https://console.anthropic.com) → API keys で取得）をお持ちの場合、すべてのClaude Codeアカウントが使用上限に達しても、Claude Codeのセッションは停止せずにそのキーで続行できます。費用がかかります。この方法で実行している間、セッションはサブスクリプションの対象外となり、AnthropicからAPI料金で請求されます。

1. [設定 → エージェント → アカウント](/settings?s=accounts&find=Use%20API%20credit%20at%20a%20limit)を開きます。**アカウント**にあるClaude Codeアカウントの行（メインのサインイン、または追加したアカウント）で**⋯**をクリックし、**APIキーを追加…**を選びます。
2. **Anthropic APIキー**にキーを貼り付け、**キーを保存**をクリックします。アプリはAnthropicでキーを確認し、このコンピューター上で暗号化して保管します。その後、行に**APIクレジット**タグが表示されます。**APIキーを変更…**でキーを置き換え、**APIキーを削除**で削除できます。
3. **使用上限時**グループにある**上限時にAPIクレジットを使う**をオンにします（(i)には、すべてのClaude Codeアカウントが使用上限に達したとき、セッションが停止せずにアカウントのAnthropic APIキーに請求する形で続行されること、オンにするまではオフであることが説明されています）。この項目は、Claude Codeにサインインしているか、Claude Codeアカウントを追加すると表示されます。

このとき、次のように動作します。

- Claude Codeセッションのアカウントが使用上限に達すると、アプリはまず**上限時にアカウントを切り替え**の動作を試し、使用量が残っている別のアカウントに移ります。どのアカウントにも残りがなく、この設定がオンの場合にのみ、セッションはAPIキーへの請求で続行されます。
- セッションは元のアカウントのままなので、履歴は移動しません。そのアカウントにキーがない場合は、別のClaude Codeアカウントのキーが使われます。
- セッションの上部、アカウントの横に**APIクレジット**タグが表示されます。カーソルを重ねると理由が表示されます。
- プランの使用量が再び使えるようになると、セッションは次のターンの終了後にそのプランに戻ります。元のアカウント、または使用量が残っている別のアカウントです。操作は必要ありません。
- アプリがアカウントの使用量を読み取れない場合は、作業がAPI課金に移ることはありません。
- Codexは対象外です。APIクレジットはありません。

## Gemini CLI、OpenCodeなどのACPエージェントを追加する

[設定 → エージェント → その他のエージェント](/settings?s=agents&find=Agents%20that%20speak%20ACP)を開きます。

- **自分のエージェント**（セッションを開始するときにClaude CodeやCodexと並んで表示されます）には、Customが最初に、その後に追加したエージェントが並びます。それぞれ、プログラムがここにインストールされていればチェック、されていなければ×と「未インストール」が表示されます。
- **ACPに対応したエージェント**（インストールし、そのCLIで一度サインインしてから、ここで追加します）には、まだ追加していない既知のエージェントが並びます。Gemini CLI、OpenCode、Qwen Code、Goose、Kimi CLI、Auggie、Grok Buildなどです。インストール済みのものが先に表示されます。「未インストール」と表示された行には、入手方法が示されます。未インストールのものは最初の数件だけが表示され、**すべて表示**で残りが表示されます。

追加するには、次の手順にします。

1. 行の端にある**追加**をクリックします。プログラムがすでにインストールされている場合、このボタンは目立つ表示になります。
2. アプリがインストール方法を把握している場合（Gemini CLI、OpenCode、Qwen Code、Auggie、Grok Build、およびACPアダプターが必要なエージェント）は、バックグラウンドでそのままインストールされます。Goose、Kimi CLIなどは、行に表示されたコマンドまたはアドレスを使って自分でインストールします。
3. エージェント自身のプログラムで一度サインインします。[ターミナル](/terminal)を開き、そのコマンド（例：`gemini`）を実行して、表示されるサインインの手順に従います。省略した場合、セッションに「Gemini CLI is not signed in. Run gemini once in a terminal and sign in there, then try again.」と表示されます。

これで、エージェントが開始ページの**実行環境**の一覧に表示されます。

追加したエージェントを変更するには、**編集**をクリックします。外すには、**⋯**メニューを開いて**外す**を選び、確認します。そのセッションは一覧に残りますが、続行するにはエージェントをもう一度設定する必要があります。Customは組み込みです。その行には「Built in: models from OpenRouter, Ollama and vLLM, in Settings → Models」と表示され、編集と外すの代わりに**モデル**ボタンがあります。

### Grok Build

**Grok Build**は、xAIのコーディングエージェント（`grok`プログラム）です。行の**追加**をクリックするだけで完了します。アプリは、必要になった最初のときにnpm（`@xai-official/grok`）からインストールするか、すでにあるものを使います。xAI独自のインストーラーによって`~/.grok/bin`に入ったものも使えます。その後、**エージェントプログラム**に表示され、ほかのものと同じく最新の状態に保たれます。HydorはこれをACPで実行し、アプリ独自のツール、承認カード、Grokのモデルを使います。

ほかのACPエージェントとはサインインの方法が異なります。ターミナルではなく[設定 → エージェント → アカウント](/settings?s=accounts)で行い、追加するとすぐに**Grok Build**の行が表示されます（[Claude Code、Codex、Grok Buildにサインインする](#sign-claude-code-codex-and-grok-build-in)を参照）。ここではGrokアカウントを追加することもできます。

### 自分のエージェントを追加する

ACPに対応していれば、どのプログラムもここで実行できます。

1. **自分のエージェント**のタイトルの横にある**自分で追加**をクリックします。
2. 次の項目を入力します。
   - **名前**：一覧に表示される名前です。例：「Gemini CLI」。
   - **コマンド**：起動するプログラムです。例：`gemini`、またはフルパス。
   - **引数**：ACPモードで起動するための指定です。例：`--experimental-acp`。
   - **環境変数（任意、1行に NAME=value）**：APIキーの変数など、プログラムに必要な設定です。
3. **保存**をクリックします。

コマンドは、標準入力と標準出力でやり取りしながら、エージェントをACPモードで起動するものである必要があります。

### 自分でセットアップするエージェント

一覧のエージェントの中には、自分でセットアップするプログラムがあります。アプリがインストールするものとは、次の点が異なります。

- **その他のエージェント**の行に、インストールに使うコマンドまたはアドレスが表示されます。アプリはウェブ上のスクリプトを代わりに実行しません。[ターミナル](/terminal)または行に示された方法で、自分でインストールします。
- エージェント自身のプログラムで、同じくターミナルで一度サインインします（たとえばそのコマンドを実行してサインインの手順に従うか、そこでモデルを選びます）。その後は、アプリが起動します。セッションとメモリは、そのエージェント自身のフォルダに保存され、承認カードもエージェントが提供するものになります。
- そのうち1つは、独自のゲートウェイに接続します。先にエージェント自身のセットアップコマンドでゲートウェイを設定し、ゲートウェイを起動したままにしてください。
- エージェント自身がACPに対応していない場合は、ACPアダプターが必要です。アプリは、アダプターをエージェントと一緒にインストールします。どちらも、インストールスクリプトを実行せずに、アプリ専用のフォルダにnpmでインストールされます。自分でインストールしたエージェントは、PATHにある場合に使われます。
- MCPサーバーを受け付けないエージェントは、そのエージェント自身のツールだけで動作します。アプリのツール（ページ、検索など）は届かず、セッションの開始時にその旨が表示されます。それでも、アプリのガイドライン、メモリのメモ、スキルは最初のメッセージと一緒に渡されます。

### ここでACPエージェントにできること・できないこと

アプリは、選んだフォルダでセッションを開き、エージェントのメッセージと手順を表示し、エージェントが許可を求めるたびに確認します。Claude CodeやCodexとは、次の点が異なります。

- メッセージは一度に1件ずつ処理されます。作業中に送ったメッセージは、メッセージ欄の上のキューで待機し、ターンの終了時に送信されます（Customも同様です）。
- 以前のセッションを開き直せないエージェントでは、古いセッションを続行すると、それまでの会話なしで最初から始まります。セッションにはその旨が表示されます。以前は開き直せたのに、できなくなった場合も、失敗せずに、メモを添えて最初から続行されます。
- 添付した画像は、エージェントが画像を受け付ける場合にのみ届きます。
- ゴール、フォーク、引き継ぎは利用できません（Customにはゴールとフォークがあります）。
- アプリのツール（ページ、検索、メモリなど）は、MCPサーバーとしてエージェントに届きます。エージェントが受け付ける場合はアドレスで、そうでない場合はアプリがそのために起動する小さなプログラムを通じて届きます。どちらも受け付けないエージェントは、自分のツールだけで動作しますが、ガイドライン、メモリのメモ、スキルは受け取ります。

## Customのモデルの入手元

Customは、ClaudeとChatGPTのプランのモデル、このコンピューター上のモデル、クラウド上のモデルを、他のエージェントと同じツール、スキル、MCPサーバーで実行します。スタートページでCustomを選び、続いてモデルを選びます。モデルは3か所から提供されます。

- **契約中のサブスクリプション**：ClaudeとChatGPTのプランのモデルです。このコンピューター上のClaude CodeとCodexのサインインを通して利用します。設定は不要です。Claude Codeにサインインしていれば、Customの**モデル**メニューにClaude Opus、Fable、Sonnet、Haikuが表示され（それぞれ常に最新のもの）、CodexにChatGPTでサインインしていれば、ChatGPTプランに含まれるモデル（例：GPT-6 Luna）が表示されます。サインアウトされているプログラムが見つかると、再度サインインするまでそのモデルはメニューから消えます。また、ChatGPTではなくAPIキーでサインインしたCodexからは、モデルは提供されません。これらはAPIキーやトークンごとの課金ではなく、プランの使用量を消費するため、これらを使ったCustomのセッションでは、そのステップの料金が$0と表示されます。プログラムの各アカウントは、他の単発の作業と同様に順番に試されます。使用量の上限に達したアカウントやサインアウトされたアカウントがあると、そのステップは次のアカウントに引き継がれます（**上限時にアカウントを切り替え**がオンの場合）。[機密セッション](/guide/sessions#keep-a-session-confidential)では、これらのモデルは使われません。AnthropicまたはOpenAIのサーバー上で動作するためです。回答の仕組みについては、[Custom](/guide/custom#what-custom-is-and-when-to-use-it)をご覧ください。
- **このコンピューター**：ここにインストールされているモデル（Ollama、vLLM）と、ネットワーク上のエンドポイントです。
- **クラウド**：OpenRouter、他の場所にあるエンドポイント、Ollamaのクラウドモデルです。

Customのモデルを選べる場所ならどこでも選べます。スタートページ、セッションのモデルメニュー、Customのティア、補助モデル、エージェントやアプリのモデルです。

[設定 → エージェント → モデル](/settings?s=models)に、Customのモデルに必要なものがすべてそろっています。このページは上から順に7つの部分で構成されています。

- **補助モデル**：アプリの小さな作業に使うモデルです。
- **ティア**：作業の種類ごとのモデルです（[ティア：作業の種類ごとのモデル](#tiers-a-model-for-each-kind-of-job)をご覧ください）。
- **契約中のサブスクリプション**：Claude CodeとCodexそれぞれの行に、Customに提供されるモデルが表示されます。行には「サインアウト済み：これらのモデルを使うには再度サインインしてください」と表示され、**アカウント**へのリンクが付きます。または「このコンピューターにインストールされていません」と表示されます。
- **このマシン上**：このコンピューターの性能と、ここにインストールされているモデルです。
- **Hugging Faceからモデルを追加**：オープンモデルの検索、確認、インストールを行います。
- **OpenRouter**：1つのキーで数百のモデルを利用できます。3つのグループがあります。キー、追加したモデル、さらに追加するための検索です。
- **ランタイムとエンドポイント**：Ollama、vLLM、その他のOpenAI互換サーバー、Hugging Faceトークンです。

Customの**モデル**メニューでは、モデルが**契約中のサブスクリプション**、**このコンピューター**、**クラウド**の下にグループ化され、各行にどこを経由するかが表示されます。「Claude Code」「Codex」「OpenRouter」「Ollama」「vLLM」、またはエンドポイントの名前です。モデルにカーソルを合わせると、実行される場所と一度に読み込める量が表示されます。例：「OpenRouter · 128Kコンテキスト」「vLLM、このマシン上 · 32Kコンテキスト · 使用時に起動」。リストは1分ごとに自動で更新されます。

## 補助モデルを選ぶ

補助モデルは、会話とは別に、セッションのそばで行う小さな作業を担当します。

- リクエストをもとに新しいセッションに名前を付ける（サイドバーに表示されるタイトル）
- Customの自動モードでステップを確認し、各ターンの後にCustomのゴールを確認する
- 1日に1回ほどメモリを整理し、それ以降の会話から学習し、エージェントが最初に読むインデックス用にメモのタイトルを付ける
- ブラウザで開いているウェブページについての質問に答える
- ウェブ検索の語句に含まれる条件（サイト、日付、ページの種類、言語）を、Naget Searchが検索する前に読み取る（[エージェントのウェブ検索の仕組み](/guide/web#how-agents-search-the-web)をご覧ください）
- 画像を認識できないCustomモデルのために画像を説明する
- Hydorサブエージェントの長い返答を要約する
- セッションからアプリやスケジュールタスクの下書きを作る
- ハンズフリー音声モード

[設定 → エージェント → モデル](/settings?s=models&find=Helper%20model)を開き、**補助モデル**グループの**モデル**メニューをクリックします（(i)に小さな作業の一覧が表示されます）。

- **自動**（デフォルト）：Claude Code経由のClaude Haiku、またはClaude Codeが応答できない場合はCodexです。使用量の上限に達したアカウントがある場合は、まず次にサインインしているアカウントに質問が引き継がれ（**上限時にアカウントを切り替え**がオンの場合）、サインアウトされたアカウントは飛ばされます。どちらのプログラムも応答できない場合は、Customモデルのいずれかが作業を行います（Customの**高速**ティアに指定されているモデル、なければ追加したモデルのうち最も安いもの。プランのモデルは同じ2つのプログラムを経由するため、ここでは対象外です）。それでも対応できない場合に限り、サインインを求めるカードが表示されます（[アカウントがサインアウトされたとき](#when-an-account-is-signed-out)をご覧ください）。どれも応答しない場合、エラーにそれぞれの理由が表示されます。「週間の上限に達しました」、Codexのプランで提供されていないモデルなどです。
- Customのモデルのいずれか。Customの**モデル**メニューと同じようにグループ化され（**契約中のサブスクリプション**、**このコンピューター**、**クラウド**）、経由先（Claude Code、Codex、OpenRouter、Ollama、vLLM、またはエンドポイントの名前）と、画像を認識できるものには「画像対応」が表示されます。ClaudeやChatGPTのプランのモデルも補助モデルにできます。その場合は、プランの使用量でClaude CodeまたはCodex経由で応答します。

自動は画像を認識できません。画像を認識できないモデルでCustomを使う場合は、画像対応の補助モデルを選んでください。そうしないと、Customは画像の説明を受け取れません。

## このコンピューターで実行できるものを確認する

[設定 → エージェント → モデル](/settings?s=models&find=On%20this%20machine)の**このマシン上**セクションは、このコンピューターの概要から始まります。

- **グラフィックス**：グラフィックスカード（GPU）とそのメモリです。Apple siliconのMacではチップ（「Apple M3 Max」など。グラフィックスはコンピューターのメモリを共有します）、GPUがない場合は「GPUなし」と表示されます（その場合、モデルはプロセッサで実行されます）。
- **メモリとディスク**：コンピューターのメモリの合計と空き容量、ディスクの空き容量と、インストール済みモデルが使用している容量です。
- **実行方法：**：**Ollama**とvLLMがインストールされているかどうかとそのバージョン、またはインストール用のリンクです。
- グラフィックスカードがある場合は、収まるモデルの大きさです。「1つのGPUに4ビットで約30Bパラメータまで収まります」（Macの場合：「4ビットで約40Bパラメータまで収まります」）。パラメータはモデルの大きさを表す指標で、4ビットは一般的な圧縮形式で、必要なメモリが約4分の1になります。

その下には次の項目があります。

- **進行中のダウンロード**：それぞれに進行状況バー、完了した量、OllamaとvLLMのどちら向けかが表示されます。**キャンセル**で中止できます。失敗またはキャンセルされたものには理由と**閉じる**が表示されます。
- **インストール済みモデル**（最初の数件のみ表示され、続きは**すべて表示**）：それぞれにランタイム（OllamaまたはvLLM）、サイズ、詳細（Ollamaモデルではサイズや圧縮方式など）、画像を認識できる場合は「画像対応」、実行中かどうかが表示されます。
  - vLLMモデルには**開始**と**停止**があります。セッションが初めてそのモデルを使うときに自動で起動し（初回の起動には1〜2分かかります）、空きメモリが最も多いグラフィックスカードで実行されます（そのままでは収まらない場合は8ビットで実行）。1枚では収まらない場合は、2、4、または8枚に分割されます（「GPU 1、2で実行中」）。Macでは、Apple siliconで実行されます。**停止**をクリックするまで、アプリを再起動しても実行され続けます。起動できない場合は、その下に理由が表示されます。
  - モデルの**⋯**メニューにある**外す**を選ぶと、確認後に、このコンピューターからモデルのファイルが削除されます。後でもう一度インストールできます。

まだモデルがない場合は、「ここにはまだモデルがありません。下のHugging Faceから追加してください。」と表示されます。

## Hugging Faceからモデルを追加する

Hugging Faceは、オープンモデルの主要なサイトです。[Hugging Faceからモデルを追加](/settings?s=models&find=Add%20a%20model%20from%20Hugging%20Face)グループ（このコンピューター向けのおすすめ、またはすべてから検索）では、いくつかのモデルの提案、検索、そしてダウンロードの前に、各モデルがこのコンピューターでどのように動作するかの確認ができます。

### このコンピューター向けのおすすめ

検索する前に、このコンピューターの性能に合わせて、アプリがおすすめする実行可能なモデルが表示されます。

- **LFM3-VL 2B**（Liquid AI）：小型で高速、画像も読み取れます。ほとんどのコンピューターで動作します。
- **Gemma 4 12B**（Google）：画像も読み取れる万能型のモデルで、高性能なグラフィックスカードを搭載したコンピューター向けです。
- **Flint**（Recursive）：コーディングエージェント向けに作られており、Apple siliconで32 GB以上のMac向けです。
- **GLM-5.3 Flash**（Z.ai）：オープンモデルの中でも最高クラスで、大型のグラフィックスカードを複数搭載したサーバー向けです。

それぞれに、ここで快適に動作するか低速かどうか、どのように実行されるか（「8ビットのvLLM、GPU 0上」「vLLM、2つのGPUに分割」「vLLM、Apple silicon上」）、ダウンロードサイズ、**インストール**が表示されます。快適に動作するモデルのうち最も強力なものには**ここで最適**と表示されます。デフォルトではvLLMで実行されます。NVIDIAのグラフィックスカードもApple siliconもないコンピューターでは、小型モデルのOllama版が表示されます。実行に必要なものがまだ設定されていない場合は、警告が表示されます（「vLLMが設定されていません」「Ollamaが起動していません」）。[Ollama、vLLM、その他のエンドポイントに接続する](#connect-ollama-vllm-or-another-endpoint)をご覧ください。**さらに2件、より高性能なコンピューター向け**（件数は状況により異なります）の行には、その他のモデルと、それぞれに必要な環境が表示されます。ウェルカムツアーでも同じモデルがおすすめされます。

### 検索とフィルタ

1. **Hugging Faceを検索、またはorg/nameを貼り付け**に入力します。`qwen3`のような名前、モデルの完全な名前（`org/name`）、またはhuggingface.coのアドレスを入力できます。入力する前には、いくつかの名前の候補や**ダウンロード数の多いものを見る**が表示されます。
2. フィルタで一覧を絞り込みます（組み合わせて使えます）。
   - **ここで快適に動作**：このコンピューターで快適に動作するモデルのみ表示します。
   - **GGUF・Ollama**：Ollamaで実行できるGGUF形式のモデルです。
   - **vLLM**：vLLMがグラフィックスカード上で実行するsafetensors形式のモデルです。
   - **画像対応**：画像も読み取れるモデルです。
3. 右側のメニューで並び順を変更します。**ダウンロード数順**、**トレンド**、**いいね数順**、**新しい順**です。

最大40件のモデルが表示されます。最初は8件で、残りは**すべて表示**で見られます。完全な名前を指定したモデルは、検索結果に含まれていなくても最初に表示され、Enterキーを押すとすぐに確認されます。

各行には、作成元と名前、形式（**GGUF**または**vLLM**）、画像を認識できる場合は**画像**、利用規約への同意を作成元が求めている場合は**制限付き**、パラメータ数で表したサイズ、過去30日間のダウンロード数、いいね数、最終更新日が表示されます。

### 最初の判定

各モデルの下には、サイズだけから出した最初の目安が色付きのラベルで表示されます。

- **vLLMで快適に動作**または**Ollamaで快適に動作**：おおよその速度が付きます（「約40トークン/秒」。トークンは単語の断片です）。グラフィックスカードのメモリに収まることを示します。
- **プロセッサで低速に実行**または**プロセッサで非常に低速に実行**：コンピューターのメモリにしか収まらないため、プロセッサで実行されます。これができるのはOllamaだけです。
- **このコンピューターには大きすぎます**：収まらない、またはダウンロードがディスクに収まりません。
- **Ollamaで4ビットなら快適に動作…**：保存されている状態のモデルは大きすぎますが、圧縮した4ビット版ならOllamaで快適に動作します。

ラベルにカーソルを合わせると、判定の根拠となる数値が表示されます。

### ダウンロード前に確認する

モデルの**確認**をクリックすると、ここでどのように動作するかを詳しく確認できます。パネルには、サイズ、一度に読み込める量（コンテキスト）、画像を認識できるかどうかが表示され、続いて次の内容が表示されます。

- GGUFモデルの場合：「Ollamaで実行」と、利用可能な各サイズが小さいものから順に表示されます（ファイルが小さいほど、品質をわずかに犠牲にして速度とメモリを優先します）。各行には、判定、必要なメモリ、おおよその速度、ダウンロードサイズ、**インストール**ボタンが表示されます。Ollamaがここで起動していない場合や、大きすぎるサイズの場合は、インストールはグレー表示になります。
- vLLMモデルの場合：「vLLMで実行。セッションが使うときにGPU上で起動します」と、同様の数値、どのグラフィックスカードを使うかの注記、**ダウンロード**ボタンが表示されます。vLLMがインストールされていない場合や、お使いのvLLMがこの種類のモデルにまだ対応していない場合はその旨が表示され、GGUF版がある場合は代わりにそちらの**確認**が表示されます。
- それ以外の場合：「このアプリで実行できる重みがありません（vLLM用のsafetensors、Ollama用のGGUF）。」

数値は、最大で約32,000トークンの会話を想定しています。これは、このコンピューター上のモデルに設定される長さです。**閉じる**でパネルが閉じます。

### インストールとその後

**インストール**（Ollama）または**ダウンロード**（vLLM）をクリックします。ダウンロードは**このマシン上**に進行状況とともに表示されます。完了すると、モデルがCustomの**モデル**メニューに表示されます。途中で中断されたvLLMのダウンロードは、もう一度試すと続きから再開されます。1枚のグラフィックスカードには大きすぎるvLLMモデルは、起動時に8ビット（FP8）で保存されます。これにより、重みが使うメモリは半分になり、品質の低下はわずかです（NVIDIAのRTX 30シリーズ以降のカードとA100以降が対象）。それでも収まらない場合は、複数のカードを合わせて収まるなら、それらに分割されます。

### 制限付きモデルと非公開モデル

作成元が先に利用規約への同意を求めるモデルもあり、そのモデルには**制限付き**と表示されます。huggingface.coのモデルのページで規約に同意し、Hugging Faceトークンを追加してください（[Hugging Faceトークン](#hugging-face-token)をご覧ください）。非公開モデルにもトークンが必要です。

## OpenRouterでモデルを使う

OpenRouter（openrouter.ai）では、1つのキーで多数のメーカーのモデルを何百も利用できます。料金は使った分だけです。

### キーを追加する

1. openrouter.aiでキーを取得します（このセクションからリンクしています）。
2. [設定 → エージェント → モデル](/settings?s=models&find=OpenRouter)の**OpenRouterのキー**の行で**キーを追加**をクリックし、ダイアログの**OpenRouterのキー：sk-or-…**に貼り付けて**保存**をクリックします。

行には**OpenRouterに接続済み**と、キーの先頭と末尾が表示されます。**⋯**メニューの**キーを削除**を選ぶと、キーが消去されます。キーはサーバーに保存され、再び表示されることはありません。

最初に必要になったときに追加することもできます。キーがない状態でエージェントが画像、絵、動画、音声を作ろうとすると、会話の中のカードでキーを求められます（[エージェントにOpenRouterのキーが必要なとき](/guide/documents-voice#when-an-agent-needs-the-openrouter-key)）。エディタのAIツールでは、ダイアログで求められます。どちらの場合も、キーはここに保存されます。

### おすすめのモデル

検索する前に、**OpenRouterのモデルを追加**グループの**おすすめ**に、Custom向けのモデルが4つ、それぞれの理由とともに表示されます。**GPT-6 Luna**（高速で低価格）、**Grok 4.7**（高品質で、拒否が少なめ）、**GPT-6.1 Sol**（より高品質）、**Claude Opus 5.5**（総合で最高）です。**追加**をクリックすると、モデル選択に追加されます。画像、音楽、音声、動画には、アプリのおすすめとしてSeedream 5.0 Pro（より速く安価なFlashもあります）、Lyria 3 Pro、Seed Audio 1.0、Seedance 2.5があります。[設定 → 機能 → 画像、動画、音声](/settings?s=images)をご覧ください。

### カタログを検索する

同じグループで、**OpenRouterを検索：deepseek、qwen、claude…**に入力するか、候補の名前または**新着を見る**をクリックします。フィルタは次のとおりです。

- **ツール呼び出し**：ツールをネイティブに呼び出せるモデルです。Customが最もうまく使えるタイプです（**最も一致**ではこれらが先頭に表示されます）。
- **画像対応**
- **推論**：答える前に考えるモデルです。
- **自由**

右側のメニューで、結果の並び順を選べます。**最も一致**（名前で検索している間）、**新しい順**、**最安**、**最長コンテキスト**です。最大50件のモデルが表示され、最初は8件で、残りは**すべて表示**で見られます。

各モデルには、メーカー、名前、ラベルが表示されます。ラベルは、**最新**（常にメーカーの最新バージョン）、**新規**（過去3週間以内に掲載）、**自由**、**推論**、**画像**、**ネイティブツールなし**（この場合、Customはツールを指示文で説明し、呼び出しをテキストから読み取ります）です。その下には、一度に読み取れる量（「128Kコンテキスト」）、最長の返信（「16K出力」）、100万トークンあたりの入力と出力の価格、掲載された月、短い説明、OpenRouterでの名前が表示されます。

### モデル選択にモデルを追加する

モデルの**追加**をクリックします。行には**追加**と表示され、モデルは検索の上の**OpenRouterのモデル**グループ（「モデル選択に表示」）と、Customの**モデル**メニューに表示されます。×をクリックすると、メニューから外せます。1つも追加しないうちは、OpenRouterのモデルは表示されません（「OpenRouterを使うには、モデルを1つ以上追加してください。」）。

## Ollama、vLLM、その他のエンドポイントに接続する

**ランタイムとエンドポイント**グループでは、モデルを実行するプログラムに接続します。[設定 → エージェント → モデル](/settings?s=models&find=Runtimes%20and%20endpoints)から開きます。

### Ollama

Ollamaは、グラフィックカードまたはプロセッサを使って、お使いのコンピューターでモデルを実行する無料のプログラムです。行には、バージョンとともに「実行中」と表示されるか、「このアドレスでは実行されていません」と**Ollamaをインストール**のリンクが表示されます。アドレスは、変更しなければ`http://127.0.0.1:11434`です。別のアドレスにするには、欄に入力します。すると横に**保存**が表示されます。そのOllamaにあるすべてのモデルがCustomのモデル一覧に表示され、アプリの外で取得したものも含まれます。

### vLLM

vLLMは、NVIDIAのグラフィックカード上でモデルを動かす高速なサーバーで、ここではHugging Faceのモデルを実行する標準の方法です。1枚のカードに収まらない大きなモデルは、8ビットで実行するか、2枚、4枚、8枚のカードに分けて実行します。Macでは、Metalプラグイン（vllm-metal）を使い、Apple siliconで動作します。アプリはPATH上や、condaまたはvenvの環境から自動で見つけ、バージョンと場所を表示します。「見つかりません（pip install vllm、またはコマンドを指定してください）」と表示された場合は、インストールするか、`vllm`コマンドのフルパスを欄に入力して**保存**をクリックします（入力すると表示されます）。欄を空にすると、アプリが自動で探します。

### その他のOpenAI互換エンドポイント

多くのプログラムやサービスが、OpenAIのAPIと同じ方法で応答します。LM Studio、llama.cppのサーバー、その他のプロバイダーなどです。追加するには次のようにします。

1. グループのタイトルの横にある**エンドポイントを追加**をクリックします。
2. ダイアログで、**名前**、アドレス（`http://localhost:1234/v1`など）、**キー（任意）**を入力します。
3. **追加**をクリックします。

エンドポイントは、アドレスと提供モデル数とともに行として表示されます。そのモデルは、Customの一覧に「モデル（名前）」の形で表示されます。×をクリックすると削除されます。同じ名前でエンドポイントを追加すると、最初のものが置き換わります。

[機密セッション](/guide/sessions#keep-a-session-confidential)では、アドレスがこのコンピューターまたはプライベートネットワークのエンドポイントを使えます。`localhost`、`127.0.0.1`、`::1`、`10.…`、`192.168.…`、`172.16.…`から`172.31.…`、または`.local`で終わる名前です。それ以外のアドレスはオンラインとみなされます。自分のサーバーにつながるアドレスでも同様ですので、その場合はプライベートアドレスを使ってください。Ollamaのアドレスも同じで、Ollamaのクラウドモデル（名前が「cloud」で終わるもの）は常にオンラインとみなされます。

### Hugging Faceのトークン

[Hugging Faceのトークン](/settings?s=models&find=Hugging%20Face%20token)があると、アプリは限定公開またはプライベートのモデルをダウンロードできます（行には「限定公開またはプライベートのモデル専用」と表示されます）。Hugging Faceのアカウント設定でトークンを作成し、**トークンを追加**をクリックして、ダイアログに貼り付け（`hf_`で始まります）、**保存**をクリックします。行にはトークンの先頭と末尾が表示され、**⋯**メニューに**トークンを削除**があります。
