# エージェント、アカウント、モデル

Hydorでは、複数のAIエージェントを使えます。Claude Code、Codex、Custom（任意のモデルに使えるアプリ独自のエージェント）のほか、ACPに対応したエージェントとして、Gemini CLI、OpenCode、Qwen Code、Goose、Grok Build、Antigravity CLI（GoogleのAIプラン向けのGoogleのエージェント）などがあります。このトピックでは、エージェントごとの違い、プログラムのインストールと更新の仕組み、サインインの方法（複数アカウントを含む）、そしてCustomのモデルの入手元（OpenRouter、Ollama、このコンピューターで動かすHugging Faceのモデル、OpenAI互換のエンドポイント）を説明します。

![開始ページでのエージェントの選択：Claude Code、Codex、Custom](images/agents-models.webp)

## どのエージェントを使えばよいですか？

エージェントは、セッションで実際に作業を行うプログラムです。メッセージを読み、ツール（ファイル、コマンド、Web）を使って答えます。モデルは、その裏側にあるAIです。ここにあるエージェントはどれも、アプリから同じサポート（Web検索、ブラウザ、メモリ、スキル、接続）を受けられます。違いは、モデルの入手元です。

- **Claude Code**（Anthropic）。Claudeのプランで動くか、AnthropicのAPIアカウントに課金されます。モデルはAnthropicのもの（Opus、Sonnet、Haiku）です。独自の使用量の上限があり、[使用量ページ](/usage)で確認できます。
- **Codex**（OpenAI）。ChatGPTのプランで動きます。モデルはOpenAIのものです。こちらにも使用量の上限があり、使用量ページに表示されます。Codexはアプリに付属しています。
- **Custom**（アプリ独自のエージェント）。ClaudeとChatGPTのプランのモデル（Claude CodeとCodexのサインイン経由）に加え、[設定 → エージェント → モデル](/settings?s=models)で追加した任意のモデルを動かせます。OpenRouter経由のモデル、このコンピューター上のモデル（OllamaまたはvLLM）、OpenAI互換のエンドポイントが使えます。オープンモデルや低価格のモデル、コンピューターの外に出さないモデルを使いたいときに便利です。詳しくは[Custom、アプリ独自のエージェント](/guide/custom)をご覧ください。
- **ACPに対応したエージェント**：Gemini CLI、OpenCode、Qwen Code、Goose、Kimi CLI、Auggie、Grok Build（xAIのコーディングエージェント。Grokのモデルを使用）、Antigravity CLI（Googleのコーディングエージェント。GoogleのAIプランを使用）など、または独自のコマンド。ACP（Agent Client Protocol）は、アプリがエージェントのプログラムと通信するための共通の方式です。どれも一度サインインすれば、それぞれ独自のモデルを使います。多くはそのプログラム自体でサインインし、Grok BuildとAntigravity CLIは[設定 → エージェント → アカウント](/settings?s=accounts)でサインインします。2026年6月18日以降、Gemini CLIはGoogle AI ProとUltra（およびGemini Code Assist for individuals）には対応しなくなりました。これらのプランでGoogleのターミナルエージェントを使うには、Antigravity CLIを利用します（[Antigravity CLI](#antigravity-cli)を参照）。Gemini CLIは、Gemini APIキー、またはGemini Code AssistのStandardかEnterpriseのライセンスで引き続き使えます。

アプリ内でそれぞれにできること：

- ゴール（合意したチェックが成立するまで、アプリがラウンドを重ねてエージェントに作業を続けさせる機能。[ゴール](/guide/goals)を参照）：すべてのエージェント（Claude Code、Codex、Custom、その他のACPエージェント）で使えます。Claude CodeまたはCodexのチャットで入力した`/goal`は、そのプログラム独自の、より簡易なゴールです。フォーク（以前の返信時点からのセッションのコピー）：Claude Code、Codex、Customで使えます。その他のACPエージェントでは使えません。
- **続きを開く…**（会話を別のエージェントに引き継ぐ機能）：Claude CodeまたはCodexから、もう一方のエージェントまたはCustomへ。
- 思考レベル（モデルがどれだけ深く考えるか）：Claude Code、Codex、Grok Build、Antigravity CLI、およびモデルが対応しているその他のACPエージェント。
- 複数アカウントと、上限に達したときのアカウント切り替え：Claude Code、Codex、Grok Build。使用量ページに表示されるプランの使用量上限：この3つに加え、Antigravity CLIでは使用量の確認先を示すカードが表示されます（サインインは1つのみで、自分で開始したセッションでのみ動作します。[Antigravity CLI](#antigravity-cli)を参照）。
- 上限のリセットと、上限到達時のAPIクレジット：Claude CodeとCodexのみ。

## 新しいセッションのエージェントとモデルを選ぶ

開始ページ（`/`）では、メッセージ欄の下の行で、作業を担当するエージェントを指定します。

1. **実行環境**をクリックします。一覧には、**Claude Code**（「Anthropic · Claudeプランまたはapiキー」）、**Codex**（「OpenAI · ChatGPTプランまたはAPIキー」）、**Custom**（「任意のモデル：OpenRouter、Ollama、vLLM」）と、設定 → その他のエージェントで追加したすべてのエージェント（「ACPエージェント · 」とそのコマンド）が表示されます。一番下の**Custom用モデル**で設定 → モデルが開き、**エージェントを追加・管理**で設定 → その他のエージェントが開きます。
2. **モデル**をクリックして選びます。一番上にある**自動**は、最初に選ばれている項目で、ティアに任せて選びます。最高から始まり、問題が難しすぎるとわかったときは最大になります（[ティア：仕事の種類ごとのモデル](#tiers-a-model-for-each-kind-of-job)を参照）。その下には、そのエージェント自身のモデルだけが表示されます。エージェントのデフォルトには「デフォルト」と表示されます。古いバージョンのモデルは「古いモデル2件」のような行の奥にあり、クリックすると表示されます。モデルが8つを超えると、上部に**モデルを検索**ボックスが表示されます。数文字入力してEnterを押すと、最初に一致したものが選ばれます。エージェントがアプリの求めどおりにモデルを返せなかったときは、メニューにエージェント自身の言葉で理由が表示され、**もう一度試す**で再度問い合わせます。
3. **オプション**の下に、**思考レベル**（対応しているエージェントとモデルのみ：デフォルト、低、ミディアム、高など。Grok Buildについては[Grok Buildの思考レベル](#effort-for-grok-build)を参照）と、**権限**（確認なしでエージェントに許可する操作）があります。メッセージ欄でShift+Tabを押しても、権限を切り替えられます。

開始ページは、作業する場所ごと（各プロジェクト、各フォルダ、**新しいタスクフォルダ**）に選んだ内容を、すべてのデバイスで記憶します。各プログラムのモデル、思考レベル、権限は、最後に設定したとおりに戻ります（[開始ページが記憶する内容](/guide/sessions#what-the-start-page-remembers)を参照）。

Custom以外のACPエージェントでは、最初のセッションを終えたあとに、**モデル**と**権限**の選択肢が表示されます。そこには、そのエージェントが前回の実行時に提示した内容が並びます。Grok Buildは例外で、アプリがGrokに問い合わせるため、追加した直後から、モデルと各モデルが対応する思考レベルが表示されます。Antigravity CLIのモデルと思考レベルは、最初のセッションを終えたあと、セッションの開始時にアプリが取得して表示されます。

**オプション** → **機密**をオンにすると、**実行環境**は**Custom**になり、**モデル**にはこのコンピューターまたはプライベートネットワーク上のモデルだけが、性能の高い順に並びます。詳しくは[セッションを機密にする](/guide/sessions#keep-a-session-confidential)をご覧ください。

スマートフォンでは、これらのメニューは画面の下からシートとして開きます。

## セッションの途中でモデルを切り替える

セッション内では、モデル、思考レベル、権限がメッセージ欄の下にあります。「Opus 5.5 · 高 · プラン」のように表示される1つのチップで、クリックすると**モデル**、**思考レベル**、**権限**を選べます。

別のモデルを選ぶと、セッションはそのモデルで続きます。

- Claude Codeはすぐに切り替わります。
- Codexは次のターンから新しいモデルを使います。
- Customは、ターンの途中でも次のステップから新しいモデルを使います。
- ほかのACPエージェントは、モデルの選択肢を提供していれば切り替わります。

セッションの**思考レベル**も同じ仕組みです。選ぶと、実行中のエージェントは次のターンからそれを使います。切り替え先のモデルがそれまでの思考レベルに対応していない場合は、そのモデルのデフォルトが表示され、モデルはそれで動きます。

モデルメニューには、そのセッションのエージェントのモデルだけが表示されます。機密セッションでは、このコンピューターまたはプライベートネットワーク上のモデルだけです。会話を別のエージェントに移すには、セッションのメニュー（⋯）→ **Codexで続きを開く**、**Claude Codeで続きを開く**、または**Custom Agentで続きを開く**を使います（Claude CodeとCodexのセッションから。2つのうちのもう一方は、サインインしている場合にのみ表示され、Customはモデルが設定されると表示されます）。次のメッセージで、同じフォルダに、これまでの会話を引き継いだそのエージェントの新しいセッションが始まります。停止したセッションは、送信前に別のモデルを選ばない限り、最後に使ったモデルで再開します。

## Grok Buildの思考レベル

Grokのモデルには、Claude CodeやCodexと同じ推論の思考レベルがあります。

- Grok 4.6（および同じ選択肢を提供する新しいモデル）：**xhigh**、**高**、**ミディアム**、**低**。デフォルトは**高**です。
- Grok 4.5：**高**、**ミディアム**、**低**。

開始ページで**実行環境**から**Grok Build**を選び、**オプション** → **思考レベル**を開くと、選んだモデルの思考レベルと**デフォルト**が一覧表示されます。Grok Buildを追加した直後、最初のセッションの前でも表示されます。実行中のGrok Buildセッションでは、自身の**思考レベル**ピッカー（メッセージ欄の下のチップ）で思考レベルを変更できます。[アプリ](/guide/apps)の実行でも指定できます。それまでの思考レベル（Grok 4.5でのxhigh）に対応しないモデルに切り替えると、ピッカーにはそのモデルのデフォルトが表示され、モデルはそれで動きます。

これはGrok専用ではありません。ACPに対応した他のエージェントでも、モデルが思考レベルを提供していれば、同じ**思考レベル**の選択肢が表示されます。

## ティア：仕事の種類ごとのモデル

エージェントは、モデルを名前ではなくティアで選びます。**高速**は、結果を確認できる小さくて明確な仕事向け、**標準**は、中くらいの規模の明確なタスク向け、**最高**は、計画を立て、サブエージェントを率い、その作業を確認するセッションのメインエージェント向け、**最大**は、最も難しい問題向けです。仕事の大半は、低価格のモデルでも十分にこなせる明確な部分でできています。そのため、結果の質を落とさずにセッションの費用を抑えられます。最も強力なモデルが、引き続き作業の計画と確認を担うからです。

開始ページでは、**モデル**は**自動**で開き、セッションは最高で始まります（[スケジュールタスク](/guide/tasks#model-effort-permissions-and-other-options)のセッションも同じ**自動**で始まり、[アプリ](/guide/apps)はモデル名の代わりにティアを指定して考えさせることもできます）。メインエージェントは、明確な部分を標準と高速のサブエージェントに任せ、最高では手に負えない難しさだとわかったとき（2回失敗した修正、見つからない原因、証明など）は、自分で最大に切り替えることがあります。そのときは、理由とともに会話に一行表示されます。リクエストが、文面だけで最大に送られることはありません。難しそうに見えるものの大半は、最高のほうが低コストで解決できます。代わりにモデルを名前で選ぶと、セッションはそのモデルで考えます。サブエージェントには引き続きティアが使われます。自分のエージェントを、1つのティアで考えさせることもできます（[エージェントが考えに使うもの：ティア](/guide/agents#what-an-agent-thinks-with-tiers)を参照）。

[設定 → エージェント → モデル → ティア](/settings?s=models&find=Tiers)では、プログラムごとに各ティアの意味を設定します。ティアごとに1行あり、グループのタイトルの横にあるスイッチでプログラム（**Claude Code**、**Codex**、**Custom**）を選びます。各行には、モデルと（Claude CodeとCodexの場合は）思考レベルがあります。ティアの（i）で詳しい説明を見られます。初期状態では、Claude Codeは、高速がHaiku、標準がSonnet、最高がOpus、最大が最新のFableです。Codexは、高速がLuna、標準がTerra、最高がSol、最大がAstraです（どれかがないプランでは、提供されている中で最も近いモデルになり、2つのティアが同じモデルを共有する場合は、上位のティアの思考レベルを高くします）。Customのティアは自動で埋まり、触れていないティアには、Customが持つモデルのうち、その種類で最新のものが入ります。Claudeのプランからは、高速がHaiku、標準がSonnet、最高がOpus、最大が最新のFableになります。なければ、ChatGPTのプランから、Luna、Terra、Sol、Astraになります。それもなければ、追加したモデルのうち、このコンピューター上にないもの（OpenRouter、エンドポイント）で、名前がこれらのファミリーのどれかを示すものが使われます。このコンピューター上のモデルは、名前から強さがわからないため、自動では選ばれません。また、小さなモデル（Haiku、Luna）が最高になることもありません。小さなモデルやローカルのモデルしかない場合は、自分で選ぶまでティアは空のままで、Customのセッションは選んだモデルをそのまま使います。最高にモデルが設定されると、開始ページのCustomで**自動**が選べるようになり、そのセッションはサブエージェントを主導します（ほかのすべてのセッションと同じく、Hydorサブエージェントです）。**Custom**タブでは、ティアごとにCustomの任意のモデルを指定できます（[Customのモデルの入手元](#where-customs-models-come-from)を参照）。サインインしていないClaude CodeやCodexはスイッチでグレー表示になり、**未設定**であることを示す行と**設定**ボタンが表示されます。このセクションは、使える最初のプログラムを表示して開きます。そのプログラム用に保存したティアは、サインインしたときのためにそのまま残ります。触れていないティアは、そのプログラムの、その種類の最新モデルに追従します。タイトル横の**⋯**メニューにある**初期設定に戻す**で、Customの選択を含め、すべて元に戻せます。

ティアの下の**セッションのティア**グループにある2つのスイッチで、セッションでのティアの使い方を決めます。

- **サブエージェントを主導**（初期状態ではオン）：セッションのメインエージェントは、計画を立て、明確な部分を低価格のティアのサブエージェントに任せ、その作業を確認するよう指示されます。ティア指定なしで依頼されたサブエージェントには、標準が使われます。オフにすると、エージェントは別の判断をしない限り単独で作業し、開始ページとタスクのフォームには「自動」が表示されません。
- **難問には最大**（初期状態ではオン）：**自動**のメインエージェントは、最高では難しすぎるとわかった問題について、自分で最大に切り替えることがあります。オフにすると、**自動**のセッションは最高のままです。

## エージェントプログラムは自動でインストールされ、更新されます

Claude Code、Codex、Gemini CLI、Grok Buildなどは、このコンピューター上のプログラムです。手動でインストールする必要はありません。例外はAntigravity CLIです。Googleが自分でのインストールを求めているため、アプリはインストールしません（[Antigravity CLI](#antigravity-cli)を参照）。更新は自動で行われます。

[設定 → エージェント → アカウント](/settings?s=accounts&find=Agent%20programs)を開き、**エージェントプログラム**グループを見てください。Claude Code、Codex、Gemini CLI、OpenCode、Qwen Code、Auggie、Grok Build（追加した場合）、およびACPアダプターが必要なエージェントが一覧表示され、それぞれ、セッションが実行しているバージョンと入手元が示されます。

- **自分でインストール**：自分でインストールしたものです（Grok Buildの場合は、xAIの専用インストーラーでインストールしたものも含み、`~/.grok/bin`に置かれます）。
- **アプリがインストール**：アプリが専用のフォルダにインストールしたものです。
- **アプリに付属**：Codexはアプリに付属しています。
- **未インストール：初めて使うときに自動でインストールされます**：入っていない状態です。今すぐ入手するには**インストール**をクリックします。

新しいバージョンが出ているときは、行に「…が公開されています」と表示されます。自分用のCodexも入っている場合、Codexの行には「ターミナルで使っているもの：…」が加わります。セッションではアプリのCodexが、ターミナルではご自身のCodexが動きます。

入っていないプログラムは、必要になった最初のときにも自動でインストールされます。Claude Codeは、サインインするときやClaude Codeセッションを開始するとき、ACPエージェントは、設定 → エージェント → その他のエージェントで追加するときやそのセッションを開始するときです。アプリはnpmで専用のフォルダにインストールするため、管理者権限は必要ありません。

Goose、Kimi CLI、Antigravity CLIなど、一部のエージェントはこの一覧にありません。自分でインストールしてください（入手先は設定 → エージェント → その他のエージェントに表示されます）。ACPアダプターが必要なエージェントは、アダプターとエージェント本体の2つに分けてインストールされますが、一覧には両方をまとめた1行が表示されます。

## エージェントプログラムを最新の状態に保つ

[**自動で更新**](/settings?s=accounts&find=Update%20automatically)をオンにすると（**エージェントプログラム**の最後の行にあります。オフにしない限りオンです）、アプリは1日に1回、各エージェントプログラムを最新バージョンに更新します。最初の実行はアプリの起動から約10分後です。

- アプリがインストールしたコピーは、アプリ専用のフォルダでnpmを使って更新されます。Codexは、アプリに同梱されているものより新しいコピーがあれば、そちらに切り替わります。
- ご自身でインストールしたものは、それぞれの更新コマンドで更新されます。Claude Codeは`claude update`、Codexは`codex update`（ターミナルで実行されるもの）、OpenCodeは`opencode upgrade`、Grok Buildは`grok update`です。
- `npm install -g`でインストールしたGemini CLI、Qwen Code、Auggie、Grok Build、またはACPアダプター対応のエージェントは、そのフォルダにユーザーが書き込める場合、npmで更新されます。それ以外の方法でインストールしたものは、インストールした方法でご自身で更新してください。
- Claude Codeは独自のリリースラインに従います。設定に`"autoUpdatesChannel": "stable"`がある場合は安定版、それ以外は最新版です。
- `DISABLE_AUTOUPDATER=1`でClaude Code自身の更新をオフにしている場合（Dockerイメージはこの設定です）、アプリもClaude Codeを自動では更新しません。**今すぐ更新**を押せば更新されます。

アプリは、新しいバージョンがセッションでの使い方どおりに動作することを確認できた場合にだけ、そのバージョンを残します。Claude Codeはセッションの開始時に応答し、モデルを一覧表示できること、Codexはアプリサーバーを起動し、モデルを一覧表示できること、それ以外はプログラムが起動してバージョンを返せることが条件です。いずれもサインインは不要で、プランの使用量も消費しません。応答を待つ時間はそれぞれ1分で、コンピューターがスリープせずに動作していた時間だけが数えられます。そのため、確認の途中でMacがスリープしても、1分を使い切ることはありません。初回の応答が遅い場合（Macは新しいプログラムを初めて実行する前に内容を調べます）は、2分の猶予を加えてもう一度起動し、それでも応答がなければ失敗となります。失敗したバージョンは取り消されます。

- アプリがインストールしたコピー、またはご自身のものをnpmで更新した場合は、1つ前のバージョンに戻ります。
- ご自身のClaude Codeの場合、セッションは1つ前のバージョンで動き続けます。このバージョンは、Claude Codeのインストーラーが新しいバージョンの隣に残しています。ターミナルの`claude`コマンドは新しいバージョンのままです。行には「… did not work here」と表示されます。
- 失敗したバージョンは自動では再試行されませんが、次のバージョンは試されます。**今すぐ更新**を押すと、もう一度試します。

この行の下には、アプリが最後に確認した時刻が「Up to date · checked 2h ago」のように表示され、**今すぐ確認**でもう一度確認できます。新しいバージョンが公開されている場合はその旨が表示され、**今すぐ更新**ですべてまとめてインストールできます（プログラムごとのボタンはありません）。更新中は、どのプログラムを更新しているかが表示されます。その下の行には、直近の更新で変わった内容（「Claude Code 2.1.308 → 2.1.316」など）や、インストールできなかった理由が表示されます。

実行中のセッションは開始時のバージョンのまま動き続け、新しいセッションは新しいバージョンを使います。**自動で更新**をオフにしても、アプリは1日に1回確認して公開されているバージョンを表示しますが、**今すぐ更新**をクリックするまでインストールはしません。

## Claude Code、Codex、Grok Buildにサインインする

Claude CodeとCodexは、サインインしないと使えません。追加した後のGrok Buildも同様です（[Gemini CLI、OpenCode、その他のACPエージェントを追加する](#add-gemini-cli-opencode-and-other-acp-agents)を参照）。[設定 → エージェント → アカウント](/settings?s=accounts)を開きます（スマートフォンでは、設定がセクションの一覧になっています。エージェントの下の**アカウント**をタップします。上部のタイトルで一覧に戻れます）。**アカウント**グループ（その (i) には、Claude Code、Codex、Grok Buildのうちセッションが使うサインインであること、仕事用と個人用など別のサブスクリプションを追加でき、セッションの開始時に選べることが説明されています）には、各エージェント自身のサインインが先に、続いて追加したアカウントが表示されます。Grok Buildのサインインにもここに行（**Grok Build**）があり、追加すると表示されます。それぞれの行には、メールアドレス、プラン、サインイン方法とともに緑のチェックが表示されます。サインインしていない場合や問題が起きた場合は、赤の×とともに「Not signed in」または問題の内容が表示されます。

サインインの手順は次のとおりです。

1. エージェントの横の**サインイン**をクリックします。
2. 方法を選びます。
   - Claude Code：**Claudeサブスクリプション**（Claudeのプラン）または**コンソール（API課金）**（AnthropicのAPIアカウント）。
   - Codex：**デバイスコード**または**ブラウザのリダイレクト**。
   - Grok Build：選ぶ項目はなく、常にコードでサインインします。
3. **サインインリンクを取得**をクリックします。
4. ダイアログに表示される手順に従います。
   - Claude Code：リンクを開き（**サインインページを開く**）、ブラウザでアクセスを承認します。ページに表示されたコードを**ページに表示されたコードを貼り付け**に貼り付けて、**サインインを完了**をクリックします。
   - Codex、デバイスコード：どのデバイスでもリンクを開き、ChatGPTにサインインして、ダイアログに表示されるワンタイムコードを入力します。完了すると、ダイアログが自動で検知します。
   - Codex、ブラウザのリダイレクト：サインイン後、ブラウザが「localhost」のページを開こうとして失敗します。そのページのアドレスをコピーし、**ブラウザのlocalhostアドレスを貼り付け**に貼り付けて、**サインインを完了**をクリックします。
   - Grok Build：リンクとワンタイムコードが表示されます。どのデバイスでもリンクを開き、Grokアカウントでサインインして、コードを確認します（**2. このコードを確認する**）。貼り付ける操作はありません。完了すると、ダイアログが自動で検知します。

成功すると「Claude Code is signed in」（CodexやGrok Buildの場合はその名前）と表示されます。失敗した場合は、ダイアログに理由が表示されるので、**もう一度試す**をクリックします。

Googleの AI プラン向けのGoogleのエージェントであるAntigravity CLIは、追加すると同じグループに専用の**Antigravity CLI**の行が表示されます。サインインの方法が少し異なります。[Antigravity CLI](#antigravity-cli)を参照してください。

サインインすると、ボタンは**アカウントを切り替え**になります。同じサインインの手順を別のアカウントで始めます（Grok Buildの場合は新しいコード）。**サインアウト**は行の**⋯**メニューにあり、確認すると、このコンピューター上でそのプログラムをサインアウトします。そのプログラムを使うすべてのターミナルとエディタが対象です。

サインアウトした状態でGrok Buildのセッションを始めると、「Grok Build is not signed in: sign in with your Grok account in Settings → Agents → Accounts, then try again.」と表示されてセッションが停止します。そこでサインインして、メッセージを送り直してください。サブスクリプションの代わりに、エージェントの環境の`XAI_API_KEY`にxAIのAPIキーを設定しても、Grok Buildを使えます。

ウェルカムツアー（アイコンバーの**ヘルプ**から開けます）では、使いたいエージェントとモデルを尋ねられ、これらのサインインも順に案内されます。

## 2つ目のアカウントを追加する（仕事用と個人用）

Claude Code、Codex、Grok Buildのアカウントを複数サインインでき、たとえば仕事用プランと個人用プランをセッションごとに選べます。

1. [設定 → エージェント → アカウント](/settings?s=accounts&find=Accounts)を開きます。
2. **アカウント**グループのタイトルの横にある**アカウントを追加**をクリックします。
3. **Claude Code**、**Codex**、**Grok Build**のいずれかを選び（Grok Buildは設定済みの場合に選べます。Antigravity CLIは選べません。サインインが1つしかないためです。[Antigravity CLI](#antigravity-cli)を参照）、名前（40文字まで。「仕事」「個人」など）を入力して**追加してサインイン**をクリックします。
4. 新しいアカウントのサインインダイアログが開きます。上で説明したとおりにサインインします。

追加したアカウントは、それぞれ独立してサインインし、独自のセッション履歴を持ちます。設定、指示、スキル、プラグインは、そのエージェントのメインのサインインと共有されるため、変更は両方に反映されます。Claude Codeでは、メインのサインインで信頼したフォルダは追加したアカウントでも信頼されるので、そのフォルダ自身の権限ルールがセッションに適用されます。同じエージェントの2つのアカウントに同じ名前は付けられません。

追加したGrok Buildのアカウントには、サインイン情報とGrok自身のセッション履歴を保存する専用のフォルダがあります。Grok CLI自身の設定（config、ルール（`AGENTS.md`）、スキル、プラグイン、MCPのサインイン）は、メインのサインインと共有されます。

追加したアカウントには、エージェント自身のサインインの下にそれぞれ行があり、**サインイン**または**アカウントを切り替え**が表示されます。**⋯**メニューには**サインアウト**、**名前を変更**、**外す**があります。

- **名前を変更**：新しい名前を入力します。
- **サインアウト**：このアカウントとして動いているセッションは、再びサインインするまで動作しなくなります。
- **外す**：アカウントをアプリから取り除きます。そのセッションは一覧から消えますが、履歴はディスクに残ります。ただし、**サインイン情報とセッションの履歴も削除する**にチェックを入れた場合は、それらも削除されます。そのアカウントとして実行中のセッションがある間は外せません。先にそれらを停止してください。

[使用量ページ](/usage)には、追加したClaude Code、Codex、Grok Buildのアカウントごとにカードが表示され、それぞれの上限を確認できます。

## セッションを実行するアカウントを選ぶ

選んだエージェントに追加したアカウントがある場合（Grok Buildは、追加した後）、開始ページの**オプション**に**アカウント**の行が表示されます。これをクリックします。

- **サインイン情報**は、そのプログラム自身のアカウントです（**アカウント**でそのエージェントの最初のもの。Grok Buildの場合は「The Grok Build CLI's own account」）。
- 追加した各アカウントは、名前で一覧に表示されます。
- **アカウントを管理**を選ぶと、設定 → エージェント → アカウントが開きます。

開始ページは、エージェントごとに選択を記憶し、どこでも同じになります。追加したアカウントで動いているセッションでは、そのアカウントの名前が人のアイコンとともにセッションの上部に表示されます。そのアカウントが使用上限に達した場合、メッセージ欄の上の上限の通知はそのアカウントについてのものです。アカウントはセッションの開始時に決まります。自動で変わるのは、**上限時にアカウントを切り替え**（下記）を使った場合だけです。

セッションを自分で別のアカウントに移すには、セッション自身の**アカウント**チップをクリックして選びます。Claude Code、Codex、Grok Buildのセッションで使え、次のメッセージから有効になります。Grok Buildのセッションでは、Grokの履歴も一緒に移ります。別のアカウントでGrokが履歴を開き直せない場合は、メモを添えて、そこで新しく始まります。

## すべてのアカウントを使う：上限時に切り替える

同じエージェントのアカウントが2つ以上あると、アプリはそのすべてを使えます。1つの使用量がなくなっても、別のアカウントで作業を続けられます。[設定 → エージェント → アカウント](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit)を開き、**アカウント**の下の**使用上限時**グループにある**上限時にアカウントを切り替え**を探します。Grok Buildを含め、アカウントを1つでも追加すると表示されます（その (i) には、セッションのアカウントの使用量がなくなると、そのエージェントの使用量が残っている別のアカウントにセッションが移って続行されること、新しいセッションは上限に達したアカウントを避けることが説明されています）。最初からオンになっていて（自分でアカウントを選びたい場合は、そこでオフにします）、ブラウザを開いていなくても動作します。

- セッションのアカウントが使用上限に達してターンが止まると、アプリは、使用量が残っている同じエージェントの別のサインイン済みアカウント（使用量が最も少ないもの）を選び、履歴をすべて引き継いでセッションをそこへ移し、「… reached its usage limit, so this session now runs on …. Continue where you left off.」を送信します。どのアカウントに移ったかは、画面の下に短いメモで表示されます。
- Claude Codeのセッションがバックグラウンドで実行しているサブエージェントも続行されます。上限に達した時点でまだ作業中だったものは、次のステップで作業内容を残したまま停止し、アプリはセッションを移す前にそれらを待ちます（最長2分）。その後、メッセージにそれらの名前が示され、エージェントが各サブエージェントを止まったところから続けます。サブエージェントだけが上限に達した場合（そのモデルだけの上限など）は、ターンが終わり、作業中のものがなくなってからセッションが移ります。
- Hydorサブエージェント（エージェントが作業の一部を任せるために開始するセッション）はそれぞれ独立したセッションなので、上限でターンが止まると、各自で移ります。それを開始したエージェントには、失敗ではなく続行すると伝えられ、完了すると返信を受け取ります。
- メインのサインインと追加したアカウントは、すべて対象です。Claude CodeのアカウントはClaude Codeのアカウントに、CodexはCodexに、Grok BuildはGrok Buildに引き継ぎます。Antigravity CLIには移行先となる別のアカウントがないため、これは適用されません（[Antigravity CLI](#antigravity-cli)を参照）。
- Grok Buildのアカウントは、週間の上限、クレジットの上限、従量課金の支出上限のいずれかに達すると、上限に達した状態になります。その場合、セッションは使用量が残っている別のサインイン済みのGrokアカウント（使用量が最も少ないもの）に移り、「… reached its usage limit, so this session now runs on …」で続行されます。短時間のレート制限（リクエストの急増）では何も移りません。自然に解消されます。メッセージ欄の上の上限の通知は、Grokのセッションにも表示されます。
- アプリが進めるゴールはアプリ自身のものなので、新しいアカウントでも続行されます。Codexで`/goal`と入力したゴールは、セッションとともに移り、続行されます。
- 数えられるのは、セッションのモデルに残っている使用量です。Fableの週間上限のように1つのモデルだけの上限は、そのモデルのセッションだけを止めます。SonnetやOpusのセッションは、Fableの分だけを使い切ったアカウントへも移ります。セッションのモデルがプランに含まれていないアカウントは、そのセッションでは使われません（Claude Codeは、ProプランのFableのように、そのモデルが「requires usage credits」と表示します）。セッションはそのモデルを含むプランのアカウントへ移るか、そのうち最初にリセットされるアカウントを待ちます。メモには「…のプランには…が含まれていないため」と表示されます。
- すべてのアカウントが上限に達している場合は、何も移りません（Claude Codeで、下記の**上限時にAPIクレジットを使う**がオンの場合を除く）。**使用量の上限後に再開**がオンの場合、最初のアカウントがリセットされた時点で、そのアカウントでセッションが続行されます。スタートページの上限の通知には、そのアカウントとリセットされる時刻が、「Workが先にリセットされます（in 3 h 36 min）」のように表示されます。これはGrok Buildのセッションにも当てはまります。詳細は[使用量、上限、料金](/guide/usage#continue-sessions-automatically-after-a-limit)を参照してください。
- アカウントの上限がリセットされた直後に、アプリはそのアカウントの使用量を読み直してから、待機中のセッションをどこへ移すかを決めます。そのため、セッションはまだ上限に達しているアカウントへ送られず、すぐに移動します。
- セッションを移せない場合は、画面の下部の短いメモにその理由が表示され、セッションは元のアカウントに残ります。**使用量の上限後に再開**がオンの場合は、そのアカウントがリセットされたときに続行されます。以前の移動で別のアカウントに残ったセッション履歴のコピーがあっても、移動は止まりません。そのコピーは移動する履歴で置き換えられ、コピーのうち異なる部分はファイルページの**ゴミ箱**に移ります。
- 上限に達したアカウントで新しいセッションを始めると、代わりに使用量が残っているアカウントで始まります（どのアカウントにも残りがない場合は、最初にリセットされるアカウントで始まり、その通知にはそこで続行する時刻が表示されます）。また、アカウントが上限に達しているセッションにメッセージを送ると、先にセッションが移るため、メッセージが拒否されることはありません。メッセージとともに、エージェントには、使用量が残っているアカウントで動いていることと、どのサブエージェントが続行できるかが伝わるので、元のアカウントのリセットを待つことはありません。
- VS Codeやターミナルで開いているセッションは、元のアカウントのままです。
- 上限のリセット（Codexのリセットクレジット、Claudeのリセット付与）とAPIクレジットは、引き続きClaude CodeとCodex専用です。
- アプリ自身がClaude CodeやCodexに送る簡単な質問（**自動**になっている補助モデル、アプリの簡単なモデルステップ、コミットメッセージ、プルリクエストの説明、コマンドの提案）は、片方が上限に達している場合やサインアウトしている場合も、同じように次のサインイン済みアカウントに送られます。Claude CodeもCodexも応答できない場合は、Customモデルのいずれかが代わりに応答します（[アカウントがサインアウトしているとき](#when-an-account-is-signed-out)を参照）。

## アカウントがサインアウトされたとき

Claude Code、Codex、Grok Buildのアカウントは、サインアウトされることがあります。サインインが終了したか取り消されると、プログラムが「Not logged in · Please run /login」や「401 Unauthorized」と表示します。アプリはできる限り自動的に対処し、ほかに方法がない場合にだけ、もう一度サインインするよう求めます。（ここで一度もサインインしていないClaude CodeやCodexについては、「もう一度」を付けずにサインインを求めます。Hydorはそのセッションやそれを使うHydorサブエージェントを開始せず、代わりに理由を示します。）

Antigravity CLIには、切り替えられる別のアカウントがありません。サインアウトされた状態でセッションを開始すると、セッションは「Antigravity CLI is not signed in: sign in with your Google account in Settings → Agents → Accounts, then try again.」と表示されて停止し、設定のアカウントの行にもサインアウト中と表示されます。そこでサインインしてから、メッセージをもう一度送信してください。

- **セッション.** セッションのターンが、アカウントがサインアウトされているために受け付けられなかったとき、[上限時にアカウントを切り替え](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit)がオンであれば（初期状態ではオンです）、そのセッションは履歴をすべて保ったまま、同じエージェントのサインイン済みで使用量に余裕のある別のアカウントに移り、作業を続けます。画面の下部に「<セッション>：<アカウント>はサインアウトされているため、<別のアカウント>で続行します」という短いメモが表示され、エージェントには「… is signed out, so this session now runs on …. Continue where you left off.」と伝えられます。少し前にアカウントのサインアウトが見つかったセッションにメッセージを送った場合も、同じ方法で先にセッションが移るため、メッセージが受け付けられないことはありません。
- **セッションが移れないとき。** **上限時にアカウントを切り替え**がオフの場合や、そのエージェントに使用量の残っている別のアカウントがない場合は、セッションが停止します。メッセージ欄の上にバナーが表示され、「<アカウント>はサインアウトされています」「もう一度サインインすると、このセッションは続行されます。」と案内され、**サインイン**ボタンが付きます。ここでも、ターミナルでも、もう一度サインインすると、セッションは自動的に続行され、エージェントには「Signed in again. Continue where you left off.」と伝えられます。
- **バックグラウンドの作業。** [補助モデル](/settings?s=models&find=Helper%20model)が**自動**になっているときの小さな作業（セッションのタイトル、メモリのメモ、[プロフィール](/guide/memory#your-profile)の要約、アプリのクイックなモデルの処理、コミットメッセージ、プルリクエストの説明など）は、サインアウトされたアカウントを15分間飛ばし、その後もう一度試します。そのため、ターミナルで行ったサインインも検知されます。代わりに、次のサインイン済みアカウントが応答し、それでだめならCodexが応答します。サインインしていないプログラムは起動すらされません。Claude CodeもCodexも応答できない場合（サインアウト、上限到達、未インストール）は、**Custom**モデルのいずれかが作業を行います。まず[設定 → エージェント → モデル → ティア](/settings?s=models&find=Tiers)でCustomの**高速**ティアに指定されたモデルが使われ（その次は**標準**、まれに大きな作業では**最高**、さらに**最大**の順）、それがなければ追加した中で最も安価なモデルが使われます（このコンピューター上のモデルは無料として扱われます）。試すのは最大2つまでです。かかる費用は、ほかのCustomモデルの使用と同じように計上されます。
- **サインインを求める通知。** どのモデルも作業できず、しかもサインアウトされたアカウントがある場合にのみ、すべてのページの右下（スマートフォンではメッセージ欄の上）にカードが表示されます。タイトルは「Claude Codeにもう一度サインインしてください」（CodexやGrok Buildの場合もあります。ここで一度もサインインしていない場合は「Claude Codeにサインインしてください」）で、その下に「<アカウント>はサインアウトされています。」と表示され、求める理由として「バックグラウンドの作業に必要ですが（プロフィールの要約）、ほかのアカウントやCustomモデルでは実行できませんでした。」、またはセッションが停止した場合は「… サインインすると続行されます。」と表示されます。**サインイン**を押すと、[設定 → エージェント → アカウント](/settings?s=accounts)と同じサインインダイアログが開きます。**今はしない**を押すと、カードは1時間非表示になります。ただし、それが原因で停止したセッションがあれば、カードはもう一度表示され、そのセッションのバナーも残ります。カードは同時に最大2つまで表示され、それを超える分は「+N件」から設定 → エージェント → アカウントに移動できます。カードは、カードや設定、ターミナルのいずれからでもアカウントにもう一度サインインすると消えます（アプリは、次に正常に通った呼び出しで検知します）。また、バックグラウンドの作業がほかの方法（別のアカウントやCustomモデルの応答）で再びできるようになった場合も消えます。Claude CodeとCodexの両方がサインアウトされているときは、先に応答するClaude Codeについてだけ表示されます。

プロフィールにも同じ内容が表示されます。アカウントがサインアウトされているために要約に失敗した場合、その下に理由が表示され（「Claude Codeアカウント「Work」はサインアウトされており、ほかのアカウントやCustomモデルでも実行できませんでした。もう一度サインインしてください（設定 → エージェント → アカウント）。」）、カードも表示されます。

## すべてのアカウントが上限に達したときにAPIクレジットを使う

Anthropic APIキー（[console.anthropic.com](https://console.anthropic.com) → API keysで取得）をお持ちの場合、Claude Codeのすべてのアカウントが使用上限に達しても、セッションは停止せず、そのキーで続行できます。これは有料です。この方法で実行されている間、セッションはサブスクリプションの対象外となり、AnthropicからAPI料金で請求されます。

1. [設定 → エージェント → アカウント](/settings?s=accounts&find=Use%20API%20credit%20at%20a%20limit)を開きます。**アカウント**にあるClaude Codeアカウントの行（メインのサインイン、または追加したアカウント）で**⋯**をクリックし、**APIキーを追加…**を選びます。
2. **Anthropic APIキー**にキーを貼り付けて、**キーを保存**をクリックします。アプリはAnthropicでキーを確認し、このコンピューター上に暗号化して保存します。その後、行に**APIクレジット**のタグが表示されます。**APIキーを変更…**でキーを置き換え、**APIキーを削除**で削除できます。
3. **使用上限時**グループで**上限時にAPIクレジットを使う**をオンにします（(i)には、Claude Codeのすべてのアカウントが使用上限に達したとき、セッションは停止せず、いずれかのアカウントのAnthropic APIキーに請求される形で続行されること、また、オンにするまではオフであることが説明されています）。この項目は、Claude Codeにサインインしているか、Claude Codeアカウントを追加すると表示されます。

このときの動作は次のとおりです。

- Claude Codeセッションのアカウントが使用上限に達すると、アプリはまず**上限時にアカウントを切り替え**の動作を試し、使用量に余裕のある別のアカウントに移ります。どのアカウントにも余裕がなく、この設定がオンの場合にのみ、セッションはAPIキーに請求される形で続行されます。
- セッションは元のアカウントのままなので、履歴は移動しません。そのアカウントにキーがない場合は、ほかのClaude Codeアカウントのキーが使われます。
- セッションの上部にあるアカウント名の横に、**APIクレジット**のタグが表示されます。カーソルを合わせると、理由を確認できます。
- プランの使用量が再び使えるようになると、セッションは次のターンの終了後にプランに戻ります。元のアカウント、または使用量に余裕のある別のアカウントに戻ります。操作は不要です。
- アプリがアカウントの使用量を読み取れない場合、作業がAPI課金に移ることは決してありません。
- Codexは対象外です。CodexにはAPIクレジットがありません。

## Gemini CLI、OpenCodeなどのACPエージェントを追加する

[設定 → エージェント → その他のエージェント](/settings?s=agents&find=Agents%20that%20speak%20ACP)を開きます。

- **自分のエージェント**（セッションを始めるときにClaude CodeやCodexと並んで表示されます）には、最初にCustom、続いて追加したエージェントが並びます。各行には、プログラムがここにインストールされていればチェックマーク、されていなければ×と「未インストール」が表示されます。
- **ACPに対応したエージェント**（インストールし、そのエージェント自身のCLIで一度サインインしてから、ここで追加します）には、まだ追加していない既知のエージェントが並びます。Gemini CLI、OpenCode、Qwen Code、Goose、Kimi CLI、Auggie、Grok Build、Antigravity CLIなどです。インストール済みのものが先に表示されます。「未インストール」と表示された行には、入手方法が書かれています。インストールされていないものは最初の数件だけが表示され、残りは**すべて表示**で確認できます。

追加するには、次の手順にします。

1. 行の右端にある**追加**をクリックします。プログラムがすでにインストールされている場合は、ボタンが目立つ表示になります。
2. アプリがインストール方法を把握しているもの（Gemini CLI、OpenCode、Qwen Code、Auggie、Grok Build、およびACPアダプターが必要なエージェント）は、バックグラウンドですぐにインストールされます。Goose、Kimi CLI、Antigravity CLIなどは、行に表示されたコマンドまたはアドレスを使って自分でインストールします。
3. エージェント自身のプログラムで一度サインインします。[ターミナル](/terminal)を開き、そのコマンド（例：`gemini`）を実行して、表示に従ってサインインします。省略すると、セッションで「Gemini CLI is not signed in. Run gemini once in a terminal and sign in there, then try again.」（Gemini CLIがサインインしていません。ターミナルで一度gemini を実行してサインインしてから、もう一度お試しください。）と表示されます。Grok BuildとAntigravity CLIは例外で、[設定 → エージェント → アカウント](/settings?s=accounts)でサインインします。

Gemini CLIは、Gemini APIキー、またはGemini Code AssistのStandardまたはEnterpriseライセンスで使うためのものです。ここでのプリセットは`--acp`を付けて起動します。2026年6月18日以降は、Google AI ProとUltra（およびGemini Code Assist for individuals）には対応しなくなりました。これらのプランにはAntigravity CLIを使ってください。

追加したエージェントは、開始ページの**実行環境**の一覧に表示されます。

追加したエージェントを変更するには、**編集**をクリックします。取り除くには、行の**⋯**メニューを開いて**外す**を選び、確認します。そのエージェントのセッションは一覧に残りますが、続けるにはエージェントをもう一度設定する必要があります。Customは組み込みです。行には「組み込み：OpenRouter、Ollama、vLLMのモデル（設定 → モデル）」と表示され、編集と外すの代わりに**モデル**ボタンがあります。

### Grok Build

**Grok Build**はxAIのコーディングエージェント（`grok`プログラム）です。行の**追加**をクリックするだけで済みます。アプリは、初めて必要になったときにnpm（`@xai-official/grok`）からインストールします。すでにあるものがあればそれを使い、`~/.grok/bin`にあるxAI自身のインストーラーで入れたものも使えます。その後は**エージェントプログラム**に表示され、ほかのプログラムと一緒に最新の状態に保たれます。HydorはACPでこれを実行し、アプリ独自のツール、承認カード、Grokのモデルを使います。

サインインの方法はほかのACPエージェントと異なります。ターミナルではなく、[設定 → エージェント → アカウント](/settings?s=accounts)で行います。追加するとすぐに**Grok Build**の行が表示されます（[Claude Code、Codex、Grok Buildにサインインする](#sign-claude-code-codex-and-grok-build-in)を参照）。ここでGrokのアカウントをさらに追加することもできます。

### Antigravity CLI

**Antigravity CLI**はGoogleのターミナル用コーディングエージェント（`agy`プログラム）で、GoogleのAIプランで使えるものです。2026年6月18日以降、Gemini CLIはGoogle AI ProとUltra（およびGemini Code Assist for individuals）には対応しなくなりました。Gemini CLIは、Gemini APIキー、またはGemini Code AssistのStandardまたはEnterpriseライセンス向けとして残ります。

**自分でインストールします。** Googleは利用者自身によるインストールを求めているため、アプリはインストールしません。[設定 → エージェント → その他のエージェント](/settings?s=agents&find=Agents%20that%20speak%20ACP)の**ACPに対応したエージェント**にある**Antigravity CLI**の行（コマンドは`agy acp`）に、Googleのインストーラーが表示されます。macOSとLinuxでは、[ターミナル](/terminal)で次のコマンドを実行します。`agy`が`~/.local/bin`に置かれます。

```
curl -fsSL https://antigravity.google/cli/install.sh | bash
```

Windowsでは、PowerShellで次を実行します。

```
irm https://antigravity.google/cli/install.ps1 | iex
```

自動で更新されるため、アプリが最新に保つ**エージェントプログラム**には含まれません。インストールしたら、行の**追加**をクリックします。

**サインインします。** 追加すると、[設定 → エージェント → アカウント](/settings?s=accounts)に**Antigravity CLI**の行が表示され、専用のサインインが使えます。

1. **サインイン**をクリックし、続けて**サインインリンクを取得**をクリックします。
2. **1. このリンクを開く**をクリックします。Googleのサインインページが開きます。Googleアカウントでサインインします。Google AI Pro、Ultra、Plus、またはAntigravityの無料プランを使っている個人アカウントが対象です。するとページにコードが表示されます。
3. そのコードを**2. ページのコードを貼り付ける**に貼り付け（または、移動した先のページのアドレス全体を貼り付け）、**サインインを完了**をクリックします。

すると行にメールアドレスが表示され、セッションを一度開いたあとはプラン（たとえばGoogle AI Pro）も表示されます。行の**⋯**メニューにある**サインアウト**を使うと、このコンピューター上のAntigravity CLIがサインアウトされ、それを使うすべてのプログラムに影響します。ターミナルアプリでは、`hydor accounts sign-in antigravity`で同じサインインができます。サインアウトした状態でセッションを始めると、「Antigravity CLI is not signed in: sign in with your Google account in Settings → Agents → Accounts, then try again.」（Antigravity CLIがサインインしていません。設定 → エージェント → アカウントでGoogleアカウントにサインインしてから、もう一度お試しください。）と表示されて停止します。

**モデルと思考レベル。** セッションでは、**モデル**にAntigravity CLI独自のモデル（Gemini 4モデル、Gemini 3.8 Flash、プランで使えるその他のモデル）、**思考レベル**にその思考レベル（low、medium、high、xhigh、max）、**権限**にその権限モードが一覧表示されます。これらは、セッションを開くときにアプリが取得するため、最初のセッションのあとに表示されます。アプリ独自のツールと承認カードは、ほかのACPエージェントと同じように使えます。

**Googleの規約がここで意味すること。** 行の下に、アプリは次のように表示します。「Googleのプランの利用規約では、Antigravity CLIは自分で開始して操作するセッションでのみ認められています。そのためサインインは1つのみで、バックグラウンドでは動作しません。」Hydorでは、次のことを意味します。

- **サインインは1つだけ。** Antigravity CLIのアカウントを追加で登録することはできません。**アカウントを追加**には表示されず、**上限時にアカウントを切り替え**も適用されません。
- **自分で始めたセッションだけ。** 開始ページ、ターミナルアプリ、チャットアプリ（Telegramなど）、ハンズフリー音声から始められます。スケジュール、別のエージェントが始めたサブエージェント、[アプリ](/guide/apps)の実行、アリーナなど、アプリが始めるものは拒否され、「Antigravity CLIは、自分で開始して操作するセッションでのみ実行できます。Googleのプランの利用規約では、アプリや他のエージェントが開始する作業（スケジュール、サブエージェント、アプリ）は認められていません。この作業には別のエージェントを選んでください。」（Antigravity CLIは、自分で開始して操作するセッションでのみ実行されます。Googleのプランの規約により、アプリや別のエージェントが開始する作業（スケジュール、サブエージェント、アプリ）は対象外です。この作業には別のエージェントを選んでください。）と表示されます。
- **アプリ側からのメッセージは送らない。** アプリが自分でメッセージを送ることはありません。送られるはずだったもの（サブエージェントの結果、アプリの回答、リマインダー）は、セッションにメモとして表示されます。「Antigravity CLIには送信されませんでした。Googleのプランの利用規約により、自分で送信したメッセージのみ受け付けます。渡したい場合は、自分で送信してください：」（Antigravity CLIには送信されていません。Antigravity CLIは自分で送ったメッセージのみを受け付けます（Googleのプランの規約）。渡すには、自分で送信してください：）のあとに、その内容が続きます。カードへの回答、キーの保存、音声など、自分で行った操作は、これまでどおり届きます。
- **自動での続行はなし。** 上限に達したあと、自動で続行することはありません。**使用量の上限後に再開**はなく、**リセット時に再開**ボタンもありません。[使用量、上限、コスト](/guide/usage#what-happens-when-you-hit-a-limit)を参照してください。

ほかのプログラムからこのサインインを使ったり、アカウントを切り替えながら使ったりすると、GoogleアカウントのAntigravityへのアクセスが停止されることがあります（GoogleがFAQで述べています）。ここで説明した方法でのみ使ってください。スケジュール、サブエージェント、アプリなどの無人での作業には、Gemini CLIとGemini APIキーを使います。

使用量は、[使用量ページ](/usage)にカードとして表示されます。メールアドレスとプランは表示されますが、メーターはありません。[プランの上限を読む](/guide/usage#read-a-plans-limits)を参照してください。

### 自分でエージェントを追加する

ACPに対応したプログラムであれば、ここで実行できます。

1. **自分のエージェント**のタイトルの横にある**自分で追加**をクリックします。
2. 次の項目を入力します。
   - **名前**：一覧に表示される名前です。例：「Gemini CLI」。
   - **コマンド**：起動するプログラムです。例：`gemini`、またはフルパス。
   - **引数**：ACPモードで起動するための引数です。例：`--acp`。
   - **環境変数（任意、1行に NAME=value）**：プログラムが必要とする設定です。APIキーの変数などがあります。
3. **保存**をクリックします。

コマンドは、エージェントを標準入出力でやり取りするACPモードで起動するものである必要があります。

### 専用のプログラムで設定するエージェント

一覧のエージェントの中には、自分で設定するプログラムもあります。アプリがインストールしてくれるものとは、いくつか違いがあります。

- **その他のエージェント**の行に、インストールに使うコマンドまたはアドレスが表示されます。アプリがWebからスクリプトを実行することはありません。[ターミナル](/terminal)で、または行に書かれた方法で、自分でインストールしてください。
- エージェント自身のプログラムで一度サインインします。これもターミナルで行います（たとえば、そのコマンドを実行して表示に従ってサインインしたり、そこでモデルを選んだりします）。以後は、アプリが起動します。セッションとメモリは、そのエージェント自身のフォルダに保存され、承認カードもそのエージェントが用意するものが使われます。
- 一部のエージェントは、独自のゲートウェイに接続します。まずそのエージェント自身のセットアップコマンドで設定し、ゲートウェイを起動したままにしてください。
- エージェント自身がACPに対応していない場合は、ACPアダプターが必要です。アプリは、エージェントと一緒にアダプターもインストールします。どちらも専用のフォルダにnpmで入れ、インストールスクリプトは実行しません。自分でインストールしたエージェントは、PATHにあればそれが使われます。
- MCPサーバーを受け付けないエージェントは、そのエージェント自身のツールだけで動作します。アプリのツール（ページ、検索など）は届かず、セッションの開始時にその旨が表示されます。それでも、アプリのガイドライン、メモリのメモ、スキルは最初のメッセージと一緒に渡されます。

### ここでACPエージェントにできること、できないこと

アプリは、選んだフォルダでセッションを開き、エージェントのメッセージとステップを表示し、エージェントが許可を求めるたびに確認します。Claude CodeやCodexとは動作が異なる点があります。

- メッセージは一度に1つずつ受け付けます。エージェントの作業中に送ったメッセージは、メッセージ欄の上のキューで待機し、ターンが終わると送信されます（Customも同じ動作です）。
- 以前のセッションを開き直せないエージェントでは、古いセッションを続けようとすると、それまでの会話なしで最初から始まります。セッションにその旨が表示されます。以前は開き直せたのにできなくなった場合も同様で、失敗せずに、メモを付けて新しく続行します。
- 添付した画像は、そのエージェントが画像を受け付ける場合にのみ届きます。
- フォークと引き継ぎは使えません（Customにはフォークがあります）。ゴールは使えます。アプリ独自のループが、すべてのエージェントでゴールを進めます。
- Antigravity CLIは、自分で開始して操作するセッションでのみ動作し、サインインは1つだけです（[Antigravity CLI](#antigravity-cli)を参照）。
- アプリのツール（ページ、検索、メモリなど）は、MCPサーバーとしてエージェントに届きます。エージェントが対応していればアドレスで、そうでなければアプリが起動する小さなプログラムを通じて渡されます。どちらも受け付けないエージェントは、自分のツールだけで動作しますが、ガイドライン、メモリのメモ、スキルは受け取ります。

## Customのモデルの入手元

Customは、ClaudeとChatGPTのプランのモデル、このコンピューター上のモデル、クラウド上のモデルを、ほかのエージェントと同じツール、スキル、MCPサーバーで実行します。開始ページでCustomを選び、続けてモデルを選びます。モデルは次の3か所から提供されます。

- **契約中のサブスクリプション**：このコンピューターのClaude CodeとCodexのサインインを通じて使う、ClaudeとChatGPTのプランのモデルです。設定は不要です。Claude Codeにサインインしていれば、Customの**モデル**メニューにClaude Opus、Fable、Sonnet、Haiku（いずれも常に最新版）が表示され、CodexにChatGPTでサインインしていれば、ChatGPTプランのモデル（例：GPT-6 Luna）が表示されます。サインアウトしていると判明したプログラムのモデルは、再びサインインするまでメニューから消えます。ChatGPTではなくAPIキーでサインインしたCodexは、モデルを提供しません。これらはAPIキーやトークンごとの料金ではなくプランの使用量を消費するため、Customのセッションではその分の手順が$0と表示されます。**思考レベル**メニューには、各モデルについてそのプログラムが示すレベルが並びます。**デフォルト**を選んでいる間は、プログラム側のデフォルトが使われます。ほかの単発の作業と同じく、プログラムの各アカウントが順に試されます。使用量の上限に達したアカウントやサインアウトしたアカウントの場合は、次のアカウントに手順が引き継がれます（**上限時にアカウントを切り替え**がオンの場合）。[機密セッション](/guide/sessions#keep-a-session-confidential)では、AnthropicやOpenAIのサーバーで動くため、これらは使われません。回答の仕組みは[Custom](/guide/custom#what-custom-is-and-when-to-use-it)を参照してください。
- **このコンピューター**：ここにインストールされたモデル（Ollama、vLLM）と、ネットワーク上のエンドポイントです。
- **クラウド**：OpenRouter、ほかの場所にあるエンドポイント、Ollamaのクラウドモデルです。

Customのモデルを選べる場所ならどこでも選べます。開始ページ、セッションのモデルメニュー、Customのティア、補助モデル、エージェントやアプリのモデルです。

Customのモデルに必要なものは、すべて[設定 → エージェント → モデル](/settings?s=models)にあります。このページは、上から順に7つの部分に分かれています。

- **補助モデル**：アプリの小さな作業に使うモデルです。
- **ティア**：作業の種類ごとのモデルです（[ティア：作業の種類ごとのモデル](#tiers-a-model-for-each-kind-of-job)を参照）。
- **契約中のサブスクリプション**：Claude CodeとCodexの行が1つずつあり、それぞれがCustomに提供するモデルが表示されます。行には「サインアウト中：これらのモデルを使うには、もう一度サインインしてください」と**アカウント**へのリンクが表示されるか、「このコンピューターにインストールされていません」と表示されます。
- **このマシン上**：このコンピューターの状況と、ここにインストールされたモデルです。
- **Hugging Faceからモデルを追加**：オープンモデルを検索、確認、インストールします。
- **OpenRouter**：1つのキーで数百のモデルを使えます。自分のキー、追加したモデル、追加用の検索の3つのグループがあります。
- **ランタイムとエンドポイント**：Ollama、vLLM、OpenAI互換のその他のサーバー、Hugging Faceのトークンです。

Customの**モデル**メニューでは、モデルが**契約中のサブスクリプション**、**このコンピューター**、**クラウド**に分けて表示され、各行にはそのモデルの経路が「Claude Code」「Codex」「OpenRouter」「Ollama」「vLLM」、またはエンドポイント名として表示されます。モデルにカーソルを合わせると、実行場所と一度に読み取れる量が表示されます。たとえば「OpenRouter · 128Kコンテキスト」や「vLLM（このマシン上） · 32Kコンテキスト · 使用時に起動」です。一覧は1分ごとに自動で更新されます。

## 補助モデルを選ぶ

補助モデルは、会話とは別に、セッションの傍らで小さな作業を行います。

- 依頼内容から新しいセッションに名前を付ける（サイドバーに表示されるタイトル）。
- Customの自動モードでの手順の確認と、レビュアーが成立すると判断しなければならないゴールのチェックの判定（レビュアーとは、作業を一切行っていないモデルのことです。機密セッションでは、このコンピューター上のモデルが担当します）。
- 1日に1回ほどのメモリの整理、それ以降の会話からの学習、エージェントが最初に読むインデックス用のメモへのタイトル付け。
- ブラウザで開いているWebページについての質問への回答。
- Naget Searchが検索する前に、Web検索の言葉が示す絞り込み条件（サイト、日付、ページの種類、言語）を読み取る（[エージェントがWebを検索する仕組み](/guide/web#how-agents-search-the-web)を参照）。
- 画像を認識できないCustomモデルのために、画像を説明する。
- コミットメッセージ、プルリクエストの説明とそのリーディングガイド、言葉で伝えた内容からのターミナルコマンド、描画とプロットのコードを書く。
- Hydorサブエージェントからの長い返信を要約する。
- セッションからアプリやスケジュールタスクの下書きを作る。
- ハンズフリーの音声モード。

[設定 → エージェント → モデル](/settings?s=models&find=Helper%20model)を開き、**補助モデル**グループの**モデル**メニューをクリックします（(i)に小さな作業の一覧があります）。

- **自動**（既定）：Claude Code経由のClaude Haiku。Claude Codeが応答できない場合はCodexを使います。問い合わせるのはサインインしているプログラムだけで、サインインしていないプログラムが起動されることはありません。使用量の上限に達したアカウントの場合は、まず次のサインイン済みアカウントに処理を渡し（**上限時にアカウントを切り替え**がオンのとき）、サインアウトしたアカウントは飛ばされます。どちらのプログラムも応答できない場合や、どちらにもサインインしていない場合は、Customのモデルのいずれかが作業を行います（Customの**高速**ティアに指定されているモデル、次に**標準**、なければ追加したモデルのうち最も安いもの。プランのモデルは同じ2つのプログラムを経由するため、ここでは対象外です）。長い質問は、まず全体を読めるモデルに送られます。どれも実行できないときにだけ、ここで使用したプログラムにもう一度サインインするよう求めるカードが表示されます（[アカウントがサインアウトしているとき](#when-an-account-is-signed-out)を参照）。どちらも設定したことがなく、モデルも追加していない場合は、[設定 → モデル](/settings?s=models)でモデルを追加するか、Claude CodeまたはCodexを設定するようエラーに表示されます。どれも応答しない場合は、それぞれの理由がエラーに表示されます。「週間の上限に達しました」や、Codexのプランで提供されていないモデルなどです。
- Customの各モデル。Customの**モデル**メニューと同じく（**契約中のサブスクリプション**、**このコンピューター**、**クラウド**）にグループ分けされ、接続経路（Claude Code、Codex、OpenRouter、Ollama、vLLM、またはエンドポイント名）と、画像を認識できるモデルには「画像対応」が表示されます。ClaudeやChatGPTのプランのモデルも補助モデルにできます。その場合、Claude CodeまたはCodex経由で、プランの使用量を使って応答します。

Claude CodeやCodex経由では、自動で画像を見ることができません。どちらにもサインインしていない場合は、画像を認識できるCustomモデルのいずれかに問い合わせます。画像を認識できないモデルでCustomを使う場合は、画像を認識できる補助モデルを選んでください。そうしないと、Customで画像を説明してもらえません。

## このコンピューターで実行できるものを確認する

[設定 → エージェント → モデル](/settings?s=models&find=On%20this%20machine)の**このマシン上**セクションは、このコンピューターの概要から始まります。

- **グラフィックス**：グラフィックスカード（GPU）とそのメモリ。Apple siliconのMacではチップ名（「Apple M3 Max」。グラフィックスはコンピューターのメモリを共有します）。GPUがない場合は「No GPU」と表示されます（その場合、モデルはプロセッサで実行されます）。
- **メモリとディスク**：コンピューターのメモリの合計と空き、ディスクの空き容量、およびインストール済みモデルが使っている容量。
- **実行方法：**　**Ollama**と**vLLM**がインストールされているかどうかとそのバージョン、またはインストール用のリンク。
- グラフィックスカードがある場合は、収まるモデルの大きさ。「GPU 1枚で4ビットなら約30Bパラメータまで収まります」（Macの場合は「4ビットなら約40Bパラメータまで収まります」）。パラメータはモデルの大きさの目安で、4ビットは一般的な圧縮形式であり、必要なメモリは約4分の1になります。

その下には次の項目があります。

- **進行中のダウンロード**：それぞれに進行状況バー、完了した量、OllamaとvLLMのどちら向けかが表示されます。**キャンセル**で1件を中止できます。失敗またはキャンセルされたものには理由が表示され、**閉じる**があります。
- **インストール済みのモデル**（最初のいくつかと**すべて表示**）：それぞれに、実行環境（OllamaまたはvLLM）、サイズ、詳細（Ollamaモデルではサイズや圧縮方式など）、画像を認識できる場合は「画像対応」、実行中かどうかが表示されます。
  - vLLMモデルには**開始**と**停止**があります。セッションが初めて使うときに自動で開始され（初回の開始には1〜2分かかります）、空きメモリが最も多いグラフィックスカード上で動きます（そのままでは収まらない場合は8ビットで）。1枚に収まらない場合は2、4、8枚に分割されます（「GPU 1、2で実行中」）。Macの場合はApple silicon上で動きます。アプリを再起動しても、**停止**をクリックするまで動き続けます。開始できない場合は、その下に理由が表示されます。
  - モデルの**⋯**メニューにある**外す**は、確認後にモデルのファイルをこのコンピューターから削除します。あとで再インストールできます。

まだモデルがない場合は、「ここにはまだモデルがありません。下のHugging Faceから追加してください。」と表示されます。

## Hugging Faceからモデルを追加する

Hugging Faceは、オープンモデルの主要なサイトです。[Hugging Faceからモデルを追加](/settings?s=models&find=Add%20a%20model%20from%20Hugging%20Face)グループ（このコンピューター向けのおすすめ、またはサイト全体から検索）では、いくつかのモデルを提案し、検索でき、ダウンロードする前に、各モデルがこのコンピューターでどのように動くかを示します。

### このコンピューター向けのおすすめ

検索する前に、このグループにはこのコンピューターの構成に合わせて、アプリが推奨するモデルが表示されます。

- **LFM3-VL 2B**（Liquid AI）：小さくて高速で、画像も読めます。ほとんどのコンピューターで動作します。
- **Gemma 4 12B**（Google）：画像を読める万能タイプで、高性能なグラフィックスカードを持つコンピューター向けです。
- **Flint**（Recursive）：コーディングエージェント向けに作られており、32GB以上のApple siliconのMac向けです。
- **GLM-5.3 Flash**（Z.ai）：オープンモデルの中でも最高クラスで、大型のグラフィックスカードを複数備えたサーバー向けです。

それぞれに、ここで快適に動くか低速かどうか、動作方法（「vLLM、8ビット、GPU 0」「vLLM、GPU 2枚に分割」「vLLM、Apple silicon上」）、ダウンロードサイズ、**インストール**が表示されます。快適に動くものの中で最も強力なものには**ここで最適**と表示されます。既定ではvLLMで動作します。NVIDIAのグラフィックスカードもApple siliconもないコンピューターでは、代わりに小さいモデルのOllama版が表示されます。実行環境がまだ設定されていない場合は警告が表示されます（「vLLMが設定されていません」「Ollamaが起動していません」）。[Ollama、vLLM、その他のエンドポイントを接続する](#connect-ollama-vllm-or-another-endpoint)を参照してください。**さらに2件（大型コンピューター向け）**（件数は変わります）の行を開くと、残りのモデルと、それぞれに必要な環境が表示されます。ウェルカムツアーでも同じモデルが提案されます。

### 検索と絞り込み

1. **Hugging Faceを検索、またはorg/nameを貼り付け**に入力します。`qwen3`のような名前、モデルの正式名（`org/name`）、またはhuggingface.coのアドレスを入力できます。入力前には、いくつかの名前の候補と、**ダウンロード数の多いものを見る**が表示されます。
2. フィルタで一覧を絞り込みます（組み合わせて使えます）。
   - **ここで快適に動作**：このコンピューターで快適に動くモデルだけを表示します。
   - **GGUF・Ollama**：Ollamaで動作するGGUF形式のモデル。
   - **vLLM**：vLLMがグラフィックスカードで動かすsafetensors形式のモデル。
   - **画像対応**：画像も読めるモデル。
3. 右側のメニューで並び順を変更します。**ダウンロード数順**、**トレンド**、**いいね数順**、**新しい順**があります。

最大40件のモデルが表示され、最初は8件で、残りは**すべて表示**で見られます。正式名で指定したモデルは、検索結果にない場合でも先頭に表示され、Enterキーを押すとすぐに確認されます。

各行には、作成元と名前、形式（**GGUF**または**vLLM**）、画像を読める場合は**画像**、利用規約への同意が必要な場合は**制限付き**、パラメータ数によるサイズ、過去30日間のダウンロード数、いいね数、最終更新日が表示されます。

### 最初の判定

各モデルの下には、サイズだけから出した最初の見立てが、色付きのラベルで表示されます。

- **vLLMで快適に動作**または**Ollamaで快適に動作**と、おおよその速度（「約40トークン/秒」。トークンとは単語の断片のことです）：グラフィックスカードのメモリに収まります。
- **プロセッサで低速に実行**または**プロセッサで非常に低速に実行**：コンピューターのメモリにしか収まらないため、プロセッサで動作します。これができるのはOllamaだけです。
- **このコンピューターには大きすぎます**：収まらない、またはダウンロード分がディスクに収まりません。
- **4ビット、Ollama：快適に動作…**：そのままのモデルは大きすぎますが、圧縮した4ビット版ならOllamaで快適に動作します。

ラベルにカーソルを合わせると、判定の根拠となる数値が表示されます。

### ダウンロード前に確認する

モデルの**確認**をクリックすると、ここでどのように動くかを詳しく確認できます。パネルには、サイズ、一度に読み込める量（コンテキスト）、画像を認識できるかどうかが表示され、続いて次の内容が表示されます。

- GGUFモデルの場合：「Ollamaで実行」と、利用可能な各サイズ（ファイルが小さいほど、品質を少し犠牲にして速度とメモリを節約できます）が小さい順に表示されます。各行には、判定、必要なメモリ、おおよその速度、ダウンロードサイズと、**インストール**ボタンが表示されます。Ollamaがここで動いていない場合や、大きすぎるサイズの場合は、インストールがグレーアウトされます。
- vLLMモデルの場合：「vLLMで実行。セッションが使うときにGPU上で起動します」、同じ数値、使用するグラフィックスカードについての注記、そして**ダウンロード**ボタンが表示されます。vLLMがインストールされていない場合や、お使いのvLLMがこの種類のモデルをまだ実行できない場合はその旨が表示され、GGUF版があればその**確認**が代わりに提案されます。
- それ以外の場合：「このアプリが実行できる重みがありません（vLLM用はsafetensors、Ollama用はGGUF）。」

数値は、最大で約32,000トークンの会話（このコンピューター上のモデルに与えられる長さ）を前提としています。**閉じる**でパネルを折りたためます。

### インストールとその後

**インストール**（Ollama）または**ダウンロード**（vLLM）をクリックします。ダウンロードの進行状況は**このマシン上**に表示されます。完了すると、モデルがCustomの**モデル**メニューに表示されます。途中で中断されたvLLMのダウンロードは、再試行すると続きから再開されます。どのグラフィックスカード1枚にも収まらないvLLMモデルは、起動時に8ビット（FP8）で保存されます。これにより重みのメモリ使用量が半分になり、品質の低下はわずかです（NVIDIAのRTX 30シリーズおよびA100以降のカード）。それでも収まらない場合は、複数のカードの合計に余裕があれば分割されます。

### 制限付きモデルと非公開モデル

作成元が先に利用規約への同意を求めるモデルには、**制限付き**と表示されます。huggingface.coのモデルのページで規約に同意し、Hugging Faceトークンを追加してください（[Hugging Faceトークン](#hugging-face-token)を参照）。非公開モデルにもトークンが必要です。

## OpenRouterでモデルを使う

OpenRouter（openrouter.ai）では、1つのキーで多くの作成元の数百のモデルを従量課金で利用できます。

### キーを追加する

1. openrouter.aiでキーを取得します（セクション内にリンクがあります）。
2. [設定 → エージェント → モデル](/settings?s=models&find=OpenRouter)の**OpenRouterのキー**の行で**キーを追加**をクリックし、ダイアログの**OpenRouterのキー：sk-or-…**に貼り付けて**保存**をクリックします。

すると、その行にキーの先頭と末尾とともに**OpenRouterに接続済み**と表示されます。**⋯**メニューの**キーを削除**でキーが破棄されます。キーはサーバーに保管され、二度と表示されません。

最初に必要になったときに追加することもできます。キーなしで画像、図、動画、音声を作ろうとしたエージェントは、会話中のカードでキーを求めます（[エージェントにOpenRouterのキーが必要なとき](/guide/documents-voice#when-an-agent-needs-the-openrouter-key)）。エディタのAIツールも、ダイアログで求めます。どちらの場合も、キーはここに保存されます。

### おすすめのモデル

検索する前に、**OpenRouterのモデルを追加**グループの**おすすめ**に、Custom向けの4つのモデルが理由とともに表示されます。**GPT-6 Luna**（高速で低価格）、**Grok 4.7**（高品質で拒否が少ない）、**GPT-6.1 Sol**（より高品質）、**Claude Opus 5.5**（総合で最高）です。**追加**を押すと、そのモデルが選択メニューに入ります。画像、音楽、音声、動画については、アプリはSeedream 5.0 Pro（および、より高速で安価なFlash）、Lyria 3 Pro、Seed Audio 1.0、Seedance 2.5を選んでいます。[設定 → 機能 → 画像、動画、音声](/settings?s=images)を参照してください。

### カタログを検索する

同じグループで、**OpenRouterを検索：deepseek、qwen、claude…**に入力するか、候補の名前のいずれか、または**新着を見る**をクリックします。フィルタは次のとおりです。

- **ツール呼び出し**：ツールをネイティブに呼び出せるモデル。Customが最も使いやすい形です（**最も一致**ではこれらが先頭に表示されます）。
- **画像対応**
- **推論**：回答する前に考えるモデル。
- **自由**

右側のメニューで結果を並べ替えます。**最も一致**（名前で検索している間）、**新しい順**、**最安**、**最長コンテキスト**があります。最大50件のモデルが表示され、最初は8件で、残りは**すべて表示**で見られます。

各モデルには、作成元、名前、ラベルが表示されます。**最新**（常に作成元の最新バージョン）、**新規**（過去3週間以内に掲載）、**自由**、**推論**、**画像**、**ネイティブツールなし**（その場合、Customはツールを指示文の中で説明し、呼び出しをテキストから読み取ります）です。その下には、一度に読み込める量（「128Kコンテキスト」）、最長の返信（「16K出力」）、入力と出力それぞれの100万トークンあたりの価格、掲載された月、短い説明、OpenRouter上の名前が表示されます。

### 選択メニューにモデルを追加する

モデルの**追加**をクリックします。すると、その行に**追加**と表示され、モデルは検索の上にある**OpenRouterのモデル**グループ（「モデル選択メニュー内」）とCustomの**モデル**メニューに表示されます。そのうちの1つの×をクリックすると、メニューから外せます。少なくとも1つ追加するまでは、OpenRouterでモデルは提供されません（「OpenRouterを使うには、モデルを少なくとも1つ追加してください。」）。

### OpenRouterのモデルの思考レベル

推論するモデルでは、**思考レベル**メニューで、OpenRouterがそのモデルに挙げているレベルを、**なし**（推論なし）、**ミニマル**、**低**、**普通**、**高**、**Xhigh**、**Max**の中から選べます。Customは、**デフォルト**を選んでいる間は普通を指定し、それ以外は選んだレベルを指定します。普通が含まれないモデルは独自のデフォルトのままになります。レベルがひとつも挙げられていないモデルには**思考レベル**の設定がなく、普通が指定されます。

## Ollama、vLLM、その他のエンドポイントを接続する

**ランタイムとエンドポイント**グループでは、モデルを実行するプログラムを接続します。[設定 → エージェント → モデル](/settings?s=models&find=Runtimes%20and%20endpoints)から開きます。

### Ollama

Ollamaは、グラフィックカードまたはプロセッサを使ってコンピューター上でモデルを実行する無料のプログラムです。行には、バージョンとともに「実行中」と表示されるか、「このアドレスでは実行されていません」と表示され、**Ollamaをインストール**のリンクが付きます。アドレスは、変更しない限り `http://127.0.0.1:11434` です。別のアドレスを使うには、フィールドに入力します。すると、横に**保存**が表示されます。そのOllamaにあるすべてのモデルが、Customのモデル一覧に表示されます。アプリの外で取得したモデルも含まれます。

### vLLM

vLLMは、NVIDIAのグラフィックカード上でモデルを実行する高速なサーバーで、Hugging Faceのモデルをここで実行する際の標準的な方法です。1枚のカードに収まらない大きなモデルは、8ビットで実行するか、2枚、4枚、8枚のカードに分割して実行できます。Macでは、vLLMはMetalプラグイン（vllm-metal）を使ってApple siliconで動作します。アプリは、PATH上、またはcondaやvenvの環境内から自動的に見つけ、バージョンと場所を表示します。「見つかりません（pip install vllm）、またはコマンドを指定してください」と表示される場合は、vLLMをインストールするか、`vllm` コマンドのフルパスをフィールドに入力して**保存**をクリックします（入力すると表示されます）。フィールドを空にすると、アプリが自動的に探します。

### その他のOpenAI互換エンドポイント

OpenAIのAPIと同じ形式で応答するプログラムやサービスは数多くあります。LM Studio、llama.cppのサーバー、そのほかのプロバイダーなどです。追加する手順は次のとおりです。

1. グループのタイトルの横にある**エンドポイントを追加**をクリックします。
2. ダイアログで、**名前**、アドレス（`http://localhost:1234/v1` など）、**キー（任意）**を入力します。
3. **追加**をクリックします。

エンドポイントは、アドレスと提供するモデルの数が付いた行として表示されます。そのモデルは、Customの一覧に「モデル（名前）」の形で表示されます。×を押すと取り除かれます。同じ名前で別のエンドポイントを追加すると、最初のものが置き換えられます。

行の下にある**各モデルでできることを設定**をクリックするとモデルが表示され、それぞれに**画像対応**と**推論の思考レベル**の2つの項目があります。どちらも**自動**、**はい**、**いいえ**から選びます。推論するモデルには、3つ目の項目として**思考レベル**があります。画像に対応したモデルには、スクリーンショットや画像がそのまま画像として渡されます。対応していないモデルには、代わりに画像の説明が渡されます（[画像を見られないモデルへの画像の渡し方](/guide/custom#images-for-models-that-dont-see)を参照）。推論するモデルでは、**思考レベル**メニューでレベルを選べます（別に設定しないかぎり、Low、Medium、High）。Customは選んだレベルを、OpenAI互換サーバーが受け付ける設定である`reasoning_effort`として送ります（**デフォルト**を選んでいる間は何も送りません）。**自動**はエンドポイントがそのモデルについて伝える情報に従い、その内容はメニューに表示されます。モデルの情報を提供するサーバー（OpenRouter形式、Mistral形式など）は、モデル一覧と一緒にこの情報を伝えます。LiteLLMゲートウェイの場合、Hydorは同じキーを使ってモデル情報も問い合わせます。エンドポイントから何も情報がない場合は「いいえ」とみなします。画像に対応している、または推論するとわかっているモデルは、**はい**に設定してください。設定した内容は、エンドポイントを追加し直しても保持されます。

モデルのレベルを変更するには、その横にある**思考レベル**をクリックします。`none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`のうち、モデルが受け付けるものにチェックを入れます。または、エンドポイントが受け付ける別のレベルを**別のレベル**に入力して**追加**をクリックします（1語で指定します。少なくとも1つのレベルにはチェックが残ります）。**low、medium、highを使う**をクリックすると、通常の3つに戻ります。モデルがどのレベルを受け付けるかは、サーバー側で決まります。サーバーがあるレベルを拒否した場合、Customはそのレベルを外してリクエストを送り直し、モデルはサーバー側の既定の設定で動きます。

[機密セッション](/guide/sessions#keep-a-session-confidential)では、アドレスがこのコンピューターまたはプライベートネットワーク内にあるエンドポイントを使えます。具体的には、`localhost`、`127.0.0.1`、`::1`、`10.…`、`192.168.…`、`172.16.…`から`172.31.…`まで、または`.local`で終わる名前です。それ以外のアドレスはオンラインとみなされます。自分のサーバーに通じるアドレスであっても同じです。その場合は、プライベートアドレスを使ってください。Ollamaのアドレスについても同様で、Ollamaのクラウドモデル（名前が「cloud」で終わるもの）は常にオンラインとみなされます。

### Hugging Faceトークン

[Hugging Faceトークン](/settings?s=models&find=Hugging%20Face%20token)を使うと、アプリでアクセス制限付きまたは非公開のモデルをダウンロードできます（行には「アクセス制限付きまたは非公開のモデル専用」と表示されます）。Hugging Faceのアカウント設定でトークンを作成し、**トークンを追加**をクリックして、ダイアログに貼り付け（`hf_` で始まります）、**保存**をクリックします。すると行にはトークンの先頭と末尾が表示され、**⋯**メニューに**トークンを削除**が表示されます。

## エージェントに頼んでみる

- 「ここにインストールされているエージェントプログラムはどれ？ Gemini CLIをインストールして。」
- 「Claude CodeとCodexは最新？ 今すぐ更新して。」
- 「OpenCodeをエージェントに追加して。」
- 「Grok Buildをエージェントに追加して、Grokのサブスクリプションでサインインして。」
- 「Googleの AI Proプランで Antigravity CLIをセットアップして。」
- 「Antigravity CLIはここにインストールされている？ サインインもできている？」
- 「スケジュールタスクでAntigravity CLIを使えないのはなぜ？」
- 「仕事用にGrokの2つ目のアカウントを追加して、次のセッションをそれで始めて。」
- 「次のGrokセッションを思考レベルxhighで始めて。」
- 「ゲートウェイのエンドポイントにあるgptモデルで、思考レベルとしてlow、high、xhighを選べるようにして。」
- 「今週、Grokのプランはあとどれくらい残っている？」
- 「Grokのアカウントをすべて使って。上限に達したら別のアカウントで続けて。」
- 「Gemini CLIとGooseをエージェントに追加して、まだインストールが必要なものを教えて。」
- 「Hugging Faceで、このコンピューターで快適に動いて画像にも対応しているモデルを探して、確認して、最適なサイズをインストールして。」
- 「OpenRouterの最新のDeepSeekモデルをモデルに追加して。」（OpenRouterのキーを設定済みの場合）
- 「補助モデルを画像に対応したモデルにして。」
- 「Customのセッションで、Claudeプランの Sonnetを使って、費用も見せて。」
- 「グラフィックカードを空けるために、実行中のvLLMモデルを停止して。」
- 「Claudeのアカウントをすべて使って。上限に達したら別のアカウントで続けて。」
- 「Claudeのアカウントがすべて上限に達したら、APIクレジットで続けて。」
- 「Claude CodeとCodexのティアごとに、どのモデルを使っている？ Claude Codeの「最大」をOpusにして。」
- 「Customのティアはどのモデルを使っている？ 「最高」が空なのはなぜ？」
- 「HydorがClaude Codeへのサインインをもう一度求めてくるのはなぜ？」
- 「Claude Codeのアカウントがサインアウトされている。そのアカウントを待っているセッションはどれ？ 別のアカウントで続けられる？」
