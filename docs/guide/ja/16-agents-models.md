# エージェント、アカウント、モデル

Hydorでは、複数のAIエージェントを使えます。Claude Code、Codex、Custom（アプリ独自のエージェントで、どんなモデルにも対応）のほか、Gemini CLI、OpenCode、Qwen Code、Goose、Grok BuildなどのACPに対応したエージェントです。このトピックでは、それぞれの違い、プログラムのインストールと最新の状態の保ち方、サインインの方法（複数アカウントも含む）、そしてCustomのモデルの入手元（OpenRouter、Ollama、このコンピューターで動かすHugging Faceのモデル、OpenAI互換のエンドポイント）を説明します。

![スタートページでのエージェントの選択：Claude Code、Codex、Custom](images/agents-models.webp)

## どのエージェントを使えばよいですか？

エージェントは、セッションで作業を行うプログラムです。メッセージを読み、ツール（ファイル、コマンド、Web）を使って答えます。モデルは、その裏にあるAIです。ここにあるエージェントはどれも、アプリから同じサポート（Web検索、ブラウザ、メモリ、スキル、接続）を受けられますが、モデルの入手元が異なります。

- **Claude Code**（Anthropic）。Claudeのプランで動くか、AnthropicのAPIアカウントに課金されます。モデルはAnthropicのもの（Opus、Sonnet、Haiku）です。独自の使用上限があり、[使用量ページ](/usage)で確認できます。
- **Codex**（OpenAI）。ChatGPTのプランで動きます。モデルはOpenAIのものです。こちらにも使用上限があり、使用量ページに表示されます。Codexはアプリに付属しています。
- **Custom**は、アプリ独自のエージェントです。ClaudeとChatGPTのプランのモデル（Claude CodeとCodexのサインイン経由）のほか、[設定 → エージェント → モデル](/settings?s=models)で追加した任意のモデルを動かせます。追加できるのは、OpenRouter経由のモデル、このコンピューター上のモデル（OllamaまたはvLLM使用）、OpenAI互換のエンドポイントです。オープンモデル、より安価なモデル、コンピューターの外に出ないモデルを使いたいときに便利です。詳しくは[Custom、アプリ独自のエージェント](/guide/custom)をご覧ください。
- **ACPに対応したエージェント**：Gemini CLI、OpenCode、Qwen Code、Goose、Kimi CLI、Auggie、Grok Build（xAIのコーディングエージェントで、Grokモデルを使用）など。自作のコマンドも使えます。ACP（Agent Client Protocol）は、アプリがエージェントプログラムと通信するための共通の方式です。それぞれ専用のプログラムで一度サインインすれば、そのエージェント自身のモデルを使います。

アプリ内でできること：

- ゴール（合意したチェックが満たされるまで、アプリがラウンドを重ねてエージェントに作業を続けさせる機能。[ゴール](/guide/goals)を参照）：すべてのエージェント（Claude Code、Codex、Custom、その他のACPエージェント）で使えます。Claude CodeやCodexのチャットで入力した `/goal` は、そのプログラム独自のより簡易なゴールです。フォーク（セッションの以前の返信から作る複製）：Claude Code、Codex、Customで使えます。その他のACPエージェントでは使えません。
- **続きを開く…**（会話を別のエージェントに引き継ぐ機能）：Claude CodeまたはCodexから、もう一方のエージェントまたはCustomへ。
- 思考レベル（モデルがどれだけ深く考えるか）：Claude Code、Codex、Grok Build、そしてモデルが対応しているその他のACPエージェント。
- 複数アカウント、プランの使用上限、上限に達したときのアカウント切り替え：Claude Code、Codex、Grok Build。
- 上限のリセットと、上限到達時のAPIクレジット：Claude CodeとCodexのみ。

## 新しいセッションのエージェントとモデルを選ぶ

スタートページ（`/`）では、メッセージ欄の下の行で、作業を行うエージェントを指定します。

1. **実行環境**をクリックします。一覧には、**Claude Code**（「Anthropic · Claudeプランまたはapiキー」）、**Codex**（「OpenAI · ChatGPTプランまたはAPIキー」）、**Custom**（「任意のモデル：OpenRouter、Ollama、vLLM」）、そして設定 → その他のエージェントで追加したすべてのエージェント（「ACPエージェント · 」とそのコマンド）が表示されます。一番下の**Custom用モデル**は設定 → モデルを開き、**エージェントを追加・管理**は設定 → その他のエージェントを開きます。
2. **モデル**をクリックして選びます。一番上にあり、最初に選ばれている**自動**では、ティアがモデルを選びます。最高が基本で、問題が難しすぎるとわかれば最大になります（[ティア：仕事の種類ごとのモデル](#tiers-a-model-for-each-kind-of-job)を参照）。その下には、そのエージェント自身のモデルだけが表示されます。エージェントの既定のモデルには「default」と表示されます。古いバージョンのモデルは「古いモデル2件」のような行の奥にあり、クリックすると表示されます。モデルが8つを超えると、一番上に**モデルを検索**欄が表示されます。数文字入力してEnterを押すと、最初に一致したものが選ばれます。エージェントがアプリの求めどおりにモデルを返さなかったときは、メニューにその旨とエージェント自身の説明が表示され、**もう一度試す**でもう一度問い合わせます。
3. **オプション**には、**思考レベル**（対応するエージェントとモデルのみ：デフォルト、低、ミディアム、高など。Grok Buildについては[Grok Buildの思考レベル](#effort-for-grok-build)を参照）と、**権限**（確認なしにエージェントが行えること）があります。メッセージ欄でShift+Tabを押しても、権限を切り替えられます。

スタートページは、作業する場所ごと（プロジェクト、フォルダ、**新しいタスクフォルダ**）に選んだ内容を、すべてのデバイスで記憶します。各プログラムのモデル、思考レベル、権限は、最後に設定したとおりに戻ります（[スタートページが記憶する内容](/guide/sessions#what-the-start-page-remembers)を参照）。

Custom以外のACPエージェントでは、**モデル**と**権限**の選択肢は最初のセッションの後に初めて表示されます。エージェントが前回の実行時に提示した内容が一覧になります。例外はGrok Buildです。アプリがGrokにモデルを問い合わせるため、追加した直後から、モデルと各モデルが対応する思考レベルが表示されます。

**オプション** → **機密**をオンにすると、**実行環境**は**Custom**になり、**モデル**にはこのコンピューターまたはプライベートネットワーク上のモデルだけが表示され、その中で最も優れたものが最初に選ばれます。詳しくは[セッションを機密にする](/guide/sessions#keep-a-session-confidential)をご覧ください。

スマートフォンでは、これらのメニューは画面の下からシートとして開きます。

## セッションの途中でモデルを切り替える

セッションでは、モデル、思考レベル、権限がメッセージ欄の下にあります。「Opus 5.5 · 高 · プラン」のように表示される1つのチップで、クリックすると**モデル**、**思考レベル**、**権限**を選べます。

別のモデルを選ぶと、セッションはそのモデルで続きます。

- Claude Codeはすぐに切り替わります。
- Codexは次のターンから新しいモデルを使います。
- Customは、ターンの途中でも次のステップから使います。
- ほかのACPエージェントは、モデルの選択肢があれば切り替わります。

セッションの**思考レベル**も同様です。選ぶと、実行中のエージェントは次のターンから使います。切り替え先のモデルがそれまでの思考レベルに対応していない場合は、そのモデルのデフォルトが選択欄に表示され、モデルはそれで動きます。

モデルメニューには、そのセッション自身のエージェントのモデルだけが表示されます。機密セッションでは、このコンピューターまたはプライベートネットワーク上のモデルだけです。会話を別のエージェントに移すには、セッションのメニュー（⋯）→ **Claude Codeで続きを開く**などではなく、**続きを開く…** から、Codex、Claude Code、Custom Agentを選びます（Claude CodeとCodexのセッションから。Customはモデルを追加すると表示されます）。次のメッセージを送ると、同じフォルダでそのエージェントの新しいセッションが、ここまでの会話を引き継いで始まります。停止したセッションは、別のモデルを選んでから送信しない限り、最後に使ったモデルで再開します。

## Grok Buildの思考レベル

Grokのモデルは、Claude CodeやCodexと同じく、推論の思考レベルを選べます。

- Grok 4.6（および同じ選択肢を持つ新しいモデル）：**xhigh**、**high**、**medium**、**low**。デフォルトは**高**です。
- Grok 4.5：**high**、**medium**、**low**。

スタートページで**実行環境**の**Grok Build**を選び、**オプション** → **思考レベル**を開くと、選んだモデルの思考レベルが**デフォルト**とともに一覧表示されます。Grok Buildを追加した直後、最初のセッションの前から表示されます。実行中のGrok Buildセッションでは、自身の**思考レベル**の選択欄（メッセージ欄の下のチップ）で変更できます。[アプリ](/guide/apps)の実行でも指定できます。それまでの思考レベル（Grok 4.5でのxhigh）に対応しないモデルへ切り替えると、選択欄にはそのモデルのデフォルトが表示され、モデルはそれで動きます。

これはGrokだけのものではありません。モデルが思考レベルに対応している、ACPに対応したほかのエージェントでも、同じ**思考レベル**の選択肢が使えます。

## ティア：仕事の種類ごとのモデル

エージェントは、名前ではなくティアでモデルを選びます。**高速**は、結果を確認できる、小さくてごく明確な仕事向け。**標準**は、中規模の明確なタスク向け。**最高**は、計画を立て、サブエージェントを率い、その作業を確認するセッションのメインエージェント向け。**最大**は、最も難しい問題向けです。仕事の大半は、安価なモデルでもこなせる明確な部分です。そのため、結果を悪くすることなくセッションのコストを抑えられます。計画と確認は、依然として最も強力なモデルが担います。

スタートページでは、**モデル**は**自動**で開きます。セッションは最高で始まります（同じ**自動**が[スケジュールタスク](/guide/tasks#model-effort-permissions-and-other-options)のセッションも開始し、[アプリ](/guide/apps)も、モデル名ではなくティアで考えることができます）。メインエージェントは、明確な部分を標準と高速のサブエージェントに任せ、問題が最高では手に負えないとわかったとき（2回失敗した修正、見つからない原因、証明など）には、自分で最大に移ることがあります。その場合は、会話に理由つきで一行表示されます。言葉づかいだけで最大に送られることはありません。難しそうに読める問題の大半は、最高のほうがより安く解けます。代わりにモデルを名前で選ぶと、セッションはそのモデルで考えます。そのサブエージェントには、引き続きティアが使われます。自分のエージェントも、1つのティアで考えさせることができます（[エージェントが考えるときに使うもの：ティア](/guide/agents#what-an-agent-thinks-with-tiers)を参照）。

[設定 → エージェント → モデル → ティア](/settings?s=models&find=Tiers)では、各プログラムでの各ティアの意味を設定できます。ティアごとに1行あり、グループの見出しの横にあるスイッチでプログラム（**Claude Code**、**Codex**、**Custom**）を選び、各行にモデルと、Claude CodeとCodexでは思考レベルを指定します。ティアの(i)で詳しい説明が見られます。初期状態では、Claude Codeは、高速がHaiku、標準がSonnet、最高がOpus、最大が最新のFableです。Codexは、高速がLuna、標準がTerra、最高がSol、最大がAstraです（どれかがないプランでは、提供されている最も近いもの。2つが同じモデルを共有する場合は、上位のティアの思考レベルを高くします）。Customのティアは自動で埋まります。手を付けないティアには、Customが持つモデルの中から、その種類の最新のモデルが入ります。Claudeのプランからは、高速にHaiku、標準にSonnet、最高にOpus、最大に最新のFableです。なければChatGPTのプランから、Luna、Terra、Sol、Astra。それもなければ、追加したモデルのうちこのコンピューター上にないもの（OpenRouter、エンドポイント）で、名前がそれらのファミリーのいずれかを示すものです。このコンピューター上のモデルは、名前から強さがわからないため、自動では選ばれません。小さいモデル（Haiku、Luna）が最高になることもありません。小さいモデルやローカルのモデルしかない場合、選ぶまでティアは空のままで、Customのセッションは自分で選んだモデルを使い続けます。最高にモデルが指定されると、スタートページのCustomに**自動**が表示され、そのセッションはサブエージェントを主導します（CustomにはAgentツールがないため、Hydorサブエージェントです）。**Custom**タブでは、ティアごとにそのモデルのどれでも指定できます（[Customのモデルの入手元](#where-customs-models-come-from)を参照）。手を付けないティアは、そのプログラムの、その種類の最新モデルに追従します。タイトル横の**⋯**メニューにある**初期設定に戻す**で、Customの選択も含めてすべて元に戻ります。

ティアの下の**セッションのティア**グループにある2つのスイッチで、セッションがティアをどう使うかを設定します。

- **サブエージェントを主導**（初期状態でオン）：セッションのメインエージェントは、計画を立て、明確な部分をより安価なティアのサブエージェントに任せ、その作業を確認するよう指示されます。ティアなしで依頼されたサブエージェントには標準が使われます。オフにすると、エージェントは別の選択をしない限り単独で作業し、スタートページとタスクのフォームには自動がありません。
- **難問には最大**（初期状態でオン）：**自動**のメインエージェントは、問題が最高では難しすぎるとわかったとき、自分で最大に移ることがあります。オフにすると、**自動**のセッションは最高のままです。

## エージェントプログラムは自分でインストールし、更新する

Claude Code、Codex、Gemini CLI、Grok Buildなどは、このコンピューター上のプログラムです。手動でインストールする必要はありません。

[設定 → エージェント → アカウント](/settings?s=accounts&find=Agent%20programs)を開き、**エージェントプログラム**グループを見てください。Claude Code、Codex、Gemini CLI、OpenCode、Qwen Code、Auggie、Grok Build（追加した場合）、そしてACPアダプターが必要なエージェントが一覧になり、それぞれセッションが実行するバージョンと入手元が表示されます。

- **自分でインストール**：自分でインストールしたものです（Grok Buildの場合は、xAI独自のインストーラーでも可。`~/.grok/bin`に入ります）。
- **アプリがインストール**：アプリが専用のフォルダにインストールしたものです。
- **アプリに付属**：Codexはアプリに付属しています。
- **未インストール：初めて使うときに自動でインストールされます**：入っていない状態です。今すぐ入れるには**インストール**をクリックします。

新しいバージョンが出ている場合は、行に「… is out」とも表示されます。自分のCodexもある場合、Codexの行には「yours in the terminal: …」が加わります。セッションはアプリのものを実行し、ターミナルはご自身のものを実行します。

入っていないプログラムは、必要になった最初のときにも自動でインストールされます。Claude Codeはサインインするとき、またはClaude Codeのセッションを始めるとき、ACPエージェントは設定 → エージェント → その他のエージェントで追加するとき、またはそのエージェントでセッションを始めるときです。アプリはnpmを使って専用のフォルダにインストールするため、管理者権限は必要ありません。

Goose、Kimi CLIなど一部のエージェントはこの一覧にありません。自分でインストールしてください（入手先は設定 → エージェント → その他のエージェントに表示されます）。ACPアダプターが必要なエージェントは、アダプターとエージェント本体の2つに分けてインストールされますが、一覧では両方で1行です。

## エージェントプログラムを最新の状態に保つ

[**自動で更新**](/settings?s=accounts&find=Update%20automatically)をオンにすると（**エージェントプログラム**の最後の行にあります。オフにしない限りオンです）、アプリは1日に1回、各エージェントプログラムを最新バージョンに更新します。最初の実行は、アプリの起動から約10分後です。

- アプリがインストールしたコピーは、専用のフォルダでnpmにより更新されます。Codexは、アプリに同梱されていたものより新しいコピーに切り替わります。
- ユーザー自身がインストールしたものは、それぞれの更新コマンドで更新されます。Claude Codeは`claude update`、Codexは`codex update`（ターミナルで実行されるもの）、OpenCodeは`opencode upgrade`、Grok Buildは`grok update`です。
- `npm install -g`でインストールしたGemini CLI、Qwen Code、Auggie、Grok Build、ACPアダプターを持つエージェントは、そのフォルダにユーザーが書き込める場合にnpmで更新されます。それ以外の方法でインストールしたものは更新されません。インストールした方法で更新してください。
- Claude Codeは独自のリリースラインに従います。設定に`"autoUpdatesChannel": "stable"`とあればstable、なければlatestです。
- `DISABLE_AUTOUPDATER=1`でClaude Code自身の更新をオフにしている場合（Dockerイメージはこの設定です）、アプリもユーザーのClaude Codeを自動では更新しません。**今すぐ更新**は引き続き更新します。

アプリは、新しいバージョンがセッションでの使われ方どおりに動作することを確認できた場合にのみ、そのバージョンを残します。Claude Codeはセッションの開始時に応答し、モデルを一覧表示できること、Codexはアプリサーバーを起動し、モデルを一覧表示できること、その他は起動してバージョンを答えられることが条件です。いずれもサインインは不要で、プランの使用量も消費しません。応答の待ち時間は1つにつき1分で、コンピューターがスリープしていない時間だけが数えられます。そのため、確認の途中でMacがスリープしても、1分は消費されません。初回の応答が遅いもの（Macは新しいプログラムを初めて実行する前に内容を調べます）は、さらに2分を与えて再起動され、それでも応答しない場合にのみ失敗となります。失敗したバージョンは元に戻されます。

- アプリがインストールしたコピー、またはnpmで更新したユーザーのコピーは、1つ前のバージョンに戻ります。
- ユーザー自身のClaude Codeでは、セッションは1つ前のバージョンで動き続けます。このバージョンは、Claude Codeのインストーラーが新しいバージョンの隣に残しています。ターミナルの`claude`コマンドは新しいバージョンのままです。行には「… did not work here」と表示されます。
- 失敗したバージョンは自動では再試行されませんが、次のバージョンは試行されます。**今すぐ更新**を押すと、もう一度試します。

その行の下には、アプリが最後に確認した時刻が「Up to date · checked 2h ago」のように表示され、**今すぐ確認**で再確認できます。新しいバージョンが公開されているときはその旨が表示され、**今すぐ更新**ですべてを一度にインストールできます（プログラムごとのボタンはありません）。更新中は、どのプログラムを更新しているかが表示されます。その下の行には、直近の更新で変わった内容（「Claude Code 2.1.308 → 2.1.316」など）や、バージョンをインストールできなかった理由が表示されます。

実行中のセッションは、開始時のバージョンのまま続行します。新しいセッションは新しいバージョンを使います。**自動で更新**がオフの場合も、アプリは1日に1回確認して公開中のバージョンを表示しますが、**今すぐ更新**をクリックするまでインストールはしません。

## Claude Code、Codex、Grok Buildにサインインする

Claude CodeとCodexは、サインインしないと使えません。追加した後のGrok Buildも同様です（[Gemini CLI、OpenCode、その他のACPエージェントを追加する](#add-gemini-cli-opencode-and-other-acp-agents)を参照）。[設定 → エージェント → アカウント](/settings?s=accounts)を開きます（スマートフォンでは、設定はセクションの一覧です。エージェントの下の**アカウント**をタップします。上部のタイトルから戻れます）。**アカウント**グループ（(i)には、セッションが使うClaude Code、Codex、Grok Buildのサインインであること、仕事用と個人用など別のサブスクリプションを追加でき、セッションの開始時に選べることが説明されています）には、まず各エージェント自身のサインインが表示され、その後にそのエージェント用に追加したアカウントが並びます。Grok Build自身のサインインにも、追加後にこの場所へ行が表示されます（**Grok Build**）。各行には、メールアドレス、プラン、サインイン方法とともに緑のチェックが表示されるか、「Not signed in」や問題の内容とともに赤い×が表示されます。

サインインするには：

1. エージェントの横の**サインイン**をクリックします。
2. 方法を選びます。
   - Claude Code：**Claudeサブスクリプション**（Claudeのプラン）または**コンソール（API課金）**（AnthropicのAPIアカウント）。
   - Codex：**デバイスコード**または**ブラウザのリダイレクト**。
   - Grok Build：選ぶ項目はありません。常にコードでサインインします。
3. **サインインリンクを取得**をクリックします。
4. ダイアログに表示される手順に従います。
   - Claude Code：リンクを開き（**サインインページを開く**）、ブラウザでアクセスを承認します。ページに表示されたコードを**ページに表示されたコードを貼り付け**に貼り付け、**サインインを完了**をクリックします。
   - Codex、デバイスコード：任意のデバイスでリンクを開き、ChatGPTにサインインして、ダイアログに表示されるワンタイムコードを入力します。完了すると、ダイアログが自動で検知します。
   - Codex、ブラウザのリダイレクト：サインイン後、ブラウザが「localhost」のページを開こうとして失敗します。そのページのアドレスをコピーし、**ブラウザのlocalhostアドレスを貼り付け**に貼り付けて、**サインインを完了**をクリックします。
   - Grok Build：リンクとワンタイムコードが表示されます。任意のデバイスでリンクを開き、Grokアカウントでサインインして、コードを確認します（**2. このコードを確認する**）。貼り付ける必要はありません。完了すると、ダイアログが自動で検知します。

成功すると「Claude Code is signed in」（CodexやGrok Buildの場合もあります）と表示されます。失敗した場合は、ダイアログに理由が表示されます。**もう一度試す**をクリックしてください。

サインインすると、ボタンは**アカウントを切り替え**に変わります。別のアカウントで同じサインインを始めます（Grok Buildでは新しいコード）。**サインアウト**は行の**⋯**メニューにあります。確認後、このコンピューター上でそのプログラムがサインアウトされ、それを使うすべてのターミナルとエディタに影響します。

サインアウトした状態でGrok Buildのセッションを始めると、「Grok Build is not signed in: sign in with your Grok account in Settings → Agents → Accounts, then try again.」と表示されてセッションが停止します。そこでサインインして、メッセージをもう一度送信してください。サブスクリプションの代わりに、エージェントの環境にある`XAI_API_KEY`のxAI APIキーでもGrok Buildを使えます。

ウェルカムツアー（アイコンバーの**ヘルプ**から開けます）では、使いたいエージェントとモデルを尋ねられ、これらのサインインについても案内されます。

## 2つ目のアカウントを追加する（仕事用と個人用）

Claude Code、Codex、Grok Buildのアカウントを複数サインインして、たとえば仕事用プランと個人用プランを、セッションごとに選べます。

1. [設定 → エージェント → アカウント](/settings?s=accounts&find=Accounts)を開きます。
2. **アカウント**グループのタイトルの横にある**アカウントを追加**をクリックします。
3. **Claude Code**、**Codex**、**Grok Build**（Grok Buildの設定後に選べます）のいずれかを選び、名前（40文字まで。「仕事」「個人」など）を入力して、**追加してサインイン**をクリックします。
4. 新しいアカウントのサインインダイアログが開きます。上で説明したとおりにサインインします。

追加したアカウントは、それぞれ個別にサインインし、独自のセッション履歴を持ちます。設定、指示、スキル、プラグインは、そのエージェントのメインのサインインと共有されるため、変更は両方に反映されます。Claude Codeでは、メインのサインインで信頼したフォルダは追加したアカウントでも信頼されるため、そのフォルダ自体の権限ルールがセッションで適用されます。同じエージェントの2つのアカウントに同じ名前は付けられません。

追加したGrok Buildのアカウントには、サインイン情報とGrok独自のセッション履歴を入れる専用のフォルダがあります。Grok CLI自体の設定（config、ルール（`AGENTS.md`）、スキル、プラグイン、MCPのサインイン）は、メインのサインインと共有されます。

追加したアカウントにはそれぞれ専用の行があり、エージェント自身のサインインの下に表示されます。行には**サインイン**または**アカウントを切り替え**があり、**⋯**メニューには**サインアウト**、**名前を変更**、**外す**があります。

- **名前を変更**：新しい名前を入力します。
- **サインアウト**：このアカウントとして動いているセッションは、再びサインインするまで動作しなくなります。
- **外す**：アカウントをアプリから取り除きます。そのセッションは一覧から消えますが、履歴はディスクに残ります。ただし**サインイン情報とセッションの履歴も削除する**にチェックを入れた場合は、あわせて削除されます。そのアカウントとして動いているセッションがある間は、外せません。先にセッションを停止してください。

[使用量ページ](/usage)には、追加したClaude Code、Codex、Grok Buildのアカウントごとにカードが表示され、それぞれの上限が確認できます。

## セッションを実行するアカウントを選ぶ

選んだエージェントに追加したアカウントがある場合（Grok Buildでは、追加した後）、開始ページの**オプション**に**アカウント**の行が表示されます。これをクリックします。

- **サインイン情報**は、プログラム自身のアカウントです（**アカウント**でそのエージェントの先頭にあるもの。Grok Buildでは「The Grok Build CLI's own account」）。
- 追加した各アカウントは、名前で一覧表示されます。
- **アカウントを管理**を押すと、設定 → エージェント → アカウントが開きます。

開始ページは、そのエージェントについての選択を覚えており、どの場所でも同じです。追加したアカウントで動いているセッションでは、セッションの上部に、そのアカウントの名前が人のアイコンとともに表示されます。そのアカウントが使用上限に達した場合、メッセージ欄の上に表示される上限の通知は、そのアカウントについてのものです。アカウントはセッションの開始時に決まります。自動で変わるのは、**上限時にアカウントを切り替え**（下記）を使った場合だけです。

セッションを自分で別のアカウントに移すには、セッション自身の**アカウント**チップをクリックして、アカウントを選びます。Claude Code、Codex、Grok Buildのセッションで使え、次のメッセージから反映されます。Grok Buildのセッションでは、Grokの履歴も一緒に移ります。Grokが別のアカウントで開き直せない場合は、そこで新たに開始され、その旨のメモが表示されます。

## すべてのアカウントを使う：上限時に切り替える

同じエージェントのアカウントが2つ以上あると、アプリはそのすべてを使えます。1つの使用量がなくなると、別のアカウントで作業が続行されます。[設定 → エージェント → アカウント](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit)を開き、**アカウント**の下の**使用上限時**グループにある**上限時にアカウントを切り替え**を探します。アカウントを1つでも追加すると（Grok Buildも含みます）表示されます。（(i)には、セッションのアカウントの使用量がなくなると、セッションがそのエージェントの使用量が残っている別のアカウントに移って続行されること、また新しいセッションは上限に達したアカウントを避けることが説明されています。）最初からオンになっています（自分でアカウントを選びたい場合は、そこでオフにしてください）。ブラウザを開いていなくても動作します。

- セッションのアカウントが使用上限に達してターンが止まると、アプリは同じエージェントの、使用量が残っているサインイン済みの別のアカウント（使用量が最も少ないもの）を選び、すべての履歴とともにセッションをそこに移して、「… reached its usage limit, so this session now runs on …. Continue where you left off.」を送信します。どのアカウントに移ったかは、画面の下部に短いメモで表示されます。
- Claude Codeのセッションがバックグラウンドで実行しているサブエージェントも続行されます。上限に達した時点でまだ作業中のものは、次のステップで停止し、作業内容は保持されます。アプリはセッションを移す前に、それらを待ちます（最長2分）。その後のメッセージにはそれらの名前が含まれ、エージェントは各サブエージェントを止まったところから続行させます。サブエージェントだけが上限に達した場合（そのモデルだけの上限など）、セッションはターンが終わり、どのサブエージェントも作業していなくなってから移ります。
- Hydorサブエージェント（エージェントが作業の一部を任せるために開始するセッション）はそれぞれ独立したセッションなので、上限でターンが止まると、各自で移ります。それを開始したエージェントには、失敗ではなく続行すると伝えられ、完了したときに返信を受け取ります。
- メインのサインインと追加した各アカウントは、すべて対象です。Claude Codeのアカウントの代わりはClaude Codeのアカウント、CodexはCodex、Grok BuildはGrok Buildが引き継ぎます。
- Grok Buildのアカウントは、週ごとの上限、クレジットの上限、従量課金の支出上限のいずれかに達すると、上限に達した状態になります。その場合、セッションは使用量が残っているサインイン済みの別のGrokアカウント（使用量が最も少ないもの）に移り、「… reached its usage limit, so this session now runs on …」で続行されます。短いレート制限（リクエストの集中）では何も移りません。自然に解消されます。上限の通知はGrokのセッションでも、メッセージ欄の上に表示されます。
- アプリが進めているゴールはアプリのものなので、新しいアカウントでも続行されます。Codexで`/goal`と入力したゴールは、セッションとともに移り、続行されます。
- すべてのアカウントが上限に達した場合は、何も移りません（Claude Codeで、下記の**上限時にAPIクレジットを使う**がオンの場合を除きます）。**使用量の上限後に再開**がオンの場合、最初のアカウントがリセットされたときに、そのアカウントでセッションが続行されます。これはGrok Buildのセッションにも当てはまります。詳しくは[使用量、上限、コスト](/guide/usage#continue-sessions-automatically-after-a-limit)を参照してください。
- 上限に達したアカウントで新しいセッションを始めると、代わりに使用量が残っているアカウントで始まります。また、アカウントが上限に達しているセッションにメッセージを送ると、先にセッションが移されるため、メッセージが拒否されることはありません。メッセージとともに、エージェントには、使用量が残っているアカウントで動いていること、そのため古いアカウントのリセットを待たなくてよいこと、どのサブエージェントが続行できるかが伝えられます。
- VS Codeやターミナルで開いたセッションは、そのアカウントのままです。
- 上限のリセット（Codexのリセットクレジット、Claudeのリセット付与）とAPIクレジットは、引き続きClaude CodeとCodex専用です。
- アプリ自身のClaude CodeやCodexへの簡単な質問（**自動**の補助モデル、アプリの簡単なモデルのステップ、プルリクエストの説明、コマンドの提案）は、あるアカウントが上限に達しているかサインアウトしている場合、同様に次のサインイン済みのアカウントに送られます。Claude CodeもCodexも答えられない場合は、Customモデルのいずれかが代わりに対応します（[アカウントがサインアウトしているとき](#when-an-account-is-signed-out)を参照）。

## アカウントがサインアウトされたとき

Claude Code、Codex、Grok Buildのアカウントは、サインアウトされることがあります。サインインが終了した、または取り消された場合で、プログラムは「Not logged in · Please run /login」や「401 Unauthorized」と表示します。アプリは可能な限り別の方法で対処し、ほかに手段がない場合にだけ、再度のサインインを求めます。

- **セッション.** アカウントがサインアウトされているためにセッションのターンが拒否されたとき、[上限時にアカウントを切り替え](/settings?s=accounts&find=Switch%20accounts%20at%20a%20limit)がオンであれば（初期状態でオンです）、セッションはすべての履歴とともに、同じエージェントで使用量に余裕のある別のサインイン済みアカウントに移り、そのまま続行されます。画面の下部に「<session>: <account> is signed out, so it continues on <other account>」という短い通知が表示され、エージェントには「… is signed out, so this session now runs on …. Continue where you left off.」と伝えられます。少し前にアカウントがサインアウトされていると判明しているセッションにメッセージを送ると、同じ方法で先にセッションが移るため、メッセージが拒否されることはありません。
- **セッションが移れないとき。** **上限時にアカウントを切り替え**がオフの場合や、そのエージェントで使用量に余裕のあるアカウントがほかにない場合、セッションは停止します。メッセージ欄の上にバナーが表示され、「<account> is signed out」と「This session continues once you sign in again.」というメッセージと、**サインイン**ボタンが表示されます。ここでも、ターミナルでも、再度サインインすると、セッションは自動的に続行され、エージェントには「Signed in again. Continue where you left off.」と伝えられます。
- **バックグラウンド処理。** **自動**に設定した[補助モデル](/settings?s=models&find=Helper%20model)の小さな処理（セッションのタイトル、メモリのメモ、[プロフィール](/guide/memory#your-profile)の要約、アプリの簡易なモデル処理、プルリクエストの説明など）は、サインアウトされたアカウントを15分間飛ばし、その後あらためて試します。そのため、ターミナルで行ったサインインにも気づけます。次にサインイン済みのアカウントが処理し、その次にCodexが処理します。Claude CodeもCodexも処理できない場合（サインアウト、上限到達、未インストール）は、**Custom**のモデルのいずれかが処理します。対象は、[設定 → エージェント → モデル → ティア](/settings?s=models&find=Tiers)でCustomの**高速**ティアに指定されているモデルで（次に**標準**、まれな大きめの処理では**最高**、さらに**最大**の順）、指定がなければ追加したなかで最も安価なモデルです（このコンピューター上のモデルは無料として扱われます）。試すのは最大2つまでです。かかった費用は、ほかのCustomモデルの使用と同様に計上されます。
- **サインインの案内。** どの手段でも処理できず、かつアカウントがサインアウトされている場合にのみ、すべてのページの右下にカードが表示されます（スマートフォンではメッセージ欄の上）。タイトルは「Sign in to Claude Code again」（またはCodex、Grok Build）で、その下に「<account> is signed out.」と表示され、求める理由が続きます。「Background work needs it (shortening your profile), and no other account or Custom model could do it.」、またはセッションが停止した場合は「… continues once you sign in.」です。**サインイン**を押すと、[設定 → エージェント → アカウント](/settings?s=accounts)と同じサインインのダイアログが開きます。**今はしない**を押すと、カードは1時間非表示になります。ただし、カードが原因で停止したセッションがあると、カードは再び表示され、そのセッションのバナーも残ります。カードは同時に最大2枚まで表示され、それ以上は「+N more」から設定 → エージェント → アカウントに移動できます。カードは、カードや設定、ターミナルからアカウントが再度サインインされると消えます（アプリは、次に通った呼び出しで気づきます）。別の方法でバックグラウンド処理が再び行えるようになった場合（別のアカウントやCustomモデルが処理した場合）も消えます。Claude CodeとCodexの両方がサインアウトされている場合は、先に処理されるClaude Codeについてのみ案内されます。

プロフィールにも表示されます。アカウントがサインアウトされているために要約に失敗した場合、その下に理由が表示され（「Your Claude Code account “Work” is signed out, and no other account or Custom model could do this: sign in again (Settings → Agents → Accounts).」）、カードも表示されます。

## すべてのアカウントが上限に達したときにAPIクレジットを使う

Anthropic APIキー（[console.anthropic.com](https://console.anthropic.com) → API keysで取得）がある場合、すべてのClaude Codeアカウントが使用上限に達しても、Claude Codeのセッションは停止せずに、そのキーで続行できます。費用がかかります。この方法で実行されている間、セッションはサブスクリプションの対象外となり、AnthropicからAPI料金で請求されます。

1. [設定 → エージェント → アカウント](/settings?s=accounts&find=Use%20API%20credit%20at%20a%20limit)を開きます。**アカウント**にあるClaude Codeアカウントの行（メインのサインイン、または追加したアカウント）で、**⋯**をクリックし、**APIキーを追加…**を選びます。
2. **Anthropic APIキー**にキーを貼り付けて、**キーを保存**をクリックします。アプリはAnthropicでキーを確認し、このコンピューター上に暗号化して保管します。その後、行に**APIクレジット**のタグが表示されます。**APIキーを変更…**でキーを置き換え、**APIキーを削除**で削除できます。
3. **使用上限時**グループにある**上限時にAPIクレジットを使う**をオンにします（(i)には、すべてのClaude Codeアカウントが使用上限に達したとき、セッションは停止せずにアカウントのAnthropic APIキーに請求して続行されること、オンにするまではオフであることが説明されています）。この項目は、Claude Codeにサインインしている場合、またはClaude Codeアカウントを追加した場合に表示されます。

その後の動作は次のとおりです。

- Claude Codeセッションのアカウントが使用上限に達すると、アプリはまず**上限時にアカウントを切り替え**の動作として、使用量に余裕のある別のアカウントを探します。余裕のあるアカウントがなく、この設定がオンの場合にのみ、セッションはAPIキーに請求して続行されます。
- セッションは元のアカウントのままなので、履歴は移動しません。そのアカウントにキーがない場合は、別のClaude Codeアカウントのキーが使われます。
- セッション上部のアカウントの横に、**APIクレジット**のタグが表示されます。カーソルを合わせると理由が確認できます。
- プランの使用量が再び使えるようになると、セッションは次のターンの終了後にそのプランに戻ります。元のアカウント、または使用量に余裕のある別のアカウントです。操作は不要です。
- アプリがアカウントの使用量を読み取れない場合、作業がAPI課金に移ることは一切ありません。
- Codexは対象外です。APIクレジットはありません。

## Gemini CLI、OpenCodeなどのACPエージェントを追加する

[設定 → エージェント → その他のエージェント](/settings?s=agents&find=Agents%20that%20speak%20ACP)を開きます。

- **自分のエージェント**（セッションを開始するときにClaude CodeやCodexの隣に表示されます）には、最初にCustom、続いて追加したエージェントが並びます。各エージェントには、プログラムがここにインストールされていればチェックが、されていなければ×と「not installed」が表示されます。
- **ACPに対応したエージェント**（インストールして、そのエージェント自身のCLIで一度サインインしてから、ここで追加します）には、まだ追加していない既知のエージェントが並びます。Gemini CLI、OpenCode、Qwen Code、Goose、Kimi CLI、Auggie、Grok Buildなどです。インストール済みのものが先に表示されます。「Not installed」と表示された行には、入手方法が示されます。未インストールのものは最初の数件だけが表示され、**すべて表示**で残りが表示されます。

追加するには次のようにします。

1. 行の右端にある**追加**をクリックします。プログラムがすでにインストールされている場合、ボタンが目立つ表示になります。
2. アプリがインストール方法を把握している場合（Gemini CLI、OpenCode、Qwen Code、Auggie、Grok Build、およびACPアダプターが必要なエージェント）は、バックグラウンドでそのままインストールされます。Goose、Kimi CLIなどは、行に表示されたコマンドやアドレスを使って自分でインストールします。
3. エージェント自身のプログラムで一度サインインします。[ターミナル](/terminal)を開き、そのコマンド（例：`gemini`）を実行して、表示に従ってサインインします。省略すると、セッションで「Gemini CLI is not signed in. Run gemini once in a terminal and sign in there, then try again.」と案内されます。

これでエージェントが、開始ページの**実行環境**の一覧に表示されます。

追加したエージェントを変更するには、**編集**をクリックします。外すには、**⋯**メニューを開いて**外す**を選び、確認します。そのセッションは一覧に残りますが、続行するにはエージェントを再度設定する必要があります。Customは組み込みで、その行には「Built in: models from OpenRouter, Ollama and vLLM, in Settings → Models」と表示され、編集と外すの代わりに**モデル**ボタンがあります。

### Grok Build

**Grok Build**は、xAIのコーディングエージェント（`grok`プログラム）です。行の**追加**をクリックするだけで完了です。アプリは、最初に必要になったときにnpm（`@xai-official/grok`）からインストールするか、すでにあるもの（`~/.grok/bin`にあるxAI公式インストーラー経由のものを含む）を使います。その後は**エージェントプログラム**に表示され、ほかのものと一緒に最新の状態に保たれます。Hydorは、アプリ独自のツールと承認カード、Grokのモデルを使って、ACP経由でこれを実行します。

サインインの方法はほかのACPエージェントと異なります。ターミナルではなく[設定 → エージェント → アカウント](/settings?s=accounts)で行い、追加するとすぐに**Grok Build**の行が表示されます（[Claude Code、Codex、Grok Buildにサインインする](#sign-claude-code-codex-and-grok-build-in)を参照）。ここでGrokアカウントをさらに追加することもできます。

### 自分のエージェントを追加する

ACPに対応したプログラムであれば、どれでもここで実行できます。

1. **自分のエージェント**のタイトルの横にある**自分で追加**をクリックします。
2. 次の項目を入力します。
   - **名前**：一覧に表示される名前です。例：「Gemini CLI」。
   - **コマンド**：起動するプログラムです。例：`gemini`、またはフルパス。
   - **引数**：ACPモードで起動するための引数です。例：`--experimental-acp`。
   - **環境変数（任意、1行に NAME=value）**：APIキーの変数など、プログラムに必要な設定です。
3. **保存**をクリックします。

コマンドは、標準入出力を通じてやり取りするACPモードでエージェントを起動するものでなければなりません。

### 自分でセットアップするエージェント

一覧のエージェントのなかには、自分でセットアップするプログラムもあり、アプリがインストールするものとはいくつか異なる点があります。

- **その他のエージェント**にある行に、インストール用のコマンドやアドレスが表示されます。アプリは、Webからスクリプトを取得して実行することはしません。[ターミナル](/terminal)で、または行の案内に従って、自分でインストールします。
- エージェント自身のプログラムでも、ターミナルで一度サインインします（たとえば、そのコマンドを実行して表示に従ってサインインするか、そこでモデルを選びます）。以降はアプリが起動します。セッションとメモリは、そのエージェント専用のフォルダに保存され、承認カードもそのエージェントが提示するものになります。
- そのうち1つは、独自のゲートウェイに接続します。先にエージェント自身のセットアップコマンドでゲートウェイを設定し、起動したままにしておきます。
- エージェント自体がACPに対応していない場合は、ACPアダプターが必要です。アプリは、アダプターをエージェントとともにインストールします。どちらもアプリ専用のフォルダにnpmで、インストールスクリプトは実行せずに入れます。自分でインストールしたエージェントは、PATHにあればそれが使われます。
- MCPサーバーを受け付けないエージェントは、そのエージェント自身のツールだけで動作します。アプリのツール（ページ、検索など）は届かず、セッションの開始時にその旨が表示されます。それでも、アプリのガイドライン、メモリのメモ、スキルは最初のメッセージとともに渡されます。

### ここでACPエージェントにできることとできないこと

アプリは、選択したフォルダでセッションを開き、エージェントのメッセージと手順を表示し、エージェントが許可を求めるたびに確認します。Claude CodeやCodexとは動作が異なる点がいくつかあります。

- メッセージは1件ずつ処理されます。処理中に送ったメッセージは、メッセージ欄の上のキューで待機し、ターンの終了時に送られます（Customも同様です）。
- 以前のセッションを再び開けないエージェントでは、古いセッションを続けると、それまでの会話なしで最初から始まります。セッションにその旨が表示されます。以前は再び開けたのに開けなくなった場合も同様で、失敗せずに、メモを添えて最初から続行されます。
- 添付した画像は、そのエージェントが画像に対応している場合にのみ届きます。
- フォークと引き継ぎは使えません（Customにはフォークがあります）。ゴールは使えます。アプリ独自のループが、すべてのエージェントで実行します。
- アプリのツール（ページ、検索、メモリなど）は、MCPサーバーとしてエージェントに届きます。エージェントが対応していればアドレス経由で、そうでなければアプリがエージェント用に起動する小さなプログラムを通じて届きます。どちらも受け付けないエージェントは、そのエージェント自身のツールだけで動作しますが、ガイドライン、メモリのメモ、スキルは引き続き渡されます。

## Customのモデルの入手元

Customは、ClaudeとChatGPTのプランのモデル、このコンピューター上のモデル、クラウド上のモデルを、他のエージェントと同じツール、スキル、MCPサーバーで実行します。スタートページでCustomを選び、続けてモデルを選びます。モデルの入手元は3つあります。

- **契約中のサブスクリプション**：ClaudeとChatGPTのプランのモデルです。このコンピューター上のClaude CodeとCodexのサインインを通じて使います。設定は不要です。Claude Codeにサインインしていれば、Customの**モデル**メニューにClaude Opus、Fable、Sonnet、Haikuが表示され（それぞれ常に最新のもの）、ChatGPTでCodexにサインインしていれば、ChatGPTのプランに含まれるモデル（例：GPT-6 Luna）が表示されます。サインアウトしていることが確認されたプログラムのモデルは、再びサインインするまでメニューから消えます。また、ChatGPTではなくAPIキーでサインインしているCodexからは、モデルは提供されません。これらのモデルはプランの使用量を消費し、APIキーやトークン単位の課金は使わないため、Customのセッションでこれらを使ったステップは$0と表示されます。プログラムのアカウントは、他の単発の作業と同様に順番に試されます。使用量の上限に達したアカウントやサインアウトしたアカウントがあると、そのステップは次のアカウントに引き継がれます（**上限時にアカウントを切り替え**がオンの場合）。[機密セッション](/guide/sessions#keep-a-session-confidential)では、これらのモデルは使われません。AnthropicやOpenAIのサーバー上で動作するためです。回答の仕組みは[Custom](/guide/custom#what-custom-is-and-when-to-use-it)をご覧ください。
- **このコンピューター**：ここにインストールされたモデル（Ollama、vLLM）と、ネットワーク上のエンドポイントです。
- **クラウド**：OpenRouter、その他の場所にあるエンドポイント、Ollamaのクラウドモデルです。

Customのモデルを選べる場所ならどこでも選べます。スタートページ、セッションのモデルメニュー、Customのティア、補助モデル、エージェントやアプリのモデルです。

Customのモデルに必要な項目は、すべて[設定 → エージェント → モデル](/settings?s=models)にあります。ページは上から順に7つの部分で構成されています。

- **補助モデル**：アプリの小さな作業に使うモデルです。
- **ティア**：作業の種類ごとのモデルです（[ティア：作業の種類ごとのモデル](#tiers-a-model-for-each-kind-of-job)をご覧ください）。
- **契約中のサブスクリプション**：Claude CodeとCodexの行が1つずつあり、それぞれがCustomに提供するモデルが表示されます。行には「サインアウトしています：これらのモデルを使うには再度サインインしてください」と表示され、**アカウント**へのリンクが付くか、「このコンピューターにインストールされていません」と表示されます。
- **このマシン上**：このコンピューターの構成と、ここにインストールされたモデルです。
- **Hugging Faceからモデルを追加**：オープンモデルの検索、確認、インストールを行います。
- **OpenRouter**：1つのキーで数百のモデルを利用できます。キー、追加したモデル、さらに追加するための検索の3つのグループがあります。
- **ランタイムとエンドポイント**：Ollama、vLLM、その他のOpenAI互換サーバー、Hugging Faceトークンです。

Customの**モデル**メニューでは、モデルが**契約中のサブスクリプション**、**このコンピューター**、**クラウド**にグループ分けされ、各行にはモデルの接続経路（「Claude Code」「Codex」「OpenRouter」「Ollama」「vLLM」、またはエンドポイント名）が表示されます。モデルにカーソルを合わせると、実行場所と一度に読み取れる量が表示されます（例：「OpenRouter · 128K context」「vLLM, on this machine · 32K context · starts when used」）。一覧は1分ごとに自動で更新されます。

## 補助モデルを選ぶ

補助モデルは、会話の外でセッションと並行して行う小さな作業を担当します。

- 依頼内容から新しいセッションに名前を付ける（サイドバーに表示されるタイトル）。
- Customの自動モードでステップを確認する。また、レビュアーが真と判断すべきゴールのチェックを判定する（レビュアーとは、作業に一切関わっていないモデルのことで、機密セッションではこのコンピューター上のモデルが使われます）。
- 約1日に1回、メモリを整理し、それ以降の会話から学習し、エージェントが最初に読む索引用にメモへタイトルを付ける。
- ブラウザで開いているWebページについての質問に1つ答える。
- Naget Searchが検索する前に、Web検索の語句に含まれる絞り込み条件（サイト、日付、ページの種類、言語）を読み取る（[エージェントのWeb検索の仕組み](/guide/web#how-agents-search-the-web)をご覧ください）。
- 画像を見られないCustomのモデルのために、画像を説明する。
- Hydorサブエージェントからの長い返信を要約する。
- セッションからアプリやスケジュールタスクの下書きを作る。
- ハンズフリーの音声モード。

[設定 → エージェント → モデル](/settings?s=models&find=Helper%20model)を開き、**補助モデル**グループの**モデル**メニューをクリックします（(i)に小さな作業の一覧が表示されます）。

- **自動**（デフォルト）：Claude Code経由のClaude Haikuを使い、Claude Codeが答えられない場合はCodexを使います。使用量の上限に達したアカウントがある場合は、まず次のサインイン済みアカウントに質問が引き継がれ（**上限時にアカウントを切り替え**がオンの場合）、サインアウトしたアカウントは飛ばされます。どちらのプログラムも答えられない場合は、Customのモデルのいずれかが処理します（Customの**高速**ティアに指定されたモデル、なければ追加したモデルのうち最も安価なもの。プランのモデルは同じ2つのプログラムを経由するため、ここでは対象外です）。それでも処理できない場合にのみ、サインインを促すカードが表示されます（[アカウントがサインアウトしているとき](#when-an-account-is-signed-out)をご覧ください）。どれも答えられない場合、エラーにはそれぞれの理由が表示されます。「週の上限に達しました」、Codexのプランで提供されていないモデルなどです。
- Customのモデルのいずれか。Customの**モデル**メニューと同じくグループ分けされ（**契約中のサブスクリプション**、**このコンピューター**、**クラウド**）、接続経路（Claude Code、Codex、OpenRouter、Ollama、vLLM、またはエンドポイント名）と、画像を見られるモデルには「画像対応」が表示されます。ClaudeやChatGPTのプランのモデルも補助モデルにできます。その場合、プランの使用量を使ってClaude CodeまたはCodex経由で回答します。

**自動**では画像を見ることができません。画像を見られないモデルでCustomを使う場合は、画像を見られる補助モデルを選んでください。そうしないと、Customは画像の説明を得られません。

## このコンピューターで実行できるモデルを確認する

[設定 → エージェント → モデル](/settings?s=models&find=On%20this%20machine)の**このマシン上**セクションは、このコンピューターの概要から始まります。

- **グラフィックス**：グラフィックスカード（GPU）とそのメモリ。Apple siliconのMacではチップ名（「Apple M3 Max」など。グラフィックスはコンピューターのメモリを共有します）。GPUがない場合は「No GPU」（モデルはプロセッサで実行されます）。
- **メモリとディスク**：コンピューターのメモリの合計と空き容量、ディスクの空き容量、インストール済みモデルが占める容量。
- **実行方法：**：**Ollama**とvLLMがインストールされているか（バージョン付き）、またはインストール用のリンク。
- グラフィックスカードがある場合は、収まるモデルの大きさ。「Fits about 30B parameters at 4-bit on one GPU」（Macの場合：「Fits about 40B parameters at 4-bit」）。パラメータはモデルの大きさの目安です。4ビットは一般的な圧縮形式で、必要なメモリは約4分の1になります。

その下には次の内容が表示されます。

- **ダウンロード中**：それぞれに進行状況バー、完了した量、OllamaとvLLMのどちら用かが表示されます。**キャンセル**で1つを中止できます。失敗またはキャンセルされたものには理由が表示され、**閉じる**があります。
- **インストール済みのモデル**（最初のいくつかのみ表示され、残りは**すべて表示**）：それぞれのランタイム（OllamaまたはvLLM）、サイズ、詳細（Ollamaモデルではサイズや圧縮方式など）、画像を見られるモデルには「画像対応」、実行中かどうかが表示されます。
  - vLLMモデルには**開始**と**停止**があります。セッションが最初に使うと自動的に起動し（初回の起動には1〜2分かかります）、空きメモリが最も多いグラフィックスカードで動作します（そのままでは収まらない場合は8ビットで）。1枚では収まらない場合は2枚、4枚、8枚に分割されます（「running on GPUs 1, 2」）。Macの場合はApple siliconで動作します。アプリを再起動しても、**停止**をクリックするまで動き続けます。起動できない場合は、その下に理由が表示されます。
  - モデルの**⋯**メニューにある**外す**を選ぶと、確認後にモデルのファイルがこのコンピューターから削除されます。後でもう一度インストールできます。

まだモデルがない場合は、「ここにはまだモデルがありません。下のHugging Faceから追加してください。」と表示されます。

## Hugging Faceからモデルを追加する

Hugging Faceは、オープンモデルの代表的なサイトです。[Hugging Faceからモデルを追加](/settings?s=models&find=Add%20a%20model%20from%20Hugging%20Face)グループ（このコンピューター向けのおすすめ、またはサイト全体の検索）では、いくつかのモデルを提案し、検索でき、ダウンロードする前に、各モデルがこのコンピューターでどう動作するかを示します。

### このコンピューター向けのおすすめ

検索する前に、このコンピューターの構成に合わせて、アプリがおすすめするモデルが一覧表示されます。

- **LFM3-VL 2B**（Liquid AI）：小型で高速、画像も読み取れます。ほとんどのコンピューターで動作します。
- **Gemma 4 12B**（Google）：画像を読み取れる高性能な万能モデルです。優れたグラフィックスカードを備えたコンピューター向けです。
- **Flint**（Recursive）：コーディングエージェント向けに作られています。32GB以上のApple silicon搭載Mac向けです。
- **GLM-5.3 Flash**（Z.ai）：オープンモデルの中でも最高クラスです。大型のグラフィックスカードを複数搭載したサーバー向けです。

それぞれ、ここで快適に動作するか低速かどうか、どのように動作するか（「vLLM at 8-bit, on GPU 0」「vLLM, split across 2 GPUs」「vLLM, on Apple silicon」）、ダウンロードサイズ、**インストール**が表示されます。快適に動作するモデルのうち最も高性能なものには**ここで最適**と表示されます。デフォルトではvLLMで実行されます。NVIDIAのグラフィックスカードもApple siliconもないコンピューターでは、代わりに小型モデルのOllama版が表示されます。実行に必要なものがまだ設定されていない場合は、警告が続きます（「vLLM is not set up」「Ollama is not running」）。[Ollama、vLLM、その他のエンドポイントを接続する](#connect-ollama-vllm-or-another-endpoint)をご覧ください。**2 more for bigger computers**（数は状況により異なります）の行では、他のモデルと、それぞれに必要な条件が表示されます。ウェルカムツアーでも同じモデルがおすすめされます。

### 検索と絞り込み

1. **Hugging Faceを検索、またはorg/nameを貼り付け**に入力します。`qwen3`のような名前、モデルの正式名（`org/name`）、またはhuggingface.coのアドレスを入力できます。入力前には、いくつかの名前の候補か、**ダウンロード数の多いものを見る**が表示されます。
2. フィルタで一覧を絞り込みます（組み合わせて使えます）。
   - **ここで快適に動作**：このコンピューターで快適に動作するモデルのみ。
   - **GGUF・Ollama**：Ollamaで実行できるGGUF形式のモデル。
   - **vLLM**：グラフィックスカード上でvLLMが実行するsafetensors形式のモデル。
   - **画像対応**：画像も読み取れるモデル。
3. 右側のメニューで並び順を変更します：**ダウンロード数順**、**トレンド**、**いいね数順**、**新しい順**。

最大40件のモデルが表示されます。最初は8件で、残りは**すべて表示**で見られます。正式名で指定したモデルは、検索結果に含まれていなくても先頭に表示され、Enterキーを押すとすぐに確認されます。

各行には、作成元と名前、形式（**GGUF**または**vLLM**）、画像を読み取れる場合は**画像**、利用規約への同意を作成元が求める場合は**制限付き**、パラメータ数によるサイズ、直近30日間のダウンロード数、いいね数、最終更新日が表示されます。

### 最初の判定

各モデルの下には、サイズだけから判断した最初の目安が色付きのラベルで表示されます。

- **Runs well with vLLM**または**Runs well with Ollama**と、おおよその速度（「約40トークン/秒」。トークンは単語の断片のことです）：グラフィックスカードのメモリに収まります。
- **プロセッサで低速に実行**または**プロセッサで非常に低速に実行**：コンピューターのメモリにしか収まらないため、プロセッサで実行されます。これができるのはOllamaだけです。
- **このコンピューターには大きすぎます**：収まらない、またはダウンロードがディスクに収まりません。
- **At 4-bit with Ollama: runs well…**：保存されている形式のモデルは大きすぎますが、圧縮された4ビット版ならOllamaで快適に動作します。

ラベルにカーソルを合わせると、判定の根拠となる数値が表示されます。

### ダウンロード前に確認する

モデルの**確認**をクリックすると、ここでどのように動作するかを正確に確認できます。パネルには、サイズ、一度に読み取れる量（コンテキスト）、画像を見られるかどうかが表示され、続けて次の内容が表示されます。

- GGUFモデルの場合：「Runs with Ollama」と、利用できる各サイズが小さい順に表示されます（ファイルが小さいほど、品質をわずかに犠牲にして速度とメモリを優先します）。各行には、判定、必要なメモリ、おおよその速度、ダウンロードサイズ、**インストール**ボタンが表示されます。Ollamaがここで動いていない場合や、大きすぎるサイズでは、インストールはグレーアウトされます。
- vLLMモデルの場合：「Runs with vLLM, which starts it on a GPU when a session uses it」と、同じ数値、どのグラフィックスカードを使うかの注記、**ダウンロード**ボタンが表示されます。vLLMがインストールされていない場合や、お使いのvLLMがこの種類のモデルをまだ実行できない場合はその旨が表示され、GGUF版がある場合は代わりにそちらの**確認**が案内されます。
- それ以外の場合：「No weights this app can run (safetensors for vLLM, GGUF for Ollama).」

数値は、最大約32,000トークンの会話を想定しています。これは、このコンピューター上のモデルに与えられる長さです。**閉じる**でパネルを折りたたみます。

### インストールと、その後の流れ

**インストール**（Ollama）または**ダウンロード**（vLLM）をクリックします。ダウンロードの進行状況は**このマシン上**に表示されます。完了すると、モデルがCustomの**モデル**メニューに表示されます。途中で中断されたvLLMのダウンロードは、もう一度実行すると中断した位置から再開されます。どのグラフィックスカード1枚にも収まらないvLLMモデルは、起動時に8ビット（FP8）で保存されます。これにより、重みが占めるメモリは半分になり、品質の低下はわずかです（NVIDIAのRTX 30シリーズおよびA100以降のカードが対象）。それでも収まらない場合は、複数のカードの合計に余裕があれば、それらに分割されます。

### 制限付きモデルと非公開モデル

作成元が先に利用規約への同意を求めるモデルには、**制限付き**と表示されます。huggingface.coのモデルのページで規約に同意し、Hugging Faceトークンを追加してください（[Hugging Faceトークン](#hugging-face-token)をご覧ください）。非公開モデルにもトークンが必要です。

## OpenRouterでモデルを使う

OpenRouter（openrouter.ai）では、多くのメーカーの数百ものモデルを1つのキーで利用できます。料金は使った分だけです。

### キーを追加する

1. openrouter.aiでキーを取得します（このセクションからリンクしています）。
2. [設定 → エージェント → モデル](/settings?s=models&find=OpenRouter)で、**OpenRouterのキー**の行にある**キーを追加**をクリックし、ダイアログの**OpenRouterのキー：sk-or-…**に貼り付けて**保存**をクリックします。

すると、その行に**OpenRouterに接続済み**と、キーの先頭と末尾が表示されます。**⋯**メニューの**キーを削除**を選ぶと、キーが消去されます。キーはサーバーに保管され、再び表示されることはありません。

最初に必要になったときに追加することもできます。キーがない状態でエージェントが画像、図、動画、音声を作ろうとすると、会話内のカードでキーを求めます（[エージェントにOpenRouterのキーが必要なとき](/guide/documents-voice#when-an-agent-needs-the-openrouter-key)）。エディタのAIツールも、ダイアログで求めます。どちらの場合も、キーはここに保存されます。

### おすすめのモデル

検索する前に、**OpenRouterのモデルを追加**グループの**おすすめ**に、Custom向けのモデルが4つ、それぞれの特長とともに表示されます。**GPT-6 Luna**（高速で低価格）、**Grok 4.7**（高品質で拒否が少ない）、**GPT-6.1 Sol**（より高品質）、**Claude Opus 5.5**（総合で最高）です。**追加**をクリックすると、モデル選択に加わります。画像、音楽、音声、動画については、アプリの選択肢はSeedream 5.0 Pro（および、より高速で低価格なFlash）、Lyria 3 Pro、Seed Audio 1.0、Seedance 2.5です。詳しくは[設定 → 機能 → 画像、動画、音声](/settings?s=images)をご覧ください。

### カタログを検索する

同じグループで、**OpenRouterを検索：deepseek、qwen、claude…**に入力するか、おすすめの名前のどれかをクリックするか、**新着を見る**をクリックします。フィルタは次のとおりです。

- **ツール呼び出し**：ツールをネイティブに呼び出せるモデルです。Customが最も使いこなせるタイプです（**最も一致**ではこれらが先頭に表示されます）。
- **画像対応**
- **推論**：答える前に考えるモデルです。
- **自由**

右側のメニューで、結果の並び順を選べます。**最も一致**（名前で検索しているとき）、**新しい順**、**最安**、**最長コンテキスト**があります。表示されるモデルは最大50件で、最初は8件のみ表示され、残りは**すべて表示**で見られます。

各モデルには、メーカー、名前、ラベルが表示されます。ラベルは、**最新**（メーカーの最新バージョンを常に指します）、**新規**（過去3週間以内に掲載）、**自由**、**推論**、**画像**、**ネイティブツールなし**（この場合、Customはツールの説明を指示文に入れ、呼び出しをテキストから読み取ります）です。その下には、一度に読み込める量（「128K context」）、最長の返答（「16K out」）、入力と出力それぞれの100万トークンあたりの価格、掲載された月、短い説明、OpenRouterでの名前が表示されます。

### モデル選択にモデルを追加する

モデルの**追加**をクリックします。するとその行が**追加**と表示され、モデルが検索欄の上にある**OpenRouterのモデル**グループ（「モデル選択に表示」）と、Customの**モデル**メニューに表示されます。メニューから外すには、その×をクリックします。1つも追加しないうちは、OpenRouterのモデルは表示されません（「OpenRouterを使うには、モデルを1つ以上追加してください。」）。

## Ollama、vLLM、その他のエンドポイントに接続する

**ランタイムとエンドポイント**グループでは、モデルを実行するプログラムに接続します。[設定 → エージェント → モデル](/settings?s=models&find=Runtimes%20and%20endpoints)から開けます。

### Ollama

Ollamaは、グラフィックカードまたはプロセッサを使って、お使いのコンピューター上でモデルを実行する無料のプログラムです。行には、バージョン付きで「実行中」、または**Ollamaをインストール**のリンク付きで「このアドレスでは実行されていません」と表示されます。アドレスは、変更しない限り `http://127.0.0.1:11434` です。別のアドレスを使うには、欄に入力します。すると、隣に**保存**が表示されます。そのOllamaのモデルはすべて、アプリの外で取得したものも含めて、Customのモデル一覧に表示されます。

### vLLM

vLLMは、NVIDIAのグラフィックカード向けの高速なモデルサーバーで、ここではHugging Faceのモデルを実行する標準の方法です。1枚のカードに収まらない大きなモデルは、8ビットで実行するか、2枚、4枚、8枚のカードに分割して実行します。Macでは、vLLMはMetalプラグイン（vllm-metal）を使ってApple siliconで動作します。アプリは、PATH上やcondaまたはvenv環境の中から自動的に見つけ、バージョンと場所を表示します。「見つかりません（pip install vllm を実行するか、コマンドを指定してください）」と表示された場合は、インストールするか、`vllm`コマンドのフルパスを欄に入力して**保存**をクリックします（入力すると表示されます）。欄を空のままにすると、アプリが自動で探します。

### その他のOpenAI互換エンドポイント

多くのプログラムやサービスが、OpenAIのAPIと同じ方式で応答します。LM Studio、llama.cppのサーバー、その他のプロバイダなどです。追加するには、次の手順に従います。

1. グループのタイトルの隣にある**エンドポイントを追加**をクリックします。
2. ダイアログで、**名前**、アドレス（`http://localhost:1234/v1`など）、**キー（任意）**を入力します。
3. **追加**をクリックします。

エンドポイントは、アドレスと提供モデル数が付いた行として表示されます。そのモデルは、Customの一覧に「モデル（名前）」の形式で表示されます。×をクリックすると削除されます。同じ名前でエンドポイントをもう一度追加すると、最初のものが置き換えられます。

行の下にある**各モデルでできることを設定**をクリックすると、そのモデルの一覧が表示され、それぞれに**画像対応**と**推論の思考レベル**の2つの選択肢があります。どちらも**自動**、**はい**、**いいえ**から選べます。画像に対応するモデルには、スクリーンショットや画像がそのまま渡されます。対応しないモデルには、その説明が渡されます（[画像を認識できないモデル向けの処理](/guide/custom#images-for-models-that-dont-see)をご覧ください）。推論に対応するモデルでは、**思考レベル**メニューに低、中、高が表示され、Customは選んだ値を、OpenAI互換サーバーが受け付ける設定である `reasoning_effort` として送信します（**デフォルト**を選んでいる間は何も送信されません）。**自動**は、エンドポイントがそのモデルについて示す内容に従い、メニューにその内容が表示されます。モデルについて説明するサーバー（OpenRouter方式やMistralなど）は、モデル一覧とともにその情報を返します。LiteLLMゲートウェイの場合は、Hydorが同じキーでモデル情報も問い合わせます。何も示さないエンドポイントは「いいえ」として扱われます。画像に対応する、または推論できるとわかっているモデルには**はい**を設定してください。設定した内容は、エンドポイントを再度追加しても保持されます。

[機密セッション](/guide/sessions#keep-a-session-confidential)で使えるのは、アドレスがこのコンピューターまたはプライベートネットワーク内にあるエンドポイントです。`localhost`、`127.0.0.1`、`::1`、`10.…`、`192.168.…`、`172.16.…`から`172.31.…`まで、または`.local`で終わる名前が該当します。それ以外のアドレスはオンラインとみなされ、自分のサーバーにつながるものでも同じです。その場合は、プライベートアドレスを使ってください。Ollamaのアドレスにも同じ決まりが適用され、Ollamaのクラウドモデル（名前が「cloud」で終わるもの）は常にオンラインとみなされます。

### Hugging Faceトークン

[Hugging Faceトークン](/settings?s=models&find=Hugging%20Face%20token)があると、アプリは制限付きまたは非公開のモデルをダウンロードできます（行には「制限付きまたは非公開のモデル専用」と表示されます）。Hugging Faceのアカウント設定でトークンを作成し、**トークンを追加**をクリックして、ダイアログに貼り付け（`hf_`で始まります）、**保存**をクリックします。すると、その行にトークンの先頭と末尾が表示され、**⋯**メニューに**トークンを削除**が表示されます。
