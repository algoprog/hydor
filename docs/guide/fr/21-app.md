# Apparence, langue et mises à jour

Comment l’app s’affiche et se comporte pour vous, et comment elle se tient à jour : mode sombre ou clair, thèmes intégrés et vos propres thèmes, langue, part de mouvement dans l’app, rôle de la touche Entrée pendant qu’un agent travaille, démarrage avec l’ordinateur, maintien en éveil pendant que les agents travaillent, mises à jour et notes de version. Cette page couvre aussi votre mot de passe, la déconnexion et l’endroit où l’app conserve ses données.

![Paramètres → Général : les thèmes](images/app.webp)

## Choisir le mode sombre, clair ou celui de votre appareil

Ouvrez [Paramètres → App → Général](/settings?s=general&find=Appearance). Le groupe **Apparence** a un sélecteur à côté de son titre :

- **Sombre** : toujours un thème sombre.
- **Clair** : toujours un thème clair.
- **Système** : suit votre appareil, avec un thème sombre quand il est réglé sur sombre (la nuit, par exemple) et un thème clair sinon.

Le mode est conservé dans ce navigateur, donc votre téléphone et votre ordinateur peuvent différer. La zone de recherche (Ctrl+K, ⌘K sur Mac) propose **Basculer entre clair et sombre**, qui passe aussitôt le mode sur clair ou sur sombre.

## Choisir un thème

Sous le titre, dans le cadre du groupe, les thèmes apparaissent sous forme de petites images de l’app dans leurs couleurs, sur deux rangées : **Sombre** et **Clair**. Quatre sont fournis avec l’app :

- **Hydor Sombre** : noir pur derrière vos sessions, panneaux noir-bleu froid et accent bleu pervenche. C’est le thème sombre par défaut.
- **Minuit** : noir pur derrière vos sessions, panneaux presque noirs et chauds, et accent doré.
- **Hydor Clair** : blanc cassé chaud avec un accent doré profond. C’est le thème clair par défaut.
- **Sauge** : un papier gris-vert froid avec un accent bleu-vert profond.

Cliquez sur un thème pour l’utiliser. Il devient le thème de son mode, et le mode bascule dessus (sauf si le mode est **Système**\u00a0: il s’affiche alors chaque fois que votre appareil est dans ce mode). Chaque mode garde son propre choix : vous pouvez avoir Minuit la nuit et Sauge le jour. Avec **Système** activé, les rangées indiquent lequel est « affiché actuellement ». Saisir le nom d’un thème dans la zone de recherche le trouve aussi, et le choisir bascule dessus.

Chaque image a un menu (⋯, visible quand vous la survolez sur un ordinateur) :

- **Créer une copie à modifier** : ouvre l’éditeur de thème avec une copie de celui-ci.
- **Copier pour partager** : copie le thème sous forme de texte, à importer ailleurs.
- **Modifier** et **Supprimer** : uniquement pour les thèmes que vous avez créés. La suppression demande d’abord confirmation, et les appareils qui l’utilisaient reviennent au thème Hydor.

Le thème affiché se choisit dans chaque navigateur. Les thèmes que vous créez sont conservés par l’app et proposés sur chaque appareil que vous utilisez.

## Créer votre propre thème

1. Cliquez sur [**Nouveau thème**](/settings?s=general&find=New%20theme) sous les images. L’éditeur s’ouvre avec une copie du thème actuellement affiché, nommée « Mon thème » (ou utilisez **Créer une copie à modifier** sur n’importe quel thème).
2. Donnez-lui un nom, puis choisissez **Sombre** ou **Clair** comme base. La base définit les couleurs du code et celles que les programmes affichent dans le terminal, et complète toute couleur que le thème ne précise pas.
3. Modifiez les couleurs de votre choix : cliquez sur un échantillon pour en choisir une, ou saisissez un code hexadécimal comme `#1e3a2f`.
4. Cliquez sur **Enregistrer le thème**. L’app l’utilise immédiatement.

Pendant que vous modifiez, toute l’app montre vos changements, ce qui vous permet de voir chaque couleur là où elle est utilisée. Rien n’est conservé tant que vous n’enregistrez pas : **Annuler**, ✕ (**Fermer sans enregistrer**) ou Échap rétablissent le thème que vous aviez. **Copier** copie le thème sous forme de texte, comme **Copier pour partager**. L’éditeur est un panneau à droite sur ordinateur, et une feuille qui monte du bas sur téléphone.

Vous pouvez avoir jusqu’à 40 thèmes à vous ; **Nouveau thème** et **Importer** deviennent alors grisés.

### Les couleurs que vous pouvez régler

- **Arrière-plans** : Page (derrière tout), Barre latérale, Cartes (la zone de message, les cartes de paramètres, les panneaux), Menus et boîtes de dialogue, Champs (zones de saisie et fonds discrets), Survol (lignes sous le pointeur, pastilles), Sélection (la ligne ouverte, les boutons secondaires).
- **Texte** : Texte, Texte secondaire, Texte atténué (indications, heures, libellés).
- **Bordures** : Bordures, Bordures marquées (zones de saisie et boutons à contour).
- **Accent** : Accent (boutons principaux, liens, focus, sélection), Texte sur l’accent.
- **Statut** : En cours ; À vous de jouer, avertissements ; Terminé, lignes ajoutées ; Échec, lignes supprimées ; Information.
- **Agents** : Claude, Codex.
- **Code et terminal** : Blocs de code, Arrière-plan du terminal, Texte du terminal.

Une couleur de texte qui devient difficile à lire sur les arrière-plans où elle se trouve affiche un avertissement, « difficile à lire », avec son contraste (par exemple 2,8:1). Un contraste de 4,5:1 se lit bien, ou 3:1 pour le texte atténué.

## Partager un thème ou en importer un

Pour donner un thème à quelqu’un, ou à un autre de vos Hydor :

1. Dans le menu du thème (⋯), choisissez **Copier pour partager** (ou **Copier** dans l’éditeur). Le thème est copié sous la forme d’un court texte.
2. Envoyez ce texte.

Pour ajouter un thème qu’on vous a donné :

1. Cliquez sur [**Importer**](/settings?s=general&find=Import) sous les images des thèmes.
2. Collez le texte dans **Importer un thème** et cliquez sur **Ajouter un thème**.

Le thème est ajouté aux vôtres et utilisé aussitôt. Si le texte n’est pas un thème, l’app affiche « Ce n’est pas un thème » et demande ce que **Copier pour partager** vous a donné.

## Changer la langue

[Paramètres → App → Général → Apparence → Langue](/settings?s=general&find=Language) est un menu avec les langues dans lesquelles l’app est affichée :

- **English** (anglais)
- **Deutsch** (allemand)
- **Español** (espagnol)
- **Français** (français)
- **Português (Brasil)** (portugais, Brésil)
- **Ελληνικά** (grec)
- **日本語** (japonais)
- **中文（简体）** (chinois simplifié)

Choisir une langue recharge la page dans cette langue. Le choix est conservé dans ce navigateur ; au départ, l’app suit la langue de votre navigateur si elle la gère, et l’anglais sinon.

Seuls les mots de l’app changent, et les dates et heures s’écrivent comme dans cette langue. Ce que les personnes et les agents ont écrit reste tel quel : conversations, notes de mémoire, noms et descriptions que vous avez donnés aux éléments, fichiers, code et terminaux.

Les agents vous écrivent dans la langue que vous choisissez : on le leur demande, sauf si vous leur écrivez dans une autre langue ou en demandez une, et le code, les commandes et les noms de fichiers restent tels quels. Cela parvient à chaque agent quand il démarre ou reprend. Les notifications arrivent aussi dans cette langue, y compris sur votre téléphone. L’app indique sa langue aux agents à chaque ouverture ; si vos appareils sont réglés sur des langues différentes, les agents et les notifications suivent celle ouverte en dernier.

## Choisir la part de mouvement

[Paramètres → App → Général → Apparence → Animations](/settings?s=general&find=Motion) détermine la part de mouvement de l’app sur cet appareil :

- **Pleine** (par défaut) : tout bouge. Un bouton s’enfonce un peu quand vous appuyez dessus puis revient, une copie se transforme en coche qui se dessine, un interrupteur rebondit, la barre de la barre d’icônes glisse vers la page ouverte, le point d’une session change selon son statut (un anneau s’étend quand le travail se termine, deux pulsations quand elle a besoin de vous), les listes glissent vers leurs nouvelles places et se referment là où un élément a disparu, les nombres comptent jusqu’à leurs nouvelles valeurs, le badge de la Boîte de réception fait un petit saut, l’eau du logo monte une fois quand une session se termine, les images scintillent jusqu’à leur arrivée, et une étape qui se termine dessine sa coche. Cinq autres choses bougent quand vous ouvrez quelque chose : la barre latérale glisse quand vous la masquez ou l’affichez, la colonne à côté d’une page (la colonne de droite du Navigateur, le panneau **Demander à un agent** de la page Fichiers) glisse pour entrer et sortir, les pages s’enchaînent en fondu quand vous passez de l’une à l’autre (sauf vers ou depuis le Navigateur), les aspects clair et sombre se fondent quand vous changez de thème, et les fenêtres apparaissent à l’ouverture, au-dessus d’une page qui s’assombrit derrière elles. Une boîte de dialogue ou une fenêtre (les détails d’un projet, la fenêtre d’un fichier, une page ouverte par-dessus l’app, l’éditeur d’agent) monte un peu en grandissant jusqu’à sa taille, et sur téléphone, où ces fenêtres se tiennent en bas de l’écran, elle monte depuis le bord inférieur comme une feuille. Un panneau latéral (les détails d’une session sur un écran étroit, le panneau d’une tâche en arrière-plan) glisse depuis la droite. La zone de recherche (Ctrl+K) et la visionneuse d’images et de vidéos apparaissent rapidement en fondu. Elles se ferment aussitôt.
- **Calme** : tout cela sauf les cinq derniers éléments. Rien ne glisse ni ne se fond quand vous ouvrez une page ou une fenêtre.
- **Désactivé** : rien de tout cela. Seul le travail en cours continue de bouger : l’eau du Ω pendant un chargement, et les points des sessions au travail.

Chaque mouvement dure environ un dixième à un quart de seconde, ne retarde jamais ce que vous ouvrez et ne se répète jamais, sauf le travail en cours. Le réglage **Réduire les animations** de votre appareil l’emporte toujours : s’il est activé, l’app se comporte comme si **Désactivé** était choisi, quoi que dise ce paramètre. Le choix est conservé dans ce navigateur. Sur téléphone, les glissements de la barre latérale et des colonnes et les fondus entre pages ne se jouent pas, mais les fenêtres montent toujours depuis le bas.

## Décider du rôle d’Entrée pendant qu’un agent travaille

Dans le groupe **Sessions**, [**Envoi pendant qu’un agent travaille**](/settings?s=general&find=Sending%20while%20an%20agent%20works) décide de ce qui se passe quand vous envoyez un message alors que l’agent est au milieu d’un tour :

- **Rejoindre le tour** (par défaut) : Entrée ajoute votre message au tour en cours, de sorte que l’agent en tient compte tout de suite. Ctrl+Entrée (⌘Entrée sur Mac) attend plutôt la fin du tour.
- **Attendre qu’il se termine** : Entrée met votre message dans la file d’attente, et il part à la fin du tour. Ctrl+Entrée (⌘Entrée sur Mac) l’ajoute plutôt au tour en cours.

Le choix est conservé dans ce navigateur. Pour en savoir plus sur la file d’attente, voir [Sessions](/guide/sessions).

## Activer ou désactiver les suggestions du terminal

Dans le groupe **Terminaux**, [**Suggestions du terminal**](/settings?s=general&find=Terminal%20suggestions) (activées par défaut) affiche du texte gris après le curseur dans les terminaux de l’app, avec la suite la plus probable de la commande ; → l’accepte. La désactiver masque seulement le texte gris : Ctrl+Espace affiche toujours la liste des suggestions. Le réglage est conservé dans ce navigateur. Voir [Suggestions grises](/guide/files-git#grey-suggestions).

## Reprendre les sessions après une limite d’utilisation

[**Reprendre après les limites d’utilisation**](/settings?s=general&find=Resume%20after%20usage%20limits) (désactivé par défaut) : quand un tour s’arrête parce que l’utilisation d’un forfait est épuisée, la session continue d’elle-même une minute après la réinitialisation de la limite. Ce réglage est conservé par l’app, il fonctionne donc sans navigateur ouvert. Pour en savoir plus, voir [Utilisation, limites et coûts](/guide/usage).

## Supprimer les sessions inactives

L’app conserve chaque session, quoi que fasse le programme propre à l’agent (voir [Chaque session est conservée](/guide/usage#every-session-is-kept)), jusqu’à ce que personne ne l’ait utilisée depuis longtemps. [**Supprimer les sessions inactives**](/settings?s=general&find=Delete%20inactive%20sessions) (activé par défaut) supprime les sessions inactives depuis **1 an**, quelques centaines par jour au maximum.

- Choisissez la durée d’inactivité autorisée dans le menu à côté de l’interrupteur, sur sa ligne : **Après 3 mois**, **Après 6 mois**, **Après 1 an**, **Après 2 ans** ou **Après 5 ans**.
- Désactivez l’interrupteur pour conserver toutes les sessions pour toujours.
- Une session est comptée comme inactive à partir de la dernière fois où quelque chose s’y est passé.
- Certaines sessions restent toujours : celles qui sont épinglées, et celles qui sont au travail, qui vous attendent, qui ont des messages en file d’attente, qui sont en pause, qui doivent reprendre après une limite, qui s’exécutent dans VS Code ou dans un terminal, ou qui ont une pull request ouverte.
- Une session supprimée quitte la liste et sa conversation disparaît, mais ses chiffres restent dans [Activité](/stats).

Ce réglage est conservé par l’app, il fonctionne donc sans navigateur ouvert.

## Limiter chaque session

[**Limiter chaque session**](/settings?s=general&find=Limit%20each%20session) plafonne ce qu’une session peut utiliser : le programme de son agent et tout ce qu’il exécute (les commandes, les serveurs qu’il démarre). Choisissez la mémoire (de **2 Go de mémoire** à **16 Go de mémoire**, ou **Aucune limite de mémoire**) et les processeurs (de **1 processeur** à **8 processeurs**, ou **Aucune limite de processeur**).

- Les limites s’appliquent à partir du prochain démarrage de l’agent d’une session ; les sessions déjà en cours gardent celles avec lesquelles elles ont démarré.
- Au-delà de sa mémoire, le programme qui en a demandé davantage est arrêté, pas l’app ni une autre session : l’agent voit sa commande se terminer et peut continuer. Les Infos de la session et Système → Moniteur l’indiquent : « un a été arrêté à sa limite de mémoire ».
- À sa limite de processeurs, les programmes de la session s’exécutent plus lentement, et le reste de l’ordinateur reste libre.
- Les limites fonctionnent sous Linux, via le systemd de votre utilisateur : chaque session s’exécute dans un scope qui lui est propre. Ailleurs, ou sans systemd utilisateur en cours d’exécution, les menus sont désactivés et le (i) de la ligne en donne la raison ; ce que chaque session utilise reste visible dans [Moniteur](/system/monitor).

## Démarrer l’app avec l’ordinateur

Dans le groupe **Démarrage et mises à jour**, [**Démarrer au démarrage de cet ordinateur**](/settings?s=general&find=Start%20when%20this%20computer%20starts) relance l’app après un redémarrage de l’ordinateur et après un plantage. Il est activé par défaut : l’installateur configure l’app comme un service, et une copie lancée à la main depuis un clone git en configure un la première fois qu’elle s’exécute. Ce que l’interrupteur peut faire dépend de la façon dont l’app s’exécute, et la ligne en dessous (ainsi que son (i)) l’indique :

- **Comme service de votre utilisateur** (l’installation habituelle) : l’interrupteur l’active ou le désactive. L’app démarre au démarrage de l’ordinateur, avant même que quiconque se connecte ; si la ligne dit qu’elle ne démarre qu’une fois que vous êtes connecté, exécutez une fois `sudo loginctl enable-linger $USER` sur l’ordinateur pour changer cela.
- **Comme service système** : le modifier demande des droits d’administrateur sur l’ordinateur.
- **Dans Docker** : sa politique de redémarrage la relance (`restart: unless-stopped`), et l’interrupteur ne peut pas la modifier.
- **Dans une app de bureau** : elle s’ouvre en arrière-plan quand vous vous connectez, avec son icône dans la barre des menus (sous Windows dans la zone de notification de la barre des tâches, sous Linux dans la zone de notification du système) et sa fenêtre fermée. Elle est activée dès la première ouverture (l’app Mac depuis le dossier Applications).
- **Lancée d’une autre façon** : l’activer la configure comme service de votre utilisateur. Là où ce n’est pas possible (pas de systemd pour votre utilisateur), la ligne l’indique.

Pendant que l’app se charge, dans un navigateur ou au démarrage d’une app de bureau, son logo s’affiche avec de l’eau qui monte dans le Ω. Dès que l’app est prête, elle se trouve sous le logo, qui disparaît en fondu tandis que l’eau se vide du Ω et que l’écran autour s’éclaircit. Vous pouvez cliquer et saisir du texte tout de suite. Si votre appareil demande de réduire les animations, le logo disparaît simplement.

## Garder l’ordinateur éveillé

Dans les apps de bureau (Mac, Windows et Linux), [**Garder l’ordinateur éveillé**](/settings?s=general&find=Keep%20the%20computer%20awake), sous **Démarrer au démarrage de cet ordinateur**, empêche l’ordinateur de se mettre en veille tout seul tant qu’il y a du travail à faire : une longue exécution n’est pas interrompue en route, et une tâche prévue à 7 h 00 s’exécute à 7 h 00 plutôt qu’à la prochaine ouverture du capot. Trois choix sont proposés :

- **Pendant que les agents travaillent et avant les tâches planifiées** (par défaut) : tant qu’un agent travaille sur cet ordinateur (les exécutions planifiées, les exécutions d’apps, les sous-agents et les expériences en cours comptent aussi), et à partir de quelques minutes avant l’échéance d’une tâche planifiée, d’un planning de vos agents ou d’un planning d’app, jusqu’au début de son exécution.
- **Pendant que les agents travaillent** : uniquement tant que les agents travaillent. Une tâche planifiée s’exécute quand l’ordinateur est éveillé.
- **Jamais** : l’ordinateur se met en veille selon ses propres réglages.

Une session qui attend votre réponse ne compte pas comme du travail. Les veilleurs qui vérifient toutes les quelques minutes (voir [Surveiller un changement](/guide/tasks#watch-for-a-change)) ne gardent pas l’ordinateur éveillé à eux seuls : seule l’exécution qu’un changement déclenche le fait, pendant qu’elle travaille. Seul compte ce qui s’exécute sur cet ordinateur, pas ce qui s’exécute sur vos autres machines. La ligne sous l’option indique quand l’ordinateur est maintenu éveillé et pourquoi (« Éveillé maintenant : les agents travaillent ») ; quelques secondes après la fin du travail, il peut se remettre en veille.

Seul l’ordinateur reste en marche : l’écran peut toujours s’éteindre comme d’habitude. Fermer le capot d’un portable le met toujours en veille, tout comme choisir vous-même la mise en veille : c’est le système d’exploitation qui décide, pas l’app. Un ordinateur déjà en veille ne se réveille pas pour une tâche ; l’exécution démarre dès qu’il est de nouveau éveillé. Pour un travail qui doit s’exécuter à toute heure, utilisez un ordinateur qui reste allumé, comme un ordinateur de bureau ou un serveur, et accédez-y depuis votre portable ou votre téléphone (voir [Utiliser d’autres machines depuis une seule app](/guide/devices#use-other-machines-from-one-app) et [Accéder à l’app depuis un autre appareil](/guide/devices#reach-the-app-from-another-device)).

L’option n’apparaît que dans les apps de bureau. L’app installée comme service (ou dans Docker) ne touche pas à la mise en veille de l’ordinateur.

## Garder l’app à jour

Une copie installée depuis git (celle de l’installateur ou de Docker) cherche une version plus récente quelques minutes après son démarrage, puis une fois par jour ; les apps de bureau cherchent une minute après leur ouverture, puis toutes les 4 heures. La ligne de version, dernière ligne de **Démarrage et mises à jour** dans [Paramètres → App → Général](/settings?s=general&find=Check%20now), porte le nom de la version que vous utilisez (**Hydor…**) et indique où en sont les choses :

- « À jour · vérifié il y a … », avec **Vérifier maintenant** pour revérifier aussitôt.
- Quand une version plus récente est disponible : « … mises à jour disponibles », le titre du dernier changement et **Mettre à jour maintenant**. Cela récupère la nouvelle version, la compile et redémarre l’app ; les agents en cours continuent pendant le redémarrage, et cet onglet se recharge de lui-même dans la nouvelle version. Si l’app ne peut pas redémarrer toute seule, elle récupère et compile la nouvelle version, et c’est à vous de redémarrer l’app pour l’utiliser.
- Pendant la mise à jour : « Récupération de la nouvelle version… », « Installation des paquets… », « Compilation… », puis « Redémarrage, cette page se reconnecte toute seule… ».
- Pendant une semaine ensuite, le déroulement de la dernière mise à jour : quand elle a eu lieu (et de quelle version à quelle version), ou pourquoi elle a échoué.

Quand une version plus récente est disponible, un point apparaît sur **Paramètres** dans la barre d’icônes. Une copie non installée depuis git ne peut pas vérifier : **Vérifier maintenant** l’indique. Le (i) de la ligne explique où s’exécutent les sessions et d’où vient leur historique.

[**Mettre à jour automatiquement**](/settings?s=general&find=Update%20automatically) (activé au départ, la ligne au-dessus de la version) installe tout seul une version plus récente : pour une copie installée depuis git, après 5 heures sans message de votre part, au plus une fois par jour ; pour les apps de bureau, dès qu’une version est disponible, avec une minute de préavis (le .deb Linux demande d’abord votre mot de passe). Les agents en cours continuent. Il faut une app capable de redémarrer toute seule (le service de l’installateur, Docker, ou une app de bureau capable de se remplacer, comme l’app Mac placée dans le dossier Applications) ; sinon, l’interrupteur est désactivé et en donne la raison.

Les autres pages ouvertes sur vos appareils remarquent quand l’app a une version plus récente que la leur, et proposent **Recharger** (« Hydor a été mis à jour »). Une page qui n’arrive pas à s’afficher montre « Cette page a cessé de fonctionner », ce qui s’est passé et **Recharger**, au lieu d’une fenêtre vide ; la barre latérale reste, et passer à une autre page refait un essai.

### Mettre à jour une ancienne copie à la main

L’historique de Hydor sur GitHub a été réécrit dans la version 0.78.0, et une copie installée depuis git ou Docker avant cette version ne peut pas se mettre à jour toute seule au-delà : **Mettre à jour maintenant** s’arrête avec « Not possible to fast-forward, aborting. », et il en va de même pour la mise à jour de cette machine depuis l’app d’une autre machine (voir [Utiliser d’autres machines depuis une seule app](/guide/devices#use-other-machines-from-one-app)), dont la page indique alors quoi faire. Mettez-la à jour une fois sur cette machine même, de la façon dont elle a été installée ; ensuite, elle se met de nouveau à jour toute seule.

- **Avec l’installateur** : relancez-le sur place. Il déplace la copie vers le nouvel historique (les fichiers que vous avez modifiés sont conservés), la compile et redémarre le service, et les agents en cours continuent : `curl -fsSL https://raw.githubusercontent.com/algoprog/hydor/main/install.sh | bash`. Si vous l’avez installée dans un dossier de votre choix, indiquez ce dossier : `curl -fsSL https://raw.githubusercontent.com/algoprog/hydor/main/install.sh | HYDOR_DIR=/that/folder bash`.
- **Dans Docker** : récupérez la nouvelle image et relancez le conteneur à partir d’elle, dans le dossier qui contient votre `compose.yaml` : `docker compose pull && docker compose up -d` (ou `docker pull algoprog/hydor` puis lancez-la comme avant). Ce que l’app conserve se trouve dans son volume, donc rien n’est perdu. Si vous compilez l’image vous-même, mettez d’abord à jour votre clone comme au point suivant, puis `docker compose up -d --build`.
- **Depuis votre propre clone git** : dans son dossier, `git fetch && git reset --keep @{u} && npm ci && npm run build`, puis relancez l’app. `git reset --keep` conserve les fichiers que vous avez modifiés et s’arrête avant d’en écraser un. Si vous avez fait vos propres commits, déplacez-les plutôt sur le nouvel historique avec `git rebase --onto`.

Les copies récentes gèrent seules un historique réécrit : quand la copie n’a pas de commits à elle, **Mettre à jour maintenant** la déplace vers le nouvel historique en conservant les fichiers que vous avez modifiés ; quand elle en a, elle le signale et les laisse tels quels.

### Mises à jour dans les apps de bureau

Les apps de bureau (Mac, Windows et Linux) fonctionnent plutôt par versions publiées. Avec [**Mettre à jour automatiquement**](/settings?s=general&find=Update%20automatically) activé, l’app télécharge une nouvelle version dès sa sortie et vérifie qu’il s’agit bien du build indiqué par la publication, sans attendre que vous soyez absent. Puis elle vous prévient à deux endroits :

- Une notification : « Hydor… est prêt », avec un redémarrage dans une minute pour l’installer. Cliquer dessus ouvre l’app ; son bouton **Redémarrer maintenant** installe aussitôt la nouvelle version.
- Une note dans le coin de chaque page ouverte de l’app, qui décompte les secondes (« Redémarrage dans 42 s pour l’installer »), avec **Redémarrer maintenant** et **Plus tard**.

Quand la minute est écoulée, l’app redémarre dans la nouvelle version : les agents en cours continuent, et sa fenêtre revient toute seule. **Plus tard** repousse de 4 heures, après quoi la notification et la note reviennent. D’ici là, **Redémarrer pour mettre à jour vers …** dans le menu de l’icône de l’app (dans la barre de menus, la zone de notification ou la barre d’état système, et dans le menu propre à l’app) l’installe quand vous voulez, tout comme **Redémarrer maintenant** dans la ligne de version, qui indique « La version … est prête à être installée » et quand elle redemandera.

Avec **Mettre à jour automatiquement** désactivé, rien ne se télécharge tout seul : la ligne de version indique « La version … est disponible », et **Mettre à jour maintenant** la télécharge, la vérifie et l’ouvre à la place de celle que vous utilisez (« Téléchargement de la nouvelle version… », puis « Ouverture de la nouvelle version, cette page se reconnecte toute seule… »).

Un téléchargement interrompu reprend là où il s’était arrêté : quand l’ordinateur se met en veille, ou que la connexion tombe ou reste muette pendant une minute, il reprend dès que possible. S’il n’avance toujours pas au bout de quelques minutes, il garde ce qu’il a déjà, la ligne sous la ligne de version indique jusqu’où il est allé, et il réessaie une heure plus tard en reprenant à ce point ; **Mettre à jour maintenant** fait de même.

Sous Windows, l’installateur de la nouvelle version s’exécute sans fenêtre, s’installe par-dessus l’app et la rouvre. Le .deb Linux demande votre mot de passe pour s’installer : une version téléchargée automatiquement attend, et **Redémarrer pour mettre à jour** (ou **Redémarrer maintenant**) demande le mot de passe et ouvre la nouvelle version.

Si la nouvelle version de l’app Mac ou d’un AppImage ne démarre pas, la version précédente revient toute seule et la ligne sous la ligne de version en donne la raison ; cette version ne s’installe alors que si vous appuyez sur **Mettre à jour maintenant**. L’app Mac ne peut se mettre à jour que depuis le dossier Applications (ou un autre dossier où vous pouvez écrire) : ouverte depuis l’image disque, elle vous demande de la déplacer. De même, un AppImage a besoin d’un dossier où vous pouvez écrire, comme votre dossier personnel.

## Lire les notes de version

Chaque version a ses notes de version : ce qui a changé pour les personnes qui l’utilisent.

- Dans la ligne de version, en bas de **Démarrage et mises à jour** dans [Paramètres → App → Général](/settings?s=general), cliquez sur **Notes de version**.
- Ou tapez « notes de version » ou « nouveautés » dans la zone de recherche.

Les notes listent toutes les versions, de la plus récente à la plus ancienne, chacune avec sa date ; celle que vous utilisez est marquée « Cette version », et les Paramètres ouvrent les notes à cet endroit.

Une fois après la mise à jour de l’app, une note dans le coin indique « Mis à jour vers Hydor… » avec **Nouveautés**, qui ouvre les notes à cette version. Chaque navigateur ne la voit qu’une fois, et la première visite d’un navigateur ne la déclenche pas.

## Faire la visite

La visite de bienvenue est conçue pour les personnes qui découvrent l’IA. Elle s’ouvre sur un court film montrant une demande en train d’être réalisée (vous demandez avec vos propres mots, l’agent travaille pas à pas, le résultat est prêt), puis demande qui doit faire le travail : **Claude** ou **ChatGPT** (avec l’abonnement que vous payez déjà), **Paiement à l’usage** (des modèles de toutes les entreprises via OpenRouter), **Gratuit, sur cet ordinateur** (des modèles qui s’exécutent ici) ou **Autres agents**. Elle configure chaque choix sur des pages qui remplissent l’écran, chacune avec son image et ses mots au même endroit et sans rien à faire défiler : se connecter, ajouter votre clé OpenRouter et choisir les modèles de votre agent, puis les modèles qui créent des images, de la musique, des voix et des vidéos, ou l’installation en un clic d’un des modèles suggérés pour cet ordinateur. L’image à côté de chaque page montre ce que vous avez choisi sous forme de cours d’eau qui se jettent dans un bassin autour du Ω, lequel se remplit à mesure que vous faites d’autres choix ; de petits points en bas indiquent où vous en êtes, au-dessus d’une mer dont les vagues dérivent doucement. Quand le dossier d’un autre agent se trouve sur cet ordinateur (Claude Code, Codex ou un autre), une page de plus, **Vous venez d’un autre agent ?**, indique ce qu’elle a trouvé et ouvre [Importer](/guide/memory#bring-in-from-other-assistants) par-dessus la visite ; s’il n’y en a aucun ici, cette page n’existe pas. Dans l’app de bureau, quand Hydor trouve d’autres navigateurs sur cet ordinateur, la page suivante, **Importer vos favoris et votre historique ?**, dit « Hydor a son propre navigateur. Importez ce que savent les navigateurs de cet ordinateur, pour que vos sites soient à un clic et que la barre d’adresse vous les suggère. Tout reste sur cet ordinateur. » Elle propose deux interrupteurs, **Favoris** et **Historique** (tous deux activés), puis chaque navigateur (et chacun de ses profils) avec son nombre de favoris et de pages d’historique, et **Importer** à côté, qui importe ce qui est activé : les favoris dans un nouveau dossier à la fin de la barre de favoris, « Importés depuis Chrome », comme dans [Importer des favoris](/guide/web#bring-in-bookmarks), et l’historique comme dans [Historique](/guide/web#history). Elle affiche **Importé** une fois l’opération terminée, et un problème (autorisation de Safari, fichier verrouillé) sur la ligne de ce navigateur, avec **Importer** pour réessayer. Sur un Mac, tant que macOS empêche Hydor de lire Safari, la ligne de Safari propose **Ouvrir les Réglages Système** au lieu d’**Importer** : cela ouvre Réglages Système → Confidentialité et sécurité → Accès complet au disque, où vous activez Hydor, et à votre retour la ligne vérifie de nouveau. Si Hydor doit d’abord se rouvrir, la visite revient à cette page. **Suivant** continue sans importer. Sans autre navigateur trouvé, ou en dehors de l’app de bureau, cette page n’existe pas. Ensuite, elle vous fait découvrir l’app partie par partie, avec quelque chose à essayer en chemin : une première tâche que vous pouvez placer dans la zone de message en un clic. Son étape **Être prévenu à la fin** active les notifications pour cet appareil ; dans une app de bureau, **Activer les notifications** affiche une notification de test ou, quand votre système n’affiche pas encore les notifications de Hydor, ouvre ses réglages où vous les autorisez (sur un Mac, Réglages Système, dans les notifications de Hydor) et revérifie à votre retour. Dans une app de bureau, l’étape suivante demande **L’utiliser aussi sur votre téléphone ?** : **La configurer** termine la visite sur [Paramètres → App → Utiliser sur votre téléphone](/settings?s=phone), pour accéder à l’app depuis votre téléphone de façon privée avec Tailscale, et **Pas maintenant** passe à la suite. Elle s’ouvre toute seule la première fois que vous utilisez l’app.

Pour la refaire : [Paramètres → App → Général → **Aide** → Visite de bienvenue → **Faire la visite**](/settings?s=general&find=Take%20the%20tour), **Faire la visite** dans la zone de recherche, ou **Faire la visite** en haut de **Aide** dans la barre d’icônes. Plus de détails dans [Premiers pas](/guide/start).

Après la visite, des astuces vous présentent le reste de l’app au fur et à mesure. La première fois qu’une partie de l’app s’affiche à l’écran (la boîte de réception, le menu d’une session, la page Git, **Paramètres → Mémoire**…), une petite carte à côté explique à quoi elle sert, et **En savoir plus** ouvre ce guide à l’endroit où il en dit davantage. Les astuces arrivent une par une et à intervalle, jamais pendant que vous tapez ou qu’un menu est ouvert.

- **Compris**, ou l’utilisation de la partie qu’elle désigne, écarte définitivement une astuce, sur tous les appareils.
- **Ignorer les conseils** les arrête toutes, sur tous les appareils. **Passer la visite** sur la première page de la visite fait de même ; fermer la visite avec ✕ les laisse activées.
- Par ailleurs, la première fois que vous choisissez un mode qui coûte plusieurs fois ce que coûte un seul agent (**Essaim**, **Campagne**, **Recherche approfondie** ou **Arène**), une boîte de dialogue explique à quoi il sert et ce qu’il coûte avant son activation. Elle ne s’affiche qu’une fois pour chaque mode, sur tous les appareils, que les astuces soient activées ou non ; demandez à un agent d’afficher de nouveau les astuces et elle revient aussi.
- Pour les activer ou les désactiver de nouveau : [Paramètres → App → Général → Aide → **Astuces**](/settings?s=general&find=Tips).

## Changer votre mot de passe

L’app n’a qu’un seul mot de passe, choisi lors de son installation. Pour le changer, ouvrez [Paramètres → App → Mot de passe](/settings?s=security&find=Change%20password) et cliquez sur **Changer…** dans la ligne **Changer le mot de passe**. Une boîte de dialogue s’ouvre :

1. Saisissez votre **Mot de passe actuel**.
2. Saisissez le **Nouveau mot de passe** (au moins 10 caractères) et **Répéter le nouveau mot de passe**.
3. Cliquez sur **Changer le mot de passe** (le bouton reste grisé tant que le mot de passe actuel n’est pas saisi et que le nouveau n’a pas 10 caractères).

Cette opération déconnecte tous les autres navigateurs : téléphones, autres ordinateurs, partout sauf sur celui-ci. Si le mot de passe actuel est incorrect, ou si les deux nouveaux mots de passe diffèrent, rien ne change et l’app en explique la raison.

Si vous l’avez oublié, exécutez cette commande sur l’ordinateur où tourne l’app, dans le dossier de l’app : `node dist/server/cli.js set-password` (avec Docker : `docker compose exec -it hydor node dist/server/cli.js set-password`). Tous les navigateurs sont déconnectés, et les adresses mises en pause après des mots de passe erronés peuvent se reconnecter.

## Se déconnecter de ce navigateur

[Paramètres → App → Mot de passe → Ce navigateur → Se déconnecter de ce navigateur](/settings?s=security&find=Sign%20out%20of%20this%20browser) → **Se déconnecter** déconnecte ce navigateur, et uniquement celui-ci. Vous aurez besoin du mot de passe pour revenir.

## Où l’app conserve ses données

L’app conserve ses propres données dans un seul dossier, son dossier de données : `~/.hydor` dans votre dossier personnel (`~/.web-agent` pour les installations antérieures à la version 0.5, ou l’emplacement indiqué par le paramètre `DATA_DIR`). Les fichiers que vous supprimez dans la page Fichiers vont dans la corbeille de ce dossier ; **Corbeille**, parmi les emplacements de la page Fichiers, indique où elle se trouve. Il contient :

- le mot de passe, sous forme de hash (le mot de passe lui-même n’est jamais stocké) ;
- la base de données avec la liste des sessions, la recherche, les paramètres et les autres enregistrements de l’app ;
- les journaux des agents en cours d’exécution ;
- les pièces jointes en attente d’envoi (les copies de l’app sont supprimées après 14 jours et limitées à 2 Go au total) ;
- la corbeille de la page Fichiers ;
- les noyaux des notebooks et le serveur privé dans lequel s’exécutent les terminaux ;
- une fois la Recherche par le sens activée, son environnement Python privé.

Les conversations elles-mêmes restent là où les agents les écrivent, `~/.claude/projects` pour Claude Code et `~/.codex/sessions` pour Codex : l’app les lit à cet endroit (le (i) à côté de la version dans Paramètres → Général l’indique). Avec Docker, tout cela se trouve dans le dossier `/home/node` du conteneur, conservé dans son volume de données.

### Ce que conserve chaque navigateur

Certains choix appartiennent au navigateur dans lequel vous les faites, si bien que chaque appareil peut avoir les siens :

- le mode (sombre, clair ou système) et le thème sombre et le thème clair affichés ;
- la langue ;
- l’importance des mouvements (**Animations**) ;
- l’action de la touche Entrée pendant qu’un agent travaille ;
- les suggestions du terminal, le son des notifications, et si cet appareil reçoit des notifications ;
- le dossier de la page Fichiers, les fichiers ouverts, les fichiers récents et l’affichage des dossiers (liste ou vignettes, et leur ordre) ; les dossiers épinglés sont conservés sur le serveur, les mêmes sur tous les appareils ;
- les fichiers marqués **Vu** lors de la relecture d’une branche ;
- l’affichage ou non de la note « Nouveautés ».

Le reste est conservé par l’app et est identique sur tous les appareils : les thèmes que vous avez créés, **Reprendre après les limites d’utilisation**, **Supprimer les sessions inactives**, **Démarrer au démarrage de cet ordinateur**, **Mettre à jour automatiquement**, si la visite guidée a été faite, et les astuces (activées ou non, et lesquelles ont été affichées).
