Please write src/regex.mjs, a small regular expression engine, exactly as SPEC.md in this folder describes it: `compile(pattern)` returning an object with `test(text)` and `match(text)` (leftmost-longest), the pattern language, the size limit, and a `SyntaxError` with the right `position` for every bad pattern. Two requirements matter more than anything else. First, matching must take time proportional to the pattern's size times the text's length whatever the pattern: no backtracking, nothing that can blow up on patterns like `(a*)*b` or `(a|aa)+$`, and no quadratic scan from every start position; the texts can be 200,000 characters long. Second, do not use JavaScript's own regular expressions anywhere in the module (no `RegExp`, no regex literals, no `eval` or `new Function`): the engine has to be your own parser and automaton. Add tests under test/ (node:test, so that `node --test` passes) covering the main rules, including a few of those slow patterns on long texts. Plain Node.js 22 ES module, no packages.
